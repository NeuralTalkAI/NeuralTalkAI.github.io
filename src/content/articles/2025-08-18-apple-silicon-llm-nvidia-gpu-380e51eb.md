## 关键问题

### 问题 1. 既然低比特量化在 Apple Silicon 上并非总能带来更快的推理速度（如 2 位模型可能快于 1 位模型），那么决定量化模型推理效率的核心硬件特性与量化方案设计的交互机制是什么？

决定量化模型推理效率的核心在于**硬件特性与量化方案的【适配性】**：

::: block-1
- Apple Silicon 缺乏专用张量核心，导致非标准比特（如 1 位）的去量化需更多位操作（移位、掩码），增加计算开销；
- 统一内存架构下，块量化（如 Q2_K）仅需加载块级尺度和偏移，内存访问更高效，而码本量化（如 IQ1_M）因频繁引用码本导致缓存未命中和缓冲流量激增，进一步拖慢速度。
:::

这种硬件计算能力与量化方案内存访问模式的交互，决定了推理效率。

### 问题 2. Apple Silicon 的统一内存架构虽能支持超大型 LLM 运行，但在性能上仍落后于 NVIDIA GPU 的部分场景，这种"内存优势-计算劣势"的平衡临界点在哪里，即模型规模达到何种程度时 Apple Silicon 的综合效益会显著超越 NVIDIA GPU？

**平衡临界点** 出现在**模型参数规模超出消费级 NVIDIA GPU 显存容量** 时：

::: block-1
- 当模型参数超过单卡或多卡 NVIDIA GPU 的 VRAM（如 48GB-96GB），需依赖 CPU 卸载，导致延迟骤增（如 Llama 70B FP16 在 2xA6000 上延迟是 M2 Ultra 的 4.3 倍）；
- 而 Apple Silicon 的统一内存（如 M2 Ultra 的 192GB）可直接容纳超大型模型（如 405B 参数），此时其内存优势覆盖计算性能劣势，综合效益显著超越 NVIDIA GPU。
:::

### 问题 3. 论文指出块量化方案（如 Q2_K）在 Apple Silicon 上表现优于码本量化方案（如 IQ1_M），其根本原因是去量化开销还是内存访问模式差异，这对针对 Apple Silicon 优化量化算法有何决定性影响？

**块量化优于码本量化的根本原因** 是:mdnice-bold-italic[去量化开销] 与:mdnice-bold-italic[内存访问模式] 的双重影响：

::: block-1
- 码本量化（如 IQ1_M）需频繁访问码本，导致缓冲加载利用率超 60%、读取限制器达 70%以上，且去量化需复杂位提取操作，ALU 利用率仅 35.8%；
- 而块量化（如 Q2_K）无需码本，去量化步骤简单，ALU 利用率达 76.8%，更贴合 Apple Silicon 的 SIMD 架构。其中去量化开销是核心，内存访问模式差异放大了这一差距。
:::

## 一、引言

数十亿参数规模的大型语言模型（LLMs）的出现及其更强的推理能力，引发了人工智能发展的深刻范式转变[45]。大型 LLM 的设备端执行具有很大吸引力，因为它有望增强隐私性、实现数据本地化、让用户掌控数据，并支持多样化的个性化应用[60]。随着机器学习（ML）加速器的最新发展，GPU 能够提供峰值性能；但获取这些 GPU 的超强能力存在一个限制因素，即其成本越来越高（可以用生成每个 token 的成本来衡量）[48]。尽管云服务提供商提供按需 GPU 实例，但从长远来看，购买 GPU 更具成本效益[51]。

> LLM 推理的一个显著限制是对 GPU 内存的巨大需求——将数十 GB 的静态模型参数加载到有限的 GPU 内存中，同时存储中间激活值和键值缓存（KV cache，用于存储注意力机制中计算的键和值，加速推理过程），这种方式效率很低。

像 **Apple Mac Studio[16]这样的设备可以支持高达 192GB 的统一内存，使其成为托管 LLM 的理想选择**。迄今为止，已有 2290 万块 Apple Silicon 芯片在流通[6]，而且这一数字还在上升。尽管 NVIDIA GPU 凭借其更高的计算利用率和专为 LLM 训练和微调中的批量处理设计的张量核心（tensor cores，一种专门用于加速矩阵运算的硬件单元，常见于 NVIDIA GPU）在市场上占据主导地位[17]，但:mdnice-bold-italic[当代的 Apple Silicon（参见第 2.1 节）却因报道的低 GFLOP（每秒十亿次浮点运算）数值而被忽视[33]，尽管它拥有大容量的统一内存。]

对于用于个人或小型用户群体的私人 LLM 服务工作站，有两个关键因素：

::: block-1
1. **推理速度** ——每秒生成的 token 数量；
2. **成本效益** ——单次推理能带来多大价值，用每 token 成本（$/token）衡量。
:::

在 LLM 训练和微调中，token 是以批量方式处理的，此时 GPU 凭借其超强的并行处理能力脱颖而出。LLM 推理是自回归的（autoregressive）：

::: block-1
- 在预填充（prefill）阶段，所有输入提示 token 被并行处理以生成第一个 token
- 但在解码（decode）阶段，每个后续 token 的生成都依赖于前一个 token
:::

在托管为多个并行请求提供服务的 LLM 引擎时（如在云服务器中），可以进行批量处理，但对于设备端推理场景中典型的单请求模型服务，解码确实是顺序进行的。

**更高的并行处理能力（即更高的吞吐量）本身并不能保证更快的 token 生成速度**，因为

::: block-1
1. :mdnice-bold-italic[对于单请求 LLM 推理，解码阶段受内存限制] [37]，在数据传输时，高效的计算单元会处于空闲状态；
2. 对于 700 亿到 4050 亿参数范围的超大型语言模型推理，一个挑战是将模型放入 GPU 显存（VRAM）中以高效处理；
3. 这对于当前显存有限（24GB-48GB）的消费级 GPU 来说是一个限制[50]。
:::

**一种解决方案是降低每次解码过程中的内存流量**，从而提高生成速度。LLM 模型的权重通常以高精度格式（FP16/FP32，16 位/32 位浮点数）表示，使用更少的比特来表示这些权重可以显著减少内存流量。**训练后量化** （PTQ，post-training quantization，在模型训练完成后对权重进行量化的技术）[61]在这方面表现出色，因为它能够在极低的每权重比特数下产生连贯的输出。但将通过量化实现的内存减少转化为延迟改善可能具有挑战性，因为这需要大量的工程努力[34]。

### 1.1 研究动机

我们的:mdnice-bold-italic[【动机源于】 Apple Silicon 提供的统一内存，其生成每百万 token 的成本更低] （参见第 4 节），这对设备端推理很有吸引力。

- 更大的内存池支持高效的数据交换、动态分配和减少开销（无数据重复）；
- 即使原始计算能力较低[36]，它也避免了显存相对较低的独立 GPU 可能遇到的、因缓慢卸载到系统内存而导致的性能损失。

这促使我们更深入地研究 Apple Silicon 的优缺点，并评估其作为设备端机器学习推理强竞争者的潜力。

### 1.2 目标

**目前对 Apple Silicon 上的 LLM 推理缺乏系统性理解** ——先前的工作主要集中在 LLM 训练[17]以及 NVIDIA GPU[40, 41, 44, 50]或 ARM CPU[31]上的设备端 LLM 推理。

> 为了填补文献中的这一空白，我们对 Apple M 系列设备在 26 种不同模型精度下的绝对运行时延迟、成本效益进行了系统性实证研究，并旨在理解硬件特性对效率的影响。

:mdnice-bold-italic[我们的观察结果以一系列“发现”的形式呈现]，供机器学习从业者在 LLM 服务中做出明智选择。我们确定了以下重要研究问题（RQ）：

::: block-1
- RQ1：Apple Silicon 对:mdnice-bold-italic[端到端 LLM 设备端推理的支持程度] 如何？
- RQ2：与 CUDA 等其他硬件加速器相比，Apple Silicon 是否是设备端 LLM 推理的**经济有效选择**？
- RQ3：Apple Silicon 上设备端推理的真正**硬件瓶颈是什么** ——:mdnice-bold-italic[硬件计算能力、DRAM 带宽限制还是反量化开销？]
:::

本文首次研究了 Apple 独特的内存架构及其对设备端 LLM 推理的影响。我们使用各种量化方案对多代 Apple Silicon 进行了自上而下的定量评估，以表征端到端性能并回答 RQ1（第 4.2 节）。

为了回答 RQ2，我们**与两种 NVIDIA 设备配置进行了比较**，:mdnice-bold-italic[评估了单 GPU 和多 GPU 设置以评估成本效益] （第 4.3 节）。我们**剖析了不同比特精度下模型的推理过程**，以确定性能瓶颈、资源利用率并回答 RQ3（第 5 节）。

### 1.3 发现总结

在当代消费级 GPU（NVIDIA、AMD 等）上，以可接受的延迟运行诸如 Llama 405B 之类的超大型模型是不可能的，但**在 Apple Silicon 上是可能的**，因为它提供了一个单一机器工作站，无需配置异构设备。

通过多项微基准测试，我们实证验证了在 Apple Silicon 上：

::: block-1
- 模型大小与推理速度不成正比——**2 比特模型可能比 1 比特模型更快** （参见第 4.2 节）。
- 随着模型参数规模的增大，Apple Silicon **相对于当代 GPU 的成本效益越来越高** （参见第 4.4 节）。
- 我们发现，Apple Silicon :mdnice-bold-italic[缺乏专用计算单元（类似于 CUDA 中的张量核心）限制了其性能] （参见第 5.5 节）。
- 此外，基于码本（codebook，量化中用于存储代表性向量的集合）的**量化方案显著减慢了 Apple Silicon 上的 token 生成速度**，这:mdnice-bold-italic[强调了量化设计需要与硬件架构相匹配] （参见第 5.4 节）。:mdnice-bold-italic[在低比特精度下，反量化 开销显著，此时 Apple Silicon 更多地受到算术操作而非内存带宽的限制] （参见第 5.5 节）。
:::

## 二、背景

### 2.1 苹果芯片（Apple Silicon）

苹果公司于 2020 年推出了其专有 M 系列系统级芯片（SoC）[2]，该芯片采用统一内存架构（Unified Memory Architecture，UMA），其中 CPU、GPU 和苹果神经网络引擎（Apple Neural Engine，ANE，苹果的神经网络处理单元，具有加速计算能力，但仅支持小型机器学习模型）:mdnice-bold-italic[紧密集成并共享一个大型内存池，减少了它们之间的数据移动开销] （参见图 1）。

![文章插图](/articles/2025-08-18-apple-silicon-llm-nvidia-gpu-380e51eb/images/06.webp)

相比之下，:mdnice-bold-italic[NVIDIA 的架构由离散 GPU 组成，其显存（VRAM）与主机内存分离[44]；这种设计旨在最大化原始计算吞吐量，尤其适用于大规模 LLM 训练所需的海量并行工作负载]。

> 由此产生了一个基本的权衡——苹果的集成和共享资源效率优势与专用 GPU 工作站的峰值**计算性能潜力之间的权衡。**

苹果用于 GPU 编程的主要 API 是 Metal[7]，它提供对其硬件的低级访问；对于 NVIDIA，相应的接口是 CUDA[29]。

### 2.2 设备端 LLM 推理

经过数万亿 token 训练的十亿级大规模语言模型（LLMs）能够提供高度类人的交互。由于其巨大的规模，这类大型语言模型通常托管在云服务器上，用户可以通过付费 API 访问。在消费级 GPU 上运行这些模型是不切实际的，除非对它们进行压缩，但这种压缩会以精度损失为代价。

量化可以通过利用更快的算术运算大幅减少模型大小和延迟[34]。

- GPU 擅长并行处理，非常适合批量进行的大规模 LLM 训练或微调。但推理通常处理少量并行请求，通常是单个批次/请求。
- 在推理过程中，**由于自回归解码，瓶颈会从计算转移到内存**，因为设备会闲置等待数据从主机传输过来[58]。

如果 GPU 内存不足以容纳所有模型参数，某些层会被卸载到 CPU[49]——这会引入额外的通信开销[17]。:mdnice-bold-italic[迄今为止，设备端 LLM 推理的研究主要集中 在 CUDA GPU[38,44,47]或 ARM CPU[31]上]。虽然已有一些研究试图表征苹果 GPU 的性能[33]，但它们并非专门针对设备端 LLM 用例。

### 2.3 量化

> 训练后量化（Post-training quantization，PTQ）[34]是一种流行的无损压缩模型权重至更低每权重位数（bits per weight，bpw）的技术，对于设备端推理非常有吸引力。

- 将全精度 FP32 的 Llama 405B 模型（内存为 1.6 TB）量化至 2 位，可将模型大小减少 11 倍。
- 对称和非对称
- 块量化（以 GPTQ[24]、QLora[19]、llama.cpp 的 K-quants[27]等为例）**将权重矩阵划分为固定大小的块（称为超级块，例如 32、64 或 256 大小），每个块有一个缩放因子和偏移量**；

在运行时，量化整数通过使用块特定的缩放因子和偏移量，或者在基于码本的量化情况下使用相应的码本条目来近似浮点值，从而进行反量化。

### 2.4 屋顶线模型（Roofline model）

> 屋顶线模型[58]将计算操作与硬件限制进行比较。它显示哪种资源限制了应用程序的吞吐量：

- 如果是内存受限（memory bound），则内核移动的数据更多（更大的权重）；
- 如果是计算受限（compute bound），则内核在算术运算（ALU 内部）上花费的时间更多。

算术强度（Arithmetic intensity，AI）量化了每移动 1 字节数据所执行的计算量，是量化这种行为的典型指标，**高 AI 意味着内核受计算限制，反之则受内存限制**。

:mdnice-bold-italic[在单批次推理的情况下，计算和内存受限之间的不平衡 所导致的内存墙 问题[37]极难解决]。

- 通常，预填充阶段（prefill）受计算限制，因为 token 是并行处理的；
- 解码阶段（decode）受内存限制[57]——加载到寄存器中的高维权重矩阵仅为单个解码 token 使用一次，导致计算单元未被充分利用。

尽管近年来高带宽 DRAM 已出现，但仍无法匹配供应商提供的 GPU 核心的高计算能力[28,46]，而这些 GPU 核心原本是为大规模训练设计的。

### 3.5 评估指标

我们从广泛的评估指标中进行选择：

1. :mdnice-bold-italic[每秒 token 数（Tokens per second，TPS），通过单请求推理期间每秒生成的 token 数计算]。与之互补的是每 token 延迟，即生成一个 token 所需的时间（在预填充或解码阶段，值越低越好）。我们交替使用这两个指标作为运行时吞吐量的度量。
2. :mdnice-bold-italic[每百万 token 成本，表示生成一百万 token 所需的美元金额] （值越低越好）。比较 CUDA 和 Metal GPU 的成本可能较为复杂，因为 Metal GPU 集成在完整的 Mac 桌面系统中，该系统包括存储和其他组件，提供更全面的即用型套餐——而 NVIDIA GPU 通常作为独立单元出售，不包含存储。作为粗略近似，我们按照[23]的方式报告每百万 token 成本。

$$
\$\$ / \text{1 M tokens} =\frac{\$ / \text{GPU_hour} * 10^{6}}{\text{TPS} \times 3600}
$$

我们将评估指标的选择与以下方面进行比较：

::: block-1
1. 模型运行时：预填充或解码；
2. 硬件特性：内存使用、算子粒度、性能限制器、开销和算术强度，以便全面了解苹果芯片上不同位精度的 LLM 工作负载。
:::

### 4.2 端到端延迟

- 2 位的 IQ2_M 是最慢的，处理速度为 57.33 毫秒/ token 。
- 4 位变体 IQ4_NL 的大小是 IQ2_M 的 1.73 倍，但运行速度快 1.21 倍。

**FP16 的 Llama 70B 在预填充阶段表现出最低延迟**。这可能看起来违反直觉——像 FP16 或 INT8 这样的高精度模型通常比量化变体占用更多内存，计算量更大。由于预填充的特性，模型权重在所有 token 中被重用，实现了高效的批次级并行性，因此内存带宽不是问题。:mdnice-bold-italic[原生 FP16 没有反量化开销]，且 INT8 能很好地适配 SIMD lanes（单指令多数据通道），确保高效利用，从而减少延迟。这些因素的详细分析在第 5 节中。

### 4.6 运行时成本总结

> 总之，我们在多个位精度下的细粒度运行时成本分析回答了 RQ1 和 RQ2：

#### （1）Apple Silicon 上的端到端延迟与模型大小相关吗？

我们驳斥了长期以来认为压缩模型权重必然会提高性能速度的观点。我们通过:mdnice-bold-italic[实证验证，推理延迟与模型精度不成正比，而是取决于用于压缩的量化方案。]

![文章插图](/articles/2025-08-18-apple-silicon-llm-nvidia-gpu-380e51eb/images/13.webp)

#### （2）与 CUDA 相比，Apple Silicon 在设备端推理方面是否具有成本效益？

基于我们在三种不同场景下的综合比较，:mdnice-bold-italic[Apple 工作站（M2 Max 和 M2 Ultra）被证明是最佳选择，并且对于更大参数的模型（图 7）越来越具有成本效益]。

在 CUDA GPU 上，随着模型规模的扩大，成本差距进一步扩大，如第 4.4 节中从 Llama 8B 过渡到 70B 时成本更高。M2 Ultra 可与 2xA6000 设置相媲美，使得 **Apple Silicon 在更高位精度的超大型语言模型（>=70B）方面具有竞争力。**

#### （3）Apple Silicon 统一内存的可量化优势是什么？

在当代消费级 GPU（NVIDIA、AMD 等）上，以可接受的延迟运行超大型语言模型是不可能的。**Apple Silicon 提供了一个单机器工作站，无需配置异构设备**。:mdnice-bold-italic[像 Llama 405B 这样的超大参数模型可以在 M2 Ultra 上以 1 位和 2 位精度运行]，但由于内存不足，无法在我们的任何 CUDA 配置上运行；添加更多 GPU 卡会不断增加每 token 成本。

![文章插图](/articles/2025-08-18-apple-silicon-llm-nvidia-gpu-380e51eb/images/21.webp)

:mdnice-bold-italic[如图 16b 所示，Apple Silicon 上的内存管理单元（MMU）在工作集大小较大时效率较低；FP16 显示出最差的空间局部性]，具有最高的 TLB（转换检测缓冲区，用于加速虚拟地址到物理地址的转换）未命中率（13%）和 MMU 利用率（6%）。**较低的 TLB 未命中率表明更好的内存局部性和性能**；然而，较低位精度的模型虽然未命中更少，但 MMU 利用率也较低。

> #### 发现#6：Apple Silicon 更青睐基于块的 K-quants，而非基于码本的 IQ 量化方案。

**原因：IQ 量化在 Apple Silicon 上明显较慢，但在 CUDA 上是标准的** （参见第 4.3 节）。在基于块的 K-quants 中，对于 16 个权重的块，只需要从内存（DRAM 或缓存）加载一个缩放和偏移值。由于其设计，在 IQ 量化中，除了加载每个块的这些缩放和偏移值外，将权重反量化到其近似值还需要每 8 或 16 个权重引用一个表，这很昂贵。这导致内存（加载/存储）指令增加。从 2 KB 到 16 KB 的表（即使来自 L1 缓存）的加载操作需要比直接在寄存器上执行的简单 ALU 操作更多的周期，例如，在具有 16KB 码本的 IQ2_M 和没有码本的 Q2_K 之间，前者慢 45%，这**表明引用码本会带来显著开销**。第 5.4 节中对底层 GPU 计数器的分析揭示了执行和内存单元的差异，反映了预期趋势线的偏差——某些 IQ 量化（如 IQ1_M/IQ2_M）由于大型码本，始终具有较低的计算利用率和较高的缓冲区使用（比其他方案高 30%）。

### 5.5 分析

#### 计算是瓶颈还是内存是瓶颈？

![文章插图](/articles/2025-08-18-apple-silicon-llm-nvidia-gpu-380e51eb/images/22.webp)

分析图 17 中的屋顶线模型（Roofline model，一种可视化硬件性能限制的模型），我们看到在 Apple Silicon 的解码流水线中，每个阶段的算术强度存在差异。整数密集型指针算术在确定算术强度方面起着关键作用[21]。

仅考虑简单的 FP32-FP32 矩阵操作是不准确的。总体而言，解码阶段受内存瓶颈限制，预填充阶段受计算瓶颈限制。**但 Metal GPU 还受到算术操作的限制**。在基于 VQ 的量化方案的每个反量化步骤中都有额外的内存查找。尽管额外的内存查找似乎会使它们更受内存限制，但事实恰恰相反。查找主要来自缓存（L1/L2 或共享内存），因此可以重用，并且获取的数据量很小（1 或 2 字节），因此全局内存读取访问不受影响，保持较高的算术强度。

> #### 发现#7：IQ 量化（如 IQ1_M）受计算操作限制。
>
> 由于其复杂性，IQ 量化需要更多的位解包步骤；这种位提取需要多个标量位移位和掩码操作。由于为 1 位精度模型加载的权重更小（即内存流量非常低），算术强度更高，将执行转向计算受限状态（图 17）。

![文章插图](/articles/2025-08-18-apple-silicon-llm-nvidia-gpu-380e51eb/images/22.webp)

反量化开销：当反量化开销的增长快于节省的带宽时，即使张量更小，延迟也会增加。因此，对于超低比特量化，减少反量化开销是主要目标。人们认为将权重加载到内存是瓶颈，而反量化和 FP16 计算的成本很小[37]，但我们发现对于超大型语言模型（Llama 70B）和 Apple 硬件，反量化开销可能是一个重要因素。

> #### 普遍观点：在解码期间，从内存加载模型权重是主要瓶颈[37]
>
> #### 发现#8：在 Apple Silicon 上，无论量化方案如何，反量化的成本都很显著。

（1）IQ 量化由于码本引用而产生延迟。（2）所有量化方案都面临由于位解包导致的反量化开销，有些方案更多——例如，Q6_K 内核的执行速度比 Q8_0 慢 1.22 倍（第 4.2 节），尽管数据流量更低（6.56 bpw vs. 8 bpw）。这是因为解包后的 INT8 权重可以平滑地适配 SIMD 通道，而解包亚字节位需要大量的位处理。因此，反量化+缩放开销超过了带宽节省，并成为主要瓶颈。

![文章插图](/articles/2025-08-18-apple-silicon-llm-nvidia-gpu-380e51eb/images/23.webp)

为什么 3 位模型的反量化开销高于 1 位模型？IQ1_M 的反量化开销高于 IQ3_S，因为从图 18 中量化内核的指令计数可以看出，前者有更多的操作、更多的分支和不规则的内存访问模式。在 IQ1_M 中，每 32 个权重计算一个增量校正位，再加上位解包，增加了开销。通过分析运行时着色器指令成本，我们发现具有更高解码开销的 IQ 量化在执行期间的等待时间比例更大——IQ1_M 为 26.29%，而 IQ3_S 为 19.24%。

位是如何打包的？现代 GPU 上的 ALU 数据路径和寄存器文件通常为 16 位或更宽（FLOAT16/INT16 256 位向量通道）。现有硬件无法原生存储 INT8 的分数部分；因此，为了表示不规则位（1/2/3 等），多个亚 INT8 位（代表多个值）被打包到一个 FLOAT16 中，随后通过位移位操作进行解包。规则位宽（如 4 位字段）可以干净地适配 16 位寄存器，没有浪费的位，而对于 1/3/5/6 位等其他位宽，额外的位存储在单独的字节中。

![文章插图](/articles/2025-08-18-apple-silicon-llm-nvidia-gpu-380e51eb/images/23.webp)

图 18 中的表格清楚地显示了这种模式：从 Q3_K_S 到 Q4_K_S（3 位到 4 位）仅导致 1.27%的延迟增加。然而，从 Q4_K_S 到 Q5_K_S（4 位到 5 位）导致延迟急剧增加 14.29%，尽管大小增加并不显著。从 Q2_K（2 位）到 Q3_K_S 和 Q4_K_S 的转换显示出类似的延迟增加（9.24%和 10.64%），这进一步表明无论方向如何，不规则位宽往往会增加更多开销。

> #### 发现#9：Apple Silicon 缺乏用于现代 ML 应用中常见的张量密集型工作负载的专用硬件单元，这阻碍了其性能并放大了反量化开销。

![文章插图](/articles/2025-08-18-apple-silicon-llm-nvidia-gpu-380e51eb/images/23.webp)

:mdnice-bold-italic[原因：由于位的打包方式，3 或 5 位等不规则位宽比规则的 4/8 位对齐需要更多的位移位、掩码和缩放操作]。从图 18a 中 Q3_K 和 Q5_K 的更高指令计数可以明显看出这一点。这种错位增加了处理复杂性，因此，从奇数位宽切换到偶数位宽（如 Q3→Q4）往往会导致较小的延迟增加，而从偶数位宽切换到奇数位宽（如 Q4→Q5）则显示出更大的延迟跳跃（参见图 18b）。偶数位精度（如 2/4/8，6 位除外）比奇数位（1/3/5）精度更受青睐。

#### 为什么 IQ1_M 在 M2 Ultra 上较慢但在 A6000 上较快？

A6000 也不支持不规则位宽，但由于张量核心提供高 INT8/INT4 吞吐量[59]，反量化开销在更快的计算中很大程度上被摊销/隐藏。M2 Ultra 缺乏专用的低位 MMA（矩阵乘法累加）单元[8]；IQ1 的位提取在通用 SIMD 整数/FP 流水线上执行，使反量化成为瓶颈。

#### 码本维度的影响

不同方案的码本维度不同：IQ1_M 存储 2048 个向量 ×8B（16KB），IQ2_S 使用 1024×8B（8KB），IQ2_XS 为 512×8B（4KB），IQ3_XXS 为 256×4B（1KB），而非线性_NL 量化只有 16 字节的元数据。

为了确定 IQ 量化中增加的延迟是由码本查找还是反量化所需的更高 ALU 周期驱动的，我们进行了两个对照实验：

::: block-1
1. 将 IQ3_XXS 的码本维度从 1KB 增加到 16KB（如 IQ1_M）。
2. 将 IQ1_M 的数据类型从 UINT32 减少到 UINT8。
:::

我们观察到，**当减少数据类型时，速度有一定显著的提升**；相反，当修改码本维度时，没有变化——这表明反量化开销是导致延迟的主要决定因素。

### 5.6 运行时瓶颈总结

我们发现，诸如量化方案的设计、反量化开销、内存带宽和模型架构等多个因素决定了一次前向传播所需的时间。

::: block-1
（1）吞吐量：在 Apple Silicon 中，吞吐量与每权重位数（bpw）不成正比，而是取决于量化方案的设计。因此，在运行时，推理受到较低吞吐量的瓶颈限制。

（2）ALU 操作成本：由于缺乏专用核心，Apple Silicon 中的 ALU 操作未融合，因此需要更多的 ALU 周期来执行指令。IQ 量化中的额外内存操作增加了推理成本。

（3）不规则位在 Apple Silicon 上效率更低，因为它们需要更多的指令来解包，并且解包后的位与 8 或 16 位 SIMD 通道不对齐。

（4）内核是否被充分利用？观察 ALU 和缓冲区加载利用率，发现有改进当前内核以适应 Apple Silicon 的空间。
:::

## 六、算法硬件优化建议

### 对于机器学习从业者

某些量化方案特别适合 Apple Silicon，在部署端侧模型时可加以考虑。

::: block-1
1. 在内存消耗相近的情况下，块基 K 量化（K-quants）在 Apple Silicon 上的推理速度、困惑度（perplexity，衡量语言模型预测能力的指标）和成本效益方面均优于码本基 IQ 量化（IQ-quants）。下图 19 报告了模型的困惑度。![文章插图](/articles/2025-08-18-apple-silicon-llm-nvidia-gpu-380e51eb/images/24.webp)
2. 如果可以接受精度的轻微下降，对于无法容纳 4 位精度模型的 Apple 设备，我们推荐 2 位精度的块基量化（Q2_K）。
3. 如果模型能装入内存，传统量化方案（如 Q4_0、Q8_0）更优，在 Apple Silicon 上应优先选择这些方案，而非 Q3_K 或 Q5_K 等非规则位宽的量化方案。
4. 我们推荐 IQ4_NL，因为它比 2 位精度量化具有更高的精度。机器学习社区或许值得探索低于 4 位精度的_NL 量化方案。
:::

### 对于硬件供应商

为缩小与主流 GPU 供应商的性能差距，可从以下方面改进：

::: block-1
1. 有充分理由在 Apple Silicon 中集成专用核心，类似张量核心（tensor cores，NVIDIA GPU 中专为大规模深度学习计算优化的硬件单元），以优化大规模 LLM 工作负载；现有 ANE（Apple Neural Engine，苹果神经引擎）容量有限，不适合此类工作负载。
2. 在 Apple Silicon 中原生支持低精度运算（如 INT4/FP8），将使子字节精度模型能直接在硬件上运行。
3. Apple Silicon 的底层内核文档大多闭源，阻碍了开发者在指令集架构（ISA）层面优化内核。
4. 需提高 Apple Silicon 的计算预算，尤其是加快标量整数 ALU 指令的处理速度——这将消除 IQ1_M 等量化方案的主要瓶颈（此类方案受计算限制）。
:::

## 七、相关工作

近期研究探索了利用 Apple Silicon 的统一内存系统和内置加速器支持多种计算任务，包括简单分类算法[52]、科学计算[33, 36]和数值模拟[25]。

::: block-1
- 文献[53]报告了其推理框架在 **M4 Pro 上的预填充（prefill）时间改进**。
- 文献[40]综述了在 **CPU、GPU、FPGA、ASIC 和 PIM/NDP 等多种硬件平台上的高效生成式 LLM 推理**，但未涉及 Apple Silicon。
:::

量化大语言模型的部署本质上具有挑战性，因为反量化（dequantization）带来的开销既是硬件限制，也是算法瓶颈[41]。

::: block-1
- QServe[41]尝试通过 CUDA GPU 上的寄存器级并行性减轻 INT4 量化中的反量化开销。
- 现有多种量化算法[24, 37, 43, 54]，其反量化复杂度各不相同。
:::

以往关于量化方案的研究[22]主要关注其对模型困惑度的影响，而:mdnice-bold-italic[本工作强调硬件特性 如何影响 Apple Silicon 上多种量化方案的效率。]

## 八、结论

> 我们对 Apple Silicon 进行了全面评估，以理解其硬件特性及对端侧 LLM 推理的影响。

我们**将其性能与同价位的** 当代 NVIDIA GPU 进行基准测试，证实其在超大型语言模型的端侧推理方面具有优势。我们的研究得出了多项关键见解，并**为机器学习从业者和硬件设计者提供了实用建议**，帮助他们:mdnice-bold-italic[根据不同位精度做出硬件感知的模型选择。]

通过对 Apple Silicon 的细粒度、底层剖析，我们解释了性能差距的原因。
