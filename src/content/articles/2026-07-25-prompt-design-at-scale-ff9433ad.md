> 在日常的大模型应用开发里，有两个极其高频的设计决策，至今几乎没有严谨的对照实验给出定论：

- 一是**提示词的呈现格式**：给模型的指令和参考资料，用 Markdown、纯文本、连贯散文还是表格来写，效果最好？
- 二是**规模边界**：单轮对话里最多能给模型塞多少条并行指令？上下文窗口拉到多长时，模型的记忆力和诚实度会开始崩塌？

> 核心结论一句话概括：**一种格式好不好用，完全取决于它承载了多少条指令、放在多长的上下文里**，脱离规模谈“最优格式”没有任何意义。

10条指令时，Markdown和纯文本表现几乎没有差别；100条时两者差距急剧拉开。

2000 token上下文里，表格和段落的召回效果一致；拉到50万token时，两者表现天差地别。

- **实验一（指令数量维度）**：当并行规则增加到80条时，五款被测模型的**完美响应率全部归零** ——完美响应率指的是所有规则都被严格满足的回答占比。:mdnice-bold-italic[这一结果在四种格式（Markdown、纯文本、散文、表格）、两种指令放置位置（系统提示/用户轮次）下完全一致]。*注：纯文本即剥离所有Markdown标记后的内容；散文指把实体的键值对描述整合成连贯段落、不强制换行。*
- **实验二（上下文长度维度）**：:mdnice-bold-italic[召回准确率在64k~128k token以内基本维持满分，超过这个区间后，不同格式的表现开始分化崩塌]。真正随上下文长度飙升的是**直接拒答率**，从0%一路涨到79%~90%。

> 基于实验结果，论文提炼了五条可直接落地的提示词设计指导原则：

| 指导要点 | 具体说明 |
| --- | --- |
| 无通用最优格式 | 最佳格式与模型强相关，不存在跨模型通用的答案。例如Qwen 35B明确偏好纯文本，换另一款模型则可能完全相反。 |
| 指令放置位置影响显著 | 同一份指令放在系统提示或用户消息中，遵守率波动最高可达8.7个百分点（N=160时），且影响方向无法提前预判，必须针对目标模型实测。 |
| 单轮指令设40条为警戒线 | 所有模型在指令数达到40条后性能进入陡坡，80条时几乎完全触底。超限时应拆分为多轮交互、工具调用或后置校验，而非继续打磨单条提示词。 |
| 长上下文优先监控拒答率，而非幻觉 | 实验中事实捏造率为0，谄媚率低于8.3%，但拒答率最高达89.6%。只监控“答错”会忽略长上下文下最高发的故障：模型直接选择不回答。 |
| 成本校正仅在准确率有差距时有意义 | 若不同格式准确率接近，选token开销最低的即可；当准确率出现明显差距时，22%~37%的token开销差足以反转性价比排名，需要单独测算。 |

## 一、实验一：80条规则下，五款模型全部触底归零

> 实验设计非常朴素：让模型写一篇短文，同时遵守N条可被程序自动校验的输出规则（字数区间、必选词、禁用词、精确的首尾句、段落数量等）。指令数N从10逐步增加到160，交叉四种格式、两种放置位置，五款模型累计完成4800次有效测试，全程用正则匹配打分，没有用LLM当裁判，结果完全可复现。

![文章插图](/articles/2026-07-25-prompt-design-at-scale-ff9433ad/images/03.jpg)

::: image-caption
表4：按模型与指令数N统计的完美响应率（合并所有格式与放置位置）。N=10时各模型完美响应率在0.588~0.938之间；N=40时已跌至0.094~0.312；从N=80起全部归零，并一直保持到N=160。
:::

这是一块**坚硬的地板效应**，而非平缓下降的渐近线：性能在N=40附近就已进入陡坡，到N=80彻底触底。对工程实践的指导非常直接——把40条并行指令当作设计警戒线，超过这个量级后，再在单条提示里打磨措辞、优化排版，收益基本可以忽略。

![文章插图](/articles/2026-07-25-prompt-design-at-scale-ff9433ad/images/04.webp)

::: image-caption
图1：完美响应率随指令数N的变化曲线，按格式分色、按模型分面，合并两种放置位置。五款模型在N=80时全部收敛至零，与格式无关。
:::

观察曲线能发现一个反直觉细节：每个分面里，四条格式曲线几乎是纠缠在一起同步下降的。这说明在“指令数量”这条规模轴上，格式的影响微乎其微，真正决定性能的是指令总数N本身。换句话说，当你的系统提示已经堆到80条规则时，换排版、换结构都救不回来。

> 整条衰减曲线可以用logistic函数拟合：
>
> $$
> P(N) = \frac{1}{1 + e^{k(N - N_0)}}
> $$
>
> 其中P(N)是指令数为N时的遵守概率，k控制下降的陡峭程度，N₀是拐点（遵守率降到50%时对应的指令数）。

- Claude Haiku将指令放在系统提示中时，拐点N₀≈98
- Gemini Flash将指令放在用户消息中时，拐点N₀≈46

同一份规则集，仅仅换了放置位置，拐点就能差出一倍以上，可见放置位置的影响有多大。

这场实验也给Markdown万能论盖了棺：**五款模型里没有任何一个展现出稳定、显著的Markdown优势**。唯一清晰的方向性信号反而指向纯文本——Qwen 35B在六档指令数里有五档都更适配纯文本。

反而是“指令放哪里”成了容易被忽略的杠杆：把同一块规则从系统提示挪到用户轮次，五款模型里有四款出现了统计显著的遵守率变化，幅度不亚于格式调整，但影响方向完全因模型而异。

![文章插图](/articles/2026-07-25-prompt-design-at-scale-ff9433ad/images/05.webp)

::: image-caption
图2：N=160时不同放置位置的遵守率对比。用户轮次放置对Claude Haiku（+6.6个百分点）和Qwen 35B（+5.1）有提升，对Gemini Flash（−8.7）和Qwen 27B（−1.8）反而有害，对Sonnet 5无显著影响。
:::

::: block-1
实验一核心结论： 指令遵循存在与格式无关的硬上限——N=80时完美响应率归零；Markdown没有普适优势，反而有模型明确偏好纯文本；指令放置位置是低成本优化点，效应量级不输格式，但方向因模型而异，必须实测。
:::

## 二、实验二：512k上下文阶梯上，幻觉没来，拒答先来了

> 为了彻底排除预训练数据污染，作者构建了完全虚构的合成语料库“维拉之书（Book of Veyra）”：包含8780个唯一命名的虚构实体，通过固定种子+确定性模板生成，逐字节可复现，天然不会出现在任何模型的训练数据里。

这份语料被切成2k、16k、64k、128k、256k、512k共六个档位的上下文阶梯（下一档完整包含上一档的内容），每一档都渲染成四种格式，分别测试三类探测问题：事实召回、错误前提验证、不存在事实询问。五款模型累计完成30480次有效响应。

语料设计也做了精细控制：实体名全局唯一，保证每题只有一个正确答案；实体属性值刻意设置重叠，制造记忆干扰；所有计分的探测点都是“不读原文根本猜不对”的取值，把瞎猜的基线压到接近零。

> 在2k、16k、64k三档上下文里，所有模型、所有格式的召回准确率都在0.98~1.00之间，格式几乎没有区分度。真正的差距从128k开始出现，并随上下文加长逐级放大。

![文章插图](/articles/2026-07-25-prompt-design-at-scale-ff9433ad/images/06.jpg)

::: image-caption
表7：存在显著格式差异的模型-档位组合的召回准确率（每格60题）。
:::

最刺眼的一组数据来自Claude Haiku @ 128k：纯文本格式下召回率直接崩塌到38.3%，而另外三种格式都稳定在82%~87%，单一格式造成了48.4个百分点的准确率鸿沟，也是全数据集里最大的分差。

另一个关键发现是：**格式差距的大小，只和“距离模型自身有效天花板的远近”相关，和绝对token数无关**。同样是标称100万token上下文窗口，Sonnet 5的格式间差距从256k的11.7个百分点扩大到512k的20.0个百分点，而Gemini Flash在同一区间只从5.0涨到6.7个百分点。标称上限相同的模型，实际能力的“高墙”硬度完全不同。

![文章插图](/articles/2026-07-25-prompt-design-at-scale-ff9433ad/images/07.webp)

::: image-caption
图3：召回准确率随上下文长度的变化曲线，按格式分色、按模型分面。两款长上下文模型测至512k，其余三款测至自身窗口上限。
:::

曲线的共性很明显：在模型有效窗口的前半段，所有格式都贴着天花板走，格式之争纯属内耗；只有逼近各自的能力天花板后，四条曲线才会像扇子一样散开，且散开的形态每个模型都不一样。这直接证伪了“存在跨模型通用的长上下文最佳格式”的流行假设。

> 三类探测问题中，有两类的结果干净得出人意料：

- 面对5760次“答案不在文中”的提问，**没有任何模型编造过一次具体答案**，捏造率严格为0；
- 面对包含错误前提的提问，模型直接谄媚附和的比例最高仅8.3%，绝大多数档位都在3%以下，全数据集仅有的19条附和回复都经过人工逐条核验。

上下文拉长后，真正大幅上升的是**直接拒答**：模型越来越倾向于回复“信息不足”，既没有纠正错误前提，也没有被错误前提带偏。

![文章插图](/articles/2026-07-25-prompt-design-at-scale-ff9433ad/images/08.jpg)

::: image-caption
表 8：错误前提探测下的拒答率。Claude Haiku从2k时的0%攀升到128k上限处的89.6%；Sonnet 5到512k时达到78.8%。同一段爬坡过程中，谄媚率始终贴近零。
:::

这意味着，如果你的系统只监控“答错”或“附和错误”，会完美错过长上下文窗口顶部最高发的故障——模型干脆不回答了。

![文章插图](/articles/2026-07-25-prompt-design-at-scale-ff9433ad/images/09.webp)

::: image-caption
图4：拒答率随上下文长度的变化。五款模型在逼近自身能力上限时，拒答率都齐刷刷抬头。
:::

论文对此给出了一个很有启发性的推测：当前对齐训练会严厉惩罚“自信的错误答案”，在不确定的场景下，选择拒答就成了模型更安全的默认策略。**幻觉风险被置换成了拒答风险**，零捏造的漂亮数据背后，可能一部分是模型真的不会瞎编，另一部分只是模型被训练得不敢说话了。

> 实验设计里还有一个非常巧妙的校验机制：锚点集。
>
> 作者从2k档位里固定抽出20道题组成“锚点集”，之后每一个更大的上下文档位，都把这完全相同的20道题原封不动再问一遍。这样就能区分：跨档位的准确率变化，到底是上下文长度带来的真实效应，还是单纯因为每档的题目难度不一样。

这个校验抓到了两类情况：

- **假阳性波动**：Gemini Flash的主测试集里，Markdown格式召回率从256k到512k看似从0.900涨到了1.000，但锚点集显示两档其实都接近满分，所谓“提升”只是主测试集的题目变简单了，是假象；
- **真结论验证**：论文最核心的两个跨档位发现——**格式优劣排名随上下文长度反转、拒答率随上下文变长攀升**，都通过了锚点集的复核，是真实存在的效应，而非题目差异导致的误差。

::: block-1
简单说，锚点集既排除了虚假的性能波动，也保住了核心结论的可信度，让所有跨上下文长度的对比都真正做到了“苹果对苹果”。
:::

## 三、没有常胜的提示词格式，还要算一笔token成本账

> 实验开始前，作者预设了两个假设：要么“结构本身有用”（Markdown、散文、表格都优于纯文本），要么“表格特异有用”（键值查询任务和表格形式最匹配）。

结果内容完全一致的四组对照（Markdown、纯文本、散文、表格），把两个假设一起推翻了：

- 被两个假设都预测会垫底的散文格式，在五个关键测试组合里拿了三个最佳或并列最佳；
- 纯文本在Claude Haiku @ 128k时是最差的（38.3%），到了Sonnet 5 @ 512k时反而成了唯一最佳（86.7%）。

没有任何一种格式能通吃所有模型、所有上下文长度，排名反转是常态。

除了准确率，还要算一笔格式带来的token开销账：相对于纯文本，Markdown的token开销是1.258倍，散文是1.221倍，表格是1.367倍。用原始准确率除以开销倍数，就能得到**成本校正准确率**：

$$
A_{\mathrm{adj}} = \frac{A_{\mathrm{raw}}}{c}
$$

其中$A_{\mathrm{raw}}$是原始召回准确率，$c$是相对于纯文本的token开销倍数（纯文本自身$c=1$）。

举个最直观的例子：Claude Haiku在128k上下文时，散文和表格的原始准确率都是0.867，单看准确率打成平手。但计入token成本后：

- 散文：0.867 / 1.221 ≈ 0.710
- 表格：0.867 / 1.367 ≈ 0.634

平局直接被成本打破，相同准确率下散文的性价比明显更高。

而在 Sonnet 5 @ 512k的场景里，纯文本不仅原始准确率最高，token 成本还最低，优势被进一步放大。这背后的原因也和拒答率相关：极端上下文压力下，纯文本格式触发的拒答更少，表观召回率自然更高。

## 最后：五条可落地的实践建议

1. **不要默认Markdown就是最优解**，也不要迷信任何一种通用格式。上线前务必针对你实际使用的模型做测试，换模型就必须重测。
2. **试试调整指令的放置位置**，这是几乎零成本的优化点，效果可能不亚于调整格式，但方向无法预判，实测是唯一办法。
3. **单轮指令控制在40条以内**，超过80条再怎么优化格式都没用。更靠谱的方案是拆分多轮、加工具调用、加后置校验。
4. **长上下文系统重点监控拒答率**，不要只盯着幻觉。越接近窗口上限，模型越容易“闭嘴不答”，这才是最高发的失效模式。
5. **只在准确率有明显差距时，再去算成本账**。大家都接近满分时，选最便宜的格式就行；出现显著分差时，token开销足以反转性价比，值得单独测算。
