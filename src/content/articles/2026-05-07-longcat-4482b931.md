## 一、时代背景：大模型基础设施的三大核心痛点

> 2025 年前后，千亿级 MoE 大模型虽全面爆发，但行业普遍面临三大难以绕过的工程难题：

- **训练层面**，万卡集群稳定性差、浮点数值误差难以根除、训练周期长且故障恢复缓慢，超大规模训练的复现性几乎成为奢望。
- **推理层面**，MoE 架构的 All-to-All 通信开销巨大、KV-Cache 随长上下文急剧膨胀、延迟与吞吐量往往顾此失彼，使大模型难以落地实时交互场景。
- **多模态层面**，视觉和音频编码器与 LLM 主干的算力特征截然不同，异构组件串行调度导致严重的流水线气泡，多模态训练效率远低于纯文本。

::: block-1
美团 LongCat 团队的三次迭代，本质上是用模型-系统协同设计的思路，逐一攻克这三大痛点，最终在**数万张 H800 加速卡** 上达成“560B 总参、平均激活 27B、30 天完成 20 万亿 Token 训练、推理超百 Token 每秒、多模态训练保持纯文本九成以上吞吐”的业界领先水准。
:::

## 二、第一代：LongCat-Flash —— 文本 MoE 基座的基础设施奠基

LongCat-Flash 是 LongCat 家族的首款模型，560B 参数规模的 MoE 架构，平均每 Token 仅激活约 27B 参数。:mdnice-bold-italic[其核心目标明确而聚焦：打造一个高效、稳定、可复现且推理成本极低的文本基座。围绕这一目标，训练和推理两套基础设施完全围绕 MoE 架构的训练稳定性与推理通信-计算重叠展开设计。]

### 训练基础设施：万卡级确定性训练体系

> 训练基础设施的核心设计原则可概括为三点：可扩展性、数值精确性与高可用性。**在数万张 H800-80GB GPU 的规模上**，这套体系实现了近线性的扩展效率、98.48%的有效训练可用性，以及 30 天内完成超 20 万亿 Token 训练的工程壮举。:mdnice-bold-italic[报告明确指出，其分布式策略中的专家并行组（EP Group）每个由 32 个加速器构成，这种精细的组网粒度为实现高效的多维并行提供了物理基础。]

大规模分布式训练中，数值误差与静默数据损坏（SDC）是导致模型隐性崩解、训练徒劳无功的元凶。LongCat-Flash 为此构建了全链路的精度保障机制。**团队采用 ULP 作为统一度量，以 CPU FP32 为真值量化加速器 BF16 运算的偏差程度，从根源上严控各类算子的浮点误差**。

![文章插图](/articles/2026-05-07-longcat-4482b931/images/02.webp)

::: image-caption
对比两种方案在 8 种 GEMM 场景的 ULP 误差精度对比中，方案1代表某种常规或默认的GEMM算子实现，而方案2则代表了经过确定性优化或采用定制底层指令流水线编排的GEMM实现，ULP (Unit in the Last Place) 误差被用来衡量每种方案通过BF16计算得到的结果与CPU FP32参考基准之间的偏差。这里根据原始Flash论文中的信息，我们可以从数据的对比中得出进一步的分析结论：从整体精度控制的稳定性来看，方案2在所有测试案例中的最小ULP误差绝对值普遍小于方案1，且最大ULP误差也表现出更强的一致性，这证明方案2通过优化计算顺序与内存I/O所实现的确定性计算流水线，显著抑制了浮点累加过程中的误差累积；在大尺寸矩阵乘法（如案例3的[1024,16384]及案例7的[1024,131072]）场景下，方案1的最大ULP值分别剧烈攀升至544和8128，远超方案2对应的22和2528，这揭示出常规实现方案在面临超大规模矩阵运算时，极易由于非顺序的原子加归约操作引发严重的非确定性数值漂移。正如 Flash 原论文所强调的，GEMM的计算误差不仅源于单次运算精度的损失，还会受到加速器代数库实现机制和Wave调度策略等多重因素的复合影响：采用方案2这类具备高精度及强确定性特点的GEMM实现，是控制大规模并行训练中的数值偏差、保障模型收敛一致性以及在扩展至数以万计的加速器后避免因算子误差放大而导致模型最终性能失真的重要基础。
:::

与此同时，针对 FlashAttention 梯度计算对 SDC 高度敏感的特性，团队设计了一套片内原位算子重算机制——在空闲计算阶段嵌入检测逻辑，通过重算结果的位级差异识别潜在风险，且重算间隔可灵活配置，在检测覆盖率和额外计算开销之间取得可控平衡。

::: block-1
更关键的是，团队将确定性确立为计算正确性的黄金标准。所有计算与通信算子强制实现确定性执行，确保同一训练步多次重跑时损失值达到位级对齐，从根本上解决了大模型训练难以复现的行业顽疾。
:::

> 为追求确定性而不牺牲效率，LongCat-Flash 在底层内核上进行了深度重设计。

- 针对原生 FlashAttention 梯度（FAG）因原子加法无序导致的非确定性，团队开发了确定性 FAG 内核，利用有限额外工作空间按确定性顺序累加 Tile，配合双缓冲流水线与精细调优的 Tile 调度，**最终达到原生非确定性版本 0.95 倍的性能，是原始确定性版本的 1.6 倍**。
- 针对反向传播中 ScatterAdd 算子因操作数不匹配引发的严重减速，团队提出分层归约算法，在所有可用处理器上并行聚合梯度，彻底解决了最高达 50 倍的性能损失，实现与非确定性版本持平的性能。
- 在计算密集的 Grouped GEMM 上，通过双缓冲流水线、对角线 Tile 调度和 HBM 带宽精准控制，**实现了 5%至 45%不等的加速**；而 Fused GemmAdd 融合算子将 FP32 加法直接嵌入 GEMM 尾声，消除中间写回，**加速比高达 3.12 至 3.86 倍。**

> 分布式策略上，LongCat-Flash 构建了以专家并行（EP）为核心的多维并行体系。

- 每个 EP 组由 32 个加速器构成，组内注意力层采用上下文并行（CP=8）替代张量并行（TP）以压缩通信开销，FFN 层则纯 EP 切分。
- 多 EP 组之间再沿流水线并行（PP）和数据并行（DP）维度扩展。尤为关键的是 Shortcut-connected MoE 这一架构创新——将 MoE 层沿 Token 维度拆为两个子块，使 All-to-All 通信能够同时与密集 FFN 计算重叠，且两个子块的通信与计算也能彼此重叠。这一设计将无法被掩盖的通信时间占比从 25.3%压缩至 8.4%，效率提升显著。
- 在流水线调度上，团队采用 V-ZB 算法，使所有流水线阶段内存均衡，训练峰值内存压至**60GB** 以下（**远低于 H800 单卡 80GB 的物理上限**），并通过对优化器状态回滚时以备份数据替代逆运算的精巧改进，严格保持了数值位级对齐。

在可靠性与可观测性方面，异步 Checkpoint 机制将训练停顿控制在 2 至 4 秒，使高频保存成为可能，最大程度缩小了故障带来的训练进度损失。配合在线关键日志过滤和优化初始化，故障恢复时间缩短至 10 分钟以内，20 次集群故障全部实现自动化无人干预处理，最终整体可用性达到 98.48%。在可观测层面，细粒度的 PyTorch Profiler 时间线可精确定位流水线气泡和跨节点通信等待，粗粒度监控则以极低开销分析拖慢节点，指标平台则实时追踪损失、权重、梯度和激活值，为模型状态提供快速评估窗口。

### 推理基础设施：百 Token 级低成本推理引擎

> LongCat-Flash 的推理设计目标同样清晰——**在 H800 集群上达到每秒 100 Token 的生成速度，同时将每百万输出 Token 成本控制在 0.7 美元以内**，以支撑 Agent 场景下的实时工具调用。整套推理体系是模型-系统协同设计的典范。

针对 MoE 推理中通信开销巨大的核心瓶颈，团队设计了四阶段的 Single Batch Overlap（SBO）调度策略，实现了模块级的计算与通信重叠。

![文章插图](/articles/2026-05-07-longcat-4482b931/images/03.webp)

::: image-caption
该图呈现 LongCat-Flash 的 SBO 四阶段流水线重叠策略，整合 MLA、调度、通信、计算全模块协同。该策略在单批次内隐藏 MoE 通信开销，阶段 2 重叠 all-to-all 调度与密集 FFN、注意力 QKV 投影，阶段 4 重叠注意力核心计算与 all-to-all 合并，搭配 GPUDirect RDMA 优化带宽，彻底破解 MoE 推理通信瓶颈，实现低延迟与高吞吐兼得。
:::

> 与业界常见的双批次重叠（TBO）方案不同，SBO 在单个批次内即完成全部重叠编排：

- 第一阶段 MLA 独立执行并输出后续所需中间结果；
- 第二阶段将 All-to-All Dispatch 与密集 FFN 及注意力 QKV 投影重叠；
- 第三阶段 MoE GEMM 独立执行，受益于宽 EP 部署的低延迟；
- 第四阶段则将核心注意力计算、输出投影及密集 FFN 与 All-to-All Combine 重叠。

配合 GPUDirect RDMA，实现节点内 NVLink 带宽与节点间 RDMA 通信的并行利用，最大化整体带宽效率。

> 在解码加速方面，LongCat-Flash 采用 MTP 作为草稿模型进行推测解码，并从三个维度系统优化加速效果。

- 为提升接受率，预训练后期集成单个 MTP 头，测试集接受率约达 90%；
- 为降低草稿模型开销，采用轻量级单密集层架构，在延迟上优于 ScMoE 层；
- 为减少验证开销，引入 C2T 方法，在正式验证前以分类模型预先过滤掉低接受概率的 Token。

![文章插图](/articles/2026-05-07-longcat-4482b931/images/04.webp)

::: image-caption
对比典型 MoE、ScMoE、分块 ScMoE 三类架构，三者专家总量与激活量完全相同。分块 ScMoE 将 MoE 层沿 token 维度拆分为两个子块，实现子块与密集 FFN 计算、子块间的双重重叠，把非重叠调度通信占比从 25.3% 降至 8.4%，大幅削减通信开销，是模型训练与推理效率跃升的核心架构设计。
:::

注意力机制层面，LongCat-Flash 采用 64 头 MLA 设计，类 MQA 结构跨维度共享 KV，实现了极致的 KV-Cache 压缩，显著减轻了长上下文场景下的存储与带宽压力，同时该结构与 WGMMA 指令的形状天然对齐，可实现最大化硬件利用率。

> 在系统级优化上，三项技术形成了合力。

- 多步重叠调度器将单次 CPU 调度扩展为多步 GPU 前向的批量下发，将调度与同步开销完全隐藏在 GPU 计算过程中，同时通过数学归纳法严格证明了多步之间动态预分配 KV Cache 的安全性和收敛性。

![文章插图](/articles/2026-05-07-longcat-4482b931/images/05.webp)

::: image-caption
以 4 步为例展示多步重叠调度器运行逻辑，CPU 单次调度迭代发起 GPU 多步前向计算内核，将调度与同步开销隐藏在 GPU 计算中。该设计解决轻量 MTP speculative decoding 的内核启动瓶颈，通过数学归纳保证 KV 缓存安全分配与大小收敛，让 GPU 持续满负载，进一步挖掘推理执行的性能潜力。
:::

- 自定义内核方面，MoE GEMM 采用 SwapAB 技术，将权重作为左矩阵、激活作为右矩阵，利用 N 维度 8 元素粒度的灵活性显著提升 Tensor Core 利用率；通信内核则直接调用 NVLink Sharp 的硬件加速广播与原位归约指令，仅用 4 个线程块即在全消息尺寸范围超越 NCCL 与 MSCCL++。
- 量化方案沿用细粒度分块策略，激活按每[1,128]块、权重按每[128,128]块分别量化，并在层级别实施混合精度，通过结合 FPTQ 方法和分块 FP8 误差分析精准定位敏感层，在精度与性能之间实现最优权衡。

在部署架构上，LongCat-Flash 采用预填充-解码分离（PD-Disaggregated）方案，最小部署单元为**2 节点 16 卡 H800-80GB**。通过层间传输 KV-Cache，在高 QPS 负载下显著压缩首 Token 延迟。宽 EP 部署配合改进版 DeepEP 和 EPLB，原生支持零计算专家——其输出无需任何通信即可直接获取，进一步降低了系统开销。

![文章插图](/articles/2026-05-07-longcat-4482b931/images/06.webp)

::: image-caption
不同配置下 LongCat-Flash 的性能。对比 LongCat-Flash 与 DeepSeek-V3 在 bf16/fp8、不同上下文长度的 TGS、TPS/u 性能。LongCat-Flash 在 128 张 H800、5000 上下文下，bf16 模式 TPS/u 最高达 100.5，fp8 模式 TGS 达 4230，全面超越竞品。量化与架构协同优化，让模型推理速度领先且成本可控，百万输出 token 推理成本仅 0.7 美元。
