关键词：:mdnice-bold-italic[确定性 LLM 推理]、**形式化验证**、KV 缓存、推理引擎、**位级一致性**

> “GPU 内核根据执行形状动态选择分块策略（tilings）与规约顺序（reduction orders），而浮点运算结果则对最终形成的算术操作顺序具有敏感性。”这是杜克大学团队在论文中指出的 LLM 推理不确定性的核心根源。

在今天的生产级 LLM 推理系统中，为了提升吞吐量和资源利用率，调度器会动态调整批处理组合、提示词分块大小、预填充与解码执行方式，同时 KV 缓存会进行复用、淘汰与重计算。**这些优化本应只影响性能，不改变模型输出，但实际情况并非如此。**

::: block-1
现有生产系统中的确定性模式，**比如 vLLM 的批不变量模式与 SGLang 的确定性模式，都只针对批处理这单一变量进行优化，缺乏系统级的形式化规范**，:mdnice-highlight[在分块预填充、预填充-解码切换、前缀复用等场景下，仍然会出现 logits 不匹配的问题。]
:::

> 论文首先形式化定义了确定性 LLM 推理：在固定模型与部署配置下，相同提示词与初始采样器状态的请求，在任意执行路径下的对应输出位置，都会产生位级完全一致的 logits。基于这个定义，**团队设计实现了 Vosti 推理引擎，采用引擎层与内核层双层验证架构，引擎层用 Verus 归纳证明调度与 KV 缓存的不变性，内核层用 Triton 分析器与 Z3 证明跨执行场景的内核输出位级一致。**

![文章插图](/articles/2026-10-05-vosti-llm-7ba23ea6/images/02.webp)

::: image-caption
图 1：Vosti 推理系统与双层验证框架。该图展示了 Vosti“引擎层 + 内核层” 的分层验证范式，是其实现全链路确定性的核心架构设计。Verus 验证层假设共享内核契约成立，内核验证器负责证明这些契约的正确性。上层 Verus 验证聚焦调度、KV 缓存管理等系统逻辑，通过维护 KV 缓存不变式、请求不变式等，归纳证明每个引擎步的输出仅由请求的 token 历史决定，与批量大小、调度顺序无关。下层内核验证针对 Triton 算子，证明不同输入布局下对应输出按位相等。两层通过标准化的内核契约衔接，引擎层将内核视为黑盒调用其保证，内核层专注于算子级等价证明，既降低了整体验证复杂度，又实现了从系统调度到底层运算的完整确定性覆盖。
:::

测试显示，Vosti 在 7 个 Llama 与 Gemma 模型的 5488 项位级对比测试中全部通过，覆盖批处理、分块预填充、预填充-解码等价与前缀复用所有场景。**性能上，在 H200 GPU 上，Vosti 的解码吞吐量达到 vLLM 批不变量模式的 1.36-3.19 倍，在合成智能体工作负载下会话完成时间快 1.14-2.20 倍**，同时提供了更强的形式化验证确定性保证。
