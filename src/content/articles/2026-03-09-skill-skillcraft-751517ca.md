## 一、引言

> “一个系统的智能程度，取决于其在一系列任务中获取技能的效率，这与先验知识、经验以及泛化难度相关。” ——弗朗索瓦·肖莱（Franc¸ois Chollet），《论智能的度量》（On the Measure of Intelligence）

![文章插图](/articles/2026-03-09-skill-skillcraft-751517ca/images/04.webp)

::: image-caption
图 1：Skill Mode 演示图。技能模式演示，展示技能如何被自动发现、本地缓存并在后续流程中被复用。该图直观对比了无技能复用和技能模式的执行步骤差异，无复用需 16 步完成的操作，借助技能模式的自动发现、本地缓存能力仅需 7 步完成。这一过程体现了技能模式的核心价值，即通过捕捉重复工具调用模式形成可复用技能，从执行步骤层面直接实现效率提升。
:::

现实世界中使用工具的语言智能体越来越多地在具有重复子结构的长期工作流中运作，例如在文档、代码仓库或网络服务中重复执行“搜索-分析-总结”的模式[Boisvert et al., 2024; Jimenez et al., 2024; Zhang et al., 2025]。:mdnice-bold-italic[在认知科学中，这种重复性正是技能抽象产生的根源：智能的特征并非执行孤立的动作，而是从经验中高效获取、复用和重组更高层级的流程]。

::: block-1
从这一角度来看，有效行为需要具备形成组合技能的能力——组合技能是可复用的工具组合，能够捕捉不同任务间的共享结构，而非通过扁平的原子工具调用从零开始重复解决每个实例。这引发了一个核心问题：智能体能否获取并复用此类可在结构相似任务中泛化的组合工具技能？
:::

现有工具使用基准测试[Zhou et al., 2023; Xu et al., 2024; Li et al., 2025]通常在部署时固定工具集和模型，并采用“智能体能否用给定工具解决该任务？”的评估范式。因此，这些基准测试难以反映智能体在跨任务场景中积累、抽象和复用组合技能的能力。**为了单独衡量这一缺失的能力，我们提出 SkillCraft 基准测试，其标准化协议专门设计用于激发和评估任务内部及任务之间的可复用工具组合（即技能）**。与现有基准测试不同，:mdnice-bold-italic[SkillCraft 在单个任务中嵌入重复子结构，要求智能体在固定预算内多次识别和复用工具组合。]

> 我们通过三阶段方式构建 SkillCraft：

- 首先，探索现有工具使用任务（如 Toolathlon[Li et al., 2025]、AgentCompany[Xu et al., 2024]和 WebArena[Zhou et al., 2023]）以确定任务设计原则；
- 其次，通过筛选和改编现有基准测试中的高质量任务，以及从零开始精心设计长期任务，构建种子任务库；
- 最后，沿两个正交维度扩展任务难度，以鼓励工具组合和技能抽象。数量维度扩展增加任务涉及的实体数量（例如，将“分析代码仓库 A 的提交历史”扩展为“分析五个代码仓库”，从而鼓励复用已学技能）；

结构维度扩展将多个子任务链接为更长的链条，增加结构难度并支持更高层级的技能形成（例如，获取提交记录、识别贡献者并建立两者间的关联）。**这些设置反映了现实世界中的长期工具使用场景，其中可复用的高层级组合对于高效稳健的问题解决至关重要。**

> 此外，我们提出一种评估智能体工具组合能力的协议。我们**为智能体配备了一种即插即用的组合机制** （称为“技能模式”），使其能够：

1. 自动发现成功的工具调用序列并将其缓存为可复用技能；
2. 当出现相似模式时，在新输入上调用这些缓存的技能。

在实践中，我们通过修改系统提示并注册一组工具来实现这一机制，这些工具允许智能体以即插即用的方式保存和执行技能。**这创造了“测试时工具演进”：智能体在测试过程中通过发现和复用扩展其动作空间，在解决任务的过程中积累能力。**

在 SkillCraft 上对最先进的模型（如 Gemini-2.5-Pro、Claude-Sonnet-4.5、GPT-5.1）进行评估后发现，技能模式显著提升了效率，令牌使用量最多可减少 80%。此外，**工具组合带来的效率提升与任务成功率高度相关，表明在相同的组合机制下，更强的模型更善于发现、复用和利用重复的工具使用模式**。:mdnice-bold-italic[这些结果表明，更强的模型往往能从可复用工具组合中获得更多收益，并且更善于在相同组合机制下识别、复用和利用重复的工具使用模式。]

我们还沿着两个互补维度对组合质量进行了细粒度分析：组合深度和泛化能力。研究发现，更深层次的自动生成层级结构通常并非可靠的扩展策略——尽管单个技能的执行率较高，但嵌套会放大错误传播和调试开销，而经过充分测试的浅层技能库则更稳健且成本效益更高。相比之下，**真正高质量的组合具有强大的迁移能力**：在一个难度级别学到的技能可以在其他级别（甚至跨模型）静态复用，且执行成功率始终很高，同时提升任务成功率和效率。

## 二、SkillCraft 基准测试

当前的工具使用基准测试主要测试智能体能否使用固定的原子工具集成功解决单个任务（例如，通过搜索 API 回答一个实时查询）。**这种单轮评估无法反映智能体的工具组合能力**。因此，我们提出 **SkillCraft，这是一个具有重复结构的长期、组合式基准测试**，更能反映现实场景，并鼓励智能体发现和复用更高层级的工具技能。

### 2.1 哪些任务能够评估技能组合能力？

> 我们的探索始于一个问题：什么样的任务能够忠实地评估智能体的技能组合和复用能力，而非仅仅评估其执行孤立工具调用的能力？要评估技能组合能力，任务必须超越单步、低分支问题。:mdnice-bold-italic[如果一个任务可以通过少数几个原子工具调用高效解决，智能体就没有动力去发现或复用更高层级的技能，其组合能力也无法被区分。因此，我们需要寻找类似现实工作流的任务：这类任务具有长期性、结构重复性，且足够具有挑战性]，使得逐个解决实例的方式效率低下，从而让可复用工具组合真正发挥价值。

在这一动机的指导下，我们的基准测试设计遵循两项原则：

- 第一，任务需要多步骤、多工具推理，单个低层级工具调用无法完成任务，而高层级组合能带来明显优势；
- 第二，任务应具有重复结构，且实例间存在丰富的实体交互，使得在一个场景中发现的技能能够在其他场景中有意义地复用。

这使我们不仅能衡量智能体是否能组合原子工具，还能衡量组合后的技能是否可复用、可泛化。

::: block-1
重要的是，这些原则也与现实世界的工具使用场景相符——**现实场景通常具有长期性和结构重复性，相似的子技能会在不同任务中重复出现**，高层级技能的抽象和复用对于高效稳健的问题解决至关重要。
:::

### 2.2 如何构建此类任务？

> 我们通过三阶段流程构建基准测试：

（1）探索阶段：首先从多个现有智能体基准测试（如 Toolathlon[Li et al., 2025]、AgentCompany[Xu et al., 2024]、WebArena[Zhou et al., 2023]和 M3ToolEval[Wang et al., 2024]）中抽样一组复杂的多步骤工具使用任务。**通过系统实验，我们识别出有用的 API 和任务类型，并获得指导任务设计原则的关键见解。**

（2）种子任务创建：我们从三个来源构建种子任务库：从阶段 1 中筛选和改编的高质量任务，这些任务所需的 API 可靠、稳定且无严重的调用频率限制，难度在模型能力范围内，确保大规模、长期交互和工具组合的可行性；（ii）大量手工设计的网络 API 任务；（iii）基于自定义数据集的本地文件和数据处理任务。阶段 1 的任务被转换为统一的 MCP（模型-工具通信协议，用于规范模型与工具的交互）接口；对于网络 API，我们调研、测试并筛选稳定的公共端点（如 GitLab、Open-Meteo、TVMaze），将其封装为标准化本地工具，并据此设计任务；对于本地任务，我们准备数据集、实现标准化处理工具，并基于这些工具构建任务。

（3）系统扩展：沿两个维度扩展种子任务：（i）数量扩展：增加实体/子任务的数量；（ii）结构扩展：增加每个子任务的工具调用次数。两者结合产生多个难度级别（如 3×3、4×4、5×5），创造足够的提升空间并鼓励发现和复用更高层级的组合技能。

### 2.3 如何评估工具组合能力？

受认知科学的启发（认知科学认为智能是在有限资源下获取和复用技能的效率[Anderson, 1982; 1987; Chollet, 2019]），我们不仅通过任务成功率，还通过效率来评估工具组合能力。在特定的智能体工具使用场景中，我们还探讨了效率是否仍是可靠的评估指标。作为第一步，我们分析基准设置以建立参考点。对当前仅使用低层级（原子）工具的模型进行分析后，我们发现两个反复出现的低效模式：（1）冗余状态传递：连续工具调用之间需要重复序列化中间结果，导致大量令牌开销；（2）上下文窗口饱和：长序列的工具调用及其输出会占用大量上下文容量，可能导致模型“遗忘”早期信息或偏离整体目标。

这些观察揭示了一个根本限制：复杂技能必须分解为原子操作序列，每个操作都需要显式的状态传递和推理。一种自然的解决方案是将频繁共存的工具链整合为单个可执行单元，我们称之为“技能”。代码是实现这种整合的理想载体，能够简洁地表示数据流、控制逻辑和迭代过程。

因此，我们的评估聚焦于：给定多步骤、多工具任务，模型能否将重复的工具链抽象为可复用的基于代码的技能？这种抽象是否能提升效率和成功率（通过令牌使用量、工具调用次数和交互步骤来衡量）？我们通过在 SkillCraft 上评估模型来回答这些问题。

## 三、SkillCraft 协议

> 本节介绍 SkillCraft 的评估协议。为了评估模型的组合和技能管理能力，我们采用了一种流程，使模型能够将现有工具组合为新的高层级工具，并在当前任务内部及跨任务中复用这些工具。

该评估协议在可量化的过程中支持两项核心能力：

1. 组合：模型可将多步骤工具链抽象为可复用的基于代码的技能；
2. 复用：模型在测试时检索并复用已发现的技能，实现流畅执行并在重复交互中积累效率提升。

### 3.1 四个最小化 MCP 原语

> 为了在最小化系统假设的情况下支持技能复用，我们提供了一个轻量级 MCP 接口，允许智能体存储和复用可执行的基于代码的技能。

在实践中，我们维护一个技能库（缓存已验证的技能及其元数据），并提供四个轻量级 MCP 原语作为与该库交互的唯一方式。**该接口特意仅涵盖技能模式所需的操作：存储、检索、枚举和执行**。具体而言，技能库通过以下原语访问：

- 保存技能（save skill）：持久化一个工作流；
- 获取技能（get skill）：检索代码和元数据；
- 列出技能（list skills）：发现可用技能；
- 执行技能（execute skill）：将技能作为高层级工具运行。

:mdnice-bold-italic[这些原语共同定义了评估边界：模型是否尝试复用技能、复用是否成功以及如何处理失败，都可以通过这些 API 调用直接观察到]。下图 8 详细说明了这些原语如何融入整体协议。

![文章插图](/articles/2026-03-09-skill-skillcraft-751517ca/images/08.webp)

::: image-caption
图 8：实现技能模式的四个原生工具伪代码图。实现技能模式的四个原生工具的伪代码。该图展示了支撑 SkillCraft 技能模式的四个核心 MCP 原生工具的伪代码，包括保存、执行、列出、获取技能，明确了各工具的输入、输出和使用场景。这四个工具构成了智能体与技能库交互的唯一接口，设计上遵循轻量级原则，仅保留核心操作，让智能体能便捷地实现技能的创建、管理和复用。
:::

### 3.2 代码验证器（Coding Verifier）

> 我们引入代码验证器，在技能进入库之前执行三阶段验证：

（a）语法验证：在接受“保存技能”请求前，解析技能代码并拒绝语法无效的提交，返回错误行号和上下文片段，以阻止存在根本性缺陷的代码；

（b）运行时错误报告：当“执行技能”失败时，返回结构化调试信息（如异常信息、堆栈跟踪和输入参数），使模型能够区分语法问题、工具调用问题或参数不匹配问题；

（c）执行后质量检测：为了过滤无用技能，通过检查输出质量检测“静默失败”（指代码无语法错误但输出无效的情况）。例如，如果超过 50%的输出字段包含“未知（Unknown）”、“无（None）”或“0”，则将该技能标记为低质量并拒绝。

> 为了捕捉模型在不同任务中发现、存储和复用技能的过程，**该协议在每个步骤都明确判断先前学到的技能是否可以替代原子工具调用序列**。

![文章插图](/articles/2026-03-09-skill-skillcraft-751517ca/images/09.webp)

::: image-caption
图 2：SkillCraft 协议流程概览图。SkillCraft 协议流程概述，该流程包含三个阶段：（1）测试时工具链演进：智能体通过探索和链接原子工具解决任务库中的任务，形成可执行的工具序列；（2）迭代技能组合：成功的序列被抽象为候选技能，在编码环境中执行和验证，执行失败触发重新探索，通过验证的技能被存储；（3）技能库与复用：不断扩充的已验证可复用技能库，可在后续任务中检索以替代低层级工具探索，实现测试时的技能积累和高效组合。该图完整呈现了 SkillCraft 协议的核心运转逻辑，将原子工具到可复用技能的转化、存储、复用全流程可视化，还列举了 gitlab 项目分析器等典型技能案例。流程中设置的编码验证环节是关键，能过滤无效技能，保证技能库的可靠性，为跨任务技能复用奠定基础。

协议流程如下：

1. 复用尝试：对于新任务，智能体通过“列出技能”查询现有技能，并尝试通过“执行技能”调用匹配的技能（传入任务特定参数）；
2. 探索：如果没有合适的技能或技能执行失败，智能体使用原子工具解决任务，并记录成功的工具序列；
3. 组合：将成功的序列抽象为参数化的候选技能，整合重复子流程，并通过代码变量而非自然语言传递中间结果；
4. 验证和保存：候选技能通过统一的 call tool()接口在受控的编码环境中执行，并由代码验证器验证。只有通过执行和验证的技能才会通过“保存技能”存入技能库，以备后续可靠复用。

## 四、评估

我们在一致且统一的设置下（相同的任务提示、工具端点和环境约束）在 SkillCraft 上评估智能体。以下介绍评估设置。

### 4.1 模型

我们对一组具有代表性的最先进模型进行基准测试，包括 Kimi-K2-Thinking[Team et al., 2025]、DeepSeek-V3.2-EXP[Liu et al., 2025a]、DeepSeek-R1[Guo et al., 2025a]、Gemini-3-Pro[Google DeepMind, 2025]、Minimax-M2.1[MiniMax, 2025]、Claude-4.5-Sonnet[Anthropic, 2025]和 GPT-5.2[OpenAI, 2025]。

### 4.2 指标

> 我们使用准确率衡量成功率：对于每个任务，遵循 Toolathlon 的做法，定义人工专家手工设计的输出匹配和评分规则，**当最终得分 ≥90%时，任务被视为成功**。

为了衡量任务完成之外的技能行为，我们报告：

- 执行率（Exec Rate），所有技能执行尝试中成功执行的比例
- 复用率（Reusing Rate），每个保存的技能被调用的平均次数）

效率指标包括输入/输出令牌数（InTok/OutTok）、LLM 交互轮数（Turn Num）以及适用时的工具调用次数（Tool Call Num）。

对于每个消耗指标 m，计算差异值 Diff 为$(m_{skill} - m_{base}) / m_{base}$（负值表示节省）。为确保公平比较，效率指标在两个对比模式（基准模式和技能模式）均成功的任务子集上取平均值。

## 五、什么是优质的工具组合？

为了理解优质工具组合的构成，我们从两个关键维度研究工具组合：组合深度和泛化能力。具体而言，我们探讨更深层次的层级组合是否能带来更好的性能，以及学到的技能是否能跨任务、跨复杂度级别和跨模型泛化。

### 5.1 更深层次的组合总是更好吗？

> 我们引入层级模式（Hierarchical Mode），允许技能在执行过程中调用其他技能，从而支持层级化、树状结构的技能组合。

在标准 SkillCraft 协议（技能模式）中，仅支持单层组合：每个技能被定义为原子工具调用的组合，不能调用其他技能。迭代模式（Iteration Mode）取消了这一限制，支持递归技能调用，允许层级组合达到可配置的嵌套深度（实验中最大技能嵌套深度=10）。**理论上，层级组合支持可复用抽象，通过嵌套技能复用实现倍增的效率提升，并允许智能体在更高层级推理，而非管理低层级细节。**

在实践中，**层级模式下执行技能时，负责在技能执行过程中调度可执行动作的 call tool 接口，不仅可以调用原子工具，还可以通过执行模式调用先前保存的技能**。相比之下，标准 SkillCraft 协议中的 call tool 仅限于调用原子工具，不能触发其他技能。这支持层级化/递归技能调用，并生成树状结构的执行图，其中高层级技能协调低层级技能，如下图 6(a)所示。

![文章插图](/articles/2026-03-09-skill-skillcraft-751517ca/images/13.webp)

#### 实际挑战

> 然而，实验表明，层级模式的整体成功率低于扁平技能模式。主要原因是错误在技能层级中传播。

上面图 6(a)展示了一个典型的失败模式：低层级技能（获取品种档案 get breed profile）在边缘情况下返回包含空字段的数据，该错误向上传播，导致中层级技能（完整品种分析 analyze breed complete）出现类型错误（TypeError），最终导致高层级技能（编译品种百科 compile breed encyclopedia）完全失败。

为了说明由实现细节导致的级联失败，我们识别出三个底层微观因素：

1. 复合失败：深度为 d 的技能依赖其整个依赖子树，成功率随嵌套深度快速下降；
2. 潜在漏洞：早期创建的技能可能包含仅在复用时才显现的边缘案例错误，污染所有基于这些技能构建的高层级技能；
3. 调试开销：诊断嵌套失败需要追溯依赖关系，其成本通常超过直接使用扁平工具调用重新执行的成本。

### 5.2 跨任务泛化

> 优质组合的一个关键特性是能够跨问题难度泛化。**如果技能捕捉的是可复用的流程结构而非实例特定的解决方案，那么它应该能在同一任务家族内从较简单任务迁移到较复杂任务** （反之亦然）。因此，我们评估在一个难度级别学到的技能是否能有效复用于其他难度级别。

我们采用两阶段静态迁移方法实现跨任务模式：

- 阶段 1（技能创建）：智能体在标准技能模式下解决源难度级别的任务，在工作空间中创建并缓存技能；
- 阶段 2（技能迁移）：运行器（1）将预计算的技能缓存复制到目标难度任务的工作空间；（2）生成跨任务技能摘要并注入系统提示，为智能体提供包含技能签名、参数和执行历史的结构化描述；（3）让智能体在完全访问继承技能的情况下执行目标任务。

我们评估三个迁移方向：简单 → 困难（E→H：从 e1-e3 任务学到的技能迁移到 h1 任务）、困难 → 简单（H→E：从困难任务学到的技能应用于简单任务）、困难 → 困难（H→H：从一组困难任务学到的技能应用于同一任务家族中的其他困难任务）。这种静态迁移方法通过阻止阶段 2 执行过程中的技能修改或积累，孤立地衡量了技能的泛化能力。

### 5.3 跨模型技能泛化

> 为了研究一个模型创建的技能是否能让其他模型受益，我们在 8 个高难度任务上进行了跨模型静态复用实验。

- 四个模型（Claude、Gemini、GLM 和 Minimax）在初始任务执行过程中各自创建技能，然后这些技能被提供给所有四个模型在静态复用模式下执行，形成 16 个跨模型组合（包括 4 个自复用基准）。
- 在静态复用模式下，智能体可以通过“执行技能”调用预加载的技能，但不能创建新技能，确保性能差异反映技能质量和跨模型兼容性，而非实时适配能力。

#### 发现 2：技能质量决定效率收益或损失

> 图 7(b)揭示了基于技能创建者质量的计算效率显著差异：

- Claude 创建的技能（第一行）在所有执行模型上均实现 54%-81%的高令牌节省，表明高质量技能能带来通用的效率收益；
- 相比之下，Minimax 创建的技能（最后一行）的令牌节省范围为-48%至+18%，意味着设计不佳的技能往往会增加而非降低计算成本。

值得注意的是，自复用（对角线）并不总是优于跨模型复用：Claude 使用 Gemini 的技能实现了 69.2%的节省，显著高于 Gemini 自身 14.8%的自复用节省——:mdnice-bold-italic[这表明执行模型的能力可以弥补中等质量的技能，但无法挽救存在根本性缺陷的技能设计。]

#### 启示

> 这些发现表明，技能创建者的质量比执行模型的能力更重要：

- 投资于从高性能模型创建高质量技能，能为整个模型生态系统带来可迁移的效率收益；
- 而设计不佳的技能无论由哪个模型执行，都可能损害性能。

**这意味着多智能体系统应优先采用来自高性能模型的技能库**，而非允许所有参与者随意贡献技能。

## 六、结论

> 我们提出了 SkillCraft 基准测试（包含 126 个具有重复子结构的任务）和技能模式（一种允许智能体自动组合、缓存和复用工具序列的协议）。

该框架使我们能够衡量智能体是否能获取组合技能，而非仅仅执行孤立的工具调用。对最先进模型的评估揭示了两个关键发现：

- 首先，**技能复用使令牌使用量最多减少 80%，同时保持或提升了成功率**；
- 其次，效率提升与模型智能高度相关。

此外，**技能在跨任务和跨模型场景中表现出良好的泛化能力** （执行率>95%），尽管层级组合由于嵌套步骤中的错误累积而可靠性较低。:mdnice-bold-italic[这凸显了组合技能获取是稳健的长期工具使用的关键能力。]
