## 一、推理黑箱：基准分数背后的认知盲区

> 大语言模型的多步推理能力常以思维链的形式外化呈现，但闭源系统的原生推理轨迹始终处于保密状态。厂商通常只对外暴露最终答案、摘要或粗粒度的推理控制开关，原始的中间思考过程被彻底封装在黑箱之中。

这直接造成了一道难以逾越的测量鸿沟。我们可以通过基准测试知道哪个模型得分更高，却不知道它是靠严谨的推导还是侥幸的猜测得到答案；**我们观察到模型能力一代比一代强，却不清楚推理效率提升的根源是什么。**

### 1.1 面向结果的局限性

> 这种只看结果、不看过程的评价体系，带来了三方面的局限。

- **第一是可靠性无法验证。同样的正确答案，可能来自完整的逻辑推导，也可能来自记住了题目答案**，甚至是错误推理碰巧得到正确结果。:mdnice-bold-italic[没有中间轨迹，就无法区分有效推理和虚假推理，这在医疗、金融等高风险场景中是不可接受的。]
- **第二是优化方向模糊。模型能力提升可能来自更深的思考步数、更准确的步骤执行，也可能来自更高效的路径选择**。:mdnice-bold-italic[如果只能看到最终准确率，研发者就无法精准定位短板，也难以复刻强模型的推理优势。]
- :mdnice-bold-italic[第三是知识蒸馏缺乏抓手。用强模型的推理轨迹监督弱模型训练，是大模型蒸馏的主流路径。但如果老师模型的推理本身是隐藏的，学生模型能学到什么、学到什么程度，都只能靠最终效果反推，无法针对性地调整轨迹的颗粒度和详细程度。]

此前已有多项研究尝试绕过原生思考通道获取推理信息。有研究者通过响应预填充技术，在关闭思考块的情况下仍让模型输出步骤化解答；也有工作通过影子模型演示、工具调用重放等方式诱导推理暴露。**但这些方法要么依赖特定模型的漏洞，要么需要复杂的 prompt 工程，难以跨模型通用对比。**

::: block-1
:mdnice-highlight[本文提出的方法跳出了上述局限，仅利用绝大多数闭源 API 都支持的自定义工具功能，通过标准化的协议提取推理]，具备极强的通用性和可复现性。
:::

## 二、强制推理协议：用标准工具通道提取隐藏 CoT

> **如果模型原生的思考通道被关闭或者隐藏，我们可以给它提供一个新的草稿纸工具，让它把中间推理过程写在工具的参数里** 😄。整个过程不需要访问模型内部，:mdnice-bold-italic[只需要调用方具备自定义工具和强制工具选择的 API 权限。]

其实现逻辑可以拆解为三个核心步骤：注册推理工具、强制首次调用、自动后续交互。整个流程没有复杂的提示词工程，仅依靠标准 API 的原生控制能力即可完成。

### 2.1 工具设计：仅作为草稿载体

::: block-1
研究者定义了一个名为`forced-reasoning`的自定义函数，:mdnice-bold-italic[工具仅包含一个字符串类型的参数`reasoning`，工具描述为“用于演算问题的草稿板”。这个工具本身不执行任何外部计算、不返回任何额外信息，它的唯一作用是承接模型输出的中间推理文本，并且将这些内容保留在对话历史中，供后续步骤调用。]
:::

这种设计的核心在于，:mdnice-bold-italic[工具为模型提供了一个独立于最终答案的“工作区”。模型可以在这个区域里完成推导、验证、探索等中间过程，最后再输出整理后的最终答案。这和原生思维链的功能完全一致，只是载体从模型内置的思考块，转移到了外部定义的工具参数中。]

### 2.2 执行流程：三步完成提取

> FORCED-REASONING 协议的完整执行流程可以用一段伪代码清晰概括，核心分为三个阶段：

- **第一阶段是初始化。构造包含系统提示和用户问题的对话消息，关闭模型的原生推理功能**，将自定义的推理工具加入工具列表。
- 第二阶段是强制首次调用。**第一次请求 API 时，通过`tool_choice`参数强制指定模型必须调用`forced-reasoning`工具。模型返回工具调用后，记录参数中的推理内容，同时向对话历史中追加助手的工具调用消息，** 以及固定内容为“Received”的工具结果消息，不提供任何额外反馈。
- 第三阶段是自动交互。:mdnice-bold-italic[从第二次调用开始，恢复自动工具选择模式，让模型自主决定是继续调用工具补充推理，还是结束思考输出最终答案。重复这个过程，直到模型返回最终答案，将所有工具调用中的推理内容按顺序拼接，就是完整的提取思维链。]

这套协议的优势非常明显：实现极简，仅依赖标准 API 功能，不需要修改模型、不需要内部权限；通用性强，所有支持自定义工具和强制选择的模型都可以使用；干扰性低，除了首次强制调用工具，后续过程完全由模型自主控制，最大程度保留了原生推理的行为模式。

## 三、三重验证：提取的推理轨迹可信吗？

> **提取出类似推理的文本，不等于它就起到了原生思维链的作用。它完全可能是模型在被要求写推理时，事后补出来的标准答案说明**，而非真正支撑它得到答案的中间过程。

研究者为此设计了三层验证机制，先在原生 CoT 可见的开源模型上建立对应关系，确认提取轨迹的有效性，再将结论推广到无法直接对比的闭源模型。

### 3.1 性能验证：准确率匹配原生水平

> 验证的第一层是性能校验。**如果提取的文本是真正的推理过程，那么它应该能支撑和原生推理相近的解题准确率**；:mdnice-bold-italic[如果只是事后编造的文字，那么准确率应该和无推理状态相差不大。]

研究团队在 DeepSeek-V4-Flash 和 GLM-5.2 两个开源模型上进行测试，对比无推理、原生高推理、强制提取推理三种模式的 MATH 基准准确率。结果显示：

- DeepSeek-V4-Flash 无推理准确率为 30.5%，**原生高推理为 70.0%，强制提取推理达到 73.3%；**
- GLM-5.2 无推理准确率为 21.4%，**原生高推理为 89.9%，强制提取推理达到 84.3%。**

::: block-1
**强制推理的准确率大幅超越无推理基线，整体接近原生推理水平**，部分场景甚至略有超出。:mdnice-highlight[这直接证明提取出的文本是实实在在承载了解题能力，起到了和原生思维链类似的作用。]
:::

### 3.2 结构验证：功能分布高度重合

> 第二层验证是内容与结构校验。研究者从词汇相似度和功能结构两个维度，对比提取轨迹和原生 CoT 的相似性。

- 词汇层面采用 ROUGE-1、ROUGE-L 和 5-gram Jaccard 三个指标衡量。**结果显示，强制推理与原生推理的词汇重叠度很高，处于同模型两次原生推理的差异量级。这说明二者在用词和表达上具有高度一致性。**
- :mdnice-bold-italic[结构层面基于 Schoenfeld 的情节理论，将推理片段划分为读取、分析、规划、执行、探索、验证、监控七大类，对比两类轨迹的功能分布。结果显示，强制推理和原生推理具备完全一致的功能类别，各类型的占比也高度相近。这说明二者不仅表面文字相似，底层的推理结构和认知步骤也是同构的。]

### 3.3 闭场景下的行为证据

> 对于闭源前沿模型，原生思维链不可见，无法直接做轨迹级对比，**研究者转而采用“准确率+推理 token 消耗”的行为证据进行验证。**

总之，三层验证共同支撑了提取轨迹的有效性：:mdnice-bold-italic[开源模型上性能接近原生、词汇结构高度相似；闭源模型上准确率匹配原生推理水平、大幅超越无推理基线。这意味着 FORCED-REASONING 提取的是可以作为原生思维链代理的有效推理轨迹。]
:::

## 四、四大维度拆解前沿模型的推理行为差异

> 研究者从四个由宏观到微观的维度，**对四款前沿闭源模型的提取推理轨迹进行了全面对比：输出长度与信息密度、局部推理粒度、推理活动组成、全局推理树结构。**

这四层分析就像从卫星地图逐步放大到街道细节，:mdnice-bold-italic[最终清晰地呈现出不同模型推理风格的本质差异，也精准刻画了高效推理的核心特征。]

### 4.1 长度与压缩性：最短也最致密

> 第一个维度是整体长度与信息密度。:mdnice-bold-italic[研究者采用两个指标：平均强制输出 token 数衡量总长度，zlib 无损压缩率衡量信息冗余度。压缩率越低，说明文本中重复模式和冗余内容越多；压缩率越高，说明信息密度越高、内容越难被压缩。]

![文章插图](/articles/2026-09-29-gpt-6-astra-8c9d94bc/images/07.webp)

::: image-caption
图 2：输出长度与轨迹可压缩性。颜色代表模型；形状代表基准。左上角的点意味着输出 token 更少，同时推理可压缩性更低。该图在二维平面上刻画了模型推理的 “长度 - 密度” 特征，清晰划分了不同模型的效率区间。GPT-6 Astra 全部落在左上角区域，是唯一同时满足短输出、低可压缩性的模型，说明其推理兼具简洁性和高信息密度。其他模型均落在右下方，输出长度是 Astra 的数倍，且可压缩性更高，存在更多冗余信息。三个基准中，MATH 的轨迹普遍更长，HLE 和 LCB 相对更短，但模型间的相对格局保持一致。这一分布证明推理效率是模型的稳定属性，不随任务类型大幅波动。同时，zlib 压缩率作为信息冗余的粗粒度指标，有效区分了模型的推理凝练度，为量化推理质量提供了简单可行的度量方法。

- 作为对比，**Claude Sonnet 5 处于右下角区域，输出 token 数最多，压缩率也最低，说明推理过程中有大量的展开说明和重复表述。**

- Claude Opus 4.8 为 2522 字符，比率 0.470；
- Claude Sonnet 5 达到 11455 字符，比率 0.375。

同样得到正确答案，Sonnet 的推理长度是 Astra 的 15 倍以上。

### 4.2 局部粒度：基础步骤内化处理

> **第二个维度是局部推理粒度，也就是面对同样的推理操作，模型会外化多少中间细节**。对比发现，:mdnice-bold-italic[Astra 的局部表达非常紧凑，大量基础步骤被放在内部完成，只输出关键结果。这种紧凑主要体现在两类场景中。]

- 第一类是算术与代数推导。Astra 会将多步计算合并为一步直接给出结果，而其他模型会完整展开中间过程。比如验证除法 $420261 \div 101$，Astra 仅用一句话确认结果正确；Sol 和 Opus 则会将乘数拆分、分步相乘、汇总验证，完整写出每一步计算。
- 第二类是背景知识调用。Astra 会直接使用已知结论，不重复基础定义。比如计算分子价电子数，Astra 直接写出 $48+18+36=102$；其他模型会先说明碳、氢、氧原子的价电子数，再分别计算求和。

![文章插图](/articles/2026-09-29-gpt-6-astra-8c9d94bc/images/09.webp)

::: image-caption
表 2：不同模型在同一问题上的推理节选对比，展示各模型如何表达对应的推理步骤。该表通过算术验证、代数推导、质量与价电子检查三个典型场景，直观呈现了不同模型推理粒度的差异。GPT-6 Astra 的表达最为凝练，在算术验证中仅给出结果确认，代数推导直接输出因式分解结论，价电子计算直接省略元素单电子数的说明步骤。GPT-5.6 Sol 和 Claude Opus 4.8 则逐步展开中间运算过程，明确写出每一步变形依据和计算细节。这种差异本质上反映了模型推理的 “内隐化” 程度：能力更强的模型会将基础运算、常识性知识保留在内部计算，仅外显关键推导节点；而能力稍弱的模型需要通过显性化中间步骤来保障推导正确性。这也解释了 Astra 推理轨迹更短但信息密度更高的核心原因。
:::

::: block-1
这种差异类似于熟练心算者和初学者的区别：:mdnice-bold-italic[初学者会把每一步竖式都写在纸上，熟练者则在脑中完成基础运算，只记录关键节点。Astra 显然属于前者🐂，它将常规的、基础的推导步骤内化处理，仅外化转折性、结论性的内容。]
:::

### 4.3 活动组成：推理类型无本质差异

> 第三个维度是推理活动的类型分布。**研究者将所有推理片段划分为七大类功能：读取、分析、规划、执行、探索、验证、监控，统计各类型的占比。**

结果显示，:mdnice-bold-italic[四款模型的整体活动分布非常相似：分析和执行占比最大，规划、探索、验证、监控等活动占比相近。没有任何一款模型缺少某类推理活动，也没有出现独有的行为模式。]

::: block-1
这一结论非常关键：:mdnice-highlight[Astra 的推理更短，并非省略了某些类型的思考，是因为每一类思考它都用更少的步骤完成]。它的推理技能库和其他模型完全一致，只是执行效率更高。
:::

### 4.4 全局结构：更直接的更少分支

> **第四个维度是全局推理树结构**。研究者采用 LCoT2Tree 方法将线性的推理轨迹转化为结构化的推理树，:mdnice-bold-italic[用三个核心指标衡量：宽度 $p$ 代表任意一层的最大节点数，反映分支和试错的多少；深度 $q$ 代表最大推理步数，反映思考的深入程度；节点数 $N$ 代表总思考节点数，反映整体思考量。]

- Astra 的中位数宽度仅为 5，总节点 27 个；
- Sonnet 5 宽度达到 28.5，节点 136 个，是 Astra 的 5 倍。

**这意味着 Astra 的推理路径非常直接，很少走弯路、很少回溯试错**，几乎沿着最优路径直达答案；而其他模型会进行更多的分支探索、路径验证和回头修正，思考过程更发散。

:::

## 五、跨模型迁移：推理链的价值并非天生均等

> 知识蒸馏是大模型领域的核心技术之一：用强模型的推理轨迹监督弱模型训练，是提升弱模型能力的常用手段。**但一直以来行业默认老师越强教得越好，很少有人思考推理轨迹的紧凑程度会对迁移效果产生什么影响。**

研究者设计了跨模型迁移实验：把一个模型（供体）的推理轨迹去掉答案后作为上下文，提供给另一个模型（受体），让受体在关闭原生推理的情况下答题，衡量其能继承供体多少准确率。

### 5.1 迁移效果由受体能力决定

实验结果呈现出清晰的分化规律。

对于 GPT-5.6 Sol 和 Claude Opus 4.8 的推理轨迹，无论受体能力强弱，都能以很小的性能损失完成复用。而 GPT-6 Astra 的紧凑推理轨迹表现出明显的受体依赖性：**能力强的受体几乎可以无损继承供体的准确率，能力弱的受体则只能恢复一部分，性能损失较大。**

![文章插图](/articles/2026-09-29-gpt-6-astra-8c9d94bc/images/13.webp)

::: image-caption
图 5：MATH 数据集上的跨模型推理复用。每个面板是一个受体模型；每一行是一个捐赠者模型。空心圆表示捐赠者准确率，实心点表示受体接收捐赠者推理轨迹后的准确率，虚线表示受体单独使用原生高算力模式的准确率。向左的连线表示相对于捐赠者出现性能损失；点重合表示准确率相等，该图系统展示了推理轨迹跨模型迁移的效果规律，验证了 “迁移效果取决于受体能力” 的核心结论。整体来看，Sol 和 Opus 的轨迹迁移效果稳定，各受体都能接近捐赠者的准确率。而 Astra 的轨迹呈现出明显的分层效应：强受体（如 Opus）能几乎无损复用，准确率接近 Astra 本身；弱受体（如 Haiku、Nano）则损失显著，甚至低于自身原生水平。这说明压缩的推理轨迹存在 “理解门槛”，只有能力足够的模型才能补全其中省略的中间步骤，弱模型无法解析凝练的推导，反而会丢失信息。同时，所有受体接收轨迹后都优于自身无推理基线，说明即使是弱模型，也能从外部推理中获得一定提升，只是提升幅度受限于自身能力。
:::

::: block-1
:mdnice-highlight[这种现象可以用笔记类比来理解：学霸的笔记通常非常精简，只记录关键思路和结论，同等水平的人看了能快速跟上思路；但基础薄弱的人看精简笔记就会卡在跳过的步骤上，无法完整理解]。反过来，详细的笔记虽然篇幅长，但不同水平的读者都能一步步跟上。
:::

### 5.2 答案前置仍答错的能力门槛

> 更值得关注的现象是，**部分情况下 Astra 的推理轨迹中已经明确写出了正确答案，但弱受体依然会给出错误结果**。比如一道概率题，Astra 的轨迹里明确给出答案 $2/5$，但部分弱受体仍然输出 $2/3$ 或者 $4/7$。

统计数据显示，Claude Haiku 4.5 的错误答案中，有 83.33%的情况正确答案已经明确出现在输入的推理轨迹里；GPT-5.4-nano 的这一比例为 68.75%，DeepSeek-V4-Flash 为 73.33%。

::: block-1
:mdnice-highlight[这说明紧凑推理轨迹存在明确的能力门槛。当受体模型的能力低于阈值时，不仅无法复用推理逻辑，甚至连理解已经给出的结论都存在困难]。推理轨迹的复用需要受体具备对应的推理能力，才能读懂并利用轨迹中的信息。
:::

### 5.3 对知识蒸馏的反向启示

> 这一发现直接挑战了传统蒸馏的固有认知：:mdnice-bold-italic[最强的模型未必是最好的老师。强模型的推理最紧凑、效率最高，但这种紧凑恰恰省略了弱学生无法自行补全的中间步骤，导致知识传递出现断层。]

这也为蒸馏实践中的“能力鸿沟”提供了一种新的解释：**大模型向小模型蒸馏时效果不达预期，不一定是小模型容量不够，也可能是大模型的推理过于内化和精简，训练数据的颗粒度和学生的能力不匹配**。:mdnice-bold-italic[如果先将强模型的紧凑推理“扩写”为详细步骤，再用于弱模型训练，可能会取得更好的效果。]

::: block-1
整体看下来，:mdnice-highlight[推理轨迹的价值是相对于受体模型的。强模型能无损利用紧凑推理，弱模型则更依赖详细的步骤展开]。对于蒸馏而言，最强的推理者未必是最好的老师；针对学生的能力匹配合适详细程度的推理轨迹，可能比单纯使用最强的供体模型更有效。
:::

## 六、局限、伦理边界与产业启示

这项研究打开了观察闭源模型推理的新窗口，但它本身也有明确的边界和局限。同时，这种能够提取隐藏推理的技术，也带来了新的伦理和安全考量。

### 6.1 研究的明确边界

> 这项研究存在三方面的局限。

- 第一，:mdnice-bold-italic[对于闭源模型，研究只能证明提取轨迹在行为上和原生推理相似，无法证明它就是模型原本的内部思考过程。它可能是模型通过工具通道重新生成的推理]，而非将原生隐藏的思考直接输出。
- 第二，:mdnice-bold-italic[协议依赖 API 支持自定义工具和强制工具选择功能，不具备这些控制能力的接口无法使用该方法。研究同时提到，最新的 Claude Opus 5、Fable 5 等模型已经拒绝了强制工具调用的提取方式，提取成功率为 0]，说明该方法存在明确的适用边界。
- 第三，**工具描述的 prompt 是启发式设计，不同模型对措辞的敏感度差异很大，不存在通用的最优 prompt**。因此提取出的推理强度不代表模型原生推理的上限，仅可用于相对对比。

### 6.2 伦理考量与防御思路

> 研究者在论文中明确披露了伦理风险评估：所有实验均使用公开基准和普通商用账号，未提取个人数据、专有提示或不安全内容；所有实验完成于 2026 年 9 月 9 日之前，并且已将研究结果和复现代码同步通报给 OpenAI 和 Anthropic 的安全团队。

从防御角度，**模型厂商可以通过多种路径缓解此类提取风险：**

- 在接口层面限制自由格式的推理工具、限制强制工具选择的使用场景；
- 在输出层面增加检测机制，识别工具参数中的推理内容并进行拦截。

::: block-1
更根本的治理思路是，:mdnice-highlight[推理披露政策应当覆盖原生思考块、工具参数、可见响应所有输出渠道，而非仅保护指定的推理通道。]
:::

### 6.3 对产业实践的三点启示

> 这项研究为大模型研发和应用带来了三方面的实际启示。

| 要点 | 内容 |
| --- | --- |
| 第一，推理效率将成为下一代模型的核心竞争力 | 前沿模型的竞争已经从“能不能推理”进入“能不能高效推理”的阶段，**用更少的 token、更短的链路完成同等复杂度的推理，将直接决定推理成本和用户体验。** |
| 第二，应用开发应理性选择推理粒度 | 并非推理步骤越多效果越好，**对于多数常规场景，紧凑、直接的推理反而具备更低的延迟和成本**。开发者可以根据任务难度和模型特性，匹配合适的推理强度，而非一味开启最高配置。 |
| 第三，知识蒸馏需重视颗粒度匹配 | 用强模型蒸馏小模型时，:mdnice-bold-italic[直接使用原生推理轨迹未必是最优选择。根据学生模型的能力水平，将老师的推理调整到对应的详细程度，可能会取得更优的蒸馏效果]。 |

## 七、结语

> 这项工作核心贡献可以归纳为两点：

- 一是提出了一套简单通用的方法，让我们无需打开黑箱就能观察闭源模型的推理行为；
- 二是通过系统的量化对比，第一次清晰刻画了前沿高效推理的本质特征。

长久以来，我们评价大模型的唯一标尺就是基准分数。分数高就是模型好，分数低就是能力弱。但这项研究清晰地展示，:mdnice-bold-italic[同样得到正确答案，背后的推理过程可能天差地别：有的模型遍历大量分支试错后找到答案，有的模型沿着最优路径直达终点；有的模型把每一步推导都写得明明白白，有的模型在内部完成所有基础运算只输出结论。]

::: block-1
:mdnice-highlight[随着前沿模型持续进化，推理会越来越内化、越来越紧凑，黑箱也会变得越来越“深”。但与此同时，我们也需要更多这样的研究，在黑箱上打开更多观察窗口]。毕竟我们追求的是真正能高效、可靠思考的智能系统。**理解模型“如何思考”，永远比只知道“它能答对”更有价值。**
:::
