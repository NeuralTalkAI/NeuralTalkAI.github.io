## 问题 1：算子优化的四大策略如何提升 LLM 推理效率？

**解答**：算子优化通过四种策略提升效率：

- **算子融合**：合并独立算子（如 FlashAttention 融合注意力操作），减少内存 I/O 和冗余计算，在 GPU 上使 Llama2-7B 推理速度提升至 115.57 tokens/s。
- **非线性函数近似**：用线性近似替代复杂函数（如 ConSmax 替代 Softmax），ASIC 功耗降至 0.43mW。
- **粗粒度处理**：合并小计算单元（如 TCP 芯片），ASIC 在 Llama2-7B 上批量大小 8 时达 1176 tokens/s。
- **存储优化**：优化数据访问（如 KV 缓存预取），GPU 在 H20 上批量大小 64 时达 3000 tokens/s。

## 问题 2：异构协作与同构协作的核心差异及典型应用是什么？

**解答**：

- **异构协作**：整合不同硬件（如 GPU+FPGA+PIM），发挥互补优势。例如 GLITCHES 用 GPU 处理预填充、FPGA 处理解码，使 Llama2-7B 达 450 tokens/s；CXL-PNM 通过 3D 存储堆叠提升内存带宽，OPT-13B 推理速度 42.68 tokens/s。
- **同构协作**：利用多台同类硬件并行（如多 FPGA/CPU）。例如 DFX 多 FPGA 加速 GPT2-1.5B 至 120 tokens/s；He 等人用 4 颗 CPU 实现 Qwen-72B 推理速度 7.14 tokens/s。

## 问题 3：各硬件平台的 LLM 推理性能峰值与能效优势是什么？

**解答**：

- **GPU**：FlashDecoding++在 A100 上对 Llama2-7B 达 115.57 tokens/s，H20 批量 64 时达 3000 tokens/s。
- **ASIC**：WaferLLM 在 Llama3-8B 上达 2700 tokens/s（批量 1 最高吞吐量），能源效率 12.34 tokens/J。
- **PIM/NDP**：Guo 等人的混合架构能效达 46.66 tokens/J（最高），PIMnast 使 OPT-6.7B 延迟降低 4.5 倍。
- **FPGA**：GLITCHES 结合 A100+7xU280 实现 Llama2-7B 450 tokens/s。

未来趋势指向多模态、推理时计算及高能效边缘部署，需算法与硬件协同创新以缩小性能差距。

## 3.4 算子优化

### 3.4.1 概述

在大型语言模型（LLM）时代，提升算子的执行效率至关重要，这不仅涉及提升计算速度，还包括最大化资源利用率。随着模型规模和复杂度的持续增加，传统的算子执行方法效率愈发低下，因此需要探索各种优化策略[1,2]。

![文章插图](/articles/2025-07-02-llm-97302426/images/05.webp)

以下四种方法为算子优化提供了有效解决方案，显著提升了不同硬件平台上模型的性能和响应能力：

- **融合**：算子融合通过将多个独立算子合并为一个整体，降低了中间数据的存储和传输需求。这种方法不仅降低了 I/O 开销，还减少了执行过程中的冗余计算，从而提高了整体效率。算子融合使硬件能够更有效地利用缓存和带宽，显著提升计算性能[3]。
- **非线性函数近似**：深度学习模型中常见的非线性激活函数通常需要专门的硬件支持，这会占用大量芯片资源。通过采用线性近似方法，我们可以使用成本较低的硬件实现计算，同时保持算法精度。这种优化策略使复杂的非线性计算更加高效，适用于资源受限的环境[4,5]。
- **粗粒度处理**：在处理大规模矩阵运算时，细粒度计算单元可能导致频繁的资源调度和竞争，引入额外开销。粗粒度处理通过将多个小计算单元合并为更大的单元来简化调度过程，减少资源竞争。这种方法有效增强了计算的连贯性和效率，尤其适用于并行计算环境[6]。
- **存储优化**：存储优化策略侧重于内存中数据的排列，旨在最小化计算过程中内存访问带来的延迟。通过策略性地组织数据存储位置和访问模式，我们可以显著提高数据访问效率，进而提升整体计算性能。这种优化不仅与硬件性能密切相关，还与算法设计息息相关[7]。

综合应用这四种优化方法，可以显著提升算子执行效率，使深度学习模型能够更有效地处理复杂任务。**针对特定应用场景和硬件平台，适当选择和组合** 这些优化策略，将成为实现高性能计算的关键[8]。

![文章插图](/articles/2025-07-02-llm-97302426/images/06.webp)

表 6 展示了不同硬件平台对这四种算子优化方法的使用情况。通过合理运用这些优化方法，能够大幅提高 LLM 在各种硬件上的推理效率[9]。

### 3.4.2 CPU

- **存储优化**：对于资源受限的 LLM 设备端推理，FlexInfer 提出了异步预取、平衡内存锁定和灵活张量保留等方法，以提高内存效率并缓解带宽瓶颈。对于 Llama2-7B 模型，它在 AMD 7995WX CPU 上实现了 12 tokens/s 的推理速度[10]。
- **融合**：V-Seek 在 Sophon SG2042（首款商用多核 RISC-V CPU，具有向量处理能力）上优化了 LLM 推理。对于 DeepSeek R1 Distill Llama 8B 和 DeepSeek R1 Distill QWEN 14B 模型，token 生成速度达到 4.32/2.29 tokens/s，提示处理速度达到 6.54/3.68 tokens/s[11]。

### 3.4.3 GPU

- **融合**：为解决注意力计算中二次方的内存需求问题，FlashAttention 通过将输入矩阵（Q, K, V）和注意力矩阵分块，将注意力操作融合为单个算子[12]。在 FlashAttention 的基础上，FlashDecoding 提出沿特征维度并行计算，提高了小批量解码阶段的性能。FlashDecoding 在单块 NVIDIA A100 和 RTX 3090 GPU 上，分别使 Llama2-7B 模型达到 95.07 tokens/s 和 54.19 tokens/s 的推理速度[13]。随后，FlashDecoding++通过统计分析预先确定统一的最大值，优化了 softmax 计算中的同步开销，使后续操作能够并行执行，提高了 Llama2 和 ChatGLM 等典型 LLM 的效率。FlashDecoding++在单块 NVIDIA A100 和 RTX 3090 GPU 上，分别使 Llama2-7B 模型达到 115.57 tokens/s 和 61.66 tokens/s 的推理速度[14]。

线性算子在深度学习中应用广泛。在常见的深度学习框架（如 Pytorch）中，线性算子的后端通常是 NVIDIA 支持的通用矩阵乘法（GEMM）操作[15]。HuggingFace 的朴素实现中，单块 NVIDIA A100 和 RTX 3090 GPU 上的 Llama2-7B 模型分别达到 44.60 tokens/s 和 36.29 tokens/s 的推理速度[16]。在 LLM 框架（如 DeepSpeed、vLLM 和 OpenPPL）中，通常使用 cuBLAS API 提供的 GEMM 实现进行优化。对于单块 NVIDIA A100 GPU 上的 Llama2-7B 模型，它们分别达到 89.24 tokens/s、88.45 tokens/s 和 93.63 tokens/s 的推理速度；对于单块 NVIDIA RTX 3090 GPU 上的 Llama2-7B 模型，分别达到 51.28 tokens/s、53.31 tokens/s 和 55.99 tokens/s 的推理速度[17,18,19]。

**为解决解码过程中因维度降低导致的 GEMM 效率低下问题，TensorRT-LLM 引入了专用的通用矩阵向量乘法（GEMV）实现，支持批量大小等于 1 时 LLM 的解码阶段[20]**。TensorRT-LLM 在单块 NVIDIA A100 GPU 上使 Llama2-7B 模型达到 98.19 tokens/s 的推理速度[21]。针对解码阶段的小批量情况，FlashDecoding++引入 FlatGEMM 来解决 cuBLAS 和 CUTLASS 库中的效率问题，并采用细粒度分块和双缓冲技术来提高并行性和减少内存访问延迟。此外，它采用启发式选择机制，根据输入动态选择最有效的算子[22]。FlashDecoding++的性能如上所述。

算子融合是一种常见且有效的优化方法，可减少运行时内存访问、消除内核启动开销并增强并行性[23]。B**yteTransformer 和 DeepSpeed 将主要算子** （如 GEMM）**和轻量级算子** （如残差添加、层归一化和激活函数）**融合为单个内核，以减少内核启动开销[24,25]。** 上述的 FlashAttention 将注意力算子融合为单个内核，显著降低了内存访问开销和内存需求[26]。**FlashDecoding++还实现了 Transformer 块中七个融合内核的集成[27]。 pInfer 是一个专为 GPU 上稀疏化 LLM 推理设计的高性能框架**。它引入了张量核心感知位图编码（TCA-BME）以最小化索引开销，并集成了带有共享内存位图解码（SMBD）的优化 SpMM 内核和异步流水线[28]。对于批量大小为 8 的 OPT-13B 模型，在单块 RTX 4090 GPU 上实现了约 500 tokens/s 的推理速度[29]。

- **存储优化**：FlashFormer 引入了一种概念验证内核，用于加速单批量推理，该内核利用内存移动的增加重叠，并在整个前向传递中分摊内核的启动开销[30]。对于 Llama3.1-8B 模型，在 NVIDIA H100 GPU 上实现了 181 tokens/s 的推理速度[31]。为解决 LLM 推理过程中的内存带宽瓶颈，Dong 等人提出了面向 L2 缓存的异步 KV 缓存预取方法，通过计算负载重叠，在单块 NVIDIA H20 GPU 上，批量大小为 64 时，Llama2-7B 模型实现了约 3000 tokens/s 的推理速度[32]。

### 3.4.4 FPGA

- **非线性函数近似**：HAAN 是一种针对 LLM 的整体归一化加速方法。HAAN 利用相邻层归一化统计量的相关性，通过从前驱层估计统计量来绕过归一化计算[33]。

### 3.4.5 ASIC

- **融合**：2020 年，Groq 公司推出了张量流处理器（TSP）架构，这是一种功能切片微架构，内存单元与向量和矩阵计算单元交错排列，以利用数据流局部性[34]。首个 TSP 实现在 14nm 工艺、25×29 mm 的芯片上，900 MHz 频率下，计算密度超过 1 TOPS/mm²[35]。2022 年，Groq 公司为 TSP 元件的大规模互连网络引入了一种新颖的软件定义通信方法[36]。这种可扩展通信架构基于软件定义的蜻蜓拓扑结构，最终形成了一个并行机器学习系统，具有弹性以支持各种工作负载[37]。每个 TSP 贡献 220 MB 的全局内存容量，最大容量仅受网络规模限制[38]。大规模并行系统实现了多达 10,440 个 TSP，以及超过 2 TB 的全局内存，端到端系统延迟小于 3ms[39]。基于前两项工作，Groq 语言处理单元（LPU）采用 14nm 工艺制造，功耗 185W[40]。根据文献，LPU 在 Gemma-7B 模型上实现了 814 tokens/s 的推理速度[41]。

另一家商业公司 HyperAccel 也推出了具有数据流架构的 LLM 推理芯片[42]。延迟处理单元（LPU）**引入了流线型硬件，无论模型大小如何，都能在端到端推理过程中最大限度地提高有效内存带宽利用率，实现高达 90%的带宽利用率**，以实现高速文本生成[43]。它由可扩展同步链路（ESL）组成，在多设备系统中隐藏了大部分数据同步延迟，以实现近乎完美的可扩展性[44]。其片上功耗为 0.284W（三星 4nm 工艺合成），系统总功耗为 86W，配备 96GB HBM3[45]。对于 OPT-1.3B/6.7B/13B/30B 模型，LPU 分别实现了 769.23 tokens/s、217.39 tokens/s、112.40 tokens/s 和 49.26 tokens/s 的推理速度[46]。

基于 Cerebras WSE2，WaferLLM 是首个晶圆级 LLM 推理系统[47]。对于完整的 LLM 推理，WaferLLM 在 Llama3-8B 和 Llama2-13B 模型上**分别实现了 2700 tokens/s 和 2039 tokens/s 的推理速度，功耗分别为 434W 和 354W** [48]。Cerebras CS-3 系统的核心——晶圆级引擎（WSE-3）是**有史以来制造的最大芯片** [49]。WSE-3 比最大的 GPU 大 57 倍，拥有多 52 倍的计算核心，以及多 880 倍的高性能片上内存[50]。作为唯一生产的晶圆级处理器，它包含 4 万亿个晶体管、900,000 个 AI 优化核心，以及 44GB 的高性能晶圆上内存[51]。每个晶圆由 84 个芯片组成，具有 40GB 片上内存，功耗 15kW[52]。对于 Llama3.1-8B 模型，它可实现约 1800 tokens/s 的推理速度，比超大规模云快 20 倍[53]。

- **非线性函数近似**：常数 Softmax（ConSmax）是一种软硬件协同设计，作为高效的 Softmax 替代方案[54]。ConSmax 采用可微归一化参数，去除了 Softmax 中的最大值搜索和分母求和[55]。它允许大规模并行化，同时执行 Softmax 的关键任务[56]。此外，使用位宽分割查找表的可扩展 ConSmax 硬件可以产生无损非线性操作，并支持混合精度计算[57]。它进一步促进了高效的 LLM 推理[58]。实验结果表明，ConSmax 在 1GHz 工作频率和 22nm CMOS 工艺下，功耗仅为 0.43mW，面积为 0.001mm²[59]。

::: block-1
MARCA 是首个针对 Mamba 模型设计的具有可重构架构的加速器[60]。它为线性和逐元素操作提出了一种简化替代 PE 阵列架构[61]。

- 对于线性操作，启用连接到 PE 阵列的归约树并执行归约操作；
- 对于逐元素操作，禁用归约树，输出绕过[62]。

它提出了一种基于可重构 PE 的可重用非线性函数单元，并将指数函数和激活函数（SiLU）分解为逐元素操作，以重用可重构 PE[63]。大量实验表明，MARCA 在批量大小为 1 时，对于 Mamba-2.8B 模型实现了 23.78 tokens/s 的推理速度，功耗 10.33W（对于约 7B 模型为 11.89 tokens/s）[64]。
:::

PICACHU 是一种插件式粗粒度可重构加速器，通过使用自定义算法和专用编译器工具链，**专门设计用于高效处理非线性操作** [65]。评估表明，PICACHU **在 Llama2-7B 模型上实现了 96-132 tokens/s 的推理速度（比 A100 快 2.4-3.3 倍），功耗约 10.7W** [66]。

- **粗粒度处理**：张量收缩处理器（TCP）由粗粒度 PE 组成，这些 PE 设计得足够灵活，可以配置为大型单个单元或一组小型独立计算单元[67]。TCP 芯片采用 5nm 工艺设计和制造，配备 256MB SRAM 和 1.5TB/s 48GB HBM3，功耗 150W[68]。对于 Llama2-7B 模型，TCP 在批量大小为 1 时实现了约 125 tokens/s 的推理速度，批量大小为 8 时实现了 1176 tokens/s 的推理速度[69]。

Habana Gaudi 和 Gaudi2 由两个主要计算引擎组成：矩阵乘法引擎（MME）和张量处理器核心（TPC）集群[70]。TPC 单元是专为通用深度学习操作设计的 SIMD 处理器[71]。Gaudi 架构与 GPU 架构的最大区别在于 MME 的大小[72]。Gaudi 架构可以处理 256×256 矩阵乘法，每个周期需要 512 个输入元素，而具有 16×16 张量核心的 GPU 架构需要 8K 输入元素[73]。因此，Gaudi 架构可以节省 16 倍的读取带宽需求[74]。除了计算引擎，Gaudi2 还包括 96GB 的 HBM2E 内存，提供 2.45TB/秒的带宽，以及 48MB 的本地 SRAM[75]。Gaudi 采用 16nm 工艺制造，Gaudi2 采用 7nm 工艺制造，功耗 600W[76]。对于 Llama2-7B 和 Llama2-13B 模型，Gaudi2 在批量大小为 1 时，推理速度分别为 81.97 至 111.11 tokens/s 和 49.02 至 64.52 tokens/s[77]。

### 3.4.6 PIM/NDP

- **融合**：现代 DRAM 具有多个存储体，可并行处理多个内存请求[78]。然而，当两个请求指向同一存储体时，它们必须串行处理，加剧了片外内存的高延迟[79]。因此，Kim 等人提出了子阵列级并行（SALP），以重叠指向同一存储体的不同请求的延迟[80]。基于 SALP，SAL-PIM 提出了一种子阵列级处理内存架构，包括三个架构特性[81]。两种类型的 ALU（SALU 和 C-ALU）分别集成到子阵列级和通道级[82]。S-ALU 利用比存储体级 PIM 更高的带宽来计算内存受限操作，而 C-ALU 支持多个存储体的累加和归约求和操作[83]。SAL-PIM 架构采用 28nm CMOS 工艺的 HBM2 8GB 实现，功耗 68.973W[84]。结果表明，当输入大小为 32 至 128，输出大小为 1 至 256 时，SAL-PIM 基于 GPT-2 中型模型（345M）的文本生成，平均比 NVIDIA Titan RTX GPU 实现了 1.83 倍的推理加速[85]。

PipePIM 引入流水线和双缓冲，以最大限度地提高数字 PIM 中的 CU 利用率[86]。PipePIM 由两个主要方案组成：子阵列级流水线（SAPI）和双向量缓冲[87]。其关键思想是通过 SAPI 在流水线方式下对不同子阵列进行激活、计算和预充电处理，并通过双向量缓冲同时执行缓冲写入和计算[88]。它在 22nm CMOS 工艺中模拟，面积为 88.82mm² 和 86.36mm²[89]。对于 LLaMA 和 Mistral 等 LLM，结果显示在 Newton 中速度提升 1.2 和 1.14 倍，在 HBM-PIM 中速度提升 1.21× 和 1.15×[90]。

- **非线性函数近似**：AttentionLego 提出了一种基于 PIM 的矩阵向量乘法和基于查找表的 Softmax 设计[91]。PIM-GPT 实现了具有高性能和高能效的 GPT 推理端到端加速[92]。在硬件层面，PIM-GPT 是一个混合系统，包括基于 DRAM 的 PIM 芯片，用于在数据附近加速 VMM，以及一个专用集成电路（ASIC），用于支持 PIM 成本过高的其他功能，包括必要的非线性函数、数据通信和 PIM 芯片的指令[93]。在软件层面，映射方案经过优化，以高效支持 GPT 数据流[94]。总体而言，PIM-GPT 在 8 个 GPT 模型上实现了比 NVIDIA T4 GPU 高 89 倍的速度提升和 221 倍的能效提升，参数高达 14 亿[95]。SAL-PIM 还采用基于 LUT 的线性插值来在 PIM 中执行复杂的非线性函数[96]。SoftmAP 在内存计算硬件上部署纯整数低精度 Softmax，以加速纯整数 LLM 推理[97]。与 A100 和 RTX3090 GPU 相比，它在能量延迟积方面实现了高达 1000 倍的改进[98]。
- **存储优化**：通过观察到真正利用 PIM 加速的关键障碍是推断将矩阵放置在内存存储体中的最佳数据放置，PIMnast 提出了矩阵分块/排序算法来解决这些因素，并确定影响 PIM 加速的编排旋钮[99]。对于 OPT-6.7B 模型，与 SoC 基线（AMD Ryzen PRO 7040 系列处理器，包括八个 CPU 核心、12 个 GPU 核心计算单元、16 个 AIE 模块和八个 LPDDR5 内存通道，峰值内存带宽为 120GB/s）相比，PIMnast 实现了每 token 延迟 4.5 倍的加速[100]。

## 3.5 异构协作

![文章插图](/articles/2025-07-02-llm-97302426/images/08.webp)

### 3.5.1 概述

> 异构协作结合了不同类型的计算平台，如 CPU、GPU、FPGA 和 PIM/NDP（处理器在内存/近数据处理），以优化系统性能、能源效率和灵活性。

每个计算单元在特定任务上都有独特的优势。例如，GPU 擅长并行处理，FPGA 提供可定制的硬件加速，而 PIM/NDP 则专门用于内存密集型操作。

通过将任务分配给最合适的硬件，异构协作可提高计算效率、降低功耗并减少延迟。它大致可分为两类：计算增强和内存增强。

**计算增强**：通常，CPU 和 PIM 在处理大规模计算任务时可能会力不从心。例如：

- CPU 虽然具有通用性和灵活性，但不适合高度并行处理；
- PIM 通过在内存中执行计算来减少数据传输，但其计算能力有限。在这种情况下，会引入强大的并行计算硬件（如 GPU、NPU 或 TPU）来辅助。

在 LLM 推理中，像注意力计算这样的计算密集型任务会放在 GPU、NPU 或 TPU 上，而其他计算则可由 CPU 或 PIM 处理。

**内存增强**：侧重于两个关键方面：存储容量增强和带宽增强。随着我们进入 LLM 时代，计算任务变得越来越复杂，导致对内存容量和带宽的需求更大。

- 从存储容量的角度来看，内存增强是通过在相同芯片面积上使用 3D 存储堆栈来集成更多片上内存实现的。这使得在有限的片上空间中可以存储更多数据和模型，减少访问外部存储的需求并提高整体效率。
- 另一种内存增强是通过提高数据传输速度来加速内存密集型计算。对于异构协作，带宽通常是限制计算性能的因素。为解决这一问题，人们提出了许多方法来支持高速片上[299,300,301]和芯片到芯片互连，如计算快速链接（CXL）[302]和 NVLink[62]。这些技术支持不同芯片之间的低延迟、高带宽数据传输，显著加快了数据交换过程。

![文章插图](/articles/2025-07-02-llm-97302426/images/09.webp)

### 3.5.2 CPU

#### 计算增强

> **CPU-GPU**：仅使用 CPU 可能导致性能较慢，因此许多方法采用 CPU 和 GPU 结合的方式来提高 LLM 推理速度。

**对于个人计算机，PowerInfer[259]提出应将热激活神经元预加载到 GPU 以实现快速访问，而冷激活神经元则在 CPU 上计算，从而显著减少 GPU 内存需求和 CPU-GPU 数据传输**。PowerInfer 还集成了自适应预测器和神经元感知稀疏算子。在配备 NVIDIA RTX 4090 的 Intel i9-13900K 处理器上，各种模型（OPT-30B/66B、Falcon40B 和 Llama-70B）的平均生成速度达到 8.32 tokens/s。在配备 NVIDIA RTX 2080Ti 的 Intel i7-12700K 处理器上，平均生成速度为 5.77 tokens/s。

**对于智能手机，PowerInfer-2[260]进一步利用智能手机 SoC 中高度异构的 XPU，如非对称大小核 CPU、GPU 和 NPU**。在配备骁龙 8 Gen 3 的一加 12 上，PowerInfer-2 在 Llama-7B 和 Mistral-7B 上分别实现了 11.7 tokens/s 和 10.5 tokens/s 的速度。在配备骁龙 8+ Gen 1 的一加 Ace 2 上，PowerInfer-2 在 Llama-7B 和 Mistral-7B 上分别实现了 6.5 tokens/s 和 6.3 tokens/s 的速度。

**对于服务器，Kim 等人[258]提出了一种自适应模型，用于根据内存容量需求和计算强度确定在 CPU 和 GPU 上分别运行的 LLM 层**。然后，他们提出了利用最新 Intel CPU 的 AMX 扩展的 CPU-GPU 协同计算。评估表明，对于 OPT-30B 模型，CPU-GPU 协同计算在批大小为 1 且输入 token 为 2016 的预填充阶段实现了 336 tokens/s 的速度。在解码阶段，批大小为 90 且输入 token 为 2016 时，速度约为 25 tokens/s；批大小为 1400 且输入 token 为 64 时，速度约为 300 tokens/s。

**Dovetail[202]、Twinpilots[261]和 Vellaisamy 等人[262]适应 GPU-CPU 和分层内存架构（GPU 和 CPU 内存），以最大化 CPU 和 GPU 利用率，并将数据加载时间完全隐藏在 CPU 计算时间之后**。在配备 24GB 内存的 NVIDIA A10G GPU 和 256GB 内存的 AMD EPYC 7R32 CPU 的服务器上，Twinpilots[261]在批大小为 1 和 8 的情况下，为 Llama-13B 分别实现了约 5 tokens/s 和 12 tokens/s 的速度。PRIMA.CPP[263]提出了一种带预取的管道环并行性和调度器，用于将模型层分割到异构设备上。它可以在苹果 M1（约 14W）和麒麟 9000（约 7.9W）等边缘 SoC 上为 Llama3-8B 和 Qwen2.5-7B 分别实现 18.52 tokens/s 和 22.73 tokens/s 的速度。HeteroLLM[109]是一种在移动设备上支持 W4A16 量化的快速 LLM 推理引擎，支持层级和张量级异构执行。评估结果表明，HeteroLLM 在骁龙 8 Gen3 平台上为 Llama2-7B 实现了 13-15 tokens/s 的速度。

### 3.5.3 GPU

#### 内存增强

**CPU-GPU**：TightLLM[264]提出并实现了一种基于自适应卸载的推理系统，通过两个关键创新来最大化推理吞吐量。其键值（KV）分配器采用计算换传输策略，通过动态重新计算部分 KV 缓存来解决不断增加的传输开销；其权重加载器对模型权重进行切片，并将加载过程分布在多个批次中，有效将数据传输与计算重叠，并分摊过多的权重加载开销。对于 OPT-13B 和 Llama2-13B 模型，在 NVIDIA RTX 3090 GPU 和 24 核 CPU 上，使用最大批大小分别实现了 22 tokens/s 和 20 tokens/s 的速度。

### 3.5.4 FPGA

#### 计算增强

**FPGA-GPU**：在对延迟敏感的场景中，通常需要小批量甚至单批处理。这导致 LLM 推理的预填充阶段和解码阶段分别成为计算和内存瓶颈。因此，同构 FPGA 或 GPU 系统难以同时解决 LLM 推理不同阶段的不同计算瓶颈，导致 FPGA 上的预填充延迟长，GPU 上的解码阶段利用率低。

GLITCHES[265]通过采用 GPU 用于预填充阶段、FPGA 用于解码阶段的协作异构系统，实现了 GPU-FPGA LLM 推理。实验表明，配备 A100/V100S GPU 和 7 个 U280 FPGA 的 GLITCHES 异构 LLM 推理系统为 Llama2-7B 实现了 390-450 tokens/s 的速度。

HPU[266]提出了高带宽处理单元（HPU）和 GPU-HPU 异构系统，并开发了带 HBM 的基于 FPGA 的 HPU 原型。

### 3.5.5 PIM/NDP

#### 计算增强

（1）**PIM-NPU**：NeuPIMs[267]和 IANUS[268]是**异构 PIM 加速系统，共同利用传统的专注于 GEMM 的 NPU 和优化 GEMV 的 PIM 设备**。NeuPIMs[267]首先在每个存储体中提出双行缓冲区，便于同时管理内存读/写操作和 PIM 命令，以实现 NPU 和 PIM 平台上的并发操作。此外，它采用运行时子批交错技术，以最大化 LLM 中 GEMM 和 GEMV 之间固有依赖关系的并发执行。我们的评估表明，NeuPIMs 在功耗约 76W（0.6348W+75W）（32GB HBM）的情况下，为批大小 8 的 GPT3-7B 实现了约 3000 tokens/s 的速度。IANUS[268]提出了新颖的 PIM 访问调度，不仅管理正常内存访问和 PIM 计算的调度，还管理 PIM 和 NPU 之间的工作负载映射。评估表明，对于 GPT-6.7B 模型，IANUS 在功耗约 240W 的情况下实现了 127.1 tokens/s 的速度。 Cambricon-LLM[279]提出了一种基于芯片 let 的混合架构，包含 NPU 和专用 NAND 闪存芯片，以实现高效的 LLM 推理。它同时利用 NPU 的高计算能力和 NAND 闪存芯片的数据容量。NAND 闪存芯片通过闪存内计算得到增强，以执行精确的轻量级管芯处理，而 NPU 执行矩阵操作并处理特殊函数计算。实验结果表明，Cambricon-LLM 在功耗约 37W 的情况下，为 70B 和 7B 的 LLM 分别实现了 3.44 tokens/s（约）和 36.34 tokens/s 的速度，比现有闪存卸载技术快 22-45 倍。

（2）**PIM-GPU**：**MoNDE[269]是一种近数据计算解决方案，可在异构硬件上高效支持专家混合（MoE）LLM 推理**。MoNDE 通过仅将热专家传输到 GPU 来减少 MoE 参数移动量，而在主机存储设备内计算剩余的冷专家。MoNDE 可实现与具有无限内存的理想 GPU 系统相当的推理延迟。AttAcc[270,271]也是一种配备 GPU 的异构系统，用于加速注意力层。与最先进的单片 GPU 系统相比，AttAcc 为 GPT3-175B 模型实现了显著更高的吞吐量（高达 2.81 倍）和能源效率（高达 2.67 倍）。2024 年，SK 海力士提出了基于 LPDDR6 的异构 LLM 系统 AiMX-xPU[278]，该系统由 1 个 NVIDIA H100 GPU 和 3 个 AiMX 组成，在批大小为 1、8 和 32 的情况下，为 OPT-30B 分别实现了 167 tokens/s、220 tokens/s 和 900 tokens/s 的速度。PAISE[280]利用 GPU-PIM 异构计算资源来优化 LLM 推理。对于 Llama2-7B 模型，配备 HBM-PIM 设备的 AMD MI100 GPU 在批大小为 1 的情况下实现了约 400 tokens/s 的速度，功耗与纯 GPU 系统相似。Pyramid[282]通过策略性地在 PIM 内分配跨层计算资源以满足多样化需求，并利用两种技术的优势，为 LLM 推理优化了 GPU-PIM 系统。评估结果表明，Pyramid 分别比现有系统 NeuPIM、AiM 和 AttAcc 高出 2.31 倍、1.91 倍和 1.72 倍。

LLM 中固有的激活稀疏性自然地将权重参数分为两类，分别称为“热”神经元和“冷”神经元。热神经元仅占所有权重参数的约 20%，但占总计算负载的 80%。相比之下，冷神经元仅占计算工作量的 20%。Hermes[283]利用 DRAM DIMM 内的 NDP 单元，通过将热神经元映射到 GPU，同时将冷神经元卸载到 NDP-DIMM 来增强 GPU 的性能。此外，Hermes 引入了轻量级预测器，以确保 GPU 和 NDP-DIMM 之间的最佳实时神经元分区和调整。Hermes 有助于在消费级硬件上以 13.75 tokens/s 的速度部署 LLaMA2-70B。

（3）**PIM-FPGA**：Kang 等人[272]将内存密集型 GEMV 计算（包括投影、前馈网络层和具有预训练权重的最后全连接层）放在 HBM2-PIM 上，并使用 PIM 驱动的 Xilinx Alveo U280 板评估系统。对于 GPT-1.3B 模型，在将 PIM 技术的带宽扩展 8 倍后，可实现约 347.83 tokens/s 的速度，比 NVIDIA A100 GPU 快 1.6 倍。从 2022 年到 2023 年，SK 海力士提出了基于 GDDR6 的内存中加速器 AiM[303,304]，并将其与 2 个 Xilinx XCVU9P FPGA 芯片集成作为控制和通信原型 AiMX[277]，以批大小 1 为 OPT-6.7B 实现 330 tokens/s 的速度。

（4）**PIM-TPU**：H3D-Transformer[274]提出了一种用于 Transformer 模型的异构 3D 计算平台设计，该设计采用具有多个 3D 内存/逻辑混合立方体的中介层基板，针对加速不同的 MatMul 工作负载进行了优化。提出了一种近似计算方案，以利用混合信号内存计算（CIM）和数字张量处理单元（TPU）的异构计算范式。从系统级评估结果来看，GPT2 模型实现了 10 TOPS/W 的能源效率，比基于 7nm TPU 和堆叠 FeFET 内存的基线高约 2.6-3.1 倍。3D-HI[276]利用基于芯片 let 的异构集成来设计中介层网络（NoI）架构，以加速 LLM 推理。3D-HI 使用流式多处理器及其相关的内存控制器（SM-MC）用于多头注意力，使用 ReRAM 核心用于前馈网络，这同时优化了可实现的能源效率和吞吐量。此外，在 2.5D 中介层上的垂直集成有助于提高整体系统性能，并缓解内存瓶颈问题。实验结果表明，与同等的最先进基于芯片 let 的平台相比，3D-HI 将延迟和能耗分别降低了高达 22.8 倍和 5.36 倍。PIM-LLM[168]利用模拟内存处理（PIM）架构和数字 systolic 阵列，分别加速投影层中的 1 位 MatMul 操作和注意力中的高精度 MatMul 操作。对于序列长度为 128 的 Llama-7B，它可实现 42.82 tokens/s 和 170 tokens/J 的速度。

#### 内存增强

（1）**PIM-CXL**：由于这些模型参数和中间值的频繁传输是通过相对较慢的设备到设备互连（如 PCIe 或 NVLink）进行的，因此它们成为 LLM 高效加速的关键瓶颈。Kim 等人[273]利用 PIM，与传统 DRAM 相比，PIM 使用存储体级并行性来提供更高的内部内存带宽，从而显著提高了内存带宽。除了通过计算快速链接（CXL）内存扩展实现高容量外，**CXL-PNM 还通过将计算逻辑集成到内存产品中展示了性能改进，从而增加了内部内存带宽**。评估结果表明，使用 PIM 和 PNM，内存密集型 LLM 的性能分别显著提高了 4.5 倍和 4.4 倍。CXL-PNM[275]首先设计了一种基于 LPDDR5X 的 CXL 内存架构，具有 512GB 容量和 1.1TB/s 带宽，在模块外形尺寸限制下，其容量比基于 GDDR6 和 DDR5 的 CXL 内存架构大 16 倍，带宽高 10 倍。其次，它设计了一种集成 LLM 推理加速器的 CXL-PNM 控制器架构，利用这种 CXL 内存的独特能力来克服 HBM-PIM 和 AxDIMM 等竞争技术的缺点。评估表明，对于 OPT-13B 模型，CXL-PNM 在功耗 77.6W 的情况下实现了 42.68 tokens/s 的速度。

（2）**PIM-3D 堆栈**：Sharda 等人[165]提出使用**无电容 3D 可堆叠 DRAM**，以比传统 DRAM 更高的密度存储更大的 LLM。为了**减少中间数据大小，他们提出使用分层稀疏量化混合（LSQH）算法，该算法基于使用低比特量化执行的计算来引入稀疏性**，以减少能耗和数据存储需求。最后，通过将 3D DRAM 与采用 3nm 技术节点、工作频率为 1GHz 的逻辑芯片 let 堆叠，设计了一种 3D 异构集成加速器。评估表明，对于 Llama2-13B，它在预填充阶段以 193W 的功耗实现了 163k tokens/s 的速度。PIM-AI[281]在 DDR5/LPDDR5 内存芯片上堆叠计算单元，以提高性能和能源效率。模拟表明，PIM-AI 为 Llama2-7B 实现了 30 tokens/s 和 35.97 tokens/J 的速度。Lue 等人[170]提出了一种使用 3D NOR 的基于闪存的内存计算架构，用于加速 LLM 推理。对于 W4A8 的 Llama-7B，他们可以实现>200 tokens/s 的推理速度。）

## 3.6 同构协作

### 3.6.1 概述

> 由于 LLM 的规模庞大且计算需求高，同构协作也可增强 LLM 推理。像模型并行这样的分布式计算旨在解决与 LLM 相关的内存限制问题。

随着模型规模的持续增长，**单个硬件单元可能无法容纳整个模型**。模型并行将模型分割成多个部分，**不同硬件单元同时处理模型的不同部分**。

### 3.6.2 CPU

分布式计算成为缓解单节点内存限制和加快 LLM 推理性能的常用策略。He 等人[284]提出了一种用于 CPU 上 LLM 的高效分布式推理优化解决方案。在四个第五代 Intel Xeon 可扩展处理器上，结果显示 Qwen-72B 的生成速度为 7.14 tokens/s。

He 等人[285]还提出了**新的注意力流 SlimAttention，以减少 KV 缓存大小并确保 CPU 上高效的 LLM 推理精度**。在 Llama2-70b 上的实验结果显示，在 Intel Xeon 8563C CPU 上，使用 2 个插槽时 token 生成延迟为 4 tokens/s，使用 8 个插槽时为 11.4 tokens/s。

### 3.6.3 FPGA

**DFX[286]是一种多 FPGA 加速器，它使用模型并行和优化的数据流来提高预填充和解码阶段的 LLM 推理速度**。在四个 Xilinx Alveo U280 FPGA 上实现后，DFX 为 GPT2-1.5B 模型实现了约 120 tokens/s 的速度。在本文中，我们提出了 LoopLynx，这是一种可扩展的数据流架构，用于高效的 LLM 推理，通过混合时空设计优化 FPGA 使用。LoopLynx 的设计包含混合时空架构，其中计算密集型算子被实现为大型数据流内核。这实现了与空间架构类似的高吞吐量，并且以时间方式组织和重用这些内核共同提高了 FPGA 的峰值性能。此外，为了克服单个设备的资源限制，我们提供了一种多 FPGA 分布式架构，该架构重叠并隐藏所有数据传输，从而充分利用分布式加速器。通过这样做，LoopLynx 可以有效地扩展到多个设备，以进一步探索大规模 LLM 推理的模型并行性。GPT2 模型的评估表明，LoopLynx 可以实现与最先进的单 FPGA 加速器相当的性能。此外，与 Nvidia A100 相比，我们的双 FPGA 配置加速器在推理延迟方面实现了 2.52 倍的加速，同时仅消耗 48.1%的能量。

### 3.6.4 ASIC

Chen 等人[287]提出了一种灵活框架，以支持两种同构二进制和浮点 PE 阵列。实验结果表明，它为 Llama-6.7B 实现了约 80 tokens/s 的速度，功耗为 5.72W。

### 3.6.5 GPU

同构 GPU 协作主要通过模型并行和数据并行来加速 LLM 推理。

- **模型并行** 将大型 LLM 的不同层分配到多个 GPU 上，使每个 GPU 仅处理模型的一部分，从而突破单个 GPU 的内存限制。例如，使用 8 个 NVIDIA A100 GPU 进行模型并行，可在处理 GPT-3 等超大规模模型时实现更高的吞吐量。
- **数据并行** 则是在多个 GPU 上复制相同的模型，每个 GPU 处理不同的输入数据批次，适用于需要处理大量并发请求的场景。例如，在服务器端部署时，通过数据并行可同时处理多个用户的查询请求，提升整体服务能力。

### 3.6.6 PIM/NDP

PIM/NDP 的同构协作研究相对较少，但也有一些探索。例如，通过将多个 PIM 设备连接在一起，形成更大规模的内存计算集群，以处理更大规模的 LLM 推理任务。

这种同构协作可以进一步提升内存带宽和计算能力，从而提高 LLM 推理的效率。然而，目前相关的研究和实际应用还比较有限，仍处于探索阶段。

### 3.6.7 各硬件平台比较

> 同构协作在不同硬件平台上的性能表现各异。

- **CPU** 的同构协作虽然可以通过**分布式** 计算提升性能，但受限于 CPU 的计算能力，整体**吞吐量较低**。
- **FPGA** 的同构协作（如 DFX）通过**模型并行和优化的数据流设计**，能在多个 FPGA 上实现较高的推理速度，且具有**较好的能效比**。
- **GPU** 的同构协作在处理大规模 LLM 时具有明显优势，通过**模型并行和数据并行的结合**，可实现**极高的吞吐量**，但**功耗也相对较高**。
- PIM/NDP 的同构协作目前应用较少，但其潜力在于通过内存计算集群进一步提升性能和能效。

在图 13 中，同构协作的功耗范围为 5.72W 至数千瓦（取决于 GPU 集群规模），推理速度范围为 7.14 tokens/s 至数千 tokens/s。

能源效率方面，FPGA 和 PIM/NDP 的同构协作具有较好的表现，而 GPU 集群虽然吞吐量高，但能源效率相对较低。

### 3.6.8 总结

> 同构协作通过分布式计算的方式，有效解决了单节点硬件在处理大规模 LLM 时的内存和计算能力限制。不同硬件平台的同构协作方案各有特点，适用于不同的应用场景。

- **CPU 的同构** 协作适合**对性能要求不高** 的轻量级应用；
- **FPGA 和 PIM/NDP 的同构** 协作在**能效方面具有优势**，适合边缘和数据中心的节能场景；
- **GPU 的同构** 协作则在**高性能计算中心** 中发挥重要作用，用于处理大规模、高并发的 LLM 推理任务。

未来，随着 LLM 规模的不断扩大，同构协作技术将进一步发展，以实现更高的性能和更低的能耗。

## 总结

算子优化通过算法 - 硬件协同设计，在各平台实现了 LLM 推理速度、功耗与能源效率的显著提升。**未来需进一步结合异构集成、专用架构设计（如 ASIC/PIM）及边缘适配技术**，以满足多模态、实时性等场景的需求，缩小现有技术与实际应用的差距。
