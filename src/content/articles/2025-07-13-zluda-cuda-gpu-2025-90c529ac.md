## 一、它到底是什么

> 如果你有一块 Radeon RX 6000/7000 系列显卡，却想跑原本只能在 NVIDIA GPU 上执行的 CUDA 应用，ZLUDA 就是那块“翻译芯片”的纯软件实现。

它把自己的 libcuda.so/nvcuda.dll 替换掉系统里的官方 CUDA 运行时，把程序发出的每一条 PTX 指令实时翻译成可在 AMD ROCm/HIP 栈上执行的代码，从而:mdnice-bold-italic[无需重新编译、无需修改源码] 就能让 Blender Cycles、llama.cpp、PyTorch 等软件在非 NVIDIA 平台上启动。

项目最初由波兰开发者 Andrzej Janik（vosen）单人维护，**2024 年 10 月正式获得商业团队注资，进入“第三次生命”。**

## 二、核心原理：三层翻译与一次调度

### 入口伪装

ZLUDA 提供与官方 CUDA 驱动完全一致的 API 符号（cuInit、cuMemAlloc、cuLaunchKernel …）。应用在启动时动态链接到这些符号，以为自己仍在和 NVIDIA 驱动对话。

### PTX → LLVM → AMD ISA 编译链

- PTX 解析器：把 CUDA 字节码（PTX）转换成 LLVM IR；
- HIP 后端：再把 LLVM IR 交给 ROCm 的 LLVM AMDGPU 后端，生成针对 RDNA/CDNA 机器码；
- 即时编译（JIT）：首次调用某 kernel 时执行，结果缓存在磁盘，后续直接加载。

### 设备调度与状态同步

CUDA 的 stream、event、context 在 AMD GPU 上被映射为 HIP 队列与信号量；显存分配通过 ROCm 的 hipMalloc 完成；ZLUDA 额外维护一张“GPU 状态补丁表”，用来处理浮点舍入模式、denormal 行为等 NVIDIA 特有但 AMD 默认关闭的硬件特性。

## 三、2025 最新进展：从“能跑 Geekbench”到“冲刺 PyTorch”

![文章插图](/articles/2025-07-13-zluda-cuda-gpu-2025-90c529ac/images/05.webp)

### 团队与节奏

- 2024 Q4 获得商业赞助，2025 Q2 全职开发者从 1 人增至 2 人，Discord 社区突破 4 k 用户。
- 官方路线图：2025 Q3 让 llm.c 完整通过，2025 Q4 让 PyTorch 训练脚本“零补丁”运行。

![文章插图](/articles/2025-07-13-zluda-cuda-gpu-2025-90c529ac/images/06.webp)

### 技术里程碑

- bit-accurate 执行：通过 PTX “sweep” 测试集，逐条指令验证与 NVIDIA 输出逐位一致，已修复 cvt、fma 等 30 余种指令的误差。
- 全局浮点模式重构：在 AMD GPU 上首次实现 per-kernel 的舍入与 denormal 控制，解决旧版 ZLUDA 只在函数级“投票”决定模式的近似行为。
- 自动化构建：GitHub Action 每晚推送预编译二进制，Windows/Linux 均可直接下载体验。
- llm.c 进度：从 2025 Q1 的“第 1 个 CUDA 调用即崩溃”提升到 Q2 的“第 552 个调用才失败”，44 个 cuBLAS / Runtime API 已完成 16 个。
- AMD 驱动 ABI 修复：定位并绕过 ROCm 6.4 comgr 接口的 v2/v3 混用 bug，保障 Windows Adrenalin 25.5.1+ 与 Linux ROCm 6.4+ 的兼容性。

![文章插图](/articles/2025-07-13-zluda-cuda-gpu-2025-90c529ac/images/07.webp)V-Ray CUDA on Radeon through ZLUDA

### 功能取舍

- 光线追踪（OptiX）暂停：旧版 ZLUDA-OptiX 仅支持少量 demo，维护成本高，商业版决定优先 ML 负载，短期内不会回归。
- Windows 体验降级：zluda.exe 启动器被移除，用户需手动把 nvcuda.dll 复制到目标程序目录；Linux 继续 LD_LIBRARY_PATH 一行启动。
- GPU 范围收窄：官方仅保证 RDNA1 及更新消费级卡，Vega/Radeon VII 与 CDNA 服务器卡需社区维护。

## 结语

> ZLUDA 的 2025 路线图清晰地指向一个目标：让 AI 开发者手里的每张 AMD 显卡都能像 RTX 一样“pip install torch”即可跑训练。

随着编译器精度、Runtime 兼容性和社区贡献者数量的同步增长，它正从“极客玩具”走向“生产可用”的临界点。
