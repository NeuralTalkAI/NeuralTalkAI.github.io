**推理经济学由前沿模型的运行方式驱动**。为了实现更高的智能水平，模型会生成海量的“推理 token”（:mdnice-bold-italic[reasoning tokens，模型在生成最终用户可见输出前，用于内部思考、推导逻辑的中间 token，通常不直接展示给用户，但对提升答案准确性至关重要]）。**要让推理在大规模场景下具备可行性，这些 token 必须以低 token 延迟和低成本交付**。混合专家模型架构的设计初衷就是解决这一问题——它仅为每个 token 激活相关的“专家”（experts，混合专家模型中负责处理特定类型任务的专业化子网络），在提供前沿级智能的同时，避免计算成本的同比增长。

**混合专家模型方法的主要限制是什么？** 核心考量因素是通信瓶颈（communication bottlenecks，由于专家分布在不同 GPU 上，GPU 间数据传输的延迟会导致 GPU 处于空闲等待状态，造成计算资源浪费）。当专家分布在多个 GPU 上时，GPU 间通信的任何延迟都会导致 GPU 闲置等待数据。这种闲置时间属于浪费性、低效的计算，会直接增加服务提供商的最终成本。

**为了理解这些转变带来的性能和经济影响，我们利用公开可用的基准测试数据，对比了不同模型架构下的 AI 基础设施选项**。

::: block-1
研究发现，对于密集型架构和小型混合专家模型，NVIDIA B200 的性能确实优于 AMD MI355X 配置。:mdnice-bold-italic[但当扩展到 DeepSeek-R1 等前沿级模型并超出单节点范围时，所有 8 块 GPU 系统（无论 NVIDIA 还是 AMD）都会因通信瓶颈而遭遇“扩展上限”] （scaling ceiling，硬件或软件在规模扩大到一定程度后，性能无法继续同步提升的极限）。
:::

**NVIDIA GB200 NVL72 架构似乎有效解决了这一扩展限制**。同样来自公开的 DeepSeek-R1 性能数据显示，**GB200 NVL72 的性能最高可达竞品 AMD MI355X 平台的 28 倍**。:mdnice-bold-italic[这种性能优势如何转化为 token 成本？] 我们的研究结果表明，对于高交互性推理工作负载，NVL72 的 token 成本最低可降至其他基础设施选项的 1/15。

## 一、引言

> 随着模型、服务堆栈和用户体验期望的变化速度超过传统数据中心的更新周期，AI 基础设施技术在持续演进。这一现实要求采用新的基础设施评估方法——强调更频繁、可对比的测量，而非静态评估。

**总拥有成本（TCO, Total Cost of Ownership）和投资回报率（ROI, Return on Investment）仍是基础设施决策的核心考量**，但只有当它们与生产工作负载下可衡量的平台优势相结合时，才具有实际意义。营销宣传和理论峰值性能参数虽具参考价值，但并不完整；**而在并发场景、输入/输出模式多样化的真实推理服务中，才能真正体现每个平台的性能实况。**

当客户评估 AI 基础设施经济学时，讨论通常围绕三个维度展开：

- 性能（吞吐量和交互性）
- 能源效率（特定功率预算下生成的 token 数量）
- 总拥有成本（生成 token 的成本，通常以每百万 token 成本表示）

这三个因素，再加上投资成本或月度服务成本，共同决定了任何 AI 服务能否在大规模场景下盈利交付。

::: block-1
在本分析中，我们采用第三方基准测试得出的性能数据来估算相对 token 经济学，而非依赖厂商的性能宣传。

我们展示了 NVIDIA B200、NVIDIA GB200 NVL72 以及 AMD MI355X 的部分结果，以直观对比它们在不同模型下的性能及由此产生的总拥有成本估算。**我们的方法遵循一个关键简化原则：在特定交互性目标下，相对 token 成本由相对平台成本除以相对 token 产出决定**。通过保持定价假设的透明度，并与性能测量分离，读者可以根据自身具体条款和部署场景调整输入参数。
:::

$$
用户每百万token成本 = <每GPU每小时成本>/<3600秒/小时>/ <特定交互性下的每GPUtoken吞吐量> × 1,000,000
$$

## 二、数据分析流程

> 本分析使用 InferenceMAX 平台的公开基准测试数据[3]，确保研究过程的开放性和可验证性。我们从这些数据集中提取了每个平台的观测结果，重点关注与决策最相关的部分数据点，而非全部呈现。

我们考察了每个硬件平台的最佳配置和峰值性能：

- 对于单节点 NVIDIA 实现，采用 TensorRT-LLM（NVIDIA 推出的用于大语言模型推理加速的软件框架）；
- 对于 AMD GPU，采用 vLLM（一款开源的大语言模型推理引擎）。

对于 DeepSeek-R1，NVIDIA 采用 Dynamo-TensorRT LLM，AMD 则采用 SGLang（另一款大语言模型推理框架）。

我们将通过帕累托前沿分析（Pareto frontier analysis，一种用于展示在多个目标（如吞吐量和交互性）下，无法同时优化所有目标时的最优权衡方案的分析方法）可视化结果，**该分析可呈现特定变量组合下，每 GPU 吞吐量与用户交互性之间的最佳权衡关系**。

> 通过这些图表，作为 AI 基础设施采购方，你可以对比目标 token 速率，并查看实现该速率所需的每 GPU 性能水平。而作为 AI 用户，你会更关注横轴——交互性越高，用户体验越好。

但完整的基准测试数据集包含大量复杂信息，难以直接转化为可行决策。因此，我们还展示了关键交互性阈值下的性能，我们称之为“基准点”（bookends），将分析锚定在与部署决策直接相关的场景中，使数据更易于理解和应用。

**在整篇报告中，我们使用“每用户每秒 token 数”（tokens per second per user）作为响应性的实际代理指标。** 该指标捕捉了终端用户最关心的核心：他们接收生成内容的速度，以及与模型或服务交互的体验。我们将交互性阈值视为决策点而非绝对标准，因为不同应用对可接受用户体验的要求存在差异。

:mdnice-bold-italic[对于每个模型分析，我们设定两个基准点：一个位于交互性范围的低端，另一个位于高端，具体数值因每个模型的性能和数据可用性而异]。例如，对于 Llama 3.3 70B，我们选择 30 token/秒/用户作为交互式使用的最低标准（参考典型阅读速度），而 110 token/秒/用户则代表接近峰值的交互性，此时体验流畅且响应迅速。GPT-OSS-120B 作为推理模型，其基准点设定得更高，具体将在以下章节中说明。

## 四、理解混合专家模型架构与推理型 AI

> 传统上，AI 模型通过增加模型参数数量来提升智能水平。

- 传统密集型模型架构要求模型中的每个参数都为每个 token 激活，这意味着随着模型规模不断扩大，其运行速度会变慢，成本会增加，同时对内存等资源的需求也会相应增长。
- 混合专家模型（MoE）架构与密集型模型架构的不同之处在于，它将模型参数拆分为多个专业化子网络（即“专家”）。混合专家模型包含一个轻量级路由器（router，负责根据输入 token 的特征，决定激活哪些专家子网络的组件），该路由器会基于每个 token 的特征决定激活哪些专家集合，从而在保持特定智能水平的同时，显著降低每个 token 的计算成本。

![文章插图](/articles/2026-01-05-moe-gb200-nvl72-gpu-mi355x-c663d69f/images/08.webp)

::: image-caption
对比稠密Transformer（如Llama 2/3）与MoE Transformer（如Mixtral）的结构：前者用单个前馈网络（FFN）；后者通过门控机制选择多个FFN子网络，二者均包含多头注意力、归一化与残差连接，体现MoE在计算资源分配上的灵活性
:::

同时，许多最知名的混合专家模型也是推理型模型（reasoning models），它们在推理过程中会进行额外计算以提高准确性。这类模型不会立即输出答案，而是在生成用户可见输出之前生成中间推理 token，相当于先“思考”请求和解决方案。这些推理 token 的数量通常远多于最终响应，且可能完全不向用户展示（尽管它们可以让我们了解模型得出结论的过程和行为）。**因此，每个请求的总 token 生成量会增加，这意味着快速且经济高效地生成 token 对于推理部署至关重要。**

根据 OpenRouter 的最新报告，**超过 50%的 token 通过推理型模型路由**。

![文章插图](/articles/2026-01-05-moe-gb200-nvl72-gpu-mi355x-c663d69f/images/09.webp)

::: image-caption
推理型与非推理型token趋势（2024年11月-2025年11月）纵轴为token占比，横轴为时间，展示推理型token占比的增长趋势。来源：https://openrouter.ai/state-of-ai，自2025年初以来，通过推理优化模型路由的token占比稳步上升。该指标反映的是推理型模型处理的token占所有token的比例，而非模型输出中“推理token”的占比
:::

::: block-1
前沿模型对混合专家模型架构和推理功能的大规模采用，在人工智能分析（Artificial Analysis）排行榜中也有所体现——排名靠前的智能开源权重模型（包括 DeepSeek、Kimi K2 Thinking 和 GPT-OSS-120B）均为推理型混合专家模型。
:::

:mdnice-bold-italic[部署混合专家模型面临着密集型模型所没有的复杂性。性能会显著受路由效率、专家间负载均衡以及调度决策的影响，尤其是在并发负载下]。随着推理功能的普及，**性能越来越依赖机架级的持续交互性，而非单节点的峰值吞吐量。**

混合专家模型也让**“token 经济学”（tokenomics，研究 token 生成、传输和成本的经济学分支）和总拥有成本** 考量更加凸显。在并发场景下，路由、调度和通信开销会大幅降低实际吞吐量。:mdnice-bold-italic[经济学核心仍然是在特定用户体验目标下，每 GPU 的持续 token 生成速度，但如今，性能超越单节点 8 块 GPU 的扩展能力变得更为关键。]

## 五、中度推理混合专家模型性能：GPT-OSS-120B

> **OpenAI 的 GPT-OSS-120B** 是一款开源模型，是理解混合专家模型部署特性的理想过渡案例。它的规模足以体现混合专家模型的复杂性，同时许多团队都能实际部署和调优。它**介于密集型 70B 级模型和市场快速转向的新型前沿推理混合专家模型架构之间，具有重要的参考价值。**

该模型架构包含 36 层，总参数达 1170 亿，但通过 128 个专家（每个 token 激活 4 个专家）的设计，每个 token 仅激活约 51 亿个参数。它支持高达 128K 的上下文长度，适用于企业文档处理和扩展推理任务。

对于混合专家模型，尤其是涉及推理功能时，高感知交互性通常需要比密集型单次摘要提示更高的 token/秒/用户阈值。在本分析中，我们设定了新的基准点：100 token/秒/用户作为实用推理交互性下限，250 token/秒/用户作为更高等级（此时推理循环和智能体工作流的体验会显著加快）。我们分析了 1K 输入/8K 输出的场景——这是一种推理密集型模式，长生成内容比快速单次答案更为重要。这些配置往往会放大调度、内存和端到端服务方面的差异。

:::

> 我们的数据包括 2025 年 10 月底和 12 月初的两次测量结果，:mdnice-bold-italic[随着 NVIDIA 和 AMD 软件堆栈的改进，结论也发生了变化。这体现了一个重要动态：平台性能并非静态不变，软件优化可以提升 GPU 性能]。然而，相对差距仍可能发生变化，尤其是在更高的交互性目标下。

- 在 10 月底的测量中，在 100 token/秒/用户的阈值下，NVIDIA B200 的速度约为 MI355X 的 1.4 倍，优势显著但并不悬殊。但在 250 token/秒/用户的交互性下，差距大幅扩大至约 3.5 倍，这表明更高的交互性目标会放大平台差异。

然而，相对差距也发生了变化。在 100 token/秒/用户的交互性下，B200 的性能现在几乎是 MI355X 的 3 倍，高于 10 月 InferenceMAX 数据中的 1.4 倍。在更能代表推理模型需求的 250 token/秒/用户交互性下，B200 的优势扩大至 6.6 倍。

::: block-1
结论很明确：密集型模型的性能差异具有一定意义，但随着向快速推理交互性目标推进，混合专家模型的性能差异会变得更大。

这自然引出一个问题：**如果在中度混合专家模型中就存在这些差距，那么在 DeepSeek-R1 等更大规模的推理型混合专家模型架构中，情况会如何？**
:::

## 六、前沿推理混合专家模型性能：DeepSeek-R1

> DeepSeek-R1 是专门为推理设计的现代混合专家模型家族，是前沿推理发展方向的良好代表。它集中体现了三个给基础设施带来压力的趋势：混合专家模型路由、大规模参数（总参数 6710 亿，激活参数 370 亿），以及高要求的推理式生成需求。

这类模型的实际部署挑战很快就会显现：更高的并发目标、更长的输出、更大的键值缓存压力，以及对调度和通信效率的更高敏感性。**前沿模型路线图越来越重视推理、测试时计算以及稀疏或模块化架构，所有这些因素都放大了对平台级规模和复杂服务软件编排的需求。**

超大型推理混合专家模型已超出 8 块 GPU 张量并行配置的有效处理范围。此时，专家并行以及最近出现的宽专家并行成为必要的扩展机制——**因为专家和路由决策必须分布在多个 GPU 上，才能维持吞吐量和交互性。**

- 张量并行（tensor parallelism，将模型的张量拆分到多个 GPU 上并行计算，以提升处理速度）
- 专家并行（expert parallelism，将混合专家模型中的不同专家子网络分布到不同 GPU 上的并行计算方式）
- 宽专家并行（wide expert parallelism，更灵活的专家分布和并行调度方式）

即使单节点在密集型或中度混合专家模型工作负载上表现良好，DeepSeek-R1 等模型也需要更强的扩展能力。**通信和编排成为首要的性能限制因素**，而且这些模型对非最优路由、键值缓存处理和 GPU 利用率缺口的容忍度更低。其结果是，**“出色的单节点性能”与“出色的多节点扩展性能”之间的差距不断扩大**。此时，:mdnice-bold-italic[机架级架构（rack-scale architecture，将多个服务器节点整合在一个机架内，通过高速互联实现协同工作的架构）不再是“锦上添花”，而是“必不可少”。]

### 6.1 NVIDIA GB200 NVL72：机架级架构性能

> NVIDIA GB200 NVL72 突破了扩展上限。通过在单个 NVLink 域（NVLink domain，NVLink 是 NVIDIA 推出的高速 GPU 互联技术，NVLink 域指通过 NVLink 连接的 GPU 组成的逻辑网络）中连接 72 块 GPU，**该系统在软件层面本质上相当于一个机架级的巨型 GPU**。

（顺便提一句，我第一次听到这种说法时，觉得纯粹是营销话术，但数据证明了其有效性。）

这种设计使张量并行扩展能够突破 B200 和 MI355X 单节点系统的 8 块 GPU 上限，从根本上提升了可实现的性能水平。

NVLink 交换架构（NVLink Switch fabric）提供 130 TB/s 的互联带宽，使每块 GPU 都能以极低延迟进行通信。:mdnice-bold-italic[对于混合专家模型而言，这意味着分布在数十块 GPU 上的专家可以实现全互联（all-to-all）通信模式——这正是这些架构高效服务所必需的。]

在 InferenceMAX 的 NVL72 测试中使用的 NVIDIA Dynamo，很好地体现了服务软件在平台中的核心作用。Dynamo 专为高吞吐量、低延迟的多节点推理设计，实现了分离式预填充和解码阶段（disaggregated prefill and decode phases，将模型推理的预填充阶段和解码阶段拆分到不同 GPU 或节点上处理）、动态调度和键值缓存路由。**这种“系统+软件”的整合，将原始 GPU 能力转化为可扩展的推理吞吐量。**

::: block-1
将当代平台与前代平台进行对比，比单纯的同代产品正面比较更能清晰地体现平台投资回报率。它可以展示在相同交互性目标下，新一代平台能释放多少性能余量，同时也印证了**性能不仅仅取决于单个 GPU，还取决于架构、系统设计和软件如何结合，形成可用的每 GPU 吞吐量能力。**
:::

我们的对比包括：

- 新一代现代平台（GB200、B200、MI355X）运行 FP4 量化（FP4 quantization，将模型参数从更高精度转换为 4 位浮点精度，以提升吞吐量并降低内存占用）的 DeepSeek-R1，
- 以及前代平台（H200、MI325X）运行 FP8 版本的 DeepSeek-R1。

> 这反映了实际部署决策：新一代堆栈通常更早采用更激进的量化技术，以最大化每美元吞吐量。我们的目标并非进行完美的“同类对比”，而是了解每代平台能提供的实用交互性水平。

基准测试数据揭示了一个全新的格局。GB200 NVL72 支持超过 8 块 GPU 的张量并行配置，实现了帕累托前沿性能，达到了单节点平台无法企及的水平。我们传统的基准点对比方法在此面临挑战，因为 **B200 的扩展性能远超 MI355X，且帕累托曲线的分歧越来越大。**

## 七、token 经济学分析

### 7.1 NVIDIA 代际成本对比

> 从 Hopper 架构代过渡到 Blackwell 架构代的 GB200 NVL72，NVIDIA 不仅提升了每 GPU 的计算能力、内存带宽和 NVLink 互联带宽，还重新设计了底层系统架构。

从 8 块 GPU 风冷 HGX 服务器转向 72 块 GPU 全液冷机架级系统（单个域连接），**系统的成本和复杂性无疑有所增加**。根据 CoreWeave 公布的标价，GB200 NVL72 的每 GPU 每小时价格约为 H200 的 1.7 倍。（注：市场上存在多种公开定价数据，从新兴云服务商到大型云服务提供商（CSP），差异较大。）

然而，:mdnice-bold-italic[每一代新技术的目标都是降低 token 成本。具体到推理，这意味着 token 吞吐量的提升幅度要超过基础设施成本的增长幅度]。而公开性能数据显示，GB200 NVL72 与 Hopper 相比，正是实现了这一点。

::: block-1
我们的“token 经济学”分析基于前文确立的 DeepSeek-R1 性能差异。

- 在 25 token/秒/用户的交互性下，GB200 NVL72 的每 GPU 性能约为 H200 的 10 倍。
- 在更高交互性下，差异更大（24 倍）。

在中度 token 经济学总结中，我们采用了约 20 倍的代际性能提升作为中间值，代表了低交互性和高交互性基准点之间的性能水平。（显然，每个用例在帕累托曲线上的位置略有不同，因此这些总拥有成本计算结果会有所差异。）

## 结论

> 前沿 AI 模型的未来趋势是更大规模、更复杂的混合专家模型。稀疏扩展（sparse scaling，通过激活部分模型参数而非全部参数来提升模型规模和性能的扩展方式）是持续提升模型能力和智能水平的最实用路径之一。这一转变提升了测试时计算和推理式生成的重要性，为基础设施效率和可扩展性设定了更高标准。

随着模型进一步向混合专家模型和推理架构发展，:mdnice-bold-italic[结果不再仅仅取决于原始 GPU 性能或内存容量]。**平台级设计成为决定性因素，包括互联和通信效率、多节点扩展特性、软件堆栈成熟度、生态系统支持和编排能力，以及在并发和混合工作负载下维持高利用率的能力。**

公开基准测试结果表明，在 Llama 3.3 70B 等高性能密集型模型上，NVIDIA 已具备明显优势。而当工作负载转向 DeepSeek-R1 等更大规模的混合专家模型时，这些优势会大幅扩大——因为在这类模型中，**扩展能力和系统设计对性能结果的影响更为显著。**

::: block-1
:mdnice-bold-italic[根据当前趋势，OpenAI、Meta、Anthropic 等前沿厂商的旗舰模型将继续沿着混合专家模型和推理的方向发展]。如果这一趋势持续，NVIDIA 将保持关键的性能和经济优势——因为其平台正是为这些模型架构带来的压力而优化设计的。
:::

- AMD 等竞争对手正在构建机架级解决方案（如 Helios），这可能在未来 12 个月内帮助缩小差距。
- 到那时，我预计 NVIDIA Vera Rubin 平台将投入生产，其 Ultra 版本也将紧随其后——这将是 NVIDIA 的第四代机架级设计。
- 谷歌 TPU 等架构也提供机架级解决方案，但它们在非第一方模型上的适用性和性能仍不明确。

这些结果只是一个快照，而非对 AMD 竞争力的最终定论。AMD 的性能已有显著提升（NVIDIA 亦然），并且在密集型模型和容量驱动型规划场景中，MI325X 和 MI355X 可能是合适的选择。随着 AMD 继续改进机架级架构和软件，部分场景下的差距可能会缩小，因此采购方应持续通过最新数据和实际工作负载目标进行验证——Signal65 也将持续关注这一领域。

本文记录的性能差异直接转化为可衡量的业务成果。**在特定交互性阈值下，每部署一块 GPU 能服务的用户越多，生成有用 token 的成本就越低**，通过大规模交付更高价值的体验，提升每个机架的收入潜力，最终为 AI 服务提供商和部署高级推理服务的企业带来更好的总拥有成本结果。

> 一个具体例子可以说明其重要性：**当一个平台在特定交互性速率下的每 GPU 吞吐量提升 28 倍时，无需硬件规模的线性增长，就能解锁新的产品等级和更复杂的功能**。这就是 AI 推理的 token 经济学，它更青睐为混合专家模型和推理时代量身打造的平台。
