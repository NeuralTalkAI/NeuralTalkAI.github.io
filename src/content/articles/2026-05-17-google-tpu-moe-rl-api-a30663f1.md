## 一、批量大小：AI 推理成本与延迟的核心杠杆

### 1.1 为什么有"快速模式"和"慢速模式"？

> 几乎所有主流 AI 服务商都提供了不同速度的服务选项：

- Claude 的 Fast Mode 比普通模式贵 6 倍，速度快 2.5 倍；
- Cursor 的 Turbo 模式价格更高，响应更快。

很多人以为这是服务商的定价策略，但 Reiner 指出，这背后是 AI 推理最基本的物理规律：**批量大小决定了成本和延迟的权衡**。

"如果你不批量处理用户请求，成本会比批量处理高出 1000 倍，"Reiner 在黑板上写下第一个公式，"这就是为什么你可以花钱买速度，也可以花时间省钱。"

::: block-1
为了解释这一点，Reiner 引入了两个核心分析工具：屋顶线模型和 Transformer 推理的两个时间组成部分——权重操作时间和上下文操作时间。
:::

### 1.2 屋顶线模型：计算与内存的永恒博弈

> 屋顶线模型是分析计算机系统性能的经典方法，它考虑两个核心资源：计算能力（FLOPS，每秒浮点运算次数）和内存带宽（每秒能从内存读取多少字节）。任何程序的性能都不会超过这两个资源中的瓶颈。

对于 Transformer 推理来说，时间主要由两部分组成：

- **计算时间**：执行权重矩阵乘法的时间，与批量大小成正比
- **内存时间**：从内存读取权重和 KV 缓存的时间，由固定的权重读取时间和与批量大小成正比的 KV 缓存读取时间组成

```
计算时间 = (批量大小 × 活跃参数数量) / 硬件计算吞吐量内存时间 = (总参数数量 / 内存带宽) + (批量大小 × 上下文长度 × 每token字节数 / 内存带宽)总时间 = max(计算时间, 内存时间)
```

Reiner 特别解释了 KV 缓存的概念：在自回归推理中，模型每次生成一个新 token 时，都需要关注之前所有 token 的内部表示。为了避免重复计算，这些表示会被缓存起来，称为 KV 缓存。KV 缓存的大小与批量大小和上下文长度成正比，是长上下文推理的主要内存开销。

### 1.3 成本曲线的秘密：批量越大越便宜

> 如果我们把时间除以批量大小，得到每 token 的成本，就会看到一个非常有趣的曲线：

- 当批量很小时，权重读取时间占主导，每 token 成本极高，几乎与批量大小成反比
- 当批量增大到一定程度，权重读取时间被分摊，KV 缓存读取时间和计算时间开始占主导
- 当批量足够大时，计算时间成为瓶颈，每 token 成本趋于稳定，达到理论最小值

"这就是为什么批量处理如此重要，"Reiner 指着曲线的最低点说，"在批量大小为 1 时，你需要为每个 token 支付读取整个模型权重的成本；而在批量大小为 2000 时，这个成本被分摊到了 2000 个 token 上，几乎可以忽略不计。"

这也解释了为什么"慢速模式"的降价空间有限：KV 缓存是每个用户独有的，无法像权重那样被批量分摊。即使你愿意等更长时间，也无法显著降低 KV 缓存的成本。

### 1.4 最优批量大小的推导：300× 稀疏度法则

> 那么，多大的批量大小才能达到最优效率？Reiner 给出了一个惊人简单的公式：

$$
最优批量大小 ≈ 300 × 稀疏度
$$

其中，稀疏度是总参数数量与活跃参数数量的比值。例如，DeepSeek V3 有 7000 亿总参数和 370 亿活跃参数，稀疏度约为 19，那么最优批量大小约为 5700。

"这个 300 是一个硬件常数，"Reiner 解释道，"它是 GPU 的计算吞吐量与内存带宽的比值，单位是每字节的 FLOPs。从 A100 到 H100 再到 B100，这个比值一直保持在 300 左右，非常稳定。"

::: block-1
这意味着，对于任何模型和任何硬件，最优批量大小只与稀疏度有关，与模型规模无关。这是一个非常强大的结论，它解释了为什么即使是最大的模型，最优批量大小也只有几千。
:::

在实际部署中，服务商通常会选择比最优批量大 2-3 倍的批量，以留出一定的余量。这意味着，一个典型的前沿模型会以每 20 毫秒一个批次的速度运行，每个批次包含约 2000 个序列。

"你可以把这想象成一列火车，每 20 分钟发一班，"Reiner 打了个比方，"不管有没有坐满，火车都会准时发车。如果你的请求刚好在火车发车后到达，你需要等下一班，这就是排队延迟的来源。"

## 二、MoE 模型的物理布局：一个机架就是一个专家层

### 2.1 专家并行：把不同专家放在不同 GPU 上

> 随着混合专家（MoE）模型的兴起，如何在 GPU 集群上高效部署 MoE 成为了一个关键问题。MoE 模型由多个专家组成，每个 token 只会被路由到少数几个专家进行处理。

Reiner 在黑板上画出了一个典型的 MoE 层结构：输入 token 经过路由器，被分配到不同的专家，每个专家是一个独立的 MLP，处理完后再将结果汇总。

"部署 MoE 的最佳方式是专家并行，"Reiner 指出，"也就是把不同的专家放在不同的 GPU 上。"

例如，DeepSeek V3 有 256 个专家，如果部署在一个有 72 个 GPU 的 Blackwell 机架上，我们可以使用其中的 64 个 GPU，每个 GPU 放 4 个专家。这样，当 token 被路由到某个专家时，只需要与对应的 GPU 通信。

### 2.2 全对全通信：MoE 的甜蜜点与瓶颈

> 专家并行的通信模式是全对全（all-to-all）通信：每个 GPU 都可能向其他任何 GPU 发送 token，也可能从其他任何 GPU 接收 token。

"这是一种非常特殊的通信模式，"Reiner 强调，"它要求所有 GPU 之间都有高速、平等的连接。"

幸运的是，现代 GPU 机架的设计正好满足了这一需求。在 Nvidia 的 Blackwell 机架中，所有 72 个 GPU 都通过 NVSwitch 连接在一起，任何两个 GPU 之间的通信只需要两跳，带宽相同。

"一个 Blackwell 机架就是为 MoE 量身定制的，"Reiner 说，"它的全对全通信带宽正好匹配 MoE 的需求。"

::: block-1
然而，当我们试图把 MoE 层扩展到多个机架时，问题就出现了。机架之间的通信带宽通常比机架内部低 8 倍左右。如果一个 MoE 层分布在两个机架上，那么平均有一半的 token 需要跨机架通信，这会成为严重的瓶颈。
:::

### 2.3 为什么一个机架是 MoE 的天然边界？

> "这就是为什么一个机架是 MoE 层的天然边界，"Reiner 得出结论，"你几乎不会看到一个 MoE 层分布在多个机架上。"

这一结论对 AI 模型的规模有着深远的影响。一个 MoE 层的总参数数量不能超过一个机架的内存容量。对于 Blackwell 机架来说，这大约是 20TB，对应约 10 万亿参数（假设使用 FP4 精度）。

这也解释了为什么 Google 的 Gemini 模型在早期能够领先：Google 的 TPU 集群很早就拥有了非常大的 scale-up 域（单个通信域内的芯片数量），能够支持更大的 MoE 层。

### 2.4 线缆密度：被物理世界限制的 AI 规模

> 那么，为什么我们不把更多的 GPU 放在一个机架里，或者建造更大的 scale-up 域呢？Reiner 给出了一个令人惊讶的答案：**物理空间和线缆密度**。

"现代机架已经被推到了物理极限，"Reiner 解释道，"你需要在有限的空间里塞进尽可能多的 GPU、电源、冷却系统和线缆。而线缆的密度是最大的瓶颈之一。"

每个 GPU 需要大量的高速线缆连接到交换机。当你增加 GPU 数量时，线缆数量会呈平方级增长。这些线缆不仅占用空间，还有最小弯曲半径的要求，不能随意弯折。

"从 Hopper 的 8 个 GPU 到 Blackwell 的 72 个 GPU，主要是产品形态的变化，从托盘式变成了机架式，"Reiner 说，"而即将到来的 Rubin 架构将 scale-up 域扩展到 500 多个 GPU，这需要在机架设计上取得重大突破，解决线缆密度、供电和冷却的问题。"

## 三、流水线并行：Ilya 为什么说"这不明智"？

### 3.1 流水线并行的基本原理：把层放在不同机架

> 既然 MoE 层不能跨机架，那么我们如何部署比一个机架内存还大的模型呢？答案是流水线并行。

流水线并行的思想非常简单：把模型的不同层放在不同的机架上。例如，一个有 100 层的模型，可以把前 25 层放在第一个机架，中间 25 层放在第二个机架，以此类推。

当一个请求进入系统时，它首先在第一个机架处理前 25 层，然后把结果发送到第二个机架处理接下来的 25 层，依此类推，直到最后一个机架生成输出。

"这看起来很直观，"Reiner 说，"但它有一个致命的缺点：流水线气泡。"

### 3.2 训练 vs 推理：流水线的不同命运

> 在训练中，流水线并行会产生明显的气泡。为了避免气泡，你需要将批次拆分成多个微批次，让流水线保持满负荷运行。但这会增加训练的复杂度，并且可能影响收敛速度。

然而，在推理中，流水线气泡几乎不存在。"在推理中，你可以连续不断地发送请求，"Reiner 解释道，"只要请求足够多，流水线会一直保持满负荷，没有任何气泡。"

更重要的是，流水线并行对推理的延迟和成本几乎没有影响。"如果把 100 层模型放在一个机架上，或者分成 4 个机架各放 25 层，总延迟是一样的，"Reiner 说，"因为你只是把工作从一个芯片转移到了另一个芯片，总工作量没有变化。"

### 3.3 致命陷阱：KV 缓存无法被流水线分摊

> 既然流水线并行这么好，为什么 Ilya Sutskever 会说"流水线并行并不明智"呢？Reiner 揭示了其中的关键：**流水线并行无法分摊 KV 缓存的内存成本**。

让我们来做一个简单的计算：假设我们有一个 4 阶段的流水线，每个阶段有 P 个 GPU。为了保持流水线满负荷，我们需要同时有 4 个微批次在运行。

这意味着，系统中同时存在的序列数量是单个阶段的 4 倍。而 KV 缓存是每个序列独有的，因此总 KV 缓存内存需求也变成了 4 倍。

"当你增加流水线阶段数量时，权重的内存需求会线性下降，但 KV 缓存的内存需求保持不变，"Reiner 在黑板上写下公式，"最终，KV 缓存会成为主导的内存开销，流水线并行带来的权重内存节省变得微不足道。"

这就是 Ilya 观点的核心：在 KV 缓存主导内存开销的今天，流水线并行的收益非常有限，却带来了巨大的系统复杂度和延迟开销（跨机架通信的延迟）。

### 3.4 规模的真相：带宽比容量更重要

> "很多人以为更大的 scale-up 域是为了增加内存容量，"Reiner 说，"但实际上，它的主要好处是增加内存带宽。"

当你把模型放在一个更大的 scale-up 域中时，你可以并行地从更多的 GPU 读取权重，从而显著降低权重读取时间。例如，一个 72 个 GPU 的 Blackwell 机架的总内存带宽是单个 GPU 的 72 倍，这意味着权重读取时间会降低 72 倍。

"这才是更大 scale-up 域的真正价值，"Reiner 强调，"它让你能够以更低的延迟运行更大、更稀疏的模型。而流水线并行无法提供这种带宽提升，因为每个阶段只能使用该阶段内的 GPU 带宽。"

## 四、RL 的颠覆：模型可能被过度训练 100 倍

### 4.1 Chinchilla 缩放定律的局限性

> 2022 年，DeepMind 提出了著名的 Chinchilla 缩放定律，指出对于给定的计算预算，最优的模型大小和训练 token 数量应该满足：

```
模型参数数量 ≈ 训练token数量 / 20
```

**这意味着，一个 100B 参数的模型应该在 2T token 上训练，才能达到计算最优。**

::: block-1
然而，Reiner 指出，Chinchilla 缩放定律只考虑了预训练的计算成本，没有考虑后续的 RL 微调和推理成本。在今天的 AI 开发流程中，RL 微调已经成为不可或缺的一部分，而推理成本则是模型部署后的主要开销。
:::

"当你把 RL 和推理成本考虑进去时，最优的训练策略会发生巨大变化，"Reiner 说。

### 4.2 总成本最小化：训练、RL、推理的三分天下

> Reiner 提出了一个简单而强大的启发式原则：**当你要最小化两个成本的总和时，最优解通常出现在两个成本相等的地方**。

对于 AI 模型来说，总成本包括三个部分：预训练成本、RL 微调成本和推理成本。

- 预训练成本 ≈ 6 × 活跃参数数量 × 预训练 token 数量
- RL 微调成本 ≈ (2~6) × 活跃参数数量 × RL token 数量
- 推理成本 ≈ 2 × 活跃参数数量 × 推理 token 数量

"如果我们要最小化总成本，那么这三个部分应该大致相等，"Reiner 推测，"每个部分大约占总成本的三分之一。"

这是一个非常大胆的假设，但它得到了现实数据的支持。Reiner 以 GPT-4 为例进行了估算：

- 假设 GPT-4 的活跃参数数量约为 100B
- 假设 GPT-4 在部署期间总共处理约 200T 推理 token
- 那么预训练和 RL 微调也应该各消耗约 200T token

### 4.3 第一性原理推导：100 倍过度训练的由来

> 根据 Chinchilla 缩放定律，一个 100B 参数的模型只需要 2T token 就能达到计算最优。但根据上面的估算，GPT-4 实际上训练了约 200T token，是 Chinchilla 最优的 100 倍。

"这就是我所说的 100 倍过度训练，"Reiner 说，"这不是浪费，而是为了最小化总成本而做出的理性选择。"

为什么会这样？因为过度训练可以让模型在相同参数数量下达到更高的质量，或者在相同质量下使用更小的模型。而更小的模型意味着更低的 RL 和推理成本。

"如果你有一个非常受欢迎的模型，它会被数十亿用户使用，那么在预训练上多花 10 倍的钱，让模型小一半，从而节省一半的推理成本，这是非常划算的，"Reiner 解释道。

RL 的引入进一步放大了这种效应。RL 微调需要大量的推理来生成轨迹，而更小的模型可以显著降低 RL 的成本。

### 4.4 这对 AI 未来意味着什么？

> 100 倍过度训练的结论对 AI 的未来有着深远的影响：

- 模型规模的增长可能会放缓，而训练 token 数量会继续快速增长
- 数据的重要性会进一步提升，高质量数据将成为最稀缺的资源
- 推理效率会成为模型设计的首要考虑因素，稀疏模型和高效架构会越来越受欢迎
- 模型的更新周期会缩短，因为过度训练的模型可以更快地迭代

"我们正在从'模型规模竞赛'转向'训练效率和推理效率竞赛'，"Reiner 总结道，"未来的赢家不一定是拥有最大模型的公司，而是能够以最低成本训练和部署高质量模型的公司。"

## 五、从 API 价格反推：长上下文的真实成本

### 5.1 Gemini 定价泄露的秘密：200K 是成本拐点

> AI 服务商的 API 定价看似随意，实则严格反映了它们的真实成本。Reiner 以 Gemini 2.5 Pro 的定价为例进行了分析：

- 输入价格：≤200K token 时 $1.25/百万，>200K token时$2.50/百万
- 输出价格：≤200K token 时 $10.00/百万，>200K token时$15.00/百万

"为什么 200K 是一个价格拐点？"Reiner 问道，"因为这正是计算和内存带宽的平衡点。"

当上下文长度小于 200K 时，计算时间占主导，成本相对稳定。当上下文长度超过 200K 时，KV 缓存的内存读取时间超过了计算时间，成为新的瓶颈，成本开始线性增长。

通过简单的代数推导，Reiner 从这个价格拐点反推出了 Gemini 模型的每 token KV 缓存大小约为 2KB。"这与我们对现代 Transformer 模型的了解一致，"Reiner 说，"它可能使用了 8 个 KV 头，每个头的维度是 128，正好是 2KB per token。"

### 5.2 预填充 vs 解码：为什么输出比输入贵 5 倍？

> 另一个有趣的定价现象是，输出 token 的价格通常是输入 token 的 3-5 倍。这是因为输入处理（预填充）和输出生成（解码）的计算模式完全不同。

- **预填充**：一次性处理所有输入 token，可以充分利用 GPU 的并行计算能力，计算效率很高
- **解码**：逐个生成输出 token，每个 token 都需要读取整个模型的权重，内存带宽成为瓶颈，计算效率很低

"在解码阶段，GPU 的计算利用率通常只有预填充阶段的 1/5 左右，"Reiner 解释道，"这就是为什么输出 token 要贵 5 倍。"

这也解释了为什么长上下文的预填充价格相对便宜，而长上下文的解码价格会大幅上涨。预填充是计算密集型的，而解码是内存带宽密集型的，长上下文会进一步加剧解码的内存带宽压力。

### 5.3 上下文缓存的经济学：HBM、DDR 还是机械硬盘？

> 为了降低长上下文的成本，很多服务商推出了上下文缓存功能。如果用户的请求包含与之前请求相同的上下文，服务商可以重用之前计算好的 KV 缓存，而不需要重新计算。

Gemini 的上下文缓存定价非常有启发性：

- 缓存读取价格：$0.3125/百万 token（≤200K）
- 缓存存储价格：$4.50/百万 token/小时

"从这些价格中，我们可以反推出服务商使用的存储介质，"Reiner 说。

存储介质的选择取决于两个成本：存储成本（每字节每秒）和读取成本（每字节）。不同的存储介质有不同的特性：

- **HBM**：速度最快，存储成本最高，读取成本最低
- **DDR**：速度中等，存储成本中等，读取成本中等
- **闪存**：速度较慢，存储成本较低，读取成本较高
- **机械硬盘**：速度最慢，存储成本最低，读取成本最高

"根据 Gemini 的定价，5 分钟的缓存可能存储在闪存中，而 1 小时的缓存可能存储在机械硬盘中，"Reiner 推测，"这听起来很疯狂，但机械硬盘的存储成本确实比 HBM 低几个数量级，对于不常访问的缓存来说，这是一个经济的选择。"

### 5.4 百万级上下文的真正障碍：内存墙

> 很多人期待未来的模型会有百万级甚至亿级的上下文窗口，但 Reiner 对此持谨慎态度。

"长上下文的主要瓶颈不是计算，而是内存带宽和内存容量，"Reiner 说，"KV 缓存的大小与上下文长度成正比，当上下文长度达到百万级时，KV 缓存会变得非常巨大。"

例如，一个 100 万 token 的上下文，每个 token 的 KV 缓存是 2KB，那么总 KV 缓存大小就是 2GB。如果同时处理 100 个这样的序列，就需要 200GB 的内存，这已经接近单个 GPU 的 HBM 容量。

**更严重的是，读取这么大的 KV 缓存需要消耗大量的内存带宽**。"当上下文长度达到百万级时，几乎所有的内存带宽都被用来读取 KV 缓存，没有多余的带宽来读取权重，"Reiner 解释道，"这会导致性能急剧下降。"

::: block-1
稀疏注意力可以在一定程度上缓解这个问题，但它不是万能的。"如果你太稀疏，模型就无法关注到重要的信息，质量会下降，"Reiner 说，"目前看来，200K-1M 是长上下文的经济合理区间。"
:::

## 六、趋同进化：神经网络与密码学的惊人相似

### 6.1 相同的核心目标：彻底混合信息

> 在讲座的最后，Reiner 分享了一个非常新颖的观点：**神经网络和密码学算法在架构上有着惊人的相似性，这是趋同进化的结果**。

"神经网络和密码学算法的核心目标是一样的，"Reiner 说，"它们都需要彻底混合输入信息，让每个输出都依赖于所有输入。"

- 对于密码学算法（如哈希函数和加密算法），混合信息是为了让输出看起来完全随机，无法从输出反推出输入
- 对于神经网络，混合信息是为了让模型能够捕捉输入中不同部分之间的复杂关系，从而做出准确的预测

### 6.2 相同的架构模式：线性+非线性的重复堆叠

> 为了实现彻底的信息混合，神经网络和密码学算法都采用了相同的架构模式：**线性变换和非线性变换的重复堆叠**。

- 在 Transformer 中，每个层由注意力机制（跨位置混合）和 MLP（位置内混合）组成，都是线性变换 followed by 非线性变换
- 在 AES 加密算法中，每个轮由 ShiftRows（行混合）、MixColumns（列混合）和 S-box（非线性变换）组成
- 在 SHA-3 哈希函数中，每个轮由 θ、ρ、π、χ 和 ι 五个步骤组成，同样是线性和非线性变换的组合

"更有趣的是，它们都采用了分块混合的策略，"Reiner 补充道，"先在小范围内混合，然后在更大范围内混合，这样可以在保证混合效果的同时，提高计算效率和并行性。"

### 6.3 相反的优化目标：结构提取 vs 随机化

> 尽管架构相似，但神经网络和密码学算法的优化目标完全相反：

- 密码学算法的目标是最大化输出的随机性和不可预测性，防止任何形式的逆向工程
- 神经网络的目标是从输入中提取有用的结构和模式，让输出具有可解释性和预测性

这种相反的目标导致了一些关键的设计差异：

- 神经网络使用残差连接和 LayerNorm 来保持梯度的稳定性，便于训练
- 密码学算法避免使用残差连接，因为它们会削弱混合效果，容易受到差分密码分析攻击
- 神经网络使用浮点数运算，便于梯度下降
- 密码学算法使用整数运算，避免数值精度问题

### 6.4 交叉启发：从 Feistel 密码到可逆神经网络

> 尽管目标不同，但两个领域之间已经出现了交叉启发。最著名的例子是 Feistel 网络在神经网络中的应用。

Feistel 网络是密码学中一种经典的可逆结构，它可以将任何非可逆函数转换为可逆函数。2017 年，研究人员将 Feistel 网络引入神经网络，提出了可逆残差网络（RevNets）。

::: block-1
"RevNets 的核心思想是让整个神经网络可逆，"Reiner 解释道，"**这样在训练时，你不需要存储中间激活，只需要在反向传播时重新计算它们。这可以节省大量的内存。** "
:::

虽然 RevNets 在今天的大模型训练中并不常用，但它展示了跨领域借鉴的巨大潜力。"我相信未来还会有更多这样的交叉创新，"Reiner 说，"密码学领域几十年的研究成果，可能会为 AI 架构的创新提供新的思路。"

## 结语

> 这场两个多小时的讲座，让我们看到了 AI 背后那些不为人知的底层逻辑。从批量大小的经济学到 MoE 的物理布局，从流水线并行的陷阱到 RL 对训练策略的颠覆，从 API 定价泄露的技术秘密到神经网络与密码学的趋同进化，每一个结论都来自第一性原理的推导，每一个公式都揭示了 AI 行业的本质。

Reiner 的分析告诉我们，**AI 不是魔法，它是建立在物理世界之上的工程技术。它的发展不仅受算法和数据的限制，更受 GPU 的内存带宽、机架的线缆密度、电力和冷却等物理因素的约束**。理解这些约束，才能真正理解 AI 的现在和未来。

在这个 AI 快速发展的时代，我们很容易被各种炫目的应用和惊人的参数所迷惑，却忽略了那些决定 AI 本质的底层问题。而正是这些底层问题，才是真正的技术壁垒和商业机会所在。

::: block-1
最后，留给大家一个开放性的问题：如果内存墙是 AI 发展的主要瓶颈，那么未来的 AI 硬件和架构会朝着什么方向发展？是继续扩大 HBM 的容量和带宽，还是探索全新的计算范式，比如存内计算或者神经形态计算？这个问题的答案，将决定下一个十年 AI 的面貌。
:::

## 📌 核心 Takeaways

1. **批量大小是 AI 推理成本和延迟的核心杠杆**，最优批量大小约为 300× 稀疏度，与模型规模无关
2. **MoE 模型受限于全对全通信**，一个机架是 MoE 层的天然部署边界，线缆密度是限制 scale-up 域大小的主要物理因素
3. **流水线并行无法分摊 KV 缓存成本**，在 KV 缓存主导内存开销的今天，其收益非常有限，这是 Ilya 认为"流水线并行不明智"的核心原因
4. **由于 RL 和推理成本的引入**，前沿模型可能被过度训练 100 倍以上，远超 Chinchilla 最优，这是最小化总成本的理性选择
5. **长上下文的主要瓶颈是内存带宽而非计算**，200K 是当前的成本拐点，百万级上下文短期内难以普及，经济合理区间在 200K-1M
