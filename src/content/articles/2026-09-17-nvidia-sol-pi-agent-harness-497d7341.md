## 一、问题根源：长周期 Agent 的 Token 浪费困境

> 编码智能体的能力边界在过去两年快速扩张，从单行代码补全到跨仓库问题修复，从单步工具调用到多 Agent 连续数天协同工作。

**随着运行轨迹不断拉长，Token 消耗的增长速度已经超过了任务产出的增长速度**。:mdnice-bold-italic[尤其是在长周期无人值守场景下，很多结构性的 Token 浪费会反复出现，最终累积成巨大的成本开销。]

### 1.1 递归自改进的成本悖论

递归自改进被业界普遍视为通向更高阶智能的关键路径。当 AI 系统能够改进自身的底层软件栈时，能力提升的速度就有可能脱离人类迭代的节奏，进入加速轨道。但这条路径上有一个容易被忽略的经济悖论：递归自改进本身是极度消耗 Token 的。

:mdnice-bold-italic[每一轮自改进尝试，从提出方案、修改代码、运行测试到验证结果，无论最终成功还是失败，都要消耗大量的模型调用和 Token。如果基础调度框架本身效率很低，每一轮迭代的成本都很高，那么即使技术上可行，经济上也会不可持续]。改进的收益会被高昂的迭代成本吞噬，最终陷入越改进越昂贵的怪圈。

::: block-1
作者明确指出了这个核心矛盾：:mdnice-highlight[在规模化推进递归自改进之前，首先应该让 AI 来优化 AI 自身的运行效率。先把每一轮迭代的成本降下来，递归自改进才能真正转起来。]
:::

### 1.2 现有优化的结构性盲区

> 目前行业内的 Token 优化大多集中在单点层面，比如 Prompt 压缩、KV 缓存优化、RAG 检索、少样本提示等。**这些方法确实能在一定程度上减少 Token 消耗，但存在两个根本性的局限。**

- **第一，这些优化大多是静态的、单点的，没有从整个 Agent 交互链路的架构层面系统性地消除浪费**。比如重复的工具输出传输、多余的模型往返、无效的上下文回放，这些跨环节的结构性浪费，单点优化很难触及。
- :mdnice-bold-italic[第二，很多所谓的效率提升本质上是降配，通过减少验证步骤、跳过必要检查、缩短推理链来节省 Token，最终以牺牲任务完成质量为代价]。这种优化在短任务中可能不明显，但在长周期复杂任务中会导致成功率大幅下降。

这就带来了一个核心判断：长周期 Agent 的效率提升，必须从架构层面入手，并且必须建立严格的能力底线，确保节省的是浪费，而不是必要的工作。

## 二、核心方法：可扩展的自动研究循环流水线

> **SoL-Pi 的核心思路是把 Harness 优化本身变成一个开放的递归自改进问题**，用自动化的研究循环大规模搜索可复用的效率机制，跳出了人工设计单点优化的传统思路。

整个系统像一个自动化的研究实验室，同时测试上百种优化思路，通过层层验证筛选出真正有效的机制，最终组合成完整的高效调度框架。

### 2.1 双层搜索架构

> **SoL-Pi 采用外层广度优先、内层深度优先的双层搜索架构**。

![文章插图](/articles/2026-09-17-nvidia-sol-pi-agent-harness-497d7341/images/03.gif)

- 外层是一个包含 152 个候选方向的提案池，覆盖上下文管理、进度控制、工具调用、委派、提示策略、改进评估六大类。
- 所有提案先经过 Oracle 分析预筛选，基于已有轨迹估计潜在收益，只有值得投入的方向才会进入完整的实验循环。

每个选中的方向都会独立进入一套自动研究循环，在谱系内部进行迭代优化。这种设计兼顾了搜索的多样性和深度：广度保证不会错过有潜力的方向，深度保证每个候选都能被充分打磨。

### 2.2 七步自动研究循环

> 每个候选机制的完整研究循环包含七个阶段，全程自动化运行，无需人工干预。

| 阶段 | 描述 |
| --- | --- |
| 轨迹生成 | 让 Agent 在训练环境中运行，生成原始的探索轨迹，作为分析的数据源。 |
| 映射归约分析 | 独立的分析器分别检查每条轨迹，提取效率痛点和优化线索，然后由归约器合并证据，形成统一的分析结论。 |
| 提案生成 | 基于分析结论，提出具体的机制改进方案，明确优化目标和预期收益。 |
| 代码实现 | 由一个专门的实现 Agent 编写代码，将提案修改到基础 Harness 中。 |
| 代码审查 | 另一个独立的审查 Agent 检查实现结果，验证是否符合行为契约，存在问题就返回实现阶段修改。 |
| 轨迹内验证 | 在训练集上运行验证，测试机制是否有效，是否满足能力底线，不通过可以返回实现或者轨迹生成阶段。 |
| 留出集验证 | 将机制完全冻结，在完全隔离的留出测试集上做最终评估。验证结果绝不反馈回研究循环，防止过拟合。 |

其中双阶段验证是保证泛化性的关键设计。训练集用来迭代和筛选，留出集用来最终检验，两者完全隔离，确保存活的机制不是针对特定任务的过拟合，而是可复用的通用改进。

::: block-1
回顾一下，SoL-Pi 的方法本质是**用大规模自动化实验替代人工设计，用广度搜索突破局部最优，用严格的隔离验证保证泛化性**。:mdnice-highlight[它跳出了单个 Prompt 调优的层面，专注于发现可复用的 Harness 架构级效率机制。]
:::

## 三、演进之路：三代工作流架构的迭代与取舍

> 要同时调度上百个自动研究循环、上千次 Agent 运行，工作流架构本身就是一个核心工程挑战。

**研究团队先后迭代了三代设计，每一代都解决了上一代的瓶颈，也带来了新的取舍**，:mdnice-bold-italic[最终定型为一次性技能循环架构，支撑起了百级并行的实验规模。]

### 3.1 三代架构的核心差异

> 三代工作流的核心差异在于编排逻辑的载体、生命周期和扩展方式，各自适用于不同的规模阶段。

| 设计 | 优势 | 局限 |
| --- | --- | --- |
| 编译型工作流 | 交接清晰，流程明确 | 超出固定图后脆弱不堪，大规模运行频繁需要人工修复 |
| 代码编排型工作流 | 运行时灵活，无固定流程限制 | 协调器代码持续膨胀，启动新实验成本极高 |
| 一次性技能循环 | 易于并行扩展，维护成本低 | 依赖可靠的基础模板，模板错误会影响所有实验 |

*表 1：三代工作流架构对比。编译型工作流是配置驱动的静态架构，适合固定流程的小规模实验；代码编排是中心化的动态架构，适合中等复杂度的多轮迭代；一次性技能循环是模板化的无状态架构，专为大规模并行实验设计。*

### 3.2 最终方案：一次性技能循环

> 一次性技能循环的核心设计理念是：**编排逻辑的生命周期和单次实验对齐**。团队维护一个最小的循环模板和使用说明，每个实验都实例化一个全新的副本，设置参数，运行结束后就丢弃修改过的编排代码。

这种设计带来了两个关键优势。

- 第一，扩展就是重复实例化模板，不需要不断修改一个中心化的协调器，并行规模可以轻松横向拓展。
- 第二，每个实验的编排代码都是独立的，不会互相影响，也不会累积历史债务。

当然它也有前提：基础模板本身必须足够可靠，因为所有实验都会继承它的行为。但实践证明，**维护这一个单一的共享依赖，比维护一个不断膨胀的中心化协调器或者修复无数个固定流程的边缘情况要容易得多。**

### 3.3 训练环境与能力底线

> 为了支撑自动研究，团队构建了 535 个可执行训练环境，分为两大类。

- 第一类包含 495 个任务，数据来自 GitHub 的 issue-PR 对。Issue 定义任务，对应的 PR 提供了接受的补丁和修改历史，作为基准轨迹。团队将仓库恢复到修复前的提交，离线安装依赖，对 Agent 隐藏 PR 和维护者的回归测试。只有修复前测试失败、修复后测试通过的环境才会被保留，确保任务、轨迹和验证器的一致性。
- 第二类包含 40 个合成任务，由验证器驱动。先生成可执行的验证器定义成功标准，再围绕验证器构建环境，没有参考轨迹，适合开放式探索。

作为最终验证的 EdgeBench 基准完全独立，其任务和验证器既不参与环境构建，也不参与研究循环，只用来做最终的留出验证。这种严格的隔离，让最终的分数更能代表对未知任务的泛化能力。

同时，每一轮筛选都设置了严格的能力地板：所有能力指标必须保持在预先声明的容忍范围内，同时至少有一个效率指标提升。这就从规则上排除了靠少做事省钱的优化，确保效率提升是真的消除了浪费，而不是降低了输出标准。

::: block-1
整体看下来，三代工作流的迭代印证了一个工程规律：**大规模并行系统的架构瓶颈，最终都会从功能灵活性转向可维护性和扩展性**。:mdnice-highlight[一次性技能循环用模板化的设计，把编排逻辑的生命周期从“永久”压缩到“单次实验”，换来了横向扩展能力的阶跃式提升。]
:::

## 四、四大存活机制：从 152 个提案中筛选出的效率密码

> 152 个候选提案经过层层筛选，最终只有 4 个机制通过了所有验证关卡，进入最终的 SoL-Pi 框架。

![文章插图](/articles/2026-09-17-nvidia-sol-pi-agent-harness-497d7341/images/04.gif)

这四个机制分别对应工具调用、上下文管理、观测压缩和多智能体委派四个维度，每一个都击中了长周期 Agent 的一个核心浪费点。

### 4.1 动作融合：一次意图，一次往返

> 基础 Pi 框架中存在一个非常普遍的交互模式：Agent 编辑完文件后，紧接着就会发出测试、构建或者运行的命令。这两个动作之间不需要额外的决策，却要多走一次完整的模型往返，浪费大量 Token。

![文章插图](/articles/2026-09-17-nvidia-sol-pi-agent-harness-497d7341/images/05.gif)

动作融合的核心思路就是把编辑和后续的命令合并成一个工具调用。Harness 在本地应用文件编辑，然后直接执行后续命令，最后返回一个合并的观测结果，省去中间的模型轮次。

它的优化过程分为四个阶段：

- 第一阶段是 Oracle 分析，预扫描现有轨迹发现，12.3%的跨轮次转换是相邻的编辑-命令对，其中 bash 命令占 85.1%，确认了这个优化点的潜力。
- 第二阶段是基线构建，稳定实现动作融合机制，在符合条件的调用中达到 87.7%的触发率，零无效调用，建立了可靠的优化基线。
- 第三阶段是 Prompt 优化，经过 10 轮搜索迭代，淘汰失败的 Prompt 变体，持续优化提示和模式定义，最终在第 10 轮达到 100%触发率，同时任务分数保持在 87.0。
- 第四阶段是最终验证，执行两轮独立的最终检查，确认释放行为符合预期，之后才加入最终的组合框架。

根据轨迹反推，如果所有符合条件的跨轮次都触发动作融合，模型轮次会从 1386 次降到 1237 次，减少 10.8%；总 Token 从 3238 万降到 2864 万，减少 11.5%。

### 4.2 在线上下文压缩：子任务边界处的精准压缩

> 传统的 KV 缓存复用策略通常把压缩推迟到运行后期，上下文已经膨胀到很大的时候才做处理，属于被动的事后压缩。在线上下文压缩采用了完全不同的时间策略。

![文章插图](/articles/2026-09-17-nvidia-sol-pi-agent-harness-497d7341/images/06.gif)

它将任务拆解为多个子任务，把语义上的子任务完成作为压缩的触发点，每当一个子任务结束时就重新评估一次压缩的必要性。但它不会为了压缩而压缩，只有当预期的未来节省能够覆盖重写的成本时，才会执行压缩操作。

这种设计让压缩从被动的满了再清变成了主动的收益驱动，每一次压缩都是净收益，避免了不必要的压缩开销。

### 4.3 观测包：保留访问权，移除重复

> 在长任务中，大文件内容或者工具的输出结果会在后续每一次请求中重复出现，同时占用上下文窗口和缓存空间。**这是长周期 Agent 最主要的 Token 浪费来源之一。**

![文章插图](/articles/2026-09-17-nvidia-sol-pi-agent-harness-497d7341/images/07.gif)

观测包机制改变了这种交互模式。它将完整的输出数据本地归档，:mdnice-bold-italic[在上下文中只保留一个句柄和简短摘要，只有当 Agent 明确需要查看详细内容时，才召回精确的对应页面。这样 Harness 不用在每一轮都重复传输完整结果，却随时可以访问原始的完整数据。]

它的优化同样经过了严格的四阶段验证：

- 第一阶段从零重建，基于干净的 Pi 基线重新实现，得到干净的初始版本。
- 第二阶段机制冻结，经过 4 轮迭代精简，最终实现只有 315 行代码和两个接入钩子，并且采用故障打开契约，确保机制失效时不会影响正常运行。
- 第三阶段权衡扫描，遍历 8 种不同的配置参数，用 4 组同期运行做确认，最终 V2 配置是唯一同时落在质量门和成本门内的版本。
- 第四阶段配对 A/B 测试，在 EdgeBench 的 11 个任务上双分支并发运行，排除环境波动影响。

最终测试结果显示，观测包机制让提供商账单减少 23.58%，单次响应成本减少 23.73%，而归一化任务分数反而提升了 22.92%。响应总数量仅变化了 0.20%，**说明成本节省完全来自于单次响应更高效，而不是减少了响应次数。**

### 4.4 证据保留归约器：委派阅读，验证证据

> 在构建和测试类任务中，往往只有长日志里的几行会决定 Agent 的下一步决策，但完整的日志却要全部传给前端的强模型，造成大量不必要的 Token 消耗。

![文章插图](/articles/2026-09-17-nvidia-sol-pi-agent-harness-497d7341/images/08.gif)

证据保留归约器利用这个边界做优化，把第一轮日志阅读委派给更便宜的小模型，生成精简的诊断收据。但它不会直接信任这个摘要，而是把收据和归档的完整日志绑定，每一行引用的内容都要和原始日志验证无误后，再传给前端的主 Agent。

这样一来，委派不再依赖于对总结质量的信任，而是有可验证的证据支撑，既节省了 Token，又保证了信息的准确性。

::: block-1
总之，这四个机制有一个共同的底层逻辑：**消除没有决策价值的 Token 传输，保留所有必要的信息访问权**。:mdnice-highlight[它们没有改变 Agent 的决策能力，也没有减少必要的工作步骤，只是把那些重复的、冗余的、不需要模型参与的中间环节全部砍掉了。]
:::

## 五、实验验证：EdgeBench 上的能效实测结果

> 所有机制组合完成后，研究团队在 EdgeBench 基准上进行了完整的对比测试，全面验证 SoL-Pi 的实际能效表现。

测试分别在 GPT-5.6 Sol 和 Claude Opus 两个主流模型后端上进行，所有模型都使用 xhigh 最高推理设置，确保对比的公平性。

### 5.1 基准选择的合理性

> 研究团队选择 EdgeBench 作为核心基准，是因为它是少有的支持长周期 Agent 运行的测试集。EdgeBench 包含 51 个任务，单次运行通常持续 2 到 12 小时，能够充分累积长周期运行中的各种效率浪费。

![文章插图](/articles/2026-09-17-nvidia-sol-pi-agent-harness-497d7341/images/09.jpg)

::: image-caption
对比不同模型在两类评测集上的平均得分。左侧 GPT-5.6 Sol-xhigh 组别里，Codex 得分最低仅 34.74，Pi 为 44.83，SoL-Pi 是 42.00；右侧 Claude Opus 5-xhigh 组别中，Claude Code 得分 43.69，Pi 达到 44.76，SoL-Pi 为 42.22。可见 Pi 模型在两组测试中均取得最高平均分，SoL-Pi 次之，Codex 在 GPT 系列评测里表现明显弱于其他模型，整体来看 Pi 在该任务下性能优势突出。

从具体数据来看：

- 能力层面，:mdnice-bold-italic[SoL-Pi 在两个模型后端都保留了 Pi 大约 94%的平均任务分数，并且在 GPT-5.6 Sol 后端超过了模型原生的 Codex 调度框架，证明效率优化没有牺牲任务质量。]
- Token 层面，**对比基础 Pi 框架，SoL-Pi 减少了 45%到 49%的总 Token 消耗**；对比模型原生的调度框架，减少了 35%到 64%的 Token。
- 成本层面，:mdnice-bold-italic[对比基础 Pi 框架，官方 API 等价成本降低约三分之一；对比模型原生调度框架，成本降低 50%到 54%。换算成单小时成本，对比原生 Codex 和 Claude Code 每小时节省 8.75 到 13.50 美元，对比 Pi 每小时节省 4.36 到 5.71 美元。]

::: block-1
整体看下来，实验结果验证了一个核心结论：**针对长周期轨迹的结构性优化，能够在几乎不损失任务能力的前提下，带来量级级别的 Token 成本下降**。:mdnice-highlight[这种效率提升来自对交互链路系统性浪费的消除，完全不需要以牺牲模型推理速度为代价，因此可以叠加在任何模型推理优化之上。]
:::

## 六、自动研究的边界与未来方向

> SoL-Pi 的意义不止于一个更高效的 Agent 框架，它更展示了自动研究循环的潜力和边界。

### 6.1 Token 效率导向可复用改进

**和针对特定任务的优化不同，Token 效率的优化目标是跨任务重复出现的工作模式**。比如消除重复上下文、合并连续动作、避免重复传输大输出，这些改进都不依赖于知道某个任务的答案，因此更容易迁移到新任务和新模型。

相反，**如果优化目标是任务分数本身，搜索循环就很容易把任务相关的信息塞进 Harness，或者针对训练任务的模式加特殊规则，最终导致过拟合，离开训练集就失效**。Token 效率作为目标，天然地引导搜索走向通用的、可复用的机制改进。

### 6.2 广度搜索突破局部最优

> **研究团队观察到一个很有意思的现象：即使是 GPT-5.6 Sol 这样的强模型，在深度优先优化时，经过 5 到 10 轮迭代也会陷入局部盆地**，只能对同一个设计做小修小补，无法跳转到更好的方向。

**而广度优先搜索则完全不同**。:mdnice-bold-italic[虽然大部分初始想法都会在验证中失败，但多样化的起点偶尔会发现不同寻常的候选，后续的迭代可以把它打磨成非常有价值的改进]。152 个初始想法里大约只有四十分之一能够存活，但正是这些少数存活者带来了最核心的效率提升。

广度让那些罕见但高价值的候选有机会被发现，这是只做深度优化永远得不到的结果。

### 6.3 人与自动研究的角色边界

> **SoL-Pi 本质上是一个混合自动研究循环，人类和 AI 各有分工。人类提供早期的先验知识，过滤掉没有探索价值的方向，比如基础 Harness 的超参数搜索**。一旦想法进入自动研究循环，就全程无人干预，自主完成实现、测试、验证的全流程。只有当候选机制最终存活后，人类才会重新介入，理解背后的原理，把代码重构成干净可维护的版本。

完全自主的递归自改进是不是最终的理想状态，目前还是未知数。在开放式循环中，目标漂移、证据漂移、实现漂移都可能在人类察觉之前就累积起来，最终的后果可能难以逆转。人类和机器规模研究之间的关系，还需要持续的探索和界定。

### 6.4 效率的递归性愿景

> 效率本身就可以是递归的。一个更高效的 Harness，可以降低构建它下一代的自动研究成本。**研究团队计划用 SoL-Pi 作为下一轮研究的起点，更低的单次运行成本意味着固定预算可以覆盖更多的实验环境、更多的轨迹和更多的研究想法。**

在这个视角下，:mdnice-bold-italic[效率既是 Harness 研究的结果，也是扩展后续研究的资源。更高效的框架，可能帮助发现更高效的下一代框架]。研究团队将这个长期愿景称为效率换效率，这也是递归自改进真正能够转起来的经济基础。

::: block-1
总之，SoL-Pi 真正的突破是**证明了用自动化研究循环系统性优化 AI 交互架构是可行的**。:mdnice-highlight[当 AI 开始高效地改进自己的基础设施，递归自改进的经济门槛就会大幅下降，整个行业的发展节奏可能都会因此改变。]
:::
