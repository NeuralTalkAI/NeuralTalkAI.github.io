## 一、 旧瓶新酒？从投机解码的瓶颈说起

> 在深入 SSD 之前，我们需要先理解其基础——投机解码（SD）的局限性。

![文章插图](/articles/2026-04-02-30-tri-dao-saguaro-d534d1ba/images/05.webp)

::: image-caption
图 1：SD 与 SSD 流程及性能对比图。左图：普通推测解码（SD）中验证器需闲置等待草稿模型完成投机；中图：本文的 SSD 算法，投机在独立设备（1 块 H100）与验证并行执行，草稿模型为多种可能的验证结果预计算投机结果，若实际结果在预计算范围内则立即返回，SSD 将草稿模型部署在独立 GPU，实现投机与验证的硬件级解耦，从根本上消除了 SD 的等待开销；右图：Llama-3.1-70B 在 4 块 H100、批大小 1、贪心解码、Llama-3.2-1B 为草稿模型的配置下，在数学、代码、对话四类数据集上，AR、SD、SSD 的端到端性能均值，显示 SSD 的解码速度远超 SD 和 AR，最高实现 3.1× 的提速。这一结果直接验证了 SSD 并行设计的有效性，也说明硬件解耦是突破 SD 性能上限的关键，同时证明 SSD 在多类型任务中均有显著的性能提升效果。
:::

如图 1（左）所示，传统的 SD 工作流程是串行的：

1. 投机阶段：一个快速的投机模型（Draft Model）基于当前上下文，自回归地生成 K 个未来 token，例如 5 个。
2. 验证阶段：一个庞大的目标模型（Target Model）在一次并行前向传递中，验证这 K 个 token 是否与自己的预测分布一致，并接受或拒绝它们。
3. 同步点：验证完成后，如果所有 K 个 token 都被接受，目标模型还会额外采样一个“奖励 token”。然后，投机模型等待验证结果，开始下一轮的投机。

::: block-1
这种“投机-验证-等待-再投机”的模式，使得目标模型在等待投机模型生成 token 时处于空闲状态，而投机模型在等待验证结果时也处于空闲状态。:mdnice-bold-italic[这种串行依赖，成为了加速推理的瓶颈。 其本质是，我们无法有效利用现代硬件（如 GPU）强大的并行计算能力，因为整个流程被一个顺序依赖所“锁住”。]
:::

**核心问题：如何让这两个模型“并行”工作**，而不仅仅是“串行”工作？

## 二、 核心理念：让投机模型“预知未来”

> SSD（投机投机解码）的答案，正是将“投机”本身也并行化。

![文章插图](/articles/2026-04-02-30-tri-dao-saguaro-d534d1ba/images/06.webp)

::: image-caption
图 1：SD 与 SSD 流程及性能对比图。左图：普通推测解码（SD）中验证器需闲置等待草稿模型完成投机；中图：本文的 SSD 算法，投机在独立设备（1 块 H100）与验证并行执行，草稿模型为多种可能的验证结果预计算投机结果，若实际结果在预计算范围内则立即返回；右图：Llama-3.1-70B 在 4 块 H100、批大小 1、贪心解码、Llama-3.2-1B 为草稿模型的配置下，在数学、代码、对话四类数据集上，AR、SD、SSD 的端到端性能均值。
:::

> 让我们看看图 1（中）描绘的 SSD 框架。其核心机制如下：

1. 异步并行：**投机模型运行在独立的硬件设备**，如另一块 H100 GPU上，与目标模型的验证过程完全并行。
2. 预计算缓存：**当目标模型正在验证来自第 T 轮的投机结果时，投机模型已经开始为第 T+1 轮做准备了**。但它:mdnice-bold-italic[不是简单地等待第 T 轮的验证结果，而是【预测】第 T 轮【可能出现的各种验证结果】。]
3. “投机缓存”：基于这些预测，**投机模型提前为每一个可能的验证结果，预计算好下一步（第 T+1 轮）的投机序列**，并存储在投机缓存（Speculation Cache）中。
4. 即时命中：当第 T 轮的验证结果实际产生时，投机模型只需检查该结果是否在缓存中。如果是（缓存命中），它就能立即从缓存中取出对应的预计算投机序列，并发送给目标模型进行下一轮验证，从而将原本需要花费的投机时间完全“隐藏”起来。

## 三、Saguaro：一个优化的 SSD 实现

尽管 SSD 框架极具吸引力，但要将其付诸实践，面临着三个核心挑战。Saguaro 正是为应对这些挑战而设计的优化算法。

### 3.1 挑战一：如何准确预测验证结果？

> 验证结果（Verification Outcome）包含两个关键信息：

- 接受长度：有多少个被投机的 token 被目标模型接受（记为 k）。
- 奖励 token：在接受了 k 个 token 后，从目标模型的残余分布中采样得到的那个 token，记为 $t*$。

**预测的难点在于，可能的结果空间是巨大的**，大约为 $(K+1) * V$，其中 $K$ 是投机长度，$V$ 是词汇表大小。例如，$K=5，V=128,000$，就有约 77 万种可能！预计算所有可能性是完全不切实际的。

::: block-1
Saguaro 的解法：将此问题转化为一个受限优化问题。:mdnice-bold-italic[给定一个预算 B ——即在验证完成前，投机模型能预计算的结果数量]。我们**如何选择最有可能发生的 B 个验证结果，以最大化缓存命中率？**
:::

#### 1. 缓存构建策略（几何扇出）

> Saguaro 将问题分解为：对于每个可能的接受长度 k（0 到 K），我们应预先计算多少个可能的奖励 token？这个数量称为“扇出”（Fan-out） $F_k$。

![文章插图](/articles/2026-04-02-30-tri-dao-saguaro-d534d1ba/images/07.webp)

::: image-caption
图 2：SSD 投机缓存策略示意图，该图展示了对正在验证的第T轮投机结果，预计算第T+1轮投机结果时，针对不同令牌接受位置k，分配扇出值 $F_k$（即对每个k猜测的奖励令牌数量）的策略，图中展示了$F_0=1、F_2=3$的扇出分配示例，扇出值分配遵循定理12的几何分布规律。这一设计避免了对低概率验证结果的无效预计算，最大化了缓存命中率。结合定理12的几何扇出规律，该策略能在固定计算预算下，让缓存覆盖最可能的验证结果，是SSD提升缓存命中率的关键设计，也为后续不同温度下的性能稳定提供了保障。
:::

如图 2 所示，Saguaro 为每个位置 k 分配一个扇出值 $F_k$，对应预测的奖励 token 数量。

#### 2. 理论推导：几何级数的扇出分布

> 作者针对投机解码中如何分配有限的缓存预算来预判验证结果，通过理论推导得出了最优的扇出分配策略。

作者首先定义了**幂律缓存命中率**，即缓存命中率与扇出值 $F$ 的 $r$ 次幂成正比。基于此，:mdnice-bold-italic[他们将问题建模为在固定缓存预算 $B$ 下最大化缓存命中率的约束优化]。通过拉格朗日乘数法求解，证明最优的扇出分布 $F_k$ 应遵循**几何级数**：

- 对于未全部接受的情况（$k < K$）：$F_k = F_0 \cdot a_p^{k/(1+r)}$
- 对于全部接受的情况（$k = K$）：$F_K = F_0 \cdot a_p^{K/(1+r)} \cdot (1-a_p)^{-1/(1+r)}$

其中，$a_p$ 是投机模型的接受率，$r$ 为幂律指数。**该公式体现了核心直觉：随着已接受 token 长度 $k$ 的增加（概率呈指数下降），分配的扇出也应相应减少，从而避免在低概率路径上浪费计算资源**。作者在下面如图 3 左、中的实验，也验证了该幂律关系的存在。

### 3.2 挑战二：如何平衡缓存命中率与接受率？

> 通常，奖励 token 是从残余分布中采样的。但这个分布很难预测，尤其是在温度参数较高时。**Saguaro 的巧妙之处在于，它通过干预投机模型的采样过程，来“操纵”残余分布，使其更容易预测。**

#### Saguaro 的解法：缓存感知采样（Cache-Aware Sampling）

在投机解码中，奖励 token 通常从残余分布 $r(t) \propto \max(p_{\text{target}}(t) - p_{\text{draft}}(t), 0)$ 中采样，该分布随温度升高变得难以预测。**Saguaro 的核心洞察是：若要提高某个 token 被选为奖励 token 的概率，只需降低它在投机模型中的概率 $p_{\text{draft}}(t)$，** 因为残余分布与 $p_{\text{draft}}$ 成反比。

::: block-1
为此，Saguaro 引入了**缓存感知采样**：给定 $F$ 个最可能成为奖励 token 的候选，通过超参数 $C \in [0,1]$ 对这些候选的概率进行“下加权”，如将对数概率除以 $C$，从而降低它们在投机分布中的权重。
:::

效果上，这带来了一个可调优的权衡：$C$ 越小，缓存命中率越高（因为奖励 token 更可能落在缓存中），但投机模型的接受率（因与目标分布差异变大）越低。反之亦然。**如下图 5（左）所示，通过调整 $C$，可以在两者之间找到最佳平衡点。**

### 3.3 挑战三：缓存未命中怎么办？

即使有再好的预测，缓存未命中（Cache Miss）也必然会发生——毕竟无法保证每次都能猜中验证结果。当这种情况发生时，系统必须有一个备用策略（Fallback）来继续工作，而不是完全阻塞。

#### Saguaro 的解法：两阶段备用策略

> 作者分析指出，缓存未命中时，**整个批次（Batch）都需要等待备用投机器（Backup Speculator）完成投机才能继续**。这在高并发场景下会严重影响性能。

##### 理论分析：批次大小的影响

当批次大小为 $b$ 时，只要批次中有一个样本未命中，整个批次就必须等待备用投机器。

在假设各序列缓存命中事件相互独立的前提下，所有样本都命中的概率是 $p_{\text{hit}}^b$。:mdnice-bold-italic[随着 b 增大，该概率迅速趋近于 0， 这意味着在高并发场景下几乎每次迭代都会触发备用投机器]。

实际系统中序列间可能存在相关性（如共享前缀），但该近似仍能指导备用策略的选择。

##### 最优策略选择

因此，我们需要根据批次大小 $b$ 选择最佳的备用投机器：

- **低并发（$b < b^*$）**：可以使用一个高质量但速度较慢的备用投机器（例如，与主投机器相同）。因为未命中概率较低，偶尔等待一下是可接受的。
- **高并发（$b \ge b^*$）**：必须使用一个**极低延迟** 的备用投机器（例如，直接返回随机 token），即使其质量稍差。因为几乎每次迭代都会触发它，低延迟至关重要。

## 五、相关工作和未来展望

### 5.1 相关工作

- 并行投机解码（AMUSD, PEARL, DSI）：这些工作也尝试在验证的同时进行投机，但通常只预测“全部接受”这一种特殊结果，或者在单设备上模拟并行，无法完全利用多设备资源。
- 树形投机解码（Sequoia, SpecInfer, EAGLE）：这些方法通过生成一个 token 树而非一个序列，提高了单次验证的接受率。但它们仍然是串行的（投机-验证），并且会显著增加目标模型的计算负担。:mdnice-bold-italic[Saguaro 与这些方法是正交的，可以结合使用。]
- 改进的投机模型（EAGLE-3, GliDe）：这些技术旨在提升投机模型的质量和速度。:mdnice-bold-italic[Saguaro 作为系统框架，可以与这些更先进的投机模型无缝集成，从而获得更大的加速收益。]

![文章插图](/articles/2026-04-02-30-tri-dao-saguaro-d534d1ba/images/15.webp)

图 9：该图为标准EAGLE-3与SSD-EAGLE3的草稿模型激活条件对比，下图为标准EAGLE-3，第T轮投机主要基于第T-1轮已验证的目标模型激活；上图为SSD-EAGLE3，第T轮投机在第T-1轮验证完成前启动，因此需用草稿模型自身的激活替代尚未获取的目标激活，浅色节点为草稿激活。该图揭示了SSD与EAGLE-3结合的核心问题：SSD的异步投机导致草稿模型无法及时获取目标模型激活，只能用自身激活替代，而过多的草稿激活会降低投机接受率。但作者也提出了解决方案——训练EAGLE-3草稿模型适应更长时间的自激活条件。该结果证明SSD能与现有先进的SD优化方法兼容，仅需少量适配即可实现性能的叠加提升，为SSD的后续优化提供了重要方向，即结合EAGLE3等方法进一步提升接受率。
:::

### 5.2 未来展望

1. 与树形投机结合：将 SSD 与 EAGLE 等树形投机方法结合，构建一个“树形 SSD”系统，可能会带来更大的性能提升。
2. 扩展投机计算资源：**理论上，可以使用更多的 GPU 来执行投机任务，构建更大、更准的投机缓存，从而进一步提升缓存命中率**。但这需要权衡成本与收益。
3. 集群级部署：**将投机模型作为一项“服务”，部署在集群中，为多个目标模型实例提供投机预测**，类似于 Prefill-Decode Disaggregation（预填-解码分离）的思想。

## 结论与总结

> 投机投机解码（SSD）及其实现 Saguaro，是 AI 推理加速领域的一项里程碑式工作。它以一种优雅而深刻的方式，打破了传统投机解码中根深蒂固的串行依赖，实现了投机与验证的真正并行。

通过巧妙的缓存构建策略、创新的缓存感知采样算法，以及基于系统理论的备用策略选择，:mdnice-bold-italic[Saguaro 不仅在端到端性能上实现了对现有方法的显著超越，更在吞吐-延迟帕累托前沿上开拓了新的可能]。值得注意的是，SSD 框架保留了投机解码的“无损”特性——其输出分布与目标模型完全一致，这得益于验证阶段严格遵循与标准投机解码相同的 token 接受机制。

它证明了，在 AI 推理系统中，我们**不仅可以利用计算，更可以巧妙地“预计算”和“预见”，从而将硬件的并行能力发挥到极致。**

::: block-1
对于任何致力于构建高性能、低延迟 AI 服务的开发者而言，Saguaro 不仅仅是一个新的算法，更是一种全新的、更具前瞻性的系统设计思路。它启示我们，:mdnice-bold-italic[当我们面临串行依赖时，或许“并行地预见未来”才是真正的解决之道。]
:::
