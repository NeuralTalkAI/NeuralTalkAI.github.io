## 一、长上下文推理的两难：全注意力贵，循环模型忘

> 长程推理的每一步都依赖前面写下的定义、约束和中间结果，模型必须能随时回头读历史。作者把两条现有路线的代价写得很直白。

- 全历史注意力能直接读到任意早的位置，代价是缓存和注意力计算随生成长度膨胀：生成 $N$ 个 token 的总解码工作量是 $O(N^2)$，持久状态是 $O(N)$。
- 循环和状态空间模型把历史压成固定维度的状态矩阵，推理扩展到 $O(N)$ 时间、$O(1)$ 内存，但反复的状态更新会磨损精确的关联信息——50 步之前写下的中间结果，可能已经被后续更新覆盖掉了。局部注意力保住最近细节，远处信息滑出窗口后同样丢失。

**YANchor 的做法是在有界状态里显式保留一部分关键信息：独立记忆留住远处的精确记录，循环状态压缩宽泛上下文，局部注意力管最近细节**。三条通路容量全部固定。:mdnice-bold-italic[这就好比做题的人工作记忆有限，但手边有一本固定页数的笔记本，重要中间结果可以随时翻回去逐条查。]

::: block-1
总的来说，长程推理的矛盾是"访问历史"和"控制成本"的对立：全注意力有记忆没效率，循环模型有效率没记忆。:mdnice-highlight[YANchor 在恒定容量内保留可检索的显式记录，补上后者缺的那一块。]
:::

## 二、改造 Qwen3.5-4B：372M 参数加一个记忆分支

> YANchor-4B 的思路是改造 Qwen3.5-4B，并没有从头训练：保留循环层，把全局注意力层换成局部注意力加独立记忆，整体架构见本文开头的图 3。

![文章插图](/articles/2026-10-20-yanchor-4b-o-n-o-8fb9aedc/images/05.jpg)

::: image-caption
图 3：YANchor-4B 架构，循环层与局部注意力、记忆模块交错排布。(a) 主干是 3 个 Gated DeltaNet 循环层加 1 个"局部注意力+记忆"层的组合，重复 8 次，图像 token 和文本 token 进同一套主干；(b) 滑窗注意力管最近 1,024 个 token，独立记忆分支把滑出窗口的重要信息写成 key-value 记录，经打分和 Top-K 留存进记忆库，查询时按组检索回来。两路输出汇入同一条残差流，后续层同时看到近期细节和远处记忆。
:::

> 层排布上，32 层主干分 8 组，每组是 3 个 Gated DeltaNet（GDN）循环层加 1 个注意力位置：

$$
[\mathrm{GDN}, \mathrm{GDN}, \mathrm{GDN}, \mathrm{SWA}_{1024} \parallel \mathrm{Memory}] \times 8
$$

其中 $\mathrm{SWA}_{1024}$ 是窗口 1,024 token 的滑动窗口注意力，$\mathrm{Memory}$ 是与滑窗并联的独立记忆分支。对第 $t$ 步的层输入 $h_t$，组合计算是：

$$
z_t = h_t + \mathrm{SWA}(\mathrm{Norm}_{local}(h_t)) + \mathrm{Mem}(h_t, M_t)
$$

$$
h_t^{out} = z_t + \mathrm{MLP}(\mathrm{Norm}_{ffn}(z_t))
$$

$M_t$ 是该记忆模块当前已提交的记录集合。滑窗和记忆各自独立做注意力归一化，输出都加进同一条残差流，后续层的输入里同时包含最近窗口的细节和远处检索回来的记忆。8 个记忆模块各有独立参数和状态。

![文章插图](/articles/2026-10-20-yanchor-4b-o-n-o-8fb9aedc/images/06.jpg)

::: image-caption
表 1：YANchor-4B 架构参数总表。文本模型 4.58B 参数，其中独立记忆 372M；主干 24 个 GDN 层加 8 个滑窗注意力层；残差宽度 2,560；每个记忆模块 16 个查询头、4 个 KV 组、头维度 256；局部窗口 1,024 token；每个 KV 组已提交记忆 1,024 条记录；记忆 K/V 状态在 BF16 下每序列 40 MiB。值得留意的是记忆参数只占总量约 8%，大部分能力来自 Qwen3.5 骨架，记忆机制是轻量外挂，改造成本可控。
:::

::: block-1
整体来说，YANchor-4B 架构选择上比较务实，不动 Qwen3.5 的循环层和预训练权重，:mdnice-highlight[只在注意力位置动刀，新增 372M 记忆参数约占总量 8%，改造成本和能力保留都可控。]
:::

## 三、记忆锚点机制：每条序列固定 40 MiB

记忆模块要回答三个问题：哪些信息值得存，容量满了淘汰谁，查询时怎么找回来。

### 3.1 写入与准入：256 token 一块，每组留 Top-1,024

> 写入端，对归一化后的层输入 $u_t = \mathrm{Norm}_{mem}(h_t)$，一个残差写入器构造待存表示：

$$
w_t = u_t + W_{down}\left(\mathrm{SiLU}(W_{gate} u_t) \odot W_{up} u_t\right)
$$

$W_{up}$、$W_{down}$ 是升维降维投影，$\odot$ 是逐元素乘，SiLU 门控控制写入内容的取舍。key 和 value 由独立投影从 $w_t$ 产生，**查询从 $u_t$ 投影——读写分离，"存什么"和"想找什么"是两组独立表达。**

**容量管理靠一个小型准入网络给每个 KV 组打分**：$a_t = W_{a,2}\,\mathrm{SiLU}(W_{a,1} u_t)$，$a_t \in \mathbb{R}^4$，打分只用写入时刻可见的信息，保证因果性。新记录按 256 token 一块累积，块边界处各组把候选与已提交记忆合并，选出新的 Top-1,024 集合，高分记录在一次次块更新中长期存活。

![文章插图](/articles/2026-10-20-yanchor-4b-o-n-o-8fb9aedc/images/07.jpg)

::: image-caption
图 4：因果记忆维护流程。当前表示经残差写入器产出独立 K/V，因果网络给出 4 个 KV 组各自的准入分数；每攒够一个 256 token 的块，就把候选记录与已提交记忆合并，每组选出持久的 Top-1,024 集合，旧条目被替换，留下的记录作为记忆锚点供后面的块读取。关键点是逐条整条保留：写入时的 key-value 表示原封不动，不做压缩混合，远处信息读回来时是精确的。
:::

### 3.2 检索与存储账：40 MiB 怎么算出来的

> 读取端按分组查询注意力组织：16 个查询头、4 个 KV 组、头维度 $d = 256$。对分配在组 $g(h)$ 的查询头 $h$，在已提交记录 $M_{g(h)}$ 上的检索为：

$$
e_{t,h} = \sum_{j \in M_{g(h)}} \frac{\exp(q_{t,h}^{\top} k_{j,g(h)} / \sqrt{d})}{1 + \sum_{i \in M_{g(h)}} \exp(q_{t,h}^{\top} k_{i,g(h)} / \sqrt{d})} \, v_{j,g(h)}
$$

**分母里的 1 是一个零 logit、零 value 的虚拟记忆项**：记忆为空时读出中性输出，也让注意力权重可以从匹配差的记录上移开。检索结果经查询条件门控调制后进独立输出投影，门控决定记忆对残差流的贡献大小。

> 存储账很直接，记忆 K/V 的每序列占用：

$$
2 \times 8 \times 4 \times (1024 + 256) \times 256 \times 2\ \text{bytes} = 40\ \text{MiB}
$$

即：K 和 V 两份、8 个记忆模块、4 个 KV 组、每组 1,024 条已提交加 256 条候选、每条头维度 256、BF16 两字节。40 MiB 固定，与上下文长度无关。

复杂度层面，设生成长度 $N$、窗口 $W$、记忆容量 $K$、块大小 $C$，每个 token 最多读 $W$ 个局部位置和每组 $K$ 条记录，块提交最多从 $K + C$ 条候选里挑，全部与 $N$ 无关：

$$
\sum_{t=1}^{N} O\left(1 + W + K + \frac{(K+C)\log(K+C)}{C}\right) = O(N)
$$

::: image-caption
表 2：四类历史机制的复杂度对比，即随生成长度 N 的扩展性对比。全历史注意力总解码工作量 $O(N^2)$、持久状态 $O(N)$；固定维循环和固定窗口注意力都是 $O(N)$、$O(1)$；YANchor 的循环加滑窗加记忆同样是 $O(N)$、$O(1)$。表里没有直接画出的一点是：前两类恒定状态机制丢了远距离精确访问能力，YANchor 在同样的渐近复杂度下用显式记录把这项能力补了回来，后文的评测数据在论证这一点。

:::

## 七、记忆消融：关掉记忆分支，准确率从 94.14% 掉到 0.39%

> 从竞赛数学的断层领先到批量推理的数倍吞吐量提升，YANchor-4B交出的答卷远不止一组亮眼的跑分数字——它真正回应了长序列领域的核心疑问：线性时间、常数内存的循环架构，**但是记忆锚点是不是真在干活，能不能支撑高强度的长程推理？作者用一个消融实验直接回答：把记忆分支关掉再测。**

如图 8 所示，在覆盖16K至13万token的长记忆任务中，完整模型的查询准确率达到94.14%；一旦关闭独立记忆分支，准确率直接暴跌至0.39%，近乎完全丧失远距离信息访问能力。

![文章插图](/articles/2026-10-20-yanchor-4b-o-n-o-8fb9aedc/images/20.jpg)

::: image-caption
图 8：长记忆任务准确率。左图四个训练阶段：M0 查询准确率 79.4%、四题全对率 54.7%；R 之后 96.1% 和 87.9%，是记忆能力成形的关键；S 和 RLVR 阶段 93.8%/82.4%、94.1%/80.1%，通用训练没有明显冲掉记忆。右图记忆路径干预：关闭后 0.39%，开启 94.14%，因果证据干净利落——远距离检索能力确实由记忆分支独自承担。
:::

这组对比干净利落地证明：:mdnice-bold-italic[模型的长程检索能力几乎完全锚定在独立记忆通路上，主干的循环状态与1024窗口局部注意力，根本无法弥补远距离信息的缺失。 从训练阶段的演进来看，联合适配阶段R是记忆能力成型的关键拐点，] 后续的监督训练与强化学习也并未稀释长记忆能力，实现了通用能力与长程记忆的兼顾。

> 表 7 的细分数据进一步勾勒出记忆机制的能力边界：精确检索、状态更新解读、跨文档组合三类任务的全对率均接近90%，表现稳健；唯独变量绑定任务成功率仅53.13%，成为明显短板。

![文章插图](/articles/2026-10-20-yanchor-4b-o-n-o-8fb9aedc/images/21.jpg)

::: image-caption
表 7：发布模型在长记忆任务上的完整上下文成功率（同一上下文四题全对）。精确检索 90.63%、状态更新解释 87.50%、跨文档组合 89.06%、变量绑定 53.13%，全部任务 80.08%。变量绑定最难，它要求多个关联同时可访问，比如"x 是 A 的编号、A 的负责人是 B、B 的密码是 y"这种链式绑定，1,024 条锚点的容量上限在这类任务上最先暴露。
:::

这类需要多组关联同时保活的链式推理，最先触碰到了1024条锚点的容量天花板。同时成对证据修改测试显示，**模型对记忆内容的更新响应准确率接近90%，说明锚点记忆是能跟随上下文动态调整的活性存储。**

::: block-1
当然，这项工作的边界也十分清晰：**所有性能与显存数据均来自官方单卡自测**，长上下文基线显存为外推值；模型基于 Qwen3.5-4B 改造，结论泛用性可能受限于主干骨架；中文知识基准出现两位数回落，是中文用户需要权衡的现实短板。

但瑕不掩瑜，YANchor-4B用完整的实验链条证明，:mdnice-highlight[“循环压缩+局部注意力+可检索锚点”的三路融合，完全可以在$O(1)$显存的约束下逼近全注意力架构的长程推理能力]，为长序列大模型的效率革命踩下了扎实的一步台阶。
:::
