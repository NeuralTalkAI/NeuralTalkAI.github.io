## 一、引言

由于机器学习（ML）模型的高计算需求，其优化至关重要。鉴于**现代 CPU 架构上最优实现的搜索空间巨大**，传统分析方法往往力不从心。为应对这一挑战，**自动调优已成为一种强大的方法。自动调优使用数学模型或机器学习技术系统地评估同一工作负载的多种实现**，以指导后续的实现选择[1],[2]。

Apache Tensor Virtual Machine（TVM）[3]是一个著名的 ML 编译器框架，实现了多种自动调优策略[4],[5]。自动调优通常需要在真实硬件上执行，由于系统负载[6]、缓存冲突[7]、热节流[8]以及频率和电压缩放[9]等因素，这会引入不确定性。

为缓解这些问题，每个基准测试需执行多次，剔除异常值，插入冷却周期，并在每次重复前刷新缓存。

> 因此，对单个实现进行基准测试所需的时间显著长于其实际运行时间。这非常耗时，尤其是在目标硬件设备有限的情况下。

本文提出以下两个主要贡献：

### 贡献一：模拟器接口

我们提出一种允许在模拟器而非真实硬件上执行自动调优工作负载的接口，图 1 展示了这种方法。

![文章插图](/articles/2025-06-26-arm-x86-risc-v-5747f25d/images/04.webp)

我们**提取 TVM 任务，并通过模拟器接口将其作为目标架构的可执行文件提供**。并行任务的数量是可配置的，每个任务在模拟器的单独实例中运行。

::: block-1
**可从我们的模拟器接口中受益的潜在场景包括**：

- 硬件尚未可用，例如用于**预硅软件（SW）开发**。
- 嵌入式**硬件仅有限量供应**，使得在高性能计算机上并行执行模拟比原生执行更快。
- 除运行时间外，**其他指标也应进行优化**。
:::

### 贡献二：得分预测器

我们旨在证明，**指令精确模拟器可用于性能分析，以自动调优工作负载为例**。

> 据我们所知，我们是**首个展示如何使用快速指令精确模拟器进行性能分析的团队**。

针对不同架构，存在许多开源的指令精确模拟器实现，例如 QEMU[10]或 gem5[11]。图 1 II 说明了这一想法。

![文章插图](/articles/2025-06-26-arm-x86-risc-v-5747f25d/images/04.webp)预测器从指令精确模拟器获取统计数据作为输入，并根据在真实硬件上测量的参考值计算得分。然后，该得分被返回给自动调优框架。

**由于指令精确模拟器不提供准确的 timing（时序信息），我们不旨在预测执行延迟**。相反，我们的方法利用得分来评估和比较同一工作负载的不同实现。

**这些得分对于指导自动调优过程至关重要，但不适用于比较不同类型的工作负载**。我们为此任务采用了多种预测器：多元线性回归（MLR）[12]、深度神经网络（DNNs）[13]、贝叶斯优化[14]和 XGBoost[15]。我们**对它们进行调优和比较，以确定常见 ML 内核的最准确预测**。我们在不同的 CPU 架构上评估了我们的方法，即 x86、ARM 和 RISC-V。

## 二、背景与相关工作

### A. TVM 中的自动调优

**Apache TVM [3] 是一个开源的机器学习编译器框架，旨在优化跨各种硬件平台的计算。** 在 TVM 中，每个操作（在本文中称为内核）可以用不同的抽象形式表示，例如张量表达式（TE）或张量中间表示（TIR）。例如，一个内核可以是一个神经网络（NN）层。TVM 允许应用转换原语来针对不同的目标架构优化内核。

与 Halide [16] 类似，**TVM 将定义内核功能行为的计算操作与定义其实现的调度区分开来**。这种区分允许单个计算具有多种调度。操作的所有可能调度的集合称为设计空间。**大型设计空间和复杂的硬件行为使得分析方法难以找到 ML 内核的最佳调度。自动调优通过在目标硬件上直接对多个调度进行经验评估来解决这一问题。** TVM 提供了三种自动调优概念：AutoTVM 框架、AutoScheduler（也称为 Ansor [4]）和 Meta-Scheduler。**本文主要关注 AutoTVM 和 AutoScheduler，因为它们基于相同的输入表示，即 TE。**

清单 1 提供了一个 TE 计算操作定义的示例。张量 c（大小为 $N×M$）包含矩阵 A（大小为 $N×L$）和矩阵 B（大小为 $L×M$）之间的矩阵乘法（MMM）结果。

```
代码清单 1：TE 中矩阵乘法计算操作的定义k = te.reduce_axis((0, L), name="k")C = te.compute((N, M), lambda i, j: te.sum(A[i,k]*B[k,j], axis=k), name="matmul")
```

AutoTVM 要求用户定义带有可调参数的模板，例如循环平铺因子。然后，AutoTVM 通过在真实硬件上执行配置并测量运行时间来探索该搜索空间。定义一个有用的调度模板需要一定的专业知识。然而，常见操作符的预设计模板可在 TVM 代码库中找到。例如，清单 2 说明了如何使用 AutoTVM 描述单轴的拆分原语。

```
代码清单 2：AutoTVM 调度模板的定义s = te.create_schedule(C.op)y,_ = s[C].op.axis# 定义调度模板cfg = autotvm.get_config()cfg.define_split("split_y", y, num_outputs=2,...)# 应用调度yo, yi = cfg["split_y"].apply(s, C, y)
```

与 AutoTVM 不同，AutoScheduler 无需手动定义模板即可自动生成调度，使其更适合非专家用户。

![文章插图](/articles/2025-06-26-arm-x86-risc-v-5747f25d/images/05.webp)

**图 2 展示了 AutoScheduler 和 AutoTVM 的工作流程**。与 AutoTVM 中手动定义的搜索空间不同，AutoScheduler 使用通过预定义推导规则从内核的有向无环图（DAG）生成的草图。草图基本上包含带有占位符的嵌套循环，这些占位符在注释阶段填充。在注释期间，循环轴还可以标记为并行化、展开或向量化。实现细节见[4]。与 AutoScheduler 相比，AutoTVM 依赖调优器根据可选择的调优算法选择后续程序。

### B. 缓存层次结构

ML 操作需要缓存优化以实现高性能 [17],[18]。

![文章插图](/articles/2025-06-26-arm-x86-risc-v-5747f25d/images/06.webp)

现代 CPU 具有包含多个缓存级（L1、L2、L3）的层次化内存系统，如图 3 所示。不同 CPU 的层次结构可能不同 [19]。L1 缓存通常分为数据缓存（L1D）和指令缓存（L1I）。**更高层的缓存通常由核心共享。大多数 CPU 使用 N 路组相联缓存，其中每个内存地址映射到特定组内的 N 路之一**。在 Linux 环境中，缓存层次结构的信息可通过 sysfs 访问。

### C. gem5 模拟器

**gem5 [11] 是一个开源的全系统模拟器（FSS），用于计算机体系结构研究，支持 x86、ARM 和 RISC-V 等不同架构**。

它提**供不同的抽象级别：**

- 在 gem5 的原子模式中，内存访问在单个事务内执行。内存访问的请求者会被阻塞，直到访问完成。
- 在时序模式中，gem5 提供内存访问时序的详细模拟，包括延迟、排队延迟和带宽限制。

gem5 还**提供不同的 CPU 模型。**

- SimpleCPU 不模拟流水线，这使其速度快但时序准确性不高。它可在原子模式和时序模式下使用。
- gem5 还提供 InOrderCPU 和 O3CPU（乱序 CPU），两者都配备了 CPU 流水线模型。

此外，**gem5 区分全系统模式和系统调用仿真模式**。系统调用仿真模式旨在模拟用户空间程序。它拦截目标软件的系统调用，并在主机上处理它们。系统调用仿真模式比全系统模式更快，并且专注于软件测试，因为它不模拟操作系统，因此无法捕获任何特定于操作系统的行为。

## 三、实现

### A. 模拟器接口

在本章的第一部分，我们解释模拟器接口的实现。在第二部分，我们使用该接口将 TVM 的自动调优与基于 x86、ARM 和 RISC-V 的指令精确模拟器连接。

#### 模拟器接口

允许在用户级或系统调用仿真模拟器上而非真实硬件上执行自动调优实现。这支持不同实现的并行执行。TVM 的自动调优需要构建器（builder）和运行器（runner）。构建器生成包含工作负载编译功能的目标文件。运行器使用 `tvm::runtime` 执行工作负载。

对于模拟器，需要独立的可执行文件。该可执行文件准备输入张量，为输出张量分配空间，并调用编译后的工作负载。为了将此行为集成到 AutoTVM 中，我们通过继承 `Runner` 类实现了一个名为 `SimulatorRunner` 的自定义运行器（见清单 3）。当调用自定义运行器的 `run` 函数时，它会生成一个主函数，对其进行编译，并将其与编译后的目标文件链接。一个名为 `simulator_run` 的函数使用可执行文件的路径调用。**该函数用作模拟器接口，可以覆盖以使用模拟器进行执行**。返回值需要是量化工作负载性能的得分，例如运行时间。名为 `n_parallel` 的参数定义可以并行实例化的模拟器数量。

```
代码清单 3：AutoTVM 流程的自定义运行函数class SimulatorRunner(Runner):    def __init__(self, n_parallel=16, ...) :        super(SimulatorRunner, self).__init__(...)    def run(self, measure_inputs, build_results):        # 构建可执行文件        # 在模拟器上并行运行可执行文件        return [AutoTVMRes0, AutoTVMRes1, ...]
```

为了将模拟器集成到 AutoScheduler 中，我们覆盖 TVM 的函数注册表中的 `auto_scheduler.local_runner.run` 函数，如清单 4 所示。返回值是包含得分的 AutoSchedResults 列表。其余实现与 AutoTVM 的工作方式相同。

生成 ML 内核的目标文件时，内核通过 TVM 进行优化和降低级别（lowering）。LLVM 用于代码生成，为了生成交叉编译的目标文件，可以在 TVM 中指定 LLVM triple。

### B. gem5 模拟器设置

为了**准确预测时序，需要周期精确模拟器**。然而，周期精确模拟器通常模拟速度慢。此外，获得具有所需细节级别的商用架构周期精确模拟器是一项挑战，因为诸如内存组件、总线或微体系结构细节的精确延迟信息很少开源可用。

我们将演示**使用非时序精确模拟器基于定量参数进行有效预测** 的可行性，而不依赖时序信息。

我们**专注于单核工作负载。为了实现快速模拟性能，我们在原子模式下使用 SimpleCPU 模型对 x86、RISC-V 和 ARM 架构运行 gem5** （见 II.C 节）。gem5 允许复制缓存架构，同时使其可参数化，以考虑内存层次结构中的缓存命中、未命中和替换（见 II.B 节）。

要将非时序精确（即指令精确）模拟器用于得分预测，必须训练预测器。图 4 说明了该预测器的训练和执行阶段。

![文章插图](/articles/2025-06-26-arm-x86-risc-v-5747f25d/images/07.webp)

**在训练阶段，工作负载不仅在 gem5 中执行，还在目标 CPU 上原生执行。我们需要为每个架构和内核类型训练不同的预测器。** 例如，Conv2D+Bias+ReLU 代表一种特定的内核类型。请注意，相应的预测器可以应用于该内核类型的任何形状和参数组合。**给定内核类型的形状和参数的固定组合称为组（group）。自动调优过程为每个组生成各种实现（调度，schedule）**。

在后续的执行阶段，我们利用预训练的预测器。此时不再需要目标 CPU，这使得在 x86 平台上模拟 RISC-V 等架构成为可能。

### D. 得分预测器训练

得分预测器为实现 I 估计得分 S。**基本原理是这些得分与运行时间相关，但仅适用于同一内核类型和组的不同实现。** 完美预测意味着 $S_{I1} < S_{I2} \Rightarrow t_{I1} < t_{I2}$，其中 $t_{Ix}$ 是实现 x 的运行时间。值得注意的是，使用该得分无法比较不同内核类型或组的实现。**鉴于时序细节不可用，得分预测器仅依赖定量信息而非延迟**。

::: block-1
从 gem5 导出的相关统计数据包括：

- 执行的加载/存储/分支指令数除以总指令数。
- 执行的总指令数归一化为该组的总执行指令数。
- 每个缓存的读取/写入替换/命中/未命中数除以读取/写入访问数。
:::

例如，考虑实现 $I_x$ 的（L1D 写）缓存命中率，我们确定：

$$
P_{L1Dw}(I_x) = \frac{L1D_{w,\text{hits}}(I_x)}{L1D_{w,\text{accesses}}(I_x)}
$$

此外，所有参数也针对组进行归一化：

$$
P_{L1Dw,\text{norm}}(I_x) = \frac{P_{L1Dw}(I_x) - \overline{P_{L1Dw}(I)}}{\overline{P_{L1Dw}(I)}}
$$

值 $\overline{P_{L1Dw}(I)}$ 表示组内的平均值。**我们发现最有希望的方法是将这些参数以原始形式 $P_{L1Dw}(I_x)$ 和归一化形式 $P_{L1Dw,\text{norm}}(I_x)$ 作为预测器的输入。** 用于训练的输出得分是针对组归一化的测量运行时间，类似于计算 $P_{L1Dw,\text{norm}}(I_x)$ 的公式。

**基于这些输入和得分，我们训练不同的预测器，这些预测器可以使用不同的损失函数**。在本文中，我们使用均方误差（MSE）、平均绝对误差（MAE）和残差平方和（RSS）。

---

以下是预测器的简要概述。

1. 多元线性回归：MLR 是线性回归的扩展，是一种简单的预测器，仅对线性关系建模。它找到多个输出 $y_k$ 和多个独立输入 $x_i$ 之间的关系 [20]，在我们的案例中为：$y = b_0 + b_1x_1 + b_2x_2 + ... + b_nx_n$
2. 深度神经网络回归：使用 DNN 进行回归意味着基于多个输入特征预测连续输出。通常，网络由多个全连接层组成，输入神经元的数量对应输入特征的数量。每个隐藏层通常应用激活函数以引入非线性，使网络能够捕捉复杂关系。最后一层的神经元数量等于输出变量的数量。常见架构可能包括几个神经元数量递减的隐藏层。
3. 贝叶斯优化：贝叶斯优化构建代理模型（在本例中为高斯过程）来近似真实目标函数。它使用该模型预测参数空间中哪些区域可能产生最佳结果，并在这些区域评估函数。采集函数平衡探索空间新区域（探索）和细化有希望的已知区域（利用）之间的权衡 [21]。清单 6 显示了所用目标函数和损失函数的选择。

```
代码清单 6：贝叶斯优化的目标函数def objective_function(C, RBF_scale, noise):    func = ConstantKernel(constant_value=C, ...) _ RBF(length_scale=RBF_scale, ...) + WhiteKernel(noise_level=noise, ...)    gp = GaussianProcessRegressor(func).fit(X_train, y_train)    predictions = gp.predict(X_test)    return - loss_function(y_test, predictions)
```

高斯过程的超参数是 `objective_function` 的输入参数。贝叶斯优化框架通过一系列迭代最大化目标函数。每次迭代涉及使用新超参数拟合高斯过程模型，并根据结果更新概率模型。

1. XGBoost：极端梯度提升（XGBoost [22]）是一种强大的回归任务算法。它使用决策树集成来预测连续结果。在 XGBoost 中，树按顺序构建，每棵树通过调整残差来尝试最小化前一棵树的误差。该算法使用梯度下降优化损失函数。XGBoost 算法的超参数包括学习率、最大树深度和正则化参数等。

### E. 得分预测器推理

对于推理，训练好的预测器集成到执行管道中，如图 4 所示。

![文章插图](/articles/2025-06-26-arm-x86-risc-v-5747f25d/images/07.webp)

一个挑战是，输入参数（例如 $P_{L1Dw,\text{norm}}(I_x)$）无法为未知的新组确定。这是由于 AutoScheduler 基于先前的得分批量生成实现（见 II.A 节），无法在开始时计算平均值（如 $\overline{P_{L1Dw}(I)}$）。

为解决这一问题，我们允许使用两种方法近似平均值：静态窗口和动态窗口。

- 在静态方法中，平均值从前 w 个样本计算。
- 在动态窗口方法中，平均值随时间自适应调整。批量大小（即窗口大小）通常足够大，实验中未观察到与使用 $\overline{P_{L1Dw}(I)}$ 相比的精度损失。

## 四、结果

为验证我们的预测器能力，**所有基准测试均在三种不同的 CPU 架构上执行：x86、ARM 和 RISC-V。**

- 对于 x86，我们使用 64 位 2.2 GHz AMD Ryzen 7 5800X 8 核处理器；
- 对于 ARM，使用 64 位 1.5 GHz 树莓派 4 Model B（配备 ARM Cortex-A72 处理器）；
- 对于 RISC-V，使用 64 位 1.2 GHz SiFive U74-MC 处理器。

![文章插图](/articles/2025-06-26-arm-x86-risc-v-5747f25d/images/08.webp)

表 I 列出了这些 CPU 的缓存层次结构。我们在 gem5 中对其进行建模（见 III.B 节）。

- 所有缓存行大小均为 64 B。
- ARM 和 RISC-V CPU 具有共享的 L2 缓存，但没有 L3 缓存。

所有 gem5 模拟均在 x86 机器上执行。我们**使用 ResNet [23] 架构中的五组 Conv2D+Bias+ReLU 内核作为基准测试**。表 II 列出了这些组的形状和参数。**为训练预测器，AutoScheduler 为每组生成 500 个实现，其中 100 个实现用于测试集。**

![文章插图](/articles/2025-06-26-arm-x86-risc-v-5747f25d/images/09.webp)

为确定参考执行时间 $t_{\text{ref}}$，每个实现执行 $N_{\text{exe}} = 15$ 次，取中值作为参考值。此外，每次运行之间插入 $t_{\text{cooldown}} = 1\ \text{s}$ 的冷却时间，以确保测量结果更具可重复性。工作负载不在真实硬件上并行执行，因为这可能影响测量结果。这意味着在 K 个并行模拟器上的执行速度比在单个设备上的原生（顺序）执行更快。

$$
K = \left\lceil \frac{t_{\text{simulator}}}{(t_{\text{cooldown}} + t_{\text{ref}}) \cdot N\_{\text{exe}}} \right\rceil
$$

我们的测量设置（$N_{\text{exe}} = 15$，$t_{\text{cooldown}} = 1\ \text{s}$）导致测试工作负载的 $K_{\text{x86}} \in [7, 97]$，$K_{\text{ARM}} \in [4, 31]$，$K\_{\text{RISC-V}} \in [3, 21]$。这意味着在最佳情况下，仅需在 x86 机器上进行 3 次并行执行，即可实现比 RISC-V CPU 上的原生执行更快的速度。

### A.未训练组的预测

首先，我们证明即使特定内核组未包含在训练数据中，训练好的预测器仍可使用。这一能力至关重要，因为我们旨在为每个架构和内核类型（如 Conv2D+Bias+ReLU）开发一个适用于所有不同形状和参数组的预测器（见 III.C 节）。

![文章插图](/articles/2025-06-26-arm-x86-risc-v-5747f25d/images/10.webp)

为此，我们首先使用所有组为所有架构训练贝叶斯预测器。随后，使用仅包含组 0、1、2、4 和 5 的数据训练额外的预测器。图 5 比较了组 3 包含在训练中时的测试集（图 5a 至 5c）与组 3 未包含在训练中时相同样本的预测结果（图 5d 至 5f）。x 轴表示各个样本。参考时间 $t_{\text{ref}}$ 显示按升序排序的实测运行时间中值。为获得预测运行时间 $t_{\text{pred}}$，预测得分按升序排序，相应的实测运行时间根据这些得分绘制。完美预测意味着 $t_{\text{pred}} == t_{\text{ref}}$。

尽管并非所有得分均完美排序，但存在明显的上升趋势。**ARM 和 RISC-V 架构的预测似乎比 x86 更准确。这种差异可能源于这些嵌入式 CPU 上较少的硬件优化**。此外，每个预测器的性能仅与参考测量结果相当。由于 x86 上的执行时间明显更快，参考测量结果相比嵌入式架构上较长的运行时间表现出更大的可变性。总体而言，目视检查显示包含或不包含训练组之间无明显优势。

这表明预测器即使对于训练数据中不存在的组也能有效使用。为便于更好地比较预测结果，我们在以下部分引入三种不同的评估指标。

### B.预测器评估指标

最重要的方面是预测最快运行时间。因此，我们引入 $E_{\text{top 1}}$ 和排名指标 $R_{\text{top 1}}$。

- $E_{\text{top 1}}$ 表示最快参考测量值与预测得分最佳样本的运行时间之间的相对误差：$E_{\text{top 1}} := \left(1 - \frac{t_{\text{ref}}[0]}{t_{\text{pred}}[0]}\right) \cdot 100\%$
- 排名 $R_{\text{top 1}}$ 表示预测器将最快样本排名的相对位置：$R_{\text{top 1}} := \frac{100\%}{|t_{\text{ref}}|} \cdot \left(\underset{x}{\text{argmin}}(t_{\text{pred}}[x] == t_{\text{ref}}[0]) + 1\right)$例如，$R_{\text{top 1}} = 3\%$ 表示最快样本位于预测结果的前 3% 以内。

此外，我们需要一个指标来评估排序质量。连续的非单调递增样本应受到惩罚，其偏离程度也应被衡量。因此，我们引入质量得分 Q：

$$
Q := \frac{100\%}{|t_{\text{ref}}|} \cdot \sum_{i} \frac{t_{\text{ref}}[i] - \min(t_{\text{ref}}[i], t_{\text{ref}}[i+1])}{t_{\text{ref}}[i]}
$$

为防止运行时间较慢部分的偏差被过度加权，我们分别对运行时间较低的 50%（$Q_{\text{low}}$）和较高的 50%（$Q_{\text{high}}$）评估 Q。对于所有指标，值越小表示性能越好。

### C.预测器比较

接下来，我们比较不同的预测器（见 III.D 节）。我们测试了各种损失函数、激活函数和参数。鉴于 XGBoost 算法有许多超参数，我们使用网格搜索 [24] 进行调优。所用配置（调优后）如下：

- 线性回归：RSS 损失
- DNN：6 个密集层（神经元数量：128, 128, 64, 32, 16, 1），线性输出激活，tanh 隐藏层激活，MAE 损失，adam 优化器
- 贝叶斯：清单 6 所示目标函数，MSE 损失
- XGBoost：列子采样率 0.6，学习率 0.05，最大树深度 3，alpha 0，lambda 0.1，梯度提升树 300，最小子节点权重 1，训练子采样率 0.8，MSE 损失

为进行评估，所有组均包含在训练中。每个 CPU 架构训练一个预测器（即线性回归、DNN 等中的一个）。每次训练使用随机选择的训练集和测试集进行 10 次。随后基于测试集的中值预测计算得分。**表 III 显示 x86 的结果，表 IV 显示 ARM 的结果，表 V 显示 RISC-V 的结果。**

![文章插图](/articles/2025-06-26-arm-x86-risc-v-5747f25d/images/11.webp)

**对于 x86 架构，DNN、贝叶斯优化和 XGBoost 均取得了良好的得分。** XGBoost 实现了最佳平均 $R_{\text{top 1}}$ 得分，最高为 2.5%。XGBoost 的预测误差也最小，平均 $E_{\text{top 1}} = 2.54\%$。**对于 ARM 和 RISC-V，得分略好**。**对于 ARM，DNN、贝叶斯优化和 XGBoost 的 $R_{\text{top 1}}$ 得分均小于或等于 2.5%**。所有 $E_{\text{top 1}}$ 误差均低于 5%，通常甚至低于 2%。

## 五、结论与未来工作

> 在这项工作中，我们引入了一种在模拟器上执行自动调优工作负载的接口，并探索了使用指令精确模拟器进行 ML 工作负载自动调优的可行性。

我们训练并比较了 x86、ARM 和 RISC-V 架构的不同得分预测器。结果表明，调优后的预测器可以在预测结果的前 3% 内识别最佳实现。

::: block-1
在目标硬件可用性有限的情况下，我们的方法甚至可用于加速自动调优。在最佳情况下，在所用 x86 机器上进行 3 次并行模拟足以替代一块 RISC-V 开发板。我们的研究为使用指令精确模拟进行性能评估奠定了基础。
:::

**未来工作将侧重于对更广泛的 CPU 架构进行基准测试**，以训练更通用的预测器。这些通用预测器可应用于先前**未测试的 CPU**，增强我们的方法对**预硅软件** 开发的吸引力。
