## 一、关键问题

### 问题一：仿真准确性的边界何在？

> NpuSim 采用多级仿真平衡精度与效率，但在**极端硬件配置或复杂工作负载** 下（如超长序列、高并发请求），其**事务级模型是否仍能保持高保真度？** 是否已验证其在动态负载下的长期稳定性？

NpuSim 的仿真准确性在论文验证的常规场景（如 Qwen3_4B 模型、中等批次与序列长度）下表现良好，其混合仿真方法在 Ascend NPU 硬件上取得了与实测接近的延迟结果（如图 7 左）。然而，其准确性边界主要存在于两类场景：

### 问题二：优化策略的普适性如何保证？

> 论文提出的张量并行、核心放置与 PD 策略在特定 NPU 架构上效果显著，但这些**策略是否普遍适用于其他多核 NPU（如不同内存层次、互联拓扑的芯片）？** 是否存在因硬件差异导致的性能退化风险？

1. **策略选择依赖硬件配置**：研究明确显示，最优张量并行策略（AllGather/AllReduce）取决于序列长度与隐藏层大小的相对关系；最优核心放置（环形/网格）受实际 NoC 带宽与拓扑影响。例如，在 WaferLLM 中优化的交错线性布局，在作者使用的带通道锁定机制的 NoC 上性能反而不如环形布局，见图 10。

Graphcore IPU、AWS NeuroCore、Tenstorrent、Tesla DOJO、Sambanova、Cerebras WSE、Groq 等各具特色，但它们共享一个共同特征：**多核架构设计**。

### 2.2 NPU 模拟器发展现状

> NPU 模拟器主要分为两类：周期精确模拟和基于性能模型的模拟。

- **周期精确模拟通过模拟每个时钟周期来评估目标架构**，虽能利用低级硬件细节获得准确性能，但:mdnice-bold-italic[模拟时间过长，对计算密集型工作负载（如 LLM）不实用]。一些研究使用 FPGA 加速模拟，但受限于硬件资源和工程复杂度，仍:mdnice-bold-italic[难以支持大规模架构探索。]
- **基于性能模型的模拟采用数学分析来表征延迟**，通过代数外推推导周期数。这类模拟器通常用于设计空间探索和神经网络映射，但对 LLM 推理服务的独特特性关注不足。更重要的是，它们:mdnice-bold-italic[无法准确捕获非确定性延迟的硬件模块，如核心间 NoC 拥塞、异步 HBM 访问和缓存系统不可预测性。]

### 2.3 多核 NPU 上的 LLM 服务加速

先前研究主要集中在优化 GEMM（通用矩阵乘）和 GEMV（通用矩阵-向量乘）计算。

- T10 为 IPU 芯片提出了矩阵计算优化，引入“旋转张量”概念，将输入和权重张量分布到不同计算核心。
- WaferLLM 在 T10 基础上扩展了 Cerebras WSE 平台的优化技术，针对 2D-mesh 拓扑引入了交错排列，确保每个环 AllGather 所需的最大跳数不超过 2。

然而，**这些工作缺乏对多核架构上 GEMM 计算的全面分析**，主要关注基于 AllGather 的 GEMM，未分析 AllReduce 或 AllReduce 与 AllGather 组合策略的性能。

- WSC-LLM 进一步研究了 HBM 和互连带宽对多核 NPU 架构中 LLM 推理的影响，提出了 PD 分离的核布局策略，**但主要针对晶圆级多核 NPU，未考虑片上 SRAM 或 NoC 互连的影响。**

## 三、核心创新：NpuSim——多级模拟框架

### 3.1 设计理念：平衡精度与效率

> 为了系统研究多核 NPU 在 LLM 服务场景中的优化策略，研究团队开发了**NpuSim** ——一个面向数据流多核架构的高效模拟平台。

NpuSim 解决了两大关键挑战：

1. 高效准确地模拟计算密集型和内存密集型的 LLM 推理任务
2. 有效处理现代 LLM 服务场景中普遍存在的流式请求

![文章插图](/articles/2026-01-19-llm-npu-1-32x-6-89356593/images/03.webp)

::: image-caption
图 2 | NpuSim 整体设计。包含计算系统、内存系统、路由系统三大子系统，以及调度器、跟踪引擎、资源分析器等辅助模块。计算系统提供算子的底层原语模拟与工作核心抽象；内存系统采用系统级事务建模（TLM）模拟 SRAM、HBM 访问；路由系统通过握手机制实现 cycle 级精确模拟；调度器支持连续批处理、预填充 - 解码分离（PD Disaggregation）、预填充 - 解码融合（PD Fusion）等策略，可灵活配置请求数量、提示长度等参数。NpuSim 通过 “混合精度模拟” 平衡效率与准确性：计算单元采用性能模型模拟（如 Matmul 算子按 systolic 阵列 tile 划分计算延迟），内存与路由模块采用 cycle 级模拟，既避免了全 cycle 模拟的高耗时，又解决了纯性能模型对非确定性延迟（如 NoC 拥塞、异步 HBM 访问）估计不准的问题。此外，其支持流式请求输入，可复现真实 LLM 服务中动态请求分布（如不同长度的提示与解码步数），为后续优化策略验证提供可靠工具
:::

> 图 2 展示了 NpuSim 的整体设计。系统分为三个组件：计算系统、内存系统和片上路由系统。通过仔细分析这三个组件，研究团队为每个部分采用了特定的模拟级别。

- **计算系统** 采用形状感知性能模型。以 Matmul 算子为例，当使用 N×N 脉动阵列时，首先将权重和输入激活划分为图块，必要时填充最后一个图块。总计算延迟计算公式为：

$$
T_{\mathrm{comp}} = N_{\mathrm{tiles}} \times T_{\mathrm{cycles}} + T_{\mathrm{inject}}
$$

其中 $N_{\mathrm{tiles}}$ 表示权重图块数，$T_{\mathrm{cycles}}$ 是每个图块的脉动周期数，$T_{\mathrm{inject}}$ 是权重注入延迟。

- **内存系统** 采用事务级建模（TLM）方法，将每个内存请求分解为四个阶段：Begin_Req、End_Req、Begin_Resp 和 End_Resp，支持异步事件驱动模拟。这种方法在保持高模拟效率的同时实现了周期精确的模拟精度。
- **路由系统** 采用带握手机制的周期精确模拟来建模路由器行为。一旦建立路由路径（通过握手信号成功交换指示），确保每个时钟周期可以传输一个数据包。这样可以基于已建立链路上的数据传输数量准确计算数据包延迟。

### 3.2 定制化调度器：应对动态 LLM 服务

先前工作主要关注 CNN 或静态 LLM 模拟，其中固定批次的请求执行一次以获得模拟运行时间。然而，这种模拟方法与实际 LLM 部署场景有显著差异。

::: block-1
典型的 LLM 场景中，端到端性能评估需要执行一次预填充阶段，然后是多轮解码阶段。**LLM 模拟必须处理动态图和调度，其中预填充期间的序列长度、解码步骤数和到达时间在不同请求间可能变化。**
:::

研究团队实现了一个:mdnice-bold-italic[迭代级调度器和监控器，允许灵活配置，如每轮迭代的请求数、提示长度、分块预填充和预填充-解码阶段]。这种设计支持定制调度策略如 PD 融合、PD 分离、连续批处理等。

## 四、优化策略：三个维度的突破

### 4.1 张量划分与核布局

> 由于多核 NPU 芯片采用数据流计算范式，其性能对张量划分和核布局策略高度敏感。

#### GEMM 张量划分策略

先前研究主要探讨如何在多核 NPU 上高效部署 GEMM 算子，但这些研究仅针对特定硬件平台提出了 AllGather 策略。**在实际服务场景中，涉及不同模型大小和序列长度，一刀切的方法证明是不充分的。**

![文章插图](/articles/2026-01-19-llm-npu-1-32x-6-89356593/images/09.webp)

::: image-caption
图 3 | GEMM算子的三种不同张量划分策略。（a）1D 划分（M/N 维度）：沿输入 / 权重张量的 M（行）、N（列）维度划分，依赖 AllGather 原语收集完整权重以完成计算，核心 1 与核心 2 通过 AllGather 交换部分张量后执行 GEMM；（b）1D 划分（K 维度）：沿张量的 K（中间维度）划分，基于 AllReduce 原语聚合部分结果，核心 1 与核心 2 分别计算后通过 AllReduce 合并结果；（c）2D 划分（M/N+K 维度）：同时沿 M/N 与 K 维度划分，核心按 2D 网格拓扑排列，先通过 AllReduce 聚合同列核心的部分结果，再通过 AllGather 交换同行核心的张量，迭代完成计算。
:::

图 3 展示了GEMM 算子三种不同的张量划分策略，适配 LLM 推理的不同场景：

- M/N 维度划分在长序列（如序列长度超模型隐藏层维度）场景更优，因 AllGather 可减少通信量；
- K 维度划分适合短序列或分块预填充场景，AllReduce 能降低中间结果传输开销；
- 2D 划分结合两者优势，在中等序列长度下平均实现 1.44 倍性能提升。

![文章插图](/articles/2026-01-19-llm-npu-1-32x-6-89356593/images/10.webp)

::: image-caption
表 2 | 不同张量划分策略的通信和内存成本。该表量化三种张量划分策略的资源消耗：输入 / 权重 / 输出张量列表示各 NPU 核心的内存占用；总通信量为单核心在 GEMM 计算中传输的总数据量；最大跳数为核心间数据传输的最大路径长度（α 通常为 2）。其中，1D（M/N）划分依赖 AllGather，总通信量为 (num-1)×K×N；1D（K）划分用 AllReduce，总通信量为 2×(num-1)/num×M×N；2D 划分结合两种原语，通信量计算更复杂，三者最大跳数均在 1~α 范围
:::

当序列长度小于隐藏大小时如在分块预填充期间，AllReduce 原语表现出更好的性能。

#### 核布局策略

> **核布局策略** 同样至关重要。研究团队首先将所有 NPU 核心划分为多个流水线，每个流水线负责处理模型的一个或多个层。

在每个流水线内，采用不同布局策略（1-D 或 2-D，环或序列）进行张量划分。

![文章插图](/articles/2026-01-19-llm-npu-1-32x-6-89356593/images/11.webp)

::: image-caption
图 4：不同核心布局策略 | 考虑流水线间（inter-pipe）与流水线内（intra-pipe）通信成本的核心布局策略示意图。包含 6 种流水线布局：Pipe-1/2 采用交错线性拓扑（WaferLLM 提出），逻辑相邻节点物理距离近，限制单传输最多 2 跳；Pipe-3/4 采用环形拓扑，天然适配环形 AllGather/AllReduce 通信，但可能降低流水线间带宽；Pipe-5/6 采用 2D 网格拓扑，流水线内互联更丰富，但流水线间带宽较低，且各维度按交错线性排列以最小化通信开销
:::

> 图 4 展示了不同的核布局策略。

- 在 1-D 布局下，有环拓扑（图中的 Pipe-3/4）和交错线性拓扑（WaferLLM 引入，图中的 Pipe-1/2）。使用环拓扑自然符合基于环的 AllGather 和 AllReduce 操作行为，但可能降低流水线间的通信带宽。相反，线性拓扑提供更高的流水线间通信带宽，但虚拟环上逻辑相邻的节点可能在物理上相距较远，需要两跳完成单次通信。
- 在 2-D 布局（Pipe-5/6）中，核心使用 2-D mesh 拓扑组织，为流水线内提供更多互连，但降低了流水线间带宽。在每个维度内，核心根据交错线性拓扑排列以最小化通信开销。

2-D mesh 布局提供最佳理论性能，但由于流水线间带宽限制以及计算和通信的重叠考虑，可能并不适合所有服务工作负载。

### 4.2 层次内存管理

> 当前多核 NPU 常采用非统一内存架构以增强核心可扩展性。然而，这种内存设计为 LLM 服务带来了新挑战，如如何跨不同请求管理 KV 缓存、权重和激活。

先前工作如 WaferLLM 通过将 KV 缓存卸载到其他计算核心来解决单个核心有限的内存容量，但这种设计主要针**对缺乏 HBM 支持的多核 NPU**，如 Cerebras WSE。当代多核 NPU 架构倾向于将 HBM 集成到计算核心附近，以支持更大的模型参数和更长的上下文长度。

::: block-1
考虑到多核 NPU 中的这种内存层次结构，研究团队提出了**混合粒度内存管理系统**，旨在高效协调不同级别的内存对象。
:::

![文章插图](/articles/2026-01-19-llm-npu-1-32x-6-89356593/images/12.webp)

::: image-caption
图 5 | 多核 NPU 的多粒度 KV 缓存管理。多核 NPU 不同内存层级的多粒度 KV 缓存管理示意图。SRAM 采用块级细粒度管理，为每个请求的 KV 缓存维护块 ID 链表（如请求 1 占用 ID1-4），空闲块维护独立链表，请求完成后回收块 ID；HBM 采用缓冲区级粗粒度管理，为每个请求分配固定最大令牌长度的环形缓冲区；同时，SRAM 还静态分配部分空间用于存储部分权重、输入 / 输出及临时计算缓冲区，动态分配空间用于 KV 缓存块，实现内存资源的高效复用
:::

#### KV 缓存管理

将 LLM 服务期间的内存需求分为四类：KV 缓存、模型权重、输入和激活、临时缓冲区。随着 HBM 的集成，不需要在其他 NPU 核心的 SRAM 中保留 KV 缓存，因为片上 SRAM 容量远小于 HBM 容量，且核心间带宽并不显著超过 HBM 带宽。

相反，**研究团队以不同粒度将 KV 缓存储存在 SRAM 和 HBM 中**。由于 SRAM 容量有限，:mdnice-bold-italic[对 SRAM 中的 KV 缓存采用细粒度管理方法，而对 HBM 中的 KV 缓存采用粗粒度管理方案]。在 SRAM 中，KV 缓存在块粒度管理，完整的 KV 缓存可能包含多个非连续块。

随着 KV 缓存不断增长，不可能将整个 KV 缓存存储在 SRAM 中。因此，研究团队**将溢出的 KV 缓存从 SRAM 溢出到 HBM**。考虑到 HBM 提供比 SRAM 大得多的容量，并为顺序读写操作提供更好性能，对 HBM 中的 KV 缓存采用粗粒度管理策略。:mdnice-bold-italic[具体来说，为每个请求分配整个 KV 缓冲区（具有最大令牌长度），并将 HBM 组织为环形缓冲区结构。]

#### 权重和激活管理

除了保留 KV 缓存，SRAM 还可能保存模型权重、激活/输入以及用于计算和通信的临时缓冲区。在预填充阶段和 FFN 阶段，NPU 核心主要执行 GEMM 操作，使计算成为主要性能瓶颈。因此，在 SRAM 中为矩阵计算的中间结果保留适量缓冲区即可。将更多 SRAM 容量分配给计算单元对整体性能影响最小。

### 4.3 PD 分离与 PD 融合

PD 分离或 PD 融合设计通常用于提高 GPU 资源利用率。对于多核 NPU，预填充和解码阶段之间也存在资源利用不平衡。因此，采用 PD 分离或 PD 融合策略同样有效，但引入了新挑战。

#### 4.3.1 多核 NPU 上的 PD 分离

##### PD 分离的核布局

对于 PD 分离，多核架构便于灵活分配片上核心，使一部分核心分配给预填充阶段，其余核心专用于解码阶段。先前研究采用了 DP 优先的核布局策略。

![文章插图](/articles/2026-01-19-llm-npu-1-32x-6-89356593/images/13.webp)

::: image-caption
图 6 | 两种预填充 - 解码分离（PD Disaggregation）的核心布局策略示意图。（a）数据并行优先（DP-prioritized）：先按数据并行度（如 DP=4）将所有核心分组，每个组内按比例分配预填充核心与解码核心，核心间通过 KV 缓存通道传输数据；（b）流水线并行优先（PP-prioritized）：按流水线并行度划分核心，每个核心在 2D 网格拓扑中仅使用一条互联通道，剩余通道用于预填充核心向解码核心传输 KV 缓存；同时将预填充核心置于两侧、解码核心置于中心，最小化 KV 缓存传输延迟。
:::

如图 6-(a)所示，所有核心首先根据预定义的数据并行性（如 DP=4）分组。在每个组内，核心根据指定比例分配给预填充和解码任务。

然而，**更有效的策略是在核布局中优先考虑流水线并行性**。在流水线并行执行中，每个核心仅使用 2D mesh 拓扑内的单个互连通道，允许剩余互连通道用于从预填充核心到解码核心的 KV 缓存传输。:mdnice-bold-italic[图 6-(b)说明了流水线并行优先的布局策略。这种方案最大化预填充和解码核心之间的通信带宽，但不影响流水线并行执行中的数据传输]。此外，研究团队将预填充核心放置在两侧，解码核心放置在中心，以最小化 KV 缓存传输的延迟。

##### PD 分离的并行策略

除了核布局策略，PD 分离还需要仔细考虑预填充和解码阶段的并行策略，例如确定 TP 和 PP 大小。

- 在预填充阶段，请求可以流式进入预填充核心，而无需等待先前任务完成，这允许高效的流水线并行性。
- 相反，解码阶段依赖于自回归计算；后续令牌的生成取决于先前令牌计算的完成。

流水线并行导致解码延迟和每个核心保留的 KV 缓存量增加 N 倍（其中 N 是流水线级数）。相比之下，张量并行提供改进的解码延迟，但由于增加的通信开销可能降低吞吐量。因此，**PD 分离的并行化策略选择应由特定的 SLO 要求决定。**

##### PD 分离的异构核心设计

**考虑到预填充和解码阶段的不同计算特性，为每个阶段部署异构核心是有利的**。例如，解码核心可以配置额外的内存资源，如扩展的 SRAM 容量、HBM 模块和增加的内存接口，同时减少其计算资源，如缩小脉动阵列和向量通道的宽度。

通过调整解码核心中计算和内存资源的分配，对解码期间 GEMM 计算的影响最小，因为解码阶段的请求批次大小通常较小。然而，这种方法大大增强了 GEMM 计算性能，并能够在解码阶段处理更多请求。

#### 4.3.2 多核 NPU 上的 PD 融合

与需要固定预填充和解码任务核心比例的 PD 分离不同，**PD 融合允许单个核心同时处理预填充和解码请求。为了支持这一点，研究团队提出了一个专用调度器，将预填充和解码工作负载共置**，确保满足 TBT（令牌间时间）和 TTFT（首次令牌时间）要求。

为了防止预填充操作过度中断解码过程，采用分块预填充策略，其中预填充请求被划分为固定大小的块。每个核心配置有最大预算大小：解码任务占用一个预算单位，而预填充任务消耗 N 个单位。

- 当解码任务数量超过分配的预算时，调度器优先处理解码请求以最小化预填充任务引起的停顿。
- 相反，当解码工作负载数量低于预算阈值时，调度器将为分块预填充分配预算。

**在 PD 融合场景中，预填充和解码阶段的并行策略【必须】相同**。然而，:mdnice-bold-italic[多核 NPU 上预填充和解码的最优并行化方法并不相同：预填充阶段优选流水线并行，而解码阶段张量并行更有利]。考虑到 PD 融合固有地增加了 TBT，研究团队更倾向于在 PD 融合中为两个阶段采用张量并行。

### 5.3 硬件配置空间探索

![文章插图](/articles/2026-01-19-llm-npu-1-32x-6-89356593/images/15.webp)

::: image-caption
图 8 | 不同硬件配置下 Qwen3 模型的单请求延迟。X 轴表示不同的 SRAM-计算配置（例如，“S32A128”表示 32MB SRAM 和 128×128 脉动阵列）。实验结果揭示硬件配置与 LLM 推理性能的关联规律：小模型（如 4B 参数）在大 SRAM（≥64MB）下，HBM 带宽对延迟影响可忽略（因 SRAM 能容纳大部分权重与 KV 缓存，极少溢出）；大模型（如 32B 参数）因权重与 KV 缓存频繁溢出，需同时提升 systolic 阵列尺寸（增强计算能力）与 HBM 带宽（缓解内存瓶颈），两者协同可降低 1.4 倍延迟；当 SRAM 容量远小于模型权重（如 32B 模型配 16MB SRAM）时，增大 SRAM 对延迟改善有限，此时 SRAM 仅作为临时计算缓冲区，性能更依赖 HBM 带宽与计算单元效率。

- 对于具有大 SRAM 的小模型（例如 4B），由于 SRAM 压力低且溢出到 HBM 最少，HBM 带宽变化对延迟影响可忽略不计。
- 相反，对于大模型（例如 32B），增加脉动阵列维度和 HBM 带宽可以将延迟降低多达 1.4 倍，表明 LLM 推理受计算性能和内存带宽的限制。

关于 SRAM 大小，当模型权重超过 SRAM 容量（例如 32B 模型）时，增加 SRAM 大小对端到端延迟影响最小。这是因为模型权重和 KV 缓存经常溢出，导致 SRAM 充当临时计算缓冲区。**只有当 SRAM 容量接近模型权重大小时，它才会加速 LLM 推理。**

所有实验采用预填充：解码核心比例为 2:1，这是先前测量中的最优配置。同时，基于台积电 7nm 工艺，计算了每单位计算能力、HBM 接口和 SRAM 的芯片面积。

##### PD 融合下的硬件优化

![文章插图](/articles/2026-01-19-llm-npu-1-32x-6-89356593/images/20.webp)

::: image-caption
图 13 | PD 融合下不同输入令牌长度、每核心 SRAM 大小和流水线级数对 Qwen3_8B（TP=4）在 256 个核心上端到端延迟的影响。PD 融合的性能受内存压力与并行度平衡影响：SRAM 容量是关键瓶颈 ——16MB SRAM 因容量不足，需频繁溢出到 HBM，36 级流水线（每核心处理层数少、数据并行度高）较 12 级、18 级实现 1.1-1.61 倍加速；当 SRAM 增至 32MB，溢出减少，延迟实现 2.6-3.7 倍提升；48MB SRAM 下，18 级流水线最优（每核心处理层数适中，既避免单核心内存压力过大，又能利用数据并行提升效率）。这表明 PD 融合需匹配 SRAM 容量与流水线级数：小 SRAM 选多流水线级（高并行度），大 SRAM 选中等流水线级（平衡并行与内存效率），以缓解 PD 融合带来的额外内存压力。

### 5.6 NPU 硬件架构与 LLM 系统设计指导

> 受益于 NpuSim 模拟器和 LLM 服务策略的全面分析，研究团队得出以下关于多核 NPU 硬件架构设计和基于多核架构的 LLM 服务系统的结论：

- **张量并行与核布局**：当序列长度较短或启用分块预填充时，执行 ALLREDUCE GEMM 操作更高效。相反，对于没有分块预填充的长提示场景，ALLGATHER 或 ALLGATHER 与 ALLREDUCE GEMM 操作的组合更可取。此外，将核心排列成环拓扑更好地符合 RING-ALLREDUCE/RING-ALLGATHER 通信模式，并与更复杂的交错序列布局相比提供更大通用性。
- **片上 SRAM 设计**：由于片上 SRAM 的细粒度管理，增加 SRAM 容量的性能效益有限，除非整个模型的权重可以放入 SRAM。
- **LLM 服务系统设计**：对于 LLM 服务工作负载，异构 PD 分离在预填充主导的场景中产生更好性能，而 PD 融合对于解码主导的工作负载更可取。
