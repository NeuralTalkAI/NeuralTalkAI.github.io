## 一、行业痛点：深度学习编译器测试的双重无解困境

> 绝大多数 AI Infra 工程师在做编译器测试时，都会陷入两类无效劳动：要么写海量模糊用例全部卡在输入校验阶段，要么调用大模型生成测试代码，**9 成以上无法正常运行。两种方案都无法触及编译优化阶段的语义缺陷。**

深度学习编译器的核心工作是将高层张量图转化为硬件可执行代码，为提速会执行算子融合、维度重排、归约拆分等改写逻辑。:mdnice-bold-italic[理论上，无论如何优化，张量运算的代数关系必须完全保留，但现有测试体系完全缺失针对这条规则的校验能力，衍生出两大行业痛点。]

### 1.1 传统模糊测试：94.86%用例卡在输入校验，触碰不到编译优化逻辑

> 模糊测试（Fuzzing）是当前工业界最主流的编译器测试手段，核心逻辑是批量生成符合格式的张量输入，观察编译是否报错、程序是否崩溃。

::: block-1
**模糊测试仅拥有“崩溃/合法模型”两类基础预言，无法定义“加法交换律、ReLU 幂等性”这类抽象数学约束。** 即便生成合法张量图，编译器悄悄篡改运算数值，模糊测试也无法识别，:mdnice-bold-italic[这类问题被论文定义为“语义漂移”，是工业场景中难以复现、危害极大的隐性 bug。]
:::

### 1.2 LLM 原生测试生成：超 9 成代码不可执行，仅 5.42%具备正确校验逻辑

> 直接向 GPT 5.5 等大模型下发 prompt 生成属性测试，看似自动化程度最高，实则存在严重的大模型幻觉问题，产出代码存在大量 API 误用、图结构非法、断言逻辑错误。

![文章插图](/articles/2026-06-22-propilot-ai-49-llm-88c76b12/images/06.webp)

::: image-caption
图 2：24 小时 TVM 持续测试下分支、代码行、函数三类覆盖率累积曲线。 该图从 GPU 编译器评测维度推翻 “代码覆盖率衡量测试有效性” 行业误区，揭示纯 LLM 基线高覆盖率的虚假价值。纯 LLM 生成测试覆盖率数值最高，但增量覆盖均来自非法张量、错误 API 的异常报错分支，无法进入算子融合、GPU 张量布局变换等核心优化 Pass；PROPILOT 覆盖率略低，但覆盖路径与编译器真实语义行为的关联度更高，更能有效捕获浮点精度偏差等底层缺陷；传统模糊测试绝大多数输入在校验阶段被拦截，根本无法触及张量变换逻辑。实验结论明确语义缺陷检出优先级远高于覆盖率，PROPILOT 主动舍弃无意义异常分支，将算力倾斜于易产生数值误差的 GPU 张量计算路径，产出可复现、具备修复意义的编译 bug。

> 论文基线实验中，无约束 LLM 24 小时产出 1863 条测试，存在多层致命缺陷：

1. 60.56% 用例调用不存在 TVM API、参数传参错误；
2. 34.85% 生成语法错误的 Relax 张量图；
3. 仅 101 条可运行测试拥有正确的代数校验逻辑，占比仅 5.42%。

::: block-1
同时无约束生成会大量重复同类算子 - 属性组合，测试冗余度较高，算力大量浪费在同质化用例上。:mdnice-bold-italic[大模型缺少张量代数领域的标准化约束，仅凭自然语言无法稳定产出合规、有效的语义校验代码。]
:::

### 1.3 底层根源：缺失张量代数不变量的标准化可执行测试载体

> **加法交换律、归约分解这类张量数学规则，本身无法直接转化为可运行测试代码，需要配套算子约束、张量形状规则、浮点比对阈值等配套规则**，现有研究从未完成这套标准化封装。

张量代数拥有数十年理论沉淀，但此前没有工作将理论规则转化为机器可读、LLM 可复用的测试模板。:mdnice-bold-italic[想要完成一条交换律测试，需要同时明确：哪些算子支持交换、张量维度如何统一、浮点数用 AllClose 还是精确相等、如何构造左右两条等价计算图，零散规则全部依靠人工手写，无法规模化批量生成测试。]

**这是模糊测试、原生 LLM 测试均失效的底层根源**：缺少统一载体衔接张量数学、编译器 API、自动化测试代码。

::: block-1
行业测试体系的核心短板：缺少标准化张量代数载体，导致测试无法完成语义守恒校验，要么大量无效用例，要么无法检测隐性数值偏差。
:::

## 二、PROPILOT 核心创新：张量代数属性骨架的标准化建模方案

> 论文提出的:mdnice-bold-italic[“属性骨架（Property Skeleton）”是整套框架的核心创新，本质是把一条张量代数不变量，封装成包含校验目标、适用范围、生成规则、比对标准的标准化模板。]

**区别于零散自然语言 prompt，骨架具备机器可解析的结构化字段，能够约束 LLM 仅在合法范围内生成测试，从源头杜绝大模型凭空编造算子、校验规则、张量约束的幻觉问题**。整套框架内置 20 套标准化骨架，覆盖三大张量校验场景，可无限拓展新增代数规则。

### 2.1 什么是属性骨架：一张表看懂张量不变量的全维度封装规范

> 表 1 原始字段翻译与延伸解读：

![文章插图](/articles/2026-06-22-propilot-ai-49-llm-88c76b12/images/07.webp)

::: image-caption
表 1：单条张量代数属性骨架存储的全部信息字段说明。
:::

1. Intent：校验语义目标，如交换操作不改变输出；定义这条测试要验证的代数关系；
2. Operator classes：适用算子分类，对称逐元素二元算子；限制骨架只能匹配对应算子；
3. Applicability conditions：生效前置条件，算子不存在顺序依赖；
4. Rejection rule：禁用场景，减法等顺序敏感算子直接跳过；
5. Concretization schema：测试图构造模板，$op(x,y)$ 对比 $op(y,x)$；
6. Oracle notes：结果比对规则，浮点采用带容差近似相等。

单条骨架一次性补齐测试生成全约束，LLM 无需自行推导张量规则，仅做模板实例化，大幅降低错误概率。

### 2.2 三大类骨架体系：覆盖代数、张量结构、兜底校验全场景

> 表 2 分类拆解：

![文章插图](/articles/2026-06-22-propilot-ai-49-llm-88c76b12/images/08.webp)

::: image-caption
表 2：张量代数属性骨架分类与典型实例。 本表将 20 套属性骨架划分为代数原生、张量结构、兜底校验三大类，分层覆盖 TVM GPU 编译全链路语义缺陷风险。代数类校验 add、mul 等基础算子数学不变量，捕捉常量折叠、算子融合破坏交换律的 GPU 编译缺陷；张量结构类针对 GPU 张量分片、维度置换、规约累加场景，论文中单精度 sum 精度丢失典型硬件数值误差 bug 即由几何分解骨架复现；兜底校验适配无通用代数恒等式小众算子，以解释器真值作为基准。传统模糊测试仅捕获程序崩溃，分层骨架可定位无报错静默数值漂移，新增代数校验规则仅补充对应骨架文档即可扩展，代数属性与张量结构属性骨架可覆盖多数算子的核心语义校验场景。

1. **代数属性：算子原生数学规则**，交换律、结合律、单位元，用于校验基础运算改写正确性；以 $add(x,add(y,z))=add(add(x,y),z)$ 结合律为例；
2. **张量结构属性：张量拆分、置换不变性**，专门检测归约、切片类优化精度丢失，论文浮点缺陷案例即依靠归约分解骨架检出；
3. **兜底属性：无专属代数规则时的备用校验**，包含解释器结果对照、形状 dtype 一致性校验，保障小众算子测试覆盖。

整套 20 套骨架形成完整校验矩阵，主流 TVM 算子均可匹配对应不变量模板，无需人工单独编写测试逻辑。

### 2.3 骨架和传统手写测试、LLM 随机 prompt 的本质差异

1. **与手写单元测试对比**：手写测试绑定固定算子与张量尺寸，复用性极差；:mdnice-bold-italic[骨架是通用模板，一次定义适配全部同类算子，规模化生成万级测试；]
2. **与无约束 LLM prompt 对比**：prompt 无算子禁用、形状约束、比对规则，极易生成非法代码；:mdnice-bold-italic[骨架自带全套硬约束，LLM 仅填充张量尺寸、随机数值，不会偏离合法范围；]
3. **与等式饱和工具（TASO、egg）对比**：同类工具仅用代数规则做图优化改写；:mdnice-bold-italic[PROPILOT 将规则反向作为缺陷检测预言，验证优化没有破坏数学等价关系。]

::: block-1
属性骨架的核心价值：实现张量代数理论到自动化测试代码的标准化转化，给 LLM 生成测试增加刚性约束，从源头消除无效、逻辑错误用例。
:::

### 3.1 步骤 1：算子探测与骨架匹配，完成张量规则受控实例化

> Agent 不会凭空编写测试，而是基于探测到的算子，检索知识库匹配合规骨架，再填充张量生成参数，输出标准化测试场景描述。

场景描述分为三段固定结构 data、apply、assert，论文提供 `relax.add` 交换律标准示例：

代码清单 1：TVM Relax 加法交换律标准化测试场景定义。该代码采用 data、apply、assert 三层声明式装饰器，构建 TVM GPU 算子测试最小标准化单元，拆分张量生成、等价图构建、浮点误差校验三大逻辑，配置了适配单精度浮点计算的 rtol/atol 容差阈值，精准匹配 IEEE754 浮点误差特性。对比直接调用 GPT 生成零散测试代码，该范式剥离重复 TVM DSL 模板，LLM 仅填充算子与属性参数即可生成合规用例。场景解析 + AST 语法双层前置校验自动过滤张量尺寸不匹配、非法 API 调用问题，大幅提升测试代码的可执行率与属性逻辑正确率，显著优于纯 LLM 无约束生成的 5.42% 有效占比。标准化代码统一适配多 GPU 后端自动化回归流程，规避人工编写测试时张量精度、尺寸疏漏，支撑实验 4579 条测试稳定批量运行。

- data：定义张量生成规则，随机同尺寸 float32 张量；
- apply：定义两条等价计算图，$op(x,y)$、$op(y,x)$；
- assert：定义浮点比对容差阈值，规避 IEEE 754 原生微小误差。

LLM 仅需要基于该场景描述生成可运行 Python 代码，无需设计代数规则、张量约束，大幅降低出错概率。框架配套 23 种专用数据生成器，包含单位张量注入、随机张量、边界极值张量，覆盖各类数值测试场景。

### 3.2 步骤 2：带权重优先调度机制，解决测试重复冗余问题

> 无约束 LLM 会反复生成 add、multiply 等高频算子的交换律测试，小众算子、分解类骨架长期缺乏覆盖，框架引入动态优先级规则平衡测试多样性。两套核心调度规则：

1. 优先分配从未使用过的算子、骨架、数据生成器组合，补齐测试盲区；
2. 提升出现故障、低覆盖率算子的生成权重，重点复现高风险编译逻辑。

实验数据显示，PROPILOT 将整体冗余降至约 29%，相比直接 LLM 生成减少 49% 冗余；同等 24 小时算力下，可执行且属性逻辑正确的测试规模较无约束 LLM 生成有量级提升。

### 3.3 步骤 3：三层前置校验，从根源消灭不可执行测试

> 校验流程按顺序执行，任意一层不通过直接驳回，附带明确拒绝理由回流 Agent：

1. 场景模式校验：检查 data、apply、assert 三段结构完整，不出现知识库不存在的骨架、生成器，拦截 LLM 编造不存在算子、规则的幻觉；
2. 适用性校验：验证骨架与算子匹配，减法直接拦截交换律测试，归约分解仅分配求和、均值算子；
3. 运行安全校验：AST 静态解析生成代码，确认包含建图、编译、结果比对、故障复现保存完整流程，过滤语法错误、缺失 API 调用代码。

**三层校验叠加属性骨架刚性约束，大幅消除执行前无效测试**，仅残留少量 API 误用问题，绝大多数进入执行阶段的用例均可正常运行。

### 3.4 反馈循环：校验拒绝信息+执行覆盖率反向引导下一轮生成

> 校验驳回的测试会标注精准失败原因：骨架算子不匹配、张量形状冲突、API 参数错误等；执行后采集分支覆盖率、故障类型、算子使用频次，更新调度优先级权重。这套闭环解决两大痛点：

1. Agent 不会重复生成同类非法测试，算力不再浪费；
2. 持续挖掘低覆盖编译路径，重点针对曾出现语义 bug 的算子生成多维度校验用例。

::: block-1
**PROPILOT 工作流核心逻辑：标准化骨架做规则约束、三层前置校验过滤非法用例、动态优先级调度降低冗余、全链路反馈循环持续拓展测试覆盖。**
:::

## 四、实验全维度对比：PROPILOT、LLM 直生成、模糊测试三维对标

### 4.1 实验基准环境与评测对象

> 实验统一基于 TVM Relax 编译器，覆盖 212 个官方算子，PROPILOT 启用 20 套属性骨架，三类测试方案统一分配 24 小时算力资源，横向对比测试有效性、故障检出类型、代码覆盖率质量。 三组对比基线定义：

1. **Fuzz 模糊测试**：仅生成合法张量输入，无代数语义校验，依靠崩溃、编译报错判断缺陷；
2. **LLM-only PBT**：直接 Prompt GPT5.5 生成属性测试，无骨架、无前置校验、无优先级调度；
3. **PROPILOT：完整框架**，属性骨架+受控生成+三层校验+反馈调度。

评测维度包含无效测试占比、测试冗余度、故障分类、浮点数值缺陷检出、代码覆盖率有效程度。

1. **模糊测试故障**：94.86%输入校验报错，无法触及编译优化，无任何语义缺陷检出能力；
2. **原生 LLM 测试故障**：99%为代码执行前错误（API 误用、非法张量图），仅 0.34%属于语义校验失败，无工程检测价值；
3. **PROPILOT 测试故障**：全部通过前置校验可执行，50%是编译器与张量数学语义冲突（核心高价值编译 bug），25%浮点精度不稳定，仅 12.5%残留 API 问题。

数据直观证明，PROPILOT 彻底把测试资源从“筛选合法输入”转移到“校验编译数学守恒”，产出故障全部具备优化逻辑缺陷分析价值。

### 4.3 数值缺陷实测案例：float32 归约运算精度漂移

> **论文基于张量分解骨架复现经典 IEEE 754 单精度浮点数归约 bug，该类缺陷模糊测试、原生 LLM 均无法稳定捕获**。测试案例参数：张量包含 2042 个数值 9035，采用 float32 存储，理论数学结果：
>
> $$
> Result = 2042 \times 9035 = 18449470
> $$

1. 拆分张量分段求和再拼接：输出结果严格等于理论值；
2. 完整张量一次性归约求和：TVM 优化后输出 18449656，存在数值偏差。

偏差底层原理：float32 尾数存储位数有限，累加至千万级大数后，新增 9035 小数位被舍弃；拆分归约分段累加数值量级接近，不会丢失精度。

**该缺陷仅能依靠归约分解类张量骨架检出**，传统测试没有定义该类比对逻辑，上线后会造成模型推理结果持续偏移。

### 4.4 代码覆盖率的认知误区：高覆盖 ≠ 高有效缺陷检出能力

> 实验 24 小时覆盖率数据：原生 LLM 分支、行、函数覆盖率数值最高，PROPILOT 次之，模糊测试最低。但论文明确指出覆盖率存在巨大欺骗性：

1. LLM 高覆盖率来源：大量非法 API、非法张量图触发编译器异常分支，全部是输入校验报错路径，不涉及核心优化逻辑；
2. PROPILOT 覆盖率：全部来自合法张量图的编译、优化、数值比对路径，每一行覆盖都对应真实推理计算流程； 工程启示：单纯追求代码覆盖率无意义，必须区分“异常报错路径覆盖”与“正常优化逻辑覆盖”，属性驱动测试产出的覆盖率具备业务落地价值。

::: block-1
实验核心结论：**PROPILOT 相较传统方案，彻底重构故障产出结构**，高占比检出编译器语义、浮点精度缺陷，**是少数将张量代数属性系统化、规模化应用于 AI 编译器属性测试的框架之一。**
:::

## 五、领域横向对比：PROPILOT 与同类编译测试工作的差异化定位

### 5.1 与 IR 变异、优化感知模糊测试的区别

> 现有 TVM 专用测试工具如 NNSmith、HirGen、OATest，**核心思路是变异张量 IR、生成多样化合法模型，校验标准仅为编译不崩溃。**

而 PROPILOT 的差异化核心为：

1. 传统工具优化测试输入多样性，PROPILOT 优化测试预言（Oracle）完备性；
2. 前者只能判断模型能否编译运行，后者验证优化后数值是否符合张量数学；

两类工具可互补使用，先依靠模糊测试生成多样模型，再用 PROPILOT 做代数语义二次校验。

### 5.2 与 TASO、egg 等式饱和张量工具的区别

- TASO、egg 依靠代数等式做张量图超优化，核心目标是生成等价轻量化计算图；
- PROPILOT 复用同类代数等式，但目标反向：**验证编译器优化不会破坏等式等价。**

两者使用同一套张量数学体系，但应用链路完全相反：等式饱和用于优化生成，属性骨架用于优化正确性校验，形成“优化-验证”闭环。

### 5.3 与 LLM 辅助测试生成框架的区别

- CoverUp、TestForge 等工具依靠覆盖率反馈微调 LLM Prompt，仍属于无约束生成；
- PROPILOT 引入结构化骨架作为中间控制层，硬性约束大模型生成边界，从根源降低幻觉。

:mdnice-bold-italic[同类 LLM 测试框架未解决“张量代数规则标准化”问题，无法稳定产出具备语义校验逻辑的代码]，而这是本工作核心突破。

::: block-1
领域差异化总结：**现有研究分别聚焦输入生成、图优化、无约束 LLM 代码生成**，PROPILOT 填补“张量代数规则标准化、语义预言自动化”空白，形成全新属性驱动测试范式。
:::

## 六、工程落地价值与未来拓展方向

### 6.1 工业落地优势

1. **极低人工维护成本：新增算子仅需匹配已有骨架**，新增代数规则仅补充一条属性模板，无需批量手写单元测试；
2. **适配主流 AI 编译器**：TVM、ONNX-MLIR 均可接入，仅需替换算子探测、API 适配模块；
3. 缺陷定位精准：故障附带两套等价张量图、完整张量输入、浮点比对日志，工程师可直接复现优化偏差，大幅缩短 bug 定位周期；
4. 算力利用率提升：零无效测试、低冗余，同等算力下产出更多有价值语义校验用例。

### 6.2 当前框架局限

1. **骨架需要领域专家预先定义**，自动化抽取张量代数规则能力缺失；
2. 当前**仅支持静态固定尺寸张量测试**，动态维度场景覆盖不足；
3. 未适配多硬件后端差异化精度校验，不同芯片浮点误差阈值需要手动配置。

### 6.3 未来迭代路径

1. 自动化骨架抽取：解析算子实现代码、数学文档，自动生成属性骨架模板，降低专家介入成本；
2. 动态张量拓展：补充动态 shape 专用数据生成器、适配动态维度代数校验规则；
3. 分布式测试调度：多机并行生成、执行属性测试，适配大规模编译器持续集成流水线；
4. 多后端精度自适应：依据 CPU、GPU、NPU 硬件特性自动调整浮点比对 rtol、atol 容差。
