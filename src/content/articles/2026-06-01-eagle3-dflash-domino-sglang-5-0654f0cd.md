关键词：**推测解码**、因果建模、**并行草稿**、:mdnice-bold-italic[LLM 推理加速]、Domino

> "因果依赖建模是提升草稿质量的关键，但标准自回归实现使其代价高昂。"这一来自 Domino 论文的核心论断，精准点出了当前 LLM 推理加速领域最棘手的矛盾。

自 2023 年推测解码（Speculative Decoding）被提出以来，它已成为工业界加速大语言模型推理的主流技术。其核心思想是用一个轻量级草稿模型提前生成多个候选 token，再由目标大模型在单次前向传播中并行验证，从而减少昂贵的目标模型调用次数。

::: block-1
然而，所有推测解码方法都无法回避一个根本的权衡：**草稿质量越高，接受长度越长，但草稿生成的成本也越高，最终可能抵消甚至超过验证阶段带来的收益**。
:::

## 一、相关工作

为了更好地理解 Domino 的贡献，我们需要先回顾推测解码技术的发展脉络，以及现有方法在解决质量-成本权衡问题上的尝试与局限。

### 1.1 传统推测解码框架

> 推测解码的基本思想最早由 Leviathan 等人于 2023 年提出。其核心公式可以表示为：

$$
\eta = \frac{\tau L_{target}}{T_{draft} + T_{verify}}
$$

其中：

- $\eta$ 是最终的端到端加速比
- $\tau$ 是每轮推测解码平均接受的 token 数（包括目标模型生成的奖励 token）
- $L_{target}$ 是标准自回归解码的单 token 延迟
- $T_{draft}$ 是草稿模型生成 γ 个候选 token 的时间
- $T_{verify}$ 是目标模型验证这些候选 token 的时间

::: block-1
从这个公式可以看出，提升加速比有两个途径：一是提高接受长度 $\tau$，二是降低草稿生成时间 $T_{draft}$。**所有后续的推测解码改进工作，本质上都是在这两个维度上进行优化。**
:::

早期的推测解码方法使用一个更小的语言模型作为草稿模型，按照自回归方式生成候选 token。:mdnice-bold-italic[这种方法虽然简单，但小模型与大模型的分布差异较大，导致接受长度较短，加速效果有限。]

### 1.2 自回归草稿方法的演进

> 为了提高草稿质量，研究者们提出了一系列改进的自回归草稿方法，其中最具代表性的是 EAGLE 系列。**EAGLE-3 通过训练时测试（Training-Time Testing, TTT）策略，让草稿模型在训练时就模拟多步生成过程，从而更好地对齐目标模型的分布。**

然而，自回归草稿方法的固有缺陷无法避免：生成 γ 个 token 需要 γ 次顺序的草稿模型前向传播和 LM 头投影。其草稿成本可以近似表示为：

$$
T_{draft}^{AR} \approx \gamma \cdot (t_{net} + t_{head})
$$

其中 $t_{net}$ 是单次草稿模型前向传播的延迟，$t_{head}$ 是单次 LM 头投影的延迟。:mdnice-bold-italic[这意味着草稿成本会随着推测预算 γ 的增加而线性增长。当 γ 增大到一定程度时，草稿成本的增加会超过接受长度提升带来的收益，导致加速比反而下降。]

::: block-1
为了缓解这一问题，FR-Spec 和 SpecVocab 通过静态或动态词汇选择，减少了 LM 头投影的计算量，:mdnice-bold-italic[但它们仍然保留了自回归的执行方式，无法从根本上解决顺序开销问题。]
:::

### 1.3 并行草稿方法的兴起

> 为了彻底消除顺序开销，研究者们开始探索并行草稿方法。**这类方法的核心思想是在单次前向传播中生成整个草稿块的所有 token**，其草稿成本为：

$$
T_{draft}^{PAR} \approx t_{net}^{block} + t_{head}^{block}
$$

与自回归方法不同，这里的 $t_{net}^{block}$ 和 $t_{head}^{block}$ 只需要执行一次，与草稿块大小 γ 无关。这使得并行草稿方法在理论上具有更高的效率上限。

近年来出现的并行草稿方法包括：

- PARD：将自回归模型适配为并行草稿模型
- DART：并行预测多个未来位置的 token 分布，然后通过树剪枝构建候选
- DFlash：使用块扩散模型作为草稿器，单次前向传播生成整个草稿块

::: block-1
然而，所有这些并行草稿方法都面临一个共同的问题：**完全并行的生成方式破坏了草稿块内部的因果依赖关系**。每个 token 的生成都只依赖于已验证的前缀，而不依赖于同一块中前面生成的 token。这导致草稿分布与目标模型的自回归分布存在较大偏差，接受长度下降，最终限制了加速比的提升。
:::

### 1.4 Domino 与现有方法的本质区别

> Domino 的出现，填补了并行草稿方法在因果建模方面的空白。与现有方法相比，它具有以下核心优势：

| 方法类型 | 代表工作 | 因果建模能力 | 草稿生成成本 | 核心局限 |
| --- | --- | --- | --- | --- |
| 自回归草稿 | EAGLE-3 | 强（显式建模） | 高（线性增长） | 顺序开销大 |
| 纯并行草稿 | DFlash | 弱（无内部依赖） | 低（常数级） | 接受长度短 |
| 词汇优化 | FR-Spec | 强（自回归） | 中（部分降低） | 仍有顺序开销 |
| 解耦式设计 | Domino | 强（轻量级修正） | 极低（接近并行） | 需额外训练轻量级头 |

从上表可以看出，**Domino 是第一个同时实现了"强因果建模能力"和"极低草稿生成成本"的推测解码框架**。它没有像自回归方法那样通过多次前向传播来建模因果，也没有像纯并行方法那样完全放弃因果，而是通过一个轻量级的修正分支，在并行生成的基础上重新引入了因果信息。

它由两个核心组件组成：**并行草稿骨干** 和**Domino 头**。并行草稿骨干负责高效地生成整个草稿块的初步分布，而 Domino 头则负责注入因果信息，对初步分布进行精细化修正。

::: block-1
这种解耦式设计的核心优势在于：将计算密集型的特征提取工作完全并行化，而将轻量级的因果修正工作放在一个独立的分支中执行。这样既保留了并行草稿的高效率，又恢复了自回归草稿的高质量因果建模能力。
:::

### 2.1 并行草稿骨干

> Domino 的并行草稿骨干基于 DFlash 架构实现。它的核心思想是利用目标模型的上下文特征，通过掩码预测的方式并行生成整个草稿块的隐藏表示。

具体来说，给定一个已验证的前缀 $x_{\leq t}$，我们使用最后一个已验证的 token $x_t$ 作为锚点，构造一个掩码草稿块：

$$
\tilde{x}_{t: t+B-1} = [x_t, [MASK], ..., [MASK]]
$$

其中 $B$ 是草稿块的大小（在 Domino 的实验中设置为 16），后面的 $B-1$ 个位置对应未来需要生成的草稿 token。

然后，骨干网络将目标模型从已验证前缀中提取的上下文特征 $C_t$，以及掩码草稿块的嵌入作为输入，在单次非自回归前向传播中生成整个块的隐藏状态：

$$
H_{t: t+B-1} = Backbone(C_t, Embed(\tilde{x}_{t: t+B-1}))
$$

最后，使用冻结的目标模型 LM 头，从这些隐藏状态中计算出每个位置的初步 logits：

$$
L_i^{base} = LMHead(H_i), \quad i = t+1, ..., t+B-1
$$

::: block-1
这里有一个非常重要的设计选择：**Domino 直接复用了目标模型的 LM 头**，而不是训练一个新的 LM 头。这不仅减少了训练参数，更重要的是保证了初步分布与目标模型分布的基础对齐。
:::

并行草稿骨干的整个过程都是完全并行的，没有任何顺序依赖。这使得它的计算效率极高，与生成的 token 数量无关。

### 2.2 Domino 头：轻量级因果修正

> 并行草稿骨干生成的初步分布虽然高效，但缺乏草稿块内部的因果依赖信息。为了解决这个问题，Domino 引入了一个轻量级的 Domino 头，它由两个部分组成：**因果编码器** 和**低秩修正头**。

#### 2.2.1 因果编码器

因果编码器的作用是总结前面已生成的草稿 token 的信息，为后续位置的修正提供上下文。Domino 选择了 GRU（门控循环单元）作为因果编码器，因为它具有轻量级、高效的特点，非常适合处理顺序信息。

对于每个草稿位置 $i$，因果编码器接收前面所有已采样的草稿 token 的嵌入，生成一个因果状态：

$$
S_{i-1} = GRU(E_{\leq i-1})
$$

其中 $E_j$ 是位置 $j$ 的 token 嵌入，$S_{i-1} \in \mathbb{R}^{d_s}$ 是因果状态向量。在 Domino 的实现中，GRU 的隐藏维度 $d_s$ 设置为 1024，这是一个非常小的维度，计算成本极低。

这里需要特别注意的是，因果编码器的输入是**已采样的草稿 token**，而不是隐藏状态。这意味着因果修正过程是在 token 级别进行的，与目标模型的自回归生成过程更加一致。

#### 2.2.2 低秩修正头

> 低秩修正头的作用是将因果状态与并行骨干生成的基础隐藏状态结合起来，生成 logit 空间的残差修正。其计算公式为：

$$
\Delta L_i = W_2 \sigma(W_1 [H_i; S_{i-1}])
$$

其中：

- $[H_i; S_{i-1}]$ 表示将基础隐藏状态 $H_i$ 和因果状态 $S_{i-1}$ 拼接
- $W_1$ 是一个投影矩阵，将拼接后的向量映射到一个低秩隐藏空间（维度 $r=256$）
- $\sigma$ 是 SiLU 激活函数
- $W_2$ 是另一个投影矩阵，将低秩表示映射到词汇空间

最终的草稿 logits 是基础 logits 加上修正 logits：

$$
L_i = L_i^{base} + \Delta L_i
$$

Domino 在这里做了一个非常关键的设计选择：**在 logit 空间进行修正，而不是在隐藏空间**。如果在隐藏空间进行修正，那么每次修正后都需要重新应用完整的 LM 头，这会重新引入昂贵的全头计算。而在 logit 空间进行修正，只需要在并行计算的基础 logits 上添加一个低秩残差，计算成本极低。

为了更直观地理解这个过程，我们可以用一个简单的例子来说明： 假设我们要生成句子"人工智能正在改变世界"。并行草稿骨干可能会同时生成"人工"、"智能"、"正在"、"改变"、"世界"这几个 token 的初步分布。:mdnice-bold-italic[但由于没有因果依赖，它可能会给"人工"后面的"智能"分配一个较低的概率，或者给"正在"后面的"改变"分配一个较低的概率。]

::: block-1
Domino 头会先采样第一个 token"人工"，然后因果编码器会将"人工"的信息编码成因果状态 $S_0$。低秩修正头会根据 $S_0$ 和第二个位置的基础隐藏状态，生成修正 logits，提高"智能"的概率。接着采样第二个 token"智能"，因果编码器更新状态为 $S_1$，修正第三个位置的 logits，提高"正在"的概率，以此类推。
:::

这个过程模拟了自回归生成的因果依赖，但每个步骤只需要执行一个轻量级的 GRU 更新和低秩矩阵乘法，而不需要重新运行整个草稿模型。

## 三、Domino 训练策略

Domino 的训练策略是其成功的另一个关键因素。论文提出了两个创新的训练技术：**教师强制因果编码** 和**基础锚定课程学习**，:mdnice-bold-italic[分别解决了因果编码器的训练信号问题和修正分支短路问题。]

### 3.1 教师强制因果编码

> 在训练因果编码器时，一个自然的想法是使用训练时测试（TTT）策略，即让编码器接收模型自己生成的前缀，模拟推理时的情况。EAGLE-3 就是采用了这种策略。

然而，Domino 的作者发现，TTT 策略存在两个严重的问题：

1. **噪声输入问题**：在训练早期，模型生成的前缀往往是错误的。让编码器学习从错误的前缀预测正确的下一个 token，会建立一个不存在于真实数据分布中的输入-输出映射，导致因果表示质量下降。
2. **与验证机制不匹配**：在推测解码的验证阶段，一个草稿 token 只有在前面所有 token 都被接受的情况下才会被考虑。也就是说，只有当前面的 token 都是正确的时候，后面的修正才会起作用。而 TTT 策略训练的编码器需要处理各种错误前缀的情况，这在推理时是无关的。

因此，Domino 采用了**教师强制** 策略，即在训练时给因果编码器输入真实的 ground-truth token 嵌入，而不是模型自己生成的前缀。

这种策略的优势非常明显：

- 它为因果编码器提供了干净、一致的训练信号，让它专注于学习正确的因果依赖关系
- 它与推测解码的验证机制完全对齐，因为只有在前面的 token 都正确的情况下，修正才会被使用

论文中的消融实验（图 4 右）证明了教师强制的有效性：与 TTT 相比，教师强制将平均接受长度从 3.80 提升到了 3.96。

![文章插图](/articles/2026-06-01-eagle3-dflash-domino-sglang-5-0654f0cd/images/08.webp)

::: image-caption
图 4：训练策略消融实验结果。左图为有无基础锚定课程的并行骨干损失曲线；右图为训练时测试（TTT）、教师强制（TF）、教师强制 + 基础锚定课程（TF+Curr）下的平均接受长度，灰色虚线为 DFlash 基准。该图揭示了适配并行推理的训练优化关键。无基础锚定课程时，Domino 头易过度依赖校正分支，并行骨干损失持续走高，训练时梯度回传不稳定，收敛速度慢；引入基础锚定课程后，前期强化骨干训练、后期逐步转向校正优化，损失稳定下降，有效避免了骨干崩溃问题。对比三种训练策略，TTT 因自生成前缀噪声大，GPU 训练有效信号少，接受长度仅 3.80；TF 用真实前缀提供因果信号，接受长度升至 3.96；TF+Curr 结合两者优势，既保证因果信号质量，又避免骨干崩溃，接受长度达 4.19，证明该训练策略能最大化 GPU 训练算力价值，适配并行草稿框架的优化需求。
:::

### 3.2 基础锚定课程学习

> 虽然教师强制解决了因果编码器的训练信号问题，但它也引入了一个新的问题：**修正分支短路**。

由于教师强制给修正分支提供了非常干净的前缀信息，模型可能会倾向于让修正分支承担所有的预测工作，而让并行草稿骨干变得无用。这会导致基础 logits 的质量严重下降，最终影响整体性能。

为了防止这种情况发生，Domino 提出了**基础锚定课程学习** 策略。它的:mdnice-bold-italic[核心思想是在训练过程中，同时监督基础 logits 和最终 logits，并使用一个随时间变化的权重来平衡两者的损失]：

$$
\mathcal{L} = (1 - \lambda_t) \mathcal{L}_{final} + \lambda_t \mathcal{L}_{base}
$$

其中：

- $\mathcal{L}_{final}$ 是从最终 logits 计算的交叉熵损失
- $\mathcal{L}_{base}$ 是从基础 logits 计算的交叉熵损失
- $\lambda_t$ 是一个随时间变化的权重，从 1 线性退火到 0

在训练初期，$\lambda_t=1$，损失完全由基础 logits 决定，这迫使并行草稿骨干学习一个强大的基础分布。随着训练的进行，$\lambda_t$ 逐渐减小，优化的重点逐渐转移到最终 logits 上，让 Domino 头学习如何在基础分布上进行因果修正。

![文章插图](/articles/2026-06-01-eagle3-dflash-domino-sglang-5-0654f0cd/images/09.webp)

::: image-caption
图 4：训练策略消融实验结果。左图为有无基础锚定课程的并行骨干损失曲线；右图为训练时测试（TTT）、教师强制（TF）、教师强制 + 基础锚定课程（TF+Curr）下的平均接受长度，灰色虚线为 DFlash 基准。
:::

- 图 4 左展示了基础锚定课程学习的效果：没有使用课程学习时，并行骨干的损失在训练过程中保持在较高水平，说明骨干没有得到充分训练；而使用课程学习后，骨干的损失稳步下降，最终达到了更低的水平。
- 图 4 右的消融实验进一步证明，基础锚定课程学习将平均接受长度从 3.96 进一步提升到了 4.19，带来了显著的性能提升。

此外，与 DFlash 一样，Domino 在计算损失时使用了位置指数衰减权重 $w_k = \exp(-k/\gamma)$，优先优化更早的草稿位置。这是因为更早的位置的接受会决定整个块的接受长度，对最终加速比的影响更大。

- 基础锚定课程学习进一步将平均接受长度从 3.96 提升到了 4.19（+5.8%）

这两个训练策略的结合，为 Domino 带来了总计 10.3%的接受长度提升。

## 五、局限性与未来展望

> 尽管 Domino 取得了显著的性能提升，但它仍然存在一些局限性，未来还有很多可以改进的方向。

### 当前局限性

1. **训练成本**：Domino 需要额外训练一个轻量级的 Domino 头，虽然参数量很小，但仍然需要一定的计算资源。论文没有讨论如何降低这部分训练成本。
2. **框架兼容性**：目前 Domino 的实现主要适配了 SGLang 服务框架，与其他主流框架（如 vLLM、TensorRT-LLM）的兼容性还需要进一步验证。
3. **硬件依赖性**：Domino 的性能优势在 A100 GPU 上得到了充分验证，但在其他硬件平台（如 NVIDIA H100、AMD MI300、国产 AI 芯片）上的表现还需要进一步测试。不同硬件的内存带宽、计算能力和内核效率都会影响最终的加速比。

### 未来展望

1. **更高效的因果编码器**：目前 Domino 使用 GRU 作为因果编码器，未来可以探索更高效的序列模型（如线性 RNN），进一步降低因果修正的延迟。
2. **动态草稿块大小**：目前 Domino 使用固定的 16-token 草稿块大小。未来可以根据输入内容的复杂度动态调整草稿块大小，在简单内容上使用更大的块，在复杂内容上使用更小的块，进一步提升效率。
3. **与其他技术的结合**：Domino 可以与其他 LLM 推理加速技术结合，如量化、稀疏化、KV 缓存优化等，实现更大的加速比。

## 总结

> Domino 是 LLM 推测解码领域的一项突破性工作。它提出了一种全新的解耦式架构设计，将因果依赖建模从昂贵的自回归草稿执行中分离出来，通过一个轻量级的 Domino 头在并行草稿的基础上注入因果信息。

这种设计完美地解决了长期困扰推测解码的质量-成本权衡问题：

- 它保留了并行草稿的低成本优势，草稿生成时间与块大小无关
- 它恢复了自回归草稿的高质量因果建模能力，接受长度接近自回归方法

实验结果表明，Domino 在 Qwen3 模型上实现了最高 5.49× 的端到端加速比和 5.8× 的吞吐量加速比，全面超越了 EAGLE-3、DFlash 等主流方法。

::: block-1
Domino 的出现，不仅为 LLM 推理加速提供了一个新的解决方案，更重要的是它提出了一种新的设计思路：将计算密集型的并行处理与轻量级的顺序修正相结合。这种思路可能会启发更多的 LLM 系统优化工作，推动大语言模型的部署效率不断提升。
:::
