## 一、困局与破局：当 GPU 能耗建模陷入“黑盒”与“过拟合”

> 在 E 级超算时代，一个残酷的现实是：我们拥有了前所未有的并行算力，却对每一焦耳能量的流向知之甚少。NVIDIA Management Library 等厂商工具能给出整卡的功耗读数，但这对需要优化内核代码的开发者来说，无异于**只知道整栋楼的电费单，却不知道哪个房间在漏电。**

传统的性能调优只看重“时间”，但在功耗封顶的现代集群中，省下的每一瓦特都可以转化为更多的计算吞吐量。然而，现有的 GPU 能耗建模手段却集体陷入了泥潭。

### 1.1 迷雾重重的现状：从 PTX 投影到脆弱的微架构仿真

为了看清 GPU 内部的能耗细节，学术界和工业界尝试了多种路径。表 1 清晰对比了 Wattchmen 与现有方案在泛化能力、细粒度归因等方面的差异。

![文章插图](/articles/2026-04-23-ml-gpu-wattchmen-sass-a7660322/images/05.webp)

::: image-caption
表 1：Wattchmen 与近期 GPU 能耗建模方法的对比。该表格从架构可移植性、冷却适配性、计算 / 控制流 / 存储层次能耗建模、细粒度分解、全面测量六大维度对比主流方法。现有方法均存在能力缺失：Arafa 等仅覆盖计算指令、Delestrac 等仅聚焦存储层次、Guser 缺失控制流指令、ML 模型无细粒度可解释性、AccelWattch 环境鲁棒性差。Wattchmen 是唯一全覆盖所有维度的方法，为跨架构、跨环境的细粒度能耗归因提供完整能力支撑，解决了传统模型的片面性缺陷。
:::

从表中不难看出，虽然各类方案各有侧重，但在“全都要”的苛刻实际需求面前，往往捉襟见肘。

> 具体而言，现有的技术路线面临三大痛点：

1. **高层虚拟 ISA 的“失真”问题**。基于 PTX 指令建模是一种直观思路。例如 Arafa 等人的工作通过 PTX 推导能耗，Guser 则关注最大功耗。但问题在于，PTX 是一种中间表示，从 PTX 到真实执行的 SASS 指令，中间隔着编译器优化与汇编器的“黑盒翻译”。:mdnice-bold-italic[编译器选项的微小变动可能导致生成的 SASS 指令序列面目全非，使得基于 PTX 的能耗估算沦为刻舟求剑。]
2. **部件级模型的“碎片化”困境**。Delestrac 等人专注于显存层次能耗，Vijay Kandiah 等人提出的 AccelWatch :mdnice-bold-italic[试图覆盖全部件，却陷入了微架构建模的“过拟合”陷阱]。AccelWatch :mdnice-bold-italic[通过性能计数器与二次规划求解器拟合功耗，但其参数极度敏感]。论文在引言中给出了一个极具说服力的例子：同样针对 V100 GPU，AccelWatch 在原始验证环境误差为 16%，但在 NSF CloudLab 的 V100 节点上，仅仅因为冷却方式、显存容量、最高频率的不同，误差剧烈波动至 32%。当作者尝试对 CloudLab 环境进行重新校准标定时，AccelWatch 的迭代求解器甚至直接崩溃，并将缓存功耗归零。
3. **机器学习方法的“可解释性”缺失。** 虽然 ML 模型能在特定语料下做出精准预测，但其归因粒度:mdnice-bold-italic[仅到 Kernel 级别]。面对“为什么这个矩阵乘功耗异常？”的追问，ML 模型只能摊手，:mdnice-bold-italic[无法给出指令级或微架构级的优化洞见。]

### 1.2 Wattchmen 的核心洞察：从“孤立法”转向“方程组解法”

> 既然直接测量每条指令如此困难，Wattchmen 换了一个思路。论文一针见血地指出：**任何微基准测试都不可能 100%只包含目标指令。**

举个例子，为了测试`FFMA`浮点乘加指令的功耗，你写的微基准测试里必然包含循环控制指令、地址计算指令、寄存器移动指令。:mdnice-bold-italic[这些“辅助指令”就像背景噪声，如果不剔除，就会导致对`FFMA`的能耗估算偏大。]

::: block-1
Wattchmen 的核心洞察在于——**这些在 A 测试中的“背景噪声”，恰恰是 B 测试想要测量的“目标信号”**。
:::

![文章插图](/articles/2026-04-23-ml-gpu-wattchmen-sass-a7660322/images/06.webp)

::: image-caption
图 3：用于求解风冷 V100 GPU 指令能耗的完整方程组子集。每行代表一个微基准测试，每列代表目标指令在基准中的出现频率。V100 的完整表格包含 90 个微基准，覆盖 90 条指令 单微基准无法避免辅助指令干扰，直接测量会导致目标指令能耗估算偏差。该方程组将所有微基准的能耗与指令计数联立，把辅助指令的能耗贡献纳入整体求解，分离出每条指令的真实能耗。90 个微基准覆盖 V100 核心指令集，非负求解保证能耗值的物理意义，从方法论上解决了传统微基准测量的系统性误差，是 Wattchmen 高精度的核心支撑。
:::

例如，图 3 展示了一个微基准测试片段，其中`IMAD_IADD`指令占比 58%，`IADD3`占比 40%。如果我们有一系列覆盖不同指令组合的测试，就可以构建一个巨大的线性方程组：

$$
E_{dynamic} = \sum_{i}^{n}count_{i}\times energy_{i}
$$

公式中的 $E_{dynamic}$ 代表单个微基准测试测得的动态能耗，$count_i$ 是该测试中第 $i$ 种指令的执行次数，而 $energy_i$ 则是我们要求解的目标——单条指令的真实能耗。

::: block-1
通过同时联立数十个这样的方程，Wattchmen 利用非负线性求解器，一举将指令的真实能耗从复杂的交织关系中“萃取”了出来。
:::

### 1.3 稳字当头：为什么稳态测量比瞬态抓取更可靠？

> 除了方程组解法，Wattchmen 的另一大法宝是“稳态测量”。

AccelWatch 等方法试图通过抓取瞬态功耗峰值或窗口平均来建模，这极易受到温度、Boost 频率机制的影响。特别是在风冷和水冷环境下，芯片的积热速度不同，导致同一计算任务的瞬态功耗曲线存在差异。

![文章插图](/articles/2026-04-23-ml-gpu-wattchmen-sass-a7660322/images/07.webp)

::: image-caption
图 4：在风冷 Tesla V100 GPU 上运行双精度加法微基准时，通过 NVML 采集的功耗轨迹，含 GPU 利用率（红色）与 GPU 功耗（蓝色）。微基准启动后快速进入稳态，功耗稳定在 150W 左右，利用率保持高位。稳态测量可屏蔽 GPU 温度波动、冷却效率变化的干扰，使功耗数据具备高度一致性。该测量方式将总能耗拆解为常量、静态、动态三部分，精准剥离指令执行的动态能耗，避免了瞬态测量的噪声干扰，为指令级能耗计算提供了可靠的数据基础，适配各类冷却环境。
:::

**Wattchmen 反其道而行之。** 如图 4 所示，:mdnice-bold-italic[它让微基准测试运行足够长的时间，直到 GPU 功耗曲线拉平为一条直线，核心温度也达到热平衡。此时，环境变量带来的扰动被最小化，测得的稳态功耗与 NVML 累计能耗数据几乎完美吻合]。通过这种策略，Wattchmen 天然地对冷却方式不敏感——这也是为什么它在水冷的 Summit 超算和风冷的 CloudLab 上都能保持 15%左右误差的根本原因。

::: block-1
Wattchmen 的方法论革命在于：

- 用“求解线性方程组”代替“孤立测试”，剥离辅助指令的噪声；
- 用“稳态热平衡测量”代替“瞬态峰值拟合”，免疫环境差异。
:::

## 二、Wattchmen 设计原理：从微基准测试到指令能耗字典

> 上一章我们理解了 Wattchmen 的战略思想，本章我们将深入其战术执行细节。构建 Wattchmen 并非一蹴而就，它分为“训练”与“预测”两阶段，而**训练阶段的核心**，在于**设计一套能够精准命中 SASS 指令“靶心”的微基准测试集。**

![文章插图](/articles/2026-04-23-ml-gpu-wattchmen-sass-a7660322/images/08.webp)

::: image-caption
图 2：Wattchmen 设计总览。Wattchmen 分为训练与预测两大阶段：训练阶段通过微基准集、稳态功耗测量、非负线性方程组求解，生成指令级能耗表；预测阶段结合指令计数、缓存命中率，通过缩放、分组、桶化提升指令覆盖率，完成应用能耗细粒度预测。整体架构实现了测量 - 建模 - 预测的全流程闭环，既保证了指令级能耗的精准性，又兼顾了对未测量指令、新架构的适配性，是高保真与灵活性兼顾的 GPU 能耗建模框架。
:::

论文中详细阐述了 Wattchmen 的总体架构，如图 2 所示。

- 顶部是训练流程，通过微基准测试、Profiler 和线性求解器生成指令能耗表；
- 底部是预测流程，对真实应用进行指令统计并加权求和得出总能耗。

### 2.1 穿透 PTX 迷雾：基于 SASS 的微基准测试构建

> Wattchmen 拒绝停留在 PTX 表层，而是**直接瞄准最终执行的 SASS 汇编**。这既是其高精度的来源，也是工程实现的难点。

因为 NVIDIA 的汇编器会将 PTX 指令映射为特定的 SASS 指令，不同 CUDA 版本、不同优化级别下的映射规则甚至会有微调。**为此，Wattchmen 的微基准测试大量使用了内联汇编与强制循环展开。**

![文章插图](/articles/2026-04-23-ml-gpu-wattchmen-sass-a7660322/images/09.webp)

::: image-caption
代码清单 1：微基准测试代码片段。该 CUDA 内核针对 SHFL 指令设计，通过循环展开 100 次提升目标指令占比，饱和线程块与 SM 调用保证 GPU 全负载运行。内核采用内联汇编直接生成 SASS 指令，规避 PTX 到 SASS 编译的指令变异问题，精准隔离 SHFL 指令的能耗。该微基准设计是 Wattchmen 指令级测量的典型实现，解决了传统微基准指令纯度不足、编译干扰的问题，确保单指令能耗测量的精准性。
:::

以上述代码清单 1 中的 SHFL 指令测试为例，为了测量 Warp 内洗牌 SHFL 指令的能耗，测试代码将`__shfl_sync`包裹在`#pragma unroll`的循环体内。:mdnice-bold-italic[这种设计不仅通过展开消除了循环跳转的开销，更关键的是通过反复执行制造了足够长的稳态窗口。]

::: block-1
**更值得称道的是，Wattchmen 设计了覆盖不同数据位宽、不同寻址模式、不同缓存命中的全方位测试**。例如，为了区分 L1 缓存命中与未命中的能耗，测试集会通过调整数据步长故意制造 Cache Miss，并结合性能计数器记录实际的命中率。
:::

![文章插图](/articles/2026-04-23-ml-gpu-wattchmen-sass-a7660322/images/10.webp)

::: image-caption

### 2.2 剥离基底：静态功耗与恒定功耗的分离艺术

> 有了微基准测试的总能耗，我们还不能直接拿来解方程，因为 GPU 的总能耗是三部分的叠加：

$$
E_{total} = E_{const} + E_{static} + E_{dynamic}
$$

- $E_{const}$ 是 GPU 在最低功耗状态下的能耗，可视为系统空转开销。
- $E_{static}$ 是 GPU 被唤醒但 SM 内无实质计算时的开销，例如时钟树、缓存漏电流等。
- $E_{dynamic}$ 才是真正由指令执行引起的开关功耗。

Wattchmen 通过一项精妙的观测方法分离了它们。

::: block-1
作者引用了 Summit 系统上的研究发现：当一个 SM 被激活但不执行任何工作时，功耗固定在某一水平。Wattchmen 利用`NANOSLEEP`内核进行测试，确认了 Volta、Ampere、Hopper 架构在空闲激活状态下，都会产生一笔固定的功耗开销。
:::

通过在执行微基准测试前采集空闲功耗，并将其按时间换算为 $E_{const}$ 与 $E_{static}$ 并从总能耗中扣除，Wattchmen 成功将**动态能耗** 这一核心变量剥离了出来。

### 2.3 补全拼图：分组、伸缩与分桶机制

> 面对 GPU 指令集成百上千的变种，穷举所有微基准测试是不可能的。Wattchmen 引入了三种机制来补全指令能耗字典：

1. **修饰符分组**。很多 SASS 指令带有`.E`、`.AND`、`.OR`等谓词或缓存控制修饰符。:mdnice-bold-italic[这些修饰符改变了控制流，但对 ALU 或数据通路的物理能耗影响微乎其微。Wattchmen 将带有此类修饰符的指令归为一组，赋予相同的能耗值。]
2. **位宽伸缩**。对于访存指令，虽然指令助记符相同，但读取 8-bit 和 128-bit 的能耗显然不同。:mdnice-bold-italic[Wattchmen 通过少数几种位宽的实测数据，推导出位宽与能耗的比例因子，进而估算未测试位宽的能耗。]
3. **功能分桶**。对于那些:mdnice-bold-italic[极其罕见、难以构造独立测试的指令，Wattchmen 将其归类到功能相似的大桶中]。例如，`R2UR`寄存器转换指令被归入“整数 ALU 指令”桶，并使用桶内已知指令的平均能耗。这一策略:mdnice-bold-italic[将指令覆盖率从 70%提升到了 93%，且未引入明显误差。]

### 2.4 预测阶段：将字典映射回真实应用

> 当训练好的“指令能耗字典”就绪后，预测变得水到渠成。

针对任意 GPU 内核，Wattchmen 调用 Nsight Compute 抓取 SASS 指令执行次数与各级缓存命中率。结合命中率信息，Wattchmen 还能修正访存指令的实际开销——**一次 L2 命中的 LDG 指令与一次直连显存的 LDG 指令，将被赋予不同的能耗值。**

最终，应用的总能耗预测值等于基底能耗与所有指令动态能耗的累加。这种细粒度的归因，使得开发者能够像看性能 Profile 一样，看到一张清晰的**能耗火焰图**。

::: block-1
Wattchmen **通过 SASS 层级微基准测试剥离了 PTX 的模糊性，利用方程组求解解决了指令耦合难题**，并借助修饰符分组与分桶策略达成了接近完备的指令集覆盖。
:::

## 四、相关工作：站在巨人的肩膀上审视 Wattchmen

> GPU 能耗建模并非全新的课题，但 Wattchmen 之所以能脱颖而出，在于它对前人的局限性有着深刻认知。通过梳理从架构级解析模型到机器学习黑盒，再到 Wattchmen 的演进脉络，我们能更清晰地定位其坐标。

### 4.1 架构级解析模型：辉煌与迟暮

- 早期的 CACTI 与 McPAT 等工具通过底层电路参数估算 CPU 缓存与内核的功耗。
- 对于 GPU，Leng 等人提出了 GPUWatch，将 McPAT 的思路延伸至 GPGPU 领域。

**这类基于第一性原理的模型虽然白盒化程度高，但依赖于对底层工艺库的精确建模**。遗憾的是，由于商业机密，这些工具无法获得最新的 FinFET 工艺参数，导致对 14nm 及更先进节点的预测严重失准。:mdnice-bold-italic[它们已停留在“前 Volta 时代”，无法反映现代 GPU 中 TensorCore 等异构单元的物理实现。]

### 4.2 经验投影与机器学习的局限

> 本文**重点对比的 AccelWatch 是经验投影法的巅峰之作，它试图用数学优化代替物理建模**。但正如前文所述，这种过度参数化的模型极易陷入局部最优，且对运行环境的微小扰动极度敏感——这正是典型的“过拟合”症状。

Arafa 等人与 Guser 的方法虽灵活，但受限于 PTX 层级的信息损失。PTX 指令`mad.lo.s32`可能在 SASS 层被拆解为多条指令，甚至被融合优化，这使得高层级的能量归因天然带有偏差。

至于纯 ML 模型，尽管 Wu 等人的工作在特定测试集上表现出色，但其无法提供可操作的优化建议。对于一个需要重写代码的 HPC 开发者而言，“Kernel A 功耗高”是句废话，只有“指令 X 占比异常”才是金玉良言🤣。

### 4.3 Wattchmen 的比较优势

::: block-1
Wattchmen 开创了第三条路：**数据驱动的、基于 SASS 的非线性归因系统**。它既不假设特定的电路参数，也不依赖黑盒训练，而是:mdnice-bold-italic[通过穷举真实硬件上的稳态响应来反推内部状态。]
:::

- 相比于 PTX 模型，它更**硬核** ——直击底层 SASS。
- 相比于 AccelWatch，它更**稳健** ——稳态方程解法规避了数值求解的不稳定性。
- 相比于 ML 模型，它更**透明** ——输出的是一张清晰的指令价目表。

## 五、结论与展望：走向精细化的后 E 级能效时代

作为总结，我们既要肯定 Wattchmen 在当前阶段取得的突破，也要以批判性视角审视其方法论边界。技术的进步往往在于直面其局限性，并以此规划下一步的航向。

### 5.1 结论总结

> Wattchmen 为 GPU 能耗建模领域带来了三个核心贡献：

1. 方法论重构。提出了基于稳态功率测量的系统性能量方程组求解框架，首次实现了对 SASS 指令级能耗的高保真逆向工程。
2. 跨平台泛化能力。实验证明 Wattchmen 对冷却方式、显存配置、架构代际具有极强的鲁棒性，在 V100 至 H100 的跨度上保持 15%以下的 MAPE，大幅领先于 AccelWatch 等现有方案。
3. 可操作的洞察。通过 Backprop 与 QMCPACK 案例展示了细粒度能耗归因在实际生产优化中的巨大潜力，证明了“看清能耗”是“降低能耗”的必要前提。

### 5.2 进阶分析：Wattchmen 的方法论边界与隐性成本

> 抛开作者视角的正面陈述，我们必须冷静审视 Wattchmen 解决方案的完整性。

首先，**“全 SM 活跃”假设下的归因偏差**。Wattchmen 训练微基准测试时，强制占满所有 SM 以摊薄共享资源开销。然而在真实应用中，SM 占用率往往动态波动。当 SM 部分空闲时，静态功耗在总功耗中的占比会急剧攀升。:mdnice-bold-italic[Wattchmen 默认的线性归因模型在低占用率场景下可能会低估空闲 SM 的漏电开销，导致预测偏差。论文作者也坦诚了这一点，指出全覆盖 SM 活动组合会导致设计空间爆炸，目前仅处理典型情况。]

其次，**深流水线中的能耗重叠问题**。现代 GPU 的指令流水线极深，多条指令的取指、译码、发射、执行、写回阶段高度重叠。:mdnice-bold-italic[将总能耗简单切割为单条指令的累加，隐含了“能耗可加性”假设。在存在数据冒险或流水线气泡时，某些指令可能并未引入额外的动态翻转，仅仅是占用了发射槽]。这种“影子能耗”的归属是现有归因模型的理论盲区。

第三，**NVML 测量精度的物理限制**。Wattchmen 使用 NVML 作为训练标签。然而 Zeyu Yang 等人的研究表明，:mdnice-bold-italic[NVML 的采样率与时延对毫秒级乃至微秒级内核的测量存在固有误差]。虽然稳态测量缓解了这一问题，但对于极致轻量级的 Kernel Launch，训练数据的噪声依然存在。

最后，**SASS 指令集变动的维护成本**。尽管分桶机制解决了覆盖面问题，但面对 NVIDIA Blackwell 及后续架构引入的全新指令簇，分桶的合理性假设将受到挑战。:mdnice-bold-italic[维护这套精确的微基准测试集需要持续的逆向工程投入，这是 Wattchmen 开源后社区需要共同面对的长期成本。]

### 5.3 未来工作

#### 原文计划

> 论文作者明确指出，未来的工作重心将集中在以下三个方向：

1. **多 GPU 通信能耗建模**。目前的 Wattchmen 仅覆盖单卡计算与访存，尚未涉及 NVLink、InfiniBand 等片间通信的能耗归因。作者已启动了名为“ET”的扩展项目，旨在填补多卡集体通信的能耗盲区。
2. 降低训练成本。:mdnice-bold-italic[论文在讨论部分实验发现，不同冷却环境下的指令能耗表存在极强线性关系。利用 10%的微基准测试数据即可拟合出剩余 90%指令的能耗。这一发现有望将新平台的训练成本降低一个数量级。]
3. 集成至全系统模拟器。团队计划将 Wattchmen 的指令能耗字典对接到 AccelSim 与 gem5 模拟器中，使得架构师在设计早期阶段就能评估新指令或新缓存策略的能耗代价。

#### NeuralTalk 视角

> 站在 AI Infra 与异构计算的发展浪潮之巅，我们认为 Wattchmen 的潜力远不止于此：

1. 面向大模型推理的功耗调度。当前 LLM 推理服务面临巨大的功耗波动，Prefill 阶段计算密集，Decode 阶段访存密集。若能基于 Wattchmen 构建一个实时的功耗预测器，结合 NVIDIA MIG 或多进程服务，调度器可以实现**功耗感知的 Batching**，在保证 SLO 的前提下最大化每瓦特 Token 吞吐量。
2. Chiplet 异构集成的能耗解剖刀。AMD MI300 与 NVIDIA B200 均采用了 Chiplet 设计，不同计算片与缓存片之间的数据搬运能耗占比急剧升高。**Wattchmen 的稳态测量法天然适合解耦这种多芯粒互联的能耗结构。若能将其扩展至对 Infinity Fabric 或 NVLink-C2C 链路的监控，将对下一代超异构芯片的软件调优产生颠覆性指导。**
3. 编译器能耗优化反馈回路。既然我们有了指令级能耗字典，为何不让编译器直接生成“更省电”的代码？当前的 NVCC 编译器几乎完全是性能导向的。**若能以 LLVM 插件形式集成 Wattchmen 的代价模型，编译器可以在指令选择阶段做出能耗感知的决策——例如在寄存器压力不大时，优先选择能耗更低的指令序列而非单纯延迟更低的序列**。这将是软件定义能效的终极形态。

Wattchmen 不仅是看守者，它更像一盏探照灯，第一次让我们如此清晰地看到了 GPU 硅基心脏每一次跳动的能量脉搏。在后摩尔时代的漫漫长夜，唯有看清能量的流向，才能让算力之火燃烧得更加持久而热烈。
