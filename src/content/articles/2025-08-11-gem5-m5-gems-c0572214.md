> gem5 模拟基础设施融合了 M5[4]和 GEMS[9]模拟器的最佳特性。

- M5 提供了高度可配置的模拟框架、多种指令集架构（ISA，即处理器能够理解和执行的指令集合）以及多样化的 CPU 模型。

## 关键问题

### Q1. 作者强调gem5的核心优势在于通过多种CPU模型、ISA、内存系统等组件的灵活组合实现广泛的模拟能力，但也提到“并非所有ISA、CPU模型和内存系统的组合都能正常工作”。这些不兼容的具体场景有哪些？其底层技术原因是组件接口设计的固有缺陷还是模块化实现的阶段性问题？这对依赖复杂组合进行前沿架构研究的用户会造成多大程度的限制？

> 关于组件不兼容的问题，作者提到“并非所有可能的ISA与其他组件的组合目前都能正常工作”，但**未明确列举具体不兼容场景**，仅指出“最新列表可在gem5网站查询”。

其技术原因在于“**每个组件模型必须支持所有ISA在任何模式下所需的功能集合** ”，导致部分组合因功能覆盖不全而存在不一致，这属于模块化实现中的阶段性问题——**作者明确提到“我们持续致力于消除这些不一致”，表明这并非接口设计的固有缺陷**。

对用户的限制主要体现在需要特定ISA与CPU/内存系统组合的研究可能无法直接开展，但:mdnice-bold-italic[通过查询官网更新列表可提前规避，一定程度上降低了影响。]

### Q2. gem5通过不同CPU模型（如AtomicSimple、O3）和内存系统（Classic、Ruby）构建了速度与准确性的权衡光谱，但在实际研究中，当需要同时模拟异构架构（如CPU与GPU协同）或新兴存储技术（如非易失性内存）时，现有模型的“权衡粒度”是否足够？是否存在既无法满足准确性要求（如细粒度时序建模）又难以接受性能损耗的“盲区”？这种局限性是否源于其合并M5与GEMS时的架构遗产？

> 关于异构架构或新兴存储技术模拟的权衡粒度，文档**指出gem5的CPU模型** （AtomicSimple、O3等）**和内存系统** （Classic、Ruby）**覆盖了速度与准确性的广泛权衡**，但:mdnice-bold-italic[未提及对异构架构（如CPU与GPU协同）或非易失性内存的支持]。

现有模型主要针对传统CPU和缓存 coherence 协议（如失效型协议），对新兴技术的细粒度建模存在“盲区”——例如，**作者提到SLICC不支持更新型协议的字级粒度**，且**未涉及非易失性内存的时序或持久化特性模拟。**

这种:mdnice-bold-italic[局限性与架构遗产相关]：gem5源于M5（侧重CPU和基础内存）与GEMS（侧重缓存 coherence）的合并，**原有组件设计未涵盖异构协同或新兴存储场景**，导致权衡粒度无法满足此类需求。

### Q3. 作者将并行化和检查点导入作为提升模拟效率的关键方向，但并行离散事件模拟在gem5中面临的核心技术障碍（如事件依赖管理、一致性维护）是什么？与QEMU等工具的检查点导入如何解决指令集状态、设备寄存器等细粒度状态的一致性问题？这些技术瓶颈是否会导致gem5在面对超大规模系统模拟时逐渐失去竞争力？

> 关于并行化和检查点导入的技术问题，并行离散事件模拟的核心障碍在**作者未明确说明，但结合并行模拟的通用挑战及作者在“重构内部事件系统”的表述，可推测主要涉及事件依赖管理** （如跨核心事件的顺序一致性）**和状态一致性维护** （如共享内存的同步更新）。

检查点导入方面，作者仅提及“计划支持从QEMU等工具导入状态检查点”，未说明如何解决指令集状态、设备寄存器等细粒度状态的一致性问题。

这些瓶颈目前尚未导致gem5失去竞争力：作者强调其作为社区工具的广泛应用和持续迭代，且并行化和检查点导入是正在推进的工作，表明团队在主动应对，短期内仍能满足多数架构研究需求。

## 一、引言

计算机体系结构研究人员通常使用软件模拟来原型化并评估他们的想法。随着计算机行业的不断发展，人们所考虑的设计范围也在扩大。

::: block-1
- 一方面，多核系统和更深层次的缓存层次结构（即由多级缓存组成的存储架构）的出现，为架构师带来了多个新的探索维度。
- 另一方面，研究人员需要一个灵活的模拟框架，能够评估各种各样的设计，并支持丰富的操作系统功能，包括输入输出（IO）和网络。
:::

计算机体系结构研究人员还:mdnice-bold-italic[需要一个能够让他们与工业界和学术界同行合作 的模拟框架]。然而，模拟器的许可条款和代码质量可能会阻碍这种合作。一些开源软件许可证可能过于严格，尤其是在工业环境中，因为它们要求公开任何对模拟器的增强内容。此外，较差的代码质量和缺乏模块化会使新用户难以理解和修改代码。

gem5 模拟器通过提供一个**灵活、模块化的模拟系统克服了这些限制**，该系统能够评估广泛的系统，并且向所有研究人员广泛开放。:mdnice-bold-italic[该基础设施通过提供多样化的 CPU 模型、系统执行模式和内存系统模型来保证灵活性]。对模块化和清晰接口的重视，使研究人员能够专注于代码的特定方面，而无需理解整个代码库。基于 BSD 的许可证使代码对所有研究人员开放，没有繁琐的法律限制。

> 本文简要概述了 gem5 的目标、理念、功能和未来工作，并提供了获取更多信息的来源。

## 二、Overall Goals

gem5 模拟器的**首要目标** 是成为一款**专注于架构建模的社区工具。**

该目标包含三个关键方面：通过:mdnice-bold-italic[灵活的建模] 吸引广泛的用户群体、为社区提供:mdnice-bold-italic[广泛的可用性和实用性]，以及通过高水平的:mdnice-bold-italic[开发者互动促进协作]。

### 2.1 灵活性

灵活性是任何成功的模拟基础设施的基本要求。

::: block-1
- 例如，当一个想法从高层概念发展为具体设计时，架构师需要一种能够在不同细节层次上评估系统的工具，以平衡模拟速度和准确性。不同类型的实验可能也需要不同的模拟能力。
- 例如，一项细粒度时钟门控（通过关闭不使用的电路部分来节省功耗）实验可能需要详细的 CPU 模型，但无需对多个核心进行建模。
:::

> gem5 模拟器提供了各种各样的功能和组件，这使其具备很强的灵活性。

这些功能和组件在多个维度上有所不同，并涵盖了广泛的速度/准确性权衡，如图 1 所示。**gem5 功能的关键维度包括**：

### 2.2 可用性

> gem5 的用户有多种类型，每种类型都有不同的目标和需求。其中包括学术和企业研究人员、工业界工程师以及本科生和研究生。我们希望 gem5 模拟器能够广泛地为每类用户所用。

gem5 社区非常活跃，并利用多种协作技术促进 gem5 的使用和开发，包括邮件列表、维基百科、基于网络的补丁审查以及公开可访问的源代码库。

## 三、设计特点

> 本节重点介绍 gem5 实现中的几个关键方面：普及的面向对象设计、Python 集成、领域特定语言以及标准接口的使用。

虽然这些特性中的大多数只是良好的软件工程实践，但它们都对模拟器的设计特别有用。

### 3.1 Pervasive Object-Oriented Design（普及的面向对象设计）

**灵活性是 gem5 模拟器的一个重要目标，也是其成功的关键方面**。灵活性主要通过面向对象设计来实现。通过独立的、可组合的对象构建配置的能力，自然地带来了诸如多核和多系统建模等高级功能。

gem5 模拟器中的所有主要模拟组件都是 `SimObject`（模拟对象），并共享配置、初始化、统计和序列化（ `checkpointing`，即:mdnice-bold-italic[保存模拟器在某个时刻的状态，以便后续可以从该状态继续模拟]）的共同行为。`SimObject` 包括具体硬件组件的模型，如处理器核心、缓存、互连元件和设备，以及更抽象的实体，如工作负载及其用于系统调用仿真的相关进程上下文。

每个 `SimObject` 都由两个类表示，一个在 Python 中，一个在 C++中，这两个类都派生自各自语言中的 `SimObject` 基类。Python 类定义指定了 `SimObject` 的参数，并用于基于脚本的配置。通用的 Python 基类提供了实例化、命名和设置参数值的统一机制。C++类包含 `SimObject` 的状态和其余行为，包括性能关键的模拟模型。

### 3.2 Python 集成

gem5 模拟器通过与 Python 的紧密集成获得了强大的功能。虽然模拟器的 85%是用 C++编写的，但 Python 贯穿于其操作的各个方面。

如 3.1 节所述，**所有 `SimObject` 在 Python 和 C++中都有对应的表示**。:mdnice-bold-italic[Python 方面负责初始化、配置和模拟控制]。

- 模拟器启动后几乎立即开始执行 Python 代码；
- 标准的 `main()`函数是用 Python 编写的，所有命令行处理和启动代码也都是用 Python 编写的。

### 3.3 领域特定语言

> 在执行特定任务需要高度灵活性的情况下，领域特定语言（DSL）通过利用该问题领域中常见的知识和习惯用法，提供了一种强大且简洁的方式来表达各种解决方案。

**gem5 环境提供了两种领域特定语言**：

::: block-1
- 一种用于:mdnice-bold-italic[指定指令集（继承自 M5）]
- 另一种用于:mdnice-bold-italic[指定缓存一致性协议（继承自 GEMS）。]
:::

#### ISA DSL（指令集架构领域特定语言）

**gem5 的 ISA 描述语言统一了二进制指令的解码及其语义的指定**。:mdnice-bold-italic[gem5 的 CPU 模型通过使用通用的 C++基类来描述指令，从而实现了指令集架构的独立性]。派生类重写诸如 `execute()`之类的虚函数来实现操作码（如加法指令 `add`）。这些派生类的实例表示特定的机器指令，如 `add r1,r2,r3`（将寄存器 r2 和 r3 的值相加，结果存入寄存器 r1）。因此，实现特定的指令集架构需要一组这些派生类的 C++声明，以及一个函数，该函数接收一条机器指令并返回与之对应的某个派生类的实例。

**ISA 描述语言允许用户简洁地指定所需的 C++代码**。该语言的一部分允许指定类模板（比 C++模板更通用），这些模板涵盖广泛的指令类别，如寄存器到寄存器的算术运算。该语言的另一部分用于指定解码树，该解码树将操作码解码与作为先前定义模板实例的特定派生类的创建简洁地结合起来。

虽然最初的 ISA 描述语言针对的是 RISC（精简指令集计算机）架构，如 Alpha 指令集架构，但它已经得到了显著扩展，以应对复杂的变长指令集架构（特别是 x86）以及具有复杂寄存器语义的指令集架构（如 SPARC）。这些扩展包括微码汇编器、预解码器和多级寄存器索引转换。这些扩展在最近的一个书籍章节[5]中有更详细的讨论。

#### Cache Coherence DSL（缓存一致性领域特定语言）

**SLICC 是一种领域特定语言**，它使 gem5 能够灵活地**实现各种缓存一致性协议**。:mdnice-bold-italic[本质上，SLICC 将缓存、内存和 DMA（直接内存访问，允许外设直接与内存交换数据而不经过 CPU）控制器定义为独立的每内存块状态机，这些状态机共同构成了整个协议]。通过在更高层次的语言中定义控制器逻辑，SLICC 允许不同的协议以最小的编程工作量整合相同的底层状态转换机制。

gem5 版本的 SLICC 与之前 GEMS 版本的 SLICC[9]非常相似。与之前的版本一样，gem5 SLICC 将协议定义为一组状态、事件、转换和动作。在规范文件中，各个转换语句定义了有效的组合，每个转换中的动作指定了必须执行的操作。与之前的版本类似，gem5 SLICC 将状态机特定的逻辑与协议无关的组件（如缓存存储器和网络端口）联系起来。

虽然 gem5 SLICC 与其前身设计有一些相似之处，但该语言也包含了一些增强功能。

::: block-1
- 首先，该语言本身现在是用 Python 而不是 C++实现的，这使其更易于阅读和编辑。
- 其次，为了符合 gem5 的 SimObject 结构，所有配置参数都被指定为输入参数，并且 gem5 SLICC 会自动生成相应的 C++和 Python 文件。
- 最后，gem5 SLICC 允许使用局部变量来简化编程并提高性能。
:::

### 3.4 标准接口

> 标准接口是面向对象设计的基础。两个核心接口是**端口接口** 和**消息缓冲区接口**。

端口是 gem5 中用于连接两个内存对象的接口之一。在 Classic 内存系统中，端口接口连接所有内存对象，包括 CPU 与缓存、缓存与总线以及总线与设备和内存之间的连接。

**端口支持三种数据访问机制** （时序、原子和功能），以及**用于确定拓扑和调试等功能的接口**。时序模式用于模拟内存访问的详细时序。通过发送消息向内存系统发出请求，并期望通过其他消息异步返回响应。

**原子模式用于获取一些时序信息**，但它不是面向消息的。:mdnice-bold-italic[当进行原子调用（通过函数调用）时，操作的状态变化是同步执行的]。这具有更高的性能，但由于没有对消息交互进行建模，因此牺牲了一些准确性。最后，功能访问会更新模拟器状态，但不会改变任何时序信息。这些通常用于调试、系统调用仿真和初始化。

Ruby 利用端口接口连接到 CPU 和设备，并添加了消息缓冲区以在内部连接 Ruby 对象。消息缓冲区与端口类似，因为它们都提供标准的通信接口。然而，消息缓冲区在消息类型和存储方面存在一些细微差异。**未来，端口和消息缓冲区可能会演变为一个统一的接口。**

## 四、模拟功能（Simulation Capabilities）

> gem5 模拟器具有广泛的模拟功能，涵盖从指令集架构（ISA）、CPU 模型和一致性协议的选择，到互连网络、设备和多系统的实例化等多个方面。本节将介绍这些类别中可用的一些不同选项。

### 指令集架构（ISAs）

gem5 模拟器目前支持多种指令集架构，包括 Alpha、ARM、MIPS、Power、SPARC 和 x86。:mdnice-bold-italic[模拟器的模块化设计允许这些不同的指令集架构接入通用的 CPU 模型和内存系统，而无需为特定指令集架构专门定制这些组件]。不过，并非所有指令集架构与其他组件的可能组合目前都能正常工作。最新的兼容列表可在 gem5 网站上查询。

### 执行模式（Execution Modes）

> gem5 模拟器可以在两种模式下运行：系统调用仿真（SE）模式和全系统（FS）模式。

#### SE 模式

在 SE 模式下，gem5 会仿真大多数常见的系统调用（例如 `read()`）。当程序执行系统调用时，gem5 会捕获该调用并进行仿真，通常是将其传递给主机操作系统。

SE 模式目前没有线程调度器，因此线程必须静态映射到核心，这限制了它在多线程应用中的使用。SPEC CPU 基准测试通常在 SE 模式下运行。

#### FS 模式

在 FS 模式下，gem5 会模拟一个适合运行操作系统的裸机环境（指没有安装操作系统的硬件环境）。这包括对中断、异常、特权级别、I/O 设备等的支持。由于需要更高的复杂性和完整性，并非所有指令集架构目前都支持 FS 模式。

---

**与 SE 模式相比，FS 模式提高了模拟的准确性，并增加了 gem5 可执行的工作负载种类**。虽然 SPEC CPU 基准测试可以在 SE 模式下运行，但在 FS 模式下运行会提供与操作系统更真实的交互。需要大量操作系统服务或 I/O 设备的工作负载可能只能在 FS 模式下运行。例如，由于 Web 服务器依赖内核的 TCP/IP 协议栈（用于网络通信的一组规则）和网络接口来发送和接收请求，而 Web 浏览器需要 X11 服务器（一种图形窗口系统）和显示适配器来显示网页，这些工作负载必须在 FS 模式下运行。

### CPU 模型（CPU Models）

> gem5 模拟器支持四种不同的 CPU 模型：AtomicSimple、TimingSimple、InOrder 和 O3。

#### AtomicSimple 和 TimingSimple

AtomicSimple 和 TimingSimple 是**非流水线 CPU 模型**，它们尝试在每个周期内取指、解码、执行和提交一条指令。

::: block-1
- AtomicSimple CPU 是**一种极简的单 IPC** （每周期指令数）:mdnice-bold-italic[CPU，所有内存访问都能立即完成]。这种低开销使 AtomicSimple 成为诸如快进等模拟任务的理想选择。
- 相应地，TimingSimple CPU 一次也只允许一个未完成的内存请求，但该 CPU 会模拟内存访问的时序。
:::

#### InOrder 模型

这是一种:mdnice-bold-italic[“执行中执行”的 CPU 模型，强调指令时序和具有顺序流水线的模拟准确性]。InOrder 可以配置为模拟不同数量的流水线阶段、发射宽度（每个周期可处理的指令数）和硬件线程数。

#### O3 模型

最后，O3 CPU 是一种:mdnice-bold-italic[流水线化的乱序执行模型，它会模拟指令之间、功能单元（如加法器、乘法器等）、内存访问和流水线阶段之间的依赖关系]。

可参数化的流水线资源（如加载/存储队列和重排序缓冲区）使 O3 能够模拟超标量架构（每个周期可执行多条指令的架构）和具有多个硬件线程（SMT，同时多线程，指在一个 CPU 核心上同时运行多个线程）的 CPU。

O3 模型也是**“执行中执行”** 的，这意味着**指令只有在所有依赖关系都得到解决后才会在执行阶段执行。**

### 缓存一致性协议（Cache Coherence Protocols）

SLICC 使 gem5 的 Ruby 内存模型能够实现多种基于失效的缓存一致性协议（通过使其他缓存中的旧数据失效来保证一致性），从监听协议到目录协议以及介于两者之间的多种协议。SLICC 将缓存一致性逻辑与内存系统的其他部分分离，提供了实现广泛协议逻辑所需的抽象。**与它的前身 GEMS[9]类似，SLICC 的所有操作都以缓存块为粒度（即按块处理数据）**。目前不支持基于更新的协议所需的字级粒度（按单个字处理数据）。到目前为止，这一限制并未造成问题，因为基于失效的协议在商业市场中占主导地位。具体而言，**gem5 SLICC 目前模拟了一种基于 AMD Opteron™ 的广播协议[7]，以及一种 CMP（芯片多处理器）目录协议[10]。**

SLICC 不仅**足够灵活以模拟不同类型的协议，还能对这些协议进行足够深入的模拟**，以体现详细的时序行为。具体来说，:mdnice-bold-italic[当缓存块从一个基本状态转换到另一个基本状态时，SLICC 允许在各个状态机中指定瞬态状态] （临时的中间状态）。SLICC 还包括独立的虚拟网络（也称为网络消息类），以便正确模拟消息依赖关系和延迟。通过这些虚拟网络，SLICC 生成的控制器可以连接到互连网络。

### 互连网络（Interconnection Networks）

**Ruby 内存模型支持多种互连拓扑**，并包括两种不同的网络模型。本质上，:mdnice-bold-italic[只要拓扑由点对点链路组成，Ruby 就可以创建任何任意拓扑。]

一个简单的 Python 文件会声明组件之间的连接，然后通过最短路径分析创建路由表。Ruby 创建链路和路由表后，可以通过两种方式实现生成的网络。

::: block-1
- 第一种 Ruby 网络模型称为简单网络（Simple network）。简单网络会模拟链路和路由器延迟以及链路带宽。然而，简单网络不会模拟路由器资源竞争和流量控制。这种模型非常适合需要 Ruby 详细协议建模，但可以牺牲详细网络建模以换取更快模拟速度的实验。
- 第二种 Ruby 网络模型是 Garnet 网络模型[1]。与简单网络不同，Garnet 会详细模拟路由器微架构，包括所有相关的资源竞争和流量控制时序。这种模型适用于片上网络研究。
:::

### 设备（Devices）

**gem5 模拟器支持多种 I/O 设备，从简单的计时器到复杂的网络接口控制器**。模拟器提供了封装常见设备接口（如 PCI，一种外设互连标准）的基类，以避免代码重复并简化新设备的实现。

目前已实现的模型包括网络接口卡（NICs）、IDE 控制器（一种硬盘接口）、帧缓冲区（用于存储图像数据）、DMA 引擎（直接内存访问引擎，可让设备直接访问内存）、UARTs（通用异步收发传输器，用于串行通信）和中断控制器。

### 多系统建模（Modeling Multiple Systems）

由于模拟器的面向对象设计，它还支持模拟多个完整的系统。这通过实例化另一组对象（CPU、内存、I/O 设备等）来实现。通常，用户通过上述网络接口连接这些系统，创建通过 TCP/IP 通信的客户端/服务器对。由于所有模拟系统都紧密集成在 gem5 中，**多系统模拟的结果仍然是确定性的** （:mdnice-bold-italic[结果可重复，不受随机因素影响]）。

## 五、未来工作

尽管 gem5 是一款功能强大的模拟器，但人们始终希望它能增加更多功能并进行其他改进。目前正在进行或考虑的一些工作包括：

### 一流的功率模型（A first-class power model）

虽然外部功率模型（如 Orion[6]和 McPAT[8]）已在 GEMS 和 M5 中使用，但我们正在为 gem5 开发一个更全面、模块化且集成化的功率模型。

### 全交叉产品的 ISA/CPU/内存系统支持（Full cross-product ISA/CPU/memory system support）

> gem5 的模块化和灵活性使其能够支持指令集架构、CPU 模型和内存系统的多种组合（如图 1 所示），每种组合都可在 SE 或 FS 模式下使用。

![文章插图](/articles/2025-08-11-gem5-m5-gems-c0572214/images/04.webp)

由于每个组件模型必须支持任何指令集架构在任何模式下所需的所有功能的集合，特定组件模型并非在所有可能的情况下都能正常工作。我们将继续努力消除这些不一致性。

### 并行化（Parallelization）

为了解决详细模拟固有的性能限制，并利用多核系统的普及性，我们一直在重构 gem5 的内部事件系统，以支持并行离散事件模拟[11]。

### 检查点导入（Checkpoint import）

尽管 gem5 的简单 CPU 模型比其详细模型快得多，但它们仍然比基于二进制翻译的模拟器（如 QEMU[3]和 SimNow™[2]）慢得多。

我们**不打算在 gem5 中重复开发二进制翻译功能的巨大努力**，而:mdnice-bold-italic[是计划支持从这些模拟器导入状态检查点] （记录模拟器某个时刻状态的数据）。

用户将能够使用这些高性能替代工具将大型工作负载快进到感兴趣的点，然后在 gem5 中从这些点开始模拟。使用诸如 KVM[1]之类的硬件虚拟机环境（而非二进制翻译）可能会实现更高的性能。
