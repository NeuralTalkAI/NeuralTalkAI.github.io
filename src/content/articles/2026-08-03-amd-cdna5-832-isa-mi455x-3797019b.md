## 二、ISA 是什么，为什么"开放 ISA"值得说

> ISA（Instruction Set Architecture，指令集架构）是硬件和软件之间的"合同"：:mdnice-bold-italic[它定义了这颗芯片能执行哪些指令、每条指令怎么编码、有哪些寄存器、内存模型长什么样。编译器作者要靠它生成机器码，驱动开发者要靠它理解硬件行为，做极致性能优化的人（比如手写矩阵乘 kernel 的那批人）要靠它把每一条指令的延迟和吞吐抠到极致。]

对 GPU 来说，ISA 文档的实际意义有三层：

- **调试**：kernel 崩了、结果错了，有 ISA 手册才能对着反汇编一条条查；
- **优化**：想知道为什么某个 kernel 跑不满理论算力，必须知道指令的编码、操作数约束和发射规则；
- **工具链建设**：LLVM、GDB、汇编器、反汇编器、性能分析器，全都建立在公开的 ISA 之上。

AMD 的思路是**把 GPU 当成"另一种指令集的 CPU"来对待**：向 LLVM 上游贡献代码让编译器原生发射 CDNA 指令，向 GDB 贡献支持让开发者用调试 CPU 的方式调试 GPU kernel。白皮书里对此有一句很形象的描述——**对使用 GDB 的程序员来说，CDNA"看起来就是另一种计算资源，只是指令集不同而已"。**

::: block-1
这种 CPU 式的开放思路，是 AMD 在 AI 加速器市场对抗 CUDA 生态壁垒的核心策略之一：:mdnice-highlight[硬件参数可以一页 PPT 讲完，但生态信任是靠 832 页文档、一行行开源代码攒出来的。]
:::

## 三、832 页手册里有什么：CDNA5 ISA 架构详解

> 现在进入正题。这份《CDNA5 Instruction Set Architecture Reference Guide》（2026 年 7 月 27 日版）共 15 章，从术语定义、硬件概览、Wave 状态、指令编码格式，到数百条指令的逐条参考，一应俱全。**下面挑出最能体现 CDNA5 架构特点的几个切面。**

### 3.1 总体结构：WGP 成为新的基本单元

![文章插图](/articles/2026-08-03-amd-cdna5-832-isa-mi455x-3797019b/images/07.jpg)

::: image-caption
图 5：CDNA5 系列处理器框图——主机经 MMIO 与命令处理器交互，计算阵列为多个 WGP（来源：AMD CDNA5 ISA Reference Guide, Figure 1）
:::

手册第一章的框图揭示了 CDNA5 的层次化组织：整颗芯片由命令处理器、超线程分派处理器（Ultra-Threaded Dispatch Processor）和 WGP 计算阵列组成。这里有一个重要的术语变化——**WGP（Work-group Processor，工作组处理器）成为基本计算单元**，它在一些语境下也被称为"双计算单元"（Double Compute Unit）或"CU 对"：:mdnice-bold-italic[一个 WGP 包含 4 个 SIMD32，而一个 CU 是 WGP 的一半（2 个 SIMD32 共享一条访存通路）。]

每个 WGP 内嵌一块既可作 LDS（Local Data Share，本地数据共享）又可作 WGP 缓存的本地存储，两者容量可配置分配；一个 workgroup 最多可以申请 **320KB 的 LDS**，每个 WGP 最多同时驻留 32 个 workgroup、每个 workgroup 最多 1024 个 work-item。

### 3.2 存储与数据通路：L2 + WGP$ + TDM 的三级结构

![文章插图](/articles/2026-08-03-amd-cdna5-832-isa-mi455x-3797019b/images/08.jpg)

::: image-caption
图 6：CDNA5 共享存储层次——L2 读写缓存经 Crossbar 连接各 WGP，每个 WGP 内是 LDS/WGP$ 与两两成对的 SIMD、SALU/VALU、寄存器堆，注意左上角和右上角的 TDM（来源：AMD CDNA5 ISA Reference Guide, Figure 2）
:::

从存储层次图可以看到 CDNA5 的一个标志性设计：**每一对 SIMD 旁边都挂着一个 TDM（Tensor Data Mover，张量数据搬运器）**。L2 是按内存通道划分的读写缓存，通过 Crossbar 向各 WGP 的 WGP$ 供数；而 TDM 负责在外部显存和 LDS 之间搬运大块结构化张量数据。内存模型上，CDNA5 采用宽松一致性（relaxed consistency），写操作和原子操作会收到缓存系统的完成确认（acknowledgment），软件借此实现 fence 来维持顺序。

### 3.3 执行模型：标量 + 向量双通路，全面转向 wave32

CDNA5 延续了 GCN 时代定下的双通路设计：

- **标量 ALU（SALU）** 每个 wave 执行一次，负责控制流和所有 wave 共享的计算（如地址计算）；
- **向量 ALU（VALU）** 为每个 work-item 维护独立的 VGPR，执行真正的并行算术。寄存器也分两类：SGPR（全 wave 共享）和 VGPR（每个 work-item 私有）。

一个值得注意的变化是 wave 宽度：初代 CDNA 白皮书里 wavefront 是 64 个 work-item，而 CDNA5 手册的术语表明确写着 SIMD32——"对 32 个 work-item 并行操作的 SIMD"，像 VOPD 双发射指令更是"仅在 wave32 下合法"。也就是说，CDNA5 在 ISA 层面完成了向 32 车道 wave 的切换，调度粒度更细了。

::: block-1
手册还透露了一个很有"底层味"的细节：由于 **CDNA5 采用激进的指令预取，所有 shader 末尾必须额外填充 64 个 DWORD（256 字节）的数据**，官方建议用 `S_CODE_END` 指令填充——否则预取硬件可能读到未初始化的内存。这种只有读了手册才知道的"坑"，正是 ISA 文档的价值所在。
:::

### 3.4 矩阵指令：从 MFMA 到 WMA，原生覆盖 FP4/FP6/FP8

> 矩阵乘加速是 CDNA 家族的立身之本。

初代 CDNA 引入的是 MFMA（Matrix Fused Multiply-Add）指令族；在 CDNA5 手册里，这套指令以 **WMA（Wave Matrix Multiply-Accumulate）** 的面目出现，语义是标准的 D = A × B + C，矩阵条带化分布在 wave 的所有 lane 上，采用 VOP3P 编码。指令族谱系相当完整：

| 指令 | A 矩阵 | B 矩阵 | C/D 矩阵 |
| --- | --- | --- | --- |
| V_WMA_F32_16X16X4_F32 | 16×4 F32 | 4×16 F32 | 16×16 F32 |
| V_WMA_F32_16X16X32_F16 / BF16 | 16×32 F16/BF16 | 32×16 F16/BF16 | 16×16 F32 |
| V_WMA_F32_16X16X64_FP8/BF8 | 16×64 FP8/BF8 | 64×16 FP8/BF8 | 16×16 F32 |
| V_WMA_F32_16X16X128_FP8/BF8 | 16×128 FP8/BF8 | 128×16 FP8/BF8 | 16×16 F32 |
| V_WMA_SCALE_F32_16X16X128_F8F6F4 | 16×128 FP4/6/8 | 128×16 FP4/6/8 | 16×16 F32 |
| V_WMA_SCALE_F32_32X16X128_F4 | 32×128 FP4 | 128×16 FP4 | 32×16 F32 |
| V*SWMAC* *（稀疏 WMA） | 稀疏 A 矩阵 | 稠密 B 矩阵 | 16×16 累加 |
| V_WMA_I32_16X16X64/128_IU8 | 整型 4/8 bit | 整型 4/8 bit | 16×16 I32 |

*表 1：CDNA5 WMA 指令族代表性成员（根据 AMD CDNA5 ISA Reference Guide 7.12 节 Table 43 整理）*

几个要点：

1. FP8 和 BF8 可以在同一条指令里混用（如 A 用 FP8、B 用 BF8）；
2. 整数 WMA 的 NEG 字段被复用起来标记有符号/无符号；
3. AMD 还在 GitHub 上放了一个开源的 AMD Matrix Instruction Calculator 工具，可以查询每条矩阵指令的吞吐、寄存器占用以及矩阵元素到硬件寄存器的映射关系。

> 数据格式方面，手册术语表给出了完整的低精度浮点定义，全部是 OCP 标准格式：

| 格式 | 位宽 | 符号+指数+尾数 |
| --- | --- | --- |
| FP8 (E4M3) | 8 | 1+4+3 |
| BF8 (E5M2) | 8 | 1+5+2 |
| FP6 (E2M3) | 6 | 1+2+3 |
| BF6 (E3M2) | 6 | 1+3+2 |
| FP4 (E2M1) | 4 | 1+2+1 |

*表 2：CDNA5 原生支持的低精度浮点格式（来源：AMD CDNA5 ISA Reference Guide 1.1 节）*

### 3.5 块缩放：MX 格式的硬件落地

> MI455X 宣传的 20 PF MXFP8、40 PF MXFP4，落到 ISA 里就是 **V_WMA_SCALE 指令族和块缩放（Block Scaling）机制**。

![文章插图](/articles/2026-08-03-amd-cdna5-832-isa-mi455x-3797019b/images/09.jpg)

::: image-caption
图 7：块缩放示意——A、B 矩阵各自携带行/列缩放因子向量（Ax、Bx），点积结果在输出/累加前乘上缩放（来源：AMD CDNA5 ISA Reference Guide 7.12.6 节）
:::

机制本身不复杂但非常实用：A、B 矩阵沿 K 维每 32 个元素（SCALE16 变体为每 16 个）共享一个 8 bit 的缩放因子，缩放因子本身可以是 E8M0（偏置 127）、E5M3 或 E4M3 格式；硬件在点积完成后、写回累加器之前把缩放乘进去。

手册还给出了合法的"A 数据格式 × B 数据格式 × 各自缩放格式"组合表——例如 A 矩阵 FP8+E8M0、B 矩阵 FP6+E8M0 是合法组合。:mdnice-bold-italic[配套的 `V_CVT_SCALE_` / `V_CVT_SCALEF32_` 转换指令负责在 4/6/8 bit 低精度与 F16/BF16/F32 之间带着缩放做转换，量化、反量化全程不需要离开硬件通路。] 这正是 MXFP4 算力能翻倍于 MXFP8 的底层原因：数据更窄、缩放由硬件并行处理，软件几乎零开销。

### 3.6 结构化稀疏与数据搬运：SWMAC 和 TDM

> 稀疏化方面，**SWMAC（Sparse WMA）** 支持 2:4 结构化稀疏——A 矩阵每 4 个元素中有 2 个必须为 0，存储空间减半，指令里附带索引组来指明哪 2 个元素非零，B 矩阵保持稠密。

数据搬运方面，前面提到的 TDM 有专属的张量指令（`TENSOR_LOAD_TO_LDS` / `TENSOR_STORE_FROM_LDS`）：

- 软件先在一组 SGPR 里填好张量 DMA 描述符（D#），描述最多 5 维的张量形状和要搬运的 tile，然后一条指令就能让 TDM 在后台异步搬运整个 tile，与 shader 的其他计算并行；
- 完成状态用 TENSORcnt 计数器跟踪，`S_WAIT_TENSORCNT` 等待。tile 写入 LDS 时还可以按规则加 padding，既方便做矩阵转置，又能避开 LDS bank 冲突。

**这套"描述符 + 异步 DMA + 专用等待指令"的玩法，对标的就是 NVIDIA 的 TMA** （Tensor Memory Accelerator）——现在它有了公开的官方文档 🤣。

### 3.7 协作层级：Workgroup Cluster 与组播加载

CDNA5 在 Grid → Workgroup → Wave → Work-item 的层级之间插入了一层 **Cluster（簇）**：最多 16 个 workgroup 组成一个簇（支持 1D/2D/3D 形状），簇内每个 workgroup 被调度到同一 Shader Engine 的不同 WGP 上，可以通过簇级 split-barrier（signal + arrive）同步，还能用**组播加载（multicast load）** 把同一份数据一次读进多个 WGP 的 LDS——TDM 的簇组播由描述符里的 workgroup_mask 字段控制。

**对大 tile 的 GEMM 来说，这意味着 A、B 矩阵的公共数据只需从显存读一次，_直接省掉成倍的 L2/显存带宽压力** *。线程块簇（thread block cluster）这个概念在 CUDA 里叫 cluster，在 CDNA5 里也叫 cluster，而且细节全部公开。

### 3.8 还有这些值得一提的新东西

- **VOPD 双发射**：一条指令编码两个相互独立的 VALU 操作并行执行，仅 wave32 合法，对 VGPR bank、literal 常量、目的寄存器奇偶性有一整套硬约束（违反则硬件行为未定义，:mdnice-bold-italic[手册原话是"does not function correctly"）——这是给编译器和手写汇编的高手准备的榨取 ILP 的武器；]
- **交叉车道原语**：DPP16/DPP8 数据并行原语和 PERMLANE 系列 lane 置换指令，wave 内洗牌不需要走共享内存；
- **WMA 转置加载**：内存和 LDS 都有带转置的矩阵加载指令（WMA Load-Transpose），配合 TDM 的 padding，转置不再需要专门的 shuffle kernel；
- **ECC 一整章**：手册第 13 章专门讲各类指令在 ECC 下的编程行为与性能影响——数据中心卡的可靠性设计同样是"合同"的一部分。

2020 年的初代 CDNA（MI100）做的是"减法 + 加法"：砍掉所有图形固定功能硬件（光栅化、曲面细分、显示引擎等），把面积和功耗全部投给计算；在 GCN 的标量 + 向量双通路基础上加入矩阵核心引擎（Matrix Core Engine），MFMA 指令支持 INT8/FP16/bf16/FP32 输入、FP32/INT32 累加。

六年时间，矩阵格式从 FP16/bf16 的"混合精度"一路走到 FP4 的"微缩放"；wave 从 64 车道收窄到 32 车道；CU 概念让位给 WGP；数据搬运从"load/store 指令逐条发"进化到"描述符驱动的异步张量 DMA"；协作粒度从 workgroup 扩展到 cluster。

**CDNA 的每一次迭代，ISA 手册都如约而至** ——CDNA5 这份 832 页的文档，已经是这个传统的第五代作品。

## 结语：832 页文档背后的生态账

> 对绝大多数用户来说，ROCm 上跑 PyTorch 永远不需要翻开这份手册。

但一个平台的开放程度，恰恰是由"最底层的那批人"——写编译器的、写推理引擎的、手写 GEMM kernel 的、做性能调优的——能拿到多少信息来定义的。

AMD 把驱动开源、把 ISA 公开、把矩阵指令计算器都做成开源工具，**本质是在向整个开发者社区让渡"知情权"，换取生态的信任和参与**。:mdnice-bold-italic[在 AI 算力竞争进入 FP4 时代、软硬件协同设计越来越深的今天，这 832 页文档的分量，可能比发布会上的任何一页 PPT 都重。]
