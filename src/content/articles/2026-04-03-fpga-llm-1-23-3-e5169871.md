关键词：大语言模型、:mdnice-bold-italic[动态推理]、**FPGA 加速**、混合精度计算、**KV 缓存管理**

> *大语言模型的推理效率问题，本质上是一个关于“公平性”的悖论：模型对每一个词元一视同仁地执行相同的计算，**而现实中，一段文字中的不同词元对语义理解的贡献却天差地别**。正如人类阅读时会自然地跳过“的、了、吗”等虚词而聚焦于实词，:mdnice-bold-italic[大模型理论上也应当学会“聪明地偷懒” ——这正是动态计算分配方法（如 SkipGPT）的核心思想。]*

然而，一个令人尴尬的现实是：算法层面宣称的“计算量减少”在实际硬件上往往难以兑现为等比例的延迟下降。为什么？

::: block-1
**因为动态执行模式与现有硬件架构（尤其是 GPU 和传统 FPGA 加速器）的静态、批处理优化设计之间存在根本性的“阻抗失配”：**

- 非线性操作（Softmax、LayerNorm）和轻量级路由器在 GPU 上引发控制流开销
- 混合精度计算导致 DSP 资源利用率低下
- 而跨层 KV 重用则制造了不规则的内存访问模式

这些挑战共同构成了动态 LLM 推理的硬件“阿克琉斯之踵”。
:::

## 一、问题本质：动态计算分配为何“叫好不叫座”？

### 1.1 SkipGPT：词元级动态计算的优雅框架

> 在深入硬件之前，我们首先需要理解 SkipGPT 这一代表性动态剪枝框架的工作原理。

传统的 Transformer 模型采用“全执行”模式：每个词元在每一层都会依次经过多头注意力（MHA）和前馈网络（FFN）子模块。:mdnice-bold-italic[SkipGPT 的创新在于：在每个子模块前插入一个轻量级路由器（通常是一个线性层，输出维度为 2），动态决定该词元是否执行当前子模块的计算。]

![文章插图](/articles/2026-04-03-fpga-llm-1-23-3-e5169871/images/04.webp)

::: image-caption
图 1(a) SkipGPT模型的框架。展示了SkipGPT的动态层剪枝框架：每个Transformer层的MHA和FFN前各有一个轻量路由模块，决定是否跳过该子模块。
:::

SkipGPT 框架中单个子模块（MHA 或 FFN）的输入输出更新规则公式表达如下：

$$
x_{l+1} = \begin{cases} f_l(x_l) + x_l, & \text{if sampled result is 1} \\ x_l, & \text{otherwise} \end{cases}
$$

其中：

- $l$ 表示 Transformer 层的索引（从 1 到 $L$）。
- $f_l$ 代表第 $l$ 层中的 **一个子模块**，可以是 **多头注意力（MHA）** 或 **前馈网络（FFN）**。每个子模块前都有一个独立的路由器。
- $x_l$ 是第 $l$ 层输入中 **当前词元** 的嵌入向量（维度 $D$）。
- **“sampled result”** 在推理阶段实际为确定性决策：  
路由器先计算 logits $r_l = W_l^T x_l \in \mathbb{R}^2$，然后取 $\arg\max(r_l)$ 得到二元决策 $d \in \{0,1\}$（1 表示执行，0 表示跳过）。训练时则采用 Gumbel-Softmax 采样以保证可微，:mdnice-bold-italic[因为 Gumbel-Softmax 是对离散采样（执行/跳过）的 连续、可微的近似，所以让路由器能在训练中通过梯度下降可学习到合理的动态决策策略。]
- 残差连接 $+ x_l$ 始终存在：即使子模块被跳过，输入信息仍直接传递到输出。

直观理解：重要词元“享受”完整的模型参数服务，而不那么重要的词元则“绕过”部分计算，从而实现计算量的动态分配。

::: block-1
**SkipGPT 的独特优势在于模块解耦**：MHA 和 FFN 可以独立决定是否执行，而非像 Mixture-of-Depth 等方法那样强制绑定。:mdnice-bold-italic[这种细粒度的控制为硬件加速带来了灵活性，但也埋下了挑战的伏笔。]

具体而言：

- **灵活性**：一个词元可以在同一层中执行 MHA 但跳过 FFN，或者相反。这允许模型更精细地分配计算资源给真正重要的运算。
- **挑战**：独立路由导致被跳过子模块的中间结果（如 MHA 的 KV 缓存）无法直接获得。SkipGPT 采用 **跨层 KV 复用** 策略：:mdnice-bold-italic[若当前层跳过 MHA，则从最近执行过 MHA 的层中继承 Key 和 Value 向量]。这虽然保持了注意力语义，却使得解码时的 HBM 访问模式变得高度不规则，成为硬件加速的主要难点之一。
:::

### 1.2 三个“硬骨头”：为什么现有硬件扛不住？

> SkipOPU 作者总结了动态 LLM 推理在硬件加速上面临的三重困境：

![文章插图](/articles/2026-04-03-fpga-llm-1-23-3-e5169871/images/05.webp)

::: image-caption
图 1(b) SkipGPT计算中的挑战以及SkipOPU中对应的解决方案。归纳了三大挑战：非线性操作与路由引入的长延迟、混合精度导致的DSP利用率不足、以及KV缓存的不规则访问。本文的SkipOPU通过三种创新应对：将非线性操作与线性计算融合的数据流、基于过打包的混合精度PE阵列、以及利用KV不变性的片上缓存。该图清晰地传达了设计动机：传统加速器为静态图优化，无法高效处理动态决策带来的控制流和存储碎片。通过将挑战与解决方案一一对应，作者强调了硬件必须与SkipGPT的算法特性共同设计，而非简单部署。
:::

#### 困境一：非线性操作的路由器延迟“放大器”

> **非线性操作（Softmax、LayerNorm/RMSNorm）和 Gumbel-Softmax 路由器有一个共同特点：低算术强度 + 强数据依赖**。这意味着它们无法像矩阵乘法那样通过流水线并行获得高吞吐，反而会成为整个推理管道的“气泡”。

以 RMSNorm 为例，其计算需要先求均值和方差（一次数据遍历），再进行归一化（第二次数据遍历）。传统的实现方式会导致矩阵乘法与归一化之间产生显著的等待延迟。更糟糕的是，路由器引入的 Gumbel 采样进一步增加了控制流开销——GPU 架构对此尤其不擅长。

#### 困境二：混合精度偏好的“资源浪费”

> 量化研究（如 GPTQ、AWQ）表明：**模型权重可以激进地量化到 4-bit 整数而精度损失极小，但激活值通常需要保留 FP16 以保证数值稳定性**。这形成了 FP16×INT4 的混合精度计算模式。

问题在于：:mdnice-bold-italic[FPGA 的 DSP48E2 原生支持 27×18-bit 乘法，执行 FP16×FP16 时已经存在位宽浪费，而处理 INT4 数据时更是“大炮打蚊子”——大量算术资源闲置]。现有 DSP 打包技术（如图 3(a)所示的标准方法）要么受限于操作数位宽约束而不可行，要么无法充分利用 DSP 内置的加法器资源。

![文章插图](/articles/2026-04-03-fpga-llm-1-23-3-e5169871/images/06.webp)

::: image-caption
图 3. 不同DSP打包技术用于FP16尾数乘法的比较。这里对比了三种DSP打包方案：(a) 标准Xilinx方法试图将两个11位尾数乘法打包到一个DSP48E2中，但受操作数宽度约束常不可行；(b) 过打包技术（FlightLLM等）允许中间结果损坏并通过后处理恢复，但DSP内部加法器仍闲置；(c) 本文提出的截断式过打包：截断右操作数LSB和左操作数MSB，利用DSP预加法器反转左操作数符号，使得损坏抵消和截断恢复可通过C端口的单次加法完成。此设计仅需5位辅助乘法，大幅简化恢复逻辑。该技术的核心洞察是：LLM推理中对尾数精度的要求可以适度放松，通过巧妙利用DSP内部数据通路，可在不增加额外逻辑的情况下实现两个FP16乘法并行。实验表明，该方案使PE阵列吞吐翻倍而资源仅微增，是混合精度加速的关键。
:::

#### 困境三：KV 重用导致的“内存访问混沌”

> 动态层剪枝引入了一个微妙的一致性挑战：当第 $l$ 层的某个词元被跳过时，其 Key 和 Value 向量从哪里来？标准做法是重用最近一次执行层（如 $l-1$ 层）的 KV 表示。**这在语义上是合理的（因为被跳过的词元变化不大），但在内存访问模式上却是灾难性的。**

![文章插图](/articles/2026-04-03-fpga-llm-1-23-3-e5169871/images/07.webp)

::: image-caption
图6(a)说明了KV缓存的token级内存映射方案：每个未跳过token的KV条目完整存储在一个HBM端口（伪通道）的连续地址空间内，而非跨端口交错。不同token的KV以轮询方式分布到各端口，使得注意力计算时每个token的KV访问可并发且连续。图6(b)展示了问题：当需要同时加载当前层新生成的KV（如$K_{i+1}^1$）和从上一层复用的KV（如$K_i^0$）时，它们可能映射到同一物理通道（Port #1），而其他通道空闲，造成通道干扰。本文的解决方案是KV不变性缓冲区：将复用的KV缓存到片上URAM，从而HBM只加载当前层的新KV，消除了通道冲突。这种映射方案的关键优势是：每个token的KV访问在端口内是连续突发，最大化AXI总线效率。与传统的交错映射相比，有效带宽从55.8%提升到360GB/s以上。
:::

如图 6(b)所示，在解码阶段计算第 $i+1$ 层的注意力时，需要同时获取：第 $i+1$ 层新生成的 KV（活跃词元）和从第 $i$ 层重用的 KV（跳过词元）。在传统的交叉存取映射下，这些 KV 分散在不同 HBM 通道的不连续地址空间，导致 AXI 突发事务频繁断裂，有效带宽急剧下降。

::: block-1
这就是动态推理硬件加速的“不可能三角”：**算法灵活性、硬件效率和内存带宽难以兼得**。 SkipOPU 的价值正在于找到了打破这个三角的巧妙支点。
:::

## 二、数据流优化：让非线性操作“隐形”

SkipOPU 的第一个核心创新在于数据流层面的重构。其指导思想可以概括为：**将非线性操作的归约阶段与相邻线性计算融合，通过增量计算隐藏延迟。**

### 2.1 路由器与 RMSNorm 的深度融合

> 传统的执行流程如下：

1. 从 HBM 加载激活矩阵 → 计算路由器 logits → 存储 logits
2. 重新加载激活矩阵 → 计算 RMSNorm 的均值/方差 → 存储统计量
3. 再次加载激活矩阵和统计量 → 执行归一化 → 存储归一化结果
4. 加载归一化结果 → 执行 MHA/FFN 的矩阵乘法

**三次大的内存往返，两次全数据遍历。**

SkipOPU 的融合数据流算法（Algorithm 1）彻底改变了这一模式，其实现深度融合路由器和RMSNorm数据流。

```
# 伪代码示意（原论文Algorithm 1）for each tile of activation matrix X_i:    # 单次加载X_i到片上缓存    for k in range(0, D, S):        # 同时进行两件事：        logit += X_k @ W_router    # 线性计算        μ += rowsum(X_k) / D       # 归约统计量        var += rowsum(X_k^2)/D - μ^2    # 路由决策（Straight-Through Gumbel-Softmax）    decision = argmax(logit + Gumbel_noise)    # 只对未跳过的词元执行归一化+后续计算    if decision == 1:        X_norm = (X - μ[decision==1]) / sqrt(var)        # 归一化结果直接流入PE阵列进行矩阵乘法        V_tile = X_norm @ W_V
```

> 该算法描述了如何将路由器的线性计算、RMSNorm的归约和归一化、以及后续子模块（如QKV生成）的矩阵乘法融合在一起。

- **核心步骤：将激活矩阵按行分块（tile），对于每个tile，同时计算路由logit（部分和）和RMSNorm所需的均值与方差（归约）。由于路由决策使用Straight-Through Gumbel-Softmax，决策可在tile级完成后立即确定**。然后，仅对未跳过的token进行归一化，并将归一化后的tile直接送入PE阵列进行矩阵乘法，同时写回片上缓冲覆盖原始值。
- :mdnice-bold-italic[该数据流的关键创新在于：将原本需要两次完整遍历激活矩阵的操作（一次路由+一次RMSNorm归约，再一次归一化+矩阵乘法）压缩为一次tile流式传递，且归约与路由并行。这使得非线性操作的延迟被完全隐藏在矩阵乘法的流水线中]。

对于LLM推理，RMSNorm和路由虽然计算量小但串行依赖强，该融合设计可减少端到端延迟约40%（如文中图8所示）。

::: block-1
更巧妙的是：归一化后的激活值在流出 NPE（非线性处理引擎）的同时被写回片上缓存，原地覆盖（in-place）原始的未归一化数据。这种“就地更新”策略既节省了存储空间，又避免了后续重复加载。
:::

### 2.2 Self-Attention 中的 Softmax 融合

> Self-attention 的融合更为精妙，其核心是借鉴 FlashAttention 的增量 Softmax 更新规则。

![文章插图](/articles/2026-04-03-fpga-llm-1-23-3-e5169871/images/08.webp)

::: image-caption
算法 2. 深度融合的自注意力数据流。该算法展示了自注意力中Softmax与矩阵乘法的融合，借鉴了FlashAttention的增量更新思想。它将Q、K、V分块，外层循环处理多个注意力头（打包以提升空间局部性），内层先计算$QK^T$分块，同时更新每行的最大值m和指数和ℓ。与标准Softmax需要完整存储整个注意力矩阵不同，该算法将中间S分块立即写回DDR，但保留m和ℓ在片上。接着，加载S分块和对应的V分块，执行指数归一化（使用最终m和ℓ）后累加到输出O。这种设计使得多头打包成为可能：原本多头需要独立存储大量中间值，现在由于m/ℓ很小，可以同时处理多个头而不消耗过多片上RAM。对于动态剪枝场景，KV访问不规则使得注意力成为内存瓶颈，该算法通过增加计算密度（多头打包）来缓解内存压力。实验表明，融合数据流使MHA吞吐提升1.4倍（prefill阶段）。此外，算法中未显式处理KV复用，但结合KV不变性缓冲区，可进一步减少HBM读取。
:::

> Algorithm 2 展示了 SkipOPU 如何将 Softmax 的归约阶段与 $QK^T$ 计算重叠：

- 按块计算 $S_{ij} = Q_i K_j^T$（多个注意力头打包以提升空间局部性）
- 对每个块，同时维护每行的最大值 $m$ 和指数和 $\ell$
- 当新块到来时，使用更新规则合并统计量：$m_{new} = \max(m, \tilde{m}), \quad \ell_{new} = e^{m - m_{new}}\ell + e^{\tilde{m} - m_{new}}\tilde{\ell}$
- 完整 $QK^T$ 计算完毕后，Softmax 归一化结果直接流入 $SV$ 计算

::: block-1
这一设计的关键价值：传统实现需要完整物化 $QK^T$ 矩阵（$O(L^2)$ 内存），而 **SkipOPU 通过流式处理将片上存储需求降低至 $O(B_r \times B_c)$（块大小），同时消除了矩阵乘法与 Softmax 之间的流水线停顿。**
:::

## 三、混合精度 PE 阵列：榨干 DSP 的每一分算力

如果说数据流优化解决了“宏观”的调度问题，那么**混合精度处理单元（PE）阵列的设计则是对“微观”计算密度的极致挖掘。**

### 3.1 DSP Overpacking：从“资源闲置”到“空间复用”

> Xilinx DSP48E2 的原生乘法位宽是 27×18-bit。对于 FP16×FP16（有效位宽 11×11），**直接映射会导致超过 60%的乘法器位宽被浪费。DSP 打包（packing）技术试图在一个 DSP 中塞入多个低精度乘法**，但面临两个挑战：

1. 位宽约束：两个 11×11 乘法需要 22×22 的乘积位宽，超出了 DSP 的 18-bit 输入限制
2. 结果污染：直接叠加会导致乘积的高位互相干扰

![文章插图](/articles/2026-04-03-fpga-llm-1-23-3-e5169871/images/09.webp)

::: image-caption
图 3. 不同DSP打包技术用于FP16尾数乘法的比较。这里对比了三种DSP打包方案：(a) 标准Xilinx方法试图将两个11位尾数乘法打包到一个DSP48E2中，但受操作数宽度约束常不可行；(b) 过打包技术（FlightLLM等）允许中间结果损坏并通过后处理恢复，但DSP内部加法器仍闲置；(c) 本文提出的截断式过打包：截断右操作数LSB和左操作数MSB，利用DSP预加法器反转左操作数符号，使得损坏抵消和截断恢复可通过C端口的单次加法完成。此设计仅需5位辅助乘法，大幅简化恢复逻辑。该技术的核心洞察是：LLM推理中对尾数精度的要求可以适度放松，通过巧妙利用DSP内部数据通路，可在不增加额外逻辑的情况下实现两个FP16乘法并行。实验表明，该方案使PE阵列吞吐翻倍而资源仅微增，是混合精度加速的关键。
:::

SkipOPU 提出的截断式 Overpacking（图 3(c)）优雅地解决了这两个问题，其核心技巧为：

- 将右操作数 $u_0$ 的最低有效位（LSB）截断，左操作数 $u_1$ 的最高有效位（MSB）截断
- 截断引入的误差通过 DSP 的 C 端口注入恢复
- 利用预加器反转左操作数符号，使得“消除污染”和“恢复截断”通过单次加法同时完成

::: block-1
结果：**原本一个 DSP 只能执行 1 个 FP16×FP16 乘法，现在可以执行 2 个，而仅需一个 5-bit 的辅助乘法器进行污染恢复**。相比级联的浮点 MAC IP 核，:mdnice-bold-italic[SkipOPU 的 PE 阵列在相同 DSP 数量下节省了 57.2%的 LUT 资源，且计算精度更高（表 1）。]
:::

### 3.2 块浮点累加：化浮点为定点，化繁为简

> Overpacking 带来了更高的乘法密度，但也意味着每个 PE 需要累加更多的部分积。FP16 加法看似简单，实则涉及指数对齐、尾数规格化和舍入等复杂操作，其硬件开销随 PE 阵列规模线性增长。

**SkipOPU 的洞察是：不需要在每个累加步骤都保持完整的浮点精度**。如图 4(b)所示，累加树接收来自 DSP 的未规格化部分积，将其转换为块浮点（BFP）格式——所有尾数共享一个公共指数。在这个统一表示下，累加退化为定点整数加法。

![文章插图](/articles/2026-04-03-fpga-llm-1-23-3-e5169871/images/11.webp)

::: image-caption
图4(a)展示了混合精度PE内部微架构：核心是DSP48E2执行尾数乘法，辅以5位乘法器用于过打包恢复，两个整数加法器生成未归一化指数。通过将浮点转换卸载到累加树，PE本身仅需处理整数操作，极大简化了数据通路。图4(b)展示了带有 BFP-FP转换的FP16累加树：将多个PE输出的部分积先转换为块浮点（BFP）格式——所有尾数共享同一指数，然后使用定点加法累加，最后仅做一次浮点重构。这种设计避免了每个加法都进行指数对齐、归一化和舍入，降低了面积和功耗。论文验证了15位截断尾数足以保持精度（误差<0.07%）。该累加树还可利用DSP内部48位加法器打包两个15位累加路径（IMPL3），进一步减少LUT。这一创新使得在FPGA上实现高吞吐混合精度矩阵乘法成为可能，尤其适合LLM中权重INT4、激活FP16的场景。

## 四、KV 不变性缓冲：化不规则为规则

数据流和计算单元的优化解决了计算效率问题，但动态推理的另一个大头是内存访问。**SkipOPU 的第三个核心创新是利用跨层 KV 的不变性，将随机的 HBM 访问转化为片上高局部性复用。**

### 4.1 核心观察：被跳过词元的 KV“静止”特性

> 一个关键但容易被忽视的事实是：如果一个词元在第 $l$ 层被跳过（即不执行 MHA），其 KV 表示从第 $l$ 层到第 $l+1$ 层保持不变，直到它被重新激活。这是因为：

- 该词元的输出 $x_{l+1} = x_l$（跳过分支）
- 下一层的 KV 生成依赖于 $x_{l+1}$，因此也保持不变

这种“跨层不变性”意味着：**一旦某个词元在第 $l$ 层生成了 KV，在后续若干层（直到它再次被选中执行）中，其 KV 值可以无限次重用而无需重新计算或重新加载。**

### 4.2 词元级内存映射与片上缓冲区

> SkipOPU 的设计利用了这一特性：

1. 词元级内存映射（图 6(a)）：将每个词元的 KV 连续存储在单个 HBM 端口的局部地址空间内，而非跨端口交叉存取。这保证了单个词元的 KV 访问是长突发、高空间局部性的。

![文章插图](/articles/2026-04-03-fpga-llm-1-23-3-e5169871/images/13.webp)

::: image-caption
图 6(a) 说明了KV缓存的token级内存映射方案：每个未跳过token的KV条目完整存储在一个HBM端口（伪通道）的连续地址空间内，而非跨端口交错。不同token的KV以轮询方式分布到各端口，使得注意力计算时每个token的KV访问可并发且连续。图6(b)展示了问题：当需要同时加载当前层新生成的KV（如$K_{i+1}^1$）和从上一层复用的KV（如$K_i^0$）时，它们可能映射到同一物理通道（Port #1），而其他通道空闲，造成通道干扰。本文的解决方案是KV不变性缓冲区：将复用的KV缓存到片上URAM，从而HBM只加载当前层的新KV，消除了通道冲突。这种映射方案的关键优势是：每个token的KV访问在端口内是连续突发，最大化AXI总线效率。与传统的交错映射相比，有效带宽从55.8%提升到360GB/s以上。
:::

1. 片上 KV 不变性缓冲区（图 6(b)）：将“被跳过词元”的 KV 值固定在片上 URAM 中。:mdnice-bold-italic[当这些词元在后续层被其他活跃词元“查询”时，直接从缓冲区提供服务，无需访问 HBM。]
2. 前瞻性更新（图 7）：由于路由决策是逐层确定的，当第 $i$ 层执行时，第 $i+1$ 层的路由 bitmask 已经就绪。控制器可以在后台“预知”哪些 KV 条目需要在下一层重用，并提前将其载入缓冲区。:mdnice-bold-italic[这意味着缓冲区维护不占用关键路径延迟。]

![文章插图](/articles/2026-04-03-fpga-llm-1-23-3-e5169871/images/14.webp)

::: image-caption
图 7 (a) 有效的KV缓存调度。(b) 无效的KV缓存调度。 整体展示了在连续注意力层（case-1）和非连续层（case-2）下的KV缓存访问调度。图中位掩码$BM_i$和$BM_{i+1}$表示16个token在层$i$和$i+1$的路由决策（橙色为活跃，灰色为跳过复用）。在连续层情况下（图a），复用条目（灰色）由KV不变性缓冲区服务，HBM仅处理橙色活跃token。调度宽度受限于缓冲区读端口数（2个）和写端口数（用于预取下一层的更新）。在非连续层情况下（图b），由于前一层跳过了注意力，缓冲区已被逐出，所有KV必须从HBM读取，导致频繁的端口冲突，调度被迫串行化，吞吐下降。该图有力地证明了KV不变性缓冲区的价值：它将无模式的HBM流量转换为确定性的片上访问，尤其在连续注意力层（动态剪枝中的常见模式）中实现了零延迟开销。此外，置换不变性处理（Permutation-Invariant Processing）允许直接使用乱序到达的KV对，无需重排序缓冲，进一步降低资源。
:::

### 5.1 实验设置

- 模型：Llama2-7B，应用 SkipGPT 剪枝（约 25%跳过概率）

- 工作负载：预填充（上下文 128-1024）+ 解码（输出 512-1024 词元），批大小=1

- +KV 重用（不重新计算被跳过词元的 KV）：加速比 1.29×
- +融合数据流：加速比 1.40×

融合数据流的提升来自于消除了 RMSNorm 和 Softmax 引起的“流水线气泡”。

在解码阶段，由于内存带宽成为瓶颈，加速效果有所减弱。**但一个关键观察是：部分跳过与 KV 重用之间的性能差距随上下文长度增加而缩小——这正是通道竞争的信号**。KV 不变性缓冲区的引入正是为了填补这一缺口。

## 六、相关工作：SkipOPU 在学术版图中的位置

### 6.1 FPGA 上的 LLM 加速器

> 早期的 FPGA Transformer 加速器（如 FACT、FET-OPU）假设静态执行图，优化目标集中在密集或静态稀疏矩阵乘法的效率。

近年来的 **FlightLLM、DFX 等工作引入了运行时适应性，但仍局限于注意力机制内的稀疏性**，如头剪枝、词元剪枝，未能捕捉跨层、跨词元的异构重要性。

**SkipOPU 首次在 FPGA 上实现了对词元级和层级动态剪枝的完整支持**，其灵活性来自三个层面：可重配置的 PE 阵列、支持条件执行的 NPE、以及可动态更新的 KV 缓冲系统。

### 6.2 非线性处理引擎（NPE）

> VPE（2024）引入了深度流水线来减少非线性操作的停顿，但其行优先处理模式与 PE 阵列的瓦片流输出不匹配，导致线性-非线性接口处存在不可避免的缓冲延迟。

DESA 和 METAL 采用了部分解耦策略，但要么硬件开销过大，要么功能局限于 BERT-era 操作（GELU、LayerNorm）。

![文章插图](/articles/2026-04-03-fpga-llm-1-23-3-e5169871/images/19.webp)

::: image-caption
图 5. 非线性处理引擎（NPE）的微架构，支持Softmax、RMSNorm、SwiGLU和RoPE等非线性操作。核心是两个共享的归约单元（Reduction Unit），用于在流水线中增量计算最大值、指数和等统计量。对于RMSNorm，归约与路由线性计算并行执行，当路由决策确定后，归一化单元（Norm Unit）直接从片上缓冲读取未跳过token的均值和方差。SwiGLU通过复用指数单元和除法单元实现SILU，再与门控值做Hadamard积。RoPE则通过偶数/奇数索引重排和复数旋转乘法实现。值得注意的是，位掩码（Bitmask）机制控制NPE仅处理活跃token，避免无效计算。这种设计将原本需要多次内存访问的非线性操作转化为与PE阵列流式输出的无缝融合，消除了传统架构中的流水线气泡。NPE的64路并行度与PE阵列的输出宽度匹配，确保整体吞吐平衡。
:::

SkipOPU 的 NPE（图 5）通过统一的瓦片流数据流，将 RoPE、SwiGLU 等现代 LLM 特有的非线性操作无缝集成到执行管线中。其**核心设计原则是“共享归约单元 + 位掩码控制”**：

- RMSNorm 和 Softmax 共享同一套统计量累加硬件
- SwiGLU 和 RoPE 则通过复用指数单元和乘法单元实现

整体额外开销极小。

### 6.3 KV 缓存管理

> vLLM 的 PagedAttention 解决了内存碎片问题，ChatOPU 通过归并溢出/重载操作强化了 AXI 访问规律性。但这些方法都假设 KV 访问模式相对可预测——动态层剪枝恰恰打破了这一假设。

**SkipOPU 的 KV 不变性缓冲可以看作是 PagedAttention 在时间维度上的扩展**：vLLM 在空间上（不同序列间）分页，而 SkipOPU 在时间上（不同层间）复用。二者互补，未来的工作可能探索在动态剪枝场景下同时优化空间和时间局部性。

## 结语与展望

> SkipOPU 是一项**从算法特性到硬件架构的协同设计典范**。其核心启示在于：

1. 数据流优先于计算单元：通过融合非线性操作与线性计算，SkipOPU 在不增加算术单元的情况下实现了 1.4 倍的端到端加速。这提醒我们：**在硬件加速设计中，“何时计算”往往比“如何计算”更重要。**
2. 内存系统是动态推理的命门：:mdnice-bold-italic[KV 不变性缓冲的设计表明，动态剪枝带来的内存访问随机性并非不可克服。通过利用算法层面的不变性（被跳过词元的 KV 静止），可以将不规则访问“规则化”，甚至实现超过物理带宽的等效吞吐。]
3. 混合精度需要体系结构层面的创新：Overpacking + BFP 累加的组合展示了如何从指令集架构（ISA）角度重新思考浮点计算——不追求每个操作的高精度，而是在保证端到端数值稳定性的前提下，最大化硬件利用率。

::: block-1
未来的方向：SkipOPU 目前针对 SkipGPT 框架进行了定制，但其设计原则——融合数据流、混合精度 PE、不变性缓冲——具有更广泛的适用性。可以预见，**随着大模型向更长上下文、更细粒度动态性演进** （如 Mixture-of-Experts、自适应深度），类似的**硬件-算法协同设计将成为常态。**
:::

对于 FPGA 社区而言，SkipOPU 也提供了一个清晰的信号：在 GPU 主导的 LLM 推理市场中，FPGA 凭借其可重构数据流和近存计算能力，在动态、不规则的工作负载上仍具备不可替代的竞争优势。
