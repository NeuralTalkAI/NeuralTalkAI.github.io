> 嵌入向量运算（Embedding Vector Operations），是指将离散实体如用户、商品转换为低维连续向量的运算，是深度学习模型处理非结构化数据的核心步骤。而**嵌入向量运算，是现代深度神经网络（DNN）工作负载的关键组成部分。**

## 一、引言

> 在现代 DNN 工作负载中，嵌入向量运算不仅是关键环节，更是诸多应用的性能瓶颈。现有 NPU 模拟器主要关注矩阵计算，无法捕捉嵌入向量运算所特有的“依赖数据、非确定性”内存行为。:mdnice-bold-italic[与具有确定性分块访问（按固定数据块大小访问矩阵的方式，如将大矩阵拆分为 256×256 的子块进行访问）特性的矩阵运算不同，嵌入向量运算呈现出不规则的内存受限型访问模式（内存访问速度成为性能瓶颈的访问方式），这类模式会显著影响整体性能]。

此外，NPU 采用多种片上内存管理方案，例如：

- 软件预取：通过软件提前将数据加载到高速内存，减少后续访问延迟[1]
- 软件管理缓存：由软件而非硬件控制缓存数据的读写与替换[2]
- 硬件级缓存配置：通过硬件电路设置缓存大小、关联度等参数[3]

而现有模拟器将片上内存视为简单的暂存缓冲区（临时存储数据的中间内存），忽略了上述管理方案的影响。

::: block-1
为实现对各类片上内存与嵌入向量运算的精细化模拟，:mdnice-bold-italic[本文基于两个核心洞察提出新型 NPU 模拟器 EONSim，矩阵运算与嵌入向量运算具有本质不同的行为：]

- 矩阵运算呈现出确定性、分块式访问模式，可通过解析模型（基于数学公式推导的性能计算模型，无需逐周期模拟）有效捕捉；
- 嵌入向量运算则涉及随机性、依赖数据的访问，需通过周期级内存模拟（精确到每个时钟周期的内存操作模拟）才能准确建模。
:::

为同时应对这两大挑战，**EONSim 将矩阵运算的解析模型与嵌入向量运算的细粒度内存模拟引擎相结合**，可对各类 DNN 工作负载进行精准且高效的分析

> :mdnice-bold-italic[EONSim 基于与硬件无关的嵌入索引轨迹运行，通过可配置的架构参数（如内存层次深度、缓存策略、数据布局）将其转换为特定平台的内存地址]。该模拟模型能够真实建模运行时访问行为，并支持单条轨迹在不同硬件配置中的复用。EONSim :mdnice-bold-italic[进一步对向量单元与完整内存层次结构进行建模，支持多种片上内存管理技术]，包括软件预取、基于缓存的管理以及双缓冲。

在 DLRM（深度推荐模型）推理场景下基于 TPUv6e 的验证结果显示，EONSim 具有极高的准确性：执行周期的平均误差为 1.4%，最大误差为 4%；片上本地内存访问次数的平均误差为 2.2%。

基于 EONSim 开展的案例研究表明，**内存行为对嵌入向量运算性能具有显著影响，这凸显了在架构设计中对片上内存进行精准建模的重要性**。EONSim 已在 GitHub 平台开源[1]。

## 二、为何需要 EONSim？

> 为实现比通用中央处理器（CPU）和图形处理器（GPU）更优的性能与能效，众多 NPU 应运而生。为实现高计算吞吐量，NPU 通常采用多核架构。每个 NPU 核心包含用于标量、向量和矩阵运算的专用计算单元，以及一块本地片上内存（核心专属的高速片上内存）。所有 NPU 核心共享一块全局片上内存（多核心共用的片上内存），该内存可提供高带宽数据访问，且延迟远低于片外内存。

尽管 NPU 的主要加速目标是矩阵运算，但现代 DNN 工作负载中，嵌入向量运算正逐渐成为关键组成部分。

- :mdnice-bold-italic[在推荐模型推理中，嵌入向量运算占据了超过 90%的总执行时间] [4]，是执行时间的主要贡献者。
- 此外，**检索增强生成** （RAG，一种结合外部知识库检索与生成模型的技术，可提升生成内容准确性）技术的兴起，:mdnice-bold-italic[也使嵌入向量运算成为大型语言模型（LLM）推理的关键环节]。在 RAG 推理中，:mdnice-bold-italic[检索阶段（根据输入查询从向量数据库中搜索并获取相关文档的过程） 常成为性能瓶颈。]

尽管嵌入向量运算的具体行为存在差异，但其通常包含三个阶段：

::: block-1
1. 根据输入数据确定需访问的嵌入向量；
2. 从内存中读取（检索）这些嵌入向量；
3. 对读取的向量执行逐向量算术运算（如求和、求平均）。
:::

图 1 展示了推荐模型中嵌入包操作（一种对多个嵌入向量进行聚合的操作）的示例：给定批量输入中每个样本的偏移值（用于定位每个样本对应嵌入向量索引起始位置的数值），NPU 先查找对应的嵌入向量索引，再从嵌入表（存储嵌入向量的表格，每行对应一个实体的向量）中读取向量，最后执行求和运算。

> 嵌入向量运算具有与矩阵运算截然不同的计算与内存访问模式。

- 在矩阵运算中，输入矩阵与权重矩阵的静态确定维度（运算前已知的矩阵行数、列数）是影响计算负载与访问模式的主要因素。NPU 会通过矩阵乘法特有的确定性访问模式，访问操作数矩阵的每一行或每一列，且矩阵中每个元素的访问次数完全相同。
- 而在:mdnice-bold-italic[嵌入向量运算中，对于每次推理请求，NPU 仅会基于运行时确定的、依赖输入的索引]，访问总嵌入向量中极小的一部分（例如，不足 0.1%）。

此外，**嵌入向量运算还呈现出高度倾斜的内存访问模式**，也就是说部分向量的访问频率远高于其他向量：在实际推理场景中，受用户行为如偏好热门商品，或内容流行度如热门视频等因素影响，:mdnice-bold-italic[某些实体（如商品、token）的出现频率会显著高于其他实体，这导致 NPU 在处理多个请求时，会频繁访问相同的嵌入向量。]

> 嵌入向量运算的重要性与独特性，要求为 NPU 架构师提供一套精准的模拟工具。然而，现有 NPU 模拟器仅聚焦于矩阵运算，**无法对嵌入向量运算进行全面的模拟分析，主要源于两大挑战：**

- 第一，**现有 NPU 模拟器【无法】建模嵌入向量运算的“依赖输入、非确定性”访问模式**。要建模这类内存访问模式，模拟器需具备一种机制——要么通过接收输入数据识别嵌入向量访问模式，要么直接接收嵌入向量访问轨迹。但:mdnice-bold-italic[现有模拟器仅能为矩阵运算生成确定性访问模式[5]-[8]：] 它们会根据矩阵维度与脉动阵列维度进行分块与调度，进而生成矩阵分块的内存访问序列。:mdnice-bold-italic[该过程完全独立于输入数据，无法用于建模嵌入向量运算的访问模式。]
- 第二，**现有 NPU 模拟器【不支持】对嵌入向量运算所需的多种片上内存管理技术进行全面模拟建模**。为充分利用嵌入向量运算的“依赖输入、倾斜访问”特性，NPU 会采用多种片上内存管理技术，例如软件嵌入缓存、将片上内存配置为缓存[2],[3]。要分析 NPU 在嵌入向量运算中的行为，必须具备整合这类管理技术的精细化片上内存模型。但:mdnice-bold-italic[现有模拟器将片上内存视为矩阵分块的中间缓冲区，仅支持双缓冲机制，无法分析多种片上内存管理技术[5]-[7],[9]。]

上述挑战亟需一种新型模拟框架，以分析嵌入向量运算在 NPU 中执行时对架构的影响——这正是 EONSim 的设计目标。

## 三、EONSim 设计

> 本文提出的 EONSim 是一款可支持 DNN 工作负载中矩阵运算与嵌入向量运算的 NPU 模拟器。
>
> - 对于矩阵运算，EONSim 采用解析模型，利用其确定性、分块式的计算与内存访问特性进行建模；
> - 对于嵌入向量运算，EONSim 通过细粒度周期级建模，捕捉其非确定性、依赖数据的访问行为，突破了现有 NPU 模拟器的模拟范围限制。

在真实 NPU 上收集嵌入向量轨迹（记录嵌入向量访问序列的数据）通常难度较大。:mdnice-bold-italic[EONSim 通过采用“与硬件无关的索引轨迹”解决这一问题：这类轨迹的模式仅依赖于工作负载与输入数据，而非具体硬件架构。在模拟过程中，EONSim 会将这些轨迹转换为特定硬件的地址，支持单条轨迹在不同架构中的复用。]

::: image-caption

图 2 展示了 EONSim 的整体架构，其包含三个部分：输入、模拟与输出。**要实现全面模拟，需增强对内存层次结构的建模，涵盖除矩阵运算专用预取方法之外的多种片上内存管理技术**。为此，EONSim :mdnice-bold-italic[设计了精细化的片上内存层次结构与模块化的片上内存管理策略]，以满足上述需求。

```
【输入部分】- 加速器硬件配置（Accelerator Hardware Config.）：时钟频率、NPU核心数、内存层次结构等- 工作负载配置（Workload Config.）：矩阵运算参数、嵌入向量运算参数、超参数等- 嵌入向量索引轨迹（Access Trace）：记录嵌入向量访问索引的序列【模拟部分】- 请求生成器（Request Generator）：基于输入生成计算与内存请求- NPU核心（NPU Core）：包含向量单元与矩阵单元，执行算术运算- 内存系统（Memory System）：  - 内存地址级轨迹生成（Memory Address-Level Trace）：将索引轨迹转换为地址轨迹  - 内存访问模拟（Memory Access Simulation）：基于内存管理策略区分片上/片外访问  - 片上内存模型（On-Chip Memory Model）：建模片上内存行为，支持多种管理策略  - 基于mNPUsim的内存模型（mNPUsim-Based Memory Model）：模拟片外内存行为- 执行时间模拟（Execution Time Simulation）：  - 矩阵运算解析模型（Analytical Model for Matrix Operations）：计算矩阵运算时间  - 向量/内存操作执行（Memory Operation / Computation）：计算向量与内存操作时间- 能量估算（Energy Estimation）：基于Accelergy工具估算能量消耗【输出部分】- 整体结果（Overall Results）：总执行时间、总内存访问次数、总算术运算次数、能量消耗等- 每批次结果（per-Batch Results）：每批次数据的执行时间、内存访问比例等
```

### 3.1 模拟输入

EONSim 的运行需三类输入数据：

- 加速器硬件配置（Accelerator Hardware Config.）：时钟频率、NPU核心数、内存层次结构等
- 工作负载配置（Workload Config.）：矩阵运算参数、嵌入向量运算参数、超参数等
- 嵌入向量索引轨迹（Access Trace）：记录嵌入向量访问索引的序列

### 3.2 模拟流程

为实现快速且精准的模拟，EONSim 对矩阵运算与嵌入向量运算采用不同的处理方式：

- **矩阵运算**：EONSim 整合了现有研究[5],[9],[10]中的解析性能模型。该模型结合了基于 SCALE-Sim 的计算周期模型（SCALE-Sim 是一款脉动阵列加速器模拟器，此处用于计算矩阵运算的时钟周期数）与内存操作周期解析模型[5],[9]。其中，内存模型通过以下公式计算数据传输时间（$T$）：$T = D / B + L$式中，$D$代表数据量，$B$代表内存带宽，$L$代表内存访问延迟。该公式可有效建模矩阵分块的大数据量传输延迟[9],[10]。
- **嵌入向量运算**：EONSim 通过精细化内存模拟，精准建模其访问模式及对性能的影响。具体流程如下：

::: block-1
在内存访问模拟阶段，模拟器会基于输入的内存访问轨迹与指定的片上内存管理策略，区分片上内存访问与片外内存访问，并生成两类访问的中间轨迹。
:::

:mdnice-bold-italic[EONSim 的内存模型接收这些中间轨迹后，执行精细化内存访问模拟——其中，片外内存模拟采用现有研究[7]中的模型，该模型整合了 NPU 内存控制器与基于 DRAMSim3（一款开源 DRAM 模拟器）的片外内存建模。]

### 3.3 模拟输出

模拟完成后，EONSim 会输出整体结果与每批次结果。两类结果均包含多种指标，如执行时间、片上/片外内存访问比例、各类内存操作与向量操作的次数。此外，EONSim 还集成了基于 Accelergy[11]的能量估算器，可根据硬件配置与操作次数估算能量消耗。

#### 4.1.2 片上内存模型验证

> 尽管当前 NPU 普遍不采用基于缓存的片上内存系统，但未来架构可能会引入这类设计，以提升数据复用效率（减少重复访问同一数据的次数）并降低冗余内存访问。

EONSim 原生支持这类类缓存片上管理方案，可模拟并分析下一代 NPU 的潜在配置。为展示这一能力，**本文评估了“将缓存机制集成到 NPU 内存层次结构”的典型场景，并分析其性能影响。**

在 EONSim 中，本文评估了推荐模型推理过程中不同片上内存管理技术的效果，共包含四种配置：

| 片上内存管理策略 | 策略描述 |
| --- | --- |
| SPM（暂存内存） | 模拟 TPU 中使用的暂存内存（软件显式管理，无缓存功能） |
| LRU（最近最少使用） | 模拟实用化的缓存系统，与 MTIA（Meta 训练和推理加速器）的末级缓存模式类似 |
| SRRIP（静态重引用间隔预测） | 另一类实用化的缓存系统，替换策略优于 LRU |
| Profiling（剖析） | 通过追踪向量访问频率，将访问最频繁的向量固定在片上内存中（不超过内存容量）的策略 |

::: block-1
评估采用 TPUv6e 的硬件配置与 DLRM-RMC2-small 模型，测量执行时间与片上内存访问比例；并通过与 ChampSim[13]（一款开源缓存模拟器，作为缓存行为验证的基准工具）对比，验证 EONSim 片上内存模型的准确性。
:::

- **图 4a 对比了 EONSim 与 ChampSim 的缓存命中次数与缺失次数**。结果显示，在 LRU 与 SRRIP 策略下，:mdnice-bold-italic[两款模拟器的结果完全一致，证明 EONSim 可精准复现缓存级行为。]
- **图 4b 展示了不同片上内存管理技术的性能影响** （以 SPM 的执行时间为基准，计算加速比）。结果显示：在高复用（Reuse High）与中复用（Reuse Mid）数据集上，采用 LRU 与 SRRIP 的缓存系统可实现超过 1.5 倍的加速比；但在低复用（Reuse Low）数据集上，由于热向量（高频访问向量）频繁被淘汰，加速效果有限。:mdnice-bold-italic[具体而言，高复用数据集中仅 4%的向量占据了大部分访问，而低复用数据集中 46%的向量均有访问，导致复用效率大幅降低]。此外，Profiling 策略通过精准识别并保留热向量，实现了最高的加速比。
- **图 4c 展示了对应的片上内存访问比例**。结果显示：SRRIP 策略的访问比例比 LRU 高约 3%，但在低访问倾斜度（数据访问分布均匀）场景下，两者均易受缓存颠簸（cache thrashing，频繁发生缓存缺失的现象）影响。:mdnice-bold-italic[这些发现表明，传统替换策略无法充分利用数据复用局部性（数据访问的局部集中特性），而基于剖析的固定策略可有效缓解缓存颠簸]，并以可接受的开销维持高复用效率。

> 综上，下一代 NPU 可从“**集成硬件缓存架构** ”或“**类缓存片上管理机制** （含剖析或访问感知策略）”中获益。这类硬件支持可实现更具适应性的内存行为，提升嵌入向量工作负载的内存利用率与整体性能。

:mdnice-bold-italic[本文评估表明，EONSim 可在多种 NPU 配置下精准建模性能与内存行为]。除验证外，EONSim :mdnice-bold-italic[还支持通过灵活配置片上管理方案，对架构策略进行精细化分析]。通过结合精准建模与可扩展设计支持，EONSim 成为下一代 NPU 研究的统一、可靠模拟框架。
:::

## 五、结论

> 本文提出 EONSim——一款可精准建模矩阵运算与嵌入向量运算的 NPU 模拟器。:mdnice-bold-italic[EONSim 解决了现有模拟器在“捕捉分层硬件结构下依赖数据、非确定性内存行为”方面的局限性。]

基于 TPUv6e 的验证结果显示：**EONSim 的平均推理时间误差为 1.4%，对片上/片外内存访问次数的平均误差分别为 2.2%与 2.8%。**

这些结果证明，EONSim 可为各类 DNN 工作负载提供高保真的时序（时间行为）与内存模拟。
