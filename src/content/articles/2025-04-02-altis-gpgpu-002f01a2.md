> 本文介绍了 Altis，这是一个**用于现代通用图形处理单元（GPGPU）计算的基准测试套件**。之前的基准测试套件，如 Rodinia 和 SHOC，为研究社区做出了很大贡献，但它们是在多年前开发的，**当时的硬件性能有限，软件支持的功能较少，而且生产环境中硬件加速的工作负载也很稀缺**。自那以后，GPU 的计算密度和内存容量呈指数级增长，可编程性特性（如统一内存、按需分页和 HyperQ）已经成熟，新的工作负载（如深度神经网络（DNNs）、图分析和加密货币）也在生产环境中出现，这些都以之前基准测试未能预见的方式对硬件和软件提出了挑战。

**Altis 从 Rodinia 和 SHOC 中汲取灵感，是一个为现代 GPU 架构和现代 GPU 运行时设计的基准测试套件**，涵盖了多样化的应用领域。通过采用和扩展 Rodinia 和 SHOC 中的应用，增加新的应用，并专注于 CUDA 平台，Altis 更好地代表了现代 GPGPU 工作负载，以支持 GPGPU 在架构和系统软件方面的研究。

## 1. 引言

> 图形处理单元（GPU）已成为许多计算领域的流行硬件加速器。最初主要用于三维渲染，其作为通用图形处理单元（GPGPU）的使用迅速增长。使用 CPU 和 GPU 的异构计算现在已成为许多领域的主导实践，例如机器学习（ML）、图处理、视频分析和加密货币。与此同时，随着高级语言和运行时（如 CUDA）的迅速发展，GPGPU 工作负载的可编程性得到了显著提升。**不幸的是，当前的 GPGPU 基准测试套件没有与硬件、编程框架和运行时或生产工作负载共同进化**，因此它们推动相关研究发现的能力已经变得有限。现有的基准测试套件，如 Rodinia 和 SHOC，旨在帮助研究人员更好地理解异构系统的特性和需求。

这些套件中的应用被精心挑选，以便每个基准测试都能展现出独特的行为，测试重要的 GPU 子系统和组件。这使得架构师能够设计出更好的硬件，并使系统软件开发人员能够提高效率和可编程性。然而，**现有的 GPGPU 基准测试套件没有跟上硬件和编程框架的演变**：一般来说，它们**没有使用或压力测试多代 CUDA 引入的新特性**：例如 HyperQ（允许多个独立 CUDA 内核在同一个 GPU 上并发执行）、动态并行性（Dynamic Parallelism，允许 CUDA 内核在运行时动态地启动子内核，用于处理具有层次结构或递归算法的工作负载）、NVLink（一种高速互连技术，用于连接多个 GPU 或 GPU 与 CPU，提高数据传输效率）、抢占式上下文切换和统一虚拟内存（UVM）。

::: block-1虽然**硬件在提供更多的原始计算能力、内存容量和内存带宽方面取得了巨大进步**，但将基准测试扩展以**适应这种增长的任务要么留给了用户** （例如 Rodinia），**要么被完全忽视了** （SHOC）。
:::

**GPU 已成为训练深度神经网络的首选平台**。像 TensorFlow 和 PyTorch 这样的框架在研究和工业环境中被广泛采用。尽管这些平台可供研究人员使用，但它们并不是为了研究硬件行为或系统软件设计而设计的。它们针对的是生产环境，引入了较大的内存占用，这使得硬件架构师在使用模拟器时难以使用。**深度神经网络（DNNs）已成为推动 GPGPU 技术趋势的最重要领域**，**但 SHOC 和 Rodinia 中的最小神经网络工作负载并不能代表当前最先进的 DNN 模型或算法**。

因此，我们**提出了 Altis，以满足 GPGPU 研究人员在架构和系统方面的新兴需求**。Altis 保留了现有套件中有用的部分，将其**扩展以使用新特性和利用新的硬件能力**。Altis 引入了**新的工作负载和特性支持**，以反映 GPGPU 应用领域的演变。我们将**重点放在 CUDA 上**，与之前的套件不同，之前的套件还支持 OpenCL 或其他框架，因为 CUDA 已成为生产环境中的主导平台，而且生产环境中对高级特性（如按需分页）的支持进展缓慢。

我们做出了以下贡献：

- **展示了现有基准测试套件不再满足研究人员需求** 的领域，特别是在工作负载多样性、问题规模和编程特性方面。
- **展示了 Altis 的改进**，并更全面地**展示了新兴 GPU 的能力**。我们实现了对 CUDA 10.0 支持的新特性的支持。
- **引入了新的基准测试，以表征新兴应用领域**，特别强调通过将常用的 DNN 内核添加到 Altis 来突出**神经网络**。

## 2. 背景与相关工作

### Rodinia

> Rodinia 是一个于 2009 年发布的**面向异构系统应用的基准测试套件**。它包含代表伯克利矮人（Berkeley dwarfs）不同行为的应用程序。**伯克利矮人是 13 种主要的计算类别，据推测它们描述了大多数类型的并行问题**。Rodinia 依赖它，而且包含了一系列多样化的应用程序，这些应用程序既涉及通信也涉及同步。

然而，Rodinia **没有利用像统一内存、HyperQ、协作组和动态并行性这样的新特性**，因为它仍然依赖于 CUDA 4.0。它没有利用在新 CUDA 版本中引入的编程结构或架构支持，这些支持可以显著提高性能：例如，新的硬件能力如半精度和张量核心计算未被使用。

为了分析 Rodinia 如何测试和压力测试 GPU，我们**使用 nvprof 对每个基准测试的性能进行了分析**。该工具报告了衡量组件**相对于峰值的利用率的指标，范围从 0 到 10**：

- 0 表示空闲，
- 10 表示满负荷利用。

许多应用程序**运行多个内核**：对于这些情况，我们**收集所有内核的平均利用率**，并**报告这些平均值的最大值**。**为了表征套件中应用的多样性**，我们**对 nvprof 支持的 69 个顶级指标应用了主成分分析（PCA）**，这些指标对所有基准测试在默认运行配置下的差异贡献最大。

![文章插图](/articles/2025-04-02-altis-gpgpu-002f01a2/images/02.png)

我们的目标是**评估基准测试之间的相似性/差异性，并展示它们如何测试 GPU 的不同组件及其运行时**，结果如下图图 2 所示。前三个主成分代表了总方差的 55%，这占了所有基准测试之间超过一半的多样性。

![文章插图](/articles/2025-04-02-altis-gpgpu-002f01a2/images/03.png)

下图**图 1 中的相关矩阵显示：理想情况下，矩阵的对角线应较深，而其他地方则较浅，这表明应用程序具有不同的行为，并以不同的方式测试系统**。

![文章插图](/articles/2025-04-02-altis-gpgpu-002f01a2/images/04.png)

然而，Rodinia 中有 41%和 70%的应用程序的相关值分别大于 0.8 和 0.6，这表明 **Rodinia 中的大多数应用程序高度相关**，**只有少数例外。** 迫切需要一个改进的套件，其中应用程序更加多样化。

![文章插图](/articles/2025-04-02-altis-gpgpu-002f01a2/images/05.png)

**图 3 显示了 Rodinia 中每个应用程序的 GPU 资源利用率及其标准差**。一个关键的观察结果是：

- 许多组件的利用率较低；
- 即使是那些包含多个内核的应用程序也是如此。
- 此外，许多基准测试（如高斯、霍夫曼、NW 和肌细胞）的平均 GPU 组件利用率，看起来非常相似。
- 许多硬件组件没有被压力测试到最大利用率，限制了对这些组件进行改进的研究。

### SHOC

> SHOC 于 2010 年开发，与 Rodinia 不同，它**将工作负载分为两个主要类别**：**压力/功能** 测试和**性能** 测试。

- **压力测试使用计算密集型内核来识别设备中存在的问题**，如内存不良、散热不足以及其他设备组件问题。
- 性能测试则侧重于合成内核和一些常见的并行算法。SHOC 应用程序在一个框架中运行，该框架接受用户指定的参数（例如迭代次数），并记录诸如每秒浮点运算次数等指标。

**SHOC 中的许多程序都是基本的并行算法**，反映了现代应用程序中实际使用的算法的一个不断缩小的子集。SHOC 涵盖了伯克利矮人，但**没有捕捉到现代应用程序的演变或复杂性**。**与 Rodinia 一样，SHOC 是在软件和硬件特性更为有限的时代编写的**。

![文章插图](/articles/2025-04-02-altis-gpgpu-002f01a2/images/03.png)

图 1 中包含了一个 SHOC 的相关矩阵，显示其整体相关性低于 Rodinia（分别有 12%和 31%的值超过 0.8 和 0.6），但有几个基准测试与其他大多数测试高度相关（例如扫描和神经网络）。

然而，虽然 SHOC 在多样性方面的问题较少，但它显著地低估了现代硬件的性能。**图 3 显示了使用最大预设数据大小时**， SHOC 中每个应用程序的 **GPU 资源利用率及其标准差**。与 Rodinia 不同，**利用率不再表现出固定模式，而是在一个广泛的范围内变化**。

这是因为 SHOC 由**针对特定硬件组件的微型基准测试组成**。重要的是，**大多数组件没有被完全测试到最大容量**。基于上述相同指标的 PCA 结果如下图图 4 所示，这些**指标是使用最小和最大预定义数据大小进行分析** 的。

![文章插图](/articles/2025-04-02-altis-gpgpu-002f01a2/images/06.png)

与 Rodinia 的 PCA 分析（图 2）类似，除了极少数例外，工作负载大多紧密聚集在一起。**紧密的聚集表明工作负载没有以显著不同的方式测试 GPU**。**随着数据大小的增加，工作负载变得更加聚集，表明一个关键技术趋势** （内存容量的增加）使得这些工作负载在捕捉多样化的关键行为方面变得更加无用。这突显了需要更好地覆盖现代和未来 GPGPU 硬件及其应用的基础指标空间的工作负载。

### 其他基准测试

> 最近的基准测试（如 Lonestar、Pannotia 和 LonestarGPU）解决了**不规则并行性的问题，而不是强调整体异构性能**。并非所有新的 CUDA 特性都得到了支持。

- Sarita、Alsop 和 Sinclair 专**注于不同级别的同步（从粗粒度到细粒度）** 的影响，但**没有涉及 GPGPU 软件和硬件演变的趋势**。
- Parboil 提供了一组吞吐量计算应用，用于研究**计算架构的吞吐量和编译器的性能**。
- MAFIA 框架旨在针对**多应用 GPU 执行**。

这些努力受到与 GPGPU 计算研究相似的挑战的激励：缺乏能够实际被测特性的工作负载。不幸的是，MAFIA 由于需要支持模拟器中的运行时实现，因此与旧版本的 CUDA 绑定，这既限制了共同演变，也限制了其捕捉真实系统行为的保真度。

- Chai 解决了许多与 Altis 相同的关注点，并引入了新的基准测试，直到 CUDA 8.0，但更多地关注任务和数据分区，而不是像 DNNs 和关系代数这样的新兴领域。与 Altis 不同，Chai 引入的新编程前端限制了其与 CUDA 演变保持同步的能力。

由于机器学习的流行度迅速增长，对在 GPU 上表征 DNN 行为的关注也显著增加。流行的框架如 TensorFlow 包括用于用户分析其模型计算需求的原始工具。

- Tango 是一个用于研究特定神经网络模型行为的框架。
- MLPerf 是一个用于测量机器学习（ML）软件框架、ML 硬件平台和 ML 云平台性能的基准测试套件。

这些系统可以帮助 GPGPU 研究人员，但由于它们**专注于高层次和端到端行为，因此缺乏对规模的控制以及对系统级和架构级现象的可见性**，使得系统和架构研究人员**难以利用它们进行 GPGPU 研究**。针对这一受众的更好的基准测试套件早已迫在眉睫。

## 3. 动机与目标

### A. 代表新兴的 GPGPU 应用领域

> GPU 被用于许多新的领域，这些领域在 Rodinia 或 SHOC 的工作负载中并未得到体现，例如数据分析、图处理、关系代数和深度神经网络（DNNs）。

虽然 GPU 已成为 DNN 训练的标准，但基准测试套件要么不包含基于神经网络的内核，要么仅包含基于过时技术的最小工作负载。我们的**目标是在保留研究人员研究系统软件** 和**单个内核的低级行为的能力** 的同时，包含**新兴领域**。

### B. 灵活的数据集大小

> 现有基准测试套件的一个关键方面需要显著改进，即**数据集和工作集大小的管理**。SHOC 提供了四种预设的数据大小。这种缺乏灵活性使得 SHOC 很难在未来保持相关性，因为技术的进步最终会使即使最大的数据大小也变得太小，**无法压力测试 GPU 资源**。

**Rodinia** 则相反，其**基准测试没有预设的数据大小**，迫使用户指定问题大小，这使得基于该套件的研究结果难以解释和比较。用户即使不知道适合所测量平台的输入大小，也必须运行数据生成脚本。

**Altis 旨在通过支持更新的默认大小和创建任意数据大小的工具来实现向前兼容**。Altis 支持现代默认大小和灵活的非默认大小的特性，**避免了 SHOC（缺乏灵活性）和 Rodinia（没有数据集大小指导）的缺点**。然而，为未来硬件更新默认值的问题是根本性的。在未来的工作中，我们计划探索提供反馈，以帮助用户根据利用率选择新的默认大小。

### C. 专注于 CUDA 和最近的 CUDA 版本

> GPGPU 编程框架在概念上具有相当的吸引力，但这增加了维护负担和跟上硬件和软件演变所需的工程工作量。由于 CUDA 已成为 GPGPU 的主导框架，我们**将重点放在 CUDA 上，并保持与最近发布的版本的功能一致性**。

除了性能改进外，每个新版本的 CUDA 通常支持新的编程特性，这些特性可以更轻松地编写更高效的代码。包含这些新特性对于理解它们对性能的影响至关重要，特别是因为通常正是这些新特性引起了系统研究人员和架构师的兴趣。

## 4. Altis 基准测试套件

> Altis 可在以下地址获取：https://github.com/utcs-scea/Altis。在Altis中，与SHOC类似，基准测试被分为不同的级别。每个级别代表的基准测试的行为范围从低级特性（如内存带宽）到端到端的实际应用性能。

在确定 Altis 的基准测试时，我们考虑了伯克利矮人（Berkeley dwarfs）和新兴应用领域（如分析和 DNNs）。我们的方法是从 Rodinia 和 SHOC 中选取代表性子集，并增加代表新兴领域的工作负载。

首先，**Altis 整合了一组新的基准测试，这些基准测试代表了在流行 DNN 模型中常用的神经网络层**。DNN 基准测试的加入创建了一个单一的套件，涵盖了现代领域，从而避免了当前研究实践中将 Rodinia、SHOC、Parboil 等套件的测量结果拼凑在一起的做法。**Altis 的 DNN 工作负载使用 CUDA API 进行并行化，并由包括 cuBLAS 和 cuDNN（NVIDIA CUDA 深度神经网络库）在内的库提供支持**。

::: block-1
#### 我们对 Darknet 改造的工作

我们使用 Darknet（一个开源神经网络框架）来构建神经网络。Darknet 使我们能够使用现有的构建块构建实际模型。然而，**Darknet 中的大多数内核并未使用 cuDNN 库，这导致其性能与 TensorFlow 等工业标准相比较差**。因此，**我们重新实现了最常用的内核，并移除了额外的内存操作以减少内存占用**。

与专注于端到端测量的 NN 专用套件（如 MLperf）不同，**Altis 分离了 DNN 模型中的单个层，从而实现了更细粒度的分析。** 至关重要的是，我们认为由于 Altis 使用了 cuDNN 实现，并且从端到端设置中提取了它们，因此它使研究人员能够基于最新代码进行详细分析。Altis 旨在在 Rodinia（预设数据大小）和 SHOC（可定制数据大小）的有利特性之间取得平衡。
:::

### 表征新的数据集

> 对于从 Rodinia 采用的所有基准测试，用户可以使用 Altis 工具提供的随机生成的数据，或者使用 Rodinia 最初提供的数据（随机生成）。**为所有额外的基准测试生成的数据都是随机生成的**。虽然灵活的大小和随机生成意味着 Altis 基准测试不使用“真实世界”数据集，但我们认为这对于我们设想的架构和系统研究来说并不是一个显著的限制。

重要的是，尽管 DNN 在端到端性能上的研究确实需要真实世界的模型和输入以准确反映训练时间收敛性，但对单个内核行为的研究并不敏感于同样的问题。虽然并非所有特性都适用于所有工作负载，但 Altis 在每个工作负载中都支持每个新的 CUDA 特性，只要该特性在该工作负载中有意义。

::: block-1
#### CUDA 特性描述

统一内存和 CUDA 事件支持出现在所有工作负载中。动态并行性和协作组支持显著改变了编程模型，因此需要新的工作负载（如下所述）来测试它们。HyperQ 仅对那些具有可以并发执行而不会影响应用语义的独立内核的工作负载才有意义。**Altis 中的所有基准测试都支持最新的 CUDA 版本（撰写本文时为 10.0）**。新支持的特性如下所述。
:::

- **统一内存（Unified Memory）**：这是一种可编程特性，_支持跨设备和主机的共享地址空间，并支持按需分页以消除显式数据传输代码的需求_。当应用程序访问当前在运行设备上不存在的数据时，硬件会自动将其分页进来。此特性在所有 Altis 工作负载中都得到支持。
- **CUDA 事件（CUDA Events）**：CUDA 事件*允许准确地对函数和内核调用进行计时*。这比之前的套件有了改进，之前的套件仍然使用系统时间，这在异步存在的情况下可能导致测量精度较低。所有 Altis 工作负载都支持 CUDA 事件。
- **HyperQ**：_允许多个独立的 CUDA 内核在资源可用的情况下在同一个 GPU 上并发执行_。HyperQ 使用 32 个独立的工作分发队列来检测并行执行的机会，而旧架构使用单个工作分发队列。我们在所有具有可以独立执行的内核的工作负载（DWT、LavaMD、SRAD）中实现了 HyperQ 支持，并扩展了 Pathfinder，使其具有在不同流中运行独立但重复的相同内核的模式。
- **动态并行性（Dynamic Parallelism）**：允许当前**正在执行的 CUDA 内核调用子 CUDA 内核（嵌套并行性）**。此特性在运行具有层次数据结构和每个层次都有并行性的递归算法时非常有用。之前的套件中没有使用这种编程模式的工作负载；我们添加了 Mandelbrot 工作负载以覆盖此特性。
- **协作组（Cooperative Groups）**：为在 GPU 上运行的*内核线程提供了另一种粒度的同步*。GridSync 允许用户在开始下一阶段的计算之前同步整个网格中的所有线程。这为相对于只暴露__syncthreads()（用于同步单个块中的所有线程）的旧 CUDA 版本提供了更细的同步粒度。与动态并行性类似，有效使用此特性需要显著的代码更改，并且仅在频繁进行数据依赖的内核启动时才有优势。支持此特性的 Altis 工作负载是 SRAD 和 kmeans。
- **CUDA 图（CUDA Graphs）**：这是一种新的 CUDA **作业提交模型**。此特性允许将工作定义为图而不是单个操作。图由一系列操作（如内核启动和内存操作）作为节点组成。这些节点之间的连接指定了相应的依赖关系。**此特性允许通过单个 CPU 操作启动多个 GPU 操作**，从而减少开销。由于整个工作流是可见的，**CUDA 驱动程序还可以执行优化**。

### A. 第 0 级工作负载（Level 0 Workloads）

第 0 级基准测试旨在测量硬件的低级特性。这些基准测试执行的简单任务是测量 GPU 的一个单一能力，因此不代表任何伯克利矮人或应用领域。

- BusSpeedDownload：通过**反复从主机向设备传输各种大小的数据** 来测量 **PCIe 总线的速度**。数据大小从 1kb 到 500kb 不等。
- BusSpeedReadback：与 BusSpeedDownload 类似，但**方向相反**。这里，数据**从设备传输到主机**。
- DeviceMemory：测量设备**内存层次结构中不同组件的带宽**，包括全局内存、常量内存和共享内存。
- MaxFlops：测量设备上**每秒可实现的最大浮点运算次数**。此特性从 SHOC 中采用，扩展了**对半精度浮点运算的支持**。

### B. 第 1 级工作负载（Level 1 Workloads）

第 1 级基准测试包括基本的并行算法，这些算法是**并行计算中的常见任务**，并且通常用于实际应用的内核中。虽然这些应用代表了伯克利矮人的一部分，但它们**足够复杂，可以代表实际的应用领域**。

- GUPS（每秒十亿次更新）：衡量计算机**能够以多高的频率对随机生成的 RAM 位置进行更新**。此测试**很重要**，**因为随机内存性能直接影响应用性能**。此特性从 HPCC（高性能计算挑战）基准测试套件中采用，并扩展以简化对 DRAM 占用空间的调整。
- 广度优先搜索（Breadth First Search）：衡量广度优先搜索的性能，这是一种常见的图遍历算法。此基准测试被包括在内，因为它对**控制流密集型操作具有重要意义**。此特性从 Rodinia 中采用，并扩展以支持现代 CUDA 特性。
- 通用矩阵乘法（General Matrix Multiply）：衡量**不同类型矩阵乘法的性能，包括单精度和双精度测试，以及是否对输入矩阵进行转置**。此特性从 SHOC 中采用，并增加了**对半精度算术、Tensor Core 和新 CUDA 特性** 的支持。
- Pathfinder：执行最短路径算法，用于测试不规则并行性。与大多数传统并行算法不同，不规则算法的线程执行行为各不相同。根据图的连通性，不同线程可能会经历独特的执行行为。此外，Pathfinder 的**控制流单元利用率会比常规并行算法高得多**，因为**每个线程需要独立决定如何执行**。此特性从 Rodinia 中采用，并扩展以支持新 CUDA 特性。
- 排序（Sort）：对整数数组执行快速基数排序。此基准测试最初包含在 SHOC 中。在 Altis 中，工作负载被扩展以简化数据集大小的调整，并支持新的 CUDA 特性。

### C. 第 2 级工作负载（Level 2 Workloads）

第 2 级基准测试是**宏观基准测试**：实际应用内核。这些基准测试是可以在行业中找到的应用，因此代表了**多种 GPU 应用领域**。**这些应用代表了多样化的性能特性**。

- CFD 求解器（CFD Solver）：这是一个计算流体力学基准测试，用于解决三维可压缩流的欧拉方程。此工作负载**通过减少全局内存访问次数和重叠计算来优化有效的 GPU 内存带宽**。此特性从 Rodinia 中采用，并扩展以添加新的 CUDA 特性支持。
- 离散小波变换（GPUDWT）：这是一种图像和视频压缩算法，也是一种流行的数字信号处理技术。此基准测试实现了前向和逆向变换，以及 9/7 和 5/3 变换。9/7 变换使用浮点数，而 5/3 变换使用整数，因此测量两者的性能很重要。此特性从 Rodinia 中采用，并扩展以添加新的 CUDA 特性支持。
- k 均值聚类（KMeans）：这是数据挖掘中常用的聚类算法。该算法展示了**高度的数据并行性**。在开始时，随机选择 k 个中心。在每次迭代中，每个数据点被分配到一个中心，并在每次迭代结束时重新计算每个中心作为其聚类中所有数据点的平均值，直到收敛。此**基准测试提供了 11 种不同的实现**，包括 **CPU 和 GPU 端的聚合**。它被扩展以添加新的 CUDA 特性支持。
- LavaMD：计算 N 体粒子相互作用。代码计算粒子之间的相互作用力以及由于相互作用力导致的粒子重新定位。此工作负载从零开始实现，并提供了 11 种不同的变体，并扩展以添加新的 CUDA 特性支持。
- Mandelbrot：计算 Mandelbrot 分形的图像，这是一种自我重复的几何图案，随着尺寸的减小而循环。常用的算法是逐像素计算的逃逸时间算法。此基准测试被特别添加以**测试动态并行性**。与逃逸时间不同，此过程从粗粒度开始，并且仅在必要时以更细的分辨率迭代某些子区域。
- Needleman-Wunsch：这是一种用于 DNA 序列比对的非线性全局优化方法。潜在的序列对被组织在一个二维矩阵中。在第一步中，算法从左上到右下逐步填充矩阵。最优比对是矩阵中得分最高的路径，其中得分是该单元格处结束的最大加权路径的值。在第二步中，向后追踪最大路径以推导出最优比对。此基准测试从 Rodinia 中采用，并扩展以添加新的 CUDA 特性支持。
- 粒子滤波器（ParticleFilter）：这是在贝叶斯框架下，根据目标位置的噪声测量值统计估计目标位置的一种方法。PF 在从视频监控（如跟踪车辆、细胞和面部）到视频压缩的众多应用中都有应用。此实现针对跟踪细胞进行了优化，特别是白细胞和心肌细胞。此基准测试从 Rodinia 中采用，并扩展以添加新的 CUDA 特性支持。
- SRAD：这是一种用于减少图像中噪声（或斑点）的计算机视觉应用，同时不破坏图像的重要特征。这是通过偏微分方程完成的。由于此应用的每个阶段都对整个图像进行操作，因此 SRAD 需要在每个阶段后进行同步。这使得 SRAD 成为**测试 CUDA 中协作组性能的理想基准测试**。此特性从 Rodinia 中采用，并添加了对协作组的支持。
- Where：这是为 Altis 开发的一个新的关系代数基准测试。GPU 在数据分析中越来越受欢迎，因为关系代数操作可以高效地利用 GPU 并行化。此基准测试实现了一个过滤器，用于返回满足一组条件的输入记录的子集。它首先将每个条目映射到 1 或 0，然后运行前缀和，并使用这两个辅助数据结构将输入数据减少到仅匹配的条目。
- 光线追踪（Raytracing）：光线追踪是一种通过追踪光的路径（以像素形式）来生成图像的渲染技术。它通过模拟其与虚拟对象的相互作用效果来操作。这是 Altis 中的一个新工作负载，实现改编自公开可用的实现。此外，还提供了一个 OptiX 版本，**用于 RT Core 基准测试**。

### D. 深度神经网络内核工作负载（DNN Kernel Workloads）

本节中的所有基准测试代表了在流行 DNN 模型中常见的神经网络层。**本节中的所有层都包括前向和后向传递**。

- 激活层（Activation layer）：用于通过计算加权和并加上偏置来决定神经元是否激活。它引入了输出中的非线性。一些最常用的激活函数包括 ReLU、sigmoid、tanh 和 LeakyReLU。这里我们展示了 ReLU，因为它是最简单的理解方式。ReLU 激活函数可以表示为 $y_i = max{0, x_i}$，其中 $x_i$ 表示输入到神经元的值，$y_i$ 是输出。
- 池化（Pooling）：在 ConvNet 架构中，池化通常用于连续的卷积层之间。其主要功能是减少卷积神经网络的的空间维度。例如，对一个 2×2 矩阵应用一个 2×2 的最大池化核将得到矩阵中的最大值，而相同大小的平均池化核将得到矩阵中值的总和的平均值。为了简化，我们只在报告中包含平均池化层。
- 批量归一化（Batch normalization）：这是一种解决深度神经网络中的协变量偏移的技术。当前面层的参数发生变化时，当前层的输入也会相应变化，导致当前层需要适应新的分布。批量归一化的主要目标是将偏移限制在一定范围内，以加速训练过程并产生可靠的模型。
- 全连接层（Connected layers）：这些层的神经元与下一层的每个神经元相连。全连接层可以被视为一个特征向量，它保存了来自前一层的聚合信息。例如，一个全连接层可以跟在卷积层之后，该卷积层提供了一个低维的不变特征空间。全连接层然后可以学习从该空间到产生更有用或更抽象知识的函数。
- 卷积层（Convolution layer）：主要用于从图像中提取重要特征，通过为图像中的各种对象分配学习权重。例如，给定一个大小为 228 的 RGB 图像（3 个通道），我们可以训练一个大小为 3×3 的卷积核（3 个通道，步长 1），以生成一个大小为 226×226 的输出张量（1 个通道）。输出张量代表图像中的一个特征，例如输入图像中不同部分的曲线存在。
- Dropout：这是一种防止神经网络过拟合的正则化技术。关键思想是在训练期间随机丢弃神经网络中的单元。当在小数据集上训练大型神经网络时，过拟合可能成为一个巨大问题，因为当模型在测试数据集上评估时会出现问题。Dropout 通过随机引入噪声来解决这个问题，以防止单元之间的过度适应，从而使模型更加鲁棒。
- 循环神经网络（RNN）：循环神经网络广泛应用于处理序列数据的学习任务，如语音识别、文本生成等。RNN 通过保持内部状态（记忆）来成功捕捉序列的动态，这些状态跟踪了来自之前时间戳的信息。在我们的基准测试中，我们只展示了 LSTM 的结果，以简化说明。
- Softmax 层：通常被视为神经网络的最后一层，用于执行多类分类。它接受输入（通常是分数值 $z_i, i=1,..,K$），并将其重新计算为概率。因此，该层的输出将代表一个真实的概率分布，其中每个单独输出的总和将等于 1。其计算过程如下：

$$
\sigma(z_c) = \frac{e^{z_c}}{\sum_{k=1}^K e^{z_k}}
$$

- 局部响应归一化（LRN）：旨在模拟一种横向抑制的形式，这种形式受到真实神经元中发现的类型的启发。它允许均匀减小响应值，并在激活图中创建高对比度。此特性特别适用于无界激活函数（如 ReLU）。原始公式如下：

$$
b^i_{x,y} = \frac{a^i_{x,y}}{[k + \alpha \sum_{j=\max(0, i-n/2)}^{\min(N-1, i+n/2)} (a^i_{x,y})^2]^\beta}
$$

其中 $b^i_{x,y}$ 是核 $i$ 在位置 $x,y$ 处的归一化输出，$a^i_{x,y}$ 是核 $i$ 应用于位置 $x,y$ 处的源输出，$N$ 是核的数量，$n$ 是归一化邻域的大小，$\alpha, \beta, k$ 是 LRN 的超参数。

### C. CUDA 特性分析（CUDA Feature Analysis）

> 在本节中，我们分析了一组支持新 CUDA 特性的基准测试，以探索每个特性的影响。

- **统一内存（Unified Memory）**：我们测量了没有统一内存的 BFS 的内核时间加上传输时间，并将其与使用统一内存的内核时间进行比较，**因为统一内存没有显式的传输时间。我们测量了三种不同版本的 BFS 使用统一内存的情况，并与没有新 CUDA 特性的基线版本进行比较**。

如下图 11 所示，只有启用了预取功能的 BFS 统一内存版本比基线版本快。此外，加速并不一致，也没有随着输入大小的增加而扩展。这是因为执行路径高度依赖于生成的图。虽然数据是随机生成的，但**图工作负载中的不规则访问模式对统一内存来说是一个挑战**，因为**隐藏频繁的按需分页延迟取决于预取，而预取并不总是有效的**。

- **HyperQ**：我们**探索了 HyperQ 对 Pathfinder 的影响**。**当多个独立内核可以并发执行时，HyperQ 提高了 SM 利用率**。我们更新的 Pathfinder 在不同的流上运行多个实例。下图的图 12 显示了随着并发内核数量的增加，加速情况。传输时间被省略，因为它是一个常数。随着并行内核数量的增加，HyperQ 的加速增加，并在大约 32 个实例时达到饱和，此时它占用了硬件支持的所有 32 个工作队列。我们看到**从单个实例开始的加速略低于 1x，之后增加到 4x。这是因为随着实例数量的增加，队列占用率增加，但总吞吐量受到可用 SM 的限制**。

![文章插图](/articles/2025-04-02-altis-gpgpu-002f01a2/images/13.png)

- **协作组（Cooperative Groups）**：我们测量并比较了使用协作内核的 SRAD 与原始内核时间，传输时间被省略。协作组的一个**关键问题是 GPU 能够启动的块数量的限制**。使用协作内核的 SRAD 无法在大于 256x256 的图像尺寸上运行。我们通过 16 的倍数变化问题大小。下面图 13 中的数据显示，**该特性在少数情况下提供了最小的性能优势，在其他情况下可能会显著损害性能**。以一种使开发人员能够推理和预测该特性效用的方式支持它，是 Altis 所揭示的研究方向之一。

![文章插图](/articles/2025-04-02-altis-gpgpu-002f01a2/images/14.png)

- **动态并行性（Dynamic Parallelism）**：对于此特性，我们**测量了使用和不使用动态并行性的 Mandelbrot 的内核时间**，传输时间未包括在内。基准测试显示，随着问题尺寸的增加，加速平稳增加。这是由于算法的效率和动态并行性所启用的问题编码的效率。虽然传统的逃逸时间算法被迫为每个像素计算值，但 Mariani-Silver 可以进行子划分，从而忽略图像中越来越多的区域，而无需同步或重新启动多个内核。

![文章插图](/articles/2025-04-02-altis-gpgpu-002f01a2/images/15.png)

- **CUDA 图（CUDA Graphs）**：对于此特性，我们测量了使用和不使用 CUDA 图的粒子滤波器的帧处理时间。帧尺寸设置为 30×30，帧设置为 40。数据传输时间和数据初始化时间未包括在内。下面图 15 中的数据显示，随着点数的增加，加速略有增加。**通过将工作定义为图，所有内核工作描述符都可以预先初始化，并尽可能快速地反复启动，从而减少启动开销**。随着**数据大小的增加，内核启动时间被计算时间所掩盖，因此加速减少**。

![文章插图](/articles/2025-04-02-altis-gpgpu-002f01a2/images/16.png)

## 6. 总结

> 总体而言，**数据表明 Altis 的主要价值在于提供新的工作负载**，这些工作负载在实际利用硬件和测试新特性方面进行了调整。虽然 DRAM 和浮点运算是 GPU 性能的关键，Altis 不会改变这一点，但测试**新特性在有意义的规模上揭示了新的见解**。例如，**某些工作负载的一级瓶颈已经改变**，如前文图 8 和图 5 所示。

通过引入 Altis 来现代化 GPGPU 基准测试套件：

- 改进了现有基准测试的**多样性**，
- 引入了来自**不同领域的新工作** 负载，
- **调整了问题大小** 以更好地**匹配现代硬件**，
- 并增加了对**新 CUDA 特性的支持**。

我们希望 Altis 能够作为**现代 GPGPU 研究的更完整的 GPGPU 基准测试套件**。
