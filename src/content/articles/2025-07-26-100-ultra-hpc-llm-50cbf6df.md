## 关键问题

### 问题 1：QAic 在大模型中能效略低是否与硬件架构相关？其支持超大规模参数模型的核心瓶颈是什么？

从论文内容看，这种性能差异与 QAic 的硬件架构存在一定关联，核心瓶颈可能集中在内存架构与大模型内存需求的适配性上：

- **硬件架构特性**：QAic 采用 4 个 SoC 通过 PCIe switch 互联的多芯片架构，单卡总 SRAM 为 576MB，而 NVIDIA H200 等 GPU 配备 HBM3e 内存（如 H200 有 141GB HBM3e，带宽 4.8TB/s），AMD MI300A 则有 128GB HBM3（带宽 5.3TB/s）。大模型（如 DeepSeek-70B、Llama3.3-70B）参数规模大，对内存容量和带宽需求更高，依赖高吞吐量的内存访问支撑频繁的参数调用和特征交换。
- **可能的瓶颈**：QAic 的 576MB SRAM 对于超大规模模型可能不足，导致需要频繁与外部内存交换数据，增加延迟和功耗；同时，PCIe switch 的互联带宽可能低于 GPU 的 NVLink 或 Infinity Fabric，在分布式计算中限制了跨芯片数据传输效率，进而影响大模型的并行处理性能。这可能解释其在 Granite-20B、DeepSeek-70B 等模型中能效略低的现象。

### 问题 2：硬件-软件适配缺陷是否影响对比公平性？排除后结论是否可能逆转？

硬件-软件适配问题确实在一定程度上影响了对比的完整性，但未从根本上颠覆核心结论：

- **适配缺陷的影响**：NVIDIA GH200 因 vLLM 在 ARM 架构的兼容性问题性能未完全释放，AMD MI300A 部分模型无法运行（图 1 缺失数据），这导致 GPU 阵营的性能未能完全展现，可能低估了其潜力，一定程度上影响了对比的全面性。
- **结论逆转的可能性**：即使排除这些限制，QAic 的核心优势（中小模型能效、单卡吞吐量）仍可能保持。理由是：① QAic 在多数模型（15 个中的 12 个）能效优势显著，尤其中小模型（如 GPT-2-117M 优势 26 tokens/(sec·watt)），而 GH200 主要针对大模型优化，即使性能提升，也难以覆盖所有场景；② AMD MI300A 即使能运行所有模型，其架构（APU 集成 CPU/GPU）更适合特定负载，未必能在能效上全面超越 QAic。因此，整体排序可能在局部调整（如大模型竞争更激烈），但 QAic 的能效优势和适用性结论不会逆转。

### 问题 3：QPC 编译耗时是否抵消能效优势？是否有优化方案？

QPC 编译的预处理开销在高频模型更新场景中可能削弱能效优势，但存在一定优化空间：

- **开销的影响**：QAic 需将模型先转为 ONNX 再编译为 QPC，耗时数小时，而 GPU 可直接部署。在高频更新（如每日迭代）的生产环境中，这种预处理时间会增加部署成本，尤其对于需要快速上线的新模型，可能抵消其运行时的能效收益。
- **潜在优化方案**：论文提到 QPC“compile once, run everywhere”的特性，即一次编译可在多设备部署，这对稳定模型（如长期服务的基础模型）是友好的；此外，Qualcomm 的 Cloud AI SDK 和 Efficient Transformers 库可能在未来支持增量编译（仅重新编译模型更新部分）或预编译模板，减少重复编译耗时。但目前论文未提及具体优化措施，这仍是实际应用中需解决的问题。

## 一、引言

近年来，大语言模型（LLMs）的普及彻底改变了自然语言处理领域，推动了各个领域的创新。随着这些模型在复杂度和规模上的增长，对能够高效运行大语言模型的专用硬件的需求日益加剧，:mdnice-bold-italic[尤其是在数据中心环境中，能效和成本效益至关重要]。为满足这一需求，新型 AI 加速器应运而生，如 Qualcomm Cloud AI 100 Ultra（QAic）[7]、AMD Instinct MI300A 和 NVIDIA GH200，这些加速器在涉及大语言模型的人工智能（AI）工作负载（指需要 AI 处理的任务）中，**在性能和效率方面都有显著提升**。然而，这些加速器并非普遍为包含训练和推理的多任务工作负载而设计。因此，全面评估它们在特定任务上的实际能力，对于评估其实际影响以及对不同大语言模型应用的适用性至关重要。

:mdnice-bold-italic[本研究对部分此类前沿加速器进行了基准测试分析]，评估了它们在运行多种大语言模型以用于推理应用时的**性能、能效和适用性**。我们考虑了**模型大小、参数数量、函数调用和上下文长度等因素**，同时也考虑了它们与 vLLM[6]等**最先进工具的实际兼容性**。

> 在被研究的加速器中，:mdnice-bold-italic[Qualcomm Cloud AI 100 Ultra 是专门为 AI 推理设计 和优化的]。通过对比这些加速器，我们旨在就它们在:mdnice-bold-italic[能耗和吞吐量] 方面的相对优势**提供有价值的见解。**

## 二、实验设置

实验在国家研究平台（NRP）上进行，这是一个分布式、多租户的基于 Kubernetes（一种容器编排系统，用于自动化部署、管理容器化应用）的基础设施，**横跨 75 多个国际站点** [10]。NRP 整合了多种计算资源，以支持先进的人工智能和机器学习工作负载（指需要 AI/机器学习处理的任务）。目前，它:mdnice-bold-italic[为 300 多个研究组和教室提供超过 1400 个 GPU 的支持]，通过用户友好的界面强调灵活性，并利用强大的自动化功能实现简化部署。本研究中使用的所有 GPU（AMD 设备除外）都属于 NRP。

- NVIDIA GH200 GPU 托管在“大平原扩展 GPU 交互实验者网络”（GP-ENGINE）[5]中
- AMD Instinct MI300A 加速处理单元（APU）则是圣地亚哥超级计算机中心 COSMOS 系统的一部分。

本研究使用 NRP Kubernetes 集群中的专用节点，采用 vLLM 作为服务框架，这反映了研究和教育领域中大语言模型（LLMs）的典型实际部署模式。**每个节点都被完全预留，以避免来自其他 pod** （Kubernetes 中的最小部署单元，可包含一个或多个容器）**或 GPU 请求的干扰，且测试 pod 间的 CPU 核心分配保持一致，以最大限度减少处理器相关的差异**。

- 每种硬件类型部署一个 pod，请求所有可用的 GPU 和内存，以消除与 AI 加速器无关的资源竞争[2]。
- 每个 pod 配置 100GB 共享内存用于大语言模型操作。本地存储挂载为模型数据的持久存储，确保高效加载和检索。
- vLLM API 端点被容器化到每个 pod 中，以消除网络瓶颈，确保测量结果反映纯粹的计算性能。

> 我们测试了 **15 个开源大语言模型，其参数范围从 1.17 亿到 900 亿，均来自 Hugging Face** [4]。

### 2.1 Qualcomm Cloud AI 100 Ultra

> Qualcomm Cloud AI 100 Ultra 是一款专为大规模人工智能和语言模型操作设计的专用加速器。

- :mdnice-bold-italic[每张加速卡采用多芯片架构，包含四个片上系统] （SoC，一种将 CPU、GPU 等多个组件集成在单一芯片上的系统）单元，通过 **PCIe 交换机互连**，总共提供 **576MB 的片上 SRAM** （静态随机存取存储器，一种高速但容量较小的内存）和 **64 个专用 AI 处理核心**。
- 单个 SoC 可以作为独立的计算单元分配，也可以组合起来处理更大的工作负载。
- 它**支持卡内和卡间的对等通信** （直接在两个设备之间传输数据，无需通过主机 CPU），这由 QAic Kubernetes 设备插件实现。

![文章插图](/articles/2025-07-26-100-ultra-hpc-llm-50cbf6df/images/06.webp)

在 QAic 卡上运行大语言模型推理是一个复杂的过程，:mdnice-bold-italic[需要先将模型导出为 ONNX 格式]，然后再转换为高通的专有 QPC（Qualcomm Program Container，高通程序容器）格式。这种转换涉及**离线的、硬件特定的优化**。尽管编译过程可能需要数小时，但**生成的 QPC 制品具有可移植性，可以在所有兼容设备上部署**。

由于编译过程与硬件无关，基于云的工作流程是可行的。**一旦生成，QPC 支持“一次编译，到处运行”的方式** [8]。该 SDK（软件开发工具包，用于开发特定硬件或软件的工具集合）:mdnice-bold-italic[自动化了模型检索、ONNX 导出、编译和部署的流程]。它还与 vLLM 的一个分支集成，通过软件全面简化了这一流程[9]。

> NRP 在圣地亚哥超级计算机中心的**一个节点上部署了 8 张 Qualcomm Cloud AI 100 Ultra 卡。**

### 2.2 NVIDIA GPUs

NRP 在全国范围内的多个节点上配备了 V100、RTX A6000、A100 GPU，并且在密苏里州有一个节点配备了单个 GH200 加速器。

::: block-1
- NVIDIA Tesla V100：一款基于 Volta 架构的传统数据中心 GPU。它拥有 5120 个 CUDA 核心（NVIDIA 的并行计算核心）、640 个 Tensor 核心（专为 AI 计算设计的核心），以及高达 32GB 的 HBM2 内存（高带宽内存，速度快于普通内存），内存带宽为 900GB/s，支持用于 AI 任务的混合精度计算（同时使用不同精度的数值进行计算，在保证精度的同时提高效率）。
- NVIDIA RTX A6000：一款基于 Ampere 架构的专业级 GPU，适用于高性能计算（HPC），配备 10752 个 CUDA 核心、336 个 Tensor 核心和 84 个 RT 核心（用于光线追踪的核心）。它拥有 48GB 的 GDDR6 内存（一种高性能图形内存），支持 ECC（错误校验与纠正，用于检测和纠正内存中的数据错误），内存带宽为 768GB/s。
- NVIDIA A100（80GB）：一款 AI 加速器。它配备 6912 个 CUDA 核心、432 个 Tensor 核心，以及高达 80GB 的 HBM2e 内存，内存带宽为 2TB/s。它支持 NVLink（NVIDIA 的高速互连技术，用于连接多个 GPU 以提高性能），可实现高速多 GPU 扩展，为训练和推理任务提供卓越性能。
- NVIDIA GH200：Grace Hopper 超级芯片结合了 Grace CPU 和 Hopper GPU 架构，适用于大规模人工智能和高性能计算应用。它配备 72 核 Arm Neoverse V2 CPU 和一个 Hopper GPU，该 GPU 拥有 132 个 SM（流式多处理器，GPU 的基本计算单元）和 528 个 Tensor 核心，以及 141GB 的 HBM3e 内存，内存带宽为 4.8TB/s。该芯片采用 NVLink-C2C（CPU 与 GPU 之间的高速互连技术）实现 CPU 与 GPU 的集成，内存带宽为 900GB/s，非常适合像大语言模型训练和推理这样的内存密集型任务（需要大量内存来处理数据的任务）。
:::

**只有当 GH200 的性能优于所有其他 GPU 配置（包括并行设置）时，才会将其纳入结果**。然而，需要注意的是，由于 CPU 优化和依赖关系，它在 ARM 架构上与 vLLM 存在兼容性问题，这带来了显著的限制，从而影响了其性能。

### 2.3 AMD Instinct MI300A

> AMD Instinct MI300A[3]是一款为高性能计算和人工智能工作负载设计的加速处理单元（APU，一种将 CPU 和 GPU 集成在同一封装中的处理器）。它在单个封装中集成了 CPU 和 GPU 核心，为数据中心应用提供了独特的解决方案。

- MI300A 采用模块化芯片设计，结合了 24 个 AMD“Zen 4”x86 CPU 核心和 228 个 AMD CDNA 3 高吞吐量 GPU 计算单元，并采用了 3D 堆叠技术。
- 该 APU 由三个包含 CPU 核心的核心复合芯片（CCD）和六个包含 GPU 计算单元的加速复合芯片（XCD）组成，所有这些都通过第四代 AMD Infinity 架构互连。
- MI300A 拥有 128GB 的统一 HBM3 内存（高带宽内存），呈现出一个单一的共享地址空间，可供 CPU 和 GPU 核心访问，理论峰值带宽为 5.3TB/s。

AMD Instinct MI300A 卡不属于 NRP。我们使用的是圣地亚哥超级计算机中心另一台机器上的这些卡。

## 3 评估方法

**为了评估并发 vLLM 请求的性能，我们在每种硬件配置上对每个大语言模型进行了一系列结构化的测试周期**。所有实验都使用了相同的 CPU 核心，除了 GH200 实验使用 ARM 核心外，其余均使用完整核心的 AMD EPYC CPU。

**测试过程包括对多个参数的系统探索**：提示并发级别在四个值（32、64、128 和 256 个同时请求）之间变化，请求数量从 100 个以 100 为步长递增到 500 个。我们密切监控 CPU 使用率，并对线程进行测试，以确保它不会造成 CPU 瓶颈。所有 vLLM 请求都是本地的，不通过网络路由。我们使用 Python 的 ThreadPoolExecutor（线程池执行器，用于管理并发线程的工具）向 vLLM API 分发并发请求，从而高效地处理在多个 CPU 核心上运行的多个线程。**测试跟踪每个请求的延迟和 token 数量**，并内置了重试机制来处理间歇性故障并确保稳健性，这意味着请求失败会自动使结果无效并重新开始测试。

此外，GPU 的数量按固定步长扩展：从 1 个 GPU 开始，然后增加到 2 个、4 个，最后根据模型的性能需求最多增加到 8 个 GPU。这种扩展方法与 QAic SoC 的灵活性形成对比，QAic 的 SoC 可以从 1 个动态扩展到任意数量。为了进一步评估每个大语言模型的能力，我们测试了其架构支持的最大上下文长度（模型能够处理的输入文本的最大长度），以评估其在最大容量下的性能。

> 我们采用**详细的日志记录来捕获全面的性能统计数据**。根据这些数据点，:mdnice-bold-italic[计算出延迟和吞吐量等关键指标的中值]。通过进行变异系数分析（用于衡量数据离散程度的统计量）确保统计稳定性，确认所有报告指标在多次试验中的变异小于 5%。

### 3.1 评估指标

我们测量了三个不同的量，如**每个请求的推理时间**、**吞吐量** （token/秒）以及实验期间**硬件的平均功耗**。:mdnice-bold-italic[为了更全面地评估效率，我们通过将平均吞吐量除以平均功耗来计算能效。]

- 推理时间：从 vLLM 收到提示到返回响应的总时间。
- 吞吐量（token/秒）：每秒生成的 token 速率：$\frac{生成的token数}{推理时间}$其中，生成的 token 数是不包括提示的输出 token。
- 功耗：使用特定于供应商的工具在硬件级别测量。
- 能效：单位功耗的吞吐量：$\frac{token数}{秒·瓦}$其中，吞吐量的单位是 token/秒，功率的单位是瓦。

尽管基于 GPU 的基准测试采用了多卡配置，但**表现最佳的 GPU 组合大多是单张大内存 GPU。正如表 2 所示**，:mdnice-bold-italic[大多数 QAic 的结果来自单卡配置]，这是评估性能和能效的一个关键因素。

- 即便是对于一些较大的模型，如 Llama-3.3-90B-Vision，QAic 使用 6 个片上系统（SoC）就能达到 5961.4token/秒，而 H200 单卡为 3555.6token/秒，能效差异为 6.2token/(秒·瓦)（表 1）。
- 图 1 进一步强化了这一趋势，显示 QAic 在几乎所有模型中都具有更优的能效，尤其是在中等规模架构（如 CodeGemma-2B）中，优势达到 18.49token/(秒·瓦)。

**表 2 突出显示了 QAic 在单卡设置下的吞吐量优势**：对于 TinyLlama-1.1B 模型，QAic 单卡吞吐量达到 7346.6token/秒，远超 H200 的 3669.6token/秒。表 1 也证实了 QAic 的功率效率——在 GPT-2-117M 模型中，QAic 的功耗为 149.9 瓦，远低于 A100 的 415.9 瓦。不过，:mdnice-bold-italic[表 1 中像 Granite-20B（-4token/(秒·瓦)）和 DeepSeek-70B（-1.1token/(秒·瓦)）这样的例外情况表明，在极端规模下存在架构上的权衡]。

> 总体而言，**QAic 的单卡性能和 ≤441.3 瓦的峰值功耗（表 1）使其成为能效敏感型部署的理想选择**，尤其适用于:mdnice-bold-italic[参数小于 320 亿] 的模型。

## 五、结论

我们的分析表明，Qualcomm Cloud AI 100 Ultra 的**架构优势在功率受限环境中最为显著**。

尽管 GPU 在内存密集型任务（如视觉-语言建模（同时处理图像和文本的任务）和代码生成）中仍保持优势，但:mdnice-bold-italic[在能效比峰值吞吐量更重要的可持续 AI 部署场景中，QAic 成为了极具吸引力的解决方案。]

这些发现**凸显了专用加速器在平衡大规模生成式 AI 系统** （能生成文本、图像等新内容的 AI 系统）的**性能和功耗方面日益重要的作用**。
