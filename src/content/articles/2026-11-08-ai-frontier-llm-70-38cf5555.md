关键词：**代码混淆**、:mdnice-bold-italic[大模型安全]、遗传算法、**逆向工程**、**代码保护**

> 用大模型分析代码已经很常见。开发者让它解释陌生项目、检查漏洞、生成测试，逆向人员也可以把反编译得到的代码交给模型，快速判断程序功能、寻找核心算法。**但代码所有者未必都希望分析变得容易**。

商业软件厂商可能担心核心算法被竞争对手还原，游戏厂商可能不希望反作弊逻辑被快速定位，授权校验等敏感代码也常需要提高分析门槛。网站防御也有类似需求。攻击者可能让大模型阅读公开的前端 JavaScript，寻找接口、参数和校验逻辑；服务器端源码泄露后，也可能被用同样方式分析。**在这类代码中加入干扰内容，可以增加模型辅助分析的难度。不过，它无法阻止攻击者直接请求登录接口或爆破密码。**

::: block-1
传统代码混淆主要增加人的阅读成本。变量名被替换，控制流被拆散，字符串被编码，但大模型仍能结合上下文恢复程序意图。:mdnice-highlight[华中科技大学团队提出的 Acoda 换了一个入手点：利用大模型的安全对齐和 Token 处理机制，让模型拒绝分析、误解逻辑，或者中途停止输出。]
:::

## 一、大模型分析代码时，哪两个环节容易被干扰

> Acoda 要做的事情是让程序照常运行的前提下，同时让大模型在分析代码时拒答、误判或中断输出。

传统混淆也能让程序照常运行，但大模型仍可能根据上下文猜出程序意图。**作者于是从大模型的工作方式入手，找到两个可以利用的环节：回答前的安全检查，以及生成回答时对结束标记的处理。**

- 大模型在训练中会加入安全限制，遇到恶意软件、武器或其他危险内容时，可能拒绝回答，这就是论文所说的“安全对齐”。:mdnice-bold-italic[Acoda 在正常代码里加入带危险含义的变量名，或者写上“此处存在后门”的警告注释。即使相关代码放在永远不会执行的分支里，模型也可能先把整段代码判为高风险，拒绝继续分析。]
- 第二个环节与 Token 有关。大模型读文字时，会先把内容切成一个个小片段，这些片段叫 Token。其中一些特殊 Token 负责表示输入或输出结束，例如 DeepSeek-Coder 使用的 EOT。**作者把这类结束标记放进不影响运行的变量，模型在复述或改写代码时可能提前停止，也可能返回无关内容。** 程序本身没有变化，模型的回答却被打断了。

这两个环节分别卡住分析的开头和结尾。如果模型没有拒答，也没有中途停止，误导性注释和特殊代码结构还会继续干扰它对程序逻辑的判断。

::: block-1
:mdnice-highlight[Acoda 利用的是模型处理代码的方式：程序的功能和运行结果不变，模型的分析与回答过程受到干扰。]
:::

## 二、八种方法怎样让大模型拒答、误判或中断回答

### 2.1 加入危险信号，让模型拒绝分析代码

> 八种方法按照大模型分析代码的过程分成三层，分别争取拒答、误判和输出中断。

分析前阶段包含欺骗性警告注释、变量重命名、函数重命名和漏洞代码注入。前两者的做法很直接：把普通名字替换成带有危险含义的词。漏洞注入则把命令注入、SQL 注入等片段放进条件永远为假的分支，再添加安全警告。人检查执行条件后可以确认它不会运行，模型却可能先对危险内容作出反应。

![文章插图](/articles/2026-11-08-ai-frontier-llm-70-38cf5555/images/05.webp)

::: image-caption
表 1：八种混淆方法及防御作用阶段。这些方法按大语言模型的推理流程划分为推理前、推理中、推理后三个防御阶段，同时标注了各方法的实现类型。推理前阶段聚焦触发安全对齐机制，通过欺骗性注释、标识符重命名、漏洞注入诱导模型直接拒绝分析；推理中阶段通过语义误导、控制流复杂化干扰模型的逻辑理解；推理后阶段通过特殊令牌破坏输出的完整性。其中仅误导性摘要需借助大语言模型生成混淆内容，其余均为规则化实现，兼顾了通用性与执行效率。该分类体系针对大语言模型通用的安全对齐与令牌处理机制设计，保障了混淆方法的跨模型迁移潜力，为后续遗传算法的优化空间提供了基础元素。
:::

### 2.2 添加误导信息，让模型理解错程序功能

分析中阶段负责让模型“读懂一个错误版本”。误导性摘要把与真实功能相反或无关的描述放进注释。字符串混淆把危险词编码，运行时再解码。Try–Except 包装把真正有用的语句放入异常处理分支，让模型误判程序实际会走哪条路径。

### 2.3 插入结束标记，让模型提前停止回答

输出前阶段插入 EOS 等结束标记。EOS 是 End of Sequence 的缩写，表示一段文本结束。三个阶段可以叠加：

- 警告注释先争取拒答；
- 模型继续分析时，误导结构再干扰判断；
- 模型开始生成答案后，结束标记仍可能截断输出。

### 2.4 修改代码后，如何确认程序仍能正常运行

**这里有一条重要约束：每次修改都要通过原有测试用例，确认程序功能不变。** 这样，模型返回错误代码可以归因于分析失败，而不是原程序已经被改坏。

::: block-1
八种方法构成一条连续防线。功能验证也很关键，它分别检查程序能否正常运行，以及模型能否正确还原代码。
:::

## 三、怎样自动找出效果较好的方法搭配

### 3.1 尝试不同方法搭配，保留效果好的方案

> 单种方法的效果随模型和代码变化，人工逐个尝试组合很费时间，Acoda 把这项工作交给自动搜索。

遗传算法借鉴了生物进化的筛选过程。每份待测试的代码带有一组“基因”，这里指按顺序执行的代码处理方法。:mdnice-bold-italic[第一轮分别测试八种方法，再让 DS-Coder 6.7B、CodeLlama 7B 和 CodeGemma 7B 还原代码。系统汇总三份结果并计算干扰得分，保留效果较好的组合，继续添加方法。默认搜索两轮，] 最终每份代码包含三种处理方法。

### 3.2 从语法、功能、结构和相似度四个方面打分

> 评分包括四项：语法分数检查代码能否解析；功能分数运行测试用例；结构分数比较还原前后的分支和路径；相似度分数使用 CodeBLEU 比较返回代码与原始代码。总分为：

$$
AdvS=\frac{\mu(SyS+SeS)+\sigma(CcS+SiS)}{2},\quad \mu+\sigma=1
$$

$AdvS$ 是干扰得分，$SyS$ 和 $SeS$ 表示语法和功能上的失败程度，$CcS$ 和 $SiS$ 对应结构复杂度和代码相似度。实验设置 $\mu=0.7$、$\sigma=0.3$：模型答错或拒答占 70%，结构和相似度占 30%。**因此，系统会优先保留让模型分析失败的组合。** 分数越高，模型越难正确还原。

**论文选择每轮得分前 15%的组合继续搜索。**

::: block-1
总得来说，遗传算法本身较简单，评分流程更关键。模型回答被转成可以比较的分数，系统才知道应该保留哪些方法组合。
:::

## 四、实验结果：方法有效，但不同模型差异很大

### 4.1 Acoda 调试时使用的三个模型：成功率最高 98%

> 一组实验检查遗传算法能否找到更好的组合，另一组检查这些组合面对陌生模型时是否仍然有效。

第一组实验在参与组合搜索的三个模型上比较随机组合与遗传算法。DS-Coder 上，随机组合的拒答率为 26%，遗传算法升至 70%；CodeLlama 从 21%升至 84%，**两者的 ASR 分别达到 95%和 98%。** CodeGemma 没有出现拒答，遗传组合的 ASR 为 50%，低于随机组合的 62%。可见，偏向触发拒答的组合遇到安全限制较宽松的模型时，效果可能下降。

![文章插图](/articles/2026-11-08-ai-frontier-llm-70-38cf5555/images/06.webp)

::: image-caption
表 3：随机组合与遗传算法的效果对比。Rand 表示随机选择，Gene 表示遗传搜索。该表格对比了随机选择混淆方法与遗传算法优化两种策略在 3 个目标模型上的拒绝率、测试失败率与总攻击成功率。结果显示遗传算法大幅提升了 DS-Coder 与 CodeLlama 的拒绝率与总攻击成功率，最高可达 98%，验证了进化优化对混淆组合的提升效果；而 CodeGemma 因安全对齐机制较弱，两种策略下拒绝率均为 0，总攻击成功率略低于随机策略。该结果一方面证实了遗传算法能够更高效地组合混淆方法、提升对抗强度，另一方面也说明混淆效果高度依赖目标模型的安全对齐强度。
:::

### 4.2 换成调试时没用过的七个模型：成功率最高 70%

**第二组实验把选好的组合用于另外七个模型，最高 ASR 约 70%。** 整体看，小模型更容易受干扰。DS-R1 可以删除不会执行的分支及其中的 SQL 注入代码，恢复真实初始化逻辑。GPT-4o 拒答率较高，则说明安全策略同样影响结果。

Qwen2.5-Coder 经常原样返回处理后的代码。这些代码仍能通过测试，所以测试失败率和 ASR 反而下降。模型没有完成代码还原，不一定会得到高 ASR。

### 4.3 运行时间和内存几乎不变，代码长度约翻倍

> 处理后与原始程序的运行时间比为 0.99，内存比为 1.00，代码长度比为 2.10。多数新增逻辑不会执行，代价主要体现为代码体积和维护难度。

![文章插图](/articles/2026-11-08-ai-frontier-llm-70-38cf5555/images/07.webp)

::: image-caption
表 5：混淆处理后与原始程序的平均开销比值。该表格从运行时间、内存占用、代码长度三个维度统计了混淆带来的相对开销。结果显示运行时开销几乎为 0，内存占用无增长，仅代码长度平均提升至原来的 2.1 倍。极低的运行时开销源于绝大多数混淆方法都将额外逻辑放入永假分支或异常分支，实际执行时不会运行；仅字符串混淆引入少量 base64 解码计算，影响可忽略。代码长度的增长主要来自额外注释与死代码，并未提升核心逻辑的复杂度。同时所有混淆代码均通过全部测试用例，验证了语义保持的特性，证明该方案在实际部署中不会影响程序的性能与功能。

高 ASR 证明这套方法能干扰当前模型，尚未证明它能长期防住针对性逆向。模型能力、安全策略和评分方法都会改变结果。

## 五、开源代码怎样实现，复现时要注意什么

> 仓库没有新增实验图表，README 重复了论文核心数据，更多实现信息需要直接阅读代码。

### 5.1 新组合的生成方式与论文描述不一致

不过，新组合的生成方式与论文文字存在差异。论文要求在已有组合的基础上继续添加方法；当前 generate_children_from_parent_genes 函数却从原始代码出发，只应用新增方法，随后又把记录写成“原有组合＋新增方法”。**这样，日志记录的方法组合可能与实际代码不一致。** 复现实验前应先确认这一点，否则两轮搜索未必能得到论文所说的三种方法叠加。

**仓库没有提供原始实验结果。** 要独立验证 95%、98%和 70%，还需固定数据样本、模型版本、提示词与随机种子重新实验。

::: block-1
代码已经给出可运行框架，实验复现仍需处理新组合的生成差异，并补齐原始结果与版本信息。
:::

## 六、这种方法能防住什么，又防不住什么

> Acoda 把代码保护扩展到了模型行为层，但效果依附于当前模型的机制。

分析者可以先删除注释、重命名危险标识符、剥离特殊 Token，再把清洗后的代码交给模型。专门针对代码还原训练的模型也可能绕过干扰。安全限制较宽松的模型不容易拒答，能力较强的模型更容易识别不会执行的分支。

工程使用还有副作用。危险词和漏洞片段可能触发静态扫描、杀毒软件或审计流程，无意义注释和异常结构会增加维护成本。**人工阅读代码、运行程序观察行为，仍然可以绕过这类防护。**

如果团队准备采用，应只处理核心算法，保留清晰源码与修改记录，并在模型升级后重新测试。**Acoda 更适合作为低成本分析的一道外层障碍，后续还需在更多真实项目和模型版本上验证。**

::: block-1
Acoda 的贡献在于建立“处理代码—模型分析—定量评分—筛选组合”的完整流程。它提高了自动分析的成本，也清楚暴露了这种方法随模型演化而失效的边界。
