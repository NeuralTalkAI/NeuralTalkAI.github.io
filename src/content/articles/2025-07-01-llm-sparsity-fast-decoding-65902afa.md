> 本文从硬件视角探讨大型语言模型（LLM）推理加速下的两个方法：稀疏性、快速解码。

- **稀疏性通过权重、激活和注意力稀疏优化**，结构化稀疏（如块稀疏、N:M 稀疏）更利于硬件加速，不同硬件对稀疏性支持各异；
- **快速解码包括推测解码和层跳过**，GPU 在推测解码中表现突出；操作符优化通过融合、非线性函数近似等提升效率，ASIC 和 PIM/NDP 在能效和吞吐量上有显著优势，各硬件平台在功耗、速度和能效上呈现不同特点。

下面是三个关键问题：

## 1. 哪种硬件平台在 LLM 推理中能效最优？

答案：ASIC 和 PIM/NDP 能效最优。ASIC 能效可达 8.49 tokens/J 以上，如 SoLA 在 ASIC 上实现 9.5× 于 A100 的推理速度；PIM/NDP 如 SpecPIM 实现 17.499W 低功耗，能效达 9.944 tokens/J，显著优于 GPU（0.434 tokens/J）和 CPU（0.158 tokens/J）。

## 2. 稀疏性优化中结构化稀疏比随机稀疏有何优势？

答案：结构化稀疏（如 N:M、通道稀疏）与硬件架构更匹配，可提升计算效率。例如 NVIDIA 2:4 稀疏 Tensor Core 实现 1.54×-1.79× 矩阵乘法加速，而随机稀疏虽精度高但计算速度较低，且硬件利用率不足，如 FPGA 对非结构化稀疏支持较差，更适合结构化稀疏模式。

## 3. 快速解码技术如何提升 LLM 推理速度？

答案：快速解码通过推测解码和层跳过减少计算量。推测解码用小模型预生成候选，主模型验证，如 EAGLE 在 A100 上使 Llama2-13B 达 132.31 tokens/s，较传统方法提升 2×；层跳过动态跳过非关键层，如 AdaInfer 在 V100 上跳过部分层后，Llama2-7B 推理速度达 25.2 tokens/s，减少无效计算。

## 3.2 稀疏性（Sparsity）

### 3.2.1 概述

> 稀疏性通过减少非零元素的数量并跳过与零的乘加运算来提升计算和存储效率。

由于标准基于 Transformer 的大型模型中存在注意力计算，稀疏化方法不仅包括**权重稀疏** 和**激活稀疏**，还包括**注意力稀疏**。

- **权重稀疏主要通过剪枝方法实现**，包括全局剪枝、逐层剪枝和结构化剪枝，这些方法通过减少权重矩阵的规模并利用稀疏矩阵库进行优化。
- **激活稀疏侧重于通过激活剪枝（如阈值剪枝）和动态稀疏等技术减少激活值的计算**，硬件优化则利用稀疏数据结构来提高效率。
- **注意力稀疏针对自注意力机制中的计算优化**，采用局部注意力、分块注意力和稀疏注意力矩阵等方法，通过限制计算范围或使用稀疏矩阵存储来降低计算负载。

这些稀疏策略有助于提高模型推理效率，尤其是在处理大规模数据和复杂任务时。

![文章插图](/articles/2025-07-01-llm-sparsity-fast-decoding-65902afa/images/04.webp)

**稀疏模式可分为如图 5 所示的随机稀疏和结构化稀疏**。

- **随机模式** 涉及矩阵内零元素的随机分布，可实现更高的精度，但计算速度可能较低。
- **结构化模式** 对稀疏性应用特定模式，通过与硬件优化对齐来提高计算效率。

在**结构化稀疏** 中，常见模式**包括分块稀疏、N:M 稀疏、通道稀疏以及某些结构化模式的组合**。这些结构化模式提供了可预测的优化计算优势。

- **分块稀疏** 涉及将权重矩阵划分为较小的块，并在每个块内应用稀疏性；
- **N:M 稀疏** 在每 N 个元素中保留 M 个非零元素，通过硬件加速提高效率；NVIDIA 的 2:4 稀疏 Tensor Core 是 N:M 稀疏的代表性硬件单元，能够实现高达 2 倍的计算加速；
- **通道稀疏** 旨在裁剪矩阵中的整个通道，显著减少计算和存储需求。

### 3.2.2 CPU

#### CPU 激活稀疏

激活稀疏由激活函数决定。

- LLMs 中常用的 SwiGLU[290]和 GeGLU[291]表现出有限的稀疏性，但简单地将这些函数替换为 ReLU 无法实现足够的稀疏性。
- **Turbo Sparse[171]提出 dReLU 激活函数以提高 LLM 激活稀疏性**，并采用高质量训练数据混合比例来促进有效稀疏性。通过将其稀疏方法应用于 Mistral 和 Mixtral 模型，每次推理迭代中仅激活 25 亿（35.7%）和 43 亿（9.2%）参数。对于 Mistral-7B，Turbo Sparse 在 Intel i9-14900HX 处理器和 Intel i7-12700K 处理器上分别实现 8.71 tokens/s 和 9.94 tokens/s 的推理速度。对于采用 4-bit 量化的 Mixtral-47B，Turbo Sparse 在 Intel i9-14900HX、Intel i7-12700K 和 SnapDragon 8 Gen3 上分别实现 16.1 tokens/s、11.98 tokens/s 和 11.1 tokens/s 的推理速度。
- **ProSparse[172]还引入激活函数替换、渐进式稀疏正则化和激活阈值偏移，以帮助非 ReLU 的 LLMs 在不降低性能的情况下获得高激活稀疏性**。对于 Llama2-7B 和 Llama2-13B，ProSparse 实现了 89.32%和 88.80%的高稀疏性，推理速度分别为 16.3 tokens/s 和 8.67 tokens/s（基于 PowerInfer[259]框架）。

#### CPU 权重稀疏

**SparAMX[173]利用最新 Intel CPU 上的高级矩阵扩展（AMX）支持，在线性层中采用非结构化稀疏**，与 PyTorch 实现相比，端到端延迟降低 1.42 倍。它还提供了一组开源定制稀疏内核，以支持所有线性层。

### 3.2.3 GPU

#### GPU 激活稀疏

- **SoLA[192]利用软激活稀疏和低秩分解**。SoLA 可根据 LLMs 的前馈网络（FFNs）中的激活模式，识别并保留对推理有显著贡献的少数分量，同时通过低秩分解压缩大部分分量。对于 Llama2-7B 和 13B 模型，其在 RTX 4090 GPU 上分别实现 76.69 tokens/s 和 55.96 tokens/s 的推理速度。
- **R-Sparse[193]发现 FFNs 的两个关键观察结果**：

1. **输入的非稀疏分量可视为少数偏置项**；
2. **完全计算可通过输入通道和权重奇异值的适当组合有效近似。**

因此，它采用基于秩感知的稀疏推理方法替换 LLMs 中的线性层，利用输入通道和奇异值分量的稀疏性。对于 Llama2-7B 和 Llama3-8B 模型，其在 NVIDIA A6000 GPU 上分别实现约 20 tokens/s 和 18 tokens/s 的推理速度。

#### GPU 权重稀疏

**LLM-pruner[174]采用基于梯度信息的结构化剪枝，有选择地移除非关键耦合结构**，最大限度地保留 LLM 的大部分功能。为此，剪枝模型的性能可通过微调技术（如 LoRA）在仅 3 小时内、仅需 50K 数据的情况下有效恢复。我们在 Llama、Vicuna 和 ChatGLM 三种 LLMs 上验证了 LLM-Pruner，结果表明压缩后的模型在零样本分类和生成任务中仍表现出令人满意的能力。

> LLMs 可在单次剪枝中至少实现 50%的稀疏性，无需任何再训练，且精度损失最小。

- **SparseGPT[175]在迭代剪枝过程中需要复杂的权重更新程序**。
- **Wanda[176]基于每个输出，对幅度最小的权重乘以相应的输入激活进行剪枝**。值得注意的是，Wanda **无需再训练或权重更新，剪枝过程更快**。

除了非结构化模式，这两种方法还可推广到半结构化 N:M（2:4 和 4:8）模式。

**E-Sparse[177]引入熵来量化输入特征的每个通道（通道内）的信息丰富度**，并采用其来增强特征范数（跨通道）作为评估参数重要性的指标。此外，它提出**通道混洗来重新排序 LLMs 中的信息分布，以获得信息损失较少的 N:M 稀疏性**。NVIDIA Ampere 及更新代 GPU 支持的 2:4 稀疏性理论上可实现矩阵乘法 2 倍加速。实际上，**2:4 稀疏性可实现 MatMul 操作 1.54×-1.79× 的加速，端到端加速约为 1.21×-1.25×** （由于注意力等额外开销）。

基于 LLM 推理的瓶颈是瘦矩阵乘法这一关键观察，Flash-LLM[178]提出了一种通用的“按稀疏加载、按密集计算”方法用于非结构化稀疏矩阵乘法。**Flash-LLM 提出了一种名为 Tiled-CSL 的新稀疏格式，以缓解内存带宽瓶颈，并支持使用张量核按块执行 SpMM** （稀疏矩阵乘法）。对于 OPT-30B 模型，Flash-LLM 在单块 A100 GPU 上实现 80%稀疏性，精度下降 1.44%，在批量大小为 8、16、32 和 64 时，推理速度分别约为 290 tokens/s、500 tokens/s、800 tokens/s 和 1187 tokens/s。

**Agarwalla 等人[179]将 SparseGPT 单次剪枝方法与稀疏预训练相结合，对高稀疏性 LLM 进行预训练**。他们分别利用 Neural Magic 的 DeepSparse 引擎和 nm-vllm 引擎在 GPU 和 CPU 上部署模型。对于 Llama-7B 模型，在 NVIDIA A10 GPU 上，50%稀疏性和 70%稀疏性时的推理速度分别为 44.4 tokens/s 和 47.9 tokens/s；在 AMD EPYC 9R14 处理器上，相应的推理速度分别为 4.4 tokens/s 和 6.9 tokens/s。

现有方法需要昂贵的再训练、放弃 LLM 的上下文学习能力，或无法在现代硬件上实现实际时间加速。**DejaVu[180]根据输入动态预测上下文稀疏性，并采用异步且硬件感知的实现来加速 LLM 推理**。对于 OPT-175B 模型，DejaVu 在 8 块 A100-80GB GPU 上实现高达 75%的稀疏性和 50 tokens/s 的推理速度，分别比 FasterTransformer 和 Hugging Face 实现快 2 倍和 6 倍以上。

**对于 Mamba 模型，shihab 等人[190]提出了一种专为 Mamba 模型设计的新型非结构化剪枝框架，可实现高达 70%的参数减少，同时保留超过 95%的原始性能**。他们整合了三项关键创新：基于梯度感知的幅度剪枝技术、迭代剪枝计划和全局剪枝策略。结果表明，他们在单块 NVIDIA A100 GPU 上对 Mamba-130M 和 Mamba-370M 模型分别实现 2083.33 tokens/s 和 1219.51 tokens/s 的推理速度。

#### GPU 注意力稀疏

在 LLM 推理的预填充阶段，注意力计算复杂度随输入序列长度呈二次增长。在 GPU 计算和内存资源有限的情况下，注意力稀疏化可减少注意力值的数量以加速预填充阶段。

对于静态稀疏性，Sparse Transformer[181]、StreamingLLM[183]、Bigbird[182]和 Longformer[184]使用全局和局部模式的手动组合来替代全注意力模式。**局部模式捕获每个标记在固定大小或步长内的局部上下文，而全局模式捕获特定标记与所有其他标记之间的关系**。对于 Llama2-7B 和 Llama2-13B 模型，StreamingLLM 在单块 NVIDIA A6000 GPU 上分别实现 15.38-32.26 tokens/s 和 9.43-20.83 tokens/s 的推理速度。

对于动态稀疏性，Adaptively Sparse Attention[185]用 α-entmax 替换 softmax，α-entmax 是 softmax 的可微泛化，允许低得分词精确获得零权重，并丢弃未来生成不再需要的部分上下文。Reformer[186]使用局部敏感哈希替换点积注意力，将复杂度从 O(L²)变为 O(L log L)，其中 L 为序列长度。Sparse Flash Attention[187]扩展了 FlashAttention[292]的 GPU 内核，涵盖键/查询丢弃和基于哈希的注意力。

Sparse Sinkhorn Attention[188]采用学习的排序网络将键与相关查询桶对齐，确保仅在相应的查询-键对之间计算注意力。H₂O[189]观察到，在计算注意力分数时，一小部分标记（称为 Heavy Hitters，H₂）贡献了大部分值。H₂O 引入动态注意力稀疏化方法，采用 KV 缓存逐出策略，动态平衡保留近期标记和 H₂ 标记。对于 OPT-6.7B 模型，含 20% H₂ 的 H₂O 在单块 NVIDIA T4 GPU 上实现 30.4 tokens/s 的推理速度。

### 3.2.4 FPGA

#### FPGA 权重稀疏

**FlightLLM[133]是首个基于 FPGA 的 LLM 加速器，提出可配置的稀疏 DSP 链以支持不同稀疏模式并提高计算效率**。随后，它提出**全片上解码方案以支持混合精度**，提升内存带宽。最后，提出**长度自适应编译方法** 以减少编译开销。对于 Llama2-7B 模型，FlightLLM 在 Xilinx Alveo U280 FPGA 和 Versal VHK158 FPGA 上分别实现批量大小为 1 时 55 tokens/s 和 92.5 tokens/s 的推理速度。**EdgeLLM[134]整合 4-bit 仅权重量化，并在矩阵乘法算子中对权重参数采用对数尺度结构稀疏性**。对于 ChatGLM2-6B 模型，其在 AMD Xilinx VCU128 FPGA 上实现平均 67 tokens/s 的推理速度，功耗 55.07W。

> 近期工作主要假设结构化模型剪枝，对非结构化稀疏性效果不佳。其背后的原因是难以从非结构化稀疏性中利用数据重用，导致硬件利用率低下。

**ChatOPU[194]提出一种基于 FPGA 的 LLM 覆盖处理器，支持具有更好数据重用的非结构化模型剪枝**。它在 systolic array（脉动阵列，一种用于矩阵运算的并行计算架构）上提出一种新的对角线数据流，以实现稀疏和密集矩阵乘法的高效数据重用。然后，它开发了高效的稀疏参数编码和解码方法，以节省片外内存流量，并通过固定片上 KV 缓存分配和整个 LLM 推理的合并访问来提升片外带宽利用率。实验结果表明，在 Xilinx U200 FPGA 上的 ChatOPU，使用 1 个和 4 个 ChatOPU 核心时，对 OPT-350M 模型分别实现 43.21 tokens/s 和 166.26 tokens/s 的推理速度。

**Zhang 等人[195]提出一种基于细粒度结构稀疏性（FSS）和通道重新分配细粒度结构稀疏性（CRFSS）的稀疏 FPGA 加速器**。对于 OPT-6.7B 模型，其方法在 Alveo U280 上结合低比特量化实现 51.744 tokens/s 和 69.776 tokens/s 的推理速度。AccLLM[145]结合 2:4 半结构化剪枝、W2A8KV4 量化和稀疏注意力以提高计算效率。大量实验结果表明，对于 Llama2-7B 模型，其在 Alveo U280 上仅用 33W 功耗实现 164 tokens/s 的推理速度。

### 3.2.5 ASIC

#### ASIC 注意力稀疏

**Spatten[196]利用标记稀疏、头稀疏和量化机会来减少注意力计算和内存访问**。它通过聚合注意力矩阵列来评估每个词的累积重要性，随后从后续层的输入中裁剪累积重要性最小的标记。在考虑 40nm 工艺下所有内存访问的情况下，其提供 2.88 TOPS 的计算能力和 8.3W 的功耗。实验结果表明，对于 GPT2-Medium 模型，其在解码阶段可实现约 35.86 tokens/s 的推理速度。

**TF-MVP[197]首次对采用前沿细粒度剪枝方案的剪枝 Transformer 模型的稀疏模式进行定量分析，并利用该方向强度提出混合长度向量剪枝（MVP）程序**。从硬件角度，其引入 TF-MVP 架构，这是一种专为所提出的剪枝 Transformer 模型设计的稀疏感知、成本高效的加速器设计。在 28nm CMOS 工艺下以 400MHz 频率实现，TF-MVP 提供 0.835 TOPS 的计算能力，片上功耗 1.721W，用于加速 GPT-2 小型模型。

**SOFA[198]通过使用基于日志的仅加法操作预测注意力稀疏性，以避免预测的显著开销**。然后，提出一种分布式排序和排序更新的 FlashAttention 机制，并采用跨阶段协调分块原则，实现阶段间的细粒度轻量级协调，帮助优化内存访问和延迟。SOFA 在 28nm 工艺下提供 24.423 TOPS 的计算能力，功耗 3.4W。对于 Llama2-7B 模型，与 NVIDIA A100 GPU 相比，其在预填充阶段实现 9.5 倍的推理加速。

### 3.2.6 PIM/NDP

#### PIM/NDP 权重稀疏

**LauWS[199]为 NDP 系统提出非结构化稀疏方法，并在实际基于 GDDR6 的存储体 NDP 上进行评估**。通过尽可能忽略非特征值，不仅保留了整个矩阵的整体特征，还保留了局部区域的特征，这有利于高稀疏性和最小精度损失之间的权衡。与密集模型相比，其在 50%稀疏性下对 GPT-2 小型模型和 OPT-125M 模型分别实现 1.23 倍和 1.24 倍的加速。**Sharda 等人[165]提出使用无电容 3D 可堆叠 DRAM 存储比传统 DRAM 密度更高的更大 LLMs。为减少中间数据大小，他们提出层级稀疏-量化混合（LSQH）算法**，该算法基于使用低比特量化的计算引入稀疏性，以减少能耗和数据存储需求。最后，通过将 3D DRAM 与 3nm 工艺节点设计的逻辑裸片堆叠，设计了一种 3D 异构集成加速器。评估表明，对于 Llama2-13B 模型，其在预填充阶段实现 163k tokens/s 的推理速度，功耗 193W。

**FlexCiM[201]提出一种灵活的层级 N:M 稀疏性，考虑异常值的存在和分布**。FlexCiM 通过将数字 CiM（DCiM）宏划分为更小的子宏，支持多种稀疏模式，与现有稀疏加速器相比，推理延迟降低达 1.75 倍，能耗降低 1.5 倍。

#### PIM/NDP 注意力稀疏

**HARDSEA[200]通过预测轻量级标记相关性提出注意力稀疏方法，并设计混合模拟-ReRAM 和数字-SRAM 近存计算加速器**。它采用对电路非理想性敏感的 ReRAM-CIM 来负责仅需计算单调性的标记相关性预测，而用于精确稀疏注意力计算的 SRAM-CIM 则重组为内存边界计算方案，从而适应不规则稀疏模式。实验结果表明，HARDSEA 将 BERT 和 GPT-2 小型模型剪枝至 20%稀疏性而无精度损失，相比 NVIDIA RTX 3090 GPU 实现 5.8×–6.7× 的加速。

## 3.3 快速解码（Fast Decoding）

![文章插图](/articles/2025-07-01-llm-sparsity-fast-decoding-65902afa/images/07.webp)

### 3.3.1 概述

- 传统自回归解码通常逐 token 生成文本，每一步仅选择概率最高的 token，即贪心采样。这种方法虽然简单易实现，但可能导致生成结果缺乏多样性和创造性。
- 另一种自回归方法称为核采样（或 top-p 采样）[293]，通过设置累积概率阈值 p，在生成时考虑多个候选 token，采样范围限定在累积概率达 p 的 token 集合中。尽管该方法比贪心采样多样性更高，但仍属于逐步生成方式。

传统自回归解码是快速解码的基础框架，而核采样作为概率生成策略，可与投机解码、层跳过等快速解码技术结合，通过算法 - 硬件协同优化提升生成效率。

**“快速解码” 指通过算法优化或硬件加速，减少自回归解码的时间开销，提升 Token 生成速度**。其核心目标是解决传统自回归解码的顺序性瓶颈（如逐 Token 生成导致的低并行性）。

> 当前，快速解码技术主要可分为两类：**推测解码（Speculative Decoding）** 和 **层跳过（Skip Layer）**。

![文章插图](/articles/2025-07-01-llm-sparsity-fast-decoding-65902afa/images/08.webp)

#### 推测解码

推测解码是一种提升大型语言模型（LLM）生成效率的技术，其**核心原理是利用轻量级的「草稿模型」（Draft Model）快速生成候选输出，再由主模型进行深度评估，从而加速文本生成过程**。在实现推测解码时，首先使用较小的草稿模型快速生成多个候选词。

::: block-1
该模型可在短时间内评估上下文并提出各种可能的输出选项，随后主模型对这些候选词进行并行评估，计算其概率或分数，最终选择分数最高的候选词作为实际生成结果。
:::

通过这种方式，**推测解码将速度与准确性结合，在显著减少计算时间的同时维持生成文本质量**。草稿模型的常见选择包括：

- 一种是**直接使用 Transformer 模型的特定层**，利用现有架构维持一定特征提取能力的同时加速推理；
- 另一种是**单独训练一个小型模型**，该模型通常参数更少、结构更简单，专注于快速生成候选词并针对特定任务优化性能。

两种方法各有优势，可根据具体应用需求、质量要求和计算资源限制选择。

#### 层跳过技术

工作原理是**在模型推理过程中动态选择性跳过某些层**，从而减少计算负载并提升生成速度。

在实际实现中，模型**处理输入时** 会**评估各层对当前任务的重要性**，根据预设启发式规则或学习到的策略**决定是否执行特定层的计算**。该方法中，**模型通常由多个层组成** （如 Transformer 中的自注意力层和前馈层）。**推理时，若输入特征相对简单或上下文复杂度较低，模型可选择跳过某些中间层的计算**。这种选择可能基于实时评估，使模型能根据不同输入动态调整计算路径。

**为有效实现层跳过，模型常需在训练阶段进行优化，学习何时跳过哪些层**，这可通过策略梯度或强化学习等方法实现，使模型在各种任务中灵活适应。通过跳过不必要的层，层跳过技术可显著加速推理速度，同时减少计算资源消耗，尤其适用于实时系统和资源受限环境。总体而言，该方法通过智能选择计算过程提升了大型语言模型的效率和适用性。

### 3.3.2 CPU

ML-SpecQD [203] 使用 MXFP4 模型作为草稿模型。而 MXFP4 草稿 token 生成本身可通过使用更小的草稿模型进一步通过推测解码加速。这种使用 MXFP4 量化草稿模型的多级推测解码相比 BF16 基线实现了高达 2.72 倍的加速。

### 3.3.3 GPU

#### GPU 推测解码

##### 推测解码

推测解码 [205] 旨在克服 LLM 自回归解码中固有的顺序性过程。其**核心解码机制是对多个时间步并行进行预测** （即草稿 token），然后**选择经评分模型验证的最长前缀作为最终输出**。

**Lookahead 解码 [206] 采用「猜测-验证」（Guess-and-Verify）范式作为整体解码机制，通过 n-gram 方法生成草稿 token，并在正向传播时同时验证草稿 token**。对于不同数据集的 Llama-7B 和 Llama-13B 模型，其在单块 NVIDIA A100-80GB GPU 上实现 65.12–94.51 tokens/s 和 56.01–90.05 tokens/s 的推理速度。为在维持生成质量的同时提高接受率，许多研究聚焦于生成草稿 token 的方案。

**Medusa [207] 添加额外解码头以并行生成多个后续 token，并使用基于树的注意力机制构建多个候选续写，在每个解码步骤同时验证**。对于 Vicuna-7B 和 Vicuna-13B 模型，其在单块 NVIDIA A100-80GB GPU 上实现 129.86 tokens/s 和 98.54 tokens/s 的推理速度。

**EAGLE [208, 209] 选择与 LLM 配置相同的单个 Transformer 层作为草稿模型进行自回归预测，并将特征和 token 嵌入作为草稿模型的输入**。在目标模型的验证阶段，EAGLE 采用与 Lookahead 和 Medusa 类似的树状注意力机制，确保草稿 token 之间的正确关系。对于 Vicuna-7B、Vicuna-13B、Llama2-Chat-7B 和 Llama-2-Chat-13B 模型，其在单块 NVIDIA A100-80GB GPU 上分别实现 139.95 tokens/s、132.31 tokens/s、133.98 tokens/s 和 156.80 tokens/s 的推理速度。基于推测解码由草稿模型预测、目标模型验证的基本范式，部分研究探索其中模块的优化。

**Ouroboros [210] 从 LLMs 的验证过程中构建短语候选池，为草稿模型的草稿 token 生成提供候选**。与 Medusa 和 EAGLE 不同，Ouroboros **使用较小的 LLMs** （如 DeepSeek-7B）**作为目标模型** （如 DeepSeek-34B）**的草稿模型**。对于 Yi-34B、DeepSeek-34B 和 CodeLlama-34B 模型，其在单块 NVIDIA A100-80GB GPU 上分别实现 61.20 tokens/s、41.00 tokens/s 和 39.2 tokens/s 的推理速度。

在**预测** 阶段，**Sequoia [211] 引入动态规划算法和硬件感知树优化器，基于运行时特征和给定硬件平台寻找最优树结构**；在**验证** 阶段，**Sequoia 采用新型采样和验证方法，在不同解码温度下均优于先前工作**。对于 Llama2-7B 和 Llama2-13B 模型，其在单块 NVIDIA A100-80GB GPU 上分别实现 169.68 tokens/s 和 149.20 tokens/s 的推理速度。

> 上述研究均需借助辅助模型（如 EAGLE 中的单个 Transformer 层、Medusa 中的多个 Medusa 头，或 Ouroboros 中的小型 LLM 如 Llama2-7B）或统计方法（如 Lookahead 中的 n-gram）生成预测 token，再由目标模型验证。

---

##### 自推测解码

> 另一些研究 [212, 213, 214] 探索无需辅助模型的 LLM 推理加速，即「自推测解码」（Self-Speculative Decoding）。

**Draft&Verify [212] 通过选择性跳过 LLMs 的某些中间层生成草稿 token，随后在一次正向传播中验证草稿 token**。对于 Llama2-13B 模型，其在单块 NVIDIA A100-40GB GPU 上实现 62.23 tokens/s 的推理速度。

**Kangaroo [213] 采用 LLM 的固定浅层子网络作为草稿模型，剩余层作为目标模型**。为**增强草稿模型（即浅层子网络）的表示能力，其训练一个适配器模块跟随子网络**。对于 Vicuna-7B 和 Vicuna-13B 模型，其在单块 NVIDIA A100-80GB GPU 上分别实现 138.14 tokens/s 和 105.89 tokens/s 的推理速度。

**LayerSkip [214] 提出在早期层退出，并利用模型剩余层进行验证和纠正**。训练时，其对早期层应用低丢弃率、对后期层应用高丢弃率的层丢弃，并添加早期退出损失以提高早期层早期退出的准确性。对于 Llama2-13B 模型，其在单块 NVIDIA H100 GPU 上实现 66.37 tokens/s 的推理速度。

**LLMA [204] 的设计动机** 是观察到**许多实际场景** （如检索文档）中，LLM 的**解码结果与参考文本存在大量相同文本片段**。LLMA **首先从参考文本中选择文本片段并将其 token 复制到解码器，然后在单个解码步骤内并行高效检查这些 token 作为解码结果的适用性**。对于 Llama-7B 和 Llama-13B 模型，其在单块 NVIDIA V100 GPU 上分别实现 59.2 tokens/s 和 41.1 tokens/s 的推理速度。

##### 异步多设备推测解码

AMUSD（**异步多设备推测解码**）[219] 引入一种系统，通过**将草稿和验证阶段解耦** 为**连续异步过程进一步加速** 生成。其**使两个模型能在独立 GPU 上分别独立进行预测，而非同一时间仅一个模型** （草稿或验证）**执行 token 生成**。对于以 Llama3.1-8B 模型为验证模型、Llama3.2-1B 模型为草稿模型的场景，其在两块 NVIDIA A100 GPU 上相比推测解码实现平均 71.02 tokens/s 的提升，功耗约 300W。

**PipeSpec [220] 提出一种框架，将推测解码推广至按层次管道排列的 k 个模型，通过轻量级协调实现异步执行以进行预测验证和回滚**。对于 Llama2-68M 和 7B 模型组合，其在单块 NVIDIA A100 GPU 上实现 79.18 tokens/s 的推理速度；对于 Llama3.1-1B、8B 和 70B 模型，其在两块 A100 GPU 上实现 20.51 tokens/s 的推理速度。

**Adaptix [221] 利用基于 trigram 矩阵的 LLM 表示动态近似 LLM 的输出分布，允许模型在解码过程中适应变化的 token 概率，还实现一种草稿构建机制以有效平衡探索与利用**。对于 Llama2-7B 和 Llama-13B 模型，其在 NVIDIA A6000 GPU 上分别实现 85.62 tokens/s 和 45.83 tokens/s 的推理速度。

**SPIN [222] 通过使用多个异构 SSM** （小型推测模型，Small Speculative Models）**改进 token 推测**，采用无请求难度先验知识的基于学习的算法进行 SSM 选择，还通过在 GPU 上对推测和验证阶段进行流水线操作以进一步加速。对于以 Llama2-7B 模型为验证模型、Llama2-68M 模型为草稿模型的场景，其在 NVIDIA V100 GPU 上实现 62.33 tokens/s 的推理速度。

**PARD（并行草稿）[223] 支持将自回归草稿模型低成本适配为并行草稿模型，在草稿阶段的单次正向传播中预测多个未来 token**。对于 Llama3.1-8B 模型，其在单块 NVIDIA A100 GPU 上实现 274.4 tokens/s 的推理速度。

**Judge Decoding [224] 注意到即使以 GPT-4o 作为草稿模型，接受率也不高**，因此研究其草稿与目标响应的对齐如何导致客观正确的续写被拒绝，进而**提出一种适应性验证方案以通用方式判断响应**。结果表明，以 Llama3.1-8B 作为草稿模型、Llama3.1-70B 作为验证模型时，其在两块 NVIDIA H100 GPU 上实现 141.8 tokens/s 的推理速度。

为**缓解推测解码中草稿模型的显著延迟，Falcon [225] 提出「耦合顺序扫视蒸馏」** （Coupled Sequential Glancing Distillation）技术，**在草稿模型训练期间强化同一块内 token 间依赖关系以提高推测准确性**。对于 Llama2-Chat 7B 模型，其在单块 NVIDIA H800 GPU 上实现 147.38 tokens/s 的推理速度。

#### GPU 层跳过

层跳过方法 [215, 216, 217] 基于「LLM 推理时并非所有层都必要」的思想提出。

**AdaInfer [215] 对跨任务的激活层进行统计** 分析，提出一种简单算法，**根据输入实例自适应确定推理终止时刻**。由于每层引入的开销对解码阶段不友好，AdaInfer 仅对问答任务的部分基准进行测试，在单块 NVIDIA V100 GPU 上对 Llama2-7B 模型实现 25.2 tokens/s 的推理速度。

基于 AdaInfer 的基本数据流，RAEE [216] 提出构建检索数据库离线存储 token 信息，利用通过搜索预构建检索数据库获取的相似 token 信息引导主干模型在某层退出。对于基于 RoBERT-large-350M 微调的 LM-BFF 模型，RAEE 实现 26.23 tokens/s 的推理速度。上述研究均使用连续浅层进行推理，即「早期退出」（Early Exiting）。

**MOD [217] 通过预训练模型在每层添加类似专家混合** （MoE, Mixture-of-Experts）**的路由器决定是否跳过当前层，实现动态选择部分层进行计算**，而非强制连续层计算。MOD 的模型未开源，论文中未给出吞吐量的相应结果。

SpecEE [218] 通过轻量化预测器降低词汇空间以预测是否早期退出，为此设计两层启发式预测器调度和上下文感知合并映射。对于 Llama-7B 和 Llama-13B 模型，SpecEE + EAGLE 在单块 NVIDIA A100 GPU 上分别实现 124.66 tokens/s 和 120.8 tokens/s 的推理速度。

### 3.3.4 ASIC

#### ASIC 推测解码

C-Transformer [226] 采用「大-小网络」（Big-Little Network），由原始 GPT-2 大模型和 1/10 规模的小模型组成，以及可重构同构架构以提高硬件利用率和能效。**推理时，仅执行小模型计算，若特定 token 的预测概率超过预设阈值，则跳过大模型计算，从而减少内存访问**。工作负载分为两类：基于加法的脉冲域（适用于小输入值）和基于乘法的非脉冲域（适用于大输入值）。其采用 28nm CMOS 工艺制造，功耗 1.431W，对于 GPT-2 大型模型，在预填充阶段实现 2146.75 tokens/s 的推理速度。

### 3.3.5 PIM/NDP

#### PIM/NDP 推测解码

SpecPIM [227] 旨在通过充分探索算法和架构带来的异构性，加速基于 PIM 的系统上的推测推理。其构建架构设计空间以满足每个模型不同的资源需求，并专门设计数据流空间以充分利用系统硬件资源。基于协同设计空间，其还提出设计空间探索框架，以在不同目标场景下提供最优设计。与 GPU 上的推测推理和现有基于 PIM 的 LLM 加速器相比，SpecPIM 实现 1.52×/2.02× 的几何平均速度提升和 6.67×/2.68× 的几何平均能效提升。

## 3.3 总结

本文以硬件视角探讨 LLM 推理加速的稀疏性和快速解码方法。

- 稀疏性通过权重、激活和注意力稀疏优化，结构化稀疏更利于硬件加速，不同硬件支持各异。

- 快速解码包括推测解码和层跳过，GPU 在推测解码中表现突出。操作符优化通过融合等提升效率，ASIC 和 PIM/NDP 在能效和吞吐量上优势显著，各硬件平台在功耗、速度和能效上特点不同。
