### 问题 1：把上下文“压碎”再“挑着看”，模型会彻底忘掉跨越压缩块的遥远线索吗？

> 如果要读一本一百万字的小说，但被规定：每读完 4 页（CSA 压缩），只能写一行摘要，或者每 128 页（HCA 压缩）才总结一次。回头查找时，还得从所有摘要里“挑一小撮”看。**如果一个关键伏笔在第 100 页埋下，到第 500 页才揭晓，那么经过几十轮“压缩-筛选”，这条线索还存在吗？**

DeepSeek-V4 的混合注意力，由“压缩稀疏注意力”（CSA）和“重度压缩注意力”（HCA）交错构成。具体来说：

- CSA 把每 4 个 token 的 KV 缓存压成 1 个，再用稀疏注意力只选前 512 或 1024 个压缩块参与计算；
- HCA 更狠，每 128 个 token 压成 1 个，走密集注意力。

> 这势必让人担心：信息在跨压缩块的边界上会不会出现系统性遗忘？

**报告里的答案** 非常清醒——他们用三个相互咬合的机制来硬抗这个问题：

#### 机制 1. 滑动窗口“兜底”防止就近失忆

CSA/HCA 只看得到前面的压缩块，一个 query 看不到自己块内其他 token 的信息。**为此，每一层都加了一条滑动窗口注意力分支（窗口大小 128），完整保留最近 128 个 token 的未压缩 KV**。这保证至少局部上下文的依赖是绝对精确的，绝不丢失分毫。

![文章插图](/articles/2026-04-25-90-deepseek-v4-4dd31fdd/images/05.webp)

::: image-caption
CSA（压缩稀疏注意力）的核心架构。它将键值条目的数量压缩至1/m倍，然后应用DeepSeek稀疏注意力进行进一步加速。此外，还结合了一小部分滑动窗口键值条目，以增强局部的细粒度依赖关系。其精髓在于“先压缩，再稀疏”。首先，通过可学习的压缩权重，将连续m个token的KV缓存聚合为一个压缩条目，这在保持长程信息的同时极大降低了存储开销。随后，Lightning Indexer 在网络中动态地、非均匀地选择前k个与当前查询最相关的压缩块进行核心注意力计算。这种机制巧妙地解决了全局注意力计算量过大的问题，而补充的滑动窗口分支则弥补了压缩导致的局部上下文丢失。CSA的设计表明，高效的注意力并非简单丢弃信息，而是通过学习哪些信息值得保留和关注，在序列的全局结构与局部细节之间实现了动态平衡。
:::

![文章插图](/articles/2026-04-25-90-deepseek-v4-4dd31fdd/images/06.webp)

::: image-caption
HCA（重度压缩注意力）的核心架构。它执行更重的压缩，将每m‘个（远大于m）token的键值条目合并为一个。同样，我们也额外引入一小部分滑动窗口键值条目，以增强局部的细粒度依赖关系。HCA追求极致效率的思路，与CSA侧重精准稀疏选择形成了互补。HCA将压缩率m’设为远大于CSA的m（如128），将长序列信息极度浓缩，因而更多地依赖压缩块所提供的概括性上下文。由于其保留所有压缩块进行稠密注意力计算，免去了稀疏选择的索引开销，在处理对局部精确性要求稍低但需要全局视野的任务时具备优势。V4系列在层间交替使用CSA和HCA，构成了一种巧妙的混合策略：CSA层负责细粒度、筛选式的信息交互，而HCA层则提供粗粒度、全局性的信息背景，这种分工使得模型在不同抽象层级上处理信息，从而在保证效率上限的同时，维持了强大的长文理解能力。
:::

#### 机制 2. 重叠压缩让块边界变得“模糊”

CSA 压缩时构建了一个精密的信息传递机制：每个压缩单元 $C_i^{\text{Comp}}$ 的生成，不仅依赖当前 $m$ 个token的 $C^a$，还融合了**上一个压缩块的**$m$ 个token的 $C^b$。

报告将此设计称为"索引存在重叠"。这种做法在不增加最终KV缓存条目数量的前提下，让相邻压缩块共享了部分原始信息，极大地增强了块间的语境连续性，从而有效缓解了硬性分块可能带来的信息割裂。

#### 机制 3. Attention Sink 让模型有权“谁都不理”

V4 引入了 Attention Sink ——每个头有一个可学习的汇点 logit，加到注意力分母上。

$$
s_{h,i,j} = \frac{\mathrm{Exp}(z_{h,i,j})}{\sum_{k}\mathrm{Exp}(z_{h,i,k}) + \mathrm{Exp}(z_{h}^{\prime})}
$$

其中：

- $\mathrm{Exp}$ 表示指数函数。
- $z_{h}^{\prime}$ 表示第 $h$ 个注意力头的可学习汇点 logit。
- $\sum_{k}$ 对所有被选中的压缩 KV 块求和。

::: block-1
:mdnice-bold-italic[这意味着每个注意力头都有一个可学习的、固定的"注意力回收站"（Sink）。它的作用是调节注意力的分布稳定：模型可以将部分无用的、多余的注意力权重"倒入"这个Sink，从而避免被迫将过高的注意力集中在少数相关性不高的token上]，让真正有效的注意力权重分布更合理、更平滑。这在根本上避免了微弱但关键的长程信号被噪声淹没。
:::

1M token 的 MRCR（多针检索）测试中，DeepSeek-V4-Pro 在 128K 内表现出惊人稳定，到 1M 时成绩依然碾压 Gemini-3.1-Pro。**实证证明这条“压缩–选择”流水线至少在事实检索式的长程依赖上没有垮掉。**

### 问题 2：用数学约束“驯服”残差流，会不会反而掐死了模型对突变的表达力？

> 如果规定自己每走一步，步子不能比上一步大，那确实永远不会摔跤，但紧急关头需要跳过一个水坑时，你就被锁死了。mHC 给每一层的残差连接绑上了“非扩张”约束，**这是不是以牺牲深层网络的剧烈表征变化能力为代价换来的稳定？**

DeepSeek-V4 用 Manifold-Constrained Hyper-Connections (mHC) 替代了传统的残差连接。它的核心是让残差变换矩阵 $B_l$ 落在“双随机矩阵”这个流形上，保证 $\|B_l\|_2 \leq 1$，从而让信号在前向和反向传播中都不爆炸。

**但报告指出了一条关键路径：约束只放在残差状态的混合方式上，层内变换的表达力原封不动。**

具体怎么做到的？mHC 先把残差流的宽度从 $d$ 拓宽成 $n_{\text{hc}} \times d$（相当于复制 4 份），然后用 $A_l$ 和 $C_l$ 做输入输出的重组合。无论 $B_l$ 怎么受限，喂给 MoE 层或注意力层的真实输入 $A_l X_l$ 始终是 $d$ 维，这些层内部的非线性计算毫无打折。

::: block-1
这里的关键在于，**mHC的设计哲学是将"信息传输的稳定性"与"模型计算的表达力"彻底解耦。** 约束施加的对象 $B_l$，只作用于那条被扩增了维度的"超空间"残差流，负责稳定地混合和传递历史信息。而真正负责核心计算的MoE层和注意力层，其输入 $A_l X_l$ 和输出 $\mathcal{F}_l(A_l X_l)$ 的维度依旧是 $d$，其内部的非线性变换能力和学习能力**原封不动、毫发无损**。

mHC的约束非但没有牺牲能力，反而通过这个更精细的双通道设计，为在极深网络中实现稳定且强大的训练奠定了基础。
:::

更巧妙的是，$A_l$、$B_l$、$C_l$ 都不是写死的，而是根据输入 $X_l$ 实时生成的。用报告的话：“动态参数化”——**同一个模型在处理不同 token 时，会组合出不同的残差混合策略，这让表达力富富有余。**

### 问题 3：Muon 优化器 + MoE，会把专家参数“修偏”然后连锁搞崩路由吗？

> V4 Pro 有 384 个路由专家，每次都只激活 6 个。Muon 优化器要求对整个参数矩阵做正交化再更新，为了省内存又不得不东切西分，还用 BF16 压缩梯度通信。这会不会导致不同专家收到的更新有效精度不一致，冷热不均，最终路由彻底混乱？

![文章插图](/articles/2026-04-25-90-deepseek-v4-4dd31fdd/images/07.webp)

这戳到了 MoE 与 Muon 结合的“七寸”。**报告原文也摆出了两道防线：**

- **逻辑上绝不割裂专家。** 工程师展平所有 MoE 专家的下投影、上投影、门控矩阵，再接顺序填充、切分给不同 rank，保证“无需切分任何逻辑上独立的矩阵”。就是说，每个专家的参数矩阵作为 Muon 正交化的单位是完整的，绝不会出现半个专家被正交化、另一半没处理的诡异情况。
- **All-to-All + 本地 FP32 求和，挽救量化精度。** 为了把跨 rank 的梯度通信量减半，他们确实把梯度量化成了 BF16，但立刻补充了一句：“为避免低精度累加器引入的累积误差，我们用一个两阶段方法取代了传统的树状或环状 reduce-scatter”——:mdnice-bold-italic[先用 all-to-all 把各 rank 的梯度交换，然后每个 rank 自己在] FP32 下执行求和。通信省了，累加精度也保住了。

::: block-1
此外，还有一个更直接、且被验证为无损的数值稳定技巧（问题 6 会具体讲）：SwiGLU Clamping。报告明确指出，:mdnice-bold-italic[将 SwiGLU 激活值直接截断在 $[-10, 10]$ 的范围内，能够在不损害模型性能的前提下，有效消除异常值，从而抑制由其引发的训练尖峰。这与前摄路由相辅相成，共同构成了稳定训练的防线。]
:::

![文章插图](/articles/2026-04-25-90-deepseek-v4-4dd31fdd/images/08.webp)

::: image-caption
DeepSeekV4的全专家并行方案及相关工作的示意图。该图深入解读了V4在系统层面实现高效训练的秘诀——细粒度的通信-计算重叠。传统方案如Comet仅实现粗粒度的重叠，仍有大量时间浪费在等待上。V4的方案通过“波次”调度专家，将计算与跨节点的分发、合并通信切分成更细的流水线步骤，让通信完全隐藏在计算背后。这一设计的精妙之处在于，只要计算-通信比满足条件，即使降低互联带宽也不会显著影响性能。这意味着V4可以在更廉价的网络硬件上运行，对降低大规模MoE模型的部署成本和推动异构算力集群的发展具有深远意义，体现了算法和硬件的协同设计思想。
:::

### 问题 4：FP4 量化“无损还原”听起来很玄，真实推理时到底赚到的是存储，还是算力？

> 报告说 FP4 的权重可以“无损”地转回 FP8 参与计算。这就像把一份缩印件用高精度扫描仪数字化——扫描过程确实没再损失，但缩印时丢掉的细节是一去不返的。**V4的'无损'指的是反量化过程，而非原始精度**。但丢了的画面细节是一去不复返的。V4 的 FP4 优势到底有多少是存储层面，有多少是实实在在的算力翻倍？

**报告出乎意料地诚实——当前赚的就是存储和内存带宽，算力收益要等新硬件。** 引言里已经讲得明明白白：“尽管 FP4×FP8 操作的峰值 FLOPs 目前在现有硬件上与 FP8×FP8 相同，它们在理论上可以在未来硬件上实现”。换句话说，今天你用 FP4 跑 V4，计算吞吐没提高，但模型权重占用少了，每次从显存搬运数据的负担轻了——这对 KV 缓存和超长上下文解码尤为重要。

那“无损”又是咋回事？FP4 是 E2M1 格式，FP8 是 E4M3，后者指数位多了 2 比特，动态范围宽得多。:mdnice-bold-italic[只要一个 128×128 的 FP8 量化块内各 1×32 的 FP4 子块的尺度因子不超出某个阈值，反量化回 FP8 时就能吸收这些细粒度信息，不存在额外舍入。所以“无损”指的是转换过程，而非原始精度。]

他们还做了一件非常诚实的事：推理和 RL rollout 时，直接用真实 FP4 权重，不搞模拟。这就把:mdnice-bold-italic[部署行为与训练对齐]，绝不粉饰。**总结就是：FP4 让 V4 的存储效率飞升，但算力红利需等硬件更新，报告没有画饼，反而把前程摊在桌面上。**

### 问题 5：KV 缓存搞出“压缩态”“滑动窗口态”“磁盘态”三套班子，会不会把省下的算力全送给 I/O 调度器？

> 好比你发明了一套极客速记法，笔记薄了 90%，但这套笔记格式奇葩，管理员每次帮你找资料得先拼凑碎片、跑好几间档案室，等找到时，省下的那点读书时间早就被等待时间耗光了。

V4 的混合注意力导出了异构的 KV 缓存：CSA/HCA 的压缩缓存、滑动窗口的未压缩缓存，还有用于共享前缀的磁盘持久化缓存。这种复杂性对系统调度是极大挑战。如果 I/O 延迟成了新瓶颈，架构的算力优势可能在工程落地时被吃掉。

**报告提到在用硬件-内核-算法的协同设计破解这个困境，而非被动接受。**

- 第一，他们根本没有用通用方案将就。报告直接指出 PagedAttention 一类统一缓存管理在这里会碰壁，于是搞了**双轨制**：
- 第二，多 Token 预测（MTP）从源头上降低了对 KV 缓存的访问频率。一次生成多个 token，就减少了反复加载巨型缓存的次数。
- 第三，对于磁盘存储，他们竟然给出了三种策略：全量存、每 p 个 token 设检查点、完全不存滑动窗口 KV。你可以根据硬件特性，自由选择用算力换 I/O 或反过来。这种可配置性揭示了设计者对 I/O 瓶颈的深刻预估和主动规避。

### 问题 6：前摄路由和 SwiGLU Clamping 这些“补丁”的存在，是不是反证了 V4 底层架构根本没法自己稳定收敛？

> 一架设计极为复杂的飞机，试飞时总莫名抖动。工程师找到两个法子：用上次飞行记录来校准这次的控制（前摄路由），以及硬性限定方向舵最大偏角（Clamping）。抖动是消失了，但我们必须问：最初的气动设计是否存在根本的、理论上未知的缺陷？

这可能是整篇报告最触达灵魂的部分。**DeepSeek 团队以一种罕见的坦诚，承认了训练不稳定，给出了工程解，然后直言“理论还没搞明白”。**

![文章插图](/articles/2026-04-25-90-deepseek-v4-4dd31fdd/images/09.webp)

::: image-caption
万亿参数MoE模型训练存在稳定性挑战，简单回滚无法根治loss尖峰问题。研究发现尖峰与MoE层异常值相关，路由机制还会加剧该问题。团队从打破路由循环、抑制异常值两方面入手，找到两种实用方法保障训练稳定，并公开分享以推动社区进一步探索。
:::

::: block-1
报告描述了万亿参数 MoE 训练时遭遇的损失尖峰，并定位到：“**异常值的出现始终与 MoE 层相关，且路由机制本身似乎加剧了这些异常值的出现** ”。也就是说，:mdnice-bold-italic[MoE 的动态路由与 SwiGLU 非线性耦合后，会形成自我强化的反馈循环。]
:::

- **前摄路由（Anticipatory Routing）的思路是：用 $\theta_{t-\Delta t}$ 而非当前的 $\theta_t$ 来算路由索引，打破骨干网络和路由网络同步更新带来的强耦合**。他们为此承担了约 :mdnice-bold-italic[20% 的额外时钟时间开销，但只在检测到尖峰时动态开启，过后恢复到普通训练。这像是一种“免疫风暴期间的紧急治疗方案”。]
- SwiGLU Clamping 则更直接：把激活值截断在 $[-10,10]$ 内。报告直言这:mdnice-bold-italic[对性能无损害，且能有效消除异常值。]

在结论部分，他们再次重申：**“尽管前摄路由和 SwiGLU 截断已被证明能有效缓解训练不稳定，其底层机制仍未充分理解。我们将积极研究训练稳定性的基础问题，力求一种更原则性、可预测的方法。”** 这完全不是遮遮掩掩，而是把问题本身当作了下一阶段的研究主题。:mdnice-bold-italic[所以，补丁的存在恰恰说明 V4 是一个在理论边界上硬踩出来的工程奇迹，它实用、强大，但它的创造者比任何人都更想知道背后的“为什么”。]

## 尾声：效率革命是一场坦率的冒险

> DeepSeek-V4 的六个技术博弈，勾勒出一个团队在“极致效率”道路上的取舍逻辑：

- **压缩与稀疏**：用重叠、滑动窗口和注意力汇来守住长程依赖的底线。
- **mHC 约束**：把稳定性锁在残差混合上，把爆发力留给层内计算。
- **Muon + MoE**：通过逻辑完整性、高精度累加和强制压制，在悬崖边踩出一条路。
- **FP4**：在存储上极致省钱，对计算收益实事求是，把未来留给硬件革新。
- **异构缓存**：用协同设计和多策略选择消化掉系统复杂性。
- **训练不稳定**：:mdnice-bold-italic[承认知识盲区，用工程手段止血]，并公开募集理论突破。
