## 一、LLM 线上推理的双重生死难题

> 面向搜索、广告的实时大模型服务，和离线批量推理存在完全不同的性能评判标准。离线任务追求单位 GPU 吞吐上限，**线上业务则要求确定性毫秒时延，二者底层优化逻辑天然割裂。**

:mdnice-bold-italic[广告场景普遍采购 NVIDIA L20 等 Ada 架构中端显卡控制算力成本]，该硬件原生存在共享内存、TMA 传输硬件双重短板，叠加解码阶段高频内核启动损耗，形成难以突破的性能天花板。

### 1.1 Decode 阶段万次内核启动的隐形性能损耗

> 常规 LLM 推理分为 Prefill 上下文填充与 Decode 逐 token 生成两个阶段，二者性能瓶颈完全分化。

- Prefill 一次性输入全部上下文，仅执行一轮完整网络前向计算，内核启动次数极少；
- Decode 每生成一个新词，就要完整运行 Transformer 解码器，单次请求会触发数万次 GPU 内核 launch 操作。

作者基于 Qwen2.5-1.5B 模型实测，**一次完整推理累计发起 165 万次内核调用，调度耗时累计 3.3 秒，占总推理时长 14.6%。** 除调度开销外，**碎片化内核会反复将中间张量写入 HBM 全局内存，算子间的数据往返进一步放大带宽压力**，成为 IO 受限 Decode 阶段的核心拖慢因素。

::: block-1
MegaKernel 的核心**设计初衷，就是将整条 Transformer 解码器算子链融合为单一持久内核**，:mdnice-bold-italic[全程驻流多处理器 SM，依靠片上寄存器、共享内存完成数据流转，彻底切断算子间 HBM 交互路径。]
:::

### 1.2 NVIDIA Ada 架构先天短板

> 主流 Hopper H100 显卡单 SM 共享内存容量 227KB，而 Ada Lovelace 架构 L20 仅提供 128KB，直接缩水近一半；同时 Hopper 原生搭载 TMA 异步传输硬件单元，**Ada 无对应硬件支持，只能依靠 PTX 汇编手动模拟异步数据搬运流程。**

共享内存容量不足直接压缩流水线深度：理论最优流水线分段数为 4 层，部署至 Ada 后仅能稳定运行 2 层，流水线占空比损耗超 30%，硬件算力利用率大幅下滑。**对于预算有限的商业广告业务，大规模采购 H100 不具备成本可行性，亟需一套适配 Ada 硬件的 MegaKernel 优化方案。**

### 1.3 现有 MegaKernel 两条技术路线无法兼顾商用需求

> 当前学术界两套成熟 MegaKernel 实现，分别卡在可移植性、运行损耗两端，**【均无法适配】广告线上推理场景：**

1. **斯坦福原版 MegaKernel**：:mdnice-bold-italic[深度耦合 Hopper 专属汇编指令]，硬编码 Llama 系列模型 tile size，:mdnice-bold-italic[不支持 Qwen 主流开源大模型，同时缺失长序列、大批量 Prefill 模块，移植至 Ada 显卡需要大规模底层代码重写，工程成本极高。]
2. **Mirage MPK 自动编译内核**：依托图抽象实现自动 tile 搜索，但运行时依靠指针状态执行 if-else 分支判断，:mdnice-bold-italic[GPU 指令发射单元频繁停顿，在 1 至 5ms 硬时延场景下性能损失严重，自动寻优算法针对不规则算子链收敛速度缓慢。[性能相比SGLang/vLLM最高提升1.7倍！Mirage Persistent Kernel：首个自动巨核化多GPU LLM推理的编译器-运行时系统，细粒度计算-通信重叠](https://mp.weixin.qq.com/s?__biz=MjM5NDczOTA4NQ==&mid=2447895728&idx=1&sn=88a267756d2f2057f868d43f0500841f&scene=21#wechat_redirect)]

::: block-1
现有 MegaKernel 方案无法同时满足三点商用诉求：适配 Ada 低成本 GPU、无运行时分支损耗、兼容 Qwen 等通用模型并支持 Prefill/Decode 全阶段。
:::

## 二、MegaKernel 技术演进全景

> GPU 算子优化历经四代迭代，从局部算子融合走向全链路持久巨型内核，MegaKernel 是当前算子融合技术的终极形态，其底层线程束分工流水线思路区别于传统优化手段。

理清算子融合技术发展脉络，才能精准定位 Ada-MK 三大创新点在领域内的技术跃迁价值。

### 2.1 算子融合四代技术路线对比

| 方法 | 说明 |
| --- | --- |
| **传统相邻内核融合、CUDAGraph** | 仅合并连续简单算子，:mdnice-bold-italic[中间张量仍需落地 HBM]，无法缓解深层网络中多层数据交换带来的带宽损耗；:mdnice-bold-italic[CUDAGraph 仅缓存内核调用序列]，不改变算子执行逻辑与内存交互方式，优化幅度有限。 |
| **编译器级编程抽象（Triton、Hidet）** | 借助块级、任务级抽象提升融合深度，但:mdnice-bold-italic[仍遵循“一算子一内核”执行范式]，无法消除多层算子切换引发的同步阻塞与调度开销。 |
| **单算子极致融合（FlashAttention 系列）** | 针对注意力模块进行 IO 感知的分块（tiling）优化，显著提升 Attention 计算效率，:mdnice-bold-italic[但适用范围局限于单一算子]，无法覆盖 Transformer 解码器全链路（如 FFN、LayerNorm、残差连接等）。 |
| **MegaKernel 全局持久融合** | 将整个解码器模块封装为常驻 GPU SM 的单一内核；通过线程束专业化（warp specialization）拆分 Loader、Compute、Store 角色；利用寄存器、Shared Memory、L2 等多级存储实现计算与访存的深度流水线重叠；**从根本上消除算子间切换开销与全局内存（HBM）往返延迟**。 |

### 2.2 两套主流 MegaKernel 底层缺陷拆解

#### 2.2.1 斯坦福 MegaKernel 硬件绑定缺陷

该方案将 SM 资源划分为加载、计算、存储、调度、释放五类线程束，同步逻辑高度依赖 Hopper TMA 硬件原语，tile size 针对 1B 级 Llama 模型硬编码，模型、硬件任意变更均需要修改底层 PTX 汇编，不具备工业化通用部署能力。同时仅覆盖轻量解码流程，无法支撑长上下文 Prefill 推理。

#### 2.2.2 Mirage MPK 运行时分支损耗缺陷

Mirage 引入 Managed Pointer 统一内存抽象，运行时根据共享内存页面空闲状态动态切换执行分支。

- GPU 流水线对条件跳转极度敏感，每次分支判断都会清空指令缓存，在低时延在线场景持续产生流水线气泡，硬件峰值算力无法释放；
- 自动搜索空间过大，不规则 tile 或复杂算子链场景下难以在合理时间内收敛到全局最优，无法适配多模型快速迭代场景。

## 三、Ada-MK 整体架构：离线编译+在线执行双阶段解耦

> Ada-MK 核心架构分为离线内核综合、在线线程束专用执行两大阶段，将所有硬件适配、路径寻优、资源分配工作全部前置离线，运行阶段仅读取序列化最优轨迹，零动态逻辑。**双阶段分离设计完美规避 Mirage 运行分支损耗，同时通过硬件约束剪枝大幅降低离线搜索开销。**

### 3.1 整体架构总览

图 1 完整呈现 Ada-MK 双层工作流，阶段一离线完成全部寻优、适配工作，阶段二在线仅做固定轨迹执行，二者完全解耦。离线阶段输入模型网络结构，输出固化无分支内核二进制；在线阶段复用成熟 TRT-LLM 框架，仅替换解码核心算子，工程改造成本极低。

![文章插图](/articles/2026-06-24-ada-megakernel-ada-mk-50-66733207/images/04.webp)

::: image-caption
图 1：Ada-MK 整体架构。阶段一为离线 MegaKernel 综合：将 Transformer 解码器与 LM 头解析为细粒度有向无环图，经硬件资源约束过滤裁剪无效分支，在指定 GPU 上性能采样后选出最优 DAG 并序列化；阶段二为在线线程束专用执行：序列化后的 MegaKernel 作为 TensorRT-LLM 插件嵌入框架，通过 Loader、Consumer、Storer 等分工线程束，依托共享内存构建线程束专用软件流水线。双阶段分离是适配 Ada 低端显卡、满足广告 1-5ms 硬时延的核心架构保障，实现 “一次离线编译、多次低延迟在线推理” 的工业落地范式。

### 3.2 阶段一：离线 MegaKernel 综合生成

1. **DAG 生成器解析网络**：遍历 Transformer 解码器堆叠层、输出 LM 头，拆解为 PTX 指令粒度的有向无环图，节点分为数据搬运、张量计算两类，边绑定数据读写依赖、共享内存资源竞争约束。
2. **硬件资源约束过滤**：输入目标 GPU 共享内存、寄存器上限，遍历 DAG 全部瓦片、流水线组合，直接裁剪超出硬件资源的无效搜索分支，大幅缩小寻优空间。
3. **硬件离线性能采样**：在目标 Ada L20 显卡上对剩余可行路径逐一轮廓采样，筛选流水线占空比最高的最优 DAG 执行轨迹。
4. **DAG 序列化存储**：将最优路径编码固化，移除所有动态判断逻辑，生成可直接加载的 MegaKernel 插件执行文件。

### 3.3 阶段二：在线线程束专用混合推理执行

> 离线生成的内核以插件形式嵌入 TensorRT-LLM，采用分阶段自适应执行策略：

1. Prefill 上下文填充阶段：完全复用 TRT-LLM 原生融合算子，长序列大批量计算充分发挥框架并行调度优势；
2. Decode 逐 Token 生成阶段：自动切换至 Ada-MK 巨型内核，依靠全链路算子融合消除内核调度、HBM 往返损耗。

单 SM 内部对线程束做空间划分，拆分 Loader 加载、Consumer 计算、Storer 写回、Controller 调度协调、Launcher 资源管理五大角色，所有角色共享片上共享内存，软件流水线重叠数据预取、张量计算、结果写回三类操作，最大化掩盖访存延迟。

::: block-1
**离线寻优、在线固化的双阶段架构，是 Ada-MK 区别于所有自动 MegaKernel 方案的核心设计**，从架构层面彻底根除运行时条件分支带来的性能气泡。
:::

## 四、三大核心创新技术深度拆解

本章为全文技术核心，逐层拆解 Ada-MK 解决 Ada 显卡内存短板、运行分支损耗、工业落地成本的三项底层创新，配套数学模型、DAG 流程图、线程束分配图完整说明实现逻辑。

### 4.1 自适应三维共享内存管控

> :mdnice-bold-italic[Ada 架构 128KB 共享内存是整套方案最大资源瓶颈，团队搭建硬件、模型、负载三维数学模型，搭配 K 维度 tile 切分、跨页面复用两套机制，将共享内存峰值占用直接降低 50%。]

传统 MegaKernel 仅静态分配共享内存空间，无法根据模型参数量、批次、硬件规格自适应调整流水线深度。

#### 4.1.1 三维资源约束数学建模

> 团队从硬件规格、模型结构、动态负载三个维度建立共享内存容量计算公式，首先定义单 SM 可用页面总数公式：

$$
N_{page }=\frac{ SMem _{max }-N_{stage } \times\left( Instr _{buf }+ Semaphores + Scratch \right)}{ Size _{page }}
$$

公式变量释义：

- $SMem_{max}$：单 SM 最大共享内存容量，L20 为 128KB；
- $N_{stage}$：流水线分段层数；
- $Instr_{buf}$、$Semaphores$、$Scratch$：指令缓存、同步信号量、临时计算占用页面；
- $Size_{page}$：单共享内存页面固定容量。

基于页面总数，推导自适应流水线深度计算公式：

$$
N_{stage }=\frac{N_{page, total }-N_{page, weight }-N_{page, scale }-N_{page, act }}{N_{page, per stage }}
$$

变量释义：

- $N_{page,total}$：硬件总可用页面；
- $N_{page,weight}$、$N_{page,scale}$、$N_{page,act}$：权重、量化缩放系数、激活张量占用页面；
- $N_{page,per stage}$：单流水线分段所需页面数量。

::: block-1
公式直观体现流水线深度随硬件、模型、批次动态调整：Ada 内存有限时自动压低分段数，H100 等高内存显卡自动拓宽流水线，最大化算力利用率。
:::

#### 4.1.2 K 维度细粒度切分+页面复用双优化

1. **K 维度 tile 对半切分**：传统 GEMM tile 一次性加载完整 K 维度权重至共享内存，峰值占用高；:mdnice-bold-italic[Ada-MK 将 K 维度 tile 尺寸减半，单次循环仅加载当前子块所需权重]，直接将峰值内存占用减半，释放的空间用于拓宽流水线分段。
2. **两级跨算子页面复用**

### 4.2 基于 MLIR 细粒度 DAG 离线寻优

> Mirage 等自动内核方案在算子抽象层构建计算图，丢失 PTX 底层并行机会；**Ada-MK 依托 Torch-MLIR 多层降级，拆解至硬件指令粒度构建依赖 DAG，离线锁定唯一最优执行路径**，运行零动态判断。

### 4.3 面向量产业务的混合引擎与量化适配

> 仅优化内核无法完成工业化落地，Ada-MK 设计 TRT-LLM 插件混合架构，复用现有业务能力；同时配套 4bit 量化专属内存、tile 优化，进一步缓解 Ada 显卡带宽、内存压力。

本创新解决两大工程痛点：完整替换推理框架迁移成本过高、低精度量化下瓦片填充产生冗余访存损耗。

#### 4.3.1 Prefill/Decode 分阶段异构执行逻辑

> **MegaKernel 的核心收益集中于 IO 受限 Decode 阶段**，Prefill 长序列大批量计算属于算力饱和场景，:mdnice-bold-italic[算子融合收益微弱，因此采用混合执行策略]：

1. Prefill：沿用 TensorRT-LLM 原生大批次并行算子，成熟 KV 缓存管理、前缀树约束生成等业务逻辑零改造复用；
2. Decode：切换 Ada-MK 巨型内核，消除数万次内核启动与多层 HBM 往返损耗。

**整套方案仅替换 Transformer 核心解码块**，嵌入插件无侵入，广告业务原有生成、打分逻辑完全兼容，避免全框架替换带来的海量业务重构工作量。

#### 4.3.2 GPTQ-W4 量化配套三重优化

> 线上广告模型普遍采用 4bit 量化压缩权重，Ada-MK 针对性设计三层适配优化：

1. **TensorCore 感知权重重排**：离线按照 LDMATRIX 加载指令排布权重，运行时无需实时布局转换，节省共享内存临时缓存；
2. **K 维度分层流水线**：量化后单迭代共享内存占用由 64KB 降至 32KB，释放空间拓宽流水线分段；
3. **小批次填充 IO 消除**：原生 TensorCore 瓦片尺寸固定，小批量场景产生大量无效填充数据，Ada-MK 改用向量级细粒度加载，跳过冗余填充张量的 HBM 读写，降低带宽消耗。

三维共享内存自适应管控、MLIR 细粒度 DAG 离线寻优、TRT-LLM 混合插件引擎，三项创新分别解决硬件资源、运行损耗、工业落地三大核心矛盾，共同构成 Ada-MK 完整技术闭环。

Ada-MK 最优适用场景为小批量、短序列、强低时延约束的线上推理服务；大批量长上下文场景内核层优化收益收窄，可搭配框架级调度优化进一步提升吞吐。
:::

## 六、工业落地价值与领域启示

> 该论文是:mdnice-bold-italic[首个将 MegaKernel 巨型内核部署至中端 Ada 架构显卡商用广告系统的完整工业方案，突破了手工调优 MegaKernel 方案高度绑定高端 Hopper/Blackwell 架构、难以低成本迁移至 Ada 架构的现状]，为低延迟在线推理场景的中端 GPU 部署提供了技术参考。

同时离线静态寻优的技术路线，为后续 LLM 编译器优化提供可复用的范式参考。

### 6.1 百度广告系统落地工程收益

1. **硬件适配优化**：无需依赖 H100 高端显卡，在 L20 显卡上即可满足 1 至 5ms 的时延指标，为中端 GPU 部署低延迟推理提供了可行方案；
2. **全链路时延稳定下降 10%至 50%，** 广告推荐响应速度提升，有效满足线上广告场景的毫秒级时延约束；
3. **零业务重构**：基于 TRT-LLM 插件改造，原有生成、打分、约束解码逻辑完全复用，无需额外业务二次开发成本。

### 6.2 未来演进方向

> 论文明确现有 Ada-MK 存在两处局限，同时规划两条迭代路线：

1. 未来工作一：拓展大参数量模型适配，优化共享内存分层复用策略，适配更大权重张量；
2. 未来工作二：迁移至 Blackwell 架构，利用原生 TMA 硬件进一步拓宽流水线深度，放大吞吐收益。

## 七、总结

> 本文完整解读百度 Ada-MK 自适应巨型内核优化框架，:mdnice-bold-italic[针对 NVIDIA Ada 系列低成本显卡共享内存不足、无 TMA 硬件、线上广告毫秒时延三大约束，通过三维自适应共享内存管控、MLIR 细粒度 DAG 离线寻优、TRT-LLM 混合插件引擎三项核心创新，解决传统 MegaKernel 硬件绑定、运行时分支损耗、落地成本过高三大痛点。]
