> GPU 已经成为大规模并行计算的核心算力底座，从机器学习训练到科学计算仿真，每一次算力跃升背后都伴随着功耗墙的逼近。:mdnice-bold-italic[一张消费级的 RTX 3090 峰值功耗就能达到 350W，数据中心级 GPU 的散热和供电成本更是占据 TCO 的大头]。**功耗效率已经成为现代 GPU 设计中与性能同等重要的核心指标**。

然而，GPU 功耗优化的前提是快速、准确的功耗评估。:mdnice-bold-italic[传统的 VLSI 功耗仿真流程需要走完 RTL 仿真、逻辑综合、物理设计、功耗分析四个阶段，单次迭代可能耗时数天甚至数周，完全无法支撑架构探索阶段的快速反馈。架构级功耗模型因此应运而生——它通过统计程序运行时的架构事件，用解析公式或机器学习模型快速估算功耗，将评估时间从天数级压缩到秒级。]

::: block-1
但问题在于，架构级模型的训练需要高质量的功耗标签。对于目标 GPU 而言，真实负载的功耗标签收集极其耗时，研究者只能退而求其次，用仅含数百条指令的微基准测试来标定模型。**这些短小、简单的微基准与包含数百万条指令的真实负载之间存在显著的数据分布差异**，直接导致现有模型在真实场景下精度崩塌。:mdnice-highlight[论文实测显示，被广泛使用的 AccelWattch 在 Ampere 和 Ada 架构 GPU 上的平均绝对百分比误差（MAPE）超过 30%，相关系数 R 不足 0.6——这样的精度根本无法指导架构级的功耗优化决策。]
:::

## 一、问题根源：微基准训练数据与真实负载的分布鸿沟

> 要理解 G-Power 的价值，必须先搞清楚一个前提：:mdnice-bold-italic[为什么架构级 GPU 功耗模型的训练数据如此匮乏？这个问题的答案藏在 GPU 设计的封闭性和功耗标签的获取成本之中。]

与 CPU 领域存在 RISC-V BOOM 等开源设计不同，**GPU 领域缺乏高质量的开源 RTL 设计**。研究者无法像 CPU 那样在开源 RTL 上跑 VLSI 功耗仿真来获取标签，只能依赖真实 GPU 芯片进行功耗测量。而真实芯片的功耗测量有一个硬性约束：:mdnice-bold-italic[你只能测量正在运行的程序的整体功耗，无法获取中间层级的组件级功耗数据。这意味着，对于每一个想要建模的目标 GPU，都需要在真实芯片上运行大量程序并采集功耗，才能获得训练数据。]

![文章插图](/articles/2026-09-13-g-power-gpu-mape-14-790f33fc/images/05.jpg)

::: image-caption
图 1：现有GPU功耗建模流程与G-Power的对比。上图(a)为模型推理阶段，目标GPU架构仿真产生架构事件输入功耗模型；中图(b)为现有AccelWattch的开发流程，仅用目标GPU的微基准数据通过VLSI功耗仿真和线性回归标定模型；下图(c)为G-Power的开发流程，额外引入已知芯片的真实功耗测量数据进行预训练和模型聚合，再在目标GPU上微调。这张图清晰展示了G-Power与现有方法的本质区别：现有方法的训练数据仅来自目标芯片的微基准，而G-Power通过已知芯片的全量数据（微基准加真实负载）构建知识基础，再迁移到目标芯片。
:::

功耗标签的获取成本直接决定了训练数据的规模。微基准测试通常只包含几百条指令，运行时间极短，可以快速采集功耗。:mdnice-bold-italic[而真实负载（如 CUTLASS 的 GEMM 内核、Rodinia 的热点计算等）包含数百万条指令，运行时间长，采集每个内核的功耗都需要锁定频率、预热 GPU、多次采样取平均，成本高昂。因此，包括 AccelWattch 在内的现有架构级 GPU 功耗模型，都只能用微基准作为训练数据。]

::: block-1
**微基准与真实负载之间的分布差异是精度崩塌的根本原因**。微基准通常被设计用来激活某个特定的硬件组件——比如一个纯浮点运算的微基准只触发 ALU，一个纯全局内存读写的微基准只触发内存控制器。:mdnice-highlight[这些程序的架构事件分布极度稀疏且极端，而真实负载往往同时激活多个组件，事件之间存在复杂的耦合关系。用极端稀疏的数据训练出来的模型，面对复杂耦合的真实输入时，泛化能力自然很差]。*论文的实验数据证实了这一点：AccelWattch 在 RTX 5880 Ada 上的 MAPE 高达 70.4%，在 RTX 4090 上也有 35.8%，完全不可用。*
:::

CPU 领域的功耗模型之所以精度较高，是因为开源 RTL 使得研究者可以在 VLSI 流程中获取大量真实负载的功耗标签，训练数据的分布与测试数据一致。**GPU 领域缺乏这个条件，这是 GPU 功耗建模比 CPU 更具挑战性的核心原因**。

## 二、G-Power 总体架构：三阶段知识迁移框架

> G-Power 的整体设计可以用一句话概括：:mdnice-bold-italic[先在已知芯片上学到通用的功耗行为模式，再根据目标芯片与已知芯片的相似度有选择地融合，最后用目标芯片的少量数据做精准适配。这个三阶段流程分别对应预训练、注意力启发聚合和目标 GPU 微调，每一阶段都有明确的设计目标和技术考量。]

![文章插图](/articles/2026-09-13-g-power-gpu-mape-14-790f33fc/images/06.jpg)

::: image-caption
图 2：G-Power三阶段框架全景图。阶段1（Pre-Training with Additional Known Chips）为每个已知GPU芯片分别训练基础模型，数据集包含微基准和真实负载；阶段2（Attention-Inspired Aggregation）从已知芯片的微基准数据生成Key向量，从目标芯片的微基准数据生成Query向量，计算相似度后剪枝并加权聚合基础模型；阶段3（Fine-Tuning on Our Target GPU）通过两级特征分组将架构事件分组，冻结组内参数比例，仅训练每组的缩放旋钮α。这张图是理解G-Power整体数据流的核心：数据从已知芯片的全量数据集流入，经过基础模型训练和相似度聚合，最终在目标芯片的微基准数据上完成适配。
:::

### 2.1 预训练：已知芯片的全量数据建模

> 预训练阶段的目标是为每一个已知 GPU 芯片训练一个基础模型（Foundation Model）。这里的"基础模型"概念借鉴自 NLP 领域的预训练语言模型——:mdnice-bold-italic[先在大规模通用数据上学到通用表示，再在下游任务上微调。不同的是，G-Power 的基础模型是一个线性回归模型。]

为什么用线性模型？**因为 GPU 功耗可以被建模为架构事件的线性函数**。:mdnice-bold-italic[每一个架构事件（如一次浮点运算、一次 L2 缓存命中）都会触发芯片内部特定电路的活动，而相同的事件总是触发相同的电路部分，因此事件的发生次数与功耗之间存在线性关系]。论文采用 28 个架构事件作为模型输入，覆盖 SM 阵列、片上网络与 L2 缓存、全局内存三个核心域。

每个已知芯片的训练数据集同时包含微基准和真实负载的架构事件与功耗标签。由于这些芯片已经量产，可以方便地用 NVML 和 nvidia-smi 在真实硬件上采集功耗，数据采集成本远低于在目标芯片的 VLSI 流程中仿真。**预训练阶段的线性回归会为每个芯片学到一组 28 维的系数向量，这组系数反映了该芯片各组件的功耗特征** ——比如 Tensor Core 的单位事件功耗、L2 缓存未命中的额外开销等。

::: block-1
:mdnice-highlight[预训练的关键在于：基础模型见过真实负载的复杂事件组合，学到了组件之间的耦合关系和不同程序行为下的功耗变化模式。这些知识是仅用微基准训练的模型无法获得的]。当有多个已知芯片时，就得到了多个基础模型，每个模型封装了一颗特定 GPU 的完整功耗知识。
:::

### 2.2 注意力启发聚合：相似度驱动的基础模型融合

> 有了多个基础模型之后，**下一个问题是：如何把它们的知识融合起来，适配到目标芯片？** 直接平均显然不合理——:mdnice-bold-italic[如果目标芯片是 Ada 架构，而某个已知芯片是完全不同的架构，它的知识可能反而有害。G-Power 的解决方案是借鉴 Transformer 中的注意力机制，为每个基础模型计算一个与目标芯片的相似度权重，相似度高的模型贡献大，相似度低的模型被剪枝丢弃。]

![文章插图](/articles/2026-09-13-g-power-gpu-mape-14-790f33fc/images/07.jpg)

::: image-caption
图 3：注意力启发聚合的详细流程。Query向量（目标芯片）分别与三个Key向量（已知芯片）计算余弦相似度S0、S1、S2，其中S0和S2超过阈值被标记为Informative（有效），S1低于阈值被标记为Uninformative（无效）并剪枝。最终将有效基础模型按softmax归一化后的相似度加权平均，得到聚合基础模型。这一设计的精妙之处在于：相似度计算在统一的微基准特征空间中进行，确保了目标芯片与已知芯片之间的可比性；剪枝机制则避免了不相关芯片的知识引入噪声。
:::

> 具体来说，G-Power 为每个已知芯片生成一个 Key 向量，为目标芯片生成一个 Query 向量。这两个向量的生成都基于微基准数据的线性回归系数——系数向量反映了功耗模型的特征，不同芯片的系数向量之间的余弦相似度可以度量它们的架构相似性。

**这里有一个关键的对齐设计：Key 和 Query 向量都只用微基准数据训练**，而不是像基础模型那样用全量数据。:mdnice-bold-italic[原因很直接：目标芯片只有微基准数据，Query 向量只能从微基准中学到；为了让 Key 和 Query 在同一个分布空间中可比，Key 向量也必须只用微基准数据。如果 Key 用全量数据而 Query 用微基准数据，两者的分布差异会导致相似度计算出现偏差。]

::: block-1
得到相似度之后，G-Power 先设定一个阈值，将相似度低于阈值的基础模型标记为"无信息"并剪枝，只保留相似度高的"有信息"基础模型。然后对保留的模型用 softmax 归一化相似度作为权重，加权平均得到最终的聚合基础模型。:mdnice-highlight[这个过程与注意力机制中"计算 Query-Key 相似度、softmax 归一化、加权 Value"的流程完全对应——基础模型的参数就是注意力中的 Value。]
:::

### 2.3 目标芯片微调：分组冻结的参数高效适配

> 聚合基础模型融合了多个已知芯片的知识，但它毕竟不是为目标芯片量身定制的。:mdnice-bold-italic[不同 GPU 的硬件资源规模不同（如 SM 数量、缓存大小、内存带宽），微架构设计也有差异（如 warp 调度器、Tensor Core 设计），因此需要在目标芯片上做微调。]

微调面临的核心挑战是：目标芯片只有微基准数据，数据量少，**如果直接微调全部 28 个参数，极易过拟合。G-Power 的解决方案是两级特征分组加参数比例冻结。**

![文章插图](/articles/2026-09-13-g-power-gpu-mape-14-790f33fc/images/08.jpg)

::: image-caption
图 4：目标GPU微调的参数结构。底层为聚合基础模型的28个参数p0到p27，按特征分组（Group0到Group5）组织；每组内的事件先求和得到$g_j$，再乘以可训练旋钮$\alpha_j$；最终所有组的贡献加空闲功耗$P_{idle}$得到总功耗P。微调时基础模型参数完全冻结，仅训练6个$\alpha$旋钮和截距，极大减少了可调参数数量。这一设计的本质是假设同一组内的架构事件在不同GPU之间的功耗比例保持稳定，只有整体缩放因子需要调整，从而用极少的参数完成跨芯片适配。
:::

> 具体做法是将 28 个架构事件分成若干组，每组引入一个可训练的缩放旋钮 $\alpha_j$。**微调时，基础模型的原始参数完全冻结，同一组内的参数比例保持不变，只有每组的 $\alpha_j$ 可以更新**。:mdnice-bold-italic[这样，可调参数从 28 个减少到组数加 1（$\alpha_j$ 和截距），论文中最终分为 6 组，仅需训练 7 个参数]。这种参数高效的微调策略使得在少量微基准数据上也能稳定适配，避免过拟合。

分组的依据将在下一章详细展开，这里需要理解的是：:mdnice-bold-italic[分组冻结的假设是同一组内的架构事件在不同 GPU 之间具有相似的变化趋势——它们的功耗比例相对稳定，只有整体的缩放因子需要根据目标芯片调整。这个假设基于 GPU 微架构的内在耦合性：同一域内的组件通常共享时钟域、电源域和设计范式，跨代变化时往往整体缩放而非各自独立变化。]

::: block-1
回顾一下，G-Power 的三阶段形成了一个完整的知识迁移链路：预训练从已知芯片获取全量功耗知识，注意力聚合根据相似度筛选并融合最相关的知识，微调通过分组冻结用极少参数完成目标芯片适配。:mdnice-highlight[每一阶段都针对 GPU 功耗建模的特定约束设计，共同将训练数据从"目标芯片的微基准"扩展到"所有已知芯片的全量数据"。]
:::

## 三、核心技术细节深度拆解

> 三阶段框架是 G-Power 的骨架，但真正决定效果的是其中几个关键的技术设计：28 个架构事件的选择与线性功耗建模、Key-Query 向量的对齐策略、以及两级特征分组的微架构依据。这些设计细节体现了作者对 GPU 微架构和功耗建模问题的深刻理解。

### 3.1 架构事件空间与线性功耗公式

G-Power 将 GPU 功耗建模为架构事件的线性函数，公式如下：

$$
P(\{e_i\}) = \sum_{i=1}^{N} e_i \cdot p_i + P_{idle}
$$

其中，$N$ 是架构事件的总数（论文中 $N=28$），$e_i$ 是第 $i$ 个架构事件按执行时间归一化后的计数值，$p_i$ 是该事件对应的单位功耗系数，$P_{idle}$ 是芯片的空闲功耗（即没有任何计算活动时的静态功耗和时钟树功耗）。

::: block-1
可以这么理解这个公式：**GPU 的总功耗等于"每个硬件单元干了多少活"乘以"这个单元每干一单位活耗多少电"，再加上"什么都不干时的基础耗电"。** 比如，一次 FMA（融合乘加）运算对应一个事件 $e_i$，它的系数 $p_i$ 反映了 SM 中浮点单元执行一次 FMA 的平均能耗；一次 L2 缓存读取未命中对应另一个事件，它的系数反映了未命中时需要访问更远层级存储所带来的额外能耗。
:::

![文章插图](/articles/2026-09-13-g-power-gpu-mape-14-790f33fc/images/09.jpg)

::: image-caption
表 1：G-Power 采用的 28 个架构事件，按 SM 阵列、NoC 与 L2 缓存、全局内存三个域分类。SM 域包含指令计数、各类缓存访问、ALU/Tensor Core/FMA 等执行单元访问、SM 和 Warp 活动率等 20 个事件；NoC 与 L2 域包含 L2 读写命中未命中、NoC 请求响应等 6 个事件；全局内存域包含读写 2 个事件。这 28 个事件覆盖了 GPU 主要功耗来源，同时保持了模型的简洁性。
:::

> 这 28 个事件的选择有几个考量。

- **首先，它们必须可以通过性能计数器直接测量** ——论文使用 NVIDIA Nsight Compute 采集硬件计数器，确保事件数据的准确性，避免了架构仿真器不精确带来的干扰。
- **其次，事件覆盖了 GPU 的三大功耗域**：SM 阵列是计算核心，通常占芯片功耗的最大比例；NoC 和 L2 缓存是数据流转的枢纽，在内存密集型负载中功耗显著；全局内存访问则直接对应 DRAM 的能耗。
- **最后，事件数量控制在 28 个**，在覆盖度和模型简洁性之间取得了平衡——:mdnice-bold-italic[事件太少会丢失关键功耗来源，太多则会增加过拟合风险和数据采集成本。]

::: block-1
**线性模型的选择是基于物理合理性**。每个架构事件触发的电路活动是相对固定的，事件计数与功耗之间的线性关系在架构级抽象下成立。:mdnice-highlight[更重要的是，线性模型具有良好的可解释性——每个系数 $p_i$ 的物理含义明确，可以直接指导架构师理解哪个组件是功耗热点]。
:::

### 3.2 Key-Query 向量生成的对齐设计

> 注意力聚合阶段的核心是相似度计算，而相似度的可靠性取决于 Key 和 Query 向量的质量。G-Power 的设计中有几个容易被忽略但至关重要的细节。

- **首先，Key 和 Query 向量的本质是线性回归的系数向量**。对每个已知芯片，用其微基准数据做线性回归，得到的 28 维系数向量归一化为单位向量，即为 Key 向量。对目标芯片做同样操作得到 Query 向量。:mdnice-bold-italic[用系数向量而非原始事件数据作为相似度表示，是因为系数向量浓缩了芯片的功耗特征] ——它反映了"这个芯片中各组件的相对功耗权重"，比原始事件分布更能代表架构本质。
- **其次，Key 和 Query 都只用微基准数据训练，这一对齐设计的重要性怎么强调都不为过**。如果 Key 向量用全量数据（微基准加真实负载）训练而 Query 用微基准训练，那么 Key 向量会包含真实负载下的组件耦合信息，而 Query 向量只包含微基准下的极端稀疏信息，两者不在同一个分布空间，余弦相似度就会失真。论文明确指出："否则，微基准和真实负载数据之间的分布差异会产生有偏的向量，无法作为 Query 的对等 counterpart。"
- **最后，系数向量归一化为单位向量**。这一步消除了不同芯片整体功耗规模的影响——:mdnice-bold-italic[一颗 350W 的 GPU 和一颗 150W 的 GPU，系数的绝对值差异很大，但归一化后只保留各组件之间的相对比例，这正是架构相似度应该关注的]。两颗同代架构的 GPU，即使 SM 数量不同、功耗规模不同，各组件的相对功耗比例应该相似，归一化后的余弦相似度就能捕捉到这种相似性。

### 3.3 两级特征分组的微架构依据

> 微调阶段的特征分组是防止过拟合的关键，G-Power 提出了两级分组策略：微架构感知分组和数据驱动分组。

- **第一级是微架构感知分组，按三个 GPU 域将 28 个事件粗分为三组**：SM 阵列组（20 个事件）、NoC 与 L2 缓存组（6 个事件）、全局内存组（2 个事件）。:mdnice-bold-italic[这一分组的依据是同一域内的微架构组件紧密耦合——它们通常共享时钟域、电源域和设计范式，在不同 GPU 之间变化时往往整体缩放]。比如，SM 域内的 ALU、Tensor Core、FMA 等执行单元都在 SM 内部，跨代设计时它们的相对功耗比例可能保持稳定，只有整体工艺缩放和频率变化带来的整体偏移。
- **第二级是数据驱动分组，仅在 SM 阵列域内进一步细分**。SM 域有 20 个事件，数量较多，单一分组可能过于粗糙。G-Power 将每个事件在所有样本中的取值视为一个向量，归一化为单位向量后进行层次聚类（Hierarchical Clustering）。层次聚类适合高维、少样本的场景，它根据事件之间变化趋势的相似性逐步合并，最终将 20 个 SM 事件细分为若干小组。

::: block-1
:mdnice-highlight[数据驱动分组的洞察是：两个事件如果在不同程序和不同 GPU 之间表现出相似的变化趋势，它们的功耗系数在跨芯片迁移时也应该保持相似的缩放比例]。比如，DCache 读取命中和 DCache 写入命中可能总是同时变化，因为它们都受 L1 数据缓存的设计影响；而 Tensor Core 访问和 ALU 访问可能变化趋势不同，因为它们对应不同的执行单元设计。层次聚类能自动发现这些数据层面的耦合关系，补充微架构先验知识可能遗漏的分组。
:::

两级分组的最终结果是将 28 个事件分为 6 组（SM 域内细分 4 组，加上 NoC/L2 组和全局内存组），**微调时仅需训练 6 个 $\alpha$ 旋钮加 1 个截距，共 7 个参数。相比直接微调 28 个参数，参数量减少了 75%，在微基准数据量有限的情况下显著降低了过拟合风险。**

## 四、实验结果与精度分析

> G-Power 在四款现代 NVIDIA GPU 上进行了全面评估，涵盖 Ampere 和 Ada Lovelace 两代架构，测试场景采用留一法——每次选一颗 GPU 作为目标芯片，其余三颗作为已知芯片提供预训练数据。这种评估协议最大程度地模拟了真实使用场景：当你需要为一颗新 GPU 建模时，手头已经有若干旧 GPU 的完整数据。

### 4.1 实验平台与评估协议

- 实验选用的四颗 GPU 分别是 **RTX A6000（8nm，Ampere）、RTX 3090（8nm，Ampere）、RTX 4090（5nm，Ada Lovelace）和 RTX 5880 Ada（5nm，Ada Lovelace），覆盖了两种工艺节点和两代架构**。
- 微基准使用 AccelWattch 提供的 65 个测试程序，真实负载来自 CUDA Samples 11.0、Rodinia 3.1、CUTLASS 1.3 和 Parboil 四个基准套件，拆解为独立内核后共约 30 个测试内核。

- **AccelWattch** 是当前最先进的架构级 GPU 功耗模型，采用解析模型加线性回归标定；
- **McPAT-Calib** 是 CPU 领域的代表性功耗模型，论文将其推广到 GPU 场景，使用 XGBoost 作为机器学习模型。

### 4.2 四卡测试场景的主实验结果

> 主实验结果非常清晰。在全部四个测试场景中，G-Power 的 MAPE 和相关系数 R 都全面优于两个基线。

- G-Power 平均相关系数 R 为 0.88，比 AccelWattch 的 0.52 提升了 0.36，比 McPAT-Calib 的 0.31 提升了 0.57。

分场景来看，RTX 5880 Ada 上的提升最为惊人：:mdnice-bold-italic[AccelWattch 的 MAPE 高达 70.4%，几乎完全不可用，而 G-Power 将其压到约 13%。这是因为 5880 Ada 的频率配置（SM 975MHz、内存 2250MHz）与其他 GPU 差异较大，AccelWattch 仅用微基准标定的线性模型完全无法适配这种特殊配置，而 G-Power 通过已知芯片的知识迁移和分组微调能够更好地泛化]。RTX 3090 上 G-Power 的 MAPE 约 7%，R 达到 0.93，是四个场景中精度最高的，这可能因为 3090 与 A6000 同属 Ampere 架构且工艺相同，已知芯片的知识迁移效率最高。

**McPAT-Calib 的表现也值得分析**。:mdnice-bold-italic[这个基于 XGBoost 的机器学习模型在训练集（微基准）上拟合很好，但在测试集（真实负载）上相关系数仅 0.31，说明存在严重的过拟合] 🤣。XGBoost 等非线性模型的容量大，在少量微基准数据上容易记住训练样本的特性，而无法泛化到分布不同的真实负载。**G-Power 的线性模型加分组冻结策略，本质上是用强归纳偏置来约束模型容量，反而在小数据场景下取得了更好的泛化效果。**

### 4.3 消融实验：各模块的独立贡献

> 消融实验验证了三阶段框架中每个模块的必要性。

![文章插图](/articles/2026-09-13-g-power-gpu-mape-14-790f33fc/images/15.jpg)

::: image-caption
图 8：消融实验结果，对比AccelWattch、G-Power-w/o-FT（去掉微调）、G-Power-w/o-Agg（去掉注意力聚合）和完整G-Power的MAPE。在3090上，去掉微调后MAPE从约9%飙升到62.8%；在5880上，去掉聚合后MAPE从约13%上升到69.5%，去掉微调后为18.5%。这些数据证明了微调和注意力聚合两个模块都是不可或缺的。
:::

- G-Power-w/o-FT 去掉**微调阶段**，直接用聚合基础模型作为最终模型，结果在 3090 上 MAPE 高达 62.8%，:mdnice-bold-italic[说明虽然不同 GPU 有架构相似性，但资源规模和微架构差异使得直接迁移的基础模型无法准确预测目标芯片的绝对功耗，微调是必须的。]
- G-Power-w/o-Agg 去掉**注意力聚合**，直接选择一个基础模型进行微调，结果在 5880 上 MAPE 为 69.5%，远高于完整 G-Power 的 13%。:mdnice-bold-italic[这说明并非所有已知芯片的知识都对目标芯片有用，有些芯片与目标芯片差异较大，直接使用其基础模型会引入负面迁移]。注意力聚合的相似度剪枝和加权融合能够有选择地利用最相关的知识，避免不相关芯片的干扰。

::: block-1
两个消融变体的结果共同证明：:mdnice-highlight[预训练提供知识基础，聚合筛选相关知识，微调适配目标芯片，三个阶段缺一不可。]
:::

## 五、领域影响与未来方向

> G-Power 的贡献不仅在于提出了:mdnice-bold-italic[一个更精确的 GPU 功耗模型，更在于它展示了一种在封闭生态下解决数据匮乏问题的方法论范式。这种"从已知芯片借知识、用注意力聚合迁移、靠分组冻结适配"的思路，有可能推广到 GPU 之外的其他加速器架构级建模场景。]

对于 GPU 架构设计而言，G-Power 最直接的影响是提升了架构级功耗评估的可信度。此前 AccelWattch 在现代 GPU 上 30%以上的误差，使得很多架构研究中的功耗分析结论存疑——如果模型本身不可靠，基于它得出的"某某优化降低了 15%功耗"的结论就缺乏说服力。G-Power 将误差压到 14%、相关系数提到 0.88，为架构级功耗研究提供了更坚实的评估基础。**这意味着未来的 GPU 架构论文中，功耗分析部分的可信度将显著提升**。

> 从方法论角度来说，G-Power 的跨芯片知识迁移思路有几个值得关注的延伸方向。

- 其一，:mdnice-bold-italic[已知芯片的数量和多样性如何影响模型精度——论文用了三颗已知芯片，如果增加到五颗、十颗，是否能进一步提升？尤其是当已知芯片覆盖更多架构代际和厂商时，基础模型的知识丰富度会更高。]
- 其二，注意力聚合中的相似度阈值是一个超参数，论文没有详细讨论阈值的选择策略和敏感性，未来可以探索自适应阈值或基于验证集的自动调优。
- 其三，两级特征分组目前在 SM 域内用层次聚类做数据驱动分组，**聚类的簇数也是人工设定的，是否可以用更自动化的方法确定最优分组？**

::: block-1
更宏观地看，G-Power 的思路与大模型时代的"预训练加微调"范式高度契合，但它:mdnice-highlight[用线性模型和注意力聚合实现了参数高效的知识迁移，避免了深度模型在小数据场景下的过拟合风险。] 这种"轻量模型加强归纳偏置"的设计哲学，在 EDA 和架构建模这类数据稀缺、可解释性要求高的领域，可能比盲目追求大模型更有实际价值。
:::

当然，G-Power 也有其局限性。它仍然依赖目标芯片的微基准数据来生成 Query 向量和微调，**如果目标芯片是尚未量产的纯架构设计（只有仿真器、没有真实硬件），就无法采集微基准的真实功耗标签**。此外，28 个架构事件可能无法完全覆盖新一代 GPU 中引入的新组件（如光线追踪核心、视频编解码引擎），:mdnice-bold-italic[未来需要根据架构演进动态扩展事件空间]。这些都是后续工作可以探索的方向。
