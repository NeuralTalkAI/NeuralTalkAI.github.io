## 一、静态模型的“阿喀琉斯之踵”

> 当前大语言模型的成功，建立在一种经典的“训练-部署”范式之上：模型在海量语料上完成预训练后，其权重便被“冻结”，部署时只做前向推理。**这种做法的好处是稳定、高效，但问题也同样尖锐——模型失去了根据上下文动态调整内部表征的能力。**

当你正在让模型处理一篇长达 10 万字的专业报告，在报告第 2 页出现了一个关键术语的定义，而在第 80 页需要基于这个定义进行推理。:mdnice-bold-italic[传统模型的注意力机制必须将这跨越数万 token 的依赖关系完整保留在 KV Cache 中]，这既是对显存的巨大消耗，也对长距离信息检索提出了严苛要求。

::: block-1
当然，In-Context Learning（上下文学习）提供了一种补救思路——把历史信息全塞进上下文窗口。但这不过是把问题转移到了另一个维度：**注意力机制的二次复杂度使得无限扩展上下文窗口在计算上不可行。**
:::

正是在这样的背景下，Test-Time Training（TTT） 进入了研究者的视野。**TTT 的核心理念是：在推理时，动态更新模型的一小部分参数（称为“快速权重”），让这些参数成为上下文信息的“压缩存储器”**。这样一来，模型就不必事无巨细地记住每一个 token，而是:mdnice-bold-italic[将关键信息提炼进权重中。]

> 然而，将 TTT 应用于现代 LLM 面临着三座难以逾越的大山：

1. **架构不兼容**：已有的 TTT 方法大多需要引入专门的循环层来替代注意力机制，:mdnice-bold-italic[这意味着必须“从零开始”预训练，无法复用现有的大模型资产；]
2. **计算效率低下**：经典的 TTT 采用逐 token 更新策略，这严重:mdnice-bold-italic[限制了 GPU/TPU 的并行能力；]
3. **学习目标错位**：现有 TTT 普遍采用“重构”作为自监督目标——让模型记住当前 token 的表征，但这与语言模型“预测下一个 token”的根本目标并不一致。

::: block-1
In-Place TTT 的诞生，正是为了同时搬走这三座大山。
:::

## 二、In-Place TTT：三管齐下的破局之道

### 2.1 核心洞察：征用 MLP，而非替换 Attention

> In-Place TTT 最关键的洞见在于：**TTT 的“快速权重”** 并不必须是某个新模块的参数，它**可以“寄生”在已有模块之中。**

回顾 Transformer 的结构，多层感知机（MLP）块占据了模型参数的大头。更重要的是，:mdnice-bold-italic[已有研究表明，Transformer 中的 MLP 层本质上扮演着一种键值记忆的角色——它存储着预训练阶段学到的海量通用知识（作为“慢速权重”）]。

那么，为什么不让这同一套参数系统，在推理时也承担起存储上下文信息（作为“快速权重”）的职责呢？

具体来说，**In-Place TTT 选择了门控 MLP 结构中的最终投影矩阵 $\mathbf{W}_{\text{down}}$ 作为被更新的对象**。门控 MLP 的计算公式如下：

$$
\mathbf{O} = \left( \phi(\mathbf{H}\mathbf{W}_{\text{gate}}^{\top}) \odot (\mathbf{H}\mathbf{W}_{\text{up}}^{\top}) \right) \mathbf{W}_{\text{down}}^{\top}
$$

其中，$\mathbf{H}$ 是输入隐状态，$\phi$ 是激活函数（如 SiLU），$\mathbf{W}_{\text{up}}$ 和 $\mathbf{W}_{\text{gate}}$ 是输入投影矩阵，$\mathbf{W}_{\text{down}}$ 是输出投影矩阵。

::: block-1
在 In-Place TTT 框架下，$\mathbf{W}_{\text{up}}$ 和 $\mathbf{W}_{\text{gate}}$ 保持冻结（作为慢速权重），而 $\mathbf{W}_{\text{down}}$ 则被征用为快速权重，在推理时动态更新。
:::

这种“原位”设计的精妙之处在于：

- **零架构改动**：不需要在模型中插入任何新层，:mdnice-bold-italic[完全保留预训练模型的完整性；]
- **热启动友好**：:mdnice-bold-italic[可以从任何预训练 checkpoint 直接开始]，无需昂贵的重新训练；
- **注意力机制的完美搭档**：由于注意力层被完整保留，In-Place TTT 不需要像其他 TTT 方法那样承担“token 混合”的职责，这为后续的“大块更新”策略铺平了道路。

### 2.2 大块更新：让并行计算真正“吃饱”

> 传统 TTT 的逐 token 更新机制有一个致命缺陷：序列依赖。要处理第 $i$ 个 token，必须先完成前 $i-1$ 个 token 的更新——这几乎摧毁了 GPU 最擅长的并行能力。

**In-Place TTT 彻底绕开了这个陷阱**。由于注意力机制已经负责了细粒度的 token 交互，**MLP 的快速权重更新可以采用一种更“粗放”的策略：分块更新**。具体流程如下：

![文章插图](/articles/2026-04-10-in-place-ttt-llm-ae633061/images/03.webp)

::: image-caption
图 1：In-Place TTT 整体框架。模块按顺序处理输入块。对每个块，当前的快速权重首先作用于中间激活 $\mathbf{Z}$ 产生输出，然后这些权重利用 $\mathbf{Z}$ 和从 token 嵌入派生的值 $\mathbf{V}$ 进行更新。这种“先应用-后更新”的循环，让模型以严格因果的方式动态适应输入上下文。
:::

对于长度为 $n$ 的序列，首先将中间激活 $\mathbf{Z} = \phi(\mathbf{H}\mathbf{W}_{\text{gate}}^\top) \odot (\mathbf{H}\mathbf{W}_{\text{up}}^\top)$ 和目标值 $\mathbf{V}$ 划分为 $k$ 个大小为 $C$ 的不重叠块。对第 $i$ 个块：

1. 应用操作：用当前快速度权重 $\mathbf{W}_{\text{down}}^{(i)}$ 处理该块，得到输出 $\mathbf{O}_{[i]} = \mathbf{Z}_{[i]} \left( \mathbf{W}_{\text{down}}^{(i)} \right)^{\top}$
2. **更新操作：计算梯度并更新快速权重：**$\mathbf{W}_{\text{down}}^{(i+1)} = \mathbf{W}_{\text{down}}^{(i)} - \eta \nabla*{\mathbf{W}} \mathcal{L}\left( \mathbf{Z}*{[i]}(\mathbf{W}_{\text{down}}^{(i)})^{\top}, \mathbf{V}_{[i]} \right)$

这种块级更新的优势是双重的：

- 并行友好：块内的 token 可以同时处理，大幅提升硬件利用率；
- 大块可行：由于注意力层依然存在，In-Place TTT 不需要小块来保证 token 混合质量。实验表明，块大小 $C=512$ 或 $1024$ 时效果最佳，见后文图 3b。

![文章插图](/articles/2026-04-10-in-place-ttt-llm-ae633061/images/04.webp)

::: image-caption
图 3 针对原位TTT框架关键设计选型的消融实验，采用17亿参数模型在RULER基准数据集上进行评估。图表展示了以下因素的影响：(a) 状态维度，表明性能随状态维度增大而提升；(b) 分块大小，体现出性能权衡特性，其中中等大小（如512、1024）为最优取值；以及(c) 大模型对齐价值目标，证实卷积操作（带卷积）与投影操作（带投影）均至关重要。
:::

### 2.3 语言建模对齐目标：从“记住当下”到“预见未来”

> 解决了架构和效率问题后，剩下的最后一道关卡是：快速权重究竟该学什么？

已有的 TTT 方法普遍采用重构目标：让模型学会将 key $k_i$ 映射回某个 value $v_i$，其中 $v_i$ 通常是从当前输入 token $x_i$ 本身派生而来。这相当于让模型“记住”自己看到了什么。

::: block-1
In-Place TTT 团队认为，对于语言建模任务，这种目标是不够的。**一个更合理的策略是：让快速权重存储对未来预测有用的信息。**
:::

基于这一动机，他们设计了一个全新的语言建模对齐目标：

$$
\hat{\mathbf{V}} = \text{Conv1D}(\mathbf{X}_0) \mathbf{W}_{\text{target}}
$$

其中，$\mathbf{X}_0$ 是 token 嵌入矩阵，$\mathrm{Conv1D}(\cdot)$ 是一维卷积操作，$\mathbf{W}_{\text{target}}$ 是可训练的投影矩阵。这个公式的美妙之处在于：

- **通过卷积，目标值 $\hat{\mathbf{V}}$ 可以包含未来 token 的信息；**
- **通过投影，模型可以学习从嵌入空间到目标空间的最优映射。**

> 举例来说，如果要实现“下一 token 预测”目标，只需将卷积核的权重设置为：下一 token 位置为 1，其他位置为 0，并将 $\mathbf{W}_{\text{target}}$ 设为单位矩阵。

在这个目标下，损失函数采用简单的相似性度量 $\mathcal{L}(\cdot, \cdot) = -\langle \cdot, \cdot \rangle*F$，快速权重的更新规则可以直接推导为：

$$
\mathbf{W}*{\text{down}}^{(i)} = \mathbf{W}_{\text{down}}^{(i-1)} + \eta \hat{\mathbf{V}}_{[i]}^{\top} \mathbf{Z}_{[i]}
$$

::: block-1
这个更新规则不仅计算简单，**更重要的是，它具有良好的结合律** ——这为后续的**上下文并行实现提供了理论基础。**
:::

### 2.4 理论保证：为什么 LM 对齐目标更优？

> 为了给上述设计提供理论支撑，研究团队在经典的**归纳头** （Induction Head）设定下进行了严谨分析。

**设定**：序列中某位置 $t^{*}$ 出现了键值对 $(k^{*}, v^{*})$，后续在查询位置 $n$ 再次出现 $k^{*}$，模型需要正确预测 $v^{*}$。

::: block-1
举个例子，当你在读一篇文章，前面出现过“奥巴马的夫人是米歇尔”。当文章后面再次提到“奥巴马”时，模型应该能自然地补全“米歇尔”。

这里的“奥巴马”就是键 $k^{*}$，“米歇尔”就是值 $v^{*}$。这个能力就是归纳头——一种从上下文中“复制粘贴”已知关联的机制，被广泛认为是语言模型实现上下文学习的基础。
:::

**假设**：

1. **不同 token 的嵌入近似正交**。模型为不同词语分配的向量几乎是“各走各的路”，就像词典里每个词都有独立编号，互相之间不会意外撞车。这保证了当我们想更新“米歇尔”的信息时，不会不小心把“奥巴马”的表征给改乱了。；
2. **相同 token 在不同位置的中间激活具有正相关性**。同一个词无论出现在文章开头还是结尾，模型内部对它的“感知”都是相似的。比如两处“奥巴马”在网络中间层的激活模式会呈现出正向关联，这为跨越长距离的信息传递提供了“暗号”。

在这些假设下，**定理 1** 给出了两种目标下正确 token 的 logit 期望变化：

| 目标类型 | 正确 token 的 logit 变化 |
| --- | --- |
| LM 对齐目标 | $\mathbb{E}[\Delta \ell_n[v^{*}]] \geq \lambda_{\mathrm{lr}} \cdot c_{\mathrm{norm}}^{2} \cdot c_{\mathrm{align}}$ |
| 重构目标 | $|\mathbb{E}[\Delta \ell_n[v^{*}]]| \leq \lambda_{\mathrm{lr}} \cdot \epsilon \cdot c_{\mathrm{align}}$ |

> 这两个公式看起来有点抽象，我们用“奥巴马和米歇尔”的例子来拆解一下。

- **LM 对齐目标（看下一步）**：当模型第一次读到“奥巴马”时，它做的不是把“奥巴马”这三个字存起来，而是**悄悄看了一眼紧随其后的“夫人是米歇尔”**，并把这个“预见到的未来”压缩进快速权重里。等到后文再次出现“奥巴马”时，快速权重里存着的正是“米歇尔”的特征向量。:mdnice-bold-italic[两处“奥巴马”的激活正相关（假设 2），就像对上暗号，于是快速权重顺势把“米歇尔”的 logit 推高]。这个推力的大小，取决于“米歇尔”这个向量自身的长度平方 $c_{\mathrm{norm}}^{2}$ 和两处“奥巴马”的关联强度 $c_{\mathrm{align}}$，因此**提升非常明显**。
- **重构目标（只看脚下）**：当模型第一次读到“奥巴马”时，它老老实实地把“奥巴马”本身的特征存进了快速权重。等到后文再次出现“奥巴马”时，快速权重里掏出来的还是“奥巴马”的特征，可模型此时要预测的却是“米歇尔”。:mdnice-bold-italic[根据假设 1，不同词语的向量几乎正交——“奥巴马”和“米歇尔”的向量指向截然不同的方向，内积小得可怜（受 $\epsilon$ 控制）]。于是，这次“掏东西”的动作几乎没能帮上“米歇尔”任何忙，**logit 的提升微乎其微。**

::: block-1
在 LM 对齐目标下，正确 token 的 logit 在期望上被显著提升（与 $c_{\mathrm{norm}}^{2}$ 成正比）；而在重构目标下，提升几乎可以忽略（只与极小的 $\epsilon$ 相关）。
:::

这从根本上解释了为什么“预见未来”比“记住当下”更能助力语言建模。

## 三、工程实现：上下文并行与因果性保证

理论优雅是一回事，工程高效是另一回事。In-Place TTT 在实现层面同样下足了功夫，尤其是在上下文并行的支持上。

### 3.1 并行扫描：把“串行”变成“并行”

> 更新规则 $\mathbf{W}_{\text{down}}^{(i)} = \mathbf{W}_{\text{down}}^{(i-1)} + \eta \hat{\mathbf{V}}_{[i]}^{\top} \mathbf{Z}_{[i]}$ 的结合律特性，使得 In-Place TTT 天然适合并行扫描（Parallel Scan）算法。具体流程如下：

![文章插图](/articles/2026-04-10-in-place-ttt-llm-ae633061/images/05.webp)

::: image-caption
算法 1：In-Place TTT 上下文并行算法（单层）。该算法给出单层In-Place TTT的上下文并行实现逻辑，分并行计算增量、前缀和聚合、并行应用更新三步，因果填充保证时序合法性，文档边界重置权重避免上下文泄露。算法将串行更新转化为并行操作，数学等价于严格因果流程，既适配现代加速器的并行特性，又保证推理正确性。这是框架高效落地的核心代码逻辑，从算法层面解决了传统TTT计算低效的核心痛点。
:::

该算法将序列沿长度维度分区，通过三步实现完全因果且高度并行的更新。这个实现的关键在于：

- 分块内并行：每个块内的 token 同时处理；
- 块间并行：不同块的 $\Delta\mathbf{W}$ 计算完全独立，可以跨设备并行；
- 前缀和加速：步骤 2 的累积求和在现代加速器上有高度优化的实现（如 NVIDIA CUB 库）。

![文章插图](/articles/2026-04-10-in-place-ttt-llm-ae633061/images/06.webp)

::: image-caption

### 3.2 因果性与边界处理

> 在追求效率的同时，In-Place TTT 没有牺牲因果性：

- 因果填充：在生成目标值 $\mathbf{V}$ 时，1D 卷积采用因果填充，确保每个位置只能看到当前及之前的 token；
- 边界重置：在文档边界处，快速权重重置为预训练初始值，防止跨文档的信息污染；
- 数学等价：整个并行算法在数学上与严格串行的逐块更新完全等价。

2. 从零开始预训练与主流 TTT 方法的对比；

## 五、相关工作：站在巨人的肩膀上

In-Place TTT 并非横空出世，它站在多条研究脉络的交汇处。

### 5.1 Test-Time Training 的演进

> TTT 的概念最早在计算机视觉领域崭露头角——Sun 等人提出在测试时通过自监督任务（如旋转预测）更新模型部分参数，以应对分布偏移。随后，这一思想被迁移到语言领域，TTT-LM 等工作尝试用类似机制增强语言模型的上下文处理能力。

然而，早期的 TTT 实现存在两个瓶颈：

1. 逐 token 更新的串行性：严重限制了并行效率；
2. 重构目标的局限性：与语言建模的因果预测本质不完全匹配。

Behrouz 等人提出的 Titans 和 Zhang 等人提出的 LaCT 开始探索分块更新，部分缓解了效率问题。:mdnice-bold-italic[但在这些工作中，TTT 模块仍然是作为注意力替代品设计的]，这导致它们必须使用较小的块来保证 token 混合质量，且无法复用现有预训练模型。

::: block-1
**In-Place TTT 的关键突破在于：将 TTT 从“替代者”转变为“增强者”**。通过征用 MLP 而非替换 Attention，它既保留了预训练模型的核心能力，又获得了使用大块更新的自由。
:::

### 5.2 高效长上下文架构

> 另一条与本文密切相关的脉络是高效长上下文架构的研究，主要包括三大流派：

- 稀疏注意力：Longformer、Sparse Transformer 等通过限制注意力范围（如滑动窗口、扩张窗口）来降低复杂度。:mdnice-bold-italic[优点是简单直接，缺点是牺牲了全局交互能力；]
- 线性注意力与状态空间模型：Linear Transformer、Mamba、GLA 等将注意力近似为核函数形式，或使用结构化状态空间来压缩历史。:mdnice-bold-italic[优点是线性复杂度，缺点是在某些任务上表达能力不如标准注意力；]
- 基于 Delta 规则的记忆增强：DeltaNet 等工作将快速权重更新形式化为 Delta 规则，实现了高效的并行化。

**In-Place TTT 与这些工作并非竞争关系，而是互补关系**。事实上，In-Place TTT 可以自然地集成到任何有 MLP 层的架构中——无论是标准 Transformer、滑动窗口变体，还是 Mamba 类的状态空间模型。**这种“架构无关”的特性使其具有广泛的适用前景。**

### 5.3 记忆增强神经网络

> 从更高维度看，TTT 可以理解为一种特殊的记忆增强机制——用参数作为动态记忆的载体。

这与 Neural Turing Machines、Memory Networks 等:mdnice-bold-italic[经典工作一脉相承，也与近期 MemoryLLM 等为 LLM 增加外部记忆的尝试有共同的精神内核。]

**区别在于：In-Place TTT 的记忆是内嵌于模型权重之中的，而非外挂的记忆库**。这使其更加轻量，且与模型原有计算流程无缝融合。

## 六、结语：迈向“持续学习”的新范式

> In-Place TTT 的出现，为大语言模型从“静态部署”走向“动态进化”打开了一扇门。它的贡献可以总结为三个层面：

- 方法层面：提出了一种“原位”TTT 设计，无需改动架构、无需重新训练，即可让任意预训练 LLM 获得推理时学习能力；
- 理论层面：首次从归纳头的角度分析了不同 TTT 目标对语言建模的影响，为后续研究提供了可参考的理论框架；
- 工程层面：实现了与上下文并行兼容的高效分块更新算法，在几乎不影响推理效率的前提下大幅提升长上下文表现。

> 当然，这项工作也留下了值得进一步探索的问题：

- **优化器的选择**：当前使用的是最简单的单步梯度下降，更复杂的优化器（如带动量的更新）是否能带来进一步提升？
- **遗忘机制**：当前的快速权重只会“累加”不会“遗忘”，这是否会在极长序列（如百万 token 级别）下导致信息过载？
- **多模态扩展**：这种“原位 TTT”的设计是否能迁移到视觉-语言模型中？

正如论文结尾所言：“我们的工作向 LLM 的持续学习新范式迈出了充满希望的一步。”在可以预见的未来，一个能够边推理边学习、与用户和环境持续交互进化的模型，或许不再是科幻。

::: block-1
对于 AI Infra 从业者而言，In-Place TTT 也提供了一个有趣的信号：:mdnice-bold-italic[未来的推理系统可能需要支持“带状态的推理”——模型权重不再是只读的，而是会在推理过程中被局部更新。这对推理引擎的设计、分布式部署策略、乃至硬件架构都提出了新的挑战与机遇。]
:::
