## 一、LLM 训练的 “隐形门槛”：稀缺的公开经验

> 过去数年，“缩放”（Scaling） 成为 LLM 研究的核心关键词。

研究早已证实，**在数据充足的前提下，模型参数规模的扩大能稳定提升下游任务性能**。但这份性能提升的背后，是模型与数据集双重膨胀带来的算力重压：更大的模型需要更多计算资源支撑，更海量的数据则进一步加剧了训练负担。

![文章插图](/articles/2025-09-25-llm-5-350m-128-256-a94d9a1a/images/04.webp)

**遗憾的是，前沿企业对训练细节的 “保密” 让行业陷入困境**。从见表 I中可见，OpenAI、Google 等公司发布的新一代模型，不仅参数规模成谜，训练流程、架构设计等关键信息更鲜少公开。这使得其他研究者在推进类似项目时，只能在分布式数据访问、瓶颈排查、并行优化等问题上 “摸黑前行”。

> MIT 团队的研究正是为了打破这种僵局 —— 他们以二进制代码为训练数据，搭建类 BERT 编码器模型，从单 GPU 的小规模试验到 128 节点、256 块 GPU 的大规模训练，完整记录了缩放过程中的关键发现。

## 二、支撑实验的 “硬核底座”：TX-GAIN 超算集群

任何大规模 LLM 训练都离不开强韧的超算基础设施，本次实验的 “主战场” 是 MIT 林肯实验室超算中心（LLSC）的 TX-GAIN 集群。作为 TX-Green 超算的重要组成部分，这个 2025 年初夏部署的集群在当年 6 月的 Top500 榜单中位列第 114 名，硬件配置堪称 “量身定制”：

::: block-1
- 316 个 HPE 计算节点构成了集群的核心，每个节点搭载双 AMD EPYC 24 核 CPU 与 768GB 内存，更关键的是配备了两块 Nvidia H100-NVL GPU—— 每块 GPU 拥有 94GB 高带宽显存（HBM），且通过 NV-Link 桥实现节点内双 GPU 的高速互联。
- 存储与网络层面，节点既挂载了 Lustre 并行存储阵列，又自带 3.8TB 本地 SSD；25GbE 汇聚以太网链路连接至无阻塞核心交换机，为数据传输提供了充足带宽。
:::

正是这样的硬件基础，让从 120M 参数到 350M 参数的模型缩放实验成为可能。

## 三、缩放路上的 “通关指南”：从数据到并行的实践智慧

> 模型与数据集的缩放绝非简单的 “规模叠加”，团队在实验中遭遇的首个卡点便是数据管理，而并行策略的优化更藏着提升 GPU 利用率的关键密码。

### 3.1 数据预处理：99% 压缩率的 “减负魔法”

实验所用的数据集包含 2020 万个二进制代码函数样本，原始大小接近 2TB。如何让数百个节点高效访问这些数据，成为训练启动前的第一道难题。团队通过两项关键操作，彻底解决了数据瓶颈：

1. **预处理 “瘦身”，保留核心信息**：原始数据中大量函数内容压缩效率极低，占用了绝大部分存储空间。团队提前完成全量数据的预处理与 token 化，仅保留训练必需的 token 化输入与注意力掩码。这一操作让数据集从 2TB 锐减至 25GB，压缩率高达 99%，彻底摆脱了原始数据的存储与传输负担。
2. **节点本地复制，避免网络拥堵**：尽管数据体积大幅缩减，团队仍选择将数据集复制到每个节点的本地 SSD。虽然初期需要承担从网络存储到本地存储的拷贝成本，但却彻底避免了训练过程中数百节点争抢网络与共享存储资源的问题 —— 这种 “一次性投入换持续高效” 的策略，为 GPU 满负荷运行扫清了障碍。

### 3.2 并行优化：找准 GPU 利用率的 “平衡点”

> 解决了数据问题，并行策略的调优成为提升效率的核心。:mdnice-bold-italic[从单 GPU 到多节点，团队逐步摸索出三条关键经验]：

1. **数据加载并行：“够用即好” 的效率哲学**：单 GPU 训练初期，团队发现 GPU 利用率会频繁在峰值与 0% 之间波动 —— 数据加载速度跟不上计算速度，导致 GPU 频繁 “空转”。通过逐步增加并行数据加载器数量，他们最终让 GPU 利用率稳定在 100%，同时也明确了 “过犹不及” 的原则：加载器数量一旦超出需求，只会造成资源浪费（最优数量需在批大小优化后确定）。
2. **多节点数据并行：网络并非 “卡脖子” 元凶**：借助 PyTorch Lightning 实现多节点训练后，实验呈现出意外发现：![文章插图](/articles/2025-09-25-llm-5-350m-128-256-a94d9a1a/images/05.webp)如图 1 所示，即便扩展到 128 个数据并行节点，训练性能仍随节点数量呈近似线性增长。这意味着，在该训练场景下，模型仍处于 “GPU 计算受限” 状态，而非被权重更新时的网络传输瓶颈所制约 —— 这一结论打破了 “多节点训练必受限于带宽” 的固有认知。
3. **模型规模与批大小：不可忽视的隐性关联**：当固定 128 个节点、仅扩大模型规模时，训练效率出现了下滑。原因在于，更大的模型（如 350M 参数）占用更多 GPU 显存，迫使批大小不得不缩减：120M 参数模型的批大小可达 184 个样本，而 350M 参数模型仅能降至 20 个。团队指出，若要进一步缩放模型，必须引入模型并行技术并开展针对性调优。

## 四、结语：为 LLM 缩放提供 “可复制的经验”

LLM 预训练的缩放之路充满隐性陷阱，而公开的实践经验正是穿越陷阱的 “指南针”。MIT 团队的研究虽未聚焦于模型本身的创新，却:mdnice-bold-italic[通过真实实验提炼出 5 条核心建议：全量预处理 token 化、节点本地复制数据、按需设置数据加载并行度、善用数据并行的线性缩放特性、关注模型规模对批大小的影响。]

这些来自一线的实操智慧，填补了公开文献在 LLM 缩放实践上的空白。对于那些试图推进自定义 LLM 预训练的研究者而言，这份 “避坑指南” 不仅能帮助他们少走弯路，更能让宝贵的 GPU 算力得到充分利用 —— 在算力成本居高不下的今天，这样的经验或许正是推动 LLM 技术普惠的关键一步。
