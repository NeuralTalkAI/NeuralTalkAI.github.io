## 一、稀疏注意力的性能瓶颈

### 1.1 稀疏注意力为何未能充分释放性能

> 自注意力因计算、内存与 IO 的二次方级开销，成为大模型扩展长上下文能力的核心瓶颈，这也推动了高效注意力机制的研究热潮。其中**稀疏注意力极具应用潜力，该机制仅关注筛选出的部分键值缓存，在保留强大建模能力的同时，避免了常规注意力随上下文增长出现的计算与 IO 开销陡增问题。**

但稀疏注意力（通常采用 Top-K 筛选方式）并未消除**内存容量瓶颈**。实际应用中，即便解码步骤仅激活少量缓存条目，全上下文的 KV 缓存仍需留存于 GPU 高带宽内存中以保证快速访问。这使得稀疏注意力常受显存容量限制而非计算能力限制，进而制约了批处理大小与整体吞吐量。**如下图所示，基准方案（未搭载 HiSparse 的稀疏注意力）的 token 生成吞吐量会快速趋于平稳，原因是 KV 缓存占用空间迅速触及 GPU 显存容量上限。**

![文章插图](/articles/2026-04-12-5-hisparse-gpu-61094881/images/03.webp)

::: image-caption
在PD同址部署的8×H200集群上，采用32k输入、8k输出查询对GLM-5.1-FP8模型[1]进行的基准测试结果。该图核心揭示了内存瓶颈对稀疏注意力的限制与 HiSparse 的突破。基线模型因 KV 缓存快速触及 GPU 内存上限，吞吐量早早进入平台期；而 HiSparse 通过分层内存管理，实现吞吐量随并发度近线性增长，256 并发时达 3 倍提升。低并发下的小幅开销源于稀疏 KV 加载的额外 I/O，但高并发场景中内存压力占主导，其内存节省优势凸显，证明 HiSparse 在长上下文高并发场景中能有效突破容量限制，为 LLM 大规模部署提供了性能扩容路径。
:::

相比之下，**HiSparse 的吞吐量随并发量提升呈近线性增长，在 256 并发请求场景下吞吐量达到基准方案的 3 倍以上**。值得注意的是，低并发场景下 HiSparse 会产生小幅额外开销，原因是:mdnice-bold-italic[稀疏 KV 加载带来的额外 IO 开销超过了显存节省收益；而当并发量提升、显存压力成为主导因素后，性能增益会显著凸显。]

::: block-1
该基准测试直观体现显存瓶颈对稀疏注意力的硬性制约，HiSparse 通过分层内存打破显存上限，实现高并发下吞吐量的线性增长。
:::

## 二、HiSparse 架构设计

### 2.1 HiSparse 整体设计

> 与我们此前 HiCache[2] 研究成果一脉相承，本次提出的 HiSparse 是一套专为破解上述瓶颈设计的分层内存系统。

- HiSparse 主动将非活跃的 KV 缓存条目卸载至主机内存，大幅缓解 GPU 显存压力；
- 同时在 GPU 高带宽内存中维护热点设备缓存区，存放高频访问的 KV 缓存区域，以此最小化关键路径上的数据迁移开销。

![文章插图](/articles/2026-04-12-5-hisparse-gpu-61094881/images/04.webp)

::: image-caption
HiSparse 针对 LLM 推理的分层内存管理架构，核心分为预填充（Prefill）和解码（Decode）两大实例模块。预填充实例通过 Staging KV Cache 将全量 KV 缓存暂存至主机内存，为解码实例提供数据支撑；解码实例则以主机内存存储完整 KV Cache 为基础，依托 Top-K Selector 筛选高频访问条目，再通过 Swap-in Kernel 将热数据迁入 GPU HBM 构成的 Hot Device Buffer，供解码实例的 Model Executor 计算，计算后新的 KV Cache 会回写至主机内存，形成 “主机存全量、GPU 存热点” 的分层缓存机制，实现内存资源的高效调度。
:::

::: block-1
该设计可支持更大的解码批处理大小，在扩展上下文长度的同时提升推理吞吐量。上图展示了 HiSparse 的工作流程，即便架构图采用预填充-解码分离部署形式，该设计同样适用于同节点部署场景。
:::

冷热缓存分离的分层设计，平衡了显存占用与数据访问延迟，是 HiSparse 实现性能突破的核心逻辑。

### 2.2 高效数据换入内核

> 该系统的核心是一款专用 CUDA 内核，可高效完成三项操作：

1. 识别设备缓存区内的 Top-K 缓存缺失条目；
2. 通过 LRU 最近最少使用策略筛选待淘汰缓存条目；
3. 更新页表并将所需缓存条目从主机内存加载至 GPU 内存。

**下图展示了热点缓存区大小与淘汰策略对缓存缺失率的影响**。采用更大容量的 GPU 热点缓存区（4096 Slot 对比 2048 Slot）并搭配 LRU 淘汰策略时，缓存缺失次数大幅下降，直接降低了关键路径上的数据换入延迟。

![文章插图](/articles/2026-04-12-5-hisparse-gpu-61094881/images/05.webp)

::: image-caption
图 2：DeepSeek-V3.2 模型[3]（top-k=2048）在 LongBenchV2 上的缓存未命中率基准测试结果，未命中次数采用 100 步滚动窗口进行平滑处理。该图量化了热缓冲区大小与淘汰策略对性能的关键影响。更大的设备缓冲区（4096 槽 vs 2048 槽）能缓存更多高频访问 KV 条目，而 LRU 策略贴合实际访问时序特征，二者结合显著降低未命中次数。未命中率直接关联 swap-in 延迟，减少关键路径上的数据移动开销，这是 HiSparse 保障稀疏注意力性能的核心优化。结果表明，合理配置缓存参数可大幅提升数据访问效率，为分层内存系统的参数调优提供了量化依据。
:::

该缓存缺失次数基准测试基于模型（Top-K=2048），在 LongBenchV2 数据集上完成，测试结果通过 100 步滚动窗口进行平滑处理。

**缓存容量与淘汰策略直接决定缓存效率**，LRU 策略结合大容量热点缓存，可大幅减少跨层级数据迁移的性能损耗。

## 四、未来研究方向

### 4.1 性能优化与模型拓展

> HiSparse 目前支持采用 DeepSeek Sparse Attention (DSA)[5] 架构的模型家族，包括 DeepSeek-V3.2 与 GLM-5.1。作为实验性功能，团队将持续优化其性能并拓展适配的模型范围。HiSparse 专为高并发场景设计以最大化吞吐量，:mdnice-bold-italic[但 Top-K 缓存缺失带来的额外 IO 操作仍会产生一定开销。]

**团队计划通过更优的任务重叠方式降低该开销**，同时认为 Grace Blackwell（GB）等新一代平台更高的 CPU-GPU 带宽，将进一步缓解这一问题。

未来，团队将延续此前 HiCache 的研究方向，把分层内存管理方案拓展至更多新兴架构，包括Hybrid Model[6]架构。
