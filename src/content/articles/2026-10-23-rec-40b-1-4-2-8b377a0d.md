## 二、rec 只服务一个模型：为 Flint 定制的本地推理引擎

> llama.cpp、Ollama 这类通用推理框架要兼容成百上千种模型架构，**rec 走了另一条路：整个引擎只为 Flint 一个模型服务**。官方文档对 rec 的定义是"Recursive 本地推理引擎的命令行工具，为在 Mac 上快速运行 Flint 优化"，它做三件事：下载模型、启动本地 server、把 server 接到编码工具上。

这个定位带来两个直接结果。

- 一是优化可以做得很深：kernel 按 Flint 的架构和权重格式定制，不需要为兼容性留余地。
- 二是使用上做得很薄：用户不需要懂推理参数，一条 `rec launch pi` 命令就完成了从模型下载、server 启动到编码工具配置的全部流程。

rec 的交付形态是"引擎 + server + harness 一键连接"。server 在本机 11500 端口暴露一个 OpenAI 兼容的 Chat Completions 接口，模型 ID 就叫 `flint`。官方推荐的编码工具是 Pi，文档引述非正式使用反馈：**Pi 的 harness 更轻，整体编码工作流比 OpenCode 快约 1.5 倍——官方同时说明这个数字随任务、硬件和配置变化，指的是整体工作流而非模型本身的速度。**

::: block-1
:mdnice-highlight[有一个设计取向需要留意：rec 为单会话场景优化。引擎一次只处理一个生成请求，重叠请求会收到 HTTP 429]。想同时跑多个 agent 的用户，官方建议改用文档里的其他运行方式（vLLM、SGLang 等）。**这个取舍和"本地个人编码助手"的场景匹配，也再次说明 rec 的目标不是替代服务器端推理框架。**
:::

## 四、快从哪来：架构、量化、kernel 三层都由自动化研究系统搜出来

> **rec 的快，一半来自引擎实现，另一半来自 Flint 模型本身就是按"在本地硬件上跑得快"这个目标设计出来的**。公告把模型构建栈的三层优化都记在自动化研究系统 Eureka Machine 头上。

### 4.1 架构：40B 总参只激活 2.5B

架构搜索的目标函数直接对着本地硬件的吞吐。:mdnice-bold-italic[Eureka Machine 从 35B 总参、3B 激活的基线出发，搜索不同的专家配置和宽度，最后选定 40B 总参、每 token 激活 2.5B 的方案——在测试过的配置里，这个方案预计是速度和编码能力组合最好的一个]。激活参数从 3B 压到 2.5B，意味着每个 token 要读的权重更少，decode 阶段的内存带宽压力直接下降。

### 4.2 量化：输出层也压到 4 bit

量化环节有一个反常规的决定。

业界惯例是把输出层（lm_head）保留在高精度，Eureka Machine 把它也量化到了 4 bit。理由是 Flint 每 token 只激活 2.5B 参数，输出层在每个 token 要读取的权重里占比很大，压它就压在了吞吐的痛点上。

**精度损失用一个离线蒸馏阶段补回来**：量化后的模型在自己预采样的回答上训练，这些回答来自系统自己发现的核心样本集（coreset），16 bit 模型当教师。这一步比公司原有的量化感知训练基线省了近一半训练步数。最终 NVFP4 模型在各基准上和 16 bit 模型的分差在 0.7 分以内。

### 4.3 kernel：Metal megakernel 融合整个 decode 前向

::: block-1
kernel 层，Eureka Machine 为量化后的模型在 Apple Silicon 和 RTX Spark 上生成了专用 kernel，覆盖低比特投影、MoE 算子、attention 和提示词处理。**在 M4 和 M5 芯片上，它产出一个 Metal megakernel，把整个 decode 前向传播融合进单个 kernel——中间结果不用反复进出内存**，这是长上下文下 rec 对 llama.cpp 优势拉大的直接原因。
:::

三层优化串起来看，方法论的线索很清楚：**架构搜索减少每 token 要算的参数量，量化减少每 token 要读的字节数，megakernel 减少计算过程中的内存往返**。三件事都在围着本地硬件真正的瓶颈——内存带宽——做文章。

## 五、安装只要一行命令，门槛是 48GB 统一内存

### 5.1 安装与命令

rec 目前只支持 Apple Silicon Mac，要求是 M4 Pro、M5 Pro 或 M5 Max 芯片、至少 48GB 统一内存、约 30GB 空闲磁盘，另外需要 Node.js 22 和 npm（用于启动 Pi 或 OpenCode）。安装脚本会校验芯片和内存，不达标的机器不会下载模型：

```
curl -fsSL https://raw.githubusercontent.com/recursive-oss/rec/main/install.sh | bash
```

装完开一个新终端，`rec doctor` 检查环境，然后在项目目录里 `rec launch pi` 就能开始用。首次运行会下载模型和配套版本的 Pi，不需要单独装 Pi、不需要手动配 provider。

![文章插图](/articles/2026-10-23-rec-40b-1-4-2-8b377a0d/images/09.jpg)

::: image-caption
表 1：rec 的全部命令，整理自官方文档与仓库 README。日常使用只涉及三个：`rec launch pi` 开工、`rec status` 看状态、`rec stop` 收工。模型 server 在关闭编码工具后会继续运行，所以收工时记得 stop。`rec pull` 适合提前把约 30GB 的模型下好，`rec exec` 用来执行 harness 自身的命令（比如给 Pi 装插件），`rec uninstall` 会列出要删除的内容并二次确认。（数据来源：rec 官方文档[10]）

### 5.3 Mac 先行，RTX Spark 支持在路上

> 文档里明确写着：rec 对 NVIDIA RTX Spark 的支持即将推出（coming soon），目前的安装说明只适用于受支持的 Mac。

NVIDIA 同日的官方帖透露了更多信息：Flint 在 GB300 NVL72 上完成训练，RTX Spark、DGX Spark 和 RTX PRO 6000 Blackwell 三个平台都可以本地运行，NVFP4 版本的 GGUF checkpoint[12] 已经上架 Hugging Face；想继续做后训练的用户，NVIDIA 给了 NeMo RL 的 flint-support 分支（开源项目 NVIDIA-NeMo/RL）[13]。

使用上的限制集中在三点。一是内存门槛：48GB 统一内存起步，把 M4 基础款和 32GB 机型挡在门外，田渊栋帖下就有开发者问何时适配 M1 和 32GB。二是单会话：引擎一次只处理一个生成，并发场景要用别的方案。三是上下文：Flint 支持最长 512K token 的上下文窗口，但官方建议在 256K 以内使用以获得最好效果。

> Flint 是 Eureka Machine 的第二个公开作品。今年早些时候，这套自动化研究系统在早期结果博文[16]里交过一份成绩单：

- NanoChat Autoresearch（单 GPU 固定 5 分钟预算训练小语言模型）把验证损失从 0.9372 BPB 降到 0.9109；
- NanoGPT Speedrun 把训到 3.28 验证损失的时间从 79.7 秒缩到 77.5 秒；
- SOL-ExecBench 上把 235 个 GPU 内核的平均 SOL 分从 0.699 提到 0.754，与最优解的差距缩小 18%。

三个基准的产物都已开源。**值得注意的是第三个结果——自动化系统做 GPU kernel 优化，和这次 rec 引擎里的 Metal megakernel、专用 kernel 是同一条能力线的延伸。**

## 七、三个判断：模型和引擎协同设计，AI4AI，Mac 用户开箱即用

**第一，模型和引擎协同设计正在变成端侧推理的标配打法**。Flint 的架构搜索目标函数直接写着本地硬件吞吐，量化方案按输出层的带宽占比决定，megakernel 按芯片型号生成——模型侧和引擎侧的任何一方单独做，都到不了 1.4–2.6 倍这个差距。:mdnice-bold-italic[对做本地推理的工程师来说，这提示了一个评估顺序：先看模型是不是为端侧设计的，再选引擎。]

**第二，"AI 造 AI"第一次有了可以亲手验证的交付物。** Eureka Machine 此前的成绩是三个基准上的数字，这次是一台 MacBook 就能跑起来的模型和引擎，任何人都可以下载复现。四个月的完整训练管线、三层自动化优化、46.5 亿美元估值的第一份答卷，都浓缩在一个 `rec launch pi` 命令里。

**第三，对开发者的实际建议很直接：手上有 48GB 以上 M4 Pro/M5 机器的，现在就可以装**；用 RTX Spark 或 Windows 的，等 rec 的官方支持落地，或者先用 llama.cpp、Ollama 跑 NVFP4 checkpoint，速度打六到七折。跑分数字目前全部来自 Recursive 自测，agentic 基准的单次运行成本（5 小时超时、至少 5 次采样）决定了第三方复现不会太快出现，社区实测值得继续跟踪。
