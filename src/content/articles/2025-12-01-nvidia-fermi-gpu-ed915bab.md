## 关键问题

### 问题 1. Fermi 的“CPU 化”改造与 GPU 并行核心优势的矛盾——是否稀释了其本质竞争力？

> Fermi 为适配 HPC 需求，新增了 ECC 全链路保护（寄存器至 DRAM）、C++异常处理/虚拟函数支持、L1/L2 缓存架构等 CPU 级特性（作者提及这些是传统 GPU 缺失的“完整架构”要素），但 GPU 的核心优势本是将硅面积与功耗集中于并行计算单元（如 Fermi 每个 SM 含 32 个计算核心，资源优先服务计算）。**这种改造是否会挤占计算单元的资源配额，导致其相较于前代 GT200 的并行效率提升被缓存、ECC 等模块的开销抵消？** 同时，与 Intel Nehalem 等 CPU 的单线程通用性相比仍有差距，**是否会陷入“并行不如纯 GPU、通用不如 CPU”的定位模糊困境？**

从作者原文内容来看，Fermi 的“CPU 化”改造（如 ECC 保护、缓存架构、多语言支持）**并非对 GPU 并行核心优势的稀释，而是突破 HPC 场景门槛的必要补全，且通过硬件设计优化与场景分工，避免了资源挤占和定位模糊。**

:mdnice-bold-italic[首先，其硬件资源分配具备灵活性，不会固定挤占计算单元配额]。

- 作者提到 Fermi 每个 SM 的 64K 本地内存可“16K/48K 或 48K/16K”灵活拆分 L1 缓存与共享内存，开发者可根据任务需求（如对共享内存需求高则减少缓存，对全局内存访问不可预测则增加缓存）动态调整，确保计算核心所需的资源不被缓存、ECC 等模块“强制占用”。
- 同时，Fermi 的 SM 架构仍以并行计算为核心——每个 SM 包含 32 个计算核心（可执行浮点/整数指令）、16 个负载存储单元与 4 个特殊功能单元，计算单元在硬件占比中仍居主导，这是其双精度浮点性能较前代 GT200 提升 8 倍的核心基础，说明并行效率提升未被辅助模块开销抵消。

:mdnice-bold-italic[其次，ECC、缓存等“CPU 化”特性是 HPC 场景的刚需，缺乏则无法进入该市场]。

- 作者明确指出，**Fermi 是“首个提供从寄存器到 DRAM 全链路 ECC 保护的 GPU** ”，而 ECC 是 HPC 处理关键数据（如气象模拟、流体力学）的【必备功能】；
- 同时，L2 缓存（768KB）与统一寻址模型解决了 GPU 以往内存访问效率低的问题，这些特性并非“模仿 CPU”，而是 HPC 对“完整计算架构”的基本要求。

:mdnice-bold-italic[最后，Fermi 与 CPU 的定位无模糊性，而是互补分工]。

- 作者多次强调，CPU 擅长“动态 workload（短计算序列、不可预测控制流）”，需大量缓存、分支预测器优化单线程；
- GPU 则擅长“长序列并行计算任务”，**Fermi 的改造仅为补全 HPC 所需的功能（如多语言支持降低开发门槛），并未试图替代 CPU 的通用场景**。例如，作者提到“GPU computing 不替代 CPU computing”，两者分别处理应用中的并行与控制流部分，形成协同而非竞争，**因此不存在“并行不如纯 GPU、通用不如 CPU”的困境。**

### 问题 2. Fermi 的量化性能优势与 HPC 软件生态的断层——为何难破“纸面性能 ≠ 实际价值”的困局？

> Fermi 宣称“双精度性能较 GT200 提升 8 倍”“原子操作加速 5-20 倍”，且 Tesla C1060 成本低于单颗 Intel Xeon W5590，但 HPC 领域长期依赖 CPU 超算（如 Cray）的软件生态（作者提及 GPU computing 仅数年历史，多数 HPC 软件为 CPU 设计）。即便其支持 C++/FORTRAN，这些**量化优势是否能突破软件迁移成本高、开发者习惯难转变的瓶颈？** 作者仅提及“200 多所高校教 CUDA”，却未提及 Fermi 在主流 HPC 场景（如气象模拟、流体力学）中替代传统超算的实际案例，这是否说明其性能优势未转化为核心替代能力？

::: block-1
Fermi 的量化性能优势正通过【生态建设】逐步转化为【实际价值】，断层问题随软件适配推进缓解。
:::

作者表示，Fermi 的量化性能优势（双精度 8 倍提升、成本优势）虽面临 HPC 软件生态的初期挑战，但通过多语言支持、高销量硬件基数、高校教育普及等措施，正逐步突破“纸面性能 ≠ 实际价值”的困局，且已有明确场景验证其实际作用。

:mdnice-bold-italic[首先，多语言支持与标准化接口降低了软件迁移成本，为性能落地提供基础]。

作者表示，**Fermi 不仅支持 C/C++（含虚拟函数、异常处理），还兼容 FORTRAN（通过 PGI 加速器模型与 NOAA 翻译工具）、Java、Matlab、Python，同时支持 OpenCL、Direct Compute 等行业标准接口。** 这解决了 HPC 软件“为 CPU 设计”的迁移痛点——例如，FORTRAN 是 HPC 领域的主流语言，Fermi 的 FORTRAN 支持让传统 CPU 超算软件（如线性代数 BLAS 库）可通过少量改造适配 GPU，而非完全重写，大幅降低开发者迁移成本。

:mdnice-bold-italic[其次，高销量硬件基数与高校教育推动生态快速成长，破解“开发者习惯难转变”问题]。

作者指出，**NVIDIA 当时已出货“超 1 亿颗支持 CUDA 的芯片”，且“200 多所高校开设 CUDA 编程课程”** ——:mdnice-bold-italic[【高硬件销量】] 意味着：:mdnice-bold-italic[厂商有动力适配 Fermi（如软件开发商为覆盖大量 GPU 用户而优化产品），高校教育则持续输送掌握 GPU 编程的人才，逐步改变 HPC 领域依赖 CPU 的开发习惯]。例如，作者提到“OpenCL 在苹果 Mac OS X 的支持将进一步提升 GPU 开发者数量”，说明生态正从“小众”向“主流”渗透。

:mdnice-bold-italic[最后，Fermi 的量化优势已在特定 HPC 场景转化为实际价值，并非“纸面性能”]。

- 作者以“直方图计算”为例，指出 Fermi 的原子操作可让区域直方图直接合并为最终结果，无需二次计算，较前代 GPU 的“同步+二次处理”流程大幅提升效率；
- 同时提到其原子操作在“光线追踪、模式识别、矩阵乘法”等场景的优化，这些都是 HPC 的典型子场景，证明其性能优势已落地。
- 而作者未提及大规模替代 Cray 等传统超算的案例，是因 GPU computing“仅数年历史”，生态建设需时间，但 Tesla C1060“成本低于 Intel Xeon W5590 且算力超 8 倍”的性价比，已让其在中小规模 HPC 场景（如高校科研、企业级模拟）具备替代能力，为后续生态成熟奠定基础。

## 一、执行摘要

> 历经 38 年的快速发展后，传统微处理器技术开始面临收益递减的问题。时钟频率（指 CPU 每秒执行指令的次数，单位通常为 GHz）和架构复杂度的提升速度逐渐放缓；尽管单线程性能仍在提升，但行业重心已转向多核设计。

多核设计在个人计算领域也逐渐触及实际应用极限：**四核 CPU 的价值未必是双核 CPU 的两倍，而核心数更高的芯片也不太可能成为未来个人电脑（PC）价值提升的主要驱动力。**

:mdnice-bold-italic[CPU 不会被淘汰，但 GPU 在 PC 系统架构中的地位正日益凸显]。对于需要高性能的应用而言，GPU 能提供更具成本效益且能效更高的性能。

GPU 的快速普及也使其成为高性能计算的天然选择。游戏及其他消费类应用每年催生数百万块高端 GPU 的需求，而庞大的销量使英伟达等公司能够为 HPC 市场提供高速、经济的 GPU 计算产品。

英伟达下一代 CUDA 架构（代号为 Fermi，费米）是这一趋势的最新且最具代表性的成果。

- 在并行软件（指可同时由多个处理单元执行的软件）上，基于 Fermi 的 GPU 性能数倍于任何传统 CPU；
- 同时，其新增特性能帮助软件开发人员更轻松地挖掘硬件的全部潜力，从而让更多用户得以接触到超级计算机级别的性能。

::: block-1
Fermi 是**首款** 具备满足**最严苛 HPC 应用** 所需【全部特性】的架构：

- 无与伦比的双精度浮点性能
- 符合 IEEE 754-2008 标准的特性
- 从寄存器到 DRAM的 ECC 校验（错误检查与纠正，能检测并修复内存中的单比特错误，防止数据损坏，保障计算准确性）
- 支持全层级缓存（高速缓冲存储器，用于缓解 CPU/GPU 与内存之间的速度差距）的直观线性寻址模型（指内存地址按连续线性方式分配，便于程序访问）
- 对 C、C++、FORTRAN、Java、Matlab 和 Python 等语言的支持
:::

凭借这些特性，再加上众多其他性能与易用性增强功能，Fermi 成为了首款完整的 GPU 计算架构。

## 二、CPU 计算——伟大的传统

> 过去 38 年间，微处理器的发展历程堪称全球范围内持续时间最长、技术进步最显著的时期之一。摩尔定律（由英特尔联合创始人戈登·摩尔提出，核心内容为：**每 18-24 个月，集成电路上可容纳的晶体管数量约增加一倍，性能也随之提升一倍**）所描述的技术进步速度，在交通、农业或机械工程领域均无先例可循。

试想一下，如果 300 年前的工业革命时期（例如 1771 年至 1809 年），结构材料的强度每 18 个月就能翻倍，那么当时的发展会有多么不同？别说蒸汽机了，19 世纪甚至可能通过豌豆大小的内燃机压缩氢气来实现核聚变供能。

::: block-1
**CPU 性能的提升源于多项相关技术的进步**，具体包括：

- 晶体管密度提升：指单位芯片面积上可集成的晶体管数量增加
- 晶体管性能提升：指单个晶体管的开关速度、能耗等特性优化
- 更宽的数据通路：指 CPU/GPU 与其他组件之间一次能传输的数据位数增加，如从 32 位提升至 64 位
- 流水线技术：将指令执行过程拆分为多个步骤，如取指、译码、执行等，使多个指令可并行处理，提升效率
- 超标量执行：指 CPU 一次能从指令流中取出多条指令并同时执行，突破传统“一次一条指令”的限制
- 推测执行：CPU 提前执行尚未确定是否需要的指令，若后续确认无需该指令则丢弃结果，以减少等待时间
- 缓存技术：如前文所述，用于缓解 CPU 与内存的速度差距
- 芯片级与系统级集成：将更多组件如内存控制器、PCIe 控制器等集成到单芯片或系统中，减少延迟
:::

**微处理器发展的前 30 年，几乎完全聚焦于串行工作负载** （指需按顺序逐步执行的任务），例如编译器（将高级语言代码转换为机器码的软件）、串行通信链路管理（如早期的串口数据传输）、用户界面代码等。**近年来，为满足从金融交易处理到计算流体力学** （用于模拟流体运动的科学计算领域）**等市场的并行工作负载需求，CPU 逐渐向多核方向演进。**

:mdnice-bold-italic[CPU 无疑是极具价值的计算组件，其【易用性】源于【编译器与硬件的协同发展】]。软件开发人员无需关注现代 CPU 的大部分复杂细节：微架构（指 CPU 内部的具体电路设计和指令执行机制）几乎是“透明”的，剩余的复杂部分也被编译器的“优化魔法”所掩盖。多核芯片与早期多处理器系统采用相同的软件架构：简单的一致性内存模型（指多个 CPU 核心访问同一内存区域时，能看到一致的数据状态）和大量相同的计算单元。

但 **CPU 核心的设计始终以牺牲并行执行为代价**，优先优化单线程性能。这一特点在观察现代 CPU 的芯片面积分配时尤为明显：整数运算单元（处理整数计算的电路）和浮点运算单元（处理小数计算的电路）仅占芯片面积的极小部分。

:mdnice-bold-italic[既然芯片中用于直接计算的区域如此之小，那么 CPU 在高性能计算应用中效率相对较低也就不足为奇了]。

::: block-1
**CPU 的大部分电路（以及由此产生的大部分热量）都用于处理“不可见的复杂部分”**：这些缓存、指令译码器（将机器码指令转换为 CPU 可执行的控制信号的电路）、分支预测器（预测程序中条件分支的走向，如“if-else”语句的执行路径，以优化推测执行）等特性，虽不直接体现在架构定义中，却能提升单线程性能。
:::

### 2.1 推测机制的影响

CPU 对单线程性能的侧重，核心在于“推测”这一设计理念。从广义上看，**推测不仅包括推测执行（如前文所述，提前执行可能需要的指令），还涵盖 CPU 设计中的多项其他元素。**

例如，:mdnice-bold-italic[缓存本质上就是一种“推测”：将数据存储在缓存中，相当于“打赌”这些数据在短期内会被再次访问]。缓存占用的芯片面积和功耗，原本可用于集成更多运算单元或提升其性能。而“赌局”是否成功，完全取决于具体工作负载的特性。

同样，:mdnice-bold-italic[多运算单元、乱序执行（CPU 不按指令的原始顺序执行，而是根据资源空闲情况调整执行顺序，以提升效率）和分支预测等设计，也都属于“推测性优化”]。对于数据局部性高（指程序频繁访问相同或相邻内存地址的数据）、操作类型多样且条件分支（如“if-else”“for 循环”等需要判断执行路径的语句）占比高的代码，这些优化通常能带来显著收益。

但当执行的代码由**大量相同类型的串行操** 作构成（如科学计算工作负载，常包含大规模重复的浮点运算）时，这些:mdnice-bold-italic[推测性组件往往处于闲置状态，却仍在占用芯片面积和消耗功耗。]

### 2.2 工艺技术的影响

CPU 设计人员为最大化单线程性能，还会采用**激进的工艺技术** （如更小的晶体管尺寸、更先进的材料）以实现尽可能高的时钟频率。但这一决策也伴随着高昂的成本：更快的晶体管会产生更多热量，即使在非工作状态下也会有更多漏电（导致额外能耗），且制造成本更高。

::: block-1
**高端 CPU 厂商在工艺技术上的投入堪称惊人，只为提升单线程性能**。仅 IBM 和英特尔两家公司，就在工艺技术和晶体管设计的研发上投入了数百亿美元。若以时钟频率（单位 GHz）衡量，成果确实令人瞩目；但从每美元浮点运算次数（GFLOPS/$，衡量成本效益）或每瓦浮点运算次数（GFLOPS/W，衡量能效）来看，优势则大打折扣。
:::

**处理器微架构** 同样对性能有重要影响。在 PC 和服务器市场，微架构优化的极端情况体现在两类 CPU 设计中：相对简单的双发射核心（一次能执行两条指令的 CPU 核心）和更复杂的多发射核心（一次能执行三条及以上指令的 CPU 核心）。

### 2.3 双发射 CPU

当前 PC 市场中最简单的 CPU 微架构是双发射超标量核心。这类设计在每个时钟周期内最多可执行两条指令，有时还会通过“配对规则”限定可同时执行的指令类型。例如，早期某些双发射 CPU 可同时执行两条简单整数指令，或一条整数指令与一条浮点指令，但无法同时执行两条浮点指令。

**双发射核心通常按程序顺序处理指令，通过挖掘大多数程序中天然存在的指令级并行性（ILP，指程序中可同时执行的指令数量）来提升性能**。不同程序的 ILP 水平存在差异，但几乎所有程序都能充分利用第二条流水线（指双发射核心中的两个指令执行通道）。

> 英特尔的 Atom 处理器（英特尔推出的低功耗 CPU 系列，主要用于上网本、嵌入式设备等）是双发射处理器的成熟范例。

- 与其他先进 x86 架构芯片一样，Atom 会:mdnice-bold-italic[将 x86 指令转换为内部“微操作”] （Micro-ops，简称微码，格式更接近早期 RISC 指令集（精简指令集，指令简单、执行速度快）的指令）。
- 在 Atom 中，:mdnice-bold-italic[每条微操作通常可执行一次算术逻辑单元（ALU）操作，以及一次或多次辅助操作] （如内存加载或存储，即从内存读取数据或向内存写入数据）。

**Atom 这类双发射处理器通常面向成本效益至上的低端市场**。因此，与英特尔更昂贵的芯片相比，Atom 的性能导向型优化更少。例如，Atom 采用顺序执行（不支持乱序执行），且无推测执行功能。**Atom 的大部分新工程设计都用于提升【非满负载】运行时的【能效】** （即低负载下的功耗控制）。

Atom 拥有 6 条执行流水线，具体包括：2 条浮点运算流水线、2 条整数运算流水线，以及 2 条地址计算流水线。然而，在单个时钟周期内，仅能向这些流水线发射（分配）两条指令。这种低利用率意味着，每个周期内总会有部分运算单元处于闲置状态。

与所有 x86 处理器一样，Atom 的很大一部分芯片面积用于指令缓存（存储近期可能执行的指令的高速缓存）、译码器（将 x86 指令转换为微操作的电路）和微码存储（用于实现复杂 x86 指令的微操作序列存储区域）。此外，:mdnice-bold-italic[Atom 还支持双向同步多线程（SMT，如前文所述，单个核心同时处理两个线程）特性。英特尔将这部分电路称为“前端集群”（Front End Cluster），其占用的芯片面积甚至超过了芯片的浮点运算单元。]

**同步多线程（SMT）本质上是一种解决运算单元利用率进一步受限问题的技术**。有时，单个线程会因等待缓存数据（如数据未在缓存中，需从内存读取，导致线程暂停）或多条指令等待同一流水线（如多条浮点指令同时等待浮点流水线执行）而停滞。此时，第二个线程可能会发射一两条指令，从而利用闲置资源。SMT 带来的性能提升通常较低，在部分应用中仅为 10%-20%，但它仅使芯片面积增加了几个百分点。

因此，Atom 核心适用于低端消费类系统，但整体性能较低，远不及英特尔其他系列的处理器。

### 2.4 英特尔 Larrabee

**Larrabee 是英特尔一款基于 x86 架构的未来图形处理架构的代号**。据称，首款 Larrabee 芯片将采用源自初代奔腾处理器设计的双发射核心，但会进行修改，以支持 64 位 x86 操作（可处理更大范围的数值和地址）和全新的 512 位向量处理单元。

除向量单元外，**Larrabee 核心比 Atom 更简单**。它不支持英特尔的 MMX（早期 x86 向量指令集，用于多媒体处理）和 SSE（流式 SIMD 扩展指令集，用于提升多媒体和科学计算性能）扩展指令，完全依赖全新的向量单元——该单元拥有专属的新指令。Larrabee 的向量单元宽度足以在每个时钟周期内执行 16 次单精度浮点运算，同时也支持双精度浮点运算，但速率较低。

> Larrabee 向量单元的多项特性在 x86 架构中均属首次出现，包括散集-聚集加载/存储（从内存中 16 个不同位置读取数据组成向量，或从向量向 16 个不同位置写入数据——这一特性虽便捷，但需谨慎使用，否则可能导致性能下降）、融合乘加运算、谓词执行（根据条件判断是否执行指令，可减少分支指令带来的延迟），以及三操作数浮点指令（一条指令可同时处理三个操作数，如“a = b + c”，提升指令效率）。

Larrabee **还支持四向多线程**，但实现方式与 Atom 不同。Atom 可同时执行两个线程的指令（因此名为同步多线程 SMT），而 :mdnice-bold-italic[Larrabee 仅维护多个线程的状态（如寄存器值、程序计数器等），以便在当前线程停滞时快速切换到新线程] （减少线程切换的延迟）。

Larrabee 的 x86 兼容性在未带来显著图形处理收益的同时，还降低了其性能和能效。**与 Atom 类似，Larrabee 芯片面积和功耗预算的相当一部分（即便不是大部分）将被指令译码器占用**。作为图形芯片，Larrabee 还因缺乏用于光栅化（将 3D 图形的顶点数据转换为 2D 像素数据的过程）、插值（如计算像素颜色的中间值）和 Alpha 混合（将前景像素与背景像素按透明度混合的技术）的优化固定功能逻辑（专门用于特定任务的硬件电路，比通用运算单元效率更高）而性能受限。:mdnice-bold-italic[由于在 3D 游戏中无法提供高性价比的性能，Larrabee 很难达到英特尔对其主要产品线预期的销量和利润率。]

::: block-1
**Larrabee 是英特尔【第二次尝试】进入 PC 图形芯片市场** ——第一次是 1998 年的 i740 项目，该项目虽在商业上失败，却为英特尔后续的集成显卡芯片组（将显卡功能集成到主板芯片组中的方案）奠定了基础。（更早之前，英特尔还曾通过 i750 涉足视频控制器领域；再往前，其 i860 RISC 处理器曾被用于部分工作站的图形加速器。）
:::

### 2.5 英特尔 Nehalem 微架构

Nehalem 是所有 x86 处理器中最复杂的微架构，其特性堪称高性能 CPU 设计的“清单集合”，具体包括：四发射超标量（每个时钟周期最多执行四条指令）、乱序执行、推测执行、同步多线程、多分支预测器（用于更准确预测条件分支走向的多个预测电路）、片上电源门控（关闭闲置核心或组件的电源，降低功耗）、片上内存控制器、大容量缓存，以及多处理器互连（用于多 CPU 之间的高速通信）。图 2 展示了 Nehalem 微架构的结构。

- 每个 Nehalem 核心配备 4 个指令译码器，这些译码器在可能的情况下并行工作，但【仅】其中一个能解码复杂的 x86 指令（这类指令占比较低）。译码器生成的微操作会被存入队列，并通过 6 个端口乱序分配给 12 个计算执行单元。
- 此外，还有 1 个加载单元（用于从内存/缓存读取数据）和 2 个存储单元（用于向内存/缓存写入数据），分别处理数据和地址相关操作。

::: block-1
Nehalem 的 128 位 SIMD 浮点运算单元与上一代英特尔处理器类似，具体包括：1 个用于浮点乘法（FMUL）和浮点除法（FDIV）的单元、1 个用于浮点加法（FADD）的单元，以及 1 个用于浮点洗牌（FP Shuffle）的单元（用于重新排列 SIMD 寄存器中的数据顺序，不参与乘加密集型算法的性能计算）。
:::

四核 Nehalem 处理器（不包含洗牌单元）的峰值单精度浮点性能可通过以下公式计算：

$$
4\ \text{核心} \times 2\ \text{条 SIMD 指令/时钟周期} \times 4\ \text{个数据值/指令} \times \text{时钟频率}
$$

此外，尽管 Nehalem 处理器的峰值 DRAM 带宽（内存与 CPU 之间的数据传输速率）可达 32GB/s——对于 PC 处理器而言，这一数值已十分可观——但这一带宽意味着，每执行 3 次浮点运算，DRAM 仅能提供不到 1 字节的数据。因此，**在许多高性能计算应用中，DRAM 性能会成为瓶颈，导致 CPU 的浮点运算单元尚未被充分利用时**，程序就已因等待内存数据而停滞。

英特尔 Xeon W5590 是基于 Nehalem-EP“Gainestown”芯片的高端四核工作站处理器。截至 2009 年 8 月，该处理器的千片起购价为 1600 美元/片。

在 3.33GHz 时钟频率下，Xeon W5590 的峰值单精度浮点性能可达 106.56 GFLOPS（每秒十亿次浮点运算）。该处理器的热设计功耗（TDP）为 130 瓦，即每 GFLOPS 性能的功耗为 1.22 瓦——这一数值尚未包含必需的核心逻辑芯片组（主板上用于连接 CPU、内存、外设的芯片）的功耗。

**Nehalem 的设计以牺牲持续吞吐量为代价，优先优化单线程性能和时钟频率**。

- 对于旨在成为市场领先的 PC 台式机和服务器处理器的芯片而言，这一权衡是合理的；
- 但对于高性能计算而言，Nehalem 却因成本高、功耗大而并非理想选择。

### 2.6 性能墙（The Wall）

> 市场要求通用处理器在客户端、服务器和高性能计算（HPC）系统的各类工作负载中，**既能提供高性能的单线程性能，又能具备高效的多核吞吐量**。这种压力促使行业在:mdnice-bold-italic[近三十年间不断追求更高的架构复杂度与更高的时钟频率] （即 CPU 主频，决定 CPU 每秒可执行的基础操作次数），并取得了显著进步。

但这种进步并非一帆风顺。英特尔曾取消了传闻中具备 40 级流水线的“Tejas”处理器项目，随后又因能效相对低下，终止了整个奔腾 4（Pentium 4）“NetBurst”产品家族。2004 年推出的奔腾 4“Prescott”（奔腾 4 系列的核心型号之一）最终将时钟频率提升至 3.8GHz，而**这一速度此后英特尔再也未能突破。**

在较新的酷睿 2（Core 2，采用 Conroe/Penryn 核心，分别为 65 纳米和 45 纳米工艺的代表型号）与酷睿 i7（Core i7，基于 Nehalem 微架构——英特尔 2008 年推出的首款酷睿 i 系列微架构，支持多核与超线程技术）处理器中，**英特尔通过提升架构复杂度，实现了相较于奔腾 4 系列的大幅性能提升，但这种提升的速度已在逐渐放缓**。

- 每一代新工艺技术的迭代，都需要投入更大的努力才能改善晶体管特性；
- 而每一代新的核心微架构，都必须**以不成比例的更高成本去挖掘和利用指令级并行** （:mdnice-bold-italic[ILP，指 CPU 通过在同一时钟周期内并行执行多条指令提升性能的技术]）潜力。

::: block-1
20 世纪 90 年代，这些挑战愈发明显，CPU 架构师们开始将**“功耗墙”“内存墙”和“指令级并行墙”** 视为**阻碍此前快速进步的关键瓶颈**。或许更贴切的比喻是，这些问题并非无法逾越的“墙”，而是一座座“山”——起初坡度平缓，但每向上一步，坡度就会变得更陡，使得进一步的突破愈发困难。
:::

尽管如此，工艺技术的不可阻挡的进步，仍让每一代 CPU 都能集成更多的晶体管。到 2005 年，“**如何利用额外的晶体管提升芯片级性能** ”的竞争压力，推动 AMD 与英特尔纷纷推出双核处理器。此后，PC 处理器设计的核心方向便聚焦于持续增加芯片上的核心数量。

然而，**这种“堆核心”的思路已逐渐陷入收益递减** 的困境。双核处理器能为大多数 PC 用户带来明显收益，但除了处理多媒体内容或运行多个对性能要求极高的应用程序（如视频剪辑、3D 渲染软件）时，其性能几乎无法被完全利用。

- 多数情况下，四核处理器的性能提升仅为小幅改进；
- 到 2010 年，:mdnice-bold-italic[桌面端将出现八核处理器，但要让大多数用户认可“额外核心”的价值恐怕并不容易，而进一步增加核心数量以推动销售，难度会更大。]
- **一旦核心数量的增长陷入停滞，行业焦点将重新回到单线程性能上** ——但此时，那容易实现、能快速提升性能的技术方向早已被采摘殆尽，进一步的性能提升将难上加难。

**短期内，AMD 与英特尔预计会通过即将推出的高级向量扩展** （AVX，英特尔和 AMD 联合推动的 CPU 指令集扩展，旨在增强向量运算能力，支持更宽的向量宽度与更多运算指令）技术，重点提升向量浮点运算性能。与流式 SIMD 扩展（SSE，英特尔早期推出的向量指令集，为多媒体和科学计算性能提升奠定基础）类似，**AVX 的核心价值将体现在这类应用场景中**：可向量化的浮点计算需要与现代 x86 架构处理器所优化的控制流代码（用于控制程序执行流程的代码，如条件判断、循环语句等）紧密结合。

CPU 核心设计仍将继续发展：工艺技术会不断进步，内存接口会更快，超标量核心（支持在一个时钟周期内发射多条指令的 CPU 核心）的“宽度”（即单次可发射的指令数量）也会更大。

:mdnice-bold-italic[但大约十年前，NVIDIA 的处理器架构师们就意识到，对于某些特定问题，CPU 已不再是最优解] ——于是，他们决定从零开始（不依赖现有 CPU 设计，重新进行架构创新），打造一种更优的解决方案。

## 三、GPU 的发展历程

> 认识到一种新处理架构的未来潜力是一回事，在这种潜力得以实现之前培育出市场则是另一回事。

### 3.1 从“看见潜力”到“养大市场”——芯片级并行的早期挫折

20 世纪 90 年代就有人尝试研发芯片级并行处理器，但当时晶体管资源有限（指芯片上可集成的晶体管数量较少，制约了复杂架构的实现），因此更复杂的单核设计更具优势。

### 3.2 GPU 计算的真正起点——不可编程的 3G 图形加速器

:mdnice-bold-italic[GPU 计算的真正发展之路，并非始于 GPU 本身，而是始于不可编程的第三代（3G）图形加速器]。从 20 世纪 80 年代开始，多家公司陆续研发出多芯片 3D 渲染引擎，但到了 90 年代中期，已能够将所有关键组件集成到单颗芯片上。**1994 年至 2001 年间，这类芯片不断发展，从最简单的像素绘制功能，逐步升级到实现完整的 3D 流水线** （指 3D 图形处理的完整流程，包含多个依次执行的关键步骤）：包括变换（对图形顶点进行坐标转换，将 3D 模型映射到 2D 屏幕坐标系）、光照（计算场景中光线与物体表面的交互效果，生成明暗层次）、光栅化（将矢量图形数据转换为屏幕上的像素点）、纹理映射（为物体表面添加细节纹理，提升真实感）、深度测试（判断不同像素在三维空间中的前后位置，避免遮挡显示错误）以及显示输出。

### 3.3 可编程着色器的萌芽与分化——GeForce 3 → 7800

2001 年，NVIDIA 推出的 GeForce 3 将可编程像素着色（:mdnice-bold-italic[指通过程序控制像素的颜色和效果，而非固定硬件逻辑]）引入消费级市场。这**款芯片的可编程能力虽十分有限，但后续的 GeForce 产品逐渐具备了更高的灵活性和更快的速度，并为顶点着色（处理 3D 模型顶点数据）和几何着色（对几何图元进行处理，如生成新的三角形）分别添加了独立的可编程引擎**。这一演进最终在 GeForce 7800 上达到顶峰，如图 3 所示。

所谓的通用图形处理器编程（GPGPU，General-Purpose GPU Programming），是在这类图形优化架构上执行非图形处理任务的一种方法——通常是**将数据【伪装】成顶点或纹理信息，运行精心编写的着色器代码，再从流水线的后续阶段获取结果**。尽管这种方式有时操作繁琐，但 GPGPU 编程展现出了巨大的潜力。

此外，8800 还推出了 CUDA——业内首个基于 C 语言的 GPU 开发环境（CUDA 最初代表“Compute Unified Device Architecture”，即统一计算设备架构，如今已不再使用该全称）。**与早期的 GPGPU 方法相比，CUDA 提供了更简便、更高效的编程模型。**

### 3.5 从显卡到计算卡——Tesla 产品线把 GPU 推向 HPC

为了将 8800 架构和 CUDA 的**优势拓展到高性能计算（HPC）等新市场，NVIDIA 推出了 Tesla 产品线**。当前的 Tesla 产品采用的是更新的 GT200 架构。

Tesla 产品线最初以 PCI Express 扩展卡（本质上是没有显示输出接口的显卡）为基础，其驱动程序针对 GPU 计算而非 3D 渲染进行了优化。**借助 Tesla，开发者无需再将任务伪装成图形操作，可直接将 GPU 视为一款多核处理器使用。**

与 20 世纪 90 年代早期的芯片级多处理尝试不同，Tesla 从一开始就是一个高产量的硬件平台。:mdnice-bold-italic[这在一定程度上得益于 NVIDIA 的【战略】：在公司的 GeForce 和 Quadro 产品上支持 CUDA 软件开发平台，使其能触达更广泛的开发者群体]。NVIDIA 表示，其已出货超过 1 亿颗支持 CUDA 的芯片。

在撰写本文时（2009年），部分互联网邮购供应商提供的入门级 Tesla C1060 扩展卡价格低于 1500 美元。这一**价格低于单颗 Intel Xeon W5590 处理器的售价**，而 Tesla 卡的:mdnice-bold-italic[峰值浮点运算性能（GFLOPS）却是该 Xeon 处理器的 8 倍以上。]

Tesla 产品线还包括 S1070——一款 1U 高度的机架式服务器（1U 是机架服务器的高度单位，约 4.45 厘米），内置 4 颗 GT200 系列 GPU，其运行频率高于 C1060（核心频率最高可达 1.5GHz，而 C1060 为 1.3GHz），因此 S1070 的峰值性能是单张 C1060 卡的 4.6 倍以上。S1070 通过 PCI Express 扩展卡与独立的主机相连。

### 3.6 生态滚雪球——开发者、高校与 OpenCL 的连锁反应

::: block-1
**这种高性能硬件的广泛普及，对软件开发者具有天然的吸引力**。正如高产量的 x86 架构比 Intel 安腾处理器的 IA-64 架构能吸引更多开发者一样，尽管 GPU 的高销量主要由游戏市场驱动，但相比 Cray、富士通、IBM、NEC 和 SGI 等公司的专用超级计算机，GPU 对高性能计算应用开发者而言更具吸引力。
:::

尽管 GPU 计算仅有数年历史，但目前拥有 GPU 计算直接经验的程序员数量，很可能已超过曾使用过 Cray 超级计算机的程序员数量。学术界对 GPU 计算的支持也在迅速增长。

- NVIDIA 表示，已有超过 200 所高校开设了 CUDA 编程课程；
- 而 OpenCL（如苹果 Mac OS X 的新版“Snow Leopard”中所支持的）的普及，将使这一数字进一步攀升。

## 四、Fermi 架构介绍

> GPU 计算并非要取代 CPU 计算，两种方式各自对特定类型的软件具有优势。

- 正如前文所述，**CPU 针对的是“线程数量有限、且线程具有高数据局部性** （指线程频繁访问相同或内存地址相邻的数据）、操作类型多样、条件分支（指程序中根据条件判断执行不同代码路径的语句，如 if-else）占比高”的应用进行了优化。
- 而 **GPU 设计则瞄准了另一种极端场景：线程数量多、且以较长序列的计算指令为主的应用**。在过去几年中，GPU 在线程处理、数据缓存、虚拟内存管理、流程控制以及其他类 CPU 特性上的能力不断提升，但“计算密集型软件”与“控制流密集型软件”之间的区别仍是根本性的。

当前 GPU 设计的最高水平，体现在 NVIDIA 下一代 CUDA 架构（代号为 Fermi）中。**图 5 展示了首款 Fermi 芯片的高层级框图。**

![文章插图](/articles/2025-12-01-nvidia-fermi-gpu-ed915bab/images/08.webp)

::: image-caption
图 5：NVIDIA 的 Fermi GPU 架构由多个流多处理器（SM，Streaming Multiprocessor，GPU 的核心计算单元）组成，每个 SM 包含 32 个核心，每个核心每时钟周期可执行一条浮点或整数指令。这些 SM 由二级缓存（L2 Cache）、主机接口、GigaThread 调度器（负责线程调度的硬件模块）以及多个 DRAM 接口提供支持。来源：NVIDIA

:mdnice-bold-italic[从这一层级的抽象视角来看，GPU 就像是由大量计算单元构成的集合，仅搭配少量支撑组件] ——这正体现了 **GPU 设计的核心目标：最大化浮点运算吞吐量。**

由于每个核心内的大部分电路都用于计算，而非用于提升单线程性能的推测性特性（如分支预测、缓存等基于“推测数据会被使用”的设计），因此 Fermi 的大部分芯片面积和功耗都投入到了应用的实际算法运算中，而非无用的辅助逻辑。

### 4.1 编程模型

> Fermi **架构的复杂性通过“多层级编程模型”进行管理**，该模型让软件开发者能够专注于算法设计，而非“如何将算法映射到硬件”的细节，从而提升开发效率。传统 CPU 尚未面临这一问题，因为 CPU 的结构简单且规整：少量核心通过虚拟总线呈现为逻辑对等的计算单元。

在 NVIDIA 的 CUDA 软件平台以及行业标准的 OpenCL 框架中，算法的计算单元被称为“内核（kernel）”（此处术语源自信号处理，而非操作系统中的“内核”）。一个应用或库函数可能包含一个或多个内核。

内核可使用 C 语言（具体为 ANSI 标准的 C99 方言）编写，并**通过额外的关键字直接表达并行性，而非依赖常规的循环结构。**

::: block-1
内核经过编译后，会生成多个并行执行相同程序的线程：一个线程相当于一次循环迭代。例如，在图像处理算法中，一个线程可处理一个像素，而所有线程共同构成的内核则可处理整幅图像。
:::

- 多个线程会被分组为“线程块（thread block）”，每个线程块最多包含 1536 个线程。一个线程块内的所有线程会在单个 SM 上运行，因此线程块内的线程可进行协作并共享内存。线程块之间可协调全局共享内存的使用，但它们的执行顺序是任意的（可并发或串行执行）。
- 线程块会进一步划分为“线程束（warp）”，每个线程束包含 32 个线程。线程束是单个 SM 内的基本调度单位。在 Fermi 中，来自不同线程块（甚至不同内核）的两个线程束可被同时派发和执行，从而提升硬件利用率和能效。
- 线程块会组成“网格（grid）”，每个网格执行一个独特的内核。线程块和线程各自拥有标识符（ID），用于标识它们与内核的关联关系。这些 ID 在每个线程内部可用作索引，以定位各自的输入/输出数据、共享内存地址等。

在任意时刻，整个 Fermi 设备会专用于单个应用。如前所述，一个应用可能包含多个内核。**Fermi 支持从同一应用中同时执行多个内核，每个内核会被分配到设备上的一个或多个 SM 中**。这一能力避免了“某个内核仅能使用设备的一部分资源，而其余资源闲置”的情况。

**Fermi 在不同应用之间的切换速度，比前一代 GPU 快约 20 倍（仅需 25 微秒，1 微秒=10⁻⁶ 秒）**。这一时间足够短，使得即使在运行多个应用（如同时运行计算代码和图形代码）时，Fermi GPU 仍能保持高利用率。高效的多任务处理对消费者（例如，运行包含物理特效的视频游戏）和专业用户（通常需要同时运行计算密集型模拟和结果可视化程序）都至关重要。

:mdnice-bold-italic[这种切换由芯片级的 GigaThread 硬件线程调度器管理]，该调度器可为每个流多处理器（SM）管理 1536 个同时活跃的线程，且支持跨 16 个内核的线程调度。

**这种集中式调度器是 Fermi 与传统 CPU 设计的另一大区别**。

- :mdnice-bold-italic[在多核或多处理器服务器中，没有任何一个 CPU 处于“主导地位”]：包括操作系统内核本身在内的所有任务，都可在任意可用的 CPU 上运行。这种方式允许不同操作系统采用不同的内核设计理念（如 Linux 的大型单内核、QNX 的微内核、Windows 7 的混合内核），但这种通用性也带来了缺点——它要求复杂的 CPU 花费时间和能量去执行“本可由更简单硬件完成”的功能。
- 而:mdnice-bold-italic[对于 Fermi，其目标应用、流处理原理以及内核-线程模型都是预先明确的]，因此可在 GigaThread 引擎中实现更高效的调度方式。

除了支持 C 语言外，Fermi 还能加速与 GT200 架构相同的所有语言，包括 FORTRAN（由 Portland Group 和美国国家海洋和大气管理局（NOAA）分别提供独立解决方案）、Java、Matlab 和 Python。所支持的软件平台包括 NVIDIA 自家的 CUDA 开发环境、由 Khronos 集团管理的 OpenCL 标准，以及微软的 Direct Compute API。

Portland Group（PGI）提供了两种利用 GPU 加速 FORTRAN 程序的方式：

- 一种是“PGI Accelerator 编程模型”——可将 FORTRAN 程序中的特定代码区域卸载到 GPU 上执行；
- 另一种是“CUDA FORTRAN”——允许开发者直接控制所连接 GPU 的操作，包括管理本地内存和共享内存、线程同步等。NOAA 则提供了一种语言转换器，可将 FORTRAN 代码转换为 CUDA C 代码。

Fermi 为市场带来了一项重要的新能力：在指令级支持 C++，包括针对 C++虚函数、函数指针、动态对象分配以及 C++异常处理操作（try 和 catch 语句）的指令。C++语言此前未得到 GPU 支持，而其广泛普及性将使 GPU 计算的受众比以往任何时候都更广。

### 4.2 流多处理器

> Fermi 的流多处理器（SM）结构如图 6 所示。

![文章插图](/articles/2025-12-01-nvidia-fermi-gpu-ed915bab/images/09.webp)

::: image-caption
图 6：每个 Fermi SM 包含 32 个核心、16 个加载-存储单元、4 个特殊功能单元、一个 32K 字的寄存器文件（Register File，用于临时存储运算数据）、64K 的可配置 RAM（随机存取存储器）以及线程控制逻辑。每个核心同时具备浮点和整数执行单元。来源：NVIDIA
:::

浮点运算遵循 IEEE 754-2008 浮点标准。**每个核心每时钟周期可执行一次单精度融合乘加** （FMA，Fused Multiply-Add，指将“乘法”和“加法”合并为一条指令执行，减少中间结果误差）运算，**每两个时钟周期可执行一次双精度 FMA 运算**。在芯片级层面，Fermi 每时钟周期的双精度运算次数是前一代 GT200 的 8 倍以上——在 GT200 中，双精度处理由每个 SM 中的专用单元负责，吞吐量远低于 Fermi。

IEEE 浮点兼容性包括所有四种舍入模式，且 **Fermi 硬件能正确处理非规格化数** （:mdnice-bold-italic[指数值绝对值小于最小规格化数的浮点数，比规格化格式能表示的数值更接近零]），而非将其置零或需要通过软件异常处理器进行额外处理。

Fermi 对融合乘加（FMA）的支持同样遵循 IEEE 754-2008 标准：:mdnice-bold-italic[它不会像传统“先乘后加”操作那样对中间结果进行舍入，从而提升了常用“乘加序列”的精度]。

- 在 Fermi 中，这一中间结果保持完整的 106 位尾数（浮点数的小数部分）；
- 实际上，在计算最终双精度结果之前，加法操作会保持 161 位的精度，以处理最坏情况下的非规格化数。

GT200 仅对双精度运算支持 FMA，而 Fermi 将 FMA 的优势扩展到了单精度运算中。

> FMA 支持还提升了其他数学运算（如除法、平方根）以及更复杂函数（如扩展精度算术、区间算术、线性代数）的精度和性能。

整数算术逻辑单元（ALU）支持常见的数学和逻辑运算（包括乘法），可处理 32 位和 64 位数值。

内存操作由每个 SM 中的 16 个加载-存储单元负责处理。现在，加载-存储指令可通过二维数组的形式引用内存，即使用 x 和 y 值表示地址。数据在 DRAM（动态随机存取存储器，容量大但速度慢于 SRAM）和核心寄存器之间传输时，可全速进行格式转换（例如，从整数转换为浮点，或反之）。**这些格式转换特性是 GPU 特有的优化** ——:mdnice-bold-italic[在通用 CPU 中，这类优化的价值不大，但在 GPU 中，它们的使用频率足够高，因此值得集成到硬件中。]

::: block-1
此外，每个 SM 还配备 4 个特殊功能单元（SFU），用于处理超越函数（指不能通过有限次代数运算表示的函数，如正弦、余弦）和其他特殊运算，例如 sin（正弦）、cos（余弦）、exp（指数）和 rcp（倒数）。**每个 SM 每时钟周期可派发 4 次这类运算。**

- **在 SM 内部，32 个核心被分为两个“执行块”，每个执行块包含 16 个核心**。再加上 16 个加载-存储单元组成的组和 4 个 SFU，每个 SM 共包含 4 个执行块（NeuralTalk 注：这里是说存储单元的组和 4 个 SFU 分别是另外 2 个执行块，详见下图 7）。
- 每时钟周期，可从一个或两个线程束中向这些执行块派发总计 32 条指令。
:::

图 7 展示了指令在各个可用执行块之间的分配过程。

![文章插图](/articles/2025-12-01-nvidia-fermi-gpu-ed915bab/images/10.webp)

::: image-caption
图 7：每时钟周期，可从一个或两个线程束中向 Fermi SM 内的任意两个执行块派发总计 32 条指令。这四个执行块分别是：两个各含 16 个核心的块、一个含 4 个特殊功能单元（SFU）的块、一个含 16 个加载-存储单元（LD/ST Unit）的块。该图展示了指令如何派发到各个执行块。来源：NVIDIA

### 4.3 指令集架构改进

#### PTX

> Fermi **首次引入了“并行线程执行（PTX，Parallel Thread Execution）2.0 指令集架构** ”。PTX 2.0 定义了一套指令集和一种新的虚拟机架构，本质上是一款为:mdnice-bold-italic[“并行线程操作”设计的理想化处理器。]

由于**这种虚拟机模型并非直接模拟 Fermi 硬件，因此它可在不同代际的 GPU 间移植**。NVIDIA 计划让 PTX 2.0 像 PTX 1.0 一样，覆盖多代 GPU 硬件以及每代中不同规格的 GPU。

支持 NVIDIA GPU 的编译器会生成符合 PTX 标准的二进制文件，这些文件可作为 GPU 计算应用和中间件的“硬件无关分发格式”。当应用在目标机器上安装时，GPU 驱动会将 PTX 二进制文件转换为硬件可直接执行的底层机器指令（Fermi GPU 驱动也可将 PTX 1.0 二进制文件转换为原生指令）。

这一**最终转换步骤不会带来额外的性能损失**。:mdnice-bold-italic[即使是对性能最敏感的应用，其内核和库也可手工编写为 PTX 2.0 ISA 代码，从而实现跨 GPU 代际和不同实现版本的可移植性。]

#### 谓词执行（Predication）

::: block-1
Fermi 中所有“架构可见的改进”都在 PTX 2.0 中有所体现，其中“**谓词执行（Predication）”是新 ISA 中一项较为重要的增强特性。**
:::

**所有指令都支持谓词执行**：每条指令是否执行，可根据条件码（程序运行中产生的状态标志，如是否为零、是否溢出等）来决定。谓词执行允许每个线程（即每个核心）根据需求执行不同操作，同时保持全速执行。当谓词执行无法满足需求时，Fermi 还支持通过分支语句（如 if-then-else）实现常规的条件分支结构。

大多数 CPU 仅依赖条件分支，并集成分支预测硬件（用于推测“最可能执行的代码路径”），这对“分支密集型串行代码”是合理的解决方案，但对“流处理应用”而言，其效率低于谓词执行。

#### 统一寻址模型

Fermi 和 PTX 2.0 的另一项重大改进是“统一寻址模型”。GPU 中的所有地址都从一个连续的 40 位（即 1TB，1TB=1024GB）地址空间中分配。全局内存、共享内存和本地内存的地址被定义为该地址空间内的不同范围，且可通过通用的加载-存储指令访问（加载-存储指令支持 64 位地址，为未来地址空间扩展预留空间）。

### 4.4 缓存与内存层级

> 与早期 GPU 类似，Fermi 架构在每个 SM 中提供本地内存。而 **Fermi 的新特性在于：可将部分本地内存用作“全局内存访问的一级缓存（L1 Cache）”**。本地内存的总大小为 64K，可按“16K（L1 缓存）/48K（共享内存）”或“48K（L1 缓存）/16K（共享内存）”的比例分配。

共享内存是本地 SM 内存的传统用途，它能以低延迟（指数据从内存传输到核心的时间短）访问中等规模的数据（例如，一系列计算中的中间结果、矩阵运算的某一行或某一列、视频的某一帧等）。由于访问该内存的延迟完全可预测，因此可通过“交错安排加载、计算和存储操作”来编写算法，以实现最高效率。

::: block-1
:mdnice-bold-italic[将本地内存分配为 16K 还是 48K 缓存，通常取决于两个因素：一是所需的共享内存大小，二是内核对全局内存（通常是片外 DRAM）的访问模式可预测性] ——共享内存需求越大，缓存应分配越少；对 DRAM 中更大区域的访问越频繁或越不可预测，缓存应分配越多。
:::

部分嵌入式处理器也以类似方式支持本地内存，**但 PC 或服务器处理器几乎从未提供这一特性——因为主流操作系统无法管理本地内存，其编程模型中也没有相关支持**。:mdnice-bold-italic[这正是“在通用处理器上运行的高性能计算应用常受内存带宽瓶颈制约”的原因之一：应用无法控制内存的分配位置，算法也无法针对访问延迟进行充分优化。]

#### L2 Cache

每款 Fermi GPU 还配备了二级缓存（L2 Cache）——对于 512 核芯片，L2 缓存大小为 768KB。该 L2 缓存覆盖 GPU 的本地 DRAM 和系统内存。

**L2 缓存子系统还实现了一项 CPU 不具备的特性**：一组“原子的（atomic）内存读-改-写操作”——即这些操作不可中断，因此**非常适合管理“需在多个线程块甚至多个内核间共享的数据”的访问**。通常，CPU 需通过两步流程实现这一功能：先使用“原子测试与置位指令”管理信号量（用于协调多线程访问共享资源的同步机制），再通过信号量管理对内存中特定位置或区域的访问。

Fermi 在需要时也可实现上述方案，但从软件角度来看，更简单的方式是：直接派发一条标准整数 ALU 指令来执行原子操作，无需等待信号量可用。

#### 原子操作

:mdnice-bold-italic[Fermi 的原子操作由一组整数 ALU 逻辑实现：在“读-改-写”序列执行期间，这些 ALU 会锁定对单个内存地址的访问。] 该内存地址可位于系统内存、GPU 本地连接的 DRAM，甚至其他 PCI Express 连接设备的内存空间中。在短暂的锁定期间，内存的其他部分仍可正常运行。对于“在系统内存中执行的锁定操作”，其原子性仅相对于执行该操作的 GPU 而言；通常会通过软件同步将内存区域分配给 GPU 控制，以避免 CPU 或其他设备的写入冲突。

以一个“计算图像直方图（直方图指统计图像中每个亮度级别的像素数量）”的内核为例：CPU 可能会循环遍历整幅图像，根据每个像素的亮度增量相应的计数器值。而不支持原子操作的 GPU，可能会为图像的每个部分分配一个 SM，让它们运行到结束（通过设置同步屏障，确保所有 SM 完成各自任务后再继续），然后运行一个简短的辅助程序来汇总所有结果。

借助 Fermi 中的原子操作，一旦计算出各区域的直方图，就可通过“原子加法操作”将这些结果合并为最终直方图，**无需再进行第二次处理。**

类似的改进还可应用于其他应用，例如光线追踪（一种逼真的 3D 渲染技术）、模式识别、以及线性代数程序（如常用的基本线性代数子程序（BLAS）中实现的矩阵乘法）。**根据 NVIDIA 的数据，Fermi 上的原子操作比前一代 GPU 使用“常规同步方法”时快 5 至 20 倍。**

#### DRAM

本地内存层级的最后一级是 GPU 直接连接的 DRAM。Fermi 提供 6 个 64 位 DRAM 通道，支持 SDDR3 和 GDDR5 两种 DRAM 类型。该芯片最多可连接 6GB 的 GDDR5 DRAM，相比 NVIDIA 之前的产品，在容量和带宽上都有显著提升。

#### ECC

Fermi 是**首款为 DRAM 提供 ECC（错误校验码，Error Correcting Code）保护的 GPU**；其**寄存器文件、共享内存、L1 缓存和 L2 缓存也均受 ECC 保护**。

保护级别为 SECDED（单比特错误纠正、双比特错误检测，Single Error Correction, Double Error Detection）——这是大多数支持 ECC 的系统采用的标准保护级别。

Fermi 对 DRAM 的 ECC 保护在 GPU 中是独一无二的，其实现方式也同样独特。其他系统通常为每个 64 位内存通道额外携带 8 位 ECC 信息，而 :mdnice-bold-italic[NVIDIA 采用了一种专有（且未公开）的方案：将 ECC 位打包到内存的预留行中。]

#### GigaThread 控制器

前文提到的“管理应用上下文切换的 GigaThread 控制器”，还提供了两个流式数据传输引擎——每个引擎都能使 Fermi 的 PCI Express 主机接口达到满带宽。通常，一个引擎用于“**在 GPU 计算初始化时将数据从系统内存传输到 GPU 内存** ”，另一个则用于“**将计算结果从 GPU 内存传输回系统内存** ”。

## 五、结论

> 在短短几年内，NVIDIA 就将 GPU 设计的技术水平从“几乎纯图形导向的产品（如 7800 系列）”推进到了“**灵活的 Fermi 架构** ”。

Fermi 仍源自 NVIDIA 的图形产品，这一特性确保 NVIDIA 能向 PC 游戏玩家销售数百万颗软件兼容的芯片。在 PC 市场中，Fermi 的 GPU 计算能力将为游戏体验、多媒体编码与增强以及其他热门 PC 应用带来显著提升。

面向 PC 用户的这些销售，也为“主要关注高性能计算的客户”带来了间接益处：在 Fermi 所处的性能区间内，其**性价比** 和**可获得性** 是其他任何计算架构都无法比拟的。

::: block-1
尽管从表面上看，每一代新 GPU 产品似乎都变得更“像 CPU”，但“不同计算应用的根本性技术差异”，导致 CPU 与 GPU 在设计和使用方式上的区别将长期存在。
:::

- **CPU 仍将是“动态工作负载（指工作负载的线程数量、操作类型随时间变化大）”的最佳选择** ——这类工作负载的特点是:mdnice-bold-italic[“计算操作序列短、控制流不可预测”。现代 CPU 将芯片硅面积的很大一部分用于缓存、大型分支预测器和复杂的指令集解码器]，而这些设计正是为了优化这类代码的执行。
- **与之相反，对于“以计算任务为主、控制流相对简单”的工作负载，则需要一种不同的处理器架构** ——这种架构既要:mdnice-bold-italic[针对流计算（指数据以连续流的形式输入并处理）进行优化，又要具备支持主流编程语言的能力]。Fermi 正是这样一种架构。

> Fermi 是首个“单芯片就能提供超高双精度浮点性能、具备灵活且带错误保护的内存层级、并支持 C++和 FORTRAN 等语言”的计算架构。正因如此，Fermi 成为了**全球首个完整的 GPU 计算架构**。
