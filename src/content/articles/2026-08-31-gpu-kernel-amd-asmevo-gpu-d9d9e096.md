## 一、GPU 内核优化的“最后一公里”困境

> 现代机器学习工作负载的性能，:mdnice-bold-italic[不仅取决于高层调度策略，更取决于编译后底层指令的细节实现。等待计数器的放置、指令选择、寄存器分配、内核描述符与元数据]，每一处微小的决策都会最终影响内核的运行延迟。

编译器、张量程序自动调优器、领域特定语言与厂商库已经在源码层面做了大量优化:mdnice-bold-italic[，但这些优化都止步于编译生成代码对象的那一刻。一旦内核成为可部署的 AMDGPU 代码对象，剩余的优化空间就无法再通过源程序暴露]，而在很多实际部署场景中，源码本身就不可获取。

这种无源码的场景在已部署的机器学习系统中非常普遍。服务栈可能只暴露编译后的 HSACO 文件、即时编译的缓存产物，或者厂商提供的二进制文件，比如 AITer 代码对象，或者嵌入在 vLLM 与 SGLang 中的 Triton 生成内核。:mdnice-bold-italic[直接优化这些已部署的产物很有吸引力，因为它针对的就是 GPU 上实际运行的代码，但这件事也非常脆弱。一条本地指令的修改就可能破坏内存、违反内核参数的 ABI 约定、导致元数据失步，或者只是因为改变了语义而看起来更快，实际结果却是错误的。]

> 近年来基于 LLM 的内核优化系统发展迅速，KernelBench 建立了执行引导的优化框架，通过正确性与性能反馈迭代优化生成的内核。后续工作又引入了强化学习、智能体进化搜索、专用内核生成模型等方向。:mdnice-bold-italic[但这些方法都假设存在可编辑的源文件和独立的参考实现，编译后的代码对象两者都不具备，原始二进制既是部署的产物，也是唯一的行为参照。]

::: block-1
总之，:mdnice-highlight[编译完成并不等于优化终点，部署后的二进制内核仍然存在可挖掘的性能空间]，但传统的源码级优化方法无法触达这一层级，核心瓶颈在于缺乏可靠的正确性验证机制与兼容的二进制修改手段。
:::

## 二、AsmEvo 整体架构：严守正确性的 Agent 优化流水线

> AsmEvo 的**核心设计原则是正确性优先于性能**。所有候选优化都必须先通过功能等价验证，再进行性能测试，从机制上杜绝“跑得快但算得错”的优化结果。

**AsmEvo 的整体工作流围绕原始代码对象展开，整个流程可以分为恢复、分析、修改、构建、验证五个环节**，由确定性控制器负责所有正确性相关的操作，由 LLM 智能体负责提出优化修改，两者严格分离。

::: block-1
整个系统的输入是原始目标代码对象 K0，首先通过恢复模块将二进制转换为可编辑的 AMDGCN 汇编代码，同时保证往返保真，也就是**重新汇编后可以得到和原始一致的二进制。随后通过性能分析定位热点指令窗口，作为智能体修改的目标**。

智能体提出的汇编修改会被重新构建为代码对象，然后经过多层门控验证，只有通过所有检查并且确实带来性能提升的候选，才会被提交到优化谱系中。
:::

### 2.1 四层门控验证机制

> AsmEvo 为每一个候选优化设置了四层验证门，只有依次通过所有门的候选才能进入下一步，任何一步失败都会直接返回结构化的错误反馈给智能体。

![文章插图](/articles/2026-08-31-gpu-kernel-amd-asmevo-gpu-d9d9e096/images/06.jpg)

::: image-caption
图 1：AsmEvo结合了可靠的代码对象恢复、元数据感知的ABI保留重建，以及针对原始$K_0$的正确性优先于性能的评估机制。模块化LLM驱动通过多起点搜索、验证式组合与防失速重定向提出修改，只有经过验证的、延迟降低的候选才会进入谱系。 该图完整呈现了“恢复-分析-修改-构建-验证”五阶段闭环流水线，左侧为输入输出通路，中间为确定性控制器的四层门控（G0-G4），右侧为Agent搜索驱动模块。核心设计在于将搜索智能体与验证闸门完全解耦：智能体只负责提出修改方案，所有正确性与性能判定均由确定性流程执行，从架构上杜绝了“为提速牺牲正确性”的可能。
:::

- 第一层是**汇编有效性检查**，:mdnice-bold-italic[验证修改后的汇编代码是否可以正常汇编通过]，存在语法错误、标号不匹配等问题的候选会直接被拒绝。
- 第二层是**静态 ABI 与资源一致性检查**，:mdnice-bold-italic[验证构建后的代码对象是否保留了原始的内核参数布局、符号接口、启动语义]，资源声明是否在合理范围内，确保优化后的内核可以被上层程序正常调用。
- 第三层是**功能等价验证**，使用原始二进制作为参照，在完全相同的输入与启动配置下运行候选内核，对比输出结果是否符合等价标准。:mdnice-bold-italic[这一层是正确性保障的核心，所有性能测试都必须在通过这一层之后进行。]
- 第四层是**提交门限**，即使候选内核功能正确且速度更快，也要满足设定的提升幅度门槛，并且考虑测量波动的影响，只有确定是真实的性能提升才会被提交。

::: image-caption
算法 1 GatedEval：验证并计时一个候选修改。输入：修改后的汇编$s'$；预言机$(X, O)$；原始$K_0$。该算法是“正确性优先”原则的核心具象化，执行严格的串行校验流程：第一步校验汇编可编译性，第二步校验静态ABI与资源一致性，第三步遍历所有测试输入完成功能等价校验，以上三步全部通过后才进入第四步性能计时。任何一步失败都会立即返回对应错误类型，不会进入后续环节，确保性能测试永远只在功能正确的候选上执行。

### 2.2 确定性控制器与智能体的职责分离

> AsmEvo **最关键的设计选择之一，是将正确性控制与优化探索完全分离**。确定性控制器掌握所有的正确性关键操作，:mdnice-bold-italic[包括构建验证、资源检查、等价验证、性能计时、提交阈值与谱系管理，所有规则都是硬编码的确定性逻辑，不会被智能体修改。]

LLM 智能体只负责分析性能数据、选择瓶颈位置、提出局部汇编变换、解释失败原因、在无收益尝试后重新规划。智能体可以引导探索方向，但无权判定任何一个候选的正确性或性能，所有结论都由确定性控制器通过实际运行得出。

::: block-1
整体看下来，:mdnice-highlight[严守正确性的架构设计是 AsmEvo 可以安全优化二进制的核心]，它把学习式探索的灵活性与确定性验证的可靠性结合起来，让智能体的优化探索始终在安全的边界内进行。
:::

## 三、核心技术拆解：从二进制恢复到差分验证的全链路

> 要在汇编层面优化二进制，首先要解决三个基础问题：

1. **如何从二进制得到可修改的汇编代码**
2. 如何**知道修改后的内核功能是否正确**
3. 如何让**修改后的内核可以正常被调用**

这三个问题分别对应代码恢复、差分验证与元数据重建三项核心技术。

### 3.1 代码对象恢复与往返保真

> :mdnice-bold-italic[优化的第一步是从 AMDGPU ELF 格式的二进制文件中，重建出可重新汇编的汇编代码]。原始的反汇编只会输出指令序列，缺少声明层的信息，无法直接重新汇编成可用的代码对象。

AsmEvo 会恢复二进制中的段信息、符号表、注释、内核描述符、AMDGPU 元数据以及 AMDGCN 指令体。它还会重建内核声明，并且将程序计数器相对的控制流重新符号化，也就是把跳转指令里的数字地址替换成标号，这样在插入、删除或者重排指令后，跳转仍然是有效的。

为了保证恢复的准确性，AsmEvo 设置了一次性的往返验证门：将恢复出来的汇编重新汇编、重新链接，然后和原始二进制对比指令体、内核描述符与元数据，只屏蔽由链接过程决定的字段。通过这道门就证明恢复出的表示是忠实且可重建的，后续的所有修改都基于这个可靠的基础进行。

### 3.2 双层差分预言机机制

> **功能等价验证需要用相同的输入运行原始内核与候选内核，然后对比输出**。但代码对象既不暴露高层函数签名，也不暴露构建指针参数的应用逻辑，:mdnice-bold-italic[如何生成合法的测试输入是核心难题。AsmEvo 提出了双层差分预言机机制来解决这个问题。]

- **第一层是合成推断**。:mdnice-bold-italic[当启动结构可以从描述符和元数据中推断出来时，AsmEvo 会推断参数偏移、标量类型、指针角色、缓冲区大小与启动维度，然后生成确定性的测试输入，覆盖典型的形状、步长、数据类型、边界值与随机种子]。分配内存时会在缓冲区周围设置保护区域，初始化为金丝雀值，这样等价检查不仅可以发现输出不一致，还能检测出越界写错误。
- **第二层是真实调度捕获**。对于很多生产内核，仅靠元数据不足以推断启动结构，比如使用混合数据类型、非连续张量、块表、嵌套指针结构或者应用定义工作区布局的内核。对于这类内核，AsmEvo 会截获一次真实的应用调度，:mdnice-bold-italic[记录内核参数缓冲区、网格与工作组维度、引用的设备内存区域以及调度前的内存状态。] 原始对象执行一次后得到参考状态，后续候选内核都在完全相同的状态下重放。

当捕获的参数包含绝对设备指针时，内存区域会恢复到原来的虚拟地址，这样嵌套指针仍然有效，不需要重建应用层的数据结构。

- 对于浮点输出，使用余弦相似度与最大误差进行检查；
- 对于整数缓冲区、不透明状态与保护区域，则进行字节精确的检查。

> 功能等价的判断标准可以用公式表示：

$$
eq(K',x) \equiv c_{x} \geq \theta \land \|\Delta_{x}\|_{\infty} \leq \tau \land \iota(K',x)
$$

其中

$$
c_{x}=cos\left(K'(x), O(x)\right), \Delta_{x}=K'(x)-O(x)
$$

公式中，$K'$ 代表优化后的内核，$x$ 代表输入，$O(x)$ 代表原始内核的输出，$c_x$ 是两者输出向量的余弦相似度，$\theta$ 是相似度阈值，$\Delta_x$ 是输出的差值向量，$\tau$ 是允许的最大绝对误差，$\iota$ 是额外约束条件，要求整数缓冲区字节精确一致、越界保护区域完整无损。

### 3.3 元数据感知的重建与保守补丁

> :mdnice-bold-italic[修改完汇编代码后，需要重新构建成可加载的代码对象。AsmEvo 会重新扫描汇编代码中的向量通用寄存器、标量通用寄存器、本地数据存储与暂存区使用情况，然后重新计算内核描述符与 AMDGPU 元数据中的资源字段，再重新链接成对象]。整个过程中，内核参数布局、参数段大小、符号接口与启动语义都保持固定，确保和原始调用者兼容。

如果正常重建失败，比如对象包含不支持或者未完全恢复的结构，AsmEvo 可以使用保守的原地字节补丁作为回退方案。这种回退只允许资源中立且大小不增加的修改，保留原始的描述符与元数据。打过补丁的候选仍然要通过静态一致性、差分等价与性能检查，回退改变的只是重建机制，不是接受标准。

::: block-1
回顾一下，:mdnice-highlight[双层预言机机制解决了无源码下的正确性验证难题]，既可以处理简单的基准内核，也可以适配复杂的生产内核，让所有优化都建立在功能等价的可靠基础上。
:::

## 四、Agent 搜索机制：长视野多起点的进化式优化

> 有了可靠的验证底座，接下来需要**高效的搜索机制来找到有效的汇编优化**。AsmEvo 没有采用随机搜索，而是:mdnice-bold-italic[使用长视野的智能体搜索驱动，结合热点定位、多起点探索、验证式组合与防失速机制]，在庞大的搜索空间中找到有效的优化。

### 4.1 热点窗口定位

完整的 GPU 内核汇编代码可能非常长，如果把整个内核都放到优化上下文中，搜索空间会过于庞大。**AsmEvo 通过硬件计数器、指令采样与静态分析，识别内核中占比最高的 stall 主导指令窗口**，也就是热点区域。

生成的性能分析报告会总结指令组合、依赖链、内存行为、占用率约束与资源压力，提供给搜索智能体。AsmEvo 不会每次都修改整个汇编，而是:mdnice-bold-italic[选择一个热点窗口，连同周围的数据依赖与相关元数据一起作为优化上下文。提出的局部修改会被拼接回完整的汇编代码，再进行全内核的构建与验证。]

这种热点窗口定位的方式，既减小了搜索上下文，又避免了无关修改，同时没有降低全内核的接受标准，所有修改最终都要经过完整内核的验证。

### 4.2 多起点探索与验证式组合

> AsmEvo 支持两种搜索模式：

- 单模式下，智能体从当前最优版本出发提出一个修改；
- 团队模式下，规划器会分配正交的优化方向给并行的工作器，比如延迟隐藏、依赖减少、寄存器压力控制、内存访问重构、指令简化等。

和传统的链式优化不同，**AsmEvo 的起点选自不同的已验证谱系节点，而不是要求所有工作器都修改同一个候选**。每一个提议都会独立进行构建与验证，避免相互干扰。

::: block-1
单独成功的修改组合在一起，不一定仍然正确或者仍然有益。:mdnice-bold-italic[AsmEvo 的整合器会考虑那些共享基础版本、修改不相交或互补指令区域的候选，逐步应用它们的修改，每一步都重新构建与验证。只有当组合后的版本通过所有正确性检查，并且性能超过两个父代候选时，才会被提交；否则保留最好的单个候选。]
:::

### 4.3 记忆与防失速监督

> **AsmEvo 维护一个有界的运行记忆，存储成功的优化经验、结构化的门控结果、失败特征与重复候选的哈希值**。如果控制器检测到长时间没有性能提升、重复提出相同的修改，或者基础设施出现故障，就会请求重定向，总结已经尝试过的方向，标记已经穷尽的假设。

智能体收到重定向请求后，可以更换目标瓶颈，或者回退到更早的已验证节点。如果持续失速，就会升级到更广泛的多起点探索。所有重定向后的候选仍然遵循相同的确定性门控规则，不会因为要解决失速就降低验证标准。

整个优化循环的逻辑由算法 2 总结，控制器在每次评估后都会将每个工作器重置到已验证状态，防止未验证的修改在迭代中累积。

![文章插图](/articles/2026-08-31-gpu-kernel-amd-asmevo-gpu-d9d9e096/images/08.jpg)

::: image-caption

总之，:mdnice-highlight[长视野智能体搜索结合了 LLM 的架构知识与进化式搜索的鲁棒性]，在保证正确性的前提下，能够高效探索汇编层面的优化空间，找到人类难以发现的低层级优化机会。
:::

> 研究团队在 **AMD CDNA3 架构的 Instinct 显卡上进行了全面的实验**，覆盖基准测试内核与真实生产内核，所有报告的提速都经过了功能等价验证。

- :mdnice-bold-italic[Level 1 的 15 个内核全部得到优化，几何平均提速 1.56 倍]，其中深度卷积、激活函数、归一化、矩阵乘法等算子都有显著提升。

### 5.3 典型案例分析

> 最大的 KernelBench 提升出现在深度卷积内核，达到 3.88 倍。另外两个 Level 1 内核也有大幅提升：MinGPTNewGelu 达到 3.82 倍，RMSNorm 达到 2.63 倍，上三角矩阵乘法提升 2.28 倍。**这些算子覆盖了卷积、激活、归一化与结构化矩阵乘法，说明优化收益并不局限于某一种指令模式。**

最强的 Level 2 案例是**矩阵乘法+Swish+求和+组归一化的融合算子，达到 2.55 倍**。:mdnice-bold-italic[AsmEvo 将完整内核作为接受单位，局部汇编修改会重建到完整代码对象中，只有当融合输出通过相同的差分验证时才会保留，这对于融合流水线非常重要]，因为看似独立的指令序列可能会影响后续的归约、归一化或激活阶段。

生产内核中，vLLM 的融合 MoE 内核提升 1.343 倍，量化块式 GEMM 内核也有 1.234 倍的提升，**说明即使是为生产服务栈生成的量化内核，仍然存在可挖掘的汇编级优化空间**。AITer 的 FP8 块式 MoE 内核提升 1.31 倍，收益主要来自长延迟内存操作周围的调度优化、等待计数器放置、缓存提示与缓冲区加载变体，以及减少的转换或地址生成工作。

::: block-1
整体看下来，:mdnice-highlight[AsmEvo 在基准与生产环境都验证了汇编级优化的价值]，无论是简单算子还是复杂融合算子，无论是厂商二进制还是 JIT 生成内核，都可以找到有效的性能提升，并且保证功能等价与 ABI 兼容。
:::

## 六、定位与意义：补全编译器优化的最后一块拼图

> **AsmEvo 是在编译完成之后增加一层新的优化**，补全从源码到二进制全链路优化的最后一块拼图，不取代现有的编译器与自动调优器。

从定位来看，:mdnice-bold-italic[现有的源码级内核智能体都设计为处理可编辑的源文件，并且依赖高层参考实现来验证正确性，无法直接处理只有二进制的场景。AsmEvo 则针对互补的后编译场景，输入是编译好的 AMDGPU 代码对象，原始二进制本身作为行为参照。]

> 和现有的汇编优化工作相比，AsmEvo 有明显的区别。

传统的超级优化器针对 CPU 汇编或者 NVIDIA SASS 指令调度，假设存在 CPU 规格说明或者受限的变换集合。而 :mdnice-bold-italic[AsmEvo 针对无源码的 AMDGPU 代码对象，同时解决了汇编恢复、ABI 与元数据保留重建、更广泛的智能体提议修改，以及针对原始二进制的差分验证等全链路问题。]

现有的 GPU 二进制框架主要面向插桩分析，比如 NVBit 和 Luthier，增加开销是可接受的。而 **AsmEvo 的目标是生成更快、经过验证的即插即用对象，同时保留调用者语义、资源声明、描述符与元数据。**

:mdnice-bold-italic[AsmEvo 的实际落地价值很高。对于厂商提供的闭源库、第三方框架生成的 JIT 缓存、历史遗留的无源码内核，都可以直接使用 AsmEvo 进行优化，不需要修改上层代码，不需要重新编译，只需要替换二进制文件即可获得性能提升]。对于大规模部署的机器学习服务，这种零侵入的优化可以带来显著的成本节约。

::: block-1
总之，:mdnice-highlight[AsmEvo 定义了后编译时代 GPU 内核优化的新范式]，将优化的边界从源码层推进到汇编层，让部署后的二进制内核可以持续获得性能提升，同时保持功能与接口的完全兼容。
:::

## 总结与展望

> AsmEvo 将 GPU 内核优化延伸到了无源码的 AMDGPU 代码对象场景，使用原始二进制作为行为预言机，只有通过 ABI 保留重建与功能等价验证的候选才会被接受。

这项工作的核心贡献可以总结为三点：

| 贡献 | 描述 |
| --- | --- |
| 问题形式化 | 将无源码、保留 ABI 的 GPU 内核优化形式化为代码对象上的正确性门控后编译问题，原始二进制作为差分正确性预言机，所有报告的提速都必须经过外部验证 |
| 流水线构建 | 构建了一套二进制恢复、重建与差分验证流水线，包括可重汇编 AMDGCN 汇编的往返恢复、元数据感知的 ABI 保留重建、保守补丁回退，以及结合合成启动推断与真实调度重放的双层预言机 |
| 智能体搜索 | 实现了外部验证下的长视野智能体搜索驱动，智能体可以规划架构特定的修改，使用失败尝试作为记忆，探索多样的已验证起点，组合兼容的改进，并且从失速中恢复，而正确性与计时由确定性门控负责 |

实验结果充分验证了方法的有效性：

- 在 MI308X 上优化了 30 个 KernelBench 内核中的 29 个，几何平均提速 1.35 倍，最高 3.88 倍；
- 在 MI300X 上优化了所有 8 个生产内核，AITer 与 Triton 系列分别达到 1.09 倍与 1.18 倍的几何平均提速。

这些结果说明，部署后的二进制内核仍然存在可恢复的低层级优化空间，而智能体搜索可以在确定性门控的保障下安全地挖掘这些空间。

当然，这项工作也存在局限。**AsmEvo 提供的是经验性的差分等价，而不是形式化验证，保证范围仅限于评估过的输入与启动配置，新的输入形状需要新的推断输入或者调度捕获**。整体框架是架构无关的，但当前的恢复与元数据感知重建实现是针对 CDNA 系列 AMD GPU 校准的。:mdnice-bold-italic[复杂的应用状态可能需要真实调度捕获，而可获得的收益取决于编译内核中剩余的优化空间。]

::: block-1
未来可以从多个方向扩展这项工作，比如支持更多的 GPU 架构，:mdnice-highlight[引入更形式化的等价验证方法，和编译期优化结合形成全链路优化流程，或者将智能体搜索从汇编层延伸到更底层的硬件特性层面]。随着大语言模型能力的提升，**汇编级的自动优化有望成为 GPU 性能优化的常规手段。**
:::
