关键词：大语言模型、**KV 缓存**、:mdnice-bold-italic[强化学习]、**缓存驱逐**、:mdnice-bold-italic[长上下文推理]

> 自 Transformer 架构诞生以来，大型语言模型（LLMs）在自然语言处理领域掀起了革命性浪潮。从文本生成到逻辑推理，从多轮对话到长文档理解，LLMs 的能力边界不断拓展。然而，模型性能的飞跃背后，是日益严峻的推理效率挑战——尤其是**当处理长序列或交互式会话时，KV（Key-Value）缓存成为制约系统部署的核心瓶颈。**

:mdnice-bold-italic[KV 缓存的设计初衷是“空间换时间”的优化智慧]：在自回归生成过程中，模型需要不断参考历史 token 的信息，KV 缓存通过存储先前 token 的键（Key）和值（Value）向量，避免了重复计算注意力分数，将推理复杂度从 O(n²)降至 O(n)。**但这种优化的代价是内存占用的线性增长：对于长度为 4500token 的序列，KV 缓存可能消耗数十 GB 显存，远超现代硬件加速器的承载能力**。例如，Llama-3-70B 模型处理 128K token 的长文本时，仅 KV 缓存就需要 42GB 内存。

::: block-1
为解决这一问题，研究人员提出了多种 KV 缓存管理方案：从简单的最近最少使用（LRU）驱逐，到利用注意力分数的复杂启发式方法，再到量化压缩和低秩近似技术。:mdnice-bold-italic[但这些方法普遍存在一个致命缺陷——它们依赖于间接的优先级代理（如近期性、历史注意力分数），而非直接优化 token 对未来解码的实际效用。 正如 Apple 团队在论文中指出的：“一个 token 的真正价值取决于其对未来生成步骤的贡献，而现有方法【从未】直接优化这一核心目标”。]
:::

## 一、背景知识：KV 缓存驱逐的核心挑战与现有方案局限

在深入解读 KVP 之前，我们需要先明确 KV 缓存驱逐的核心问题本质，以及现有方案为何难以满足长上下文推理的需求。

### 1.1 KV 缓存的工作机制与驱逐问题本质

> Transformer 模型的自注意力机制中，每个 token 会生成查询（Q）、键（K）和值（V）三个向量。在推理过程中，模型分为两个阶段：

- **Prefill 阶段**：处理完整输入提示，计算所有 token 的 K 和 V 向量并存储到 KV 缓存中，此阶段为计算密集型；
- **Decode 阶段**：逐一生成输出 token，新 token 的 Q 向量仅需与缓存中的历史 K/V 向量计算注意力，新生成的 K/V 向量则追加到缓存中，此阶段为内存带宽密集型。

::: block-1
KV 缓存驱逐的核心问题可以形式化为：给定 $n$ 个 token 的集合 $X$ 和内存预算 $b$，选择子集 $\mathcal{S}^*⊂X$，使得下游任务性能损失最小化，即：

$$
\mathcal{S}_{b}^{* }\in arg \operatorname* {max}_{|\mathcal{S}|=b,\mathcal{S}\subset \mathcal{X}}R(\mathcal{S})
$$
:::

其中 $R(S)$为子集 $S$ 的性能奖励。这一问题看似简单，实则:mdnice-bold-italic[具有 NP-hard 复杂度，尤其当序列长度超过数千 token 时，如何精准识别“关键 token”成为核心挑战。]

### 1.2 现有 KV 缓存管理方案分类与局限

> 作者将现有方案分为四大类，各类方法的核心思路与缺陷如下，清晰展示了现有方案在“精准性-效率-泛化性”三者之间的权衡困境：

| 方法类别 | 核心思路 | 核心局限 |
| --- | --- | --- |
| **基于注意力的驱逐方法** | 利用历史注意力分数或 Q-K 相似度筛选 token（如 StreamingLLM 保留 attention sinks，SnapKV/TOVA 动态剪枝） | ① 向后看：依赖历史模式，难适应动态生成；② 计算开销大：需重复统计注意力，不兼容 FlashAttention；③ 依赖当前查询，限制预填充阶段优化。 |
| **内存层次管理方法** | 将 KV 条目卸载至 CPU 内存等二级缓存（如 IceCache、ArkVale、MagicPig） | ① 加载延迟高：CPU↔GPU 数据搬移引入显著 IO 开销；② 卸载策略依赖人工启发式，缺乏数据驱动优化。 |
| **表示压缩方法** | 降低单条 KV 向量存储成本（如 Minikv 量化、Loki/Palu 低秩近似、MorphKV 状态合并） | ① 性能损失：过度压缩损害生成质量；② 未触及本质：仅压缩“如何存”，未解决“保留哪些 token”的选择问题。 |
| **学习型方法（早期探索）** | 利用模型激活或序列摘要生成驱逐信号（如 Gisting Token、Activation Beacon） | ① 粒度粗糙：多为序列级摘要，缺乏 token 级精细排序；② 缺乏针对性：非专为 KV 缓存动态驱逐设计，泛化性与实用性受限。 |

## 二、KVP 的核心创新：从启发式规则到强化学习排序

Apple 团队的 KVP 框架**通过四大核心创新，彻底重构了 KV 缓存驱逐的解决思路**，实现了“精准预测-高效推理-泛化能力”的三重突破。

### 2.1 创新一：问题重构——将驱逐转化为未来效用排序任务

> KVP 的首要创新是打破了“基于代理指标筛选 token”的传统思路，直接将 KV 缓存驱逐问题定义为“预测 token 未来效用并排序”的学习任务。

论文通过两个关键假设简化问题复杂度：

1. **唯一性假设**：对于每个预算 b，存在唯一的最优子集 $S^*_b$；
2. **嵌套性假设**：最优子集满足 $S^*_b ⊂ S^*_{b+1}$，即小预算下的关键 token 在大预算下仍需保留。

基于这两个假设，作者证明了**KV 缓存驱逐问题等价于 token 的全序排序问题** （命题 1）：存在一个排序 $\pi$，使得对于任意预算 b，最优子集 $S^*_b$ 恰好是排序中前 b 个 token。:mdnice-bold-italic[这一证明至关重要，它在唯一性和嵌套性假设下，将 NP-hard 的最优子集选择问题，转化为一个等价的、可学习的排序任务，为后续的强化学习建模奠定了理论基础。]

命题 1 的形式化表述如下：

$$
S_{b}^{*}=\{i \in[n]: \pi(i) \leq b\} \quad for\ all\ b
$$

::: block-1
其中 $\pi$ 为 token 的全序排序函数。**这一转化的核心价值在于：无需为每个预算单独设计驱逐策略，只需学习一个全局排序规则，即可适配所有内存约束场景。**
:::

### 2.2 创新二：架构设计——per-head 轻量级 RL 智能体

> 为充分捕捉不同注意力头的专用特性，KVP 提出了“**per-head 智能体** ”架构：**为 LLM 的每个 KV 头训练一个独立的轻量级 RL 智能体**，【每个智能体】专门学习【对应头】的 token 排序策略。

#### 2.2.1 智能体输入表示

每个 token 的输入特征仅包含三部分信息，均来自 KV 缓存本身，无需额外计算：

- 键向量 $k_i$：token 的 Key 向量；
- 值向量 $v_i$：token 的 Value 向量；
- 位置编码 $pos_i$：token 在序列中的原始位置。

输入特征表示为 $x_i = (k_i, v_i, pos_i)$，确保智能体决策完全基于缓存中已有的静态信息，不依赖未来 token 或查询向量，与高效推理框架兼容。

#### 2.2.2 评分函数与排序机制

::: block-1
智能体的核心是一个轻量级多层感知机（MLP），参数总量仅约 600K，避免了额外的计算负担。MLP 输出 token 的未来效用评分 $f(x_i; \theta)$，其中 $\theta$ 为智能体参数。
:::

为实现高效的随机排序，KVP 采用 Plackett-Luce 模型建模排序分布，排序概率为：

$$
\pi_{\theta}\left(\sigma | x_{1}, ..., x_{N}\right)=\prod_{i=1}^{N} \frac{exp \left(f\left(x_{\sigma_{i}} ; \theta\right)\right)}{\sum_{j=i}^{N} exp \left(f\left(x_{\sigma_{j}} ; \theta\right)\right)}
$$

为解决序列采样的低效问题，KVP 引入 Gumbel-Sort 技术，通过添加 Gumbel 噪声实现并行采样：

$$
\sigma=argsort_{i\in[N]}\left(f(x_{i} ; \theta)+g_{i}\right)
$$

其中 $g_i ~ Gumbel(0,1)$为独立同分布的噪声。这一优化使排序采样可在单次前向传播中完成，完全适配现代硬件的并行计算能力。

#### 2.2.3 per-head 设计的合理性

**不同注意力头在 LLM 中承担着不同的语义功能**：有的关注语法结构，有的捕捉语义关联，有的跟踪指代关系。**作者通过实验验证：单一启发式规则无法适配所有头的特性**，这个得看图 15 —— StreamingLLM 在部分头表现优异（图中浅蓝色），在另一些头则性能糟糕，这种巨大的性能波动，恰恰说明了无法用单一规则适配所有头，从而凸显了per-head专用策略的必要性。对应下图:mdnice-bold-italic[图 15，不过此图太大了，即使这里贴出来也看不清，我在图 15 下面的注释里补充了一些信息。]

### 2.3 创新三：奖励设计——全局预算无关的离线 RL 奖励

> KVP 的第三个核心创新是设计了一种全局、预算无关的奖励函数，能够在不进行额外 LLM 推理的情况下，评估排序策略在所有可能预算下的性能。

#### 2.3.1 奖励函数定义

奖励函数的核心思想是：**排序策略的优劣取决于其在所有预算下保留高未来效用 token 的能力**。具体分为三个步骤：

1. **计算 token 的真实未来效用**：对于训练数据中的每个 token $x_i$，计算其在未来 $f$ 个 token 生成过程中获得的累计注意力分数，即：

$$
\text{Importance}(x_i) = \sum_{j=n+1}^{n+f} A(x_i, x_j)
$$

其中 $A(x_i, x_j)$ 为 token $x_i$ 与未来 token $x_j$ 的注意力分数（GQA 模型取组内最大注意力值）。

1. **计算单预算奖励**：对于给定排序 σ 和预算 $b$，保留前 $b$ 个 token，驱逐剩余 token。单预算奖励为驱逐 token 的总未来效用的负值（即最小化驱逐损失）：

$$
\mathcal{R}^{b}\left(\sigma_{1}, ..., \sigma_{n} ; \mathcal{X}\right)=-\sum_{i=b+1}^{n} \sum_{j=n+1}^{n+f} A\left(x_{\sigma_{i}}, x_{j}\right)
$$

1. **全局奖励聚合**：总奖励为所有预算（$1≤b≤n-1$）的单预算奖励之和，:mdnice-bold-italic[这意味着，一个排序若要获得高分，必须在任何缓存大小下都能将高未来效用的token保留下来，从而确保学习到的策略能够适应动态变化的内存约束]：

$$
\mathcal{R}\left(\sigma_{1}, ..., \sigma_{n} ; \mathcal{X}\right)=\sum_{b=1}^{n-1} \mathcal{R}^{b}\left(\sigma_{1}, ..., \sigma_{n} ; \mathcal{X}\right)
$$

最后，通过最优排序的奖励进行归一化，使奖励值不受注意力分数分布的影响，确保训练稳定性。

#### 2.3.2 奖励函数的优势

- **全局优化**：:mdnice-bold-italic[同时考虑所有预算场景，避免策略在某一预算下表现优异而在其他预算下性能糟糕；]
- **离线计算**：基于预计算的生成轨迹计算奖励，:mdnice-bold-italic[无需在 RL 训练过程中运行 LLM，大幅降低训练成本；]
- **直接优化核心目标**：奖励直接关联 token 的未来效用，而非间接代理指标，确保学习方向的正确性。

### 2.4 创新四：训练与推理效率——离线训练+零推理开销

> KVP 在设计之初就充分考虑了工程实用性，通过离线训练和轻量级架构，实现了“训练高效、推理无额外开销”的目标。

#### 2.4.1 离线训练流程

KVP 的训练完全基于预计算的生成轨迹，无需实时运行 LLM，具体流程如算法 1 所示：

1. **数据准备**：运行基础 LLM 处理训练语料，存储每个序列的 Q、K、V 张量（不存储注意力矩阵以节省空间）；
2. **采样训练数据**：随机采样序列和缓存大小，生成训练样本；
3. **生成排序候选**：智能体生成 K 个排序候选；
4. **计算奖励**：基于预存的未来注意力信息计算每个排序的全局奖励；
5. **更新参数**：使用 REINFORCE 算法结合 Leave-One-Out（RLOO）基线更新智能体参数，梯度估计为：

$$
\nabla_{\theta} J(\theta) \approx \frac{1}{K} \sum_{k=1}^{K}\left[\left(\mathcal{R}\left(\sigma^{k}\right)-\overline{\mathcal{R}}\right) \sum_{i=1}^{n} \nabla_{\theta} log \pi_{\theta}\left(\sigma_{i}^{k} | \mathcal{X}\right)\right]
$$

![文章插图](/articles/2026-03-02-rl-kv-kv-policy-sota-73baa599/images/07.webp)

::: image-caption
算法 1 | 基于预计算 KV 轨迹的强化学习训练流程，核心输入是含 m 条序列的预计算 KV 轨迹静态数据集，每条序列含查询、键、值张量且有对应长度。训练未收敛时，先随机采样数据样本和缓存尺寸；再从智能体中采样 K 个令牌排列结果；接着依据公式 3.4 计算每个排列的奖励值；最后通过公式 3.6 更新智能体的参数 θ，重复上述步骤直至训练收敛。该算法是 KVP 框架高效离线训练的核心，全程无需实时 LLM 推理，仅依托预存的 KV 轨迹完成训练，大幅降低计算开销。采样环节的随机性保障了模型的泛化性，多排列采样与针对性奖励计算让参数更新更贴合令牌未来效用预测的目标，REINFORCE 算法结合 RLOO 基线的使用，还能有效降低梯度方差，提升训练稳定性与效率。
:::

::: block-1
这种离线训练模式的优势在于：训练过程与 LLM 推理完全分离，可利用闲置资源批量完成，且训练时间极短——112 个智能体在 8 块 NVIDIA H100 GPU 上训练仅需 30 分钟。
:::

#### 2.4.2 推理阶段的零额外开销

KVP 在推理阶段的操作完全兼容现有 LLM 推理流程，仅增加 1%的预填充阶段计算开销，解码阶段无任何额外负担：

1. **预填充阶段**：LLM 处理输入提示生成 KV 缓存后，KVP 的 per-head 智能体并行计算所有 token 的排序分数，生成全局排序；
2. **缓存压缩**：根据当前内存预算，保留排序中前 b 个 token，通过自定义注意力掩码实现驱逐（不修改 LLM 架构）；
3. **解码阶段**：新生成 token 的 KV 向量追加到缓存后，仅需重新计算该 token 的排序分数，无需全局重排。

根据作者的 FLOPs 估算：:mdnice-bold-italic[Qwen-7B 模型的预填充阶段开销从 14.00 GFLOPs/token 增加到 14.15 GFLOPs/token，仅增加 1%，而解码阶段无任何额外开销如图 6 所示。]

## 三、关键技术细节：从模型实现到工程优化

### 3.1 智能体架构细节

KVP 的智能体采用极简设计，确保轻量高效：

实验结果如图 5b 所示：监督学习模型的成本曲线（-Rᵇ）高且不稳定，而 RL 模型能够稳定收敛到低损失。作者对此的解释是：:mdnice-bold-italic[KV 缓存驱逐任务具有固有的稀疏性——仅少数 token 对未来生成至关重要，监督学习所依赖的可微分排序代理（Blondel et al., 2020）在此任务上失效，其根本原因在于KV淘汰任务的固有稀疏性]。由于只有极少数token对未来生成至关重要，可微分排序的温度参数难以平衡：

- 低温度：梯度消失，无法有效学习；
- 高温度：梯度稠密但有偏，错误地分散重要性分数。

::: block-1
而 RL 的策略梯度方法通过非可微分排序操作提供无偏学习信号，能够精准聚焦于关键排序决策，避免稀疏性带来的优化难题。
:::

论文通过消融实验验证了 per-head 设计和 RL 训练的必要性：

- **per-head vs 全局智能体**：全局智能体的平均成本（-Rᵇ）比 per-head 设计高 23%，因为其无法适配不同头的专用需求；
- **RL vs 监督学习**：监督学习基线的成本比 RL 高 31%，且训练不稳定，证明 RL 更适合处理稀疏排序任务；
- **全局奖励 vs 单预算奖励**：仅优化单预算奖励的模型在其他预算下性能下降 15-20%，证明全局奖励的重要性。

## 六、总结与未来展望

### 6.1 工作总结

> Apple 团队提出的 KV Policy（KVP）框架，通过四大核心创新，彻底改变了 KV 缓存管理的范式：

1. **问题重构**：将 NP-hard 的子集选择问题转化为 token 未来效用排序任务，奠定理论基础；
2. **架构创新**：设计 per-head 轻量级 RL 智能体，适配不同注意力头的专用特性；
3. **奖励设计**：提出全局预算无关的离线奖励，直接优化核心目标且无需额外 LLM 推理；
4. **效率优化**：离线训练+推理零额外开销，确保工程实用性。

::: block-1
实验结果表明，KVP 在长上下文推理、多轮对话等任务上显著优于现有启发式方法，且具有出色的跨任务、跨模型泛化能力。这一工作证明：:mdnice-bold-italic[学习型方法能够替代手工设计的规则，实现更精准、更自适应的 KV 缓存管理。]

### 6.2 未来研究方向

> 作者指出了三个值得探索的未来方向：

1. **动态预算分配**：当前 KVP 对所有头和层采用统一预算，:mdnice-bold-italic[未来可基于 per-head 排序结果，动态分配内存资源，将更多预算分配给关键头；]
2. **多智能体协同**：当前智能体独立决策，未来可:mdnice-bold-italic[探索头间协同优化，捕捉不同头之间的依赖关系]；
3. **在线学习更新**：当前模型为离线训练，未来可设计:mdnice-bold-italic[在线学习框架，根据实时生成数据自适应更新策略]，进一步提升泛化能力。

### 6.3 实践启示

> KVP 的工作对 LLM 推理优化具有重要的实践启示：

- **从“代理优化”到“直接优化”**：未来的系统优化应:mdnice-bold-italic[更多聚焦核心目标] （如未来效用），而非间接代理指标；
- **轻量级学习集成**：在:mdnice-bold-italic[系统层面集成轻量级学习模型]，可在不显著增加开销的情况下大幅提升性能；
- **模块化设计**：KVP 的模块化架构使其可:mdnice-bold-italic[与量化、压缩、内存层次管理等技术无缝结合]，形成协同优化效应。

随着 LLM 的上下文长度不断突破（从 128K 到 1M），KV 缓存管理的重要性将愈发凸显。KVP 框架为解决这一核心瓶颈提供了全新的思路，有望推动长上下文 LLM 在更多实际场景中的部署与应用——从智能客服的多轮对话，到法律文档的深度分析，再到科学研究的长文本推理，KVP 正在让高效的长上下文推理变得触手可及。
