## 一、Agentic 推理正在重构推理工作负载

> 大语言模型正在从单轮对话交互走向智能体应用，:mdnice-bold-italic[模型需要在多轮交互中完成推理、行动与外部环境交互。这一转变直接改变了底层推理系统的工作负载特征，也让传统统一硬件架构的效率短板彻底暴露。]

代表性的智能体工作负载包括计算机使用智能体、自主编码智能体、网页使用智能体等。:mdnice-bold-italic[在这些交互过程中，截图、网页内容、代码上下文、中间推理结果、工具调用返回、用户反馈会被持续累加到提示词中，对服务系统的内存与计算需求远高于传统聊天机器人推理。]

### 1.1 从单轮对话到多轮 Agent：上下文的数量级跃迁

传统聊天机器人的会话上下文通常在几千 token 量级，**而智能体工作负载的上下文长度会随交互轮次快速增长**。在 OSWorld 基准测试中，智能体会话的平均上下文长度达到 38K token，峰值可突破 100K token，:mdnice-bold-italic[超出标准对话会话一个数量级。]

![文章插图](/articles/2026-08-19-when-does-disaggregation-pay-heteropanacea-8c204134/images/04.jpg)

::: image-caption
图 1a：智能体工作负载具有更大的token使用量。图中对比了标准聊天机器人与计算机使用智能体的预填充token规模，智能体场景的平均上下文达到38K，是传统对话的十余倍。长上下文直接放大了推理各阶段的硬件需求差异，是驱动异构拆解的核心 workload 动因。
:::

上下文长度的增长并非线性提升资源需求，而是会放大推理不同阶段之间的架构错配。预填充阶段的计算量随序列长度二次增长，解码阶段的访存压力随 KV 缓存容量线性上升，两者**对硬件的需求偏差会随上下文变长持续扩大。**

### 1.2 Prefill 与 Decode 的架构错配：统一硬件的效率天花板

> 基于 Transformer 架构的大语言模型采用自回归生成模式：输入提示词首先经过可并行的预填充阶段处理，随后在解码阶段逐 token 生成输出。两个阶段的计算特征存在本质差异：预填充属于计算密集型，能够充分利用 GPU 算力；解码属于内存带宽密集型，受限于 KV 缓存读取与权重加载的速度。

在统一部署的服务系统中，:mdnice-bold-italic[预填充请求与解码迭代会互相抢占硬件资源，导致首 token 延迟与单 token 生成时间同时劣化。随着并发请求规模上升，这种资源冲突会进一步加剧，造成系统利用率与服务质量的双重下降。这也是行业转向预填充-解码拆解架构的根本动因。]

::: block-1
总之，:mdnice-highlight[智能体工作负载的长上下文特征放大了预填充与解码阶段的架构错配]，**单一同构硬件已经无法高效承载端到端推理流程**，这是行业转向异构拆解架构的根本驱动力。
:::

## 二、拆解的演进：从两阶段到四阶段的异构范式

> 推理拆解架构的演进遵循粒度不断细化的规律，:mdnice-bold-italic[从最初的预填充与解码分离，到解码内部的注意力与前馈网络分离，最终形成两个维度正交的四级拆解体系。每一级细化都对应更精准的硬件匹配，也带来更高的系统复杂度。]

理解不同拆解粒度的差异，是判断异构架构收益的基础。每一种拆解模式都有其适用的负载场景，并非粒度越细收益就越高，传输开销与流水线平衡成本会随拆解层级同步上升。下面先提前放出一张图，后面会慢慢讲解：

![文章插图](/articles/2026-08-19-when-does-disaggregation-pay-heteropanacea-8c204134/images/05.jpg)

::: image-caption
图 7 (b)：GPU 平台下的均衡负载场景（I/O=1），此时不同解耦模式的表现分化最为明显：8 款模型中仅有 4 款的 PD 解耦超过 ND 基准，PDAF 则仅有 2 款超过，不同模型的性能差异极大，跨度从 0.01 倍到 2.64 倍。这种剧烈分化源于不同模型的计算内存特征与 GPU 硬件的匹配度差异：对于计算密集型、预填充瓶颈更突出的模型，解耦带来的收益更高；而对于内存带宽敏感、KV 缓存压力大的模型，跨节点通信的开销会大幅抵消解耦收益，甚至出现性能倒退。这一结果说明，在商用 GPU 场景下，均衡负载场景没有普适最优的解耦方案，必须结合具体模型的架构特征、批处理规模进行针对性评估，盲目引入细粒度解耦反而可能导致性能下降。
:::

### 2.1 PD 拆解：Prefill 与 Decode 的池化分离

预填充-解码拆解将两个阶段部署到独立的硬件资源池。:mdnice-bold-italic[预填充池针对首 token 延迟与计算吞吐量优化，解码池针对单 token 生成时间与内存效率优化。两者通过流水线方式衔接，避免了同节点部署的资源抢占问题。]

> DistServe、Splitwise 等代表性系统已经验证，**这种分离能够显著提升服务等级目标达成率与有效吞吐量。但该架构也引入了两类新的系统开销：**

- 一是预填充生成的 KV 缓存需要通过网络传输到解码实例，传输成本由网络拓扑与链路带宽决定；
- 二是两个阶段的处理速度存在差异，需要动态调整资源配比与负载均衡，否则会出现 KV 缓存堆积或解码设备空转的情况。

### 2.2 AF 拆解：Decode 内部的 Attention 与 FFN 分离

> **注意力-前馈网络拆解将粒度进一步细化，把解码阶段本身拆分为两个独立模块**。两者随批处理规模变化的方向完全相反：

- 注意力模块需要为每个请求读取独立的 KV 缓存，批处理增大会直接增加内存流量但不会带来复用收益，始终处于内存带宽绑定状态；
- 前馈网络模块对所有 token 复用同一套权重，批处理增大能够提升权重复用率，算力利用率随之上升。

::: block-1
**这种更细粒度的拆解也带来了更高的开销**：:mdnice-highlight[每一层的隐藏状态都需要在两个硬件池之间传输，产生更频繁的网络通信；两个模块以流水线方式协同工作，单阶段延迟必须高度匹配，任何不平衡都会导致流水线停顿与资源闲置。]
:::

### 2.3 PDAF 四级拆解：两个维度的正交组合

> 四级 PDAF 拆解同时沿预填充-解码、注意力-前馈网络两个维度拆分，将完整推理流程分解为预填充-注意力、预填充-前馈网络、解码-注意力、解码-前馈网络四个独立阶段。每个阶段都可以独立配置硬件架构、并行策略与数值精度。

该架构包含了两种粗粒度拆解作为特例：合并预填充与解码内的注意力、前馈网络，就退化为传统的 PD 拆解；合并预填充与解码阶段的同类模块，就退化为传统的 AF 拆解。

![文章插图](/articles/2026-08-19-when-does-disaggregation-pay-heteropanacea-8c204134/images/06.jpg)

::: image-caption
表 1：代表性LLM推理仿真框架功能对比。HeteroPanacea是唯一同时支持异构硬件建模、PD与AF拆解、分阶段量化、多种并行策略与设计空间搜索的框架。现有框架大多仅覆盖单一维度，无法支撑多维度联合的系统级探索，也无法对四级PDAF架构进行完整评估。

整体看下来，**PDAF 四级拆解是当前粒度最细的异构推理范式**，:mdnice-highlight[其收益的核心来源是每个阶段都能匹配最适配的硬件架构]，但收益能否覆盖系统开销，取决于负载特征、硬件设计空间与模型架构的共同作用。

## 三、HeteroPanacea：跨栈异构推理仿真框架的设计内核

> 要系统**探索异构拆解的设计空间，需要一个能够同时建模硬件架构、并行策略、量化精度与调度策略的跨栈仿真框架**。现有工具大多仅覆盖单一维度，无法支撑多维度联合优化的系统级评估。

![文章插图](/articles/2026-08-19-when-does-disaggregation-pay-heteropanacea-8c204134/images/07.jpg)

::: image-caption

:::

HeteroPanacea 正是针对这一空白提出的事件驱动型仿真器，基于解析化的屋顶线模型与互连模型，能够在功率或成本预算约束下，自动搜索不同拆解模式的最优硬件配置。研究团队基于 8 卡 B200 服务器对模型组件进行了实测验证，确保仿真结果的可靠性。

### 3.1 五维设计空间：全维度覆盖的系统级探索

> HeteroPanacea 支持沿五个维度进行设计空间探索：一是数据并行、张量并行、流水线并行、专家并行等多种并行策略；二是预填充-解码阶段拆解；三是注意力-前馈网络模块拆解；四是细粒度的异构 NPU 参数配置，包括矩阵引擎规模、SRAM 容量等；五是混合精度量化策略。

除吞吐量与延迟之外，**框架还能够建模分阶段量化的精度影响**。预填充与解码阶段的注意力层、线性层可以各自配置独立的 MXINT 量化参数，支持精度与效率的细粒度权衡分析。

### 3.2 设备与互连模型：基于屋顶线的解析化建模

> 框架没有采用周期精确的微架构模型，而是**通过峰值规格参数与屋顶线执行模型刻画加速器性能**，在保证核心规律准确的前提下控制设计空间的探索成本。

每个设备由三类核心参数定义：峰值算力、内存技术类型、配套的内存容量与带宽。内存技术覆盖 SRAM、HBM、DDR、LPDDR、GDDR 等七类，每类选取若干具有代表性的容量-带宽工作点，而非采用连续自由变量。

算子的执行时间遵循标准屋顶线约束：

$$
t=max \left(\frac{\Phi}{F_{eff }}, \frac{\beta}{B_{eff}}\right)
$$

其中 $t$ 为算子执行时间，$\Phi$ 为算子的总浮点运算量，$\beta$ 为算子的总访存字节数，$F_{eff}$ 为经过并行扩展后的有效算力，$B_{eff}$ 为经过并行扩展后的有效带宽。

::: block-1
这个公式描述的是一个算子的实际耗时由计算和访存中更慢的那一端决定。

- 如果算子运算量大、访存量小，耗时由算力决定；
- 如果算子访存量大、运算量小，耗时由内存带宽决定。这就像水管输水，最终流量由水龙头大小和管道粗细中的瓶颈决定。
:::

功耗模型分为计算功耗与内存功耗两部分。计算功耗遵循亚线性幂律，参考 H100 的规格作为锚点拟合得到，反映了工艺进步下单算力功耗的边际递减效应。内存功耗基于物理模型，分为动态读写能耗与静态漏电功耗两部分，按内存技术类型分别计算。

互连模型同样采用屋顶线思路，区分节点内设备间通信与节点间通信两个带宽域。张量并行、专家并行的集合通信使用节点内高带宽，跨拆解阶段的 KV 缓存与激活传输使用节点间网络带宽。

### 3.3 两级搜索策略：效率与精度的平衡

> 完整的端到端仿真成本较高，因此框架采用两级搜索策略平衡效率与精度。

- 第一阶段为解析排序，直接基于屋顶线吞吐量模型计算每个硬件候选的容量得分，过滤掉超出功率预算、无法容纳模型权重的不合格选项。
- 第二阶段为预算分配，将总功率预算分配到拆解模式的各个阶段，优先满足瓶颈阶段的资源需求，再对排名靠前的候选配置执行完整的端到端事件仿真。

量化搜索则采用实证方式，对每一种分阶段精度配置运行完整推理并评估任务精度，仅保留精度无损失的候选方案。框架通过相位自动切换钩子，根据张量序列长度自动切换预填充与解码对应的量化配置，实现分阶段精度的运行时切换。

::: block-1
回顾一下，**HeteroPanacea 的核心优势在于用解析化模型大幅降低了设计空间探索的成本**，:mdnice-highlight[同时保留了端到端仿真的精度，能够同时覆盖硬件、并行、量化三个维度的联合优化]，这是其能够系统回答“拆解何时划算”这一问题的基础。
:::

## 四、定制 NPU 场景：四级拆解的收益边界与临界点

> 在可自由定义硬件参数的定制 NPU 设计空间中，异构拆解的收益能够得到充分释放。这一场景对应未来专用推理芯片的架构探索，也最能体现四级拆解的理论上限。

实验在固定装机功率预算下进行，覆盖八种不同架构与规模的模型，通过调整预填充与输出 token 的比例，模拟从解码主导到预填充主导的不同负载特征。

### 4.1 不同负载比例下的拆解模式对比

> **在低预填充占比与均衡负载场景下，无拆解的同构架构表现最优**。:mdnice-bold-italic[所有拆解模式的相对吞吐量均低于 1.0 倍，拆解带来的通信与调度开销超过了硬件专业化带来的收益。] 其中 PD 拆解最接近同构架构，AF 拆解收益差距最大。

当预填充与输出 token 比例达到 100 时，排名发生反转。包含预填充-解码分离的方案全部超过同构架构：

- PDAF 在全部八个模型上都超过同构架构，收益区间为 1.05 到 1.92 倍，且在六个模型上成为最优方案；
- PD 拆解在七个模型上超过同构架构。AF 拆解始终处于垫底位置，无法突破同构架构的基线。

### 4.2 分阶段硬件配置的差异化特征

> **最优硬件配置的差异直观体现了四个阶段的需求分化**。解码阶段的两个子模块都会选用最高规格的内存容量与带宽，但算力配置处于两个极端：解码-注意力选用最低档位的算力，因为其瓶颈完全在于 KV 缓存访存；解码-前馈网络选用中等档位的算力，匹配其权重流式读取的特征。

**预填充阶段的两个子模块则相反，主要配置最高档位的算力，同时接受较小的内存容量**。因为预填充属于计算密集型，内存只需容纳权重与激活即可，不需要大容量的 KV 缓存。

### 4.3 收益临界点：陡峭跃迁与平台衰减

> 对九个预填充比例的连续扫描显示，:mdnice-bold-italic[拆解收益的临界点非常陡峭。在比例为 1 时，PDAF 的相对吞吐量仅为 0.48 倍；到比例为 10 时，已经跃升至 2.10 倍，跃迁发生在一个数量级的区间内。]

收益并非随预填充占比单调递增。

- 在比例 10 到 500 的区间内，收益维持在 1.5 到 1.8 倍的平台期；
- 当比例达到 1000 时，收益回落至 1.27 倍。

:mdnice-bold-italic[这是因为当预填充占比极高时，解码阶段不再是系统瓶颈，为解码单独配置的专用硬件闲置率上升，专业化收益被稀释。智能体工作负载恰好处于平台期的中间区间，是四级拆解收益最高的场景。]

总之，**定制 NPU 场景下 PDAF 四级拆解的收益显著高于 PD 两阶段拆解**，:mdnice-highlight[但收益存在明确的临界点，仅在预填充占比足够高的负载下才能超过无拆解架构]，且收益随预填充占比的变化并非单调递增。
:::

## 五、商用 GPU 场景：现实约束下的务实选择

> 商用 GPU 的硬件参数是固定绑定的，算力与内存带宽无法独立调整，这极大压缩了异构拆解的设计空间。这一场景更贴近当前工业界的实际部署环境，结论也更具现实参考意义。

实验基于 AWS EC2 的 GPU 实例选型，覆盖从 H100 到 T4 的多代产品，所有配置都采用准确的官方算力、内存与功耗参数。约束条件为固定小时成本预算，互连带宽区分节点内 NVLink/PCIe 与节点间 EFA 两种场景。

### 5.1 GPU 设计空间的固有局限

> 商用 GPU 的核心局限在于**算力与内存带宽是强绑定的固定组合**。一款 GPU 的型号确定后，峰值算力、内存容量、内存带宽就同时确定，:mdnice-bold-italic[无法针对单个阶段做定向优化]。无法给解码-注意力配置低算力高带宽，也无法给预填充模块配置高算力小内存。

这种绑定直接压缩了四级拆解的收益空间。在 PDAF 的 32 个阶段配置中，有 31 个都选择了 H100，仅有一个选用 A100。也就是说，:mdnice-bold-italic[四个阶段本质上使用的是同一种算力-带宽比例的硬件，拆解只能调整设备数量，无法调整硬件特性，专业化的核心优势无法发挥。]

### 5.2 不同负载下的实际收益表现

> **GPU 场景下，拆解收益的临界点出现得更早**。在解码主导的极低预填充占比场景下，PD 拆解就已经在全部八个模型上超过同构架构，收益区间为 1.18 到 2.50 倍。这是因为同节点部署时，预填充对解码的资源干扰在 GPU 上更为显著，分离带来的调度收益更早显现。

**但四级拆解并没有带来额外优势**。在高预填充占比场景下，六个模型的 PD 拆解表现持平或优于 PDAF，与 NPU 场景的结论完全相反。AF 拆解在所有场景下都无法超过同构架构，最优情况也仅达到同构的 0.96 倍。

::: block-1
在均衡负载场景下，不同模型的表现分化最大，PD 与 PDAF 的相对收益跨度极大，:mdnice-highlight[没有统一的最优模式，需要结合具体模型的计算-访存特征单独评估。]
:::

### 5.3 NPU 与 GPU 结果差异的本质

> **两种场景结论反转的核心原因，在于硬件设计空间的自由度差异**。NPU 可以独立调节算力与内存参数，让每个阶段都拿到恰好匹配自身瓶颈的硬件，四级拆解的专业化收益能够充分释放；:mdnice-bold-italic[GPU 的算力-带宽是固定组合，拆解只能调整设备数量，无法实现阶段级的硬件差异化匹配。]

这也给出了一个非常务实的产业结论：**在当前商用 GPU 生态下，PD 两阶段拆解是投入产出比最高的方案；PDAF 四级拆解只有在可定制专用加速器的场景下，才能体现出额外的架构价值。**

![文章插图](/articles/2026-08-19-when-does-disaggregation-pay-heteropanacea-8c204134/images/11.jpg)

## 六、模型架构对拆解收益的影响：消融实验发现

> **不同模型架构下，异构拆解的收益差异巨大**。通过控制变量的消融实验，可以分离出各个架构因子对拆解收益的具体影响，从而找到驱动收益的核心机制。

实验基于三个 MoE 基线模型，固定预填充输出比例为 100，分别对五个架构因子进行单变量扫描，量化每个因子对 PDAF 相对收益的影响程度。

### 6.1 KV 流量：拆解收益的核心正向驱动

**解码注意力的 KV 缓存流量，是影响 PDAF 收益的最核心正向因子**。随着 MLA 的潜在向量宽度从 128 提升到 4096，三个模型的 PDAF 相对收益分别提升了 100%、147%和 67%，呈现严格的单调上升趋势。

::: block-1
背后的机制非常直观：:mdnice-highlight[KV 缓存宽度越大，解码-注意力的访存压力就越高，算术强度就越低，与解码-前馈网络的硬件需求差异就越大，四级拆解的专业化收益也就越明显]。当 KV 宽度很小时，解码-注意力与解码-前馈网络的硬件需求趋同，两者用同一种硬件就足够，拆解反而会带来额外开销。
:::

### 6.2 稀疏性与容量：截然不同的影响逻辑

> 专家总数与激活专家数对拆解收益的影响完全不同。:mdnice-bold-italic[增加总专家数几乎不会改变 PDAF 的收益，三个模型的收益波动都在个位数百分比以内。因为总专家数只增加权重存储容量，不会增加每 token 的计算量与访存量，不会改变两个阶段的瓶颈结构。]

**增加每 token 激活的专家数则会大幅削弱 PDAF 的收益**。激活专家数提升会同时增加解码-前馈网络的计算量与权重访存量，缩小其与解码-注意力的硬件需求差距。在 DeepSeek-V4-Flash 模型上，8 倍基线的激活专家数会让 PDAF 的相对收益从 1.41 倍暴跌至 0.38 倍，完全失去架构优势。

### 6.3 量化精度：并非越窄收益越高

> **降低数值精度并非对所有模型都能提升拆解收益**。将精度从 4 字节压缩到 0.5 字节，GPT-OSS 模型的 PDAF 收益提升了 57%，:mdnice-bold-italic[而 GLM-4.6 与 DeepSeek-V4-Flash 的收益反而分别下降了 41%和 42%，后者甚至跌破同构基线。]

背后的逻辑是：

- 降低精度会同时提升所有阶段的算术强度。如果精度压缩缩小了解码-注意力与解码-前馈网络之间的算术强度差距，就会削弱拆解的专业化收益；
- 如果精度压缩没有改变两者的差距格局，就能够提升整体收益。

**不存在通用最优的量化策略，必须结合具体模型与负载共同判断。**

## 总结与展望

> 这项工作系统回答了:mdnice-bold-italic[“异构拆解何时划算”这一行业核心问题，为智能体时代的推理基础设施设计提供了量化的决策依据。其结论不仅适用于定制 NPU 的架构探索，也对当前商用 GPU 环境下的部署优化具有直接指导意义。]

HeteroPanacea 框架**通过跨栈的系统级仿真，首次实现了量化、并行、硬件架构三个维度的联合设计空间探索，验证了 PDAF 四级拆解范式的收益边界与适用条件**。研究证实，:mdnice-bold-italic[在定制 NPU 场景下，智能体负载可以获得最高 2.06 倍的吞吐量提升；而在现有商用 GPU 场景下，PD 两阶段拆解是更务实的最优选择。]

研究同时存在若干局限。

- 当前验证仅覆盖仿真器的组件模型，尚未对端到端服务的调度与批处理效应做完整的部署验证；
- 量化敏感性研究仅覆盖单模型与两类任务，阶段不对称性的量级仍需更大范围验证；
- GPU 实验基于单一云服务商的定价模型，成本结论会随定价策略变化。

未来的研究方向包括三个方面：在**真实部署** 的拆解服务栈上验证仿真器的端到端精度；构建更轻量的精度智能体指标，扩展分阶段量化搜索的覆盖范围；**基于模型架构参数建立拆解收益的预判模型，无需完整硬件搜索即可快速评估架构适配性。**

::: block-1
随着智能体应用的普及，:mdnice-highlight[推理系统的异构化、专业特化是必然趋势]。这项工作为这一趋势提供了重要的理论工具与量化基准，也为下一代推理加速器的架构设计指明了方向。
:::
