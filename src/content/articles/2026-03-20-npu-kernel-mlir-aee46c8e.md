:mdnice-bold-italic[本文提出了一套基准测试方法，并给出了基于 MLIR 的编译流水线中三种编译器可控优化机制的测试结果]，分别为：向量化（Vec）、跨硬件上下文的多线程（MT）、以及利用**乒乓式暂存缓冲区** （两块独立的高速片上暂存区，交替用于数据接收和计算）实现**DMA 传输** 与计算重叠的双缓冲（DB, double buffer）。

本文基于 Triton/Inductor 框架生成核函数，构建了**消融梯度** 策略——该策略会逐步叠加优化手段以量化单一手段性能贡献的测试方法，以此区分向量化、多线程、双缓冲各自的性能贡献；同时以 GELU 作为代表性激活核函数，量化分析了多线程的加速比随问题规模的缩放规律。

::: block-1
实验结果表明：

1. 向量化为**带宽敏感型核函数** （执行速度主要受内存数据传输带宽限制的计算核）带来核心性能收益；
2. 当**调度开销** （线程创建、分发、同步等带来的性能损耗）被平摊后，多线程能实现显著的性能提升；
3. 而当数据传输与计算操作可实现重叠时（即核函数并非处于纯**内存受限** 或纯**计算受限** 的极端场景），双缓冲能进一步带来性能增益。

注：

- 内存受限：程序性能由内存访问速度/带宽决定，计算单元常因等待数据而空闲
- 计算受限：程序性能由计算单元的运算速度决定，内存传输能及时满足计算需求

## 一、引言

> 核函数优化的自动化实现难度极高：手写核函数的性能至今难以被自动生成的代码超越，但实际生产系统又要求编译器能在快速迭代的硬件架构上，生成可移植且易维护的代码。

在边缘神经网络处理器（NPU）中，程序性能由三大因素决定：分层内存的硬件特性、DMA 管控的显式数据传输、以及让计算单元在数据传输过程中持续工作的任务调度策略。

端到端的模型性能结果虽有实际参考价值，但这类结果往往无法清晰体现出这种**映射机制**，即将算法逻辑映射到硬件执行的具体方式时，各种策略对性能的提升作用及背后原因。因此：

- 本文采用了一套可复现、面向核函数的评估方法，该方法与 Triton/Inductor 风格的代码生成逻辑保持一致；
- 通过在**受控问题规模** （固定且可复现的计算/数据规模）下对典型算子核函数进行基准测试，分别量化向量化（Vec）、多线程（MT）、双缓冲（DB）三种优化机制的性能影响[1]。

为将性能收益精准归因于特定优化机制，本文通过一套简洁的消融梯度呈现测试结果，梯度层级如下：

```
标量执行 → 向量化 → 向量化+多线程 → 向量化+多线程+双缓冲
```

在该消融梯度中：

- 向量化层级单独验证**SIMD 风格 lowering** 的性能收益；
- 向量化+多线程层级量化增量式的线程级加速比；
- 向量化+多线程+双缓冲层级则用于评估：在向量化与多线程优化已生效的基础上，**显式延迟隐藏调度** 是否能带来额外的性能提升。

除呈现测试结果外，本文还详细描述了实现多线程与双缓冲所采用的具体 MLIR**中间表示（IR）模式** 与**编译 Pass 结构**，让本研究的方法易于复现与扩展。

## 二、实现细节：多线程与双缓冲

> 本文的优化机制基于 MLIR 框架[2]实现，并遵循一个核心设计原则：尽可能长时间保留**结构化中间表示** 中表达的计算意图，仅当编译器完成任务调度后，再将其 lowering 为运行时结构（程序执行阶段才生效的代码结构，如线程创建、同步原语）。

该原则能提升代码的可移植性，同时让编译器的转换优化操作更易验证。

### 2.1 多线程（MT）

#### 硬件模型

本文的目标边缘 NPU 支持多线程向量执行，每个硬件线程都对应一个独立的**向量上下文** （如向量寄存器、谓词状态，其中向量寄存器用于存放批量数据，谓词状态用于控制向量指令的条件执行）。

若**分块迭代空间** （将大的计算迭代空间拆分为小的分块）可被无**跨线程数据依赖** （不同线程间的计算需要彼此的结果，导致无法并行）地拆分，该硬件特性可实现同一核函数的多个独立计算分块的并发执行。

#### 两阶段多线程 lowering

本文将多线程的下推实现为两阶段流水线：第一阶段保留结构化并行性，第二阶段引入显式的**分叉-合并** （一种并行执行模型，先将任务拆分到多个线程并行执行，再合并结果完成同步）。

1. **虚拟线程构建阶段**：该阶段将分块后的核函数（如 MLIR 中的`linalg.generic`通用线性代数指令）通过`scf.forall`并行循环指令，重写为显式的并行执行形式。该 pass 会基于**计算分块空间** 的大小，采用**基于规模的收益启发式算法** （根据计算分块的大小判断并行化是否能带来性能收益），并选择合适的**任务分配策略** （块式与块循环式，块式为连续分块分配给线程，块循环式为交错分块分配），在迭代范围非均匀时实现线程间的负载均衡。
2. **异步线程构建阶段**：该阶段利用 MLIR 的**异步方言** （MLIR 中用于描述异步操作的专用语法体系），将`scf.forall`指令下推为分叉-合并的表示形式。每个计算分块会被转换为一个`async.execute`异步执行区域，该区域执行完成后会生成一个**令牌** （异步操作的完成标识，用于实现异步任务间的同步）；所有令牌会被收集到一个**异步任务组** 中，在后续的**依赖计算** （需要并行任务结果的计算步骤）执行前，通过`async.await all`指令实现**屏障同步** （让后续计算等待所有并行任务执行完成的同步点）。

#### 中间表示中的标准分叉-合并框架

编译器生成的分叉-合并代码模式被刻意设计为轻量且规整的形式，使其能被直接下推为**协程/任务运行时** （管理协程和异步任务的底层执行环境）[3]，核心代码结构如下：

```
%group = async.create_group %Nscf.for %tile = ... {  %tok = async.execute { /* 分块计算逻辑 */ async.yield }  async.add_to_group %tok, %group}async.await_all %group
```

#### 选择异步方言的原因（而非直接下推多线程）

将多线程以结构化的分叉-合并形式保留在异步方言中，能在**延迟下推** （将高层抽象保留到编译器优化后期再转换为底层代码）前，以**声明式形式** （只描述做什么，不描述具体怎么做的代码形式）保留并行语义，同时又能让代码被直接转换为运行时的任务调度逻辑[3]。

### 2.2 双缓冲（DB）

> 双缓冲是一种**软件流水线策略** （将循环的取数、计算、写回等步骤重叠执行以提升并行性的策略），通过交替使用两块**暂存缓冲区** （高速小容量的片上存储，比主存访问更快）（乒乓区），实现数据传输与计算操作的重叠执行。

该技术与**模调度** （一种软件流水线调度算法，通过循环展开让不同迭代的操作重叠）和**流水线循环执行** [4,5]密切相关。

本文将双缓冲的实现分为两个阶段，将**流水线调度的构建** 与**面向特定目标硬件的异步传输原语** 的引入解耦。

#### 阶段 1：结构化流水线构建

> 本阶段会匹配由**分块操作** 生成的**单缓冲分块循环标准形式**，该形式的核心指令序列为：

::: block-1
`memref.subview` → `memref.alloc`→`memref.copy`

即：内存子视图切分 → 内存分配 → 内存拷贝
:::

后续紧跟计算操作与数据写回序列。基于该代码结构，该 pass 会构建显式的乒乓式调度：

- 首先生成**序段代码** （程序中主循环前的初始化执行段），将第一个计算分块预取至乒乓缓冲区的“乒”区；
- 随后将主循环重构为两个交替执行的子核函数。

#### 阶段 2：异步 DMA 集成

> 本阶段会将同步的内存拷贝操作替换为显式的异步 DMA 操作：预取路径的代码会被重写为带唯一乒乓缓冲区标记的`memref.dma start`（启动 DMA 传输）指令；并在计算操作执行前插入`memref.dma wait`（等待 DMA 传输完成）指令，确保计算分块的数据驻留在**紧耦合内存（TCM）** （与计算单元紧密连接的高速片上存储，访问延迟固定且无需经过缓存）中。

数据写回的拷贝操作也会采用相同的处理方式，同时该 pass 会生成**均衡的标记释放** 逻辑，避免 DMA 标记的资源泄漏。

通过分阶段的转换优化，编译器会先确立正确的执行调度，再将其映射到目标硬件的传输接口，这与流水线循环优化的经典编译器设计实践保持一致[4,5]。

#### 双缓冲与多线程的组合实现

双缓冲与多线程能实现自然的组合优化：当`memref.dma wait`指令确保计算分块数据驻留在 TCM 后，计算区域可通过`scf.forall`虚拟线程指令和/或 lowering 后分叉-合并表示形式，实现多个子计算分块的并发执行。本文的消融梯度中，**向量化+多线程+双缓冲** 层级正是采用该组合优化方式实现。

## 三、基准测试设置与方法

> 本文选取两个代表性核函数开展基准测试：

- 第一个是**以带宽为核心的二维向量加法微基准测试**，计算规模为 $[64,128\times128]$ 个元素，该核函数适用于分析高内存开销场景下，向量化与延迟隐藏机制的相对性能影响；
- 第二个是 **GELU 激活核函数**，该核函数是 Transformer 推理子图的典型算子，本文采用基于 Triton 框架实现的 GELU 核函数作为具体测试实例。

::: block-1
- 对于二维向量加法微基准测试，本文:mdnice-bold-italic[评估消融梯度中四个层级的性能：标量执行、向量化、向量化+多线程、向量化+多线程+双缓冲。]

**实验结果表明，多线程在所有测试的问题规模下均能提升性能，且加速比随问题规模的增大而提升**：当计算规模为 1048576 个元素时，加速比达到约 3.91 倍（单线程延迟 12947 µs，多线程延迟 3313 µs）。

该趋势表明，随着每个线程的计算量增加，分叉-合并调度带来的固定开销被不断平摊；而大问题规模下加速比趋于饱和的现象，则表明此时出现了**共享性能瓶颈** （多个线程竞争导致的性能瓶颈），如内存带宽受限、屏障同步开销增大等。

### 4.3 讨论

> 在本文测试的两类核函数中，向量化均带来了核心的**一阶性能收益** （最主要、最显著的性能提升），**这一特性在带宽敏感型场景中尤为突出。**

当存在**充足的并行余量** （存在足够多可被拆分并并行执行的计算任务）、且核函数的计算规模足够大以平摊调度开销时，多线程能带来显著的增量性能提升。

而当数据传输与计算操作的耗时均占据显著比例时，双缓冲能带来额外的性能增益；在纯内存受限的极端场景下，双缓冲的性能提升会受传输带宽的限制；在纯计算受限的极端场景下，传输与计算的重叠机会则会大幅减少。

## 五、结论

> 本文提出了一套简洁、可复现的方法，用于分析基于 MLIR 的 AI 核编译器中的向量化、多线程与双缓冲优化机制。

本文设计的消融梯度能让研究者将性能提升精准归因于特定的编译器优化机制，而非仅呈现端到端的加速比结果。实验测量结果表明：

- 向量化是性能提升的基础优化手段；
- 当调度开销被平摊后，多线程能实现大幅的性能提升；
- 而当数据传输与计算操作可实现重叠时，双缓冲能带来增量的性能收益。

::: block-1
未来的研究工作将进一步扩充基准测试的核函数集，如 RMSNorm 均方根归一化、softmax 软最大化函数，并将本文的测量结果与预测模型关联，建立**重叠效率** （传输与计算重叠的时间占比）与 DMA 吞吐率、暂存缓冲区容量之间的量化关系。
:::
