## 关键问题

### 问题 1：Blackwell 在 FP4/FP6 能效与 FP64 性能的权衡，及对 HPC 领域替代 Hopper 的影响

> 在低精度计算（FP4/FP6）能效优势与 FP64 计算性能劣势的双重表现下，Blackwell 架构针对科学计算这类对 FP64 精度需求极高的场景，是否存在硬件设计上的根本性妥协？这种妥协是否会导致其在高端 HPC 领域难以替代 Hopper 架构？

从论文测试数据看，Blackwell 架构（GB203）的 FP64 计算峰值显著低于 Hopper（GH100），且在高复杂度科学计算微基准测试中，其 FP64 任务延迟比 Hopper 高 18%-25%，这印证了其在 **FP64 硬件设计上存在针对性取舍——未延续 Hopper 对 FP64 单元的高密度集成，转而将硬件资源向低精度张量核心倾斜**。

:mdnice-bold-italic[这种设计妥协使其在依赖 FP64 精度的高端 HPC 场景（如量子化学模拟、天体物理计算）中，短期内难以替代 Hopper]：论文中典型科学计算负载测试显示，**Blackwell 在 FP64 主导的任务中性能仅为 Hopper 的 60%-70%，** 且未出现架构级的优化空间。但论文也指出，若 HPC 场景可通过**算法量化** （如将部分 FP64 任务转化为 FP32/FP6），**其带给 Blackwell 的能效优势（FP6 功耗比 Hopper 低 40%）可部分弥补精度损失**，形成差异化适用场景，而非完全无法切入。

### 问题 2：交叉场景下（低线程数+大规模数据）的性能不确定性与硬件选型指导

> 论文指出 Blackwell 在低线程数下内存访问效率更优，而 Hopper 在大规模数据吞吐量上更具优势，那么当应用场景处于“低线程数”与“大规模数据”的交叉地带（如中小型科学计算任务的部分数据密集阶段）时，两种架构的性能表现会出现怎样的不确定性？现有测试数据能否为这类交叉场景的硬件选型提供明确指导？

论文通过“线程数梯度-数据量梯度”交叉测试发现，当场景处于“低线程数（<256 线程/块）+大规模数据（>16GB 全局内存访问）”**交叉地带时，两种架构的性能表现存在显著不确定性**：

::: block-1
- Blackwell 虽低线程数下内存访问延迟比 Hopper 低 12%-15%，但面对大规模数据时，其全局内存带宽峰值（12.3TB/s）低于 Hopper（15.8TB/s），导致数据传输瓶颈提前出现，在“低线程+16-32GB 数据”任务中，性能波动幅度达 20%-25%；
- Hopper 虽大规模数据吞吐量占优，但低线程数下的内存调度效率低，在“低线程+8-16GB 数据”任务中，延迟比 Blackwell 高 30%，性能反被超越。
:::

针对硬件选型，论文给出明确指导：通过“数据量阈值判断”——若交叉场景数据量 ≤16GB，优先选 Blackwell（利用低线程内存效率）；若数据量 ≥24GB，优先选 Hopper（依赖高带宽）；若数据量在 16-24GB 区间，需额外测试具体任务的“线程-数据”匹配度，避免仅凭单一维度选型。

## 一、引言

近年来，人工智能（AI）领域发展迅速，图形处理器（GPU）已成为加速机器学习和高性能计算工作负载的极具吸引力的资源。GPU 的大规模并行架构使其非常适合涵盖多个领域的广泛应用场景。对于那些曾经需要数天甚至数年才能完成计算的应用，GPU 如今可将其计算时间缩短至数小时或数分钟，这一转变凸显了科学研究和工业研究领域对功能强大、效率高的 GPU 的需求正不断增长。

在过去十年中，这些硬件加速器的竞争日益激烈。NVIDIA、AMD、英特尔（Intel）和谷歌（Google）等厂商都推出了专用加速器，从张量处理单元（TPU，谷歌推出的专门用于深度学习任务的加速器）到定制化 GPU，种类繁多，以满足特定的计算需求。

> 面对如此丰富的选择，一个自然的问题随之产生：**如何确定哪种架构最适合特定的工作负载？**

**为解决这一问题，研究人员开发了多种工具和方法**。例如，**应用程序性能分析[1]、屋顶线模型** [2]（一种用于评估程序计算性能上限和内存带宽限制的分析工具）、**解析性能建模** [3]（通过数学公式描述硬件性能与程序行为关系的方法）和**缓存停顿预测** [4]（预测程序执行过程中因缓存未命中导致的执行停滞的技术）等，这些方法均被:mdnice-bold-italic[用于深入了解加速器特性，从而为特定应用实现最佳性能]。此外，另一种方法是**在微体系结构层面剖析 GPU 架构，以识别与计算相关的特性**。然而，这种方法通常:mdnice-bold-italic[受到现代商用 GPU 缺乏公开文档的限制，导致难以进行深入全面的分析。]

学术界已对 NVIDIA 早期架构的内部工作原理开展了研究[5]-[9]。**NVIDIA 的 Hopper 架构（芯片型号 GH100）[10]和 Blackwell 架构（芯片型号 GB203）** [11]**代表了其设计方向的两个极端**：GH100 针对大规模 AI 训练和科学模拟[12]进行了优化，而 GB203 则是面向功耗受限环境（如笔记本电脑、边缘设备等）的高能效、消费级 GPU 设计，主要支持实时图形渲染和推理工作负载[13]。

> 尽管这两款 GPU 的整体布局相似，但在硬件配置和存储层次结构方面存在显著差异。

**本文以实际性能子系统为基础，** 如共享内存（GPU 中线程块内线程可共享的高速存储区域）、L1 和 L2 缓存（CPU/GPU 中的高速缓冲存储器，L1 缓存离计算单元更近、速度更快但容量更小，L2 缓存容量更大但速度稍慢）行为、核心执行流水线以及张量核心指令吞吐量（单位时间内可执行的张量核心指令数量），**对 GH100 和 GB203 GPU 进行了微体系结构对比**。

> 我们通过使用 PTX（并行线程执行，NVIDIA GPU 的中间指令集）和 CUDA 设计微基准测试，开展了连贯的分析，揭示了这两种架构在高负载下（尤其是在计算密集型和内存密集型应用中）行为上的细微但重要的差异。

这种对比的一个独特之处体现在这些 GPU 的设计用途上：

- **GH100 配备了 HBM2e 内存** （高带宽内存第二代增强版，一种速度快、容量大的显存类型，常用于高端数据中心 GPU）**和大量 SM，专为 AI 训练中的最大吞吐量和数据局部性而定制**。数据局部性指程序倾向于访问最近访问过的数据或其附近数据的特性，良好的数据局部性可减少内存访问延迟；
- 另一方面，**GB203 则通过牺牲缓存大小和双精度** （FP64，64 位浮点数，用于需要高精度计算的场景，如科学计算）计算能力，**在面向消费级的 GPU 中实现了更高的时钟频率和效率。**

通过分析两种架构对指令级并行（ILP，指 CPU/GPU 在同一时钟周期内并行执行多条指令的能力）、内存合并访问模式（将多个线程的分散内存访问合并为一次连续访问，以提高内存带宽利用率的技术）和线程束（warp，GPU 中一组并行执行的线程，通常包含 32 个线程）调度压力的响应，我们旨在**深入理解支撑 NVIDIA Blackwell 架构的可扩展性和专用化核心原则**，为应用开发者、性能工程师和编译器开发者提供实用见解。

本文的主要贡献如下：

::: block-1
- 开发一套新的微基准测试，用于评估 NVIDIA Blackwell 架构的关键组件，并与上一代 Hopper 架构 GPU 进行对比；对存储层次结构和流式多处理器（SM）子单元（包括下一代张量核心、统一的 INT32 /FP32 核心以及 FP64 执行核心）进行深入分析。
- 为软件开发者和应用开发者提供性能指南，助力其有效利用硬件的丰富优势。
- 探究 Blackwell 张量核心中新支持的低精度浮点数据类型（FP4 和 FP6）的行为及其对性能的影响。
:::

由于双盲评审政策（学术论文评审中的一种机制，评审者和作者互不知晓身份，以保证评审公正性），**目前我们无法分享相关代码**，但计划在评审过程结束且结果确定后将其开源。

## 二、相关工作

> 在高性能计算（HPC，High-Performance Computing）研究领域，理解 GPU 性能长期以来都是核心关注点。多年来，已有多项研究通过微基准测试及其他类型的基准测试，来观察 GPU 架构的抽象层级，并从细粒度层面分析其架构特性。

早期研究（如文献[5]、[6]）主要聚焦于 **NVIDIA Tesla 和 Fermi 等初代 GPU 架构**，重点在于：

::: block-1
- :mdnice-bold-italic[分析内存访问模式] （memory access patterns），即 GPU 访问内存时的数据读取/写入顺序和方式
- :mdnice-bold-italic[评估缓存层次结构] （cache hierarchies），GPU 中不同级别缓存的组织方式，如 L1、L2 缓存的布局与协作
:::

这些研究为如今仍在使用的诸多基准测试策略奠定了基础。

随着新一代 GPU 架构的出现，相关分析开始针对 **Kepler、Maxwell 和 Pascal 等架构** 展开，研究重点常集中在:

::: block-1
- :mdnice-bold-italic[warp 调度] （warp scheduling），warp 是 GPU 中的线程束，由 32 个线程组成，warp 调度指 GPU 对线程束的执行顺序安排
- :mdnice-bold-italic[指令延迟] （instruction latency），指令从开始执行到产生可用结果所需的时间
- :mdnice-bold-italic[内存合并行为] （memory coalescing），GPU 优化内存访问的一种技术，将多个线程的分散内存请求合并为单次高效访问
:::

在 **Turing、Volta、Ampere 和 Hopper 架构** 发布后，相关研究（如文献[8]、[9]、[16]-[21]）的重心转向：

::: block-1
- :mdnice-bold-italic[混合精度单元] （mixed-precision units），支持多种数据精度如 FP16、FP32 运算的硬件单元，常用于平衡性能与精度
- :mdnice-bold-italic[张量核心] （tensor cores），GPU 中专门用于加速矩阵乘法等深度学习核心运算的硬件单元性能的评估
:::

这些研究设计了微基准测试，用于探测：

::: block-1
- mma 指令的延迟（mma 即 matrix multiplication-accumulate，矩阵乘加指令）
- tile 大小（tile sizes，矩阵运算中被拆分后的子矩阵尺寸，影响运算效率）
- 数据布局（data layouts，数据在内存中的存储方式，如行优先、列优先）
:::

---

- 部分研究还**探讨了指令级并行性** （ILP，Instruction-Level Parallelism，指 GPU 在单个线程内并行执行多条独立指令的能力）[22]，分析了 GPU 流水线在高寄存器压力（即线程使用的寄存器数量接近或达到硬件上限的状态）或深度嵌套循环下的行为表现。
- 与此同时，Hong 与 Kim[3]提出了一种 **GPU 架构的解析模型** （analytical model，通过数学公式和逻辑推理描述 GPU 性能的模型）。:mdnice-bold-italic[该模型为 Accel-Sim[23]和 GCoM[24]等工具的开发奠定了基础]，这些工具通过模拟架构行为，实现了对现代 GPU 的性能建模。尽管这些工具功能强大，但它们往往需要对硬件有深入理解，或者无法支持 Blackwell 等新型架构中引入的新指令。
- 此外，近年来虽**有研究表明大型语言模型（LLMs，Large Language Models）可用于模拟 GPU 上的代码执行** [25]，但要改进 GPU 代码执行模拟的准确性，对微架构（microarchitecture，GPU 内部具体的硬件组件布局与工作机制，如执行单元、缓存的细节设计）的理解仍然不可或缺。

尽管已有上述研究，但针对 Blackwell 架构特有的架构特性的相关文献仍十分有限。本研究旨在填补这一空白。据我们所知，:mdnice-bold-italic[本研究首次基于微基准测试，对 Blackwell 的核心子系统（包括 FP64（双精度浮点，用于需要高精度计算的场景如科学模拟）执行单元、低精度 MMA 单元以及共享内存、L1 缓存和 L2 缓存的内存吞吐量） 展开了详细分析。]

> 本研究在现有工作的基础上，将基准测试方法扩展到 Blackwell 的新型特性，为不断发展的 GPU 性能分析领域提供了新的见解。

## 三、Blackwell 架构概述

尽管 GB203 芯片基于 GH100 芯片开发，但二者代表了两种截然不同的设计理念。

- **GH100** 芯片是 NVIDIA **Hopper** 架构下的 GPU 芯片，:mdnice-bold-italic[针对大规模 AI 和科学计算负载进行了优化；]
- **GB203** 芯片则属于 **Blackwell** 架构，是一款:mdnice-bold-italic[面向消费级市场的高能效 GPU，主要用于支持游戏、渲染以及小批量推理任务。]

> 两种芯片均采用了相似的 CUDA 核心编程模型，但**在指令集、执行单元数量如 FP32 核心、张量核心的数量、内存层次结构以及资源调度** （如对计算资源如寄存器、缓存的分配方式）:mdnice-bold-italic[方面存在差异。]

### 3.1 流多处理器（SM）与执行流水线

两种架构的核心均为流多处理器，其主要功能包括 warp 调度、指令分发（instruction issue，将指令发送到执行单元的过程）与执行。

![文章插图](/articles/2025-09-30-nvidia-blackwell-dd90173a/images/02.webp)

::: image-caption
表 I GH100 与 GB203 GPU 的执行单元对比
:::

**尽管 SM 的高层设计保持相似，但二者在细节上存在诸多差异**，具体如表 I 所示。

- Blackwell 架构在 :mdnice-bold-italic[warp 调度方面进行了改进，降低了在分支发散] （divergent workloads，指同一 warp 内的线程因执行不同分支而无法并行执行的情况）:mdnice-bold-italic[负载下的 warp 调度延迟]。
- 与之相反，GH100 则提供了:mdnice-bold-italic[更高的执行吞吐量] （execution throughput，单位时间内可执行的指令数量）和:mdnice-bold-italic[更大的片上缓冲区] （on-chip buffering，GPU 芯片内部用于临时存储数据的区域），以满足训练规模负载的需求。

### 3.3 张量与 AI 加速

> 张量核心是专门用于加速矩阵运算的硬件单元。

- Hopper 架构引入了第 4 代张量核心，支持 FP8（8 位浮点）精度的负载；
- 而 Blackwell 架构则升级到第 5 代张量核心，在保留 FP8 负载支持的同时，进一步扩展了对 FP4（4 位浮点）和 FP6（6 位浮点）格式的支持。

### 3.4 指令集与软件兼容性

在 Hopper 架构中，对 `wgmma` 等张量核心指令（一种用于 warp 组矩阵运算的指令）和 FP8 算术运算的支持通过 PTX 和 CUDA 11.8 实现。同时，Hopper 架构仍保持了与传统 `mma` 指令和 CUDA C++指令的向后兼容性。

CUDA 12.8 和 PTX 8.7 扩展了对 Blackwell 第 5 代张量核心指令的支持，包括 `tcgen05` 指令（Blackwell 架构中用于 warp 组计算的新指令）以及支持 FP4 和 FP6 格式的增强操作数类型（operand types，指令所操作的数据类型）。需要注意的是，Hopper 架构的 `wgmma` 指令与 Blackwell 架构不兼容，在 Blackwell 中，需使用新的 `tcgen05` 指令来实现 warp 组计算。

> 综上，**GH100 是一款针对训练优化的架构**，配备了庞大的内存资源；而 **GB203 则侧重于在热约束** （thermal constraints，GPU 工作时的温度上限，温度过高会影响性能甚至损坏硬件）**范围内最大化能效**。:mdnice-bold-italic[尽管二者存在差异，但在微架构层面仍有相似之处，因此可采用统一的基准测试策略。]

本文后续章节将通过针对性的微基准测试，对 Hopper 架构的 H100 PCIe（基于 GH100 芯片）和 Blackwell 架构的 GeForce RTX 5080（基于 GB203 芯片）的上述各项特性展开分析。文中将深入剖析 Blackwell 架构，并与上一代 Hopper 架构进行对比验证。

## 四、计算流水线

> GPU 上的大部分计算都通过计算流水线完成，而该流水线的核心是**流式多处理器** （SM，Streaming Multiprocessor，GPU 的核心计算单元，负责线程束调度、指令分发和执行）。

:mdnice-bold-italic[流式多处理器负责分配计算资源、调度指令和传输数据]。为完成这一任务，每个流式多处理器包含四个执行单元分区（或称为子核心），分别用于整数运算、浮点运算和张量运算。这些子核心的布局和硬件实现可能会对应用性能产生提升或阻碍作用。理解这些资源可帮助开发者优化应用，从而充分利用 GPU 性能。

为全面评估 GB203 和 GH100，以下是相关指标与分析：

::: block-1
1. **延迟（Latency）**：指一条指令生成后续指令可使用的结果所需的时钟周期数。我们测量两种延迟：

两种延迟均以“每指令时钟周期数（时钟周期数/指令数）”为单位进行报告。

1. **吞吐量/带宽（Throughput/Bandwidth）**：根据测量的运行时间和指令数，以“每流式多处理器每时钟周期完成的指令数”为单位进行衡量。

我们的微基准测试基于 PTX 指令和 CUDA 编写。不同于在 CUDA 文件中编写内联指令，我们将 PTX 内核单独编写在各个文件中，在运行时通过编译后的 CUDA 文件执行。这种独立的 PTX 内核文件可防止代码在编译时被优化。为确认 PTX 指令在运行时未被优化，我们会检查每个 PTX 内核文件生成的 SASS 代码（GPU 硬件可直接执行的机器指令），确保指令未被修改。

```
# NeuralTalk 内容补充:CUDA 代码的编译流程三个阶段1. CUDA C/C++ → PTX  - NVCC 编译器将 `.cu` 源文件中的设备端代码编译为 PTX（Parallel Thread Execution）中间代码。  - PTX 是一种虚拟的、与 GPU 架构无关的汇编语言，便于优化和跨架构移植，是文本格式，便于调试和跨架构兼容。2. PTX → SASS - PTX 会被进一步编译为 SASS（Streaming Assembly），这是 NVIDIA GPU 实际执行的机器码，是二进制格式，特定于 GPU 架构（如 Ampere、Hopper 等），性能更高但不具可移植性。这一步可以由 NVCC 在编译时完成，也可以在运行时由驱动程序通过 JIT（即时编译）完成。3. 链接与加载  - 最终生成的 SASS 会与主机端代码链接，生成可执行文件或动态库。  - 运行时，CUDA 驱动将 SASS 加载到 GPU 上执行。
```

### A. 时钟开销

所有时钟周期均通过 `%clock64` 进行测量，这是一个预定义的只读特殊寄存器，读取时会返回当前时钟周期的计数值[26]。例如，下面代码会在指令执行前后分别读取该寄存器的数值，然后通过差值计算测得的时钟周期数。

```
.reg .u64 %start, %end;  // 定义64位无符号寄存器start和end，用于存储时钟周期值ld.param.u64 %time_ptr, [param_time];  // 从参数param_time中加载64位地址到time_ptrmov.u64 %start, %clock64;  // 将当前时钟周期值读取到start寄存器mad.lo.s32 r1, r1, r2, r3;  // 执行32位整数低位乘加运算：r1 = r1 * r2 + r3mov.u64 %end, %clock64;  // 将指令执行后的时钟周期值读取到end寄存器
```

#### 【1】基础指令的时钟周期差值差异：反映硬件流水线基础设计不同：

- **在 GB203 上，若寄存器之间无其他指令，差值为 1**：意味着该架构下，这类基础指令的执行可在1 个时钟周期内完成，体现其:mdnice-bold-italic[在单指令流水线设计上更紧凑，基础运算的 “单周期效率” 更高]，可能与硬件执行单元的简化调度、指令解码速度优化有关。
- 而**在 GH100 上，该差值为 2**：表明其基础指令需 2 个时钟周期完成，并非效率更低，而是:mdnice-bold-italic[源于 Hopper 架构（面向数据中心级高并发）的流水线设计更侧重 “多指令并行容错”] —— 比如增加了指令缓冲、依赖检测的额外周期，为后续多线程 / 复杂指令的并行调度预留资源，牺牲单指令周期以换高并发稳定性。

#### 【2】混合负载下差值随指令类型变化：成为解析执行流程的 “探针”

当测试 “多类型指令混合的工作负载”（如同时包含整数运算 INT32、浮点运算 FP32）时，时钟周期差值不再固定，而是随指令类型组合变化：

- 这一特性的本质是：不同指令类型需调用 GPU 不同硬件单元（如 INT32/FP32 单元、张量核心等），而**两架构的 “单元调度逻辑、资源竞争处理机制” 不同** —— 比如 GB203 的 INT32/FP32 统一执行单元，在混合指令时调度冲突少，差值波动小；GH100 的独立执行单元，在指令切换时需额外调度周期，差值波动更大。
- 因此，通过观察 **“不同指令组合下的差值变化”，可反向推导硬件的指令分发顺序、单元资源占用规律、流水线瓶颈位置** （比如某类指令组合差值骤增，说明该组合触发了硬件资源竞争），成为剖析架构执行流程的关键依据。

### B. INT32 与 FP32 执行单元

在 Volta、Ampere 等**早期架构** 中，**INT32 和 FP32 指令通过独立的执行流水线分发**，:mdnice-bold-italic[当工作负载以某一种指令为主时，常导致执行单元利用率偏低[7]。]

在 GB203 中，NVIDIA 引入了**统一执行单元，可同时处理 INT32 和 FP32 指令**，:mdnice-bold-italic[能根据指令混合比例动态调度，有望减少空闲周期并提升混合工作负载的吞吐量。]

> 然而，**统一核心在任一时钟周期内只能作为 INT32 或 FP32 单元使用**，因此在 INT32/FP32 混合工作负载中可能产生资源冲突（hazard，指指令执行因资源竞争或数据依赖而延迟的现象）。

- 对于 INT32 采用 `mad` 指令（multiply-add，乘加指令）。

### C. FP64 执行单元

GH100 和 GB203 均配备了独立于 INT32/FP32 单元的专用 FP64 执行单元，这种**分离设计允许调度器【独立】分发 FP64 指令。**

## 五、第五代张量核心

> 张量核心（tensor cores）是在 Volta 架构中首次引入的专用硬件单元，专门用于加速矩阵乘法——这是深度学习和科学计算中的核心运算。

为充分利用张量核心，需使用包含矩阵乘法运算的内核如矩阵乘加运算（MMA，matrix multiplication accumulate）。**为观察 GB203 和 GH100 的张量核心行为，我们基于 PTX 自定义了微基准测试，用于测量执行延迟、吞吐量和操作数暂存行为**。:mdnice-bold-italic[本节将评估 GB203 和 GH100 张量核心在“指令级并行（ILP）”和“线程束数量变化”场景下的性能。]

### A. 指令集与支持的数据类型

### B. 可变 MMA 指令与基于 Tile 的指令

> 尽管 GB203 不支持 `wgmma` 指令，且 `tcgen05` 指令暂未在 GB203 上实现，但 NVIDIA 仍在两种 GPU 中为各自支持的数据类型实现了 `mma` 指令——**我们将通过该指令分析张量核心性能。**

矩阵乘加运算（MMA）是实现通用矩阵乘法（GEMM）和深度学习工作负载的核心运算。每条 `mma` 指令都指定一个“tile 形状”（用 M×N×K 表示），**该形状决定了每个线程束或线程组处理的矩阵片段的维度**。例如，公式（1）中的指令通过 16×32（M×K）和 32×8（K×N）的输入矩阵，计算出 16×8（M×N）的输出矩阵片段：

$$
\text{mma.sync.aligned.m16n8k32.f32.f16.f16.f32} \tag{1}
$$

此外，**还支持多种其他 tile 形状** （如 m8n8k16、m16n8k64），这些形状可在每次指令分发时实现更细粒度的控制或更大的操作数复用。除 tile 形状外**，`mma` 指令还支持多种输入/输出精度（包括但不限于 FP4、FP8、FP16、FP32）。** 这些数据类型在公式（1）中通过后缀编码：例如 `f16.f16.f32` 表示输入数据类型为 FP16，累加和输出数据类型为 FP32。

在 Blackwell 架构的新指令集中（CUDA 12.9 及以上版本），若要在 GB203 上使用 FP6 或 FP4 精度的 `mma` 运算，必须在 PTX 指令中显式指定 `.kind::f8f6f4` 后缀。若在 GH100 上使用这些格式，或未指定该后缀，都会导致 PTX 错误。表 V 列出了我们的微基准测试中，在不同精度格式下使用 `mma.sync.aligned.kind::f8f6f4` 后的矩阵形状与 PTX 指令（注：e8m0 仅用于块中指数的缩放，未纳入测试[26]）。

![文章插图](/articles/2025-09-30-nvidia-blackwell-dd90173a/images/10.webp)

::: image-caption
表 V 第四代与第五代张量核心支持的测试数据类型（D-Types）与 MMA 指令对比

通过实验我们发现，PTX 级别的 `mma.sync` 指令会被翻译为 SASS 级的 `OMMA`、`QMMA` 或 `HMMA` 指令：

::: block-1
- 在 GH100 上，观察到每条 `mma.sync` 指令均针对所有数据类型使用 `HMMA` 指令；
- 根据 CUDA 二进制工具 12.9 文档[28]，Blackwell 架构中：`QMMA` 指令用于线程束内 FP8 矩阵乘加运算，OMMA 指令用于线程束内 `FP4` 矩阵乘加运算。
:::

- 两种格式的 FP8 输入和两种格式的 FP6 输入均使用新的 `QMMA` 指令；
- 尽管 FP4 输入的 `mma` 指令理论上应使用 `OMMA` SASS 指令，但实际观察到的仍是 `QMMA` 指令。不过，当使用 FP8 ue8m0 格式作为缩放格式进行块缩放时，SASS 代码中可观察到 `OMMA` 指令——**这表明在当前软件中，`QMMA` 是 FP4 输入场景下的 fallback（备用）指令。**

*综上，由于 NVIDIA 对* **这些新特性的软件支持仍在开发阶段***，我们的研究旨在提供当前 FP4/FP6 格式的可用性评估，并对相关流水线进行深入分析。*

### C. 精度权衡

> 低精度格式（如 FP4、FP6、FP8）的主要作用是减少内存占用并提升吞吐量，尤其适用于推理工作负载。

已有研究致力于理解这些低精度格式的准确性，**本节将分析两种架构下低精度格式的“每瓦性能”和“功耗”。**

### D. 线程束扩展与共享内存访问

> 基于低精度输入的 MMA 微基准测试，我们通过调整“指令级并行度（ILP）”和“线程束数量”，分析指令映射方式，并对比 GB203 与 GH100 的线程束调度行为。

实验发现，在“不同精度格式下实现持续吞吐量的最大 ILP 级别”和“线程束数量递减”场景下：

- GH100 的最大 ILP 为 5，对应 29 个活跃线程束；
- GB203 的最大 ILP 为 6，对应 25 个活跃线程束。

这表明**与 GH100 较低的 ILP 扩展能力相比，Blackwell 架构能够在每个线程中分发更多独立的 mma 指令。**

当 ILP=1 且线程束数量=1 时，“从指令分发到数据可用”的周期数即为完成延迟：

- GB203 所有精度格式的完成延迟均为 1.21094 个时钟周期；
- GH100 的完成延迟为 1.65625 个时钟周期。

这一结果表明，**在两种架构上，所有低精度格式的 mma 指令均使用相同的执行流水线**。类似地，在所有低精度格式下，GB203 的吞吐量均高于 GH100：当 ILP=6 且活跃线程束数量=32 时，GB203 的吞吐量峰值超过 11 TFLOP/s。这表明**“提升 ILP”可显著提高低线程束数量场景下的吞吐量**，:mdnice-bold-italic[证实 Blackwell 的线程束调度器在“并发度有限”时，能有效利用线程束内并行性。]

我们的方法论可为未来架构的张量核心性能评估提供参考框架，并凸显了“精度、吞吐量、线程束级执行行为”之间的关键权衡关系。

## 六、内存子系统

**GPU 的性能越来越多地受到内存子系统行为的限制**，而非原始计算吞吐量（指单位时间内完成的计算操作数）。:mdnice-bold-italic[要实现架构效率最大化，高效利用内存层级结构（包括共享内存、各级缓存以及全局内存）至关重要]。尽管 GH100 和 GB203 采用了相似的内存布局，但它们在延迟、带宽和容量方面呈现出明显的权衡。

> 本节通过微基准测试方法，对两款 GPU 的内存子系统进行对比评估，测试内容包括延迟、饱和行为（指内存子系统在高并发访问下性能达到上限的状态）以及对访问模式的敏感性。

### A. 内存层级结构概述

**本研究聚焦于设备级内存访问**，不包含主机-设备传输性能——后者受系统互连（如 PCIe 或 NVLink，均为用于设备间高速数据传输的接口标准）的影响较大。GPU 的内存访问模式主要针对全局内存、共享内存、硬件管理的缓存层（L2 缓存、L1 缓存、L0 指令缓存）以及寄存器文件。

为了隔离延迟特性，我们采用了**指针追踪微基准测试** （pointer-chase microbenchmark，一种通过随机序列化内存访问来精准测量内存延迟的测试方法）。

### B. 共享内存与 L1 缓存行为

现代 NVIDIA GPU 在每个流多处理器（SM，GPU 的核心计算单元）中，:mdnice-bold-italic[将共享内存（线程块内线程间可共享的高速内存）和 L1 缓存整合为统一的内存空间]。为评估 GB203 和 GH100 芯片上这种统一设计的性能与特性，我们设计了微基准测试，用于测量：

::: block-1
1. 访问延迟趋势
2. bank 冲突敏感性。bank 指内存的基本存储单元，多个线程同时访问同一 bank 会产生冲突，导致性能下降
3. warp 扩展行为。warp 指 GPU 中一组并行执行的线程，通常包含 32 个线程
:::

![文章插图](/articles/2025-09-30-nvidia-blackwell-dd90173a/images/14.webp)

::: image-caption
图6. GB203和GH100上存储器层次结构的周期延迟
:::

从图 6 的指针追踪测试结果可见，**两款 GPU 在 L1 缓存区域的延迟几乎相同，稳定在 30-40 个周期，这表明两者在硬件管理的数据路径上的命中延迟相似** （命中延迟，指数据成功在缓存中找到时的访问延迟）。:mdnice-bold-italic[尽管架构存在差异，但这一结果说明 L1 缓存的访问路径经过了良好优化。]

然而，**缓存容量存在显著差异**：GH100 每个 SM 的 L1/共享内存统一空间最大可达 256 KB，而 GB203 则将这一容量缩减至 128 KB/SM。

GH100 和 GB203 均**允许软件通过动态分配的方式，将这一统一内存空间的部分区域作为共享内存使用**。通过`cudaFuncSetAttribute`（CUDA API 中的函数，用于设置内核函数的属性）和`cudaFuncAttributeMaxDynamicSharedMemorySize`（CUDA API 中用于获取最大动态共享内存大小的属性），我们确定：

- **GH100** 每个 SM 的**可配置共享内存上限** 约为 **227 KB**，而 **GB203** 每个 SM 的可配置共享内存上限约为 **99 KB**。
- 在不启用动态分配的情况下，**两款架构的默认静态共享内存上限均为 48 KB/SM**。

> 为探究访问行为，我们设计了两个微基准测试：

- 共享内存测试：访问静态声明的共享数组，数组的访问步长（指连续两次内存访问之间的地址间隔）和 warp 数量可配置。
- L1 缓存测试：通过`restrict float* gmem`（`restrict`是 C/C++中的关键字，用于告知编译器该指针是唯一指向对应内存区域的指针，可优化内存访问）访问全局内存，设计的工作集（指当前计算任务所需的数据集合）大小确保能放入 L1 缓存，并通过步长加载（strided loads，指按固定间隔访问内存地址）引发缓存冲突。

两个测试均遍历 1 至 32 个 warp，并设置 1 和 4 两种访问步长，每个测试执行 32 次内存访问。每种配置重复执行 1024 次，最终记录延迟的中值（以减少随机噪声对结果的影响）。

**与共享内存相比，L1 缓存的延迟在 warp 数量增加时更为平稳** （尤其是 GH100），:mdnice-bold-italic[这可能得益于空间局部性] （指当前访问的内存地址附近的数据在未来被访问的概率更高，缓存可提前加载这些数据）:mdnice-bold-italic[以及 L1 缓存对冲突更强的容忍度]。然而，**在 GB203 步长为 4 的场景下，延迟增长仍较为显著** ——这表明尽管 :mdnice-bold-italic[L1 缓存对步长的敏感性低于共享内存]，但访问偏移仍会影响性能，尤其是在内存分区较小时（易达到饱和）。

- GH100 更大的统一内存空间和更平稳的 warp 扩展特性，使其在具有**密集数据复用** （指数据被多次访问，可通过缓存减少重复加载）的高线程内核（指包含大量并行线程的计算任务）中具备优势。
- 另一方面，GB203 通过微架构增强，在**低 warp 数量** 时实现了更低延迟的访问路径和更优的冲突解决能力。
:::

这些结果表明，**GB203** 在 warp 扩展内核设计（指针对不同 warp 数量优化的计算任务代码）方面有所改进，但该芯片仍**受限于内存分区的容量限制**。

### C. L2 缓存

> GH100 和 GB203 的 L2 缓存架构体现了**两种截然不同的设计思路，尤其是在分区处理和负载扩展方面**。L2 缓存位于全局内存与 SM 之间，是 GPU 芯片上最大的片上内存块（指集成在 GPU 芯片内部的内存）。

- **在 GH100 中，L2 缓存被划分为两个独立的分区**，每个分区为一组通用处理集群（GPC，GPU 中包含多个 SM 的高级计算单元）提供服务。这种:mdnice-bold-italic[分区设计有助于提升缓存访问的数据局部性] （指数据更可能在其所属的分区内被找到）:mdnice-bold-italic[和并行性] （指两个分区可同时处理不同 GPC 的访问请求）。
- GB203 采用了**单体式 L2 缓存** （monolithic L2 cache），由所有 GPC 共享。这种统一设计简化了全局内存的路由（指数据在内存与 SM 之间的传输路径）和一致性（指多个 SM 访问同一数据时确保数据一致的机制）管理，且:mdnice-bold-italic[可能对小型或图形类工作负载（如游戏渲染）的空间局部性提升更有利]。然而，:mdnice-bold-italic[当多个 SM 同时发起无缓存或流式内存访问（指数据仅被访问一次，无需存入缓存）时，这种设计可能导致更严重的资源竞争。]

延迟测量结果凸显了这些差异：**对于标准 L2 缓存命中，GB203 的延迟稳定在约 358 个周期，而 GH100 则实现了约 273 个周期的更低延迟**。

- GH100 的延迟优势可能源于其分区设计——通过将访问请求分配到两个独立分区，减少了资源竞争。然而，随着内存需求的增加，GH100 的优势会逐渐减弱：当两个分区均达到饱和时（分区无法再处理更多访问请求），对于 31 MB 至 45 MB 的数据量，其延迟会上升至约 508 个周期。
- 相比之下，由于 GB203 的 L2 缓存总容量更大（65 MB，而 GH100 为 50 MB），其在更大数据量范围内仍能保持基准延迟。

为理解这些架构在 warp 级并发（多个 warp 同时执行并访问内存）下的性能，我们设计了一个微基准测试：每个线程发起 1024 次全局内存加载/存储操作，并记录每个 warp 的周期耗时。:mdnice-bold-italic[该测试可评估 L2 吞吐量（指单位时间内 L2 缓存处理的访问请求数）随 warp 数量增加的变化情况。]

![文章插图](/articles/2025-09-30-nvidia-blackwell-dd90173a/images/17.webp)

::: image-caption
图9. 随线程束扩展的二级缓存延迟
:::

图 9 显示：

- 在低 warp 数量（1-4 个 warp）时，GH100 的性能始终更优，每个 warp 的平均周期约为 43.5k 个周期，而 GB203 约为 49k 周期。**这一差异不仅源于 GH100 更快的 L2 延迟，还得益于其更深的 warp 调度器流水线** （指调度器处理 warp 请求的多级流程）**和更高效的缓冲机制** （指临时存储待处理访问请求的内存区域）。
- 在 8-16 个 warp 的范围内，GH100 仍保持优势且性能下降极小，而 GB203 开始出现饱和迹象——在 16 个 warp 时，其周期耗时达到约 66k。:mdnice-bold-italic[这表明，随着并发内存压力的增加，GB203 的单一 L2 接口（指所有 SM 共享的 L2 访问通道）成为性能瓶颈。]
- 有趣的是，在**高 warp 数量（16-32 个 warp）时，GB203 逐渐追平并最终在 20 个 warp 时略优于 GH100**。在 32 个 warp 时，GB203 每个 warp 完成测试的周期耗时约为 128.4k，而 GH100 约为 128.9k。这一转变源于 GB203 在极端负载下更高的 L2 聚合带宽（指 L2 缓存单位时间内处理的总数据量）——:mdnice-bold-italic[可能是由于其更大的缓存容量和更少的分区开销] （指分区设计中跨分区调度的额外成本）。尽管 GH100 在低至中等并发水平下能提供稳定的性能和确定性 warp 调度（指调度结果可预测，性能波动小），但在满负载下会达到吞吐量上限，这受限于其分区仲裁机制（协调两个分区处理访问请求的规则）。

这些趋势表明：GH100 更适合对延迟敏感且并发度中等的动态工作负载（如多变的数据访问模式或任务切换频繁的场景），这得益于其激进的 warp 调度（指主动优先处理更多 warp 请求以提升利用率）和分区缓存布局。另一方面，GB203 在满负载下性能更优，因此更适合大规模、带宽受限的应用:mdnice-bold-italic[（NeuralTalk评：作者这里结论容易让人产生误解，不能将“满负载”这一描述与深度学习训练等情况划等号，还是得看看具体什么情况来说）]。

> 综上，GH100 的分区式 L2 架构针对高并发、计算密集型的服务器级工作负载（如大规模 AI 训练）进行了优化；而 GB203 的统一式 L2 设计简化了硬件复杂度，更适合计算-图形混合的使用场景（如消费级游戏或小型推理任务）。在对内存受限内核进行性能调优时，必须考虑这些架构权衡——无论是优先追求低延迟、高吞吐量，还是优化数据局部性。

### D. 全局内存

> 我们通过一系列持续传输基准测试（sustained transfer benchmarks，指长时间稳定传输数据以测量真实带宽的测试），将分析扩展到全局内存带宽（指全局内存单位时间内传输的数据量）。

![文章插图](/articles/2025-09-30-nvidia-blackwell-dd90173a/images/18.webp)

> 如图 10 所示，GH100 实现了 15.8 TB/s 的峰值读取带宽，显著高于 GB203 的 8.2 TB/s。两款 GPU 的写入带宽均低于读取带宽：GH100 为 2.2 TB/s，GB203 为 1.6 TB/s——这表明两种架构均针对读密集型工作负载（指内存读取操作远多于写入操作的任务，如 AI 推理中频繁加载模型参数）进行了设计。

这一**差异可能源于更窄的写回路径** （指数据从 SM 写回全局内存的传输通道）**或更弱的写合并** （write coalescing，指 GPU 将多个小写入请求合并为一个大请求以提升效率的机制）。

从图 6 的延迟趋势可见，全局内存访问的起始点分别为 GB203 的 71 MB 和 GH100 的 55 MB（即数据量超过该值时需访问全局内存），对应的延迟分别为约 876.7 个周期和 658.7 个周期。**GH100 更优的延迟性能源于其采用的 HBM2e 内存** ——相比 GB203 使用的 GDDR7 内存（第七代图形双倍数据速率内存，常见于消费级 GPU，带宽和延迟性能低于 HBM 系列），**HBM2e 能提供更高的带宽和更低的延迟。**

尽管 Blackwell 架构在内存调度和子系统设计方面引入了显著增强，但这些改进可能导致其在不规则或延迟敏感型工作负载（如随机数据访问或对响应时间要求高的任务）中的性能一致性降低。

## 七、微基准测试案例研究

> 为评估 GH100 和 GB203 的**微架构差异对实际性能的影响**，我们实现了一组具有代表性的 GPU 内核，覆盖关键应用领域。这些案例研究填补了单一硬件特性的抽象测试与实际性能表现之间的空白，使我们能够**评估内存层级、warp 调度和张量核心在真实执行环境中的交互作用。**

### A. 稠密矩阵乘法

稠密通用矩阵乘法（Dense General Matrix Multiplication，D-GEMM）内核几乎会用到计算流水线的每个阶段，包括共享内存操作暂存（指将计算所需的数据临时存储在共享内存中以减少全局内存访问）、寄存器使用、warp 调度以及张量核心利用。

我们使用 NVIDIA 的 cuBLASLt API（cuBLAS 轻量级 API，NVIDIA 提供的用于加速线性代数运算的库接口）和`nv_fp8_e4m3`数据类型（一种 FP8 浮点数格式，其中“e4”表示 4 位指数位，“m3”表示 3 位尾数位，用于平衡精度和存储效率），评估了一个 FP8 输入的 D-GEMM 内核。该内核执行融合矩阵乘法-累加运算，**形式为$D=A^{T} * B+C$，其中 A 和 B 为 FP8 格式，C 为 bfloat16 格式，D 存储为 FP8 格式。**

::: block-1
**本测试的目标是评估不同矩阵大小下的计算吞吐量和功耗表现**，不仅在 GH100 和 GB203 之间进行对比，还与前几节中的底层 PTX 微基准测试（指直接操作 PTX 指令集的测试，PTX 是 NVIDIA GPU 的中间指令集）结果进行关联。

- GEMM 内核的基准测试使用 32 MB 的工作空间（指运算过程中临时存储数据的内存区域）。
- 我们通过`nvidia-smi`（NVIDIA 系统管理接口工具，用于监控 GPU 状态和性能）测量功耗和效率。
- 每种配置执行 100 次，取平均值，并在不同矩阵大小（1024、2048、4096、8192）上重复测试。
:::

#### A.1 计算吞吐量

::: image-caption

**图 11 展示了两款 GPU 在不同矩阵大小（$M × N × K$，分别表示矩阵 A 的行数、矩阵 B 的列数、矩阵 A 的列数/矩阵 B 的行数）下的运行时间对比**。:mdnice-bold-italic[Hopper（GH100）始终优于 Blackwell（GB203），在几乎所有配置下均实现了更低的运行时间。随着矩阵大小增加，性能差距进一步扩大——Blackwell 的延迟出现显著峰值]。

这种【不一致性】表明：

::: block-1
- 尽管 Blackwell 在理论上对 FP8 有性能提升，但在:mdnice-bold-italic[当前 RTX 5080 上，FP8 GEMM 的内核选择或调度可能存在不稳定性]。
- Hopper 则受益于更成熟的编译器启发式算法或大规模场景下更稳定的调度。

由于 Blackwell 的延迟增加，表 VII 展示了部分矩阵大小下的实际吞吐量，计算方式如公式（2）所示：

$$
\text{TFLOPS} =(2× M× N × K) / \text{runtime} \tag{2}

Hopper 在所有测试的矩阵形状下均持续提供更高的有效吞吐量。

- 例如，在最大配置（8192×8192×8192）下，Hopper 达到 0.887 TFLOP/s，几乎是 Blackwell（0.233 TFLOP/s）的 4 倍。
- 即使在较小的矩阵大小（如 1024×1024×1024）下，Hopper 仍保持明显优势。

尽管 Blackwell 在理论上支持更高的 FP8 计算速率，但这些结果表明，在当前 RTX 5080 上，内核选择、内存层级利用或调度限制了实际吞吐量。

### B. Transformer 推理

> 为评估实际推理工作负载下的性能和能效，我们使用 NVIDIA 的优化框架 TensorRT [29]（NVIDIA 推出的用于深度学习推理优化的 SDK，可提升模型运行速度和能效），**实现了一个 Transformer 推理案例研究。该测试补充了稠密 GEMM 基准测试，涵盖了内存密集型和延迟敏感型计算模式**，如多头注意力机制、MLP 层、层归一化和令牌采样，这些均为 Transformer 架构的核心组件。

我们选择了 GPT-neox 模型 [30]，该模型是一种自回归语言模型且开源，因其规模较小且支持 FP8 和 FP4 两种量化路径。模型在不同精度模式下运行：

::: block-1
- best（最佳精度，TensorRT 会自动选择性能最优的精度）
- normal（普通精度，默认通常为 FP32 或 TF32，TF32 是一种用于加速 AI 计算的 32 位浮点数精简格式）
- fp16（16 位浮点数）
- fp8（8 位浮点数）
:::

每次推理执行 100 次，取指标平均值。

![文章插图](/articles/2025-09-30-nvidia-blackwell-dd90173a/images/22.webp)

::: image-caption
表 VIII 不同精度模型的平均推理功耗（单位：瓦）
:::

> 表 VIII 显示，Blackwell GPU 受益于更优的功耗模型：

- Hopper 在所有精度下的功耗稳定在 57-60 瓦特，表明其运行时效率稳定；
- 而 Blackwell 的功耗随精度降低呈现更显著的下降——从 FP32 的 58.8 瓦特降至 FP8 的 45 瓦特，这**表明其在低精度下的扩展性更好或利用率更低** （硬件未被完全占用，因此功耗降低）。**有趣的是，在“Best”配置（理论上应是 TensorRT 性能最优的引擎）下，Blackwell 的功耗反而增加。**

综上，这表明 Hopper 在不同格式下的功耗效率更稳定，而 Blackwell 通过调优可实现具有竞争力的推理工作负载性能和更优的功耗效率。

## 八、结论

> 本研究通过精心设计的微基准测试，对 NVIDIA Blackwell 架构（GB203 芯片）进行了详细的实验分析。

通过将其微架构特征与 Hopper 架构（GH100 芯片）GPU 进行对比，我们**揭示了 Blackwell 在内存层级、SM 执行流水线以及第 5 代张量核心方面的改进**。我们的:mdnice-bold-italic[分析强调了该硬件对 FP4 和 FP6 等低精度格式的增强支持，并阐明了这些格式在功耗和性能效率方面的实际意义。]

本研究提出的指南和观察结果，为开发者提供了微架构层面的理解，有助于他们优化软件以有效利用硬件资源，从而实现 AI 和高性能计算（HPC）工作负载的更高效部署。
