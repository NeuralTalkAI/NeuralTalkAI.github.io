## 一、GPU 路径追踪底层矛盾：不规则光路与 SIMT 并行的天生冲突

> 路径追踪依靠蒙特卡洛随机采样模拟光线弹射，每一条像素光路的弹射次数、碰撞材质、终止条件完全随机，这种无规律的执行流，与 GPU 批量并行、同束线程同步执行的底层设计逻辑完全相悖。

近十年 GPU 硬件迭代持续扩充流处理器、RT 光追核心，**但大量实时光追项目落地后，开发者普遍发现硬件算力始终无法完全跑满**，程序长期受内存延迟、缓存失效拖累，算力资源大量闲置。

### 1.1 光传输方程与蒙特卡洛路径追踪基础

> 所有基于物理的渲染底层数学根基为光传输方程，完整描述三维空间中物体表面辐射亮度的生成逻辑：

$$
L(x,\omega _{o})=L_{e}(x,\omega _{o})+\int _{S^{2}}L_{i}(x,\omega _{i})f(x,\omega _{o},\omega _{i})|n\cdot \omega _{i}|d\omega _{i} \tag{1}
$$

式内全部变量释义：

- $L(x,\omega_o)$：空间坐标 $x$ 处，沿出射方向 $\omega_o$ 向外发射的辐射亮度，即像素最终呈现的色彩亮度；
- $L_e(x,\omega_o)$：$x$ 点自身自发光辐射，仅光源物体该数值非零；
- $S^2$：以 $x$ 为球心的完整单位球面，代表所有入射光线方向；
- $L_i(x,\omega_i)$：从入射方向 $\omega_i$ 抵达 $x$ 点的外部辐射亮度；
- $f(x,\omega_o,\omega_i)$：双向散射分布函数 BSDF，定义物体材质对入射光线的反射、折射规则；
- $|n\cdot \omega_i|$：表面法线与入射光线夹角余弦，遵循朗伯光照衰减规则。

该公式为连续积分方程，无法直接数值求解，行业统一采用蒙特卡洛积分近似计算，通用采样公式为：

$$
\hat{I}=\frac{1}{N} \sum_{i=1}^{N} \frac{f\left(X_{i}\right)}{p\left(X_{i}\right)} \approx \int_{\Omega} f(x) d x
$$

变量释义：

- $N$：单像素采样光线数量，采样数越高画面噪点越少；
- $X_i$：第 $i$ 次随机采样的光线样本；
- $p(X_i)$：当前样本的采样概率分布；
- $\Omega$：积分完整定义域。

上面公式可以这么理解：通过随机发射多条光线，取光线采样结果的平均值，近似求解连续光照积分。:mdnice-bold-italic[路径追踪就是以相机为起点，逐像素发射采样光线，光线在场景中反复弹射，累积所有光源贡献的辐射亮度，最终合成像素色彩。单条光路完整执行流程分为 5 步：]

1. 从相机生成初始主光线；
2. 沿光线方向与场景求交，获取碰撞表面坐标；
3. 累加当前光路携带的辐射亮度；
4. 根据材质采样新弹射方向，更新光路透射率；
5. 重复求交、着色、弹射流程，直至达到最大弹射深度或光线飞出场景。

$$
\hat {L}(x_{n})=\frac {L_{0\to 1}T(x_{n})}{p(x_{n})}, T(x_{n})=\prod _{j=1}^{N-1}f(x_{j},\omega _{o,j},\omega _{i,j})|n_{j}\cdot \omega _{i,j}| \tag{3}
$$

公式(3)为路径追踪蒙特卡洛积分简化形式，$x_n$ 代表拥有 $n+1$ 个碰撞顶点的完整光路，$T(x_n)$ 为光路透射率，记录光线每一次弹射后的能量衰减系数。

### 1.2 Megakernel 单内核执行的天然缺陷：分支发散与缓存失效

> Megakernel 是早期 GPU 路径追踪最主流的实现方案，设计逻辑极简：单 GPU 线程对应单个像素，**单个计算内核一次性完成整条光路全部流程**，光线生成、场景求交、材质着色、方向采样、光路循环全部封装在同一个 Shader 内核中，**单次 Dispatch 调度全部像素线程。**

该架构存在两个无法根治的底层硬件缺陷：

1. **SIMT 线程束分支发散**。GPU 每 32 个线程组成一个 warp 线程束同步执行，若束内不同像素光路出现差异化逻辑（部分光线 2 次弹射终止、部分光线 5 次弹射、部分光线折射透明材质），warp 会串行执行所有分支逻辑，空闲线程持续等待，硬件执行效率断崖式下跌；
2. **内存缓存局部性崩塌**。同一 warp 内线程交替执行求交、纹理采样、材质计算、随机数生成，访问的显存资源分散无规律，L2 缓存、SM 共享缓存命中率持续走低，频繁触发高延迟显存访问，内存带宽成为性能锁死瓶颈。

::: block-1
:mdnice-bold-italic[Megakernel 架构的核心短板：单内核封装全光路带来开发便捷性，但光路随机行为破坏 GPU 并行执行的一致性与内存访问局部性，场景材质、弹射深度越复杂，性能损耗越严重。]
:::

## 二、两条技术路线完整拆解：Megakernel 与波前路径追踪实现原理

> **波前路径追踪（WPT）的核心重构思路，是打破“一线程一完整光路”的绑定关系**，将光路拆解为独立流水线阶段，用状态缓冲区存储每一步光线数据，同批次仅执行单一操作，强制收敛线程执行行为，从根源减少分支发散。

两种架构的本质差异在于任务调度粒度：**Megakernel 以像素光路为最小调度单元，波前以光路单阶段操作为最小调度单元，调度粒度的重构直接改变 GPU 缓存访问模式。**

### 2.1 Megakernel 正向路径追踪：单线程全包一条光路

> Megakernel 正向路径追踪执行流程无分段、无中间存储，完整执行链路如下：

1. CPU 发起单次 Compute 内核调度，调度分辨率宽 × 高数量的 GPU 线程，一线程绑定一个像素；
2. 线程内部循环执行光路弹射逻辑，循环内部包含光线求交 RT Core 调用、纹理贴图读取、OpenPBR 材质 BSDF 计算、随机方向采样、俄罗斯轮盘光路终止判断；
3. 光路终止后，直接将累积辐射亮度写入像素累积缓冲区，单次内核执行完成该像素全部采样光线。

**该方案优势**：CPU 调度开销极低，无多阶段屏障同步、无光线状态缓冲区读写，代码实现轻量化，适合低采样、简单场景的低延迟实时渲染。

**该方案短板**：循环内大量条件分支导致 warp 发散，不同阶段混合内存访问打散缓存命中，高弹射深度、复杂材质场景下性能衰减明显。

### 2.2 波前路径追踪：分阶段流水线+状态缓冲区解耦光路

> 波前路径追踪将光路完整流程拆分为 4 个串行独立 GPU 计算阶段，每一次光线弹射都需要 4 轮内核调度，阶段之间通过全局缓冲区存储所有活跃光线的完整状态（光线起点、方向、透射率、像素索引、碰撞信息），四个固定阶段分别为：

1. 光线生成阶段：初始化像素主光线，采用 Halton 低差异序列生成亚像素抖动采样，搭配 Cranley-Patterson 旋转降低帧间噪点；
2. 场景求交阶段：读取缓冲区存储的活跃光线，调用 Vulkan 内联光线查询，通过 TLAS 顶层加速结构完成场景相交，将碰撞几何、材质 ID 写入命中记录缓冲区；
3. 材质着色阶段：读取碰撞记录，插值法线、切线、纹理坐标，执行 OpenPBR 分层 BSDF 材质计算，采样下一次弹射方向，更新光线透射率；
4. 辐射累积阶段：判定光路是否终止，完成的光路将亮度叠加至像素累积缓冲区，未终止的光线更新状态，写入新活跃光线缓冲区供下一轮弹射使用。

阶段之间依靠 Vulkan 管线屏障同步，保证前一阶段缓冲区写入全部完成后，下一阶段内核才开始读取数据，避免内存读写竞争。

::: block-1
波前架构天然实现同批次线程执行完全相同操作：同一轮求交阶段所有线程仅执行光线追踪，同一轮着色阶段所有线程仅读取材质纹理，线程执行行为高度统一，大幅缓解 warp 分支发散，同时同类内存访问集中爆发，显著提升 L2 缓存、显存带宽利用率。
:::

### 2.3 波前架构关键优化：光线压缩与间接调度消除无效线程

> 原生波前架构存在显著资源浪费：每一轮弹射都调度完整分辨率宽 × 高线程，但经过俄罗斯轮盘、场景飞出判定后，大部分光线已经终止，大量线程读取空光线状态，无有效计算任务，浪费 SM 与内存带宽。

论文团队增加两级配套内核优化该缺陷：

1. **压缩内核 Compaction**：遍历当前所有光线缓冲区，筛选仍存活的活跃光线，将有效光线索引紧凑存入新数组，统计本轮活跃光线总数量；采用双计数缓冲区，索引 0 存储当前弹射活跃光线总数，索引 1 累积下一轮有效光线计数，原地复用缓冲区无读写竞争，无需额外同步原子锁；
2. 间**接参数准备内核 PrepareIndirect**：将压缩后的活跃光线总数写入 GPU 间接调度参数缓冲区，下一轮流水线仅调度对应数量线程，不再按全屏像素调度。

该优化带来的收益随最大弹射深度提升而增大，场景中光线经 2–3 次弹射大量终止时，可显著削减无效线程开销，抵消多阶段调度、缓冲区读写带来的额外开销，实现净性能提升。

::: block-1
波前架构核心优化逻辑：分阶段收敛线程执行行为提升缓存命中率，搭配光线压缩间接调度消除闲置线程，以多轮内核调度、中间状态存储的开销，换取硬件并行效率与内存访问效率的大幅提升。
:::

## 三、统一 Vulkan 实验平台：无变量干扰的公平对照实验设计

> 过往两类光追架构对比实验普遍存在变量污染：两套渲染器材质系统、加速结构、随机数生成逻辑不一致，无法判定性能差异来自架构本身还是配套工具链差异，**本文最大创新点是实现完全同源的底层渲染底座。**

整套渲染器基于 Vulkan Compute Shader+硬件 RT 实现，几何、材质、采样、加速结构模块完全复用，**仅替换路径追踪积分器内核，唯一变量仅为 Megakernel 与波前两种执行架构**，保证实验结论严谨可复现。

### 3.1 渲染器底层技术栈与测试环境

硬件测试平台：NVIDIA RTX 3060 Ti 消费级显卡，启用完整硬件 RT Core 光线求交单元； 软件渲染底座技术栈：

1. 图形 API：Vulkan 1.3，使用内联光线查询 Inline Ray Query 硬件光追接口；
2. Shader 编译：Slang 着色器语言，统一实现两套路径追踪材质、光照计算；
3. 材质标准：Adobe OpenPBR 分层物理材质模型，统一金属、玻璃、次表面散射等材质计算逻辑；
4. 场景导入：Assimp 模型导入库，Blender 制作标准测试场景；
5. 加速结构：BLAS 底层几何加速结构+TLAS 顶层实例加速结构，两套架构共享同一套加速结构数据；
6. 调试分析工具：NVIDIA Nsight Graphics 硬件性能探针，采集 SM、RT Core、L2 缓存、显存、PCIe 全链路吞吐量指标；
7. 工程构建：模块化 CMake 编译系统，ImGui 可视化调试界面，支持实时切换两套积分器，同步采集帧耗时数据。

CPU 侧所有场景数据、几何变换、材质参数提前打包为 GPU 友好缓冲区上传显存，两套架构全程复用同一份显存资源，不存在场景数据加载、存储差异。

### 3.2 基准场景与测试约束

测试基准场景选用 Khronos glTF 官方标准资产《A Beautiful Game》，中等几何面数、混合金属/玻璃/漫反射材质，存在多次反射折射光路，具备足够光线发散测试压力。 全局统一测试约束：

1. 固定分辨率、单像素采样数量、最大光线弹射深度；
2. 禁用所有后处理差异化优化，仅对比路径追踪核心积分器性能；
3. 稳定运行后采集多帧数据，取平均帧率、帧耗时作为基准指标；
4. Nsight 采集全硬件单元吞吐量、缓存读写命中、warp 分支发散统计数据。

## 四、硬件剖析实测数据：16%提速的真实成因拆解

> 多数开发者会默认渲染性能提升=计算单元利用率提升，但论文硬件探针数据给出完全相反结论：Megakernel 架构 SM、RT Core 硬件利用率更高，反而帧率更低，**说明现代 GPU 渲染的性能瓶颈不仅来自算力，内存子系统延迟与缓存效率同样是关键制约因素。**

两组量化数据分为宏观帧性能指标、硬件底层吞吐量指标两层，结合 Nsight 时序追踪日志，完整还原 16%性能提升的底层来源。

> 分层解读硬件指标背后的硬件逻辑：

1. **SM、RT Core 利用率 Megakernel 更高**：单内核无分段调度、无缓冲区读写开销，GPU 计算单元持续处于工作状态，不存在多阶段同步带来的计算间隙；但利用率高不代表有效计算多，大量算力消耗在分支发散带来的无效等待、零散显存访问阻塞；
2. **VRAM、L2 缓存吞吐量波前大幅领先**：分阶段流水线让同批次线程执行同类操作，纹理、几何、光线状态内存访问地址高度连续，其中 VRAM 吞吐量提升超一倍，L2 缓存吞吐量提升约四成，缓存命中率改善后有效显存带宽被充分利用，减少了高延迟显存随机读取次数；
3. **PCIe 吞吐量波前略高**：两者 PCIe 利用率均处于较低水平，该差异对整体性能无显著影响。

::: block-1
**核心推论：波前架构 16%的帧率提升，完全来源于内存子系统访问效率优化，而非计算算力利用率提升。** 现代 GPU 光追场景的首要性能瓶颈为缓存局部性缺失、显存访问延迟，而非流处理器、RT 核心算力不足。
:::

:::

## 五、两种架构取舍权衡：实时渲染与离线渲染场景适配逻辑

> **不存在绝对最优的 GPU 路径追踪架构，Megakernel 与波前具备完全差异化的开销与收益模型，适配场景、硬件架构、渲染目标各不相同**，论文完整梳理两类架构的适用边界，覆盖游戏实时交互、数字孪生、影视离线渲染全场景。

同时需要区分 GPU 波前与 CPU 波前实现的底层差异，两类硬件并行模型不同，分阶段流水线带来的性能增益逻辑完全独立，不可直接套用优化思路。

### 5.1 Megakernel 架构优势与适用边界

> Megakernel 架构核心优势：

1. CPU 调度开销最小，单次渲染仅一次内核 Dispatch，无多阶段管线屏障同步，CPU-GPU 交互延迟极低；
2. 无全局光线状态缓冲区，显存占用量更低，对显存容量有限的移动端、入门级 GPU 更友好；
3. Shader 代码结构简洁，迭代调试、功能拓展成本更低，快速原型项目开发效率高。

**适配场景边界**：

1. 低采样数、低最大弹射深度的轻量化实时交互项目，移动端光追、轻量化数字预览；
2. 简单材质、低几何复杂度小型场景，光路分支发散程度低，缓存失效损耗可控；
3. 极致低延迟需求场景，如 AR 实时渲染、VR 头戴设备本地渲染，多阶段调度带来的延迟无法接受。

::: block-1
固有短板上限：场景复杂度提升、光线弹射深度增加后，warp 发散与缓存失效损耗会指数级上涨，帧率衰减速度远高于波前架构。
:::

### 5.2 波前架构优势与适用边界

> 波前架构核心优势：

1. 分阶段收敛线程执行行为，大幅降低 SIMT 分支发散损耗，复杂材质、高弹射深度场景性能优势持续放大；
2. 同类内存访问集中执行，缓存命中率显著提升，充分释放显存带宽，缓解内存延迟瓶颈；
3. 配套光线压缩间接调度后，可过滤大量无效光线线程，场景光路终止比例越高，性能增益越明显；
4. 流水线天然支持多阶段并行优化，可独立对求交、着色阶段做专项硬件适配，模块化迭代优化。

**适配场景边界**：

1. PC 端高画质实时光追游戏、高精度数字孪生场景，材质种类丰富、光线弹射深度高；
2. 离线影视渲染，渲染吞吐量优先，单帧渲染耗时无严格延迟限制，可接受多阶段调度开销；
3. 大几何规模、复杂光照传输场景，光路发散严重，Megakernel 架构性能损耗难以接受。

::: block-1
固有短板上限：多轮内核调度、管线同步屏障带来固定 CPU 调度延迟，光线状态缓冲区占用大量显存，低显存硬件运行压力大，轻量化小场景下多阶段开销会抵消缓存优化收益，甚至性能弱于 Megakernel。
:::

### 5.3 CPU 与 GPU 波前实现的本质差异

> 论文专门区分两类硬件下波前架构的底层逻辑，避免开发人员混淆优化思路：

1. GPU 端波前核心解决 SIMT 线程束分支发散、显存缓存局部性问题，依靠分阶段拆分统一单批次线程操作；
2. CPU 端无 SIMT 束同步约束，分支执行无同步等待损耗，波前思路更多等价于广度优先光线遍历、数据包批量追踪，优化目标为 CPU 多级缓存数据复用、多核负载均衡；
3. 硬件并行模型不同，两类平台波前架构的性能收益来源完全独立，GPU 优化方案无法直接迁移至 CPU 离线渲染器。

::: block-1
架构选型核心判断标准：场景复杂度、光线最大弹射深度、硬件显存容量、渲染延迟约束四大指标，低复杂度低延迟场景优先 Megakernel，高复杂度高吞吐量场景优先波前路径追踪。
:::

## 六、研究结论与下一代光追架构演进方向

> **论文两组架构均未跑满 GPU 任意一类硬件单元，证明当前两套主流路径追踪方案均存在性能天花板**，同步指明:mdnice-bold-italic[三大核心瓶颈：跨阶段数据通信开销、内存访问延迟、多内核同步等待损耗，也是后续架构优化的核心发力点。]

团队提出混合路径追踪架构作为下一代研发方向，融合两套架构优势，规避各自固有短板，平衡调度延迟与缓存执行效率。

### 6.1 核心结论复盘

1. 同源 Vulkan 渲染器对照实验证实，波前路径追踪相对 Megakernel 实现 16%帧率提升，性能增益核心来源是 L2 缓存、显存访问局部性改善，而非计算、RT 核心算力利用率提升；
2. 现代 GPU 实时光追性能同时受计算资源与内存子系统制约，当前实现中内存延迟、缓存行为与同步开销是重要限制因素，单纯提升 RT Core、流处理器数量无法完全解决性能短板；
3. 两类架构存在明确场景取舍：Megakernel 轻量化、低延迟，适配简单实时交互场景；波前缓存效率高、扩展性强，适配复杂高画质、离线渲染场景；
4. 当前两种主流 GPU 路径追踪实现方案均无法充分利用硬件全部资源，同步、缓冲区通信、内存延迟持续限制渲染吞吐量，存在巨大优化空间。

### 6.2 未来混合路径追踪架构研发思路

论文提出三大后续研究方向，也是行业下一代硬件光追渲染器的主流演进路线：

1. 混合架构融合方案：浅层光路采用 Megakernel 低延迟调度，深层光路光线大量分叉后切换波前分阶段流水线，兼顾低弹射深度的调度开销与高弹射深度的缓存效率；
2. 波前架构内存布局重构：优化光线状态缓冲区内存排布，贴合 GPU 缓存行对齐规则，进一步提升 L2 缓存命中率，降低显存随机访问次数；
3. 多类型基准场景拓展测试：当前仅使用单一标准 glTF 场景，后续增加室内、室外、体积光、次表面散射等差异化场景，量化不同光路发散程度下两类架构的性能差距；
4. 硬件调度层优化探索：借助 GPU 硬件间接调度、任务队列硬件单元，削减波前多阶段内核切换、管线屏障带来的同步开销。

## 结语

> 这篇 2026 年犹他大学的对照研究，:mdnice-bold-italic[跳出单纯帧率对比的浅层分析，以硬件探针全链路数据为支撑，验证了缓存局部性、内存访问模式对 GPU 路径追踪性能的显著影响]，补充了行业对光追性能瓶颈的量化认知。

对于实时渲染、图形引擎底层研发从业者而言，该研究提供了一套标准化、可复现的 GPU 光追架构对照实验范式，为自研硬件光追渲染器的架构选型提供量化参考。随着实时全局光照、AI 降噪路径追踪逐步普及，场景材质、光线弹射复杂度持续上涨：

- 波前分阶段流水线架构更适配 PC 端高画质实时光追、离线渲染等高复杂度场景
- 而轻量化 Megakernel 架构在移动端、低延迟轻量化交互场景中仍具备明显优势

> 混合式路径追踪架构有望融合两套方案的优势，平衡调度延迟与硬件并行效率，是值得深入研究的下一代技术方向。
