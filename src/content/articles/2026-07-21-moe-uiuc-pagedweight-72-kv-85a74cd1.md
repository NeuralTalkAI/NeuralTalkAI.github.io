## 一、MoE 推理的显存困局：权重与 KV 缓存的零和博弈

> 混合专家架构通过稀疏激活大幅降低了大模型的推理计算量，成为长上下文、复杂推理任务的主流架构选择，但参数总量的膨胀也让它成为 GPU 显存的消耗大户，与推理必需的 KV 缓存形成了直接的显存竞争关系。

在现代 LLM 推理服务中，GPU 显存需要同时承载两部分核心数据：模型权重与 KV 缓存。其中 KV 缓存用于存储每一步生成的键值向量，避免重复计算，它的大小随上下文长度线性增长，在长文档分析、代码仓库级推理、多轮对话等场景下，KV 缓存的占比会持续攀升，成为显存压力的主要来源。

业界已经针对 KV 缓存推出了大量优化方案，比如 vLLM 的 PagedAttention 通过分页管理减少内存碎片、提升批处理效率，还有各类 KV 缓存量化、压缩方案，在极小精度损失下降低显存占用。**但所有这些方案都绕不开另一个显存大头——模型权重**。论文数据显示，:mdnice-bold-italic[MoE 模型加载后的权重可以占据超过 60%的 GPU 显存，这意味着哪怕 KV 缓存优化到极致，也会被庞大的权重挤占空间]，无法支撑更长的上下文或者更大的批处理规模。

权重量化是降低权重显存占用的主流手段，从 GPTQ、AWQ 到 SmoothQuant，各类训练后量化技术已经能在较低精度下保持不错的模型精度，但绝大多数都是静态量化——量化过程在推理前完成，推理过程中精度固定不变。这种僵化的模式无法适配动态的显存压力：

- 上下文短、KV 缓存占用小时，显存有余量却不能用更高精度提升效果；
- 上下文长、KV 缓存压力大时，固定的量化精度又挤不出更多显存给 KV 缓存，只能整体卸载到 CPU 引发性能暴跌。

![文章插图](/articles/2026-07-21-moe-uiuc-pagedweight-72-kv-85a74cd1/images/03.jpg)

::: image-caption
图 2：Qwen1.5-MoE-A2.7B 的专家激活模式，纵轴为分配给各专家的归一化路由权重。整组图从跨数据集、同数据集内部分块两个维度，全面验证了 MoE 模型的路由不平衡特性。整体来看，专家的路由权重呈现显著的长尾分布，前 20% 的专家承载了绝大多数的计算流量，而后半部分专家的总路由权重占比极低。

MoE 架构还有一个非常特殊的属性：**专家激活存在严重的不均衡性。大部分 token 只会路由到少数几个热门专家，大量冷门专家的调用频率极低，不同专家的权重对模型输出质量的贡献差异极大**。如果一刀切地用同样的量化精度，本质是在浪费显存空间——:mdnice-bold-italic[冷门专家完全可以用更低的精度，甚至暂时卸载出 GPU 显存，几乎不会影响整体输出质量。]

::: block-1
总得来说， MoE 推理的显存矛盾本质是静态固定的权重精度与动态变化的 KV 缓存需求之间的不匹配，而 MoE 自身的路由不均衡特性，为动态差异化权重量化提供了天然的可行性基础。
:::

## 二、PagedWeight 的核心洞察：分页式权重的动态表示

> PagedWeight 的核心设计灵感来自于已经被广泛验证的 PagedAttention 技术：**既然 KV 缓存可以拆分成独立的分页进行动态调度，那么 MoE 的专家权重同样可以拆分为分页**，根据显存压力动态调整驻留 GPU 的精度与数量。

PagedWeight 的底层基于任意精度大模型的位平面表示格式，这种格式可以通过不同的位平面子集组合，实现多种不同的有效位宽。:mdnice-bold-italic[可以把位平面理解成叠加的图层，每个图层存储权重的一位二进制数据，所有图层叠在一起就是完整的高精度权重；需要低精度的时候，只保留高位的几个核心图层就可以]，不需要存储多份不同精度的权重，只调整加载的图层数量就能切换精度。

PagedWeight **将量化粒度设定为每个专家的线性块，也就是每个专家的 gate_up 和 down 两个线性层，每个线性块对应一个权重分页单元**。系统通过一张权重页表统一管理所有线性块的状态，页表中记录了每个线性块支持的位宽集合、当前推理实际使用的提交位宽、规划器选定的目标位宽，以及每个位平面对应的显存状态，包括 GPU 驻留、CPU 驻留、传输中三种状态。

> 对于某个线性块，如果当前位宽是 b，要降到更低的位宽 b'，释放的显存大小就是两个位宽下的显存占用差值，计算公式如下：

$$
\Delta_{i}^{b \to b'} = M_{i}^{b} - M_{i}^{b'} \quad \text{for } b' < b
$$

其中 $i$ 代表线性块的索引，对应层、专家、线性块类型的三元组；$M_{i}^{b}$ 是该线性块 b 位量化下的 GPU 显存占用，包含位平面数据和对应的查找表；$\Delta_{i}^{b \to b'}$ 就是降精度后可以释放的显存空间。

![文章插图](/articles/2026-07-21-moe-uiuc-pagedweight-72-kv-85a74cd1/images/04.jpg)

::: image-caption
图 3：PagedWeight 系统总览。虚线箭头表示控制流，实线箭头表示权重数据移动。该架构图清晰呈现了 PagedWeight 的核心组件与完整运行流程，系统核心由权重页表、运行时规划器、推理引擎三大模块构成，配合 GPU 显存与 CPU 内存的两级存储实现权重的动态调度。
:::

分页调度的逻辑非常清晰：

- 卸载权重时，系统先更新页表中的提交位宽，再把不需要的低位平面从 GPU 显存搬到 CPU 内存；
- 重载权重时，先把需要的位平面从 CPU 搬回 GPU，等全部到位后再提升提交位宽。

这种设计**保证了推理过程中永远只会使用已经完全驻留 GPU 的位宽**，不会出现精度切换导致的推理错误。:mdnice-bold-italic[需要明确的是，PagedWeight 和 PagedAttention 并非替代关系，而是互补关系。]

- PagedAttention 管理的是 KV 缓存的分页，目的是提升 KV 缓存的内存利用率和批处理效率；
- 而 PagedWeight 管理的是量化后的权重分页，目的是动态调整权重的显存占用，为 KV 缓存腾出空间。

两者可以叠加使用，进一步提升长上下文场景的显存利用率。

## 三、质量感知规划器：三层信号实现精准量化决策

> **动态降精度的核心挑战在于，如何在有限的显存释放目标下，选择对模型输出质量影响最小的权重进行降精度**，也就是用最小的质量代价换最大的显存收益。PagedWeight 的质量感知规划器通过三层信号叠加，实现了精准的量化决策。

运行时规划器是 PagedWeight 的控制大脑，它会根据当前的 KV 缓存压力计算出需要释放的显存目标，然后评估所有合法的降精度操作的质量损失，贪心选择单位释放显存质量损失最低的操作，直到满足显存目标。整个决策过程结合了离线全局敏感度、在线路由统计和运行时提示残差三个维度的信息，兼顾了通用性与场景适配性。

### 3.1 离线全局敏感度

离线全局敏感度是规划器的基础，基于 Hessian 加权的质量损失分数，在服务开始前就完成校准。Hessian 矩阵可以衡量每个权重参数对最终输出的影响程度，权重越重要，量化带来的误差对结果的影响就越大。对于每个线性块的每个位宽，都计算对应的敏感度分数，公式如下：

$$
s_{i}^{b}=\sum _{j}h_{i,j}\left( W_{i,j}-W_{i,j}^{b}\right) ^{2}
$$

其中 $i$ 是量化单元也就是线性块的索引，$j$ 是权重矩阵中的元素索引；$h_{i,j}$ 是由 Hessian 矩阵推导的权重元素重要性分数，权重越重要，这个值越高；$W_{i,j}$ 是原始的高精度权重，$W_{i,j}^{b}$ 是 b 位量化后的权重。$s_{i}^{b}$ 的值越低，说明这个线性块越能承受更低的量化精度，质量损失越小。

基于敏感度分数，可以定义从 b 位降到 b'位的全局损伤为两个位宽敏感度的差值，也就是降精度带来的质量损失增量：

$$
g_{i}^{b \to b'}=max \left\{s_{i}^{b'}-s_{i}^{b}, 0\right\}
$$

这个值是不依赖具体输入的全局先验，代表平均情况下这个降精度操作的质量影响。

### 3.2 在线路由统计

> MoE 的专家调用频率极不均衡，热门专家被大量 token 使用，降精度的影响更大；冷门专家很少被调用，降精度几乎不会影响整体效果。就像公司里的骨干专家和冷门专家，给骨干专家降级设备对整体效率影响很大，给冷门专家降级几乎没感觉。

PagedWeight 在服务运行过程中实时收集每个专家的路由权重，计算路由质量，也就是专家在一层中的流量占比：

$$
m_{\ell, e}=\frac{\sum_{t} \sum_{k} r_{\ell, t, k} 1\left\{z_{\ell, t, k}=e\right\}}{\sum_{t} \sum_{k} r_{\ell, t, k}}
$$

其中 $\ell$ 是层索引，$e$ 是专家索引；$t$ 是观测到的 token，$k$ 是路由选择的 top-k 序号；$z_{\ell, t, k}$ 是选中的专家，$r_{\ell, t, k}$ 是对应的路由权重。路由质量越高，专家的实际作用越大。

系统会把每一层的专家按路由质量排序，分到不同的桶里，热门专家的桶对应更高的损伤乘数和位宽下限，也就是更不容易被降精度，从机制上保护核心专家的精度。同一个专家的两个线性块共享同一个路由桶的参数。

### 3.3 运行时提示残差

> 全局敏感度是平均情况的估计，但不同的输入提示下，同一个量化操作的质量影响是不一样的。比如处理数学题和处理日常对话，同一个专家的重要程度会有差异。**PagedWeight 用提示残差对全局损伤进行输入相关的修正，通过线性回归头预测当前输入下的损伤偏差。**

离线校准阶段会测量每个降精度操作在不同序列下的实际损伤，和全局估计的差值作为残差，训练对应的线性回归头。运行时提取当前输入的三个特征：路由加权的输入范数均值、路由加权的输入范数均方根、最大输入范数，通过线性头预测残差，再调整全局损伤值。

### 3.4 贪心规划决策

最终每个降精度操作的预测损伤是全局损伤乘以路由桶的损伤乘数，再乘以提示残差的调整系数，同时设置一个最小损伤下限，避免出现 0 损伤的极端情况：

$$
\hat{d}_{i}^{b \to b'}=max \left\{\epsilon, \mu_{\beta_{i}} g_{i}^{b \to b'} \eta_{i}^{b \to b'}\right\}
$$

其中 $\epsilon$ 是最小损伤下限；$\mu_{\beta_{i}}$ 是专家对应路由桶的损伤乘数；$\eta_{i}^{b \to b'}$ 是提示残差计算出的调整系数，大于 1 说明当前输入下这个操作的损伤比平均情况大，小于 1 则更小。

规划器把所有合法的降精度操作按损伤与释放显存的比值从小到大排序，也就是**单位显存释放的质量代价从低到高，依次选择操作，直到释放的总显存达到 KV 缓存压力要求的目标**。如果当前位宽下限下释放的显存不够，再逐步放宽位宽下限，直到满足目标或者达到最低位宽限制。

::: image-caption
算法 1：PagedWeight 运行时规划器。该算法是 PagedWeight 运行时动态量化的核心决策逻辑，负责根据实时 KV 缓存压力生成最优的权重位宽调整计划。算法输入包括当前权重页表状态、运行时观测数据、离线校准结果与当前计划队列，输出更新后的计划队列与待执行的页移动方案。执行流程中，首先将 KV 缓存压力转换为需要释放的目标字节数，随后按位宽下限阶段逐次对所有合法的位宽降低动作进行精度损失评分，通过贪心策略选择单位释放字节带来的精度损失最小的动作，生成候选计划并更新队列。仅当内存压力触发阈值时，才从队列中选择最优计划执行。这套设计兼顾了决策的质量与效率，贪心策略保证了有限内存预算下的精度最优，而计划队列的持续刷新机制则让决策能够适配不断变化的运行时状态，实现动态的内存 - 质量权衡。

在批量推理场景下，规划器会把所有请求的信号按 KV 块使用权重做平均，合并为批次级的决策表，保证整个批次的整体质量损失最小。

::: block-1
三层信号叠加的质量感知规划，让 PagedWeight 的动态量化不是盲目降精度，而是精准选择性价比最高的权重进行压缩，在有限的显存预算下最大化保留模型质量。
:::

## 四、异步调度与内核优化：隐藏动态调整的性能开销

> 动态调整权重精度必然涉及 GPU 与 CPU 之间的数据传输，如果处理不当，传输延迟会直接抵消显存优化带来的收益，甚至拖垮推理吞吐量。**PagedWeight 通过异步分页移动和融合内核设计，将数据传输的延迟完全隐藏在推理流程中。**

传统的权重卸载方案通常是显存不够了才开始搬，属于被动的同步操作，会直接中断推理流程，等待数据传输完成才能继续。**PagedWeight 采用的是前瞻式的异步调度，规划器持续监控显存状态，提前生成精度调整计划，在合适的时间点触发传输，让数据移动和推理计算并行执行。**

规划器会持续监测空闲 KV 块数量、分配器余量和预期的 KV 缓存增长，不断更新最新的精度调整计划。当显存占用达到卸载阈值时，系统直接采用最新的计划，启动权重页从 GPU 到 CPU 的传输，同时更新提交位宽，推理可以继续使用当前驻留的高位宽进行，等传输完成后再释放对应的 GPU 显存。当显存压力下降、达到重载阈值时，系统先把权重页从 CPU 搬回 GPU，等全部传输完成后再提升提交位宽，整个过程不会中断推理。

![文章插图](/articles/2026-07-21-moe-uiuc-pagedweight-72-kv-85a74cd1/images/06.jpg)

::: image-caption
图 4：异步页移动流水线。PagedWeight 规划器在运行时持续生成精度转换计划；触发卸载阈值时，最新计划降低提交位宽并从 GPU 显存中释放权重页；触发重载阈值时，先恢复权重页，再提交更高的位宽。
:::

除了传输延迟，另一个潜在开销是混合精度的推理计算开销。PagedWeight 实现了一个融合的 CUDA 内核，把路由、专家激活、向下投影、输出累加整个流程都融合在一个内核里完成，直接读取权重的位平面和查找表进行计算，不需要分开执行每个专家的计算，大幅降低了多专家、多精度调度的内核启动开销和中间数据读写开销。

同时，因为精度是按线性块粒度管理的，内核可以直接读取规划器设定的每个 gate_up 和 down 模块的位宽，实现专家级甚至线性块级的差异化精度，不需要全局统一精度，完美适配规划器的决策结果。

::: block-1
异步传输隐藏延迟、融合内核降低计算开销，两项设计共同保证了 PagedWeight 的动态精度调整几乎不会牺牲推理吞吐量，让显存优化真正能转化为实际的服务效率提升。
:::

## 五、多维度实验验证：全面领先的质量-显存-吞吐平衡

> 研究团队在三款主流开源 MoE 模型上完成了全面的实验验证，覆盖语言建模、推理任务、长上下文场景，从质量-显存权衡、长上下文保持、吞吐量三个维度验证了 PagedWeight 的优势。

实验选用的三款模型覆盖了不同的专家规模和路由模式，分别是 143 亿参数的 Qwen1.5-MoE-A2.7B、467 亿参数的 Mixtral-8x7B-v0.1、252 亿参数的 Gemma-4-26B-A4B，对应中小规模多专家、少专家大参数、超大规模专家三种典型 MoE 设计，保证了实验结果的普适性。实验硬件分别为 RTX 6000 Ada 工作站和 GH200 Grace Hopper 系统，服务后端基于 vLLM v0.20.1 实现。

![文章插图](/articles/2026-07-21-moe-uiuc-pagedweight-72-kv-85a74cd1/images/07.jpg)

::: image-caption
表 1：被评估 MoE 模型的架构规格：该表汇总了实验选用的三款主流开源 MoE 大模型的核心架构参数，覆盖了不同专家规模、参数量与路由模式的典型设计。
:::

实验对比了 FP16 原生精度、APL 统一量化、MxMoE 静态混合精度量化、DP-LLM 动态混合精度量化四个基线。需要注意的是，DP-LLM 和 MxMoE 的实际显存占用远高于理论值：DP-LLM 需要同时保留高位张量，推理时还要反量化两条精度路径；MxMoE 用的是伪量化实现，权重实际还是高精度存储，还要加载多组权重，所以理论显存优势在实际部署中无法完全体现。

### 5.1 质量-显存权衡

> 实验在 Wikitext2、C4 语言建模任务，以及 GSM8K、MATH-500 推理任务上测试不同显存占用下的模型质量。**结果显示，在所有模型和任务上，PagedWeight 都能以最低的显存占用达到最高的模型质量。**

![文章插图](/articles/2026-07-21-moe-uiuc-pagedweight-72-kv-85a74cd1/images/08.jpg)

::: image-caption
图 5：三款 MoE 模型、四项评估任务下的质量 - 内存权衡。 该组图全面展示了不同方案在语言建模、推理任务上的质量与内存的权衡关系，横轴为 GPU 内存消耗，纵轴为任务质量，其中困惑度指标越低越好，准确率指标越高越好。实验覆盖三款不同架构的 MoE 模型，对比了 PagedWeight 与 FP16、均匀量化 APL、DP-LLM、MxMoE 等基线方案的表现。
:::

在语言建模任务上，PagedWeight 在 Qwen1.5-MoE-A2.7B 上 16GB 显存、Mixtral-8x7B 上 35GB 显存、Gemma-4-26B-A4B 上 22GB 显存就达到了接近 FP16 的效果。统一量化的 APL 在低显存下质量损失更大，DP-LLM 需要更高的显存才能达到类似质量，静态混合精度的 MxMoE 虽然理论表现不错，但实际显存占用远高于 PagedWeight。

推理任务上的趋势和语言建模一致，**相同显存预算下 PagedWeight 的准确率始终高于所有基线，显存越紧张，优势越明显**。整体来看，PagedWeight 可以在保持 FP16 等效精度的前提下，最高节省 72.0%的 GPU 显存，吞吐量提升 1.94 倍；在相同显存预算下，模型质量比现有量化方法最高提升 39.3%，吞吐量损失最多仅 4.1%。

### 5.2 长上下文质量保持

> 长上下文场景是 KV 缓存压力最大的场景，也是 PagedWeight 最核心的适用场景。实验基于 Qwen1.5-MoE-A2.7B，在 LongBench 的段落检索、叙事问答、会议摘要三个长上下文任务上测试。

## 总结与未来展望

> PagedWeight 为 MoE 大模型的长上下文推理服务提供了一套全新的显存管理思路，它用分页式权重表示、质量感知动态规划、异步调度三大核心设计，破解了权重与 KV 缓存的显存矛盾。

这项工作的核心贡献可以归纳为四点：

- 一是提出了分页式的 MoE 权重管理机制，实现了运行时的精度动态调整；
- 二是设计了结合离线敏感度、在线路由统计、提示残差的质量感知规划器，精准控制量化的质量损失；
- 三是通过异步分页移动和融合内核，将动态调整的性能开销降到最低；
- 四是在三款主流 MoE 模型上全面验证了方案的效果，证明了其在质量、显存、吞吐量三个维度的综合优势。

论文也提到了后续的拓展方向，一是**将 PagedWeight 适配更多的量化权重格式，不局限于 APL 的位平面表示，让更多量化方案都能享受到动态分页调度的优势**；二是探索更精准的提示级专家敏感度估计方法，进一步优化质量-显存权衡；三是和 KV 缓存的动态压缩、卸载方案做联合调度，实现全局最优的显存分配。

::: block-1
:mdnice-highlight[整体来看，PagedWeight 代表了大模型推理优化的一个重要方向：从单点的算子优化、模型压缩，走向系统级的全局资源动态调度]。随着大模型架构越来越复杂、部署场景越来越多样化，**这种弹性的、自适应的系统优化方案，会成为推理服务效率提升的核心驱动力**。未来随着长上下文、大批次 MoE 服务的需求持续增长，这类动态显存调度技术会成为推理框架的标配能力。
:::
