## 关键问题

### 问题1：跨厂商NPU适配的可行性与通用化潜力

> 论文核心方案（硬件感知瓦片量化、基于LUT的计算）仅在高通Hexagon NPU（骁龙平台）上验证，而不同厂商移动NPU（如华为Ascend、联发科NeuroPilot）的矩阵单元布局、指令集（如矩阵操作指令是否公开）、内存子系统存在显著差异，且部分厂商SDK（如联发科NeuroPilot）非公开，该方案如何突破硬件架构与生态壁垒实现跨厂商NPU适配？其核心设计（如瓦片量化的布局规则、LUT与特定NPU指令的绑定）是否具备可迁移的通用适配框架？

论文指出，**NPU的“向量+矩阵”混合架构具备一定普遍性** ——不仅移动NPU（如高通Hexagon、华为Ascend、AMD XDNA）采用该架构，现代CPU（如Intel AMX、ARM SME）也开始集成专用矩阵单元，形成类似硬件结构，且AI加速器普遍存在“通用计算性能弱、低精度矩阵计算能力强”的共性特征，因此**本文方案的核心思路（利用矩阵单元空闲算力、硬件感知量化、LUT替代复杂操作）具备广泛适用性。**

但当前方案存在明确的硬件依赖局限：

1. 验证仅基于高通Hexagon NPU（因其SDK相对可访问，且支持反向工程获取矩阵单元指令），而联发科NeuroPilot等其他厂商SDK非公开，导致无法基于现有工具链实现适配；
2. 关键技术深度绑定Hexagon的硬件特性，例如瓦片量化依赖HMX的2级内存布局（外层瓦片列优先+内层2行洗牌）、LUT计算依赖Hexagon的vgather/vlut16指令，论文未提出针对不同架构的“通用适配框架”，仅强调核心思路的迁移性，未解决具体硬件差异（如不同NPU的瓦片尺寸、指令集）的适配问题。

### 问题2：老NPU地址空间限制的软件优化路径与中大型LLM部署价值

> 论文指出，老一代NPU（如骁龙8 Gen 2的V73架构）存在32位虚拟地址空间限制，导致3B以上模型无法运行，且当前实现中lm_head的logits计算因NPU地址限制只能放在CPU，批量为16时CPU端计算占比已接近或超过50%，严重制约吞吐量 scaling。在不依赖厂商硬件迭代（如提供64位NPU地址空间）的前提下，该方案能否通过软件层面优化（如算子拆分、内存动态复用、部分计算卸载策略调整）突破这一硬限制？若无法突破，其面向中大型LLM（如7B及以上）的移动部署价值是否会大幅受限？

针对老一代NPU（如骁龙8 Gen 2的V73架构）的32位虚拟地址空间限制，**论文提出了明确的软件优化方向，但未实现完整解决方案**：

1. **多NPU会话**：论文指出“采用多个NPU会话可缓解单会话地址空间限制”，这是当前软件层面的核心应对思路，但未展开具体实现细节；
2. **算子与内存优化**：论文提到，可借鉴T-MAC的方法实现细粒度分组量化下的高效GEMV（缓解解码瓶颈），同时通过“算子融合减少内存访问”“更多算子卸载到NPU”优化性能，这些方向可间接降低对单一地址空间的依赖，但当前方案尚未落地这些优化；
3. **lm_head计算问题**：论文明确，当前lm_head因地址限制只能在CPU运行，批量16时CPU计算占比超50%，但未提出临时软件解决方案（如动态内存复用、计算拆分），仅指出“解决地址空间后可迁移至NPU”。

对于中大型LLM（7B及以上）的部署价值，论文认为当前方案存在局限——7B模型仅用于性能-cost对比，未在移动设备上实际运行，且老NPU的地址限制直接导致3B以上模型无法部署。若无法突破这一限制，方案对中大型LLM的移动部署价值会大幅受限，但**论文强调“硬件迭代（如64位地址空间）+软件优化（多会话）”可逐步解决该问题，长期仍有适配潜力。**

## 一、引言

随着商用硬件和算法的发展，在移动设备上部署大型语言模型（LLM）变得越来越可行。许多专为移动设备定制的语言模型应运而生，包括 Llama 3.2 [42]、MiniCPM [23, 72]、Gemma [56, 57]等。然而，这些模型的性能通常低于其更大规模的同类模型。提升模型性能的直接方法是扩大模型规模，但这会显著增加内存消耗和带宽需求，给资源受限的移动平台带来严峻挑战。

> 近年来，一种名为“测试时计算扩展”的新范式为通过增加推理时计算量来提升 LLM 能力带来了新机遇。并行测试时计算扩展方法包括生成多个路径，并从多个生成候选中选择最优样本[3, 5, 24, 37, 54, 61, 63]。迄今为止，这些方法仅限于计算资源丰富的云端或离线场景。

直觉上，在移动设备上采用测试时计算扩展技术来提升 LLM 的生成质量似乎不切实际。智能手机等移动设备通常被认为是资源受限的，而 LLM 推理本身就以高资源消耗著称。此外，在运行时扩展计算资源还需要更多的计算量。

然而，近年来**移动系统级芯片中集成神经网络处理器（NPU）的趋势正逐渐改变这一局面**。高通（Qualcomm）、英特尔（Intel）、AMD 等厂商已设计并集成了 NPU 以加速 AI 负载[10, 41, 52]。这些 NPU 不仅能实现高峰值计算能力（指硬件理论上能达到的最高计算速度，通常以 TOPS 为单位，1 TOPS 表示每秒执行 1 万亿次操作），而且还在快速演进：高通声称其骁龙 X Elite（Snapdragon X Elite）芯片中的 Hexagon NPU（高通公司为其骁龙系列芯片开发的专用神经网络处理器）可实现 45 TOPS 的 INT8 精度性能[26]，而 AMD 最新一代 NPU 的性能已实现 3.1 倍的提升[25]。这些发展正改变着移动设备的计算能力格局。

我们发现，**移动 NPU 通过专门的矩阵乘法单元实现高峰值性能，这些单元针对大型矩阵分块** （tile，将大矩阵分割成小块进行计算以提升硬件利用率的技术）进行操作。然而，在典型的 LLM 推理中，解码阶段的矩阵乘法操作通常会退化为矩阵向量乘法，导致硬件利用率低下，且针对大分块优化的矩阵单元计算能力被浪费。

### 测试时扩展的端上挑战

> 这种未充分利用的情况为我们提供了机遇：通过增加采样并行性（指同时生成多个候选结果的并行计算方式）的测试时计算扩展方法，能够利用这些闲置的计算能力，而不会显著增加推理开销。

尽管存在这种潜力，但在**移动 NPU 上实现高效的测试时计算扩展仍面临重大的硬件挑战**，我们将其归纳为以下两个方面：

#### 挑战1：精度

移动 NPU 最初是为粗粒度量化模型设计的，**缺乏对细粒度分组量化的原生支持**，而细粒度分组量化对于以低精度部署的现代 LLM 至关重要。我们观察到，采用**传统逐通道量化** （per-channel quantization）方法的模型在测试时计算扩展所依赖的推理任务中，**性能会严重下降**。

#### 挑战2：效率

虽然 NPU 在矩阵乘法方面表现出色，但其通用向量单元的计算吞吐量和内存带宽却十分有限。LLM 推理中测试时计算扩展所需的许多关键**非矩阵计算必须在向量单元上运行，这成为了显著的瓶颈**。此外，宽 SIMD（单指令多数据，一种并行计算技术，一条指令可同时处理多个数据）向量组件与数据粒度之间的不匹配，再加上硬件的内存访问限制，使得软件难以充分利用向量单元的计算能力，进一步加剧了这一问题。

> 为解决这些挑战，我们提出了一个端到端的 LLM 推理系统，该系统利用移动 NPU 丰富的计算能力来支持测试时计算扩展负载。为满足设备端资源限制和精度要求，我们主要**采用仅权重（weight-only）的 4 位细粒度分组量化**。

针对由此产生的效率挑战，我们的解决方案包含以下关键技术：

### 关键技术1：硬件感知的分块量化

我们提出了一种新颖的矩阵与向量单元感知量化布局。通过在**量化前后进行权重布局转换**，我们在**硬件友好的分块上应用细粒度分组量化**，并与 NPU 的内存访问模式对齐，从而最小化运行时内存访问开销，最大化向量计算利用率。

### 关键技术2：基于查找表（LUT）的高效计算

我们使**用向量单元的查找表（LUT）指令和广义查找表机制，替换 Softmax 中的指数计算和混合精度矩阵乘法中的反量化等复杂关键操作**，从而缓解向量单元上的计算瓶颈。

我们在三代高通骁龙平台上对系统进行了评估。实验表明，我们提出的技术可为混合精度矩阵乘法带来高达 19.0 倍的加速，为 Softmax 带来高达 2.2 倍的加速，分别优于基准方案。结果证明了利用移动 NPU 处理 LLM 测试时计算扩展负载的有效性。

::: block-1
值得注意的是，我们表明测试时计算扩展实现了**当前最先进的性能-成本权衡**：:mdnice-bold-italic[采用测试时计算扩展的小模型能够达到甚至超过未采用扩展的大模型的性能。]

据我们所知，本文是**首个** 探索在移动设备上利用 NPU 实现 LLM 测试时计算扩展方法可行性并评估其权衡的研究。
:::

我们的贡献总结如下：

- 我们分析了现代移动 NPU 的架构，并指出了 LLM 解码阶段专用矩阵单元的未充分利用问题。
- 我们提出了两项技术：硬件感知的分块量化方案和基于查找表（LUT）的计算，以加速移动 NPU 上的 LLM 测试时计算扩展。
- 我们设计并实现了一个端到端的 LLM 推理系统[2]，该系统利用移动 NPU 支持测试时计算扩展负载，且对专有软件栈的依赖最小。
- 我们证明了测试时计算扩展能够有效利用 NPU 中原本被浪费的计算能力，提升设备端小语言模型的生成质量，在精度和成本方面实现了优于传统模型扩展的帕累托最优边界。这为在移动设备上部署 LLM 开辟了新的机遇。

## 二、背景

### 2.1 大语言模型的测试时计算扩展

并行测试时扩展（parallel test-time scaling）是一种新兴且有效的范式，无需修改模型参数即可提升模型精度，其**核心是在测试阶段投入更多计算资源**。最简单的测试时扩展方法包括多数投票（majority-voting）和自一致性（self-consistency）[3,61]，**这些方法通过从多组生成样本中筛选出最一致的答案来提升性能**。对于数学或编程等结果可验证的任务，以及存在奖励模型（即结果奖励模型，Outcome Reward Models）的领域，可从完整样本集中选择得分最高的选项，这种策略被称为“最优 N 选 1”（Best-of-N）[54]。

通过前瞻展开（lookahead rollouts，提前生成多步结果以评估当前路径质量的方式），类似蒙特卡洛树搜索（Monte Carlo Tree Search, MCTS）的方法能**从部分生成的序列中筛选出最优路径，进而衍生出“过程奖励模型”（Process Reward Models, PRMs）[14,45,60,74]——这类模型可直接对生成过程中的中间结果打分**。:mdnice-bold-italic[在 PRM 的辅助下，无需前瞻的步级束搜索（step-level Beam Search）[54,63]能动态丢弃低质量生成路径，从而平衡探索（exploration，尝试新的生成路径）与利用（exploitation，利用已有高质量路径）]。

### 2.2 神经处理单元

随着 AI 负载的增长，现代 SoC 正越来越多地集成神经处理单元（NPUs）以加速神经网络推理[10,41,52]。NPUs 的核心优势在于对低精度、高计算强度的神经网络核心操作（如通用矩阵乘法 GEMM）进行专用加速，在实现极高计算吞吐量的同时，还能保持良好的能效（power efficiency，单位功耗下完成的计算量）。

::: block-1
目前被**广泛采用的 NPU 架构采用“向量+矩阵”组合模式**：

- 矩阵单元（matrix unit）负责加速矩阵乘法、卷积等操作
- 向量单元（vector unit）则处理归一化（normalization）、复杂激活函数（activation functions）等通用计算任务
:::

**典型案例包括高通的 Hexagon NPU[41]、华为的昇腾 NPU[32]、AMD 的 XDNA NPU[52]、英特尔 NPU[10]以及英特尔的 Gaudi HPU[11]，这些 NPUs 的架构均遵循这一模式。**

![文章插图](/articles/2025-10-12-npu-llm-lut-19-0-da058862/images/05.webp)

::: image-caption
图 2. (a) GPU 的 SIMT 执行模型与(b) NPU 的 SIMD 执行模型的对比
:::

**此类 NPUs 与常见的图形处理器（GPUs）在硬件执行模型上存在显著差异**。如图 2 所示：

- 在 GPU 的单指令多线程（SIMT，Single Instruction Multiple Threads）模型中，不同线程可独立执行分支、内存访问和计算操作
- 在 NPU 的单指令多数据（SIMD，Single Instruction Multiple Data）执行模型中，单个线程需处理大型向量或矩阵数据块

![文章插图](/articles/2025-10-12-npu-llm-lut-19-0-da058862/images/06.webp)

::: image-caption
图 3. 骁龙（Hexagon）NPU 架构
:::

在硬件层面，NPUs 通常**采用更少的硬件线程，并通过超长指令字（VLIW，Very Long Instruction Word）架构减少控制逻辑开销**。与 GPUs 相比，NPUs 以牺牲编程灵活性和易用性为代价，换取了更高的执行效率和能效。

## 三、动机与挑战

> 在本节中，我们首先介绍移动 NPUs 的关键特性，随后分析利用 NPUs 空闲计算资源的机会，以及为测试时扩展负载构建高效系统所面临的挑战。

### 3.1 高通 Hexagon NPU

高通骁龙 SoC 上的 Hexagon NPU 是具有代表性的移动 NPU——其架构典型、应用广泛且 SDK相对易获取。因此，我们以该 NPU 为例，阐述移动 NPUs 的核心特性。

#### 3.1.1 编程接口

对高通 Hexagon NPU 进行编程的主要方式是通过“高通 AI 引擎 Direct”（Qualcomm AI Engine Direct，通常简称 QNN）[51]——这是一种**专有、闭源的深度神经网络（DNN）推理框架**。

尽管 Hexagon SDK 中提供了适用于 Hexagon NPU 的完整 LLVM 工具链，但在大多数情况下，开发者**无法自定义高性能的底层 kernel**，核心原因在于**矩阵单元的指令未公开**。我们通过对二进制库中未公开的指令进行**逆向工程，得以利用 FP16 矩阵单元**。

#### 3.1.2 架构

##### 计算单元

Hexagon NPU **采用典型的“向量+矩阵”混合架构**。其向量单元和矩阵单元分别被命名为 HVX（Hexagon Vector eXtension，**Hexagon 向量扩展单元**）和 HMX（Hexagon Matrix eXtension，**Hexagon 矩阵扩展单元**）。

Hexagon NPU 包含 6 至 8 个用于逻辑控制的标量 VLIW 硬件线程；所有向量或矩阵指令均从标量核心的 4 个 VLIW 插槽之一发出。

HVX 单元的上下文包含 32 个宽度为 1024 位的向量寄存器（vector registers），此类 HVX 单元的数量范围为 4 至 6 个；经推导，HMX 单元的数量为 1 或 2 个。

##### 内存子系统

Hexagon NPU 包含 1MiB（兆字节）的共享 L2 缓存（L2 Cache）和 **8MiB 的紧耦合内存** （TCM，Tightly Coupled Memory）——后者是一段**由软件管理的片上内存** （on-chip memory，**集成在芯片内部的内存，访问速度远快于外部内存**）。:mdnice-bold-italic[HVX 可从 L2 缓存或 TCM 中读取数据；而向量散列/聚集操作（vector scatter/gather operations，用于处理非连续内存地址的数据访问）及所有 HMX 指令【仅】能访问 TCM。]

数据可通过 l2fetch 指令和 DMA 机制，分别从 DDR 内存加载到 L2 缓存和 TCM 中；这两种方式均支持 1D 或 2D 张量数据的异步传输。

##### HMX 单元

Hexagon NPU 强大的矩阵乘法能力源自 HMX 组件。根据高通的公开信息，**HMX 单元支持多种精度，包括 INT4、INT8、INT16和 FP16** [41]。:mdnice-bold-italic[以下介绍主要基于 FP16 精度的 HMX 单元]，相关信息来源于逆向工程、Hexagon SDK、QNN SDK 及高通的公开资料。

::: block-1
- HMX 操作的基本数据单元是“瓦片”（tile），每个瓦片对应一个特定大小的矩阵。
- 对于 FP16 精度的 HMX 单元，一个瓦片的尺寸为 `32×32`（即 32 行 32 列的矩阵），占用 2KiB 的存储空间。
- HMX 单元可从 TCM 中加载多个权重内存（weight memory）瓦片和激活内存（activation memory）瓦片，对每对矩阵瓦片执行矩阵乘法后，将结果累加到内部累加器（accumulator）中，最终输出一个与累加器对应的瓦片。
- 同时，HMX 单元还能对输出瓦片的每个通道（列）独立执行系数缩放（scaling）和偏置加法（bias addition）操作。
:::

::: image-caption
图4.（a）FP16 HMX瓦片的内存布局。每个瓦片对应一个32×32的矩阵，占用2048字节。每两行进行置换，其布局与转置后的2×32子矩阵相同。（b）基于HMX的通用矩阵乘法（GEMM）的整体内存布局。由于硬件在瓦片级别执行内积运算，权重瓦片按列优先布局排列

FP16 精度的 HMX 瓦片具有特殊的内存布局，如图 4（a）所示——输入瓦片和输出瓦片均遵循此布局。构建该布局的典型方式是：**使用 HVX 指令对原始矩阵的每两相邻行执行跨通道重排** （cross-lane shuffling，调整数据在向量通道中的位置以匹配硬件访问要求）。

### 3.2 机会：LLM 解码过程中的空闲矩阵计算

在 LLM 的自回归生成（autoregressive generation，逐 token 生成文本的过程，前一 token 输出作为后一 token 输入）过程中，**输入通常仅对应单个 token，这导致通用矩阵乘法操作在解码阶段** （decoding phase，LLM 生成文本时将隐藏状态转换为 token 的阶段）**退化为通用矩阵向量乘法**。例如，形状为`[1, 隐藏层维度]`的激活矩阵，需与形状为`[隐藏层维度, 投影维度]`的权重矩阵相乘。

以 FP16 精度的 HMX 单元为例，此时每个计算瓦片的有效尺寸为`[1,32]×[32,32]`。由于硬件计算的基本单元是 `32×32` 的瓦片，:mdnice-bold-italic[输入激活瓦片中有 31 行不包含实际有用的内容——这导致矩阵单元的利用率极低，针对大瓦片优化的矩阵单元计算能力被浪费。]

**与此同时，部分测试时扩展算法可通过增加生成过程中的计算量来提升生成质量**，这类算法包括自一致性（Self-Consistency）、最优 N 选 1（Best-of-N）、束搜索（Beam Search）等并行采样方法**。它们的核心特征是：通过大于 1 的批大小（batch size，单次计算处理的样本数量）探索多条生成路径，并通过特定方式（如外部验证器）筛选更优的生成路径。**

图 5 展示了基于“最优 N 选 1”的测试时扩展示例：随着生成预算（generation budget，即解码阶段的最大批大小）的增加，模型在 MATH500 数据集（一个数学推理数据集）上的精度显著提升。

**基于上述观察，我们提出在移动 NPUs 上运行 LLM 的测试时扩展负载：通过这种方式，可有效利用传统 LLM 生成过程中被浪费的 NPU 计算能力**。理论上，:mdnice-bold-italic[这种方法不会显著增加解码开销，且无需修改模型权重，就能在运行时提升模型的生成质量。]

### 3.3 挑战

尽管利用移动 NPUs 实现测试时扩展在理论上可行，但要构建高效的实现方案，仍需应对诸多硬件挑战。我们将这些挑战总结为以下两类：

#### 挑战1：精度不足

尽管 HMX 单元支持 FP16 精度的 GEMM 操作，但在资源受限的设备（如智能手机）上部署 FP16 模型仍不现实——因此量化模型（quantized models，将高精度浮点数参数转换为低精度整数参数的模型）成为主流选择。

包括 HMX 在内的大多数移动 NPUs 的矩阵单元，最初是为加速整数量化的 DNN 模型设计的，这些模型采用粗粒度量化方案（coarse-grained quantization schemes），如逐张量量化（per-tensor quantization，对整个参数张量使用同一套量化参数）或逐通道量化（per-channel quantization，对每个参数通道使用独立量化参数）。具体而言，:mdnice-bold-italic[Hexagon NPUs 缺乏对现代 LLM 至关重要的细粒度量化方法（fine-grained quantization methods）的原生硬件支持——这种限制也体现在 Hexagon 软件栈中：仅支持逐张量或逐通道的权重量化。]

![文章插图](/articles/2025-10-12-npu-llm-lut-19-0-da058862/images/09.webp)

::: image-caption
表 1：Llama3.2-1B-Instruct 模型在不同实现方式下的性能对比。QNN 的量化方式严重损害了模型的推理能力
:::

若将粗粒度低比特量化直接应用于 LLM 权重，会导致模型精度显著下降。如表 1 所示，Llama 3.2 1B-Instruct 模型在 QNN 逐通道量化和AWQ逐组4比特量化（均为W4A16设置，即权重4比特、激活16比特）下的精度结果显示：**逐通道量化的模型在测试时扩展所依赖的数学推理等关键任务中，性能下降严重**。遗憾的是，由于测试时扩展方法需在这类任务中应用，**QNN实现的基准精度甚至无法满足性能扩展的最低要求。**

#### 挑战2：通用计算能力与内存带宽不足

在缺乏细粒度分组量化（fine-grained group quantization）原生硬件支持的情况下，常用的解决方案是依赖通用计算单元（general-purpose computing units）处理此类计算。然而，我们发现 **NPU 内部的【通用向量单元】与专用矩阵单元在计算能力和内存访问能力上存在巨大差距。**

![文章插图](/articles/2025-10-12-npu-llm-lut-19-0-da058862/images/10.webp)

::: image-caption
表 2：HVX 和 HMX 单元的性能指标，包括 FP16 GEMM 计算能力（单位：GFLOPs）和内存读取带宽（单位：GB/s）
:::

我们在 Hexagon V75 NPU 上测试了 HVX（向量单元）和 HMX（矩阵单元）的 FP16 GEMM 性能——测试使用 `1024×1024×1024` 的 GEMM 操作，且所有输入和输出均存储在片上 TCM 中，以反映硬件的峰值性能。**如表 2 所示，矩阵单元的 FP16 GEMM 吞吐量高达 12 TFLOPS（每秒万亿次浮点运算），是单个向量线程（vector thread）的 300 倍以上。**

**在内存带宽（memory bandwidth，单位时间内可传输的内存数据量）方面，专用 DMA 引擎从 DDR 内存读取数据的带宽超过 60 GB/s，而向量单元通过核心数据路径（core data path）读取内存的带宽则低于 30 GB/s**。此外，DMA 提供的高带宽仅适用于大型、规则的 1D 或 2D 数据块，无法高效处理小型或不规则的内存访问（irregular memory accesses，数据在内存中的地址不连续的访问方式）。

这些观察表明：**向量单元的通用计算能力和内存带宽，无法跟上专用矩阵单元的计算吞吐量** ——这为实现细粒度量化下的高性能混合精度 GEMM 内核（mixed-precision GEMM kernels，同时使用多种精度进行计算的 GEMM 核心代码）带来了重大挑战。

## 四、设计概述

> 我们提出了一个专为移动 NPU 设计且针对测试时扩展负载优化的 LLM 推理系统。

**为【解决精度问题】，我们对主要权重采用 4 位细粒度分组量化，同时将激活值保留为浮点数格式**。在运行时，我们会动态地将权重实时反量化为浮点数，并利用 NPU 强大的 16 位浮点数（FP16）矩阵计算能力，高效支持测试时扩展任务。

对于向量处理单元（vector processing units）**在【内存带宽和计算吞吐量上存在局限】的不可避免的通用计算场景，我们的核心策略包括：**

- :mdnice-bold-italic[采用硬件感知的离线设计] （hardware-aware offline design），即提前根据硬件特性设计优化方案，而非运行时动态调整，以最小化运行时计算开销；
- :mdnice-bold-italic[充分利用单指令多数据向量单元的固有能力]，弥补专用硬件与灵活软件需求之间的差距。 具体而言，我们引入以下两项关键技术：

::: block-1
1. **硬件感知的细粒度块量化方案（Hardware-aware Fine-grained Tile Quantization Scheme）**：我们提出了:mdnice-bold-italic[一种新颖的量化布局，该布局在细粒度矩形块（fine-grained rectangular tiles）中执行分组量化，而非传统方法中沿累加轴（accumulation axis，矩阵计算中用于累加结果的维度）进行分组的方式]。为与矩阵单元和向量单元的内存访问模式（memory access patterns，硬件读取内存数据的方式，如顺序访问、随机访问等）对齐，我们设计了一个包含权重量化前转换、量化、量化后转换的离线流水线。这一设计提升了运行时内存访问的连续性，并消除了不必要的计算开销。
2. **高效的基于查找表（LUT）的计算（Efficient LUT-Based Computation）**：:mdnice-bold-italic[对于更复杂的运行时操作，我们利用向量单元的查找表指令和通用 LUT 机制，替代复杂的转换逻辑]。该方法可加速测试时扩展负载中的关键瓶颈操作，包括**混合精度矩阵乘法中的反量化过程，以及注意力机制中的 Softmax 操作。**
:::

## 五、系统设计

### 5.1 硬件感知的细粒度块量化方案

已有研究[30, 36]表明，在数学推理等具有挑战性的任务中，量化误差会显著降低模型性能。然而，由于设备端（如手机等移动设备）存在严格的资源限制，全精度模型仍难以部署，因此细粒度量化成为维持精度的关键手段。

遗憾的是，在移动 NPU 上实现**细粒度量化下基于反量化的高效矩阵乘法 Kernel 面临巨大的系统挑战**。我们发现主要存在以下两个问题：

::: block-1
- 矩阵单元期望的权重布局与传统分组量化布局不匹配；
- 小分组尺寸导致宽向量寄存器的利用率不佳。
:::

为克服这些局限，我们**提出了一种新颖的块量化方案**，该方案包含两个组成部分：

- **基于块的量化策略**：设计用于:mdnice-bold-italic[与矩阵单元的固有数据布局对齐]；
- **量化后权重重排方法**：:mdnice-bold-italic[最大化向量单元处理能力的利用率]，即量化操作完成后调整权重在内存中的顺序，以适配向量单元的处理方式。

#### 5.1.1 块分组量化（Tile-Group Quantization）

在传统的量化矩阵乘法（quantized GEMM）中，权重矩阵通常以列优先布局存储，这种布局与基于 CPU 的矩阵乘法（如 llama.cpp CPU 后端，一个开源的 LLM 推理框架的 CPU 计算模块）中使用的向量点积运算（vector dot-product operations，两个向量对应元素相乘后求和的运算）相契合。权**重沿列维度被划分为连续的量化组（contiguous quantization groups，在内存中连续存储的量化小组）——通常每组包含 32 个元素**。:mdnice-bold-italic[在每个组内，数值被量化为整数，得到的整数权重与其对应的扩展因子（scale）和零点（zero-point）参数（量化过程中用于将浮点数映射到整数以及反量化回浮点数的关键参数）在内存中交错存储] （interleaved in memory，如权重整数与对应扩展因子交替存储），同时保留矩阵原始的按列排序。

![文章插图](/articles/2025-10-12-npu-llm-lut-19-0-da058862/images/11.webp)

::: image-caption
图6. 量化组布局与HMX瓦片布局之间不匹配的简化说明
:::

然而，在具有特殊矩阵单元的 NPU 上，**传统分组布局往往与硬件要求不匹配。如图 6 所示，在传统布局中连续的元素，在片上紧密耦合内存** （on-chip TCM，Tightly Coupled Memory，一种速度快、与处理器紧密连接的片上内存，用于存储高频访问数据）**中会变得分散**。对于 SIMD 向量单元而言，这种非顺序的访问模式存在问题。尽管现代向量引擎提供了收集/分散操作（gather/scatter operations，SIMD 中的两种操作：收集指将分散在内存中的数据聚合到向量寄存器，分散指将向量寄存器中的数据分发到内存的不同位置，这两种操作通常耗时较长）来缓解分散访问的问题，但这些操作本身开销依然很大。**简单地对权重矩阵进行转置无法解决这种不匹配，因为矩阵单元期望的复杂多级数据布局仍会导致非连续的内存访问**。

**为解决这一问题，我们首先将权重重排（permute the weights，调整权重的顺序）为矩阵单元期望的布局，然后逐组应用就近舍入量化** （round-to-nearest quantization，将浮点数量化为最接近的整数）。:mdnice-bold-italic[当分组大小为 32 时，该方法实际上以 2×16 的块（tiles）为单位执行分组量化]。考虑到典型模型中的预训练权重大致遵循零均值高斯分布（zero-mean Gaussian distribution，一种常见的概率分布，数据围绕均值 0 呈钟形分布），**与传统分组方式相比，在这些重排后的块组内进行量化，并不会显著改变每个组内的统计特性** （statistical properties，如均值、方差等描述数据分布的数据特征）。因此，:mdnice-bold-italic[最终产生的量化误差（quantization error）与传统方法相当。]

![文章插图](/articles/2025-10-12-npu-llm-lut-19-0-da058862/images/07.webp)

::: image-caption
图4.（a）FP16 HMX瓦片的内存布局。每个瓦片对应一个32×32的矩阵，占用2048字节。每两行进行置换，其布局与转置后的2×32子矩阵相同。（b）基于HMX的通用矩阵乘法（GEMM）的整体内存布局。由于硬件在瓦片级别执行内积运算，权重瓦片按列优先布局排列
:::

具体而言，我们在量化前按照图 4 所示的布局排列权重，该布局分为两个层级的结构化设计：

- 块的外层列优先排序，与矩阵单元的块级内积运算相匹配；
- 每个块内每两行重排。

随后，我们按照新的内存顺序对权重进行逐组量化。

#### 5.1.2 合并量化组以适配宽向量访问

默认情况下，量化后的权重以结构体数组（AoS，Array of Structures）布局存储。以 Q4_0 对称量化为例，每组 32 个元素包含 16 字节的 4 位整数量化值和 2 字节的 16 位浮点数扩展因子，量化值与扩展因子在内存中交错存储。

由于 NPU 架构的内存访问高度依赖软件管理的本地 1D 或 2D 预取（software-managed local 1D or 2D prefetching，由软件主动将内存中的 1 维或 2 维数据提前加载到片上内存，以减少访问延迟），我们避免使用数组结构体（SoA，Structure of Arrays）布局——在该布局中量化值和扩展因子分别存储在独立的大型连续数组中——以更好地与硬件偏好的访问模式对齐。

然而，**细粒度量化组与向量单元的原生处理粒度存在不匹配**：单个量化组过小，无法填满 128 字节宽的向量寄存器（128-byte wide vector register，一次可存储 128 字节数据的寄存器，如可存储 32 个 4 字节浮点数或 64 个 2 字节浮点数）。**访问这种小组需要多次内存操作或额外指令来合并多个寄存器的数据，导致内存带宽利用率低下和计算开销增加。**

图7. 将8个细粒度量化组重新打包成一个超级块。INT4量化值可放入向量寄存器中。

**为解决这一问题，我们将 8 个量化组合并为一个更大的超组（super-group），并重新组织其内容，使得 256 个连续元素的 INT4 值恰好填满一个完整的 HVX 寄存器**，这一过程如图 7 所示。

### 5.2 基于查找表（LUT）的计算

鉴于向量单元的通用计算性能有限，我们提出使用通用查找表（LUT）指令和通用 LUT 机制替代复杂计算，从而减少指令数量（instruction count，完成某一计算所需的机器指令条数）和计算开销。基于**LUT 的计算对于加速测试时扩展负载中的关键操作尤为有效，例如 Softmax 中的指数函数和反量化过程。**

#### 5.2.1 基于向量收集（Vector Gather）的快速 Softmax

> 测试时扩展方法通常会提高采样并行度（sampling parallelism，同时生成多个样本的能力），导致批大小（batch sizes，一次处理的数据样本数量）增大和上下文长度（context lengths，LLM 处理的输入文本长度，通常以 token 为单位）增加。

我们分析了这些扩展因素对基于 Transformer 架构的 LLM 生成过程中主要算子的影响：

- **矩阵乘法（GEMM）**：根据前文描述的 NPU 硬件特性，在测试时扩展负载中适度增加批大小，并不会显著增加矩阵乘法延迟。此外，矩阵乘法延迟与上下文长度无关。
- **其他算子（Misc. Ops.）**：对于激活函数、层归一化（LayerNorm，一种归一化技术，用于稳定模型训练和推理过程中的数据分布）、残差加法（residual Add，残差网络中的操作，将输入直接与后续层的输出相加，缓解梯度消失问题）和旋转位置编码（RoPE，Rotary Position Embedding，一种位置编码技术，通过旋转向量来注入位置信息，广泛用于 LLM）等算子，尽管它们的计算开销（computational overhead）大致与输入大小成正比（proportional to input size），但:mdnice-bold-italic[由于其计算量和内存访问量较小，我们忽略它们的影响]。
- **注意力机制（Attention）**：:mdnice-bold-italic[注意力机制的理论计算复杂度随批大小和上下文长度增长而增长，使其成为测试时扩展场景下潜在的性能瓶颈]。

我们在高通 Hexagon NPU 上使用 FP16 精度的 HMX 单元实现了 FlashAttention[12]，并在提示词长度为 4096、不同输入批大小（查询序列长度，query lengths）下测量了其延迟构成，结果如图 8 所示。

> 结果表明，矩阵乘法对总延迟的贡献很小，而**随着查询序列长度增加，Softmax 逐渐主导注意力机制的执行时间**。

我们的分析显示，**片上 Softmax 的主要瓶颈在于指数计算** （exponential computation，计算$e^x$的操作，Softmax 的核心步骤之一），该操作需应用于$\Theta(N_q \times N_{kv})$个元素（其中$N_q$为查询序列长度，$N_{kv}$为键值序列长度，大 Θ 符号表示计算量与两者乘积同阶）。更严重的是，**这些高开销的指数运算，必须在 HVX 单元上执行，而 HVX 单元缺乏对特殊数学函数的专用硬件支持** （dedicated hardware support for special math functions，如专门计算指数、对数等函数的硬件模块）。

遵循常规做法，我们将自然指数函数$exp$替换为以 2 为底的指数函数$exp2$（即计算$2^x$），并将系数$\log_2 e$（自然对数的底$e$的以 2 为底的对数，约为 1.4427）融入到$QK^T$（查询矩阵$Q$与键矩阵$K$的转置的乘积）的扩展因子$\frac{1}{\sqrt{d}}$（$d$为注意力头维度，用于防止$QK^T$的值过大导致 Softmax 梯度消失）中。**对于分解为整数部分$k$和小数部分$f$的输入元素$x$（如$x=3.2$可分解为$k=3$、$f=0.2$），$2^f$通过泰勒级数多项式展开（Taylor series polynomial expansion，一种用多项式近似函数的数学方法）进行近似计算**，而$k$则直接添加到$2^f$的 IEEE-754 标准表示（IEEE-754 representation，一种浮点数的二进制表示标准，包含符号位、指数位和尾数位）的指数域（exponent field，IEEE-754 浮点数中用于存储指数部分的位段）中。**然而，多项式求值（polynomial evaluation，计算多项式结果的过程）存在顺序依赖（sequential dependencies，前一步计算结果是后一步计算的输入，无法并行执行）**，限制了超长指令字（VLIW，Very Long Instruction Word）架构下的指令级并行（instruction-level parallelism，同时执行多条机器指令的能力）。

**为缓解指数计算瓶颈，我们尝试用预计算的查找表（LUT）替代显式的指数计算** （explicit exponent calculation，实时计算指数值的方式）。HVX 单元提供了`vgather`指令，该指令可将 TCM 中分散位置（scattered locations in the TCM）的数据收集到 TCM 中一个连续的 128 字节区域（contiguous 128 byte TCM region）。**尽管`vgather`可实现大型 LUT，但将 LUT 用于指数计算仍面临挑战**：

- 为 32 位浮点数存储$2^{32}$个条目（entries）不切实际；
- 此外，`vgather`指令本身会引入显著延迟——在 Hexagon V75 架构版本上:mdnice-bold-italic[需 24 至 48 个指令包（instruction packets，VLIW 架构中，多条指令打包成一个指令包，一次发射执行），因此必须尽量减少其使用。]

> 为实现实用的基于 LUT 的指数计算，我们设计了如下方案：

首先，在整个 FlashAttention 中广泛使用 FP16 精度，其片上计算流程（on-chip computation process，完全在 NPU 片上完成的计算步骤）如算法 1 所示。

![文章插图](/articles/2025-10-12-npu-llm-lut-19-0-da058862/images/14.webp)

矩阵$P$、$O$和向量$\vec{m}$、$\vec{l}$（$P$通常为经过扩展和 Softmax 前的矩阵，$O$为注意力输出矩阵，$\vec{m}$存储每行的最大值，$\vec{l}$存储每行的和）均以 16 位浮点数格式存储，指数计算的输入和输出也均为 16 位浮点数。

- FP16 精度的 HMX 单元在内部累加时使用更高精度的浮点数如 FP32，以减少累加误差；
- 对于矩阵$P$的按行求和等关键操作，我们会将元素提升到 32 位精度。

使用 16 位的输入和输出将 LUT 的条目数量限制为 65536 个（$2^{16}=65536$，即 16 位浮点数的所有可能取值），所需存储空间为 128 千字节（KiB），这一大小可容纳在 TCM 中（TCM 容量通常为几兆字节，如文中提到的 8 兆字节 MiB）。`vgather`指令的一个变体支持在一条指令中收集 64 个 2 字节元素（64×2 字节=128 字节，与 HVX 寄存器宽度一致），其最大地址偏移为 65536 字节。然而，65536 个 FP16 条目占用 128 千字节存储空间，导致直接寻址（direct addressing，通过地址直接访问内存单元的方式）无法覆盖一半的条目（因`vgather`指令的最大地址偏移限制，128 千字节的 LUT 中有一半地址超出偏移范围）。

**为解决这一问题，我们利用了安全 Softmax（safe softmax[44]，一种 Softmax 优化方法，通过减去每行最大值确保输入到$exp$的数值非正，避免数值溢出**）的特性：:mdnice-bold-italic[通过减去每行最大值$m_i$，确保所有输入到$exp$的数值均非正（non-positive，小于或等于 0）]。因此，我们只需存储$x \leq 0$对应的结果，最终 LUT 包含 32768 个条目，占用 64 千字节存储空间（32768×2 字节=65536 字节=64 千字节）。在基于 LUT 的指数计算过程中，我们忽略 FP16 输入的最高有效位（MSB，即符号位，sign bit，FP16 中最高位表示符号，0 为正，1 为负），并将输入左移一位（相当于乘以 2），以生成`vgather`指令所需的字节偏移。

**模型推理开始前提前计算好 LUT 内容，在模型推理过程中无额外开销**。它在 TCM 中占用固定的 64 千字节区域，仅占 TCM 总容量的$64\ \text{KiB} / 8\ \text{MiB} \approx 0.8\%$，因此对其他操作的 TCM 可用性影响极小。

#### 5.2.2 以查找表为核心的高效反量化

运行时 HVX 反量化（runtime HVX dequantization，在 HVX 单元上实时进行的反量化操作，将量化后的整数权重转换为浮点数）需要精心设计以避免额外开销（additional overhead）。**我们提出了一种基于 HVX 查找表指令（如`vlut16`）的高效反量化流程。**

`vlut16`指令能够对源向量寄存器中每个 8 位索引（8 bit index），在一个包含 16 个元素的表中执行查找操作（table lookup）。每个输入字节会转换为一个 16 位值，因此`vlut16`指令的结果需存储在一对寄存器中（数据量翻倍，需两个向量寄存器）。

##### 基于查找表的快速 INT4 到 FP16 转换

利用`vlut16`指令，我们可直接将 Q4_0 量化方案中的 4 位量化值转换为[-8, 7]范围的 FP16 值，避免了传统的“掩码-解包-转换”指令序列，传统方法需先通过掩码提取 INT4 数据，再解包为独立数据，最后转换为浮点数，步骤多、耗时久。

![文章插图](/articles/2025-10-12-npu-llm-lut-19-0-da058862/images/15.webp)

::: image-caption
图9. 展示了两种方法的对比。通过查表将INT4量化值转换为FP16数字。对于 V79 版本之前的 Hexagon NPU（早期的 Hexagon NPU 架构版本），所有 HVX 浮点数运算的结果均以一种名为 qfloat 的内部格式存储，这种格式需要额外指令转换回标准 IEEE-754 格式，而基于查找表的方法可消除这些开销。这种以 LUT 为核心的设计只需调整表内容，即可轻松支持不同的 4 位编码方案（如 FP4、NF4[13]、llama.cpp 中使用的 IQ4_NL）。
:::

##### 基于查找表的扩展因子广播

一个 128 字节的 HVX 寄存器可容纳两个 32 元素的 FP16 量化组。因此，传统方法需将标量扩展因子广播到整个向量寄存器，然后拼接两个寄存器，以便后续与量化值相乘。然而，通过将四组扩展因子作为 LUT 内容（scales of four groups as LUT contents），并应用预定义的常量索引（用于查询 LUT 的固定索引值），我们仅用一条`vlut16`指令即可实现四组扩展因子的广播（broadcast of four groups of scales），大幅提升效率。

## 六、实现

我们的推理系统基于 llama.cpp[16]实现，包含约 7000 行 C/C++代码和内联汇编。我们使用 Hexagon SDK（版本 6.0.0.2）中的 LLVM 工具链为 Hexagon NPU 生成代码。**需要特别说明的是，我们的系统不依赖高通的 AI 推理框架，从而避免了静态固定形状计算图的局限性。**

我们的实现主要包含两个模块：

::: block-1
- 一个是面向 Hexagon NPU 的算子库，该库被编译为独立的 Hexagon DSP 共享对象文件；
- 另一个模块集成在 CPU 端的 llama.cpp 中。
:::

NPU 算子库实现了计算内核、电源管理、硬件资源管理以及计算线程池。

我们为 llama.cpp 添加了 Hexagon NPU 后端，将 rpcmem 共享内存（rpcmem shared memory，一种用于 CPU 与 NPU 之间共享物理内存的技术）作为底层缓冲区类型。rpcmem 是内核 dmabuf 内存（直接内存访问缓冲区内存，**Direct Memory Access Buffer，允许硬件设备直接访问内存而不经过 CPU 的内存区域**）的封装，**支持 CPU 与 NPU 之间的物理内存共享**。相关的内存分配、释放和映射接口由安卓系统厂商库中的 libcdsprpc.so 提供。

通过使用共享内存缓冲区，我们不仅消除了不必要的处理器间数据拷贝，还尽可能复用了现有的内存管理系统。此外，我们还能将尚未在 NPU 上实现的算子调度到 CPU 上运行，实现了与上层应用的无缝集成。

在后端初始化阶段，我们调用 Hexagon SDK 的 FastRPC[50]工具（一种用于 CPU 与 NPU 之间高速远程过程调用的技术）启动远程 NPU 会话，并初始化一块共享内存区域用于通信。在 NPU 端，有一个线程持续轮询该共享内存区域，以接收来自 CPU 的计算请求。与默认的 RPC（远程过程调用，Remote Procedure Call）实现相比，通过共享内存进行通信的延迟更低。

需要注意的是，在 CPU 将数据写入共享内存后，由于骁龙 SoC 上 CPU 与 NPU 之间仅存在单向一致性（one-way coherence，指 CPU 修改内存后，NPU 不会自动感知该修改，需手动维护缓存一致性），**NPU 不会自动使对应区域的缓存失效。因此，在 NPU 轮询前，我们需要手动清理缓存**。对于包含模型激活值（activations，模型中间层输出的特征数据）的共享缓冲区，也需要执行类似的缓存维护操作（cache maintenance operations），用于确保 CPU 与 NPU 访问的内存数据一致性。

具体来说，这些矩阵包括注意力投影矩阵$w_q$、$W_o$以及前馈网络（FFN，Feed Forward Network，Transformer 模型中的核心组件）中的$W_{gate}$、$W_{up}$、$W_{down}$。

##### 4.5 BPW 的解释

我们以“32 个权重为 1 组”（LLM 量化的主流分组大小）为例，拆解 BPW 的构成：

| 组成部分 | 比特数计算 |
| --- | --- |
| 1 组权重的量化存储开销 | 每组 32 个权重，每个权重用 4 位（Q4_0）存储 → 32 × 4 = 128 比特 |
| 1 组权重的量化参数开销 | 每组共享 1 个缩放因子（scale），通常用 FP16 存储（16 比特，平衡精度与开销）→ 16 比特 |
| 1 组的总存储开销 | 权重开销 + 参数开销 = 128 + 16 = 144 比特 |
| 平均到每个权重的 BPW | 总开销 ÷ 权重数量 = 144 ÷ 32 = 4.5 比特/权重 |

**数据显示，对于三款设备，随着批次大小增加，系统的端到端解码吞吐量显著提升**。:mdnice-bold-italic[解码吞吐量提升的根本原因是 HMX 单元的空闲算力被利用，且本质上核心 HMX 单元的计算时间并未增加]。然而，解码吞吐量并未实现完美的线性扩展，因为推理过程中包含部分随输入长度增长而显著变慢的模块。

#### 基于反量化的 GEMM

![文章插图](/articles/2025-10-12-npu-llm-lut-19-0-da058862/images/22.webp)

::: image-caption
图15. 所提出的优化方法在GEMM反量化上的消融研究。我们在一加12手机上对GEMV的性能进行了测量
:::

> 图 15 展示了 GEMM 反量化布局优化的消融实验。

- 基线方法（baseline）对应传统内存布局：按内存中连续的组对列主序（column-major，矩阵元素按列存储的顺序）权重矩阵进行量化；GEMM 内核在运行时逐组对 32 大小的组进行反量化，然后将元素分散（scatter，将数据从连续内存写入非连续内存地址的操作）到 TCM（紧耦合内存，NPU 上的高速片上内存）中的正确位置。
- “HMX layout”条目表示对 HMX 布局应用离线权重重排（offline weight rearrangement，在推理前对权重进行的布局调整）和块量化组，使 FP16 权重能够连续写入 TCM。
- “Ours”表示采用了包括量化组合并（quantization group coalesce）在内的所有优化的版本。
- 此外，我们还添加了一组标记为“no dequantization”（无反量化）的数据：在该实现中，不执行实际的权重反量化，而是直接从内存读取量化权重并复制到片上内存，不进行任何计算——这组数据可视为基于反量化方法的性能上限。

**与基线相比，我们的方法在不同矩阵大小下实现了 9.65 倍至 19.04 倍的加速**。:mdnice-bold-italic[这主要是因为基线中的分散操作（scatter operations）开销极高]。应用 HMX 布局后，量化组合并和重排操作也有效减少了计算浪费，带来了 1.82 倍至 3.45 倍的加速。特别地，**与“无反量化”组相比，我们的方法平均仅慢 27%，这表明该实现已接近反量化方法的性能上限。**

## 八、讨论

### 8.1 对其他硬件的通用性

> 我们认为，**NPU 的“向量+矩阵”架构具有一定的普遍性**，并且观察到 CPU 与 NPU 之间的界限正逐渐模糊。

除 NPU 外，**现代 CPU 也开始集成专用矩阵乘法单元（如英特尔的 AMX 单元和 ARM 的 SME 单元），这使其具备了类似的“向量+矩阵”架构**。此外，我们注意到，现代 AI 加速器（如 NVIDIA GPU）普遍存在通用计算性能与专用低精度矩阵乘法能力之间的显著差距。尽管不同硬件的架构可能存在差异，但我们所提技术背后的核心思想仍具有广泛的适用性。

### 8.2 系统性能与局限性

#### （a）解码性能（Decoding Performance）

**当前我们系统的解码速度仍受到一定限制，这主要源于反量化带来的开销**。但这并不会影响测试时扩展（test-time scaling）方法的有效性。基于 QNN 的量化矩阵乘法通常仅利用直接内存访问（DMA）和 HMX 组件（Hexagon NPU 中的矩阵计算单元），不会引入 HVX（Hexagon NPU 中的向量计算单元）计算开销。类似 T-MAC[62]的方法或许能在 NPU 上实现支持细粒度分组量化的高效矩阵向量乘法（GEMV），从而加速大语言模型（LLM）的解码过程。

#### （b）预填充性能（Prefill Performance）

**当前系统的预填充性能仍有提升空间**。将更多算子卸载到 NPU 执行、通过算子融合减少内存访问与通信开销、以及优化矩阵乘法的分块（tiling）与流水线（pipelining）策略，均有助于提升预填充性能。我们将这些优化工作留待未来研究。

#### （c）模型规模限制（Model Size Constraints）

当前实现受限于旧设备上单个 NPU 会话的 32 位地址空间，因为 32 位地址空间最多可寻址 4GB 内存，无法满足大规模模型的内存需求。采用多 NPU 会话或许能缓解这一问题。

### 8.3 并行测试时扩展的应用范围

尽管并行测试时扩展方法目前主要在数学推理任务中发挥作用，但近期研究[8, 17, 22, 49, 69, 71]的证据表明，该方法可扩展至更广泛的推理与规划领域，展现出显著的通用潜力。

## 九、相关工作

### 9.1 基于 NPU 的端侧大语言模型推理

- **llm.npu[66]率先在 NPU 上采用按张量量化的 INT8 精度矩阵乘法来加速 LLM 的预填充阶段**，并利用 CPU 辅助执行异常值相关计算（指模型中偏离大多数数据分布的极端数值的处理计算）以维持精度。
- **HeteroLLM[7]通过张量划分实现了 GPU 与 NPU 之间的协同推理**。
- 开源推理框架 PowerServe[2]利用中间 ONNX 格式实现了自定义的量化与浮点计算划分。
- **ShadowAttn[73]通过 NPU 与 CPU/GPU 的协同加速稀疏注意力** （sparse attention，仅对输入中部分关键位置进行注意力计算的优化技术）。
- ExecuTorch[48, 58]是知名的开源端侧深度神经网络（DNN）推理框架，支持 SpinQuant[38]量化方法和 QNN 后端。

上述所有工作均基于高通 Hexagon NPU，并以闭源的 QNN[51]作为后端。vivo 的相关研究[6, 40]虽利用了联发科（MediaTek）的 NPU，但由于 NeuroPilot SDK 未公开，此类研究仍较为稀少。

### 9.2 大语言模型量化

最知名的训练后量化算法（post-training quantization algorithms，在模型训练完成后对模型参数进行量化的技术，无需重新训练模型）包括 GPTQ[15]和 AWQ[34]，它们**均采用仅权重量化** （weight-only quantization，仅对模型权重进行量化，激活值仍保持高精度的量化策略），且**仅需少量校准数据**，因此被广泛应用。**后续方法如 SmoothQuant[65]、DuQuant[33]将量化范围扩展至权重-激活量化**，:mdnice-bold-italic[通过开发缓解激活值异常值分布的技术，解决了激活值量化这一更具挑战性的问题。]

最近**，QuaRot[1]和 SpinQuant[38]等综合性方法应运而生，旨在将模型的所有主要组件（权重、激活值以及关键的键值缓存（KV cache））量化至 4 位精度**。这些方法:mdnice-bold-italic[利用旋转变换（rotation transformations）在模型中构建更易于量化的特征分布。]

### 9.3 推测性解码

推测性解码[29, 39, 43]是一类 LLM 推理加速方法，其核心思想是**在一次模型前向传播中验证多个推测的 token，以缓解 LLM 解码过程中的内存受限问题** （memory-bound issue，指计算性能受限于内存数据读写速度而非计算单元处理速度的情况）。

推测性解码存在多种扩展变体，部分变体[19, 31]不再严格遵循目标模型的分布。理论上，广义的推测性解码与测试时扩展方法均属于“生成-验证”框架（Generate-then-Verify framework，先生成候选结果，再通过验证步骤筛选或修正结果的计算框架），因此我们的系统理论上可无缝支持这些应用场景。

## 十、结论

> 本研究证实了利用移动 NPU（高通 Hexagon NPU）未充分利用的计算能力来实现 LLM 测试时扩展的可行性与有效性。

通过设计端到端推理系统——该系统集成了**硬件感知的分块量化** （hardware-aware tile quantization，:mdnice-bold-italic[考虑硬件架构特性的量化方式，使量化后的数据布局更适配硬件内存访问和计算模式]）、**权重布局优化** 以及**基于查找表（LUT）的关键算子加速** ——我们证明，**结合测试时扩展的小型模型在精度和延迟方面均可超越采用传统部署方式的大型模型。**

该方法为在资源受限的移动设备上部署高性能语言模型提供了新路径，推动了端侧 AI 在效率与能力方面的帕累托前沿（Pareto frontier of efficiency and capability，指在给定资源约束下，无法在不降低某一指标性能的前提下提升另一指标性能的最优状态集合）的发展。
