## 一、引言

> 近年来，大语言模型（LLMs）取得了显著进展，在机器翻译、代码生成、问答和对话式人工智能等自然语言处理任务中实现了最先进的性能。像 GPT - 3、LLaMA 和 DeepSeek - R1 等模型表明，增加模型规模可以显著提高泛化能力和任务性能。然而，这种扩展在计算需求、内存使用和能源消耗方面带来了巨大成本。

在边缘设备上部署大语言模型，即在低功耗、资源受限的设备（如嵌入式系统、FPGA 或移动 SoC）上运行这些模型，对于注重隐私、对延迟敏感的自主应用至关重要。然而，由于大语言模型的复杂性与边缘平台有限的内存带宽、内存容量、计算能力和功率预算之间存在差距，这种部署仍然具有挑战性。

**为了弥合这一差距，最近的研究主要集中在极端模型压缩上，特别是通过低比特量化。** 诸如 BitNet 等开创性工作表明，Transformer 模型可以使用 1 比特权重进行训练，而 **BitNet - 1.58 和 DeepSeek 则将其扩展到三值量化（{-1, 0, 1}），实现了与全精度模型近乎相同的性能**。这些创新显著**减小了模型大小并降低了能源成本**，使大语言模型在边缘设备上运行更具可行性。

然而，在实际硬件（尤其是 FPGA）上部署这些压缩模型存在独特的挑战。与云规模的 GPU 不同，边缘 FPGA 在片上内存（BRAM/URAM）、外部 DRAM 带宽和能源预算方面有严格限制。此外，自回归译码的要求（如不断增长的键值（KV）缓存、长上下文处理和对延迟的敏感性）加剧了这些限制。虽然大多数先前的工作要么侧重于模型量化，要么侧重于软件加速，但仍然没有一种系统的软硬件协同优化解决方案，能够在充分利用极低比特宽度大语言模型优势的同时，满足边缘推理的计算需求。

> 在边缘大语言模型部署中，一个关键但常常被忽视的问题是**过度关注译码吞吐量**，而**预填充延迟在很大程度上被忽视。**

例如，文献[9]展示了在嵌入式 FPGA 上高效的大语言模型译码，但完全忽略了预填充阶段。然而，**预填充延迟** 不仅仅是一个技术细节，它是对延迟敏感的边缘人工智能应用中**用户体验和安全性的主要瓶颈**。虽然在云环境中预填充开销可能可以忽略不计，但在设备上部署时，它直接处于关键执行路径上。尽管其很重要，但**预填充优化仍未得到充分探索，需要社区给予更认真的关注。**

**为了解决这些限制，我们提出了 TeLLMe（三值大语言模型边缘加速器）**，这是**首款基于边缘 FPGA 的加速器**，专门为**三值大语言模型推理设计**，**全面支持预填充和译码阶段**。TeLLMe 通过针对经济高效的 FPGA（如 AMD KV260）进行优化，实现了在资源受限平台上低延迟、高能效的大语言模型部署。它**支持三值量化权重** （1.58 比特）和 **8 比特激活值**。

::: block-1我们的设计对计算、内存和调度效率进行了协同优化，主要贡献如下：

- 我们开发了**首款支持预填充和译码阶段的端到端边缘 FPGA 三值大语言模型加速器**。
- 我们提出了**基于查找表的三值矩阵乘法**，这是一种高效且节省资源的矩阵乘法单元，专门针对 FPGA 进行了优化，在投影层和前馈网络（FFN）层的三值矩阵乘法中重用分组激活值和在线计算。
- 我们引入了一种用于**预填充和译码的融合注意力单元**，采用了新颖的反向注意力机制和完全融合的流水线，以最小化片外数据移动，避免冗余的掩码计算，同时保证并行性。
- 我们在**功耗低于 7W 的情况下，在长达 1024 个 Token 的上下文中实现了高达 9.51 个 Token /秒的生成速度，性能优于功耗更低的移动 SoC。**
:::

TeLLMe 在边缘 FPGA 上，对于 64 - 128 个 Token 的提示，实现了 0.55 - 1.15 秒的预填充延迟，在支持 1024 个 Token 的上下文长度时，译码吞吐量高达 9.51 个 Token /秒，所有**这些都在 7 瓦的功耗下完成**。这标志着与现有移动边缘设备和先前基于 FPGA 的加速器相比有了显著进步，后者通常需要更高的精度和更大的功率预算。

据我们所知，TeLLMe 是首款在实际 FPGA 硬件上为三值大语言模型推理（包括预填充和译码阶段）提供端到端支持的加速器，为边缘设备上高效、低延迟的生成式人工智能建立了新的基线。

## 二、背景与相关工作

### A. 大语言模型基础

典型的大语言模型，如 LLaMA，由多个相同的 Transformer 模块组成，每个模块包含一个注意力模块，随后是一个多层感知器（MLP）模块，如图 1 所示。在每个注意力模块中，三个线性投影用于计算查询（Q）、键（K）和值（V）表示。然后，这些表示由多头注意力机制处理，该机制结合了当前的 QKV 张量和历史的 KV 缓存。MLP 模块由一个上投影层和一个下投影层组成，以及一个应用于上投影输出的额外门控投影。

![文章插图](/articles/2025-06-11-tellme-fpga-llm-018843a7/images/04.png)

大语言模型的生成推理通常分为两个阶段：**预填充阶段和解码阶段（生成），如图 1 所示**。

- 在**预填充阶段**，整个提示通过完整的模型堆栈进行处理，以生成第一个输出 Token 。这个阶段涉及**对多个输入 Token 的并行计算**，并且主要由**计算密集型的矩阵 - 矩阵乘法主导**，特别是在线性投影层中。
- 相比之下，**解码阶段** 以自回归的方式进行，每次生成一个 Token ，将先前生成的 Token 反馈回模型。这个阶段通常**受内存限制**，因为它**依赖于 KV 缓存查找和较小的矩阵 - 向量操作。**

> 根据 Chen 等人的观察，虽然在**计算密集的预填充阶段，FPGA 通常不如 GPU 高效**，但**在内存密集的解码阶段，FPGA 展现出竞争优势**。

在这项工作中，我们优先**优化** 大语言模型推理的**解码阶段**，以充分**利用 FPGA 架构的优势。**

### B. 二进制、三进制和低比特量化 Transformer

模型量化是压缩大语言模型以在受限设备上运行的关键技术。大多数传统量化方法针对 8 比特或 4 比特表示，但**最近的工作已将界限降低到二进制范围。**

- **BitNet 引入了一种从头开始使用 1 比特权重训练 Transformer 的方法**。尽管进行了极端量化，BitNet 通过**自定义缩放** 和**逐层归一化** 策略保持了有竞争力的困惑度（一种衡量语言模型性能的指标，困惑度越低，模型性能越好 ）。在此基础上，**BitNet - 1.58 引入了三进制权重表示（{-1, 0, 1}），在表达能力和压缩率之间取得了平衡**。这两种方法都凸显了二进制大语言模型在存储、吞吐量和能源效率方面的潜力。
- 类似地，**FBI - LLM 和 OneBit 展示了使用自回归蒸馏训练的完全二值化模型**，在开放域生成任务上取得了有前景的结果。
- DeepSeek - R1 提出了一种**混合量化策略，将三值量化应用于专家混合（MoE）层**，在一个 6710 亿参数的模型上实现了**高达 80%的模型大小缩减**。
- 除了训练时量化，训练后量化（PTQ）也发挥着作用。BitDistiller 将自蒸馏与量化感知技术相结合，将 3 比特和 2 比特大语言模型的性能提升到了新的水平。QuIP 引入了带有非相干处理和舍入保证的 2 比特量化。

> 这些工作主要集中在算法方面。相比之下，**TeLLMe** 为在实际中部署此类模型提供了**一种硬件适配的解决方案**，为边缘执行**提供了矩阵乘法重用和流水线融合**。

### C. FPGA 上以边缘为重点的大语言模型加速

由于带宽和逻辑资源有限，在 FPGA 上部署 Transformer 具有挑战性。**一些工作探索了在嵌入式 FPGA 上的量化 Transformer 加速器。**

- T - MAC **为 CPU 实现了一种基于查找表（TL - based）的矩阵乘法（matmul）内核**，使用低比特权重和高比特激活值。它在 Apple M2 和树莓派 5 上取得了显著性能，但由于是基于软件的，它缺乏实现最高效率所需的深度硬件级优化。
- Li 等人在 AMD KV260 平台上成功实现了一个 **4 比特量化的 LLaMA2 - 7B 模型**。尽管模型权重被量化为 4 比特，但解码计算依赖于未量化的 FP16 激活值，因此所有操作都需要以 FP16 进行，无法使用更高效的 4 比特计算单元。此外，硬件加速仅限于解码阶段，无法满足预填充阶段的计算需求。
- LlamaF **针对 ZCU102 上的 LLaMA2 风格模型进行 int8 量化**。它利用流水线矩阵 - 向量单元和异步调度，但没有解决长上下文解码的需求，并且完全忽略了预填充阶段。
- Edge - MoE **引入了一种内存高效的 MoE 视觉 Transformer 加速器，使用动态任务级稀疏性**。一项关键技术是专门的重排序，以实现注意力计算的数据重用，这一想法在 TeLLMe 的预填充模块中得到了扩展。
- SECDA 设计了支持**在 PYNQ 上进行块浮点量化操作的矩阵乘法加速器，与基于双核 Arm NEON 的 CPU 执行相比，TinyLlama 模型的延迟降低了 11 倍**。然而，其每秒 Token 生成数仅为 0.58，这意味着生成一个 Token 需要 2 秒。

> 与这些工作相比，我们的工作首次将二进制权重推理、预填充/解码支持以及 FPGA 级内存层次结构优化统一到一个连贯的设计中。

### A. FPGA 上基于查找表的三值矩阵乘法

基于查找表（TL-based）的矩阵乘法是 CPU 中实现三值矩阵乘法的高效方法，它**利用 ARM NEON 和 AVX 等专用指令执行 128/256 位查找表操作**。然而，其有限的表大小往往导致频繁的内存访问和延迟增加。**FPGA 通过利用其固有的查找表单元（LUT）资源支持更大的表，提供了理想的解决方案**，但以往的 FPGA 研究主要集中在模块级设计自动化优化，而非全面的数据流或调度策略。

> 在本工作中，我们在 FPGA 上实现了基于查找表的三值矩阵乘法，并深入探索高效流水线调度以最大化性能。

#### A.1 算法背景

一般来说，混合精度矩阵乘法的按位运算可表示为：

$$
A \otimes W = A \otimes \left( \sum_{i=0}^{n-1} 2^i W_i \right) = \left( \sum_{i=0}^{n-1} 2^i A \otimes W_i \right)
$$

对于三值矩阵乘法 $( W \in -1, 0, 1$），上述公式可简化为：

$$
A \otimes W = A \otimes W_0, \ W_{\text{ternary}} \in \{-1, 0, 1\}
$$

**此时，简单的加减法可替代乘法运算**。但选择 $-1、0、1$ 来决定加减的方式可能并非最优，因为三者的组合有限，会导致对应 A 元素的重复计算。此外，通过复制加减路径的选择单元来增加计算并行性时，选择单元的资源消耗可能超过查找表本身——片上分布式 RAM 的多读取端口可支持查找表的多次访问，仅需额外缓冲寻址信息。支持性消融研究将在下一小节呈现。

![文章插图](/articles/2025-06-11-tellme-fpga-llm-018843a7/images/06.png)

> 正如算法 1 和图 2 所述，基于查表（TL）的矩阵乘法可分为两个阶段：

1. 将权重预处理为大小为 G 的组；
2. 执行在线三元矩阵乘法计算。

![文章插图](/articles/2025-06-11-tellme-fpga-llm-018843a7/images/07.png)

- 在预处理阶段，假设每 $G=3$ 个三元值被打包成一个用于查表（TL）表寻址的索引，从而产生 $3^{G}=3×3×3=27$ 种组合。这种打包的索引表示需要 $log _{2} 27≈5$ 位。设 $A \in \mathbb{N}^{M ×N}$ 且 $W \in ternary^{N \times K}$。
- 在在线阶段，我们执行按向量分块的矩阵乘法（涉及矩阵 A 和 B）。第一步是利用预计算单元构建查表（TL）表，该表由 $3^{G}=27$ 组加法器和减法器组成，以覆盖动态激活的所有可能组合。随后，打包后的索引用于从 TL 表中寻址并选择对应值。最后，将所选值累加，在输出矩阵中生成单个向量 $O \in \mathbb{N}^{1 ×K}$。

#### A.2 多查找表数据流设计

**如图 2 所示，我们精心优化了基于查找表的矩阵乘法数据流。** 假设共有 T 个表，为向量化矩阵乘法，可将连续 T 个索引分组为索引向量，实现不同查找表的并行访问。权重索引向量矩阵可表示为：

$$
W_{\text{idx}} \in \{5\text{B, T}\}^{\frac{N}{T \times G} \times K}
$$

其中，$W_{\text{idx}}$ 加载至片上 URAM。

::: block-1调度方面，最内层循环首先基于 A 矩阵的前 $T \times G$ 个元素执行向量操作，同时构建 $T$ 个查找表。随后，利用 URAM 的多读取特性，并行处理 $QW$ 索引向量以寻址查找表，返回 $Q \times T$ 个结果。对应查找表返回值累加入大小为 $K$ 的输出缓冲区。$W$ 矩阵每行的 $K$ 个索引向量以 Q 为步长遍历。由于迭代间无依赖关系，查找表寻址和累加过程可按单周期间隔完全流水线化。处理完 A 矩阵的前 $T \times G$ 个元素后，中间循环以 $T \times G$ 为步长遍历 A 矩阵行的 M 个值，最外层循环则遍历 A 中的不同行向量（对应 LLM 预填充阶段的 Token ）。
:::

### B. 预填充注意力专用反向重排序

#### B.1 边缘 FPGA 的预填充挑战

预填充是边缘 FPGA 最具挑战性的环节之一，需要大量资源和带宽完成多 Token 计算（尤其是注意力计算，涉及复杂度 $N^2$ 的 softmax 和矩阵-矩阵多头操作）。有限的内存带宽和计算单元要求精心调度预填充注意力的计算顺序，否则易受边缘 FPGA 带宽限制，**如图 5 的“Naive Attention Scheduling”所示**。

![文章插图](/articles/2025-06-11-tellme-fpga-llm-018843a7/images/11.png)

在边缘 FPGA 视觉 Transformer 场景中，文献[17]**提出先进的密集注意力调度策略（如图 6、图 4），考虑了不同 Token 间 Q 值的重用**。但**与视觉 Transformer 不同，LLM 使用因果注意力掩码**，导致密集调度在零掩码区域浪费计算资源。

此外，$Q \otimes K$、softmax、$S \otimes V$ 等操作的融合可减少 DRAM 访问次数。GPU 端的 Flash Attention 通过内核融合实现高效计算，**但 FPGA 的片上 BRAM/URAM 资源远小于 GPU 的 SRAM，无法直接套用**。

> 为此，我们提出反向注意力方法，结合融合注意力和反向重排序调度，专为边缘 FPGA 优化。

#### B.2 反向注意力

反向注意力调度如图 7 所示。假设预填充 Token 长度为 N，$1 < i \leq N$ 和 $1 < j \leq N$ 分别表示当前查询（q）和键值（k/v）的 Token 索引，总共有 $h$ 个头。

![文章插图](/articles/2025-06-11-tellme-fpga-llm-018843a7/images/12.png)

调度上，不从首个 Token $q_1$ 开始，而是从 $q_{N-1}$ 开始。并行度设为 p（图中 $p=4$，意味着片上 BRAM 可存储 p 个 $q_i$ Token ）。每次迭代加载一个 $q_i$ Token 至片上内存（首批加载 $q_N$ 至 $q_{N-3}$），同时加载对应 $k_j$ 和 $v_j$ Token 计算。加载完所有 N 个 $k_j$ 和 $v_j$ 并完成融合内核计算后，下一迭代从 $k_{N-3}$ 和 $v_{N-3}$ 开始逐出 p 个 $k_j$ 和 $v_j$ Token ，避免因果掩码导致的冗余计算。迭代持续至遍历所有 $1 < i \leq N$、$1 < j \leq N$。该方法仅需 p 个 $q_i$ Token 、1 个 $k_j$ 和 1 个 $v_j$ 的输入缓冲区，中间缓冲区包括 $h \times p$ 个多头 MAC 中间结果 s、$h \times p$ 个多头历史最大值 m、$h \times p$ 个中间分母 $\ell$。

![文章插图](/articles/2025-06-11-tellme-fpga-llm-018843a7/images/13.png)在引入反向注意力过程后，表 II 提供了简单注意力、Edge Moe 中的密集注意力和我们提出的反向注意力之间的比较。比较表明，反向注意力的迭代次数最低，所需带宽保持不变。此外，计算核心的冗余输出率可以直接从图 4 中的注意力图中评估。简单和密集的调度方法没有考虑因果掩码，导致许多冗余计算值。

### C. 解码阶段注意力与语言模型头部的硬件专用化与重用

前节聚焦预填充阶段优化，而端到端 LLM 推理需同时高效实现预填充和解码阶段。注意力机制是两者的核心，但计算特性迥异：预填充阶段处理全输入序列矩阵，解码阶段处理单 Token 向量与缓存键值矩阵的交互，这为硬件专用化提供了机会。

::: block-1解码阶段每步生成一个 Token ，总序列长度为 M（提示+已生成 Token ），查询 q 为 $1 \times N$ 向量（对应新 Token ），键值缓存 $K_{\text{cache}}/V_{\text{cache}}$ 为 $M \times d$ 矩阵。核心计算包括：

1. 注意力分数计算 $q \times K_{\text{cache}}^T$（$1 \times N$ 向量与 $N \times M$ 矩阵相乘，结果是 $1 \times M$ 的分数向量）；
2. 对分数应用 softmax 归一化。对分数 $1 \times M$ 向量乘以 $\mathbf{V}_{\text{cache}}$（一个 $M \times N$ 矩阵）以获得 $1 \times N$ 输出向量。
:::

计算以矩阵-向量和向量-向量操作为主，单步计算负载 $O(Nd)$ 远低于预填充阶段，但每步需从片外 DRAM 中获取大型 $\mathbf{K}_{\text{cache}}$ 和 $\mathbf{V}_{\text{cache}}$ 矩阵，导致解码阶段受内存带宽限制（尤其当 $M$ 增大时）。由于计算强度低且延迟由内存访问主导，大规模并行会浪费资源，低并行度顺序计算单元已足够，这显著减少了预填充时片上硬件资源需求（如处理单元数、缓冲区大小）。

![文章插图](/articles/2025-06-11-tellme-fpga-llm-018843a7/images/14.png)

**图 8 分析表明，解码注意力受内存约束，预填充注意力受计算约束，印证了轻量化解码实现以节省资源用于预填充的必要性。**

::: block-1
### 解码注意力在语言模型头部的重用

LLaMA 等典型 LLM 架构中，经 N 个 Transformer 模块处理后， Token 生成前的最后一步是语言模型头部的线性投影（将最终隐藏状态映射为词汇表概率分布的 logits 向量）。推理时（尤其自回归解码阶段）：

- 语言模型头部输入为 $1 \times N$ 的 Token 隐藏状态向量，N 代表隐藏状态维度（例如，对于某些模型，N = 1536），
- 权重矩阵为 $N \times V$（V 为词汇表大小，如 32,000），
- 核心计算为 $[1 \times N] \times [N \times V] = [1 \times V]$ 的矩阵-向量乘法，

与解码注意力同为内存受限的低数据重用操作（$V \gg H$ 时更显著）。
:::

> 基于此，我们重用解码注意力硬件执行语言模型头部计算，省去专用单元，大幅节省面积和功耗。由于语言模型头部每 Token 仅执行一次（注意力每层执行 N 次），性能影响可忽略。

解码阶段注意力与语言模型头部的硬件重用，使得无法在其中实现完全融合的注意力流水线。因此，解码阶段采用解耦执行模型：

1. 注意力分数计算 $s = q × K_{cache}^T$；
2. softmax：$p = softmax(s)$；
3. 值聚合：计算最终注意力输出 $o = p × V_{cache}$。

中间分数/概率向量（$1 \times M$）尺寸小，可缓存于片上 BRAM，延迟代价低。反观预填充阶段的 $N \times N$ 注意力分数矩阵，因尺寸过大无法片上缓存，需通过完全融合流水线（集成分数计算、softmax、值聚合）最小化片外数据移动。

### D. 特殊功能单元的实现与优化

除核心模块外，LLM 推理依赖量化/反量化、RMSNorm、激活函数等特殊功能单元。这些操作计算强度低，设计策略聚焦轻量级硬件实现和操作融合以减少开销，向量数据按 256 位分组处理（匹配 AXI 总线宽度）。

- **量化与反量化**：激活值在三值线性模块前需量化，采用 Absmax 量化（两步法：1. 求绝对值最大值计算缩放因子；2. 逐元素应用缩放）。如图 1 所示，量化紧接 RMSNorm 后，两者融合以减少数据移动；反量化则融合至线性层输出流水线。
- **RMSNorm**：包含两步操作，先计算输入 $x$ 的均方根 $\text{RMS}(x) = \sqrt{\frac{1}{n} \sum_{i=1}^{N} x_i^2}$，再通过除以 RMS 值并乘以学习参数 $\gamma$ 实现归一化。鉴于 RMSNorm 与 Absmax 量化均需两次遍历，我们将四步逻辑融合为两步硬件操作，大幅减少数据移动。
- **激活函数**：前馈网络（FFN）的门控投影后需逐元素 SiLU 激活（$x \cdot \frac{1}{1+e^{-x}}$）。SiLU 操作流水线化并直接融合至前级线性模块，有效隐藏延迟。

## 四、实验结果与分析

### A. 实验设置

我们使用 Vitis HLS 和 Vivado 2023.1 中的高级综合 C/C++实现了 TeLLMe 加速器。我们在 Kria KV260（Zynq UltraScale+ XCK26 MPSoC）上对设计进行评估。为确保时序收敛，我们在生成最终比特流时采用 250MHz 的时钟频率。

### B. LLM 推理性能和资源分解

**图 9 展示了 LLM 推理中的关键指标，包括解码吞吐量** （ Token 生成速度）**和预填充时间** （生成第一个 Token 所需的时间）。

我们在不同配置（提示大小、生成大小）下对 TeLLMe 进行评估，需要注意的是总 Token 数 = 提示大小 + 生成大小。**TeLLMe 在 512 个上下文长度下实现了大于 9 个 Token /秒的吞吐量，在 1024 个上下文长度下约为 8 个 Token /秒。** 当提示大小小于 128 时，TeLLMe 的预填充时间约为 1 秒。这表明 TeLLMe 在实际应用中具有可行性和部署潜力。

- 在 BRAM（块随机存取存储器）使用方面，大部分被顶层 AXI 缓冲区占用。

### D. 与移动 CPU 的比较

尽管 KV260 与现代移动 SoC 之间存在显著的技术差距，但我们的 TeLLMe 设计**在关键推理指标上表现出极具竞争力的性能**。如表 V 所示，**TeLLMe 的预填充延迟为 0.55 秒，与高通骁龙 8 Gen 3** （采用先进的 4nm 工艺制造，集成 LPDDR5x 内存，带宽更高）**上观察到的 0.3 - 0.7 秒相当**。相比之下，KV260 基于 16nm 工艺，依赖带宽低得多的 DDR4 内存。考虑到预填充通常受计算限制，且在带宽受限的 FPGA 上较难加速，我们**能实现与移动 SoC 相当的预填充性能尤为显著**。

> 这一结果凸显了我们架构优化的有效性，包括基于查找表的三值矩阵乘法、具有融合操作的带宽高效注意力模块以及用于加速预填充的反向注意力重排序方案。

虽然 TeLLMe 的解码吞吐量（9.51 个 Token /秒）落后于移动 SoC，但这一差距主要归因于 KV260 有限的外部内存带宽，这对受内存限制的解码阶段影响较大。我们要强调的是，这一限制是架构层面的，而非算法问题；**我们的设计在更高带宽的平台** （如支持 HBM 的 FPGA 或定制 ASIC）**上具有良好的扩展性。**

> 总体而言，这些结果验证了 TeLLMe 作为首款在边缘 FPGA 上支持完整推理（包括预填充和解码）的二进制 LLM 加速器的有效性，其能效和架构灵活性使其在未来的边缘 AI 部署中具有良好的前景。

## 五、结论

> 我们提出了 TeLLMe，这是首个针对三值大语言模型推理进行端到端优化的 FPGA 加速器，全面覆盖预填充和解码阶段。

通过**对计算、内存和调度** 的**协同优化**，TeLLMe 采用了**基于查找表的矩阵乘法引擎**，该引擎在投影层和前馈层中**重用分组激活值** 和**在线预计算**，以实现高效的三值矩阵运算。

**融合的注意力模块** 结合**反向注意力机制** 和类似 Flash Attention 的**内核融合技术**，降低了带宽需求，消除了冗余的掩码操作，并支持并行处理。在 **7W 的功耗下，TeLLMe 的吞吐量高达 9.51 个 Token /秒**，支持 1024 个 Token 的上下文长度，在功耗显著更低的情况下**性能优于移动 SoC**。对于 64 - 128 个 Token 的提示，它的预填充延迟为 0.55 - 1.15 秒。

> 据我们所知，TeLLMe 是**首个** 在**实际硬件 FPGA** 上【完全支持】**三值大语言模型端到端推理的加速器**，为高效、低延迟的边缘推理建立了新的基准。
