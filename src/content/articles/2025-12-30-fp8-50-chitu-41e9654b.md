## 一、Chitu 推理框架核心技术创新

> Chitu 的技术突破源于对大模型推理核心痛点的精准把握——模型与硬件的适配割裂、显存占用过高、并行效率不足、量化精度损失等。其核心技术体系以“**高效适配+性能优化+工程稳定** ”为三大支柱，形成了多维度的技术创新矩阵。

### 1.1 软 FP8/FP4 精度支持：突破硬件依赖的核心引擎

FP8/FP4 作为新一代高效能数据精度格式，能将模型权重存储空间压缩 50%-75%，但:mdnice-bold-italic[传统方案需依赖 NVIDIA Hopper（H100/H200）等高端硬件的原生支持，导致大量存量 GPU（如 A100、V100）及国产芯片无法直接运行此类模型]。

::: block-1
Chitu 提出**软 FP8/FP4 在线转换技术**，通过**软件层面的算子重构与数学优化，实现了“存储用低精度、计算用高精度”的平衡**，彻底打破了硬件对模型精度的限制。
:::

#### 技术原理：高效格式转换与性能优化

Chitu 的软 FP8 实现本质是一种“w8a16”（8 位权重+16 位计算，此处 8 指的是 float8）方案，即存储 float8 权重，计算 bfloat16 权重，但通过创新的转换逻辑降低了性能开销：

- **精简转换流程**：
- **精度无损保障**：DeepSeek-R1-671B 的 FP8 版本就是原版。而 DeepSeek-R1-671B 的 FP4 量化版在 MMLU 测试中得分 88.0，仅比原版 FP8（89.8）降低 2%，显著优于 INT8（87.2）和 INT4（82.1）量化方案。
- **显存与算力双节省**：FP8 权重仅为 BF16 的 1/2，FP4 更是低至 1/4。以 DeepSeek-R1-671B 为例，BF16 版本需 1.3TB 显存，而 FP4 版本仅需不到 400GB，使得 8×64GB GPU 服务器即可部署，:mdnice-bold-italic[硬件成本降低 60%以上。]

::: block-1
节省一半算力的同时还能有几倍性能加速是**比较特殊的情况**，更多时候，赤兔方案带来的是性价比而非绝对性能的提升。

关于什么时候会出现这种**比较特殊的情况**，知乎上的这篇回答《如果 GPU 本身没有 FP8 运算单元，赤兔要怎样直接运行 FP8 模型呢？》[1]做了进一步说明。
:::

### 1.2 多元算力适配：全栈优化与跨平台兼容

Chitu 的核心目标之一是构建“适配国内多元算力环境”的推理引擎，通过编译优化、后端抽象与硬件原生算子开发，实现了对主流 GPU 与国产芯片的深度支持，解决了传统引擎“重 NVIDIA、轻国产”的适配痛点。

#### 适配技术架构

- **条件编译与后端选择**：通过环境变量（如`CHITU_ASCEND_BUILD=1`、`CHITU_HYGON_BUILD=1`）控制编译流程，自动适配目标硬件的原生算子库；运行时通过 Backend 抽象层动态选择最优计算后端，无需修改业务代码。
- **利用高性能原生算子**：针对不同硬件的指令集特性（如 NVIDIA 的 CUDA 核心、昇腾的 MLA 单元），优化 GeMM、Swiglu 等关键算子，提升计算效率。例如，在昇腾 910B 上可使用优化的 npu_swiglu 算子。
- **异构部署支持**：从 v0.2.2 版本开始支持 CPU+GPU 异构推理[2]，可将部分模型层放置于 CPU，缓解 GPU 显存压力，适用于显存受限的小规模部署场景（如单卡部署 DeepSeek-R1-671B）。

### 1.3 多维并行：突破规模瓶颈的分布式优化

> Chitu 设计了张量并行（TP）、流水线并行（PP）、数据并行（DP）、专家并行（EP）四维正交并行架构，通过灵活组合实现从单卡到千卡集群的无缝扩展，同时满足低延迟与高吞吐需求。

#### 并行核心特性

> 赤兔支持多种并行策略[3]。

**对于一般模型**，赤兔支持 TP（张量并行）、PP（流水线并行）以及多实例部署，如下图所示：

![文章插图](/articles/2025-12-30-fp8-50-chitu-41e9654b/images/03.webp)

::: image-caption
通过 PP（流水线并行）按 Layer1-3 分层划分，TP（张量并行）分割每层内的 Attn、FFN 权重；激活值（Act）在模块间传递，同时有 P/D/P+D 实例复制，实现层间流水线、层内张量并行的混合加速
:::

**对于 MoE 模型**，模型中的 attention 块和 MoE 块可以通过不同方式并行：

- Attention 块可通过 TP（张量并行）和 DP（数据并行）进行并行。
- MoE 块可通过 ETP（专家张量并行）、EP（专家并行）以及（静态或动态）将专家复制到专家槽位进行并行。
- 在 attention 块和 MoE 块之上，还可以进一步通过 PP（流水线并行）以及多实例部署进行并行。

如下图所示：

### 性能测试：量化推理效率

Chitu 提供官方性能测试脚本，可测试不同批量下的吞吐量（TPS）、首 token 延迟（TTFT）、token 间延迟（ITL）等关键指标。

#### 1. 运行性能测试脚本

```
# 进入测试脚本目录cd /workspace/chitu/benchmarks# 定义测试参数MODEL=Qwen3-32B-FP8BASE_URL=http://0.0.0.0:8001OUTPUT_DIR=/root# 测试不同批量（1、2、4、8、16、32、64）for i in 1 2 4 8 16 32 64do    python benchmark_serving.py \        --model ${MODEL}\        --batch-size ${i} \        --input-len 500 \        --output-len 50 \        --warmup 1 \        --iterations 1 \        --base-url ${BASE_URL} \        --output-dir ${OUTPUT_DIR} \        --append-resultdone
```

![文章插图](/articles/2025-12-30-fp8-50-chitu-41e9654b/images/10.webp)

#### 2. 解读测试结果

测试完成后，在`${OUTPUT_DIR}`生成结果文件，核心指标说明：

- **TPS（Token Per Second）**：每秒输出 token 数，反映吞吐量；
- **TTFT（Time to First Token）**：首 token 生成时间，反映延迟；
- **ITL（Inter-token Latency）**：token 间生成延迟，反映流畅度。

### 常见配置优化建议

根据实际场景调整以下参数，可进一步提升性能：

1. **并行参数优化**：多卡部署时，调整`tp_size`（张量并行）和`pp_size`（流水线并行），例如 2 卡部署可设`tp_size=2`，4 卡部署可设`tp_size=4`或`tp_size=2+pp_size=2`；
2. **缓存优化**：长序列推理（如`max_seq_len=4096`）时，使用`infer.cache_type=paged`，短序列高并发时使用`dense`；
3. **CUDA Graph**：批量 ≥8 时启用`infer.use_cuda_graph=True`，降低内核启动开销；
4. **量化精度**：显存紧张时，改用 FP4 量化模型（如`Qwen3-32B-FP4`），配置`quant_config.type=blockfp4`。

### 3.2 行业应用场景

> Chitu 的“低门槛、高性能、多适配”特性使其适用于以下核心场景：

1. **企业私有化部署**：金融、医疗、政务等对数据安全敏感的行业，可通过 CPU+GPU 异构部署或国产芯片部署，降低硬件成本，满足合规要求；
2. **大规模集群推理**：互联网、云服务厂商的高并发场景（如智能客服、内容生成），通过多维并行提升吞吐量，支持万级并发请求；
3. **科研与教育**：高校、科研机构可在存量 GPU（如 A100、V100）上运行千亿级 FP8 模型，降低科研成本；
4. **国产芯片生态适配**：芯片厂商可基于 Chitu 快速适配新硬件，无需重复开发软件栈，加速国产芯片的产业化落地。
