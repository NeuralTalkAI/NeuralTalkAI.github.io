## 一、引言

> 大型语言模型（LLM）近年来的快速发展使其在推理、代码生成等众多任务上实现了最先进的性能[1–6]。依托这些能力，由 LLM 驱动的自主智能体已开始实现软件开发流程部分环节的自动化[7–9]。:mdnice-bold-italic[本研究聚焦于将 LLM 驱动的智能体应用于 GPU 核函数优化——这一长期存在于高性能计算与机器学习交叉领域的挑战，其核心需求是生成兼具正确性与高度优化特性的代码。]

GPU 核函数优化对于提升 LLM 推理与训练效率至关重要，而这正是 LLM 成功部署的关键所在。然而，**即便 GPU 编程已发展数十年，核函数开发仍是一项极具挑战性的实际工程问题。硬件的快速迭代往往需要大量手动调优与重新实现**。例如，FlashAttention-2[10]首次移植到 NVIDIA H100 GPU 时性能下降了 47%，直到两年多后，FlashAttention-3[11]才通过引入大量新优化手段恢复了性能。此外，**新兴的模型架构[12–15]以及输入长度可变的动态工作负载[16]，进一步增加了核函数优化的复杂度**。因此，:mdnice-bold-italic[许多现有核函数的性能远未达到硬件峰值。缩小这一性能差距对于提升运行效率、降低成本以及改善能效均具有重要意义。]

> 从系统角度来看，GPU 核函数优化主要存在两种主流范式。

- 第一种是**完全手动调优，以 NVIDIA cuDNN[17]等库为代表**。这种方法不仅需要大量手动投入，涉及耗时的工程周期，且仍可能遗漏部分优化机会。
- 第二种是**基于编译器的优化，以 TVM[18]、Triton[19]、Mirage[20]、ThunderKittens[21]及其他系统[22,23]为代表**。例如，Triton 通过引入分块级中间表示（tile-level intermediate representation）并结合自动调优，实现了接近手动优化核函数的性能，大幅降低了终端用户的工程负担。尽管如此，这些基于编译器的系统本身仍需大量工程投入来开发，且必须随着硬件演进持续迭代适配。

鉴于 LLM 的巨大潜力，研究人员已积极探索其在 GPU 核函数优化中的应用。KernelBench[24]是该领域的开创性工作，首次为 LLM 明确了这一任务定义并提出了相应的基准测试集。其他研究则探索了单智能体方法[25–27]以及用于改进 LLM 的基于训练的方法[28,29]。

:mdnice-bold-italic[在本研究中，我们提出 Astra——首个用于 GPU 核函数优化的基于 LLM 的多智能体系统。我们的【核心观察】是：核函数优化本质上是一个包含代码生成、测试、性能分析与规划的多阶段过程，单一 LLM 智能体难以在所有环节中均表现出色。]

![文章插图](/articles/2025-09-12-llm-gpu-astra-sglang-cuda-e5b562e3/images/02.webp)

如图 1 所示，Astra 通过:mdnice-bold-italic[将任务分解为多个专业智能体，利用智能体间的迭代协作来应对这一挑战]。这种协同工作流程充分发挥了不同智能体的**互补能力**，能够**系统性地探索优化空间**，并**持续生成兼具正确性与高性能的核函数**。

给定一个从 SGLang 中提取的现有 GPU 核函数，Astra 采用多智能体方法进行核函数优化。其中，专业的 LLM 智能体通过迭代式代码生成、测试、性能分析与规划协同工作，最终生成正确且高性能的核函数。

> 我们的研究设定与 KernelBench[30]在两个重要方面存在差异。

- 首先，KernelBench 将任务定义为从 Python 编写的高级 PyTorch 模型生成 CUDA 核函数，而**我们则聚焦于优化现有 CUDA 实现——这更符合生产环境的实际情况**：:mdnice-bold-italic[生产环境中通常已存在核函数，真正的挑战在于挖掘额外的性能提升空间，而非从零开始生成 CUDA 代码]。KernelBench 已证实，对于 LLM 而言，从 Python 到 CUDA 的转换并非易事；而**本研究则专注于性能优化，避开了转换过程可能引入的错误与性能损耗。**
- 其次，我们的:mdnice-bold-italic[核函数直接取自 SGLang[31]，且优化后的核函数可无缝重新集成到该系统中]。由于 SGLang 是一款已大规模部署的生产级 LLM 推理框架，每天为各大企业与机构处理数万亿 token 的生成任务，因此即便核函数层面的小幅改进，也能产生显著的实际影响。

我们在从 SGLang[31]中提取的三个核函数上对 Astra 进行了评估，结果显示：**使用 OpenAI o4-mini 进行零样本提示时，Astra 平均实现了 1.32 倍的性能加速**。重要的是，这些结果是在无需任何额外训练（包括有监督微调或强化学习）的情况下取得的——这既证实了我们提出的纯提示方法的有效性，也暗示了其与基于训练的方法结合后进一步提升的潜力。

**为验证专用智能体角色的【必要性】**，我们还与单智能体基准模型进行了对比，结果显示后者平均仅实现 1.08 倍的性能加速。最后，我们通过深入的案例分析探究了性能提升的来源。研究发现，L:mdnice-bold-italic[LM 能够自主应用循环变换、重构内存访问模式、大量使用 CUDA 内置函数，并利用快速数学运算——这些都是实现性能加速的关键因素。]

综上，本研究的贡献如下：

::: block-1
- 设计并实现了 Astra——一款用于 GPU 核函数优化的多智能体系统。在该系统中，专业的 LLM 智能体通过迭代式代码生成、测试、性能分析与规划协同工作，最终生成正确且高性能的核函数。
- 在生产级 LLM 推理框架 SGLang 的核函数上，证实 Astra 平均可实现 1.32 倍的性能加速；且优化后的核函数可无缝重新集成到 SGLang 中，产生显著的实际影响。
- 通过对 Astra 生成的核函数进行详细人工分析，明确了实现性能加速的优化策略，包括循环变换、内存访问改进、大量使用 CUDA 内置函数以及采用更快的数学运算。
:::

## 二、相关工作

### 2.1 多智能体系统

多智能体系统（MAS）由多个交互的智能体组成，**这些智能体通过协作解决复杂的共享问题——这类问题超出了单一智能体的能力范围**。:mdnice-bold-italic[该范式特别适用于编程领域：在编程中，复杂的工作流可自然分解为规划、实现、测试和性能分析等子任务。]

近年来，研究人员已探索出多种多智能体框架，包括 AutoGen[32]、Trace[33]和 MetaGPT[34,35]等，这些框架在数学和代码生成相关基准测试中展现出了优异性能[36–39,9]。**然而，将多智能体系统应用于 GPU 内核优化的研究仍较为匮乏** ——GPU 内核优化领域存在高度专业化的性能考量，由此带来了独特的挑战。

### 2.2 GPU 内核优化的编译器与基于学习的方法

> 长期以来，GPU 内核优化主要由编译器框架和领域特定语言（DSL）驱动。

诸如 Halide[40]、TVM[18]、MLIR[41]、TensorFlow XLA[42]和 NVIDIA CUTLASS[43]等系统，以及其他相关系统[44–48]，**为张量计算的表达提供了高层抽象，并支持编译器驱动的优化。**

为进一步提升性能，AutoTVM[18]、Ansor[22]和 AMOS[23]等自动调优框架借助搜索和机器学习技术，探索庞大的优化空间。

Triton[19]、Mirage[20]和 ThunderKittens[21]等较新的系统在此基础上进一步拓展：例如，:mdnice-bold-italic[Triton 引入了瓦片级（tile-level）中间表示，并结合自动调优，实现了接近手工优化内核的性能，大幅降低了终端用户的工程开发负担]。尽管如此，这些基于编译器的系统本身仍需大量工程投入来开发，且必须随着硬件的演进持续调整。

### 2.3 基于大语言模型的高性能代码生成方法

> 在基于大语言模型（LLM）的代码生成领域，早期研究（如 AlphaCode[49]）主要针对通用编程任务，并取得了颇具前景的成果。

近年来，研究重点逐渐转向领域特定的高性能代码生成，涵盖向量化[50,51]、汇编级优化[52]、基于领域特定语言（DSL）的并行编程[53,39,54]以及张量程序优化[55]等任务。其中，:mdnice-bold-italic[一个尤为活跃的研究方向是高性能 GPU 内核的自动生成[24,56]。由于代码优化的收益可验证，迭代优化已成为一种自然范式：]

模型生成候选内核，并通过包含编译检查、正确性验证、运行时性能分析或自我反思的反馈循环，逐步改进内核性能[24,57,39]。:mdnice-bold-italic[与通用代码生成任务不同，代码优化的【核心挑战】在于确保大语言模型生成的代码兼具功能正确性和高性能] ——其中，**正确性意味着对于所有输入，生成代码与原始程序的输出均等价** [58,59]。

为应对这一挑战，研究人员已探索了**基于提示** 的方法[60,61,26,27,25,62]和**基于训练** 的方法，:mdnice-bold-italic[后者包括多轮强化学习[28]和对比强化学习[29]。]

> 本研究则通过采用多智能体系统方法来应对这一挑战。

## 三、方法

### 3.1 任务定义

> CUDA 优化的目标是生成优化后的内核 $S'$：该内核需比基准内核 $S$ 运行更快，同时保持功能正确性。

下文将正式定义正确性和性能标准，并阐述本研究设置与先前工作的差异。

#### 3.1.1 正确性

设 $x$ 为输入域，$y$ 为输出空间。基准内核与优化内核均为函数 $S, S': \mathcal{X} \to \mathcal{Y}$。理想情况下，我们要求：

$$
\forall x \in \mathcal{X}: S'(x) = S(x)
$$

若允许浮点数偏差，则要求：

$$
\forall x \in \mathcal{X}: d\left(S'(x), S(x)\right) \leq \varepsilon
$$

其中，$d$ 为偏差度量函数，$\varepsilon \geq 0$ 为容差。由于在实际场景中无法判定“完全等价”，我们通过有限测试集 $T$ 评估正确性：

$$
T = \{ (x_i, y_i) \}_{i=1}^m, \quad y_i := S(x_i)
$$

其中，选择的输入 $x_i$ 需覆盖多样的张量形状和数值。若满足以下条件，则认为 $S'$ 正确：

$$
\max_{1 \leq i \leq m} d\left(S'(x_i), y_i\right) \leq \varepsilon
$$

#### 3.1.2 性能

设 $\tau(S, x)$ 表示内核 $S$ 在输入 $x \in \mathcal{X}$ 上的运行时间。对于每个输入 $x$，加速比定义为：

$$
\sigma(x) = \frac{\tau(S, x)}{\tau\left(S', x\right)}
$$

为总结测试集 $T$ 上的结果，我们**采用几何平均值 $\sigma_T$ 作为加速比的评价指标** ——几何平均值是平均加速比的标准选择，原因在于：**它能正确聚合比率、对加速与减速具有对称性，且能降低异常值的影响**。几何平均值的计算公式为：

$$
\sigma_T = \left( \prod_{i=1}^m \frac{\tau\left(S, x_i\right)}{\tau\left(S', x_i\right)} \right)^{1/m}
$$

**优化目标是在保持正确性的前提下，最大化该几何平均加速比。**

### 3.2 多智能体系统

#### 3.2.1 智能体角色（Agent Roles）

![文章插图](/articles/2025-09-12-llm-gpu-astra-sglang-cuda-e5b562e3/images/02.webp)

> 如图 1 所示，Astra 围绕四个专业化智能体构建，每个智能体负责 CUDA 优化流程中的一个特定阶段：

- **测试智能体（Testing Agent）**：基于基准内核生成测试集，并验证候选内核的正确性；
- **性能分析智能体（Profiling Agent）**：在测试集上测量候选内核的运行时间，提供性能反馈；
- **规划智能体（Planning Agent）**：结合正确性与性能信号，提出针对性的修改建议；
- **编码智能体（Coding Agent）**：根据修改建议，生成新的内核实现。

这些智能体共同构成反馈循环，支持迭代优化，同时确保内核正确性。

#### 3.2.2 算法（Algorithm）

算法 1 概述了多智能体优化流程。

![文章插图](/articles/2025-09-12-llm-gpu-astra-sglang-cuda-e5b562e3/images/05.webp)

该流程始于初始测试集的构建和基准内核的性能分析，随后通过 $R$ 轮迭代优化推进：

- **在每一轮中**，:mdnice-bold-italic[规划智能体] 提出修改建议，:mdnice-bold-italic[编码智能体] 生成新的候选内核，:mdnice-bold-italic[测试智能体与性能分析智能体] 则重新评估候选内核的正确性与性能。
- 所有结果均记录在日志（Log）中，日志的每个条目为元组（轮次，代码，正确性，性能）——其中“正确性”为二进制指标（1 表示通过测试，0 表示未通过）。**该日志可用于系统地跟踪优化轨迹。**

#### 3.2.3 预处理与后处理

由于 **SGLang 框架[31]中的原始 CUDA 内核存在大量内部依赖**，Astra 无法直接对其进行优化。

为解决这一问题，我们**执行手动预处理步骤**：

::: block-1
- 提取内核并将其简化为独立版本，作为 Astra 的基准输入。
- 优化完成后，我们执行后处理步骤：将生成的优化内核重新集成到 SGLang 中，并基于原始框架实现（而非仅基于提取的独立版本）验证其正确性。
:::

**我们报告的加速比以原始 SGLang 内核为基准，确保优化后的内核可作为“即插即用”的替代品无缝集成到框架中**，且性能测量在完整框架环境下进行。

## 四、实验设置

我们的评估同时关注正确性和性能。

::: block-1
- 正确性通过我们构建的具有多样张量输入形状的**测试用例来判定**。我们将生成的内核输出与原始 SGLang 实现的执行结果进行对比，后者作为基准真值（ground truth）。
- 对于性能，我们在**相同的张量形状下测量原始内核和优化版本的执行时间**，并将加速比（speedup）作为评估指标。
:::

尽管多智能体框架内部会通过测试智能体生成自身的测试用例，但最终评估依赖于人工设计的测试用例，以确保对功能验证的高度信心。

我们从 LLM 服务框架 SGLang[31]中选取了三个内核进行评估，分别是 `silu_and_mul`、`fused_add_rmsnorm` 和 `merge_attn_states_lse`。它们的计算过程汇总于表 1。

表 1：内核名称及计算过程。

| 序号 | 内核名称 | 计算过程 |
| --- | --- | --- |
| 内核 1（Kernel 1） | merge_attn_states_lse | $V_{out }=\frac{e^{S_{a}} V_{a}+e^{S_{b}} V_{b}}{e^{S_{a}}+e^{S_{b}}},$$S_{out }=\log (e^{S_{a}}+e^{S_{b}})$ |
| 内核 2（Kernel 2） | fused_add_rmsnorm | $y = \frac{x + residual}{\sqrt{\text{Var}(x + residual) + \epsilon}} \odot w$ |
| 内核 3（Kernel 3） | silu_and_mul | $out = \text{SiLU}(x) \odot g,$$\text{SiLU}(z)=\frac{z}{1+e^{-z}}$ |

我们在多种输入形状下评估性能，并报告平均结果。对于每种输入形状，我们在进行 20 次热身运行（warm-up runs）后，再执行 100 次重复运行。:mdnice-bold-italic[输入形状的选择基于现代 LLM（包括 LLaMA-7B、13B 和 70B 模型）中使用的实际维度。关于输入形状如何影响性能的详细分析，将在 6.1 节中提供。]

> 我们:mdnice-bold-italic[基于 OpenAI Agents SDK 框架[63]实现多智能体系统，该框架为定义智能体和集成功能工具提供了标准化抽象]。智能体由 OpenAI 的 o4-mini 模型提供支持，所有实验均在配备 NVIDIA H100 GPU 的机器上进行。我们将优化轮次（R）设置为 5。

#### 性能

> 如表格 3 所示，多智能体方法实现了比单智能体方法更高的性能加速比（1.32 倍 vs 1.08 倍），同时两种方法生成的内核均始终保持正确性。

**我们观察到，随着内核复杂度的增加，多智能体设置的优势愈发显著**。

- 对于相对简单的内核 3，两种方法的性能表现相近；
- 相反，:mdnice-bold-italic[内核 1 的复杂度最高，暴露了单智能体设置的局限性] ——在单智能体设置中，某些任务可能无法得到有效执行，从而难以实现理想的整体结果。

具体而言，单智能体设置下内核 1 出现性能下降，原因在于测试用例构建过程中生成的测试输入不具代表性，导致性能分析结果存在偏差。而**在多智能体方法中，由于有专门的智能体负责生成代表性测试输入，另有专门的智能体负责执行性能分析，因此不会出现此类问题**。

> 总体而言，这些结果表明，在处理**更复杂的内核时，Astra 相比单智能体设置具有更显著的优势。**

### 5.3 案例研究

我们对比了基准内核与 Astra 优化后内核的源代码，并使用 NVIDIA Nsight Compute 进行了详细的性能分析。:mdnice-bold-italic[总体而言，性能提升主要源于三个方面：消除冗余计算、提高内存访问效率，以及利用高级 CUDA 特性]。

具体来说，优化后的内核通过以下方式实现性能提升：应用循环变换以增强并行性、采用更积极的内存访问策略以最大化带宽、大量使用 CUDA 内置函数（CUDA intrinsics）以实现硬件级效率，以及利用快速数学运算（fast math operations）。

> 以下通过具体示例说明这些优化策略。

#### 内核 1：merge_attn_states_lse

![文章插图](/articles/2025-09-12-llm-gpu-astra-sglang-cuda-e5b562e3/images/06.webp)

图 2 所示的一项:mdnice-bold-italic[关键优化是将循环不变量计算（loop-invariant computations）从内层元素循环中提离（hoisting）。]

::: block-1
- 在基准版本中，混合权重（mixing weights）及其归一化计算会针对输出向量的每个元素重复进行，导致在内层热点循环（hot loop）中反复执行指数运算和除法运算。
- 优化版本则针对每个输出向量仅计算一次这些量，使得内层循环仅包含内存加载、乘加（multiply–add）和存储操作。
:::

通过从循环体中移除耗时操作，**优化后的内核在不影响正确性的前提下，减少了指令数量并提高了吞吐量。**

#### 内核 2：fused_add_rmsnorm

![文章插图](/articles/2025-09-12-llm-gpu-astra-sglang-cuda-e5b562e3/images/07.webp)

该内核包含一个块级归约（block-level reduction）操作，此操作是运行时间的主要消耗源。如图 3 所示，

::: block-1
- 基准版本在片上共享内存（shared memory）中实现了树形归约（tree-based reduction）——相比基于全局内存的朴素归约，这种方式已能改善延迟和带宽，但在归约过程中会逐步禁用线程。
- 优化版本首先**使用 warp 级内置函数（__shfl_down_sync）执行 warp 内归约** （intra-warp reduction），该过程将部分和（partial sums）保存在寄存器中，从而减少同步开销；随后，**在共享内存中完成剩余的 warp 间聚合** （inter-warp aggregation）。
:::

这种“寄存器驻留的 warp 内归约 + 短共享内存归约”的方式，相比纯共享内存归约方法，实现了更高的算术吞吐量和更低的内存流量。

#### 内核 3：silu_and_mul

> 我们重点介绍两项关键优化策略：**向量化内存访问** （vectorized memory access）和**快速数学内置函数** （fast math intrinsics）的使用。

![文章插图](/articles/2025-09-12-llm-gpu-astra-sglang-cuda-e5b562e3/images/08.webp)

如图 4 所示:

::: block-1
- 基准内核采用标量加载（scalar loads）方式，从全局内存中逐个读取 half 类型的值；
- 而优化后的内核则通过将两个连续的 FP16 值组合为half2 类型**，实现向量化加载（vectorized loads），使得每条指令可同时获取一对元素。这种方式** 减少了内存事务（memory transactions）的数量，提高了有效内存带宽**。类似的向量化访问模式也应用于内核 1 和内核 2 中。
:::

![文章插图](/articles/2025-09-12-llm-gpu-astra-sglang-cuda-e5b562e3/images/09.webp)

除内存访问优化外，通过优化 SiLU 函数的实现，计算吞吐量得到了进一步提升。

::: block-1
- 基准版本使用标准数学库调用和浮点除法计算 SiLU（如图 5a 所示）；
- 而优化后的内核（如图 5b 所示）则**使用 CUDA 设备内置函数：expf 用于指数运算，frcp_rn 用于倒数计算，__fmul_rn 用于乘法运算**。**将除法运算替换为“倒数-乘法”序列，减少了指令延迟**，提高了算术流水线的利用率，并在保持数值正确性的前提下实现了更快的执行速度。
:::

## 六、讨论

### 6.1 张量形状对性能加速比的影响

> 为研究张量形状对性能的影响，我们报告了每个核函数四种代表性形状的实验结果。

![文章插图](/articles/2025-09-12-llm-gpu-astra-sglang-cuda-e5b562e3/images/10.webp)

如表 4 所示，经 Astra 优化后的核函数在不同形状下均实现了稳定的加速比。

::: block-1
- 对于 merge_attn_states_lse（核函数 1），我们采用的形状格式为[序列长度（seq_len）、头数（number_of_heads）、头维度（head_dim）]；
- 对于 fused_add_rmsnorm（核函数 2）和 silu_and_mul（核函数 3），则采用[批次大小（batch_size）、隐藏层大小（hidden_size）]的形状格式。
:::

由于性能加速比会随张量形状变化，因此在第 5 章中，我们报告了每个核函数在一组源自主流开源模型（如 LLaMA-7B、13B 和 70B）的常见形状上的平均加速比，以确保实验结果能在不同形状和服务场景下具有泛化性。

与[22,23]等张量编译器优化方法不同（这类方法会针对特定形状进行调优），**Astra 不会引导智能体针对某一特定形状进行优化**。相反，其:mdnice-bold-italic[目标是为通用张量计算提供性能提升]。

### 6.2 局限性与未来工作

目前我们的评估仅针对三个 CUDA 核函数，且该框架是为 SGLang [31]量身定制的。在未来的工作中，我们计划将支持范围扩展到更多核函数以及其他框架，例如 vLLM [64]、PyTorch [65]和 TorchTitan [66]。

**本研究的一个关键局限性在于，预处理和后处理步骤（见 3.2 节）完全依赖人工操作**。

::: block-1
- 预处理需要从 SGLang 中提取核函数并将其简化为可作为 Astra 输入的独立版本；
- 后处理则需要通过“猴子补丁”（monkey-patching）将优化后的核函数重新集成到 SGLang 中，并与原始框架实现（而非仅与提取出的独立版本）进行正确性验证。
:::

由于现代服务框架的复杂性，这些步骤难以自动化。未来的研究应探索如何使这一过程更自动化，例如引入人机协同指导机制，从而使 Astra 能够扩展到更多核函数的优化场景。

## 七、结论

> 在高性能计算和机器学习领域，GPU 核函数优化是一项关键但劳动密集型的挑战。

在本研究中，我们提出了 Astra——首个专门用于 GPU 核函数优化的基于大语言模型（LLM）的多智能体系统。与

以往将高层 PyTorch 模块转换为 CUDA 代码的方法不同，Astra 直接对来自广泛部署的 LLM 服务框架 SGLang 的现有 CUDA 核函数进行优化。通过协调负责代码生成、测试、性能分析和规划的专用智能体，Astra 能够生成兼具正确性和高性能的核函数。

我们的评估结果表明，**Astra 实现了 1.32 倍的平均加速比**；案例研究进一步显示，**LLM 能够自主应用循环变换、重构内存访问模式、利用 CUDA 内部函数以及采用快速数学运算等优化策略**。

> 这些结果充分证明，基于多智能体的 LLM 系统是核函数性能优化的一种极具潜力的新范式。
