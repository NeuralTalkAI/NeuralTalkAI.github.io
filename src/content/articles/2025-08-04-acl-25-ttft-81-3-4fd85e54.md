## 一、引言

考虑到数据隐私和服务可访问性，将预训练的大型语言模型（LLMs）直接部署在移动设备（如智能手机）上至关重要（Yi 等人，2023a；Kong 等人，2024b）。为了使预训练模型适应设备上多样化的特定领域需求，低秩适应（LoRA）（Hu 等人，2022；Dettmers 等人，2024）是一种广泛使用的参数高效微调技术。**LoRA 保留基础模型参数，并在 Transformer 层** （Transformer 是一种基于自注意力机制的深度学习模型结构）**中引入即插即用适配器进行微调**，其大小通常为数十兆字节。:mdnice-bold-italic[苹果和谷歌等主要移动设备厂商在其设备端智能服务中大量依赖 LoRA 适配器] （Gunter 等人，2024；Android Developers，2023）。

鉴于基于 LoRA 的大型语言模型的前景，将一组适配器与基础模型高效协同服务引起了广泛关注。研究人员致力于在数据中心中服务大量 LoRA 适配器（Wu 等人，2024a；Sheng 等人，2024；Chen 等人，2024；Kong 等人，2024a）。这些研究以吞吐量为重点，将多个 LoRA 适配器与基础模型融合，并利用手工设计的 CUDA 内核（CUDA 是英伟达推出的并行计算平台，内核是在 GPU 上执行的函数）支持融合模型的批量推理。

相比之下，对于设**备端大型语言模型推理，首 token 生成时间** （即 TTFT，指从输入请求到生成第一个 token 所需的时间）**等延迟指标至关重要**，因为:mdnice-bold-italic[移动设备上实时交互和处理单个请求是常见场景]。其他主流大型语言模型服务框架（Kwon 等人，2023；Gao 等人，2024b；Liu 等人，2024；Lin 等人，2024）侧重于存储中间状态，即键值（KV）缓存（在 LLM 推理中，用于存储注意力机制计算时的键和值，避免重复计算），以避免在具有共享前缀的请求之间进行重复计算。移动设备有限的计算和内存资源凸显了复用 KV 缓存的重要性。:mdnice-bold-italic[然而，现有方法不能直接应用于基于 LoRA 的大型语言模型]，因为即使请求相同，不同适配器的 KV 缓存也无法复用。因此，在移动设备上高效服务基于 LoRA 的大型语言模型面临挑战。

> 幸运的是，:mdnice-bold-italic[移动设备上有两个独特的机会] 尚**未被充分利用** 来加速基于 LoRA 的大型语言模型推理，即**语义级和系统级上下文**。

### 加速机会1：复用语义级上下文

在移动设备的日常使用中，**使用相同的语义级上下文（即提示词和用户输入）请求不同的 LoRA 适配器是常见的** （Hong 等人，2023；Wu 等人，2024b）。例如，用户在写电子邮件时，首先使用校对适配器润色文本，然后使用摘要适配器浓缩同一段落。

尽管不同适配器上相同 token（token 是文本处理中的基本单位，可理解为词或子词）的 KV 缓存不同，但我们的初步实验表明，它们表现出**较高的 token 级相似性**。这种:mdnice-bold-italic[相似性有助于在语义级上下文下对 LoRA 适配器的 KV 缓存进行高效编码和复用。]

### 加速机会2：利用系统级上下文

除了语义级上下文外，设备端大型语言模型推理的另一个独特特征是**易于获取系统级上下文**，例如查询大型语言模型的应用程序状态（如前台活跃或已终止）。:mdnice-bold-italic[利用这类上下文为移动设备上高效的大型语言模型服务带来了更广阔的优化空间]。例如，当用户终止一个应用程序时，与该应用程序查询相关的 KV 缓存可能不会被复用。此时，明智的做法是**清除这些缓存，为其他活跃应用程序腾出空间。**

---

利用上述机会，我们提出了 MobiLoRA，以加速移动设备上基于 LoRA 的大型语言模型推理。考虑到移动设备的资源有限，我们**引入了一种新的注意力机制 CtxAttention，通过设备端上下文来提高 KV 缓存的复用性**。

::: block-1
基于 CtxAttention：

- 针对**语义级上下文**，MobiLoRA :mdnice-bold-italic[为不同 LoRA 适配器上共享前缀的 KV 缓存提出了相似性感知的增量编码] （delta encoding，记录数据与基准数据的差异来压缩存储的方式），以促进其高效存储和复用。
- 针对**系统级上下文**，MobiLoRA :mdnice-bold-italic[利用上下文感知的 KV 缓存管理来优化 KV 缓存的保留和淘汰] （eviction，当缓存空间不足时，移除部分缓存数据的操作）。
:::

除了广泛使用的基于最近最少使用（LRU，一种缓存淘汰策略，优先移除最久未被使用的缓存项）的管理方式（Zheng 等人，2023；Kwon 等人，2023）之外，**MobiLoRA 在决定 KV 缓存淘汰时还会考虑查询大型语言模型的应用程序状态**。

:mdnice-bold-italic[我们在最先进的大型语言模型服务系统 SGLang（Zheng 等人，2023）的基础上实现了 MobiLoRA]，并基于真实世界的移动应用程序使用轨迹对该框架进行了广泛评估。结果表明，在首 token 生成时间（TTFT）方面，MobiLoRA 将设备端基于 LoRA 的大型语言模型推理速度提升了 18.1%~81.3%。

::: block-1
本文的贡献如下：

- 据我们所知，这是第一项针对移动设备上基于 LoRA 的大型语言模型的 KV 缓存进行优化的工作。这种优化源于我们的观察，即利用语义级和系统级上下文可以提高推理效率。
- 基于我们的观察，我们提出了一种供不同 LoRA 适配器使用的相似性感知的 KV 缓存增量编码方法，以及一种上下文感知的 KV 缓存管理策略，以实现设备端 KV 缓存的高效复用。
- 我们实现了 MobiLoRA 并对其性能进行了广泛评估。结果表明，我们的方法提高了设备端自然语言处理任务的效率。

## 二、背景与动机

在本节中，我们首先介绍设备端基于 LoRA 的大型语言模型（LLMs）以及复用 LoRA 的键值（KV）缓存所面临的困难。然后，我们介绍指导 MobiLoRA 设计的相关观察结果。

### 2.1 设备端 LoRA 服务基础

面向移动设备的基于 LoRA 的大型语言模型。基于 LoRA 的大型语言模型微调现已在移动设备上被广泛采用。**苹果和谷歌等主要移动设备制造商在其设备端智能服务中利用 LoRA**，例如 Apple Intelligence（苹果智能，苹果公司的设备端智能服务）（Apple, 2024）和 Android AICore（安卓人工智能核心，安卓系统的人工智能服务组件）（Android Developers, 2023）。

![文章插图](/articles/2025-08-04-acl-25-ttft-81-3-4fd85e54/images/04.webp)

为了在资源受限的情况下满足多样化的日常需求，**设备端基于 LoRA 的服务通常采用“单模型、多适配器”的方式，如图 1 所示**。LoRA 适配器会根据请求被选择性激活。

> 例如，Apple Intelligence 采用一个拥有 30 亿参数的大型语言模型作为基础模型，并**提供各种 LoRA 适配器以适用于不同场景**，如包含文本校对和改写功能的写作工具、通知优先级排序以及智能回复等。

基于 LoRA 的键值缓存复用面临挑战。由于大型语言模型推理的自回归特性，每个 token 的生成都会用到其前面所有 token 的隐藏状态。**存储这些隐藏状态（即键值缓存）用于未来的 token 生成，有助于避免重复计算。**

因此，利用键值缓存已成为加速大型语言模型推理的一种流行技术。各种键值缓存框架被相继提出，如 vLLM（Kwon 等人，2023）和 SGLang（Zheng 等人，2023）。**除了在单个请求中使用键值缓存外，这些框架还研究了在多轮对话中或不同请求之间复用缓存的可能性**。这种机会:mdnice-bold-italic[背后的原理是，具有相同前缀的提示词之间可以复用键值缓存。]

然而，对于基于 LoRA 的大型语言模型，不同 LoRA 适配器之间直接复用键值缓存是不现实的。我们以基于 Llama2-7B 模型微调得到的 FinGPT LoRA 适配器为例进行说明。FinGPT 在每个 Transformer 层的 Q、K、V 计算中应用低秩矩阵。

![文章插图](/articles/2025-08-04-acl-25-ttft-81-3-4fd85e54/images/04.webp)

图 1 展示了 V 的计算示例。LoRA 将原始计算 $V = xW_v$ 转换为 $V'=xW_v + xW_v^aW_v^b$，其中 x 是注意力输入，$W_v \in \mathbb{R}^{h \times d}$ 是 V 的投影矩阵（用于将输入映射到特定维度的矩阵）。$W_v^a \in \mathbb{R}^{h \times r}$、$W_v^b \in \mathbb{R}^{r \times d}$ 是秩为 r 的低秩矩阵（秩较小的矩阵，可减少参数数量）。类似地，带有 LoRA 的注意力得分计算公式如下：

$$
Attn_{LoRA}=softmax\left(\frac{Q'K'^T}{\sqrt{d_k}}V'\right) \quad (1)
$$

其中，$Q'$ 和 $K'$ 是由于 LoRA 而更新后的 Q 和 K 的值，$d_k$ 是隐藏维度。带有 LoRA 的键值缓存（$(K', V')$）与不带有 LoRA 的键值缓存（$(K, V)$）**不同**，而且非线性的 softmax 运算（一种将输出转换为概率分布的函数）**进一步导致键值缓存难以复用**。更糟糕的是，由于**自回归生成特性**，有无 LoRA 之间的**差异会通过更深的网络层和后续的 token 不断传播。**

### 2.2 利用上下文的机会

#### 语义级上下文

在移动设备的日常使用中，向不同 LoRA 适配器发送语义级上下文（即相似甚至相同的提示词）是很常见的。为了研究如何有效复用语义级上下文，我们进行了一项初步实验。我们将从 ShareGPT（ShareGPT, 2023）中提取的相同提示词输入到基础模型 Llama2-7B 和基于 FinGPT LoRA 微调的模型中。

![文章插图](/articles/2025-08-04-acl-25-ttft-81-3-4fd85e54/images/05.webp)

然后，我们对比了这两个模型的键值缓存的相似性，结果如图 2 所示。我们得到以下观察结果。

> **观察 1**：:mdnice-bold-italic[对于相同的提示词，不同 LoRA 适配器的键值缓存存在相似性]。我们观察到键缓存和值缓存的最大相似性分别为 97%和 95%。基于这种相似性，存在一种机会，即只**需存储不同 LoRA 之间键值缓存的增量差异，以减少内存消耗**，这在内存有限的移动设备上尤为重要。

> **观察 2**：可以观察到 :mdnice-bold-italic[token 级的相似性递减模式]。具体来说，在**较浅的 Transformer 层中，相似性更为明显，并且随着网络层加深，相似性逐渐降低**。这种模式背后的原因是，:mdnice-bold-italic[随着网络层加深，更多 LoRA 的输出与基础模型的输出融合，导致键值张量] （张量是多维数组，这里指存储键值缓存的数据结构）:mdnice-bold-italic[的差异更大]。如何利用这一观察结果来提高键值缓存的编码效率，需要 MobiLoRA 进行大量的设计工作。

#### 系统级上下文

由于移动设备的资源有限，无法让缓存无限增长，因此键值缓存管理（如缓存淘汰）是必要的。然而，常用的基于最近最少使用（LRU）的淘汰策略在某些场景下表现不佳。例如，当用户终止一个应用程序时，与该终止应用程序的查询相关的键值缓存通常不再需要，应该优先被淘汰。

**这种系统级上下文对于数据中心的服务框架来说几乎无法获取，因为它们的请求来自外部应用程序**。在:mdnice-bold-italic[设备端服务方面，MobiLoRA 能够轻松获取这种上下文]，为键值缓存管理开辟了新的视野。因此，我们关于系统级上下文有以下观察结果：

> **观察 3**：利用系统级上下文有助于实现高效的键值缓存管理。

## 三、MobiLoRA 设计

> 基于上述机会，我们设计了 MobiLoRA。图 3 展示了整体系统架构。

![文章插图](/articles/2025-08-04-acl-25-ttft-81-3-4fd85e54/images/06.webp)

MobiLoRA 的核心是一种新的注意力机制 CtxAttention，它有助于利用上下文来管理 LoRA 键值缓存。基于 CtxAttention，我们的系统提出了：

::: block-1
1. 一种相似性感知的键值缓存增量编码机制（用于结合语义级上下文高效存储 LoRA 键值缓存）
2. 一种结合系统级上下文的上下文感知键值缓存管理策略
:::

### 3.1 面向基于 LoRA 的大型语言模型的 CtxAttention

为了利用设备端上下文的潜力，我们引入了一种新的注意力机制 CtxAttention，以促进基于 LoRA 的大型语言模型实现上下文感知的键值缓存复用。

![文章插图](/articles/2025-08-04-acl-25-ttft-81-3-4fd85e54/images/06.webp)

如图 3 所示，**CtxAttention 包括一个上下文感知基数树** （radix tree，一种用于高效字符串匹配和前缀查找的树状数据结构）**和一个 LoRA 键值池**。

:mdnice-bold-italic[受 RadixAttention 的启发，CtxAttention 利用基数树将缓存的 token 序列映射到其键值缓存张量] （张量，多维数组，这里指存储键值缓存的数据结构），并通过以下两个方面对其进行增强。

> 为了**复用于不同 LoRA 的语义级上下文**，CtxAttention 扩展了基数树，使其在树的同一条边上为不同的 LoRA 实例（即#LoRA）存储多个映射信息（即指向键值池的偏移量和长度、基准信息）。

在 LoRA 键值池中，第一个记录的 LoRA 请求的键值缓存张量以原始形式存储，称为基准张量（anchor tensor）。其他适配器的后续键值缓存张量则编码为与基准键值的差异，称为增量张量（delta tensors），以提高存储效率。

这些基准信息也存储在上下文感知基数树中。有了上述上下文信息，公式 1 中带有 LoRA 的注意力得分可以通过复用基准键值缓存转换为如下形式：

$$
Attn_{LoRA}=softmax\left[\frac{Q\left(K_A \star K_{\Delta}\right)^T}{\sqrt{d_k}}\left(V_A \star V_{\Delta}\right)\right]
$$

其中，$K_A$ 和 $V_A$ 是基准键张量和值张量，即已有的键值缓存。$K_{\Delta}$ 和 $V_{\Delta}$ 是增量张量。运算符 `*` 表示增量张量与其基准张量的解码操作。

> 为了**利用设备端系统级上下文**，CtxAttention 除了记录最近最少使用（LRU）信息外，还额外记录应用程序 ID（即 app_id）。

这些数据帮助 MobiLoRA 结合移动设备上的应用程序状态来改进键值缓存管理。

### 3.2 相似性感知的增量键值编码

基于前面提到的不同 LoRA 适配器之间的 token 级相似性（观察 1），**MobiLoRA 利用增量编码方法来高效存储和复用键值缓存**。编码过程包括以下两个步骤。

::: block-1
- 首先，通过 LoRA 相关前缀匹配，确定哪些输入 token 应该用增量方式编码。
- 然后，通过分层增量编码，结合键值缓存的相似性计算增量。
:::

#### LoRA 相关前缀匹配

借助 CtxAttention 机制，当一个新请求到达时，MobiLoRA 会在基数树中对比提示词的前缀，以找到匹配的前缀。

- 如果前缀匹配且 LoRA 适配器与已有的键值缓存不同，则触发相似性感知的增量编码。
- 如果**没有匹配的前缀，MobiLoRA 会将输入的键值缓存作为基准张量存储**，并在基数树中为该输入创建一条新边。

#### 分层增量编码

与大型语言模型的各种量化方案（将模型参数或中间结果从高精度转换为低精度以减少存储和计算开销的方法）相匹配，键值缓存有不同的数据类型，如 8 位整数（INT8）和 16 位浮点数（FP16）。**对于整数键值缓存，计算高相似性张量的增量会减小张量的绝对值，从而可以用更少的位来表示它**。因此，:mdnice-bold-italic[MobiLoRA 直接利用算术编码（Liang 等人，2018）进行编码。]

然而，对现实部署中更常见的浮点键值缓存进行编码面临不小的挑战。尽管浮点增量的绝对值相对较小，但其表示中尾数位的强随机性使其难以实现高无损压缩率。考虑到移动设备有限的计算和存储能力，**MobiLoRA 通过有误差界的量化（在允许的误差范围内将连续值转换为离散值）对浮点增量进行编码，以实现高压缩率。**

#### 以键缓存编码为例

我们用 $K_I$ 表示要与已有的 $K_A$ 进行编码的输入键缓存张量。借鉴 sz 压缩的思想，我们计算 $K_I$ 和 $K_A$ 之间有误差界的增量量化：

$$
K_{\Delta}=\left\lfloor\frac{K_I - K_A}{2\log(1+\epsilon)}+0.5\right\rfloor
$$

其中，$K_{\Delta}$ 是张量增量的有误差界量化结果。误差界参数 ϵ（如 1E-4、1E-5）的选择是平衡编码精度和压缩率的关键。**基于相似性递减模式的见解（观察 2），我们对更深的网络层应用更宽松的误差界**。具体来说，:mdnice-bold-italic[对于每个 token，我们持续监控其键值缓存与基准张量的相似性]。我们将网络层分为多个相似性组，即高相似性层（在当前实现中>97.5%）、中等相似性层和中低相似性层（<85%）。然后，我们为每个组应用不同的 ϵ：高相似性组用 1E-4，中等相似性组用 1E-3，中低相似性组用 1E-2。值缓存的编码与此类似。

> 值得注意的是，这些误差界参数并非凭经验设置。参数应根据特定的基础模型架构进行调整，同时考虑注意力头的数量和维度。

### 3.3 上下文感知的键值缓存管理

我们首先说明如何记录系统级上下文，并提出一种基于效用的键值缓存淘汰机制，以替代最近最少使用（LRU）机制，从而实现高效的设备端 LoRA 推理。

![文章插图](/articles/2025-08-04-acl-25-ttft-81-3-4fd85e54/images/06.webp)

#### 系统级上下文表示

如图 4 所示，不同移动操作系统（OS）上应用程序进程生命周期的状态转换是不同的（Zheng 等人，2024；Lee 等人，2016）。**从设计上讲，MobiLoRA 旨在作为一种与操作系统无关的大型语言模型服务中间件**。

因此，我们:mdnice-bold-italic[将两种生命周期模型映射到一个通用的三态模型，即前台、后台和已终止]。我们实现了一个轻量级状态监控器作为插件，用于各种移动系统，以*跟踪所有与键值缓存相关的应用程序的状态转换。*

#### 基于效用的键值缓存淘汰

当缓存池满时，淘汰过时的键值缓存是 MobiLoRA 中一项关键的管理考虑。利用系统级上下文，MobiLoRA 通过键值缓存未来被复用的效用对其进行排序。我们将 CtxAttention 基数树中一个键值缓存节点 n 的效用定义为三个部分：与请求相关的应用程序 a 的状态得分 $\mathbb{S}(a)$、最近最少使用（LRU）得分 $\mathbb{T}(n)$，以及键值缓存的长度 $\mathbb{L}(n)$。具体来说，我们有以下公式：

$$
U(n)=\lambda_s\phi_s\left(\sum_{a \in A_n}\mathbb{S}(a)\right)+\lambda_t\phi_t(\mathbb{T}(n))+\lambda_l\phi_l(\mathbb{L}(n))
$$

其中，$A_n$ 表示与节点 n 相关联的应用程序集合。$\lambda_s$、$\lambda_t$ 和 $\lambda_l$ 是控制这三个得分权重的超参数。$\phi_s$、$\phi_t$ 和 $\phi_l$ 是单调非负函数，确保 $U(n)$ 是次模函数（Kumari 等人，2024；Bilmes，2022）（次模函数具有边际收益递减的特性，即对一个集合添加元素时，新元素带来的收益会随着集合规模增大而减少）。

在缓存淘汰过程中，**效用 $U(n)$ 最低的节点会被优先清除，确保在内存紧张时前台应用程序的缓存得以保留，同时主动回收过时的缓存项**。:mdnice-bold-italic[这种机制将系统级上下文与键值缓存管理相结合，从而优化用户感知的响应性和内存效率]。由于 $U(n)$ 是次模函数，根据次模函数的性质（Bilmes 和 Bai，2017），我们利用贪心算法在有限步骤内获得一个（1-1/e）因子内的次优解。

![文章插图](/articles/2025-08-04-acl-25-ttft-81-3-4fd85e54/images/07.webp)

因此，我们得到了如算法 1 所示的上下文感知键值管理算法。在每个时间步，MobiLoRA 更新前缀树中每个节点的效用（第 5 行）。然后，MobiLoRA 根据内存预算判断是否需要淘汰缓存（第 6 行）。

- 如果内存预算足够，直接存储输入的键值缓存（第 7 行）；
- 否则，通过贪心算法选择效用最低的节点进行淘汰，直到有足够空间存储新的缓存（第 8-16 行）。

- Punica（Chen 等人，2024）提出了一种新的 CUDA 内核设计，允许在 GPU 集群中对不同 LoRA 模型的 GPU 操作进行批处理。
- S-LoRA（Sheng 等人，2024）提出了一种新的张量并行策略，用于解耦基础模型和 LoRA 适配器，还包括一种统一的分页策略来统一管理 KV 缓存和适配器权重。
- CaraServe（Li 等人，2024）采用 CPU 辅助方法和秩感知调度算法，分别缓解冷启动开销和满足服务等级目标（SLOs）。
:::

这些工作主要针对云环境下的高吞吐量推理，而设备端服务需要不同的目标，例如小批量场景下的低延迟。

### KV 缓存优化

KV 缓存被广泛用于加速大语言模型的自回归解码（即逐 token 生成文本的过程）。现有工作从多个角度探索了减少 KV 缓存存储需求的方法。

::: block-1
- SGLang（Zheng 等人，2023）和 vLLM（Kwon 等人，2023）利用前缀共享来减少 KV 缓存的生成。
- CacheGen（Liu 等人，2024）通过将 KV 缓存压缩为紧凑的比特流来减少传输所需的带宽。
- CacheAttention（Gao 等人，2024a）通过分层 KV 缓存放置和一种重叠机制来管理 KV 缓存，以减少与此过程相关的开销。
:::

在本文中，我们探索了一种利用**增量压缩机制来减少 KV 缓存占用的新方法**，为 KV 缓存优化开辟了新的维度。

## 六、结论

> 在本文中，我们提出了 MobiLoRA，一种用于移动设备上基于 LoRA 的大语言模型的高效推理框架。

MobiLoRA 利用:mdnice-bold-italic[语义级和系统级上下文来加速推理]。MobiLoRA 的**核心是一种新的注意力机制，称为 CtxAttention**，它存储语义级和系统级上下文以优化 KV 缓存管理。

借助 CtxAttention，MobiLoRA 提出了相似性感知的 KV 增量编码，以促进基于 LoRA 的大语言模型的 KV 缓存的高效存储和重用。此外，MobiLoRA 利用系统级上下文（即发送大语言模型请求的应用程序状态）来优化 KV 缓存管理。

基于真实世界移动设备使用轨迹的评估表明了我们设计的有效性。与现有的 LoRA 服务框架相比，MobiLoRA 实现了 **18.1%~81.3%的性能提升**。

## 七、研究局限性

本文是对基于 LoRA 的大语言模型的 KV 缓存优化的初步尝试，旨在促进移动设备上更多自然语言处理任务的实现。我们认识到这一初步尝试存在其局限性和潜在问题。

- 首先，尽管 MobiLoRA 的设计不局限于特定的基础模型和适配器，但我们当前的实现并**未涉及不同的基础模型架构** 和**其他分布的 LoRA 适配器**。
- 其次，我们的**概念验证实现专注于特定的移动设备平台，且仅支持 GPU** 加速。而商用移动设备具有多样化的硬件配置，例如某些移动平台依赖于特定领域的加速器，如神经网络处理器（NPU，专门用于处理神经网络计算的硬件）。

> 我们发现，多加速器之间的协同推理能够进一步加速 LoRA 推理，这是未来值得探索的一个有前景的问题。
