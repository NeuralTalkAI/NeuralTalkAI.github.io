一、11 项核心发现总览

> 所有结论均满足“文档隐藏（H）”或“与文档矛盾（C）”的判定标准，其中 8 项为隐藏特性，3 项为矛盾描述，按类别归纳如下：

### 硬件调度与性能

1. **fp8（E4M3）`matmul2d` 为软件模拟**：吞吐最高为 fp16 的 0.94 倍，未达 1.5 倍硬件加速阈值，仅为内存占用优化特性。（H）
2. **无专用矩阵单元**：算子完全运行于 GPU 着色器核心，底层复用 simdgroup matrix 与 FP32 ALU 流水线，无独立矩阵数据通路，也无调度至 ANE 的证据。（H）
3. **累加器位宽 ≥ fp32**：内部累加精度不低于单精度浮点，文档未提及。（H）

### 张量布局与编程约束

1. **协作张量为 8×8 基础分片**：输入 A/B 与输出 C 共用统一的 8×8 平铺分片规则，单 SIMD 组内每线程持有分块内同列相邻两行元素，文档声明布局“不透明、设备专属”。（H）
2. **主机绑定张量需 128 字节对齐**：内层步长必须 128 字节对齐，对应 fp8/fp16/fp32 的收缩维度需分别为 128/64/32 的整数倍；该约束仅在头文件 SFINAE 注释中提示，文档未收录。（H）
3. **内联张量无法实现分块 GEMM**：`slice()` 接口仅做逻辑划分，不偏移实际读取地址，仅 (0,0) 分块计算正确。（H）
4. **设备张量仅支持主机绑定模式**：无裸指针构造函数，文档未说明。（H）
5. **张量功能受双重版本门控**：需同时满足 `HAVE_TENSOR` 宏与部署目标 ≥ 26.2，文档无相关说明。（H）

### 工具链与版本矛盾

1. **Metal 4.1 强制绑定 Xcode 27 + macOS 27.0**：与文档标注的“Xcode 26.1+ 可用”矛盾；4.1 版本二进制无法在 macOS 26.5 上加载。（C）
2. **4.1 低精度格式在 4.0 工具链不可用**：与功能表的版本支持描述冲突。（C）
3. **int2b、MXFP4 块缩放格式实际未实现**：文档功能表标注支持，但硬件不可用。（C）

## 二、实验方法：四重校验保障可信度

> RIGEL 采用 Objective-C++ 宿主层 + Python 校验层的分层设计，前者负责内存分配、内核调度与计时，后者负责正确性校验与溯源记录，所有数据需通过四重校验才会纳入统计。

1. **校验码正确性门控**采用与 GPU 完全一致的量化输入，:mdnice-bold-italic[在 float64 下计算参考真值，抵消输入量化误差，仅保留硬件累加带来的残差]。误差超过格式容忍阈值的测试单元直接标记无效并丢弃；配套独立 Python 脚本复核全部结果，50 组测试判定零偏差。
2. **全链路可溯源**每次测试自动记录配置哈希、代码提交版本、输入生成规则、随机种子、完整软硬件环境快照，缺失任意一项的记录均不纳入统计。论文所有图表均可通过 `make reproduce` 命令基于开源 CSV 数据复现，无需 GPU 设备。
3. **基准对照证伪机制**预设四组基准排除“性能提升来自循环优化而非专用硬件”的干扰：标量 ALU Roofline、朴素分块 GEMM、simdgroup matrix 指令、标准 fp16 MPP 通路。判定阈值提前设定：
4. **置信区间与时钟双峰现象**：每组测试预热后重复 300 次，输出中位数性能与 95% 自助置信区间。

![文章插图](/articles/2026-06-21-rigel-apple-m4-max-gpu-af82e08b/images/03.png)

::: image-caption
图 1 M4 Max GPU 时钟状态双峰分布。左图为 fp16 matmul2d 吞吐中位数与 95% 自助置信区间：512³ 规模下置信区间显著拓宽，1024³ 以上时钟稳定后区间收窄至近乎一条线。右图为 300 次重复测试的吞吐分布：512³ 呈现明显双簇分布（对应高低两个时钟档位），大尺寸矩阵则为单峰稳定状态。小规模矩阵运算耗时短，GPU 无法锁定高频性能档位，随机切换高低频形成两组吞吐量集群，单点测试数值完全不具备参考价值；2048³ 大矩阵运算时长充足，可稳定维持最高时钟，数据分布收敛单一。基于该现象，论文放弃单点吞吐量指标，强制采用中位数 + 自举 95% 置信区间的统计方案消除调频偏差。该硬件特性提示在小尺寸矩阵场景下性能测量存在显著随机性，为 Mac 端模型压测、性能标定提供了底层硬件层面的注意事项。
:::

- 小尺寸矩阵（512³）下 M4 GPU 时钟存在双峰分布：短内核运行于时钟爬升阶段，随机落入高低两个电源档位，吞吐分别约 4.65 与 6.5 TFLOP/s，置信区间宽度显著；
- 1024³ 以上规模时钟逐步稳定，2048³ 时稳定跑满最高主频，吞吐达 14.80 TFLOP/s，置信区间收窄至可忽略。单点中位数无法反映该特性，因此所有性能结论均附带置信区间。

## 三、算子调度路径：三重信号验证无专用矩阵单元

> `matmul2d` 的硬件执行目标是决定低精度加速能力的核心前提，本文通过三组独立信号交叉验证。

![文章插图](/articles/2026-06-21-rigel-apple-m4-max-gpu-af82e08b/images/04.png)

::: image-caption
图 2 matmul2d 调度目标实测信号。左图：fp16 分块 matmul2d 吞吐随矩阵尺寸变化曲线，峰值 14.8 TFLOP/s，仅为标量 ALU 理论算力的约 46%，全程未突破 ALU Roofline。本图和右图（下图）结合来看 simdgroup 矩阵对比实验、功耗采集完成 matmul2d 执行单元三角验证，敲定全文核心架构结论。具体来说，fp16 吞吐量始终低于通用 ALU 算力天花板，证明不存在独立专用矩阵计算核心；持续满载时 GPU 功耗拉满、硬件占用率达 100%；受系统测量限制无法直接读取 ANE 功耗，结合性能信号可间接排除张量算子卸载至神经网络引擎的可能性。M4 Max 属于 M5/A19 之前无 GPU 内置神经加速器的前代芯片，matmul2d 完全复用着色器 SIMD 矩阵通用管线，这也是 fp8 仅仿真、无硬件加速的底层根源。该结论推翻了社区流传的 “M4 Max 上 Metal 张量原语内置独立张量核心” 猜想，明确了这一代 GPU 的矩阵运算架构事实。
:::

### 信号 1：吞吐上限未突破 ALU Roofline

校验通过的 **fp16 分块 GEMM 在 2048³ 规模下峰值吞吐为 14.8 TFLOP/s，仅约为标量 ALU 理论 fp16 算力（~32 TFLOP/s）的 46%，** 全程未突破 ALU 算力天花板，证明不存在隐藏的高速矩阵数据通路。

### 信号 2：与 simdgroup matrix 性能高度接近

> 四组 GEMM 实现横向对比显示：

![文章插图](/articles/2026-06-21-rigel-apple-m4-max-gpu-af82e08b/images/05.png)

::: image-caption
图 4 四种 GEMM 实现的性能对比。MPP matmul2d 相对朴素分块 GEMM 有 2.9~5.5 倍性能提升，但相对传统 simdgroup matrix 指令仅领先 1.05~1.21 倍，二者性能高度接近，佐证 MPP 底层复用了 SIMD 矩阵计算流水线。本图横向对比四种矩阵乘实现方案，再次验证 MPP matmul2d 底层复用 simdgroup 矩阵管线的核心判断。MPP 张量原语针对显存分块、线程调度做上层封装，相比手写朴素 GEMM 大幅优化访存逻辑，性能提升显著；但与官方标注 “即将淘汰” 的 simdgroup 矩阵指令差距不足 21%，说明苹果文档推荐开发者全面迁移至 matmul2d 存在宣传夸大。同时 fp8 曲线持续垫底，与图 3 实验结论交叉印证，双重佐证低精度格式仅靠软件仿真运行。该图为 Mac GPU 内核开发者提供量化性能参考，权衡 simdgroup 矩阵与 MPP 张量 API 的取舍。

- MPP `matmul2d` 相对朴素分块 GEMM 性能提升 2.9~5.5 倍；
- 但相对 legacy simdgroup matrix 仅提升 1.05~1.21 倍。

二者性能差距极小，**符合“MPP 底层下沉至 simdgroup matrix 流水线”的推断，** 而非独立专用矩阵单元。

### 信号 3：功耗归因匹配 GPU 负载特征

> 满负载运行 `matmul2d` 时，GPU 硬件占用率达 100%，GPU 供电轨功耗约 42W。

受 macOS 27.0 beta 限制，CPU/ANE 功耗无法直接计量，**但结合性能信号可间接排除 ANE 调度：若算子卸载至 ANE，吞吐应显著高于纯 GPU 路径，而实测未出现该现象。**

::: block-1
综上，**M4 Max 上 `matmul2d` 完全执行于 GPU 着色器核心，复用通用 SIMD 矩阵与 ALU 流水线**，无专用矩阵硬件。
:::

## 四、fp8 加速性判定：纯软件模拟，无性能收益

> 控制变量对比 fp16 与 E4M3 fp8 分块 GEMM（布局、分块、执行域完全一致，结果均通过比特级校验）：:mdnice-bold-italic[512³ / 1024³ / 2048³ 规模下，fp8 吞吐分别为 fp16 的 0.871 / 0.927 / 0.941 倍，峰值仅 0.94 倍， 远低于 1.5 倍的硬件加速阈值。]

![文章插图](/articles/2026-06-21-rigel-apple-m4-max-gpu-af82e08b/images/06.png)

::: image-caption
图 3 fp8（E4M3）与 fp16 matmul2d 吞吐对比。全尺寸下 fp8 吞吐均低于 fp16，峰值仅为 fp16 的 0.94 倍，远低于预设的 1.5 倍硬件加速阈值，直接证实 M4 Max 上 fp8 矩阵乘法为纯软件模拟实现。fp8 单元素仅占用 1 字节，fp16 为 2 字节，若存在专用低精度数据通路，fp8 理应凭借更低内存读取量实现更高吞吐量，但实测全程落后于 fp16，证明矩阵运算属于计算密集型负载，fp8 解码、格式转换的额外开销完全抵消内存带宽优势。对比英伟达 Hopper 架构张量核心 fp8 吞吐量近乎翻倍的特性，论文明确 M4 Max 上低精度量化仅能缩减显存占用、扩大动态范围，无法提升推理速度，硬件加速能力需等待新一代 M5/A19 GPU 神经加速器，这一结论直接影响 Mac 端量化模型的部署优化策略。
:::

论证逻辑：fp8 单元素字节数仅为 fp16 的一半，若算子为访存瓶颈，fp8 理应更快；**实测 fp8 性能更低，说明 matmul2d 为计算瓶颈，fp8 需额外解包开销，无专用低精度计算通路。**

::: block-1
该结果与 M4 无神经网络加速器的硬件定位完全匹配，与 NVIDIA Hopper 架构 fp8 张量核心翻倍吞吐的特性形成鲜明对比。

对工程落地的指导意义：**M4 平台上 fp8 仅用于压缩模型显存、扩大动态范围，无法提升推理速度，加速能力需等待 M5 及后续搭载专用矩阵单元的芯片。**
:::

## 五、数值语义与隐藏编译约束

### 5.1 累加器精度验证

> 通过极限压力测试验证：收缩维度 K=128，由 1 个大数 448 与 127 个小数 0.0625 累加，精确和为 455.9375。

![文章插图](/articles/2026-06-21-rigel-apple-m4-max-gpu-af82e08b/images/07.png)

::: image-caption
图 5：数值计算语义特性。(a) 累加器位宽≥fp32：fp8 矩阵乘可精准还原高精度求和结果，顺序 fp16 累加会丢失微小数值产生显著误差。论文设计极端求和测试用例，验证 matmul2d 内部全程采用 fp32 精度累加，规避 fp16 累加丢失微小数值的精度缺陷，保障量化大模型、视觉模型推理数值稳定性，对齐英伟达张量核心统一 fp32 累加的行业设计规范。
:::

- 若以 fp16 累加，小数会因精度间隔丢失，结果停留在 448；
- 而 fp8 `matmul2d` 可输出精确结果，证明内部累加精度 ≥ fp32。

### 5.2 低精度格式行为

> fp8（E4M3/E5M2）、fp4（E2M1）的编码完全符合 OCP 标准，无自定义偏差。饱和特性存在差异：

![文章插图](/articles/2026-06-21-rigel-apple-m4-max-gpu-af82e08b/images/08.png)

::: image-caption
图 5：数值计算语义特性。(b) E4M3 数值饱和规则：E4M3 无无穷编码，溢出强制钳位至 ±448；E5M2 溢出会输出正负无穷。E4M3、E5M2 两类主流 fp8 格式饱和行为存在本质差异，E4M3 截断饱和、E5M2 保留无穷值，直接影响量化模型误差控制策略，是 M4 平台低精度模型精度调优不可缺少的底层参数依据。
:::

- E5M2：默认无饱和，溢出输出 ±∞；
- E4M3：无无穷编码，溢出强制钳位至 ±448，即使输入为 +∞ 也会被饱和。

### 5.3 128 字节对齐陷阱

主机绑定内联张量的内层步长必须 128 字节对齐，对应不同数据类型的收缩维度约束：fp8 需为 128 倍数，fp16 为 64 倍数，fp32 为 32 倍数。该约束仅通过头文件 SFINAE 隐式触发，编译报错为“无匹配构造函数”，极易误导开发者。

此外，官方文档建议全面从 simdgroup matrix 迁移至 MPP 张量，但实测 MPP 相对 simdgroup matrix 仅 5%~21% 的性能优势，小规模下几乎持平，文档指引存在夸大。

图 6 逆向还原的协作张量分片布局（单 SIMD 组，32×32 输出）。基础重复单元为 8×8 tile，在输出矩阵上平铺扩展；输入矩阵 A、B 与输出矩阵 C 共用完全一致的分片重排规则。本图逆向破解苹果文档标注 “设备私有、不对外公开” 的张量内存分片排布规则，是全文内核融合优化的核心底层依据。8×8 tile 是 GPU 调度张量计算的最小硬件单元，32 线程 SIMD 分组均分 tile 内元素，输入、输出张量统一采用相同重排逻辑。开发者可依托该布局设计寄存器驻留融合内核，消除矩阵计算后处理频繁读写显存的开销。论文基于该布局实现 GEMM+bias+GELU 寄存器内融合，获得 6.5%~12.9% 的端到端性能提升，证明掌握底层 tile 布局是实现算子融合、进一步挖掘 MPP 张量原语性能潜力的关键基础，补充了 Apple GPU 张量内存架构逆向工程的公开细节。
:::

- 基础单元为 8×8 分片，在输出矩阵上平铺扩展；
- 单 SIMD 组（32 线程）内，每线程持有每个 8×8 分块中同列的上下相邻两行元素；
- 输入矩阵 A、B 与输出矩阵 C 共用完全一致的分片重排规则。 该布局是实现布局感知内核优化的核心基础。

## 七、优化落地：后融合有效，注意力融合失效

基于上述硬件特性，本文验证了两类典型优化的收益。

### 寄存器内后处理融合（有效）

> 依托还原的分片布局，在协作张量寄存器内一次性融合 bias + GELU 激活，仅执行一次显存写入，对比“GEMM→bias→GELU”三段拆分调用：

![文章插图](/articles/2026-06-21-rigel-apple-m4-max-gpu-af82e08b/images/10.png)

::: image-caption
图 7 寄存器内后处理融合性能收益。融合 bias+GELU 双算子相对拆分调用，在 1024³ 规模下性能提升 12.9%，2048³ 规模下提升 6.5%，均超过 10% 的有效收益阈值；融合算子越多，缓存驻留场景的收益越显著。
:::

- 1024³ 规模性能提升 12.9%；
- 2048³ 规模性能提升 6.5%； 均突破 1.10 倍的收益阈值，适配 LLM 推理主流矩阵尺寸。 收益来源为规避了 O(n²) 量级的中间结果显存读写，因此缓存驻留场景收益最大，随矩阵规模增大、计算量占主导，收益逐步衰减。

### FlashAttention 融合（失效）

> 相同融合逻辑无法迁移至注意力计算：

![文章插图](/articles/2026-06-21-rigel-apple-m4-max-gpu-af82e08b/images/11.png)

::: image-caption
图 8 注意力算子融合性能对比。标量、矩阵单元适配、split-K 分块三类 FlashAttention 实现，性能均弱于拆分式 GEMM 注意力；根源是 M4 Max 统一内存带宽充足，S×S 中间矩阵的读写开销低于分块调度带来的额外开销。
:::

- 纯标量 FlashAttention 比分拆 GEMM 注意力慢 9 倍，根源是融合 softmax 迫使矩阵乘法脱离 SIMD 矩阵单元，降级为标量 ALU 计算；
- 适配矩阵单元、split-K 分块的优化版本虽逐步提速，但仍比分拆方案慢 3.6~5 倍。 核心原因：M4 Max 统一内存带宽充足，S×S 中间矩阵的读写开销极低；而 FlashAttention 的分块调度、屏障同步带来的开销超过了访存节省的收益。

::: block-1
结论：**协作张量融合仅对不脱离矩阵单元的轻量后处理算子有效**；若融合逻辑迫使算子离开矩阵通路，反而会显著劣化性能。
:::

## 八、局限性与开源说明

### 局限性

1. 测试仅覆盖单颗 M4 Max 芯片与 macOS 27.0 beta 系统，结论不推广至 M1~M3、M5 及 A 系列芯片，跨代特性需后续验证。
2. 受 beta 系统限制，ANE 功耗无法直接测量，“未调度至 ANE”为间接推导结论，需正式版系统进一步验证。
3. 实现的 FlashAttention 为学术原型，未做寄存器分块、多 SIMD 组调度等工业级优化，量产版本仍有优化空间。

### 开源与可复现性

全套微基准测试套件、Metal 内核代码、逐测试单元 CSV 数据、图表重绘脚本均以 MIT 协议开源，读者可通过 `make reproduce` 命令基于原始数据复现全文所有图表。

## 结语

> RIGEL 项目通过实证逆向的方式，补齐了 Metal 4.1 文档在硬件行为上的信息差：

**M4 Max 代际尚无专用矩阵加速单元，fp8 为软件模拟实现，张量算子依托着色器 SIMD 流水线运行**。还原的 8×8 分片布局与编译约束，为 Apple Silicon 平台的 ML 内核优化提供了底层硬件依据，而融合优化的正反案例，也为工程落地提供了明确的取舍方向。
