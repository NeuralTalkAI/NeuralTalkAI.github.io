## 一、引言

> 现代通用编译器框架使用与目标无关的中层类 RISC 中间表示（IR）作为通用且经过良好优化的后端输入。因此，针对 LLVM IR 的 C/C++、Fortran、Swift、Rust 等众多语言都能受益于共享的中层优化和成熟的 CPU 后端。

尽管基于 MLIR 的现代领域特定语言（DSL）编译器通过跨领域特定抽象渐进式 lowering，有效优化了机器学习（ML）中的深度神经网络（DNN）及其他领域，但它们通常以 LLVM 作为后端。

LLVM 确实能较好地针对 CPU，**但其以加载-存储/算术/分支为中心的 IR** （虽对单指令多数据（SIMD）操作有良好支持），**无法有效建模现代硬件的领域特定结构**。*英特尔在针对其 CPU 的优化 SIMD 时使用手写代码生成器[41]，相比 LLVM 后端提供了更多控制*。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/02.webp)

如图 1（左）所示，传统后端为 MLIR 等富含抽象的框架提供了狭窄的接口，这通常促使开发专家调优库以利用自定义加速器特性。**我们的多层后端（图 1 右）将特定于目标的抽象与渐进式 lowering 相结合**，为加速器代码生成提供了广泛的后端支持。

> 我们通过提出多层后端来**拓宽这一“沙漏”**，该后端接受、保留并利用领域特定信息以针对创新硬件。

我们的可扩展设计（图 1 右）不是使用单一的通用表示，而是公开了一系列静态单赋值（SSA）IR。

::: block-1
我们**将建模核心指令集架构（ISA）的基础 IR** （如 RISC-V）**与针对领域特定加速器扩展的结构化 IR 相结合**。我们通过跨 IR 抽象操作的多层寄存器分配器支持结构化控制流和非标准寄存器使用，并:mdnice-bold-italic[证明在“最佳努力”寄存器分配中常见的溢出对于峰值性能并非必需]。

通过从高层 DSL lowering，我们表明，:mdnice-bold-italic[宽后端允许将领域特定概念直接 lowering 到相应的硬件特性，与传统后端相比简化了代码生成]。
:::

我们将这一想法实现为 Snitch[80]的后端，Snitch 是一种可扩展的有序 RISC-V 内核，具有用于流寄存器和硬件循环的自定义扩展，并为 Snitch 生成高性能 DNN 内核。

我们的贡献包括：

::: block-1
- 以**一组基于 SSA 的 IR 对 RISC-V ISA 和 Snitch 加速器扩展进行底层表示** （第 3.1 和 3.2 节）。
- 用于结构化后端 IR 的多层无溢出寄存器分配器（第 3.3 节）。
- 从高层 DSL 渐进式 lowering 到上述基于 RISC-V SSA 的 IR（第 3.4 节）。
- 评估表明，**手写微内核实现了峰值性能** （高达 95%的浮点单元（FPU）利用率），而通过微内核编译器针对高层线性代数 DSL 生成的代码性能接近（高达 90%的 FPU 利用率）（第 4 节）。
:::

## 二、背景

我们描述:mdnice-bold-italic[支撑基于 SSA 的编译器的基础]、在:mdnice-bold-italic[基于 SSA 的 IR 中建模高层领域特定概念] 的进展，并介绍 Snitch[80]——这是一种具有**自定义 ISA 扩展的先进基于 RISC-V 的加速器**。我们在原型后端中利用这些概念，展示了针对 Snitch 的新型有效抽象 lowering 方法。

#### 2.1 带区域的静态单赋值

静态单赋值（SSA）中间表示（IR）广泛应用于现代研究和工业编译器（如 LLVM[52]、GCC[3]、Cranelift[1]、xDSL[14]），这得益于显式数据流信息带来的广泛认可的优势[22,28]。SSA 通过避免在每个代码位置*证明事实* （指 SSA 通过显式数据流信息减少了传统分析中对每个代码位置进行条件证明的繁琐过程），简化并改进了分析[22]。SSA 形式中的值与唯一名称相关联，每个值的使用都引用唯一的定义。我们使用 MLIR[53]中实现的 SSA IR。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/05.webp)

- 操作（operation）与它们的 SSA 值（即结果和操作数）一起概述计算（图 2，将程序抽象组织为基于 SSA 的 IR，为编译器构建实现了模块化方法。
- 上述 MLIR 中的向量-矩阵乘积使使用-定义关系显式化，并通过在正确抽象级别捕获信息如在 `linalg.generic` 中直接表达迭代类型，避免了复杂分析的需要）。
- 方言（dialect）为一组相关操作形成命名空间。操作以其方言名称作为前缀（如 `arith.addf`），并可能包含属性（编译时常量的键值映射）。
- 组织在块中的操作对应于直线代码（线性代码，即基本块[28]，指无分支、无循环的顺序执行代码块）。
- 块可以表示函数体或 `for` 循环，并可能以值作为参数。
- 区域（region）是与操作相关联的块列表。区域和块之间的复杂控制流由其父操作的语义定义。例如，`scf.for` 体现了典型的 `for` 循环，带有在整数范围内递增的归纳变量（图 2）。
- 将区域作为 IR 的一等元素与 SSA 结合，允许在 IR 中直接编码嵌套层次结构，而对用于表达程序的方言组合没有任何限制。

---

我们使用对常见编程抽象建模的现有方言，如函数（func）、结构化控制流（scf）和内存引用操作（memref）。例如，向量-矩阵乘积可以实现为这些方言的组合（图 2）。通过引用传递参数的函数表示为带有 `memref` 参数的 `func.func` 操作。

> 我们在这些抽象之上构建，并利用现有机器学习 DSL 来生成高性能线性代数微内核（第 4 节）。

#### 2.2 SSA 中的机器学习抽象

SSA 非常适合在 ML[16,55,59]和其他领域[19,38]的编译流中，用不同抽象级别的 IR 表达程序以进行优化。`linalg` 方言作为基于 SSA 的 IR，是高层面向 ML 的 IR（如 onnx、pytorch）的常见 lowering 目标[12,45]。

```
# linalg 方言通过高层抽象、SSA 形式和领域特定属性，成为连接深度学习框架与专用硬件的桥梁，其设计允许编译器在保留计算语义的同时，高效生成适配加速器（如 Snitch）的代码，是多层编译器后端的核心组件之一。特点1. 高层抽象与领域特定建模linalg 方言通过通用操作 `linalg.generic`捕获高层线性代数运算（如矩阵乘法、卷积），直接编码迭代空间、数据映射和计算逻辑，避免低层指令级抽象的信息丢失例：矩阵向量乘积可通过 linalg.generic 的iterator_types（并行 / 归约迭代类型）和indexing_maps（索引映射）显式定义 特点2. 保留领域特定属性操作包含编译时常量属性，如：2.1 迭代器类型（iterator_types）：指定循环类型（如 parallel 并行迭代、reduction 归约迭代）。2.2 索引映射（indexing_maps）：定义迭代空间与操作数数据的仿射关系，便于硬件适配 
```

该方言通过通用操作 `linalg.generic` 简洁地捕获高层线性代数计算，编码以下属性[58]：

::: block-1
1. 显式迭代器类型
2. 迭代空间和操作数数据之间的仿射映射
3. 完全由输入/输出操作数定义的迭代空间
4. 指定计算的 lambda（图 2）。
:::

**这些属性【很难】或【不可能】从低级编码中重建** [7,17,73]。

#### 2.3 RISC-V：可扩展的 ISA

> 随着技术挑战推动硬件设计走向**垂直专业化**，RISC-V **模块化**、**可扩展且免版税** 的指令集架构（ISA）在领域特定加速器中越来越受欢迎[42]。

- RISC-V ISA 定义了简单的加载-存储精简指令集计算机（RISC）架构[75]。
- 该 ISA 按逻辑相关指令的小组组织，**简化了硬件实现并支持组合**。
- **自定义扩展** 越来越多地被采用以**实现专用设计** [29,60,78]，例如从具有硬件屏障、缓存控制和自定义向量指令的多核云 CPU[4,15]到具有多精度打包 SIMD 指令的节能架构[34,63]。

硬件专业化的增加给传统编译器后端的高效代码生成带来了挑战。这是由于此类扩展的:mdnice-bold-italic[高层应用驱动语义] 与:mdnice-bold-italic[常见 IR 和后端数据结构] **难以表示之间的差距** 日益扩大[57]。

#### 2.4 Snitch 架构

Snitch[80]是苏黎世联邦理工学院开发的开源先进 RISC-V 核设计。它应用新颖的架构解决方案，在能源效率方面解决计算可扩展性挑战，*实现了比其他领先商业加速器高出一倍以上的每瓦性能*。它*已成功用作大型多核加速器的基本处理单元* （PE），如 Occamy[61]、Manticore[79]和异构 tiled 设计[2]。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/06.webp)

- Snitch 包含一个精简的有序整数核，为大型浮点单元（FPU）服务，能够执行多精度和（非标准）打包 SIMD 指令[34,67]。
- 整数核通过 sequencer 单元连接到浮点（FP）子系统，独立驱动 FPU 操作（图 3）。
- Snitch 还使用快速、节能且高吞吐量的紧耦合数据内存（TCDM）（128 KiB），充当软件管理的 L1 缓存。

> 其关键设计理念是通过**利用 FPU 核** 进行**大部分计算**，:mdnice-bold-italic[最大化面积和能源效率]。

两个自定义特性实现了最佳 FPU 利用率：

- **流语义寄存器（SSR，Stream Semantic Registers）**：在遵循仿射内存访问时隐式处理 FP 加载/存储[65]。
- **浮点重复（FREP）**：重复执行 FP 指令序列，无需循环控制流（条件、跳转、归纳变量）。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/07.webp)

SSR 在语义上类似于向量操作，消除了对 TCDM 的加载/存储需求（图 4：a-b）。使用 FREP 允许 FPU 执行指令而无需等待整数核提供指令，有效使架构成为伪双 issue（图 4：c）。:mdnice-bold-italic[SSR 和 FREP 可以高效处理密集线性代数操作，而无需过度特化。]

```
# 一些缩写的进一步解释## SSR（Stream Semantic Registers）即流语义寄存器。它在语义上类似于向量操作，能够隐式处理符合仿射内存访问的浮点加载 / 存储操作。这意味着在进行某些计算时，无需像传统方式那样执行显式的加载 / 存储指令来访问内存，而是可以像向量操作一样直接对寄存器进行读写，从而消除了对 TCDM 的加载 / 存储需求，提高了数据处理效率 。## TCDM（Tightly Coupled Data Memory）即紧耦合数据内存。是一种与处理器紧密相连的数据内存，Snitch 架构中，它作为软件管理的L1 缓存（大小为128 KiB ），能有效减少内存访问延迟。但有了 SSR 后，对它的加载 / 存储需求得以消除。## FREP（Floating-point Repetition）即浮点重复。它是一种硬件特性，允许重复执行 FP（浮点）指令序列。使用 FREP 时，FPU 执行指令无需等待整数核提供指令，能有效使架构成为伪双 issue，即可以在一个时钟周期内同时执行两条指令（这里是近似的双指令执行效果），提高了指令执行效率。## FPU（Floating-Point Unit）即浮点单元，是处理器中专门用于处理浮点运算的部件。在文本所描述的架构中，FPU 是重要的计算单元，而SSR 和 FREP 这两个特性都对提升 FPU 的运算效率起到关键作用 。
```

Snitch 的打包 SIMD 指令[33]早于并不同于 RISC-V P 扩展规范[10]中批准的指令。Snitch 寄存器分布在八个通道上，允许每个 64 位宽寄存器同时对八个 8 位、四个 16 位或两个 32 位值进行操作。

在传统编译器中实现 Snitch 扩展已被证明具有挑战性，因为其功能引入了隐式内存访问和迭代，需要从后端分析中重建代码保证[6,80]。

```
# 隐式内存访问（Implicit Memory Accesses）指 Snitch 架构中通过硬件特性（如流语义寄存器 SSR）自动处理内存读写，无需编译器生成显式的 Load/Store 指令。传统 RISC-V 需用fld指令加载浮点数据（图 4 左），而 Snitch 的 SSR 可隐式处理仿射访问模式，例如按固定步长读取连续内存，编译器无需生成对应的加载指令。But！问题在于！！！编译器需理解 SSR 的隐式访问逻辑（如访问地址的计算方式），但传统后端的 IR（如 LLVM）缺乏对这种隐式行为的建模，导致内存访问顺序和依赖关系【难以捕获】。# 隐式内存迭代（Implicit Iterations）指通过硬件循环 FREP 实现指令序列的重复执行，无需编译器生成显式的循环控制指令（如分支、归纳变量更新）。传统循环需用bnez指令判断循环结束（图 4 左），而 FREP通过硬件参数指定迭代次数，自动重复执行 FP 指令序列。But！问题在于！！！编译器需将高层循环结构映射到 FREP 的隐式迭代，但传统后端的控制流分析依赖显式的循环指令，【难以直接处理】这种硬件级的迭代抽象。
```

## 三、多层编译器后端

> 我们分四个步骤介绍多层编译器后端的架构（图 5）。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/08.webp)

我们引入对 RISC-V 汇编和更高层**特定于目标的概念建模的 MLIR 方言**，支持后端中的高层推理（第 3.1 节）。

- 然后讨论*如何通过附加方言表示 Snitch ISA 扩展*，自然地构建在基础 RISC-V 基础设施之上（第 3.2 节）。我们展示*在后端中维护结构化控制流如何允许更直接和可预测的寄存器分配* （第 3.3 节）。
- 最后，我们演示*从领域特定操作到多层编译器后端抽象的渐进式 lowering* 如何实现有效利用加速器能力的代码生成（第 3.4 节）。

### 3.1 基于 SSA 的 RISC-V ISA IR

> 我们的 RISC-V 后端在:mdnice-bold-italic[多个抽象级别表示特定于目标的概念]，在整个编译流中利用 MLIR 基础设施。

我们使用较低层的 `rv` 和 `rv_cf` 方言对汇编指令建模，并使用较高层的方言编码语义（如 `rv_scf` 中的结构化控制流和 rv_func 中的调用约定）（图 5）。**与单片后端相比**，我们的基础设施分为**易于推理和扩展** 的组件。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/09.webp)

我们使用 MLIR 的可扩展类型系统定义 `rv` 方言，将汇编指令表示为操作，其中源寄存器和目标寄存器分别对应操作数和结果（图 6：1）。一些操作（如 `rv.get_register`）不在汇编中打印；这些操作存在于 IR 中以创建 SSA 值，桥接 SSA 语义和我们在类型中对寄存器的表示（图 6：2）。`rv_cf` 方言中的操作通过跳转到 IR 中其他基本块的指令对非结构化控制流建模。汇编使用基于接口的设计打印，其中 IR 按顺序遍历，并根据每个操作的实现进行打印。我们的**低层程序表示允许编译器推理** （如控制流）和**转换**，同时**与目标汇编保持密切对应**。

更高层的 RISC-V 方言让我们保留更多对特定于目标的优化有用的语义信息。例如，`rv_func.func` 操作（图 6：3）编码应用二进制接口（ABI）约束，要求函数参数和结果在 A 寄存器中传递。类似地，`rv_scf.for` 操作以结构化方式表示 `for` 循环，简化了寄存器分配期间的优化和活跃范围构建。这些方言旨在镜像现有 `func` 和 `scf`，使**从更高抽象的 lowering 变得直接**。

### 3.2 表示 RISC-V ISA 扩展

> 与单片编译器后端不同，我们的模块化方法简化了新功能的添加。

我们通过遵循类似的多层方法来增强后端结构以支持 ISA 扩展，在 IR 中显式编码加速器语义和应用编程接口（API）。我们的高层操作让我们能够轻松优化和推理加速器使用。

我们在 `rv_snitch` 中对 Snitch 打包 SIMD 操作、流配置和浮点重复（FREP）循环（第 2.4 节）建模。流语义寄存器（SSR）为以前的纯算术操作添加内存效应，**使用与流寄存器显式交互的操作对其建模** （图 6：a），这种表示**让我们能够将数据访问的通用分析与下游处理的分析分离**。我们将打包 SIMD 指令类似地表示为标准 FP 指令，因为它们对标量 FP 寄存器操作。我们使用区域体和迭代计数操作数对 FREP 建模，并附带累积结果的机制（图 6：b），添加约束：循环体中仅允许 FP 寄存器和流操作的指令。我们定义 `snitch_stream.streaming_region` 操作来封装流配置和启用流的区域（图 6：c）。这些操作为更高层的编译器通道提供了方便的目标。

> 我们的模块化方法通过利用共享抽象和基础设施，使后端轻松扩展以针对具有自定义 ISA 扩展的加速器。

### 3.3 SSA 中带区域的寄存器分配

> 我们提出一种:mdnice-bold-italic[无溢出寄存器分配方法]，利用结构化控制流等信息（在我们的高层 RISC-V 和 Snitch IR 中显式编码）来推理值的活跃性。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/09.webp)

我们分三个线性通道分配寄存器。

- 第一通道从 RISC-V ABI 中指定为调用者保存的 15 个整数（a 和 t）和 20 个 FP 寄存器（fa 和 ft）中排除 IR 中已使用的所有寄存器（图 6：A）。通过排除已使用的寄存器，我们可以以通用方式处理部分分配的代码，即使寄存器的排除过于保守，因为预分配值的活跃范围的精确计算会增加设计的复杂性。
- 第二通道跟踪在引用区域外定义的变量，供以后处理循环时使用（图 6：B）。
- 最后通道反向遍历 IR 并原地分配值，在首次使用时分配寄存器，并在定义时释放（图 6：C）。SSA 形式保证线性遍历尊重使用-定义关系；此属性扩展到 MLIR 中带区域的 SSA，让我们能够在对其实现的单次遍历中分配整个函数体。

循环迭代结果在迭代前表示为操作数，在迭代期间表示为块参数，我们首先分配它们以确保其寄存器匹配（图 6：D）。然后我们分配第二通道中跟踪的变量，如上所述；循环体内使用但体外定义的值的活跃范围因可能多次执行循环而扩展到其范围之外。分配这些值后，我们使用反向遍历递归处理循环体。递归允许我们分配任意嵌套循环，并将循环和单块处理的逻辑分开。我们的循环处理方法是上述单块步骤的简单扩展。

Snitch ISA 扩展对寄存器分配施加了额外约束。Snitch 在流期间保留某些寄存器的使用，我们在相关操作定义中以声明方式表达（第 3.2 节）（图 6：E）。类似地，FREP 操作显式声明其循环结构，并以与 `rv_sc.for` 循环相同的方式处理。**分配器的通用设计减少了实现微内核编译器后端所需的工作。**

通用编译器后端中的寄存器分配通常在低级抽象的代码上执行，需要分析基本块图以重建活跃性和控制流[28,77]。当编译器的输入保证为线性代数 DSL 时，非结构化控制流的处理超出了范围。同样，寄存器溢出方案（当寄存器压力超过可用物理寄存器容量时采用）会因访问目标内存层次结构而导致性能损失。**我们检查多层寄存器分配器的寄存器使用情况，该分配器在一系列数据和形状大小上完全避免溢出，以确定其在生成高性能内核中的适用性** （表 2）。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/10.webp)

**对于双精度内核变体，寄存器压力是可管理的**，如有未分配寄存器的剩余。例如，在 Fill 内核中，我们使用两个 FP 寄存器（一个用于填充值，一个用于流输出）以及两个整数寄存器（一个用于缓冲区指针，另一个用于流配置）。保留的寄存器使 FP 和整数类型的使用量各为三个，因为填充值和缓冲区作为函数参数提供给内核。池化、卷积和矩阵乘法内核按因子四展开，并具有多维访问模式，增加了整数和 FP 寄存器的压力。**在双精度情况下，可用寄存器的余量允许处理更复杂的内核，同时避免溢出。**

**单精度变体的寄存器使用范围更高**。MatMulT 的 32 位变体是唯一对 FP 和整数类型均表现出高寄存器压力的内核。该内核使用 SIMD 操作计算输入矩阵行的偶数和奇数元素的点积，将它们求和，并将结果存储在相应偏移量处（第 3.2 节）。**与其他内核类似，为实现高 FPU 利用率，该内核按因子四展开**。

::: block-1
使用的 11 个 FP 寄存器是：

1. 4 个用于循环归约值
2. 4 个用于结果值
3. 1 个用于初始零值
4. 2 个用于流输入
:::

使用的整数寄存器要么是三个保留的函数参数、循环计算中使用的指针和偏移量，要么是其他临时值。尽管其复杂性，该内核不需要溢出。

::: block-1
在单精度和双精度内核中：

- FP 寄存器主要用于流寄存器、常量数据值和中间结果，
- 而整数寄存器用于缓冲区指针和循环记账。
:::

**我们为内核的函数参数和结果保留寄存器，这一选择简化了内核的实现，但增加了它们的寄存器压力** （第 3.3 节）。虽然排除用于函数参数和结果的寄存器的决定对于与我们选择的集合具有相似特征的内核不构成挑战，但对于具有更复杂功能（如更深循环嵌套）的内核可能成为问题。这一趋势得到我们对具有不同计算和内存访问模式复杂性的内核的分析支持（表 2）。缓解此约束的优化以及减少寄存器压力的其他转换，已计划用于未来工作。

### 3.4 针对高层后端抽象

> 我们的**编译器设计遵循的指导原则** 是：:mdnice-bold-italic[尽早利用我们对目标硬件的了解，并结合源中提供的信息]。

我们使用 `linalg.generic` 操作中内存访问和计算的解耦结构来针对 Snitch 的 N 维访问模式和 FREP 循环。我们设计**一种调度，能够通过就地重写微内核的高层表示，有效针对可用硬件资源，然后再 lowering 到控制流构造**。我们的方法将加速器硬件能力的表示推到传统编译器通常限制的抽象级别之上。

`memref_stream` 方言桥接 `linalg` 抽象和 `snitch_stream` 操作（图 7 如下）。`memref_stream.generic` 操作基于其 `linalg` 对应操作，除了迭代边界的显式编码，这与 `linalg` 通过输入形状推断边界的方法不同（第 2.2 节）。**这种解耦让我们能够对无形状的值（如流）上的函数建模**。`memref_stream.streaming_region` 是 `snitch_stream` 操作的高层对应物，对抽象算术值而不是 RISC-V 寄存器操作（第 3.2 节）。由于流配置固定了数据访问的顺序，我们必须在 lowering 时将数据访问与执行分离之前决定调度。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/11.webp)

Snitch 的有序核和软件管理的 L1 缓存使其性能可预测，允许我们构建简单的调度管道，无需昂贵的调度空间探索。为避免在内存中累积中间结果，避免在内存中累积中间结果，我们从迭代空间规范的结果中排除归约索引，引导我们的 lowering 过程使用局部值进行累积。通过应用循环展开合并（unroll-and-jam）避免读后写（RAW）冲突，该技术在最内层循环中交织多个迭代，用增加的代码大小和寄存器压力换取性能（图 7）。我们**根据流水线深度自动选择最佳展开因子**。对于 Snitch，FPU 对所有操作有三个阶段，因此当展开因子至少为四时，停顿最小化。这些转换固定了迭代空间，允许我们将流设置与计算分离，计算可 lowering 到 scf 循环，内部操作对流而不是内存操作。lowering 被构造为小的自包含通道，使其更容易 introspect、开发和维护，并让我们达到接近最佳的性能（第 4.4 节）。

```
# 上面这段内容比较抽象，主要表达意思如下：Snitch 的硬件特性让性能稳定→用简单调度省精力；计算时不存中间结果→用寄存器提速；循环展开合并→牺牲代码大小换性能；模块化解构→方便维护且性能好。这些操作环环相扣，最终让编译优化既高效又容易管理。关键内容如下：## 一、Snitch 架构的性能可预测性Snitch 的 “有序核”（按顺序执行指令，不重排）和 “软件管理的 L1 缓存”（程序员手动控制数据缓存）让它的性能表现稳定可预测。就像你按固定步骤做事不会出错一样，这种特性让我们能设计简单的任务调度流程，不用花大量精力去尝试各种复杂的调度方案（比如不用像拼图一样试很多组合找最优解）。## 二、避免中间结果存内存的技巧为了不让中间计算结果在内存里堆积（否则会拖慢速度），我们在设计计算流程时，会把 “归约索引”（比如循环里累加结果的变量）排除在内存存储之外。举个例子，比如算 1+2+3+4 时，不把每一步的和都存到内存，而是用寄存器临时存着，这样直接用 “局部值”（寄存器里的数据）累积结果，速度更快。## 三、循环展开合并（unroll-and-jam）优化1. 解决读后写冲突（RAW 冲突）：比如先读数据 A，修改后再写回 A，如果同时操作就会冲突。通过 “循环展开合并”，把最内层循环的多个迭代交叉执行（比如同时算第 1 步和第 2 步的部分操作），就像同时处理多个任务的不同步骤，减少等待时间。2. 代价与收益：这样做会让代码变多（展开后指令数增加），也会更占用寄存器（寄存器压力），但能换来更高的性能，就像多花钱买效率一样。3. 自动选最佳展开因子：根据流水线深度（Snitch 的 FPU每个操作分 3 个阶段），当展开因子（一次处理的迭代数）至少为 4 时，流水线停顿最少（就像流水线每 3 步处理 1 个任务，4 个任务能让流水线一直满负荷）。## 四、计算与数据流的分离设计通过上述优化，我们把迭代空间固定下来，让数据流动（流设置）和计算过程分开处理。计算部分可以转化为简单的循环（scf 循环），内部操作直接处理数据流（比如从寄存器读数据），而不是频繁读写内存。这种设计把流程拆成独立的小模块，像搭积木一样，方便检查、开发和维护，同时还能让性能接近最优状态。
```

不是丢弃 `linalg.generic` 操作的高层信息和约束，并必须从后端的循环表示中重建它们，我们将它们直接 lowering 到表示 Snitch 流体的自定义操作。

> 单个操作中访问和执行的解耦表示让我们能够确定性地构建适应 Snitch 能力的调度，减少为目标硬件生成高性能代码所需的工作。

## 四、评估

我们通过**提出三个研究问题**，评估我们的**多层后端是否支持有效的内核编译**：

::: block-1
- **RQ1**：我们的汇编级 RISC-V 方言是否足以表达针对峰值性能调优的神经网络微内核？
- **RQ2**：无溢出的多阶段寄存器分配方法是否适合生成此类微内核？
- **RQ3**：当从高层 DSL targeting 时，我们的后端是否仍能持续生成峰值性能的代码？

在概述我们的实验设置（第 4.1 节）后，我们的:mdnice-bold-italic[结果表明]：

- 在我们的**汇编级方言中表达的微内核** 可以**有效地编译** 到 Snitch 加速器（RQ1，第 4.2 节），达到高达 **95%的峰值性能**；
- 我们的**多阶段寄存器分配方法始终无溢出** （RQ2，第 4.3 节）；
- 并且我们的后端可以**有效地从高层 DSL targeting** （RQ3，第 4.4 节），**获得 90%的 FPU 利用率**。

### 4.1 实验设置

我们将具有代表性的神经网络（NN）微内核编译到 Snitch——一种先进的基于 RISC-V 的加速器，并与现有编译流进行比较。我们现在详细说明我们的内核、输入、仿真基础设施、方法、编译流和其他使用的软件。

:mdnice-bold-italic[内核]：我们从两个 DNN 中获取微内核：NSNet2[23]（一种噪声抑制模型）和 AlexNet[50]（一种图像分类模型）。这两个网络代表了近期和经典的 NN 架构。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/12.webp)我们手动实现这些两个网络使用的内核（如表 1，我们在各种输入形状上，对具有代表性的 DNN 微内核，按计算和内存访问特征分组，进而评估我们的多层编译器。FLOPs 表示每次计算所需的最小周期数），不包括 Softmax 和 Sigmoid，因为它们依赖指数和对数函数，其实现超出了本文的范围。我们选择的内核包括元素级计算、线性和非线性内存访问、归约和嵌套循环，涵盖了广泛的特性。

:mdnice-bold-italic[输入]：我们**选择形状大小以适应 TCDM** （第 2.4 节），使得我们的**性能测量不受内存层次结构其余部分的影响**。具有归约的内核（如 MatMul）包括两个 `linalg` 操作：

1. 将输出缓冲区归零（使用 `linalg.fill`）
2. 执行计算。

在实验中，我们评估一系列大小，以提供关于计算开销的详细信息。

:mdnice-bold-italic[仿真目标]：作为先进的基于 RISC-V 的加速器，我们选择 Snitch[80]，它构成了首批基于芯片 let 的研究架构之一的核心[11]（第 2.4 节）。我们使用 Verilator[13]编译 Snitch 的开源参考 SystemVerilog 实现，以生成寄存器传输级（RTL）周期精确仿真器。根据 Snitch 微架构，FPU 每个周期可执行一条指令（峰值），或在操作 64 位值时，每个周期执行两个浮点操作（FLOPs）（在融合乘加（FMA）指令的情况下）。对于较小的类型，可以执行相应数量的向量操作。作为没有运行时或操作系统的有序裸机平台，Snitch 平台上的所有测量都是确定性的。

:mdnice-bold-italic[方法]：:mdnice-bold-italic[为了获得准确的性能数据，我们测量内核的周期数、吞吐量和 FPU 利用率，利用 Snitch 的性能计数器，并结合 Verilator 基础设施提供的指令跟踪后处理]。我们对每个内核的周期数测量包括函数调用开销、整数算术指令、显式加载/存储指令和加速器设置。

- 我们**将每个内核的 FLOPs 计算为：i）循环迭代次数，和 ii）循环体中执行的 FLOPs 的乘积**。
- 我们将吞吐量定义为内核执行期间**每周期的 FLOPs 数**。

> 结合理论最大吞吐量，内核 FLOP 数可用于估计执行计算所需的最小周期数。我们将 FMA（fmadd）指令计为两个 FLOPs，并为使用它的内核调整我们的最小周期估计。

:mdnice-bold-italic[FPU 利用率表示为 FPU 执行算术指令的周期数与总执行延迟的比率]。这三个指标评估内核执行速度和可用计算资源的有效利用。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/13.webp)

:mdnice-bold-italic[编译流]：通用编译器（如 LLVM）可以 target RISC-V ISA，生成可在 Snitch 上执行的代码。我们使用两种替代编译流（图 8），均利用 LLVM RISC-V 后端：

1. 使用现有 MLIR 通道的流水线，lowering 与我们的原型编译器相同的输入（标记为“MLIR”）
2. 相同内核的朴素 C 重新实现（标记为“Clang”）。

由于没有现有编译器 target Snitch ISA 扩展，这些流仅用于额外讨论，而非直接比较的基线。

:mdnice-bold-italic[软件]：我们利用 MLIR 丰富的编译器组件和工具生态系统。我们的后端在 xDSL 开源编译器框架（v0.21.1）[14,31]中实现，xDSL 是 MLIR 的 Python 对应物，支持核心 MLIR 构造（即 SSA、区域）在语言内的原生集成。**xDSL 和 MLIR（v16.0.6）之间的互操作性通过通用文本 IR 格式实现**。对于 C 实现，我们使用 Snitch 架构师提供的 LLVM 工具链[6]，其中包含我们所有内核实现中使用的汇编器和链接器。利用行业中流行的现有工具，便于我们的工作在研究和生产中的采用。

### 4.2 低层微内核表示

为了评估我们的 RISC-V 方言的表达能力，我们分析了选定的微内核（图 9），这些微内核以 RISC-V 方言（第 3.1 节）和编码 Snitch ISA 扩展的方言（第 3.2 节）的组合编写，以部分寄存器分配的形式表示。我们的**测量表明，所有选定的内核都实现了有效的 FPU 使用。**

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/14.webp)

我们在 32 位 FP 数据上表达 Sum、ReLU 和 MatMulT 内核，使用 snitch_stream、rv_snitch 和结构化 rv 方言，并使用我们的后端代码生成通道 lowering 到汇编。

::: block-1
- **Sum 和 ReLU 内核表现出相似的性能行为**，达到 **95%的 FPU 利用率**。这些内核是对一个或两个操作数的元素级操作，没有归约，以线性方式操作，导致加速器设置的最小和恒定开销，以及更简单的控制流结构，达到接近 100%的 FPU 利用率。周期数开销与大小无关，保持恒定（图 9 底部），表明在 Snitch 集群的内存约束下，**随着大小增加，内核的性能将趋向于理论上限的 100%。**
- MatMulT 内核达到 **74%的 FPU 利用率**，但仅获得 2.45 FLOPs/周期的吞吐量。

所有三个内核的性能与我们的最佳努力优化的手写汇编版本匹配。我们认为，鉴于 Snitch ISA 中可用的扩展，:mdnice-bold-italic[我们的内核低层表示已接近最优]。
:::

我们的低层抽象使我们能够表达所有选定的内核，没有构成任何固有障碍，不需要规避或用外部特性补充，同时在我们的目标上实现高性能。

### 4.3 微内核的无溢出寄存器分配

片上加速器资源的稀缺使实现高利用率变得复杂，寄存器是一个普遍的约束。**一旦寄存器压力超过可用物理寄存器容量**，就会采用寄存器溢出方案**，导致从目标内存层次结构访问的性能损失**。我们检查我们的多层寄存器分配器的寄存器使用情况，该分配器:mdnice-bold-italic[在一系列数据和形状大小上完全避免溢出]，以确定其在生成高性能内核中的适用性（表 2）。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/15.webp)

**对于双精度内核变体，寄存器压力是可管理的**，有未分配寄存器的剩余。例如，在 Fill 内核中，我们使用两个 FP 寄存器（一个用于填充值，一个用于流输出）以及两个整数寄存器（一个用于缓冲区指针，另一个用于流配置）。保留的寄存器使 FP 和整数类型的使用量各为三个，因为填充值和缓冲区作为函数参数提供给内核。池化、卷积和矩阵乘法内核按因子四展开，并具有多维访问模式，增加了整数和 FP 寄存器的压力。在双精度情况下，可用寄存器的余量允许处理更复杂的内核，同时避免溢出。

**单精度变体的寄存器使用范围更高**。MatMulT 的 32 位变体是唯一对 FP 和整数类型均表现出高寄存器压力的内核。该内核使用 SIMD 操作计算输入矩阵行的偶数和奇数元素的点积，将它们求和，并将结果存储在相应偏移量处（第 3.2 节）。与其他内核类似，为实现高 FPU 利用率，该内核按因子四展开。使用的 11 个 FP 寄存器是：i）4 个用于循环归约值，ii）4 个用于结果值，iii）1 个用于初始零值，iv）2 个用于流输入。使用的整数寄存器要么是三个保留的函数参数、循环计算中使用的指针和偏移量，要么是其他临时值。尽管其复杂性，该内核不需要溢出。

在单精度和双精度内核中，FP 寄存器主要用于流寄存器、常量数据值和中间结果，而整数寄存器用于缓冲区指针和循环记账。**我们为内核的函数参数和结果保留寄存器，这一选择简化了内核的实现，但增加了它们的寄存器压力** （第 3.3 节）。虽然排除用于函数参数和结果的寄存器的决定对于与我们选择的集合具有相似特征的内核不构成挑战，但对于具有更复杂功能（如更深循环嵌套）的内核可能成为问题。这一趋势得到我们对具有不同计算和内存访问模式复杂性的内核的分析支持（表 2）。缓解此约束的优化以及减少寄存器压力的其他转换，已计划用于未来工作。

> 我们的测量支持我们的主张，即无溢出寄存器分配非常适合线性代数微内核。

### 4.4 原型微内核编译器

我们评估我们的多层编译方法从高层抽象生成目标优化的高效内核的能力。**我们将我们的编译器生成的代码（第 3.4 节）的性能与使用 MLIR 编译的代码和用 Clang 编译的朴素 C 实现进行比较** （第 4.1 节）。与第 4.2 节一样，:mdnice-bold-italic[目标是最小化内核执行时间并最大化 FPU 利用率。]

MLIR 和 Clang 编译流不会生成有效利用硬件能力的代码。在我们的测量中，它们具有相似的性能，峰值利用率约为 42%（图 10）。这两个流共享 LLVM RISC-V 后端，该后端不适应有序 Snitch CPU 的特性或其 ISA 扩展。这导致两个编译流生成的汇编中出现次优模式，如显式加载/存储和 RAW 冒险，因此性能低下。由于 LLVM 后端对一些循环的展开和加载的重新调度以最小化延迟，Max Pool 受益最大，但仍低于 50%的 FPU 利用率。

> 关键见解是，即使使用高层领域特定的 MLIR 优化，LLVM IR 和后端也决定并最终限制了微内核的性能。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/16.webp)

另一方面，**我们的方法即使对于较小的内核大小也实现了高利用率，并达到高达 90%（图 10），与加速器设置开销无关**。

::: block-1
- 对于并行内核（Sum、Fill 和 ReLU），FPU 利用率随着输入大小的增加而增加，接近 100%。
- 对于归约内核（Conv、Max Pool 和 Sum Pool），当输入宽度变化时，FPU 利用率增加，但速度较慢，保持在 70-80%之间。我们所有的内核都被转换为一次处理四个归约，当 N=4 时，导致 90%利用率的异常值，因为（现在单迭代）最外层循环被展开，消除了循环开销，并减少了加速器设置中的维度数量。
- 其余内核的行为与它们的并行对应物类似，随着内核宽度的增加，利用率稳步增加。
:::

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/17.webp)

我们对 MatMul 内核进行了额外测量，以检查其在更广泛输入形状范围内的性能（图 11）。对于内维度或第二操作数列的最小大小，加速器设置成本主导运行时，导致吞吐量相对较低，从未达到理论峰值的 80%以上。与其他内核一样，较大的输入形状导致更高的吞吐量，因为设置和函数调用的恒定开销被计算的运行时所抵消。同样，随着任一输入大小的增大，吞吐量的增长速度较慢。当在 Snitch 核心之间分配更大的工作负载时，调用我们编译器的高层工具应考虑这些趋势。

![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/18.webp)

为了理解我们流水线中每个高层和低层优化的影响，我们在 MatMul 内核上增量应用它们（表 3）。该内核由两个 `linalg.generic` 操作组成：第一个将输出初始化为零，第二个计算矩阵乘法。这些操作共同构成一个非累积内核，这是大多数 MLIR DNN 前端使用的形式。基线流水线表示直接 lowering，没有调度优化，target 标准 RISC-V ISA。**由此产生的 FPU 占用率低于 3%，与完整流水线相比，速度慢约 36 倍。**

**“Streams”优化启用 Snitch SSR 的使用，导致周期数减少 50%。** 同时，发出的显式加载和存储数量减少 66%，但性能仍然较低。添加“Scalar Replacement”通过进一步减少显式加载和存储，带来了超过 4 倍的额外性能提升，因为内核不再直接将结果累积到内存中。在此阶段启用“FRep”仅导致总周期数的边际改善，因为运行时主要由最内层循环中的点积计算主导，而不是循环设置开销。

> 所有剩余优化影响执行调度，强调了流水线中早期目标感知调度的重要性。

通过融合（Fuse Fill）**将结果矩阵的初始归零操作融合到矩阵乘法操作中，我们进一步减少了指令数量**。在具有大内维度的矩阵乘法情况下，计算主导填充结果所需的时间，因此性能提升最小。更重要的是，在用零融合初始化后，我们能够忽略矩阵乘法结果缓冲区的先前内容，消除剩余的加载和存储。在此阶段，限制因素是内核归约维度中的跨迭代 RAW 依赖关系。展开合并（Unroll-and-Jam）（第 3.4 节）通过一次交织计算结果的五个元素，消除了由于 FPU 流水线停顿而浪费的周期。

我们还考虑了我们的**优化通道对寄存器使用的影响**。这些通道中的**每一个都简化了计算的控制流或内存访问，从而减少了使用的寄存器数量**。然而，“Fuse Fill”增加了 FP 寄存器的使用，因为需要两个额外的变量来存储初始标量值和执行累积。在“Unroll-and-Jam”之后，由于额外的交织计算，寄存器压力增加到八个 FP 寄存器。如第 3.3 节所述，选**择较小的展开因子可以缓解增加的寄存器压力。**

当使用我们的编译器编译:mdnice-bold-italic[线性代数微内核时，高层和低层通道的组合产生了接近最佳的性能]，在我们的内核中实现了 **73%-90%的 FPU 利用率**。

> 我们展示了我们利用 `linalg.generic` 携带的高层语义来有效 target 自定义 ISA 扩展（如 SSR 和 FREP）的能力。

## 五、讨论

通过在 MLIR 框架内对特定于加速器的后端进行建模，我们接受并实现了其核心概念和原则[53]（见表 4，我们针对 Snitch 的多层编译器后端展示了核心概念在实现通用 ISA 和加速器开发方面的多功能性）。![文章插图](/articles/2025-07-05-gemm-95-fpu-mlir-risc-6170665b/images/19.webp)

我们使用遵循 SSA 形式的操作对标准目标 ISA 及其扩展的语义进行编码，并使用区域来限定代码范围，避免了汇编语言通常的**平面表示**。

```
# 平面表示指的是指令的线性排列。汇编语言中的指令按执行顺序线性排列，缺乏对代码逻辑的层次化抽象。例如：addi x1, x0, 1    ; 指令1addi x2, x1, 2    ; 指令2beq x1, x2, label ; 指令3（分支跳转）所有指令在同一层级，控制流（如分支）通过显式标签（label）跳转实现，未对循环、函数等逻辑单元进行封装。因而，平面表示不区分代码块的语义角色（如循环体、条件分支），仅按物理顺序组织指令
```

在代码生成方面，我们:mdnice-bold-italic[应用渐进式 lowering 方法来针对自定义加速器特性]，在增量步骤中调整高层领域特定信息，同时遵循其语义。

以这种方式遍历抽象级别还使我们能够:mdnice-bold-italic[逐步处理典型的编译器后端任务]，如寄存器分配。我们**希望我们的工作将启发** 并帮助塑造在**工业级编译器后端中使用结构化领域特定信息** 来**支持自定义加速器** 的未来路径。

## 六、相关工作

我们建立在领域特定编译、高性能计算中的优化技术以及基于 SSA 的 IR 上的寄存器分配的最新进展之上。

### 编译器

针对通用 CPU 的编译器通常采用三层设计，以解耦实现问题并独立处理问题（如后端中的指令选择和寄存器分配），随着复杂性的增加，这导致了很大程度上的单片编译器层。

> 增强可组合性和模块化的努力（例如在多面体编译器中将循环执行调度与算法分离[18,37]）在很大程度上未能渗透到主流编译器后端。

- 更**接近我们工作** 的是另一个**基于 DSL[43]的微内核编译器** [24]，它仅专注于矩阵乘法，并且需要用户输入来执行调度、数据传输和转换。
- MoNaCo 是一个 MLIR 代码生成器[68]，它强调 x86-64 ISA 的即时（JIT）编译速度，但对高层抽象的支持有限，仅将低层方言直接映射到特定指令，同时避免对 LLVM 后端的任何依赖。**我们的 lowering 流水线是自动的，并且对广泛的线性代数操作起作用。**

MLIR 生态系统中的一些方法旨在生成考虑**目标微架构的高效代码**，但最终**重用现有的通用编译器后端**。

- 一个案例研究[20]在 MLIR 中执行高层循环转换，以匹配已知对生成基本线性代数子程序（BLAS）实现有效的优化。一种类似的方法[51]通过 LLVM IR 内置类型采用端到端的 C/C++编译流。
- 另一种技术[72]为基于 ARM 的微架构生成优化的 BLAS 内核，专注于向量方言内转换的基于概要的探索。一个 GPU 代码生成流水线[46]摄入高层方言，并为 NVIDIA GPU 张量核心生成矩阵乘法内核的 LLVM IR。

:mdnice-bold-italic[据我们所知，我们的工作是第一个基于 MLIR 的编译器后端]，它捕获特定于加速器的抽象并采用自包含的代码生成方案。

### 库

线性代数和其他领域的专家调优代码通常在库中提供，如 oneMKL[9]、cuDNN[27]和其他库[36,71]，通常遵循通用接口（如 BLAS[30]）。这些库提供有限的灵活性，使用内核模板、提前（AOT）或 JIT 编译，以基于目标信息（如缓存大小）生成定制的库代码[5,41,71]。

**LIBXSMM** [41]通过**将跨各种抽象级别** 的众多决策**嵌入其代码生成策略** 中，将这种方法**发挥到了极致**。我们恢复了编译器作为灵活表达低层特定于目标的抽象以生成高度优化代码的手段。

### DSLs

近年来，受 Halide[64]等方法的启发，开发了大量特定于应用的语言和随附的支持工具，以暴露和控制计算的各个方面（如调度、内存放置等）[18,25,40,43,47,64,66,73,81]。这一趋势还导致采用自动调优和分析框架来探索配置选项[26,54,69,70]。

Triton-C[69]用张量操作功能扩展 C，并内置自动调优器，对预定义的用户不透明的微内核进行操作。:mdnice-bold-italic[不可避免的是，这些 DSL 重新实现了紧密耦合的编译器基础设施] [48,69]，**依赖** 通用后端进行代码生成[43]，**或需要外部工具** 进行互操作[35]。

> 将我们的方法嵌入 MLIR 使我们能够利用开放、通用和可重用的基础设施，同时在正确的抽象级别封装领域和特定于目标的概念。

### 解耦访问-执行

先前关于将数据传输与计算解耦的工作已将最佳努力的手动[49]和基于编译器的转换[44,74]与 CPU 频率缩放结合使用，以实现不同的能量和性能目标。我们的工作保证了访问与执行的分离，这在 Snitch ISA 扩展中表达，是 lowering 高层操作的结果，无需用户指定的调度。

### 寄存器分配

我们的方法扩展并适应了现有关于 SSA 形式寄存器分配的研究[21,39,62,76]，通过将重点从整个程序的基本块和 ϕ 函数转移到微内核的结构化控制流区域，以支持最大化硬件利用率。

## 七、结论

> 现代通用编译器的“沙漏”设计中前端和后端的严格分离，导致了高层代码抽象和目标新颖硬件特性之间的信息瓶颈。

为了实现峰值性能，专家们经常绕过编译器，使用手工调优的内核，这构成了用户和自动分析无法理解的概念黑盒。随着现代硅技术中的制造挑战推动专用硬件的激增，手工调优内核的成本和工作量更加突出。

在这项工作中，我们:mdnice-bold-italic[重新思考了编译器后端结构]，利用**基于多层 SSA 的 IR 的结构化、抽象驱动策略**。我们基于 MLIR 的原型展示了一种渐进式方法，用于创建模块化和表达性的编译器后端，将领域知识与硬件能力相结合。

我们为 RISC-V 目标和 Snitch ISA 扩展生成汇编，在代表性的 ML 内核上实现了 **90%的 FPU 利用率**。我们的贡献包括作为多层基于 SSA 的 IR 的 RISC-V ISA 编码、多层编译器后端、定制寄存器分配器，以及用于高性能线性代数微内核的代码生成方法。
