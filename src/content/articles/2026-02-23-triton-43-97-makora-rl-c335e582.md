关键词：**GPU 内核生成**、:mdnice-bold-italic[强化学习]、**Triton**、代码优化、Makora

> 2025 年，全球数据中心部署的 GPU 数量已突破千万级别。这些并行计算巨兽支撑着从大模型训练到实时推理的各类 AI 应用，成为整个 AI 基础设施的算力基石。然而，有一个尴尬的事实始终存在：**真正能把 GPU 性能榨干的人，寥寥无几**。

编写高效的 GPU 内核（Kernel）——即在 GPU 上运行的核心计算函数——需要开发者精通硬件架构：理解共享内存与全局内存的层次、掌握线程调度与同步、优化指令级并行、妥善处理数据搬运……这些技能通常只集中在少数专家手中，而大部分高性能内核都是闭源的，普通开发者只能依赖编译器（如 PyTorch 的 TorchInductor、XLA 等）自动生成。但像是 Torch Inductor、XLA **这类编译器，其优化受限于内置的启发式规则，往往无法达到手写调优的水平。**

大语言模型（LLM）在通用代码生成上已经展现出了惊人的能力如 GitHub Copilot，那么能否让 LLM 自动生成高性能 GPU 内核呢？答案并不简单。GPU 内核生成面临着四大挑战：

| 问题类别 | 描述 | 关键挑战 |
| --- | --- | --- |
| **数据稀缺** | 高质量手写内核多为商业机密，公开数据极少；Python 通用代码达上亿样本，GPU 内核数据集仅一两万。 | 样本量严重不足，难以支撑深度模型训练。 |
| **编译器数据的局限性** | 编译器生成的合成代码存在性能天花板、大量内部库调用、可读性差等问题。 | 模型无法习得真实人工优化技巧，泛化能力弱。 |
| **仅正确远远不够** | 功能正确的内核可能比优化版本慢数个数量级；优化策略高度依赖硬件（如 Hopper 与 Blackwell 架构表现差异巨大）。 | 正确性 ≠ 高性能，硬件耦合性强，跨平台迁移困难。 |
| **优化空间指数爆炸** | 涉及分块策略、内存布局、向量化模式等大量离散决策，组合空间近乎不可穷举。 | 搜索与建模难度极高，传统方法难以系统化覆盖。 |

::: block-1
面对这些困难，传统的**监督微调（SFT）** 显得力不从心——它需要大量高质量标注数据，而这正是 GPU 领域所缺乏的。于是，一个替代思路浮出水面：**强化学习（RL）**。:mdnice-bold-italic[模型通过执行代码并获得反馈——编译是否成功、运行是否快速，从而实现自我改进]，不依赖于大规模标注数据。
:::

## 一、相关工作：从通用代码生成到 GPU 内核优化

> 大语言模型在代码生成领域的成功已无需赘述。从 OpenAI 的 Codex 到 DeepMind 的 AlphaCode，模型能够根据自然语言描述生成可执行的代码。然而，当任务从“写一个排序函数”变为“写一个针对特定 GPU 的 FlashAttention 内核”时，复杂度急剧上升。

近年来，专门针对 GPU 内核生成的探索开始涌现：

| 工作名称 | 简要描述 |
| --- | --- |
| **KernelBench & KernelBook** | 提供 GPU 内核生成的基准数据集与示例库；KernelBench 包含 264 个 PyTorch 参考问题，覆盖矩阵乘、卷积、规约等典型模式。 |
| **EvoEngineer** （Guo et al., 2025） | 基于 LLM 引导的演化算法，将 CUDA 内核优化建模为策略遍历任务，自动探索优化空间。 |
| **CUDA-LLM** （Chen et al., 2025） | 引入迭代优化循环，每轮利用上一轮执行反馈（如性能、编译结果）改进 CUDA 代码生成。 |
| **Kevin** （Baronio et al., 2025） | 采用多轮强化学习框架，微调 QwQ-32B 模型生成 CUDA 内核，通过对话式交互持续提升正确性与性能。 |
| **Astra** （Wei et al., 2025） | 首个多智能体 LLM 系统，由多个专业化智能体协同完成内核生成、编译测试、性能分析与迭代优化。 |

这些工作大多聚焦于 CUDA，而 Makora 选择了**Triton** ——一种更易于编写和编译的 GPU 编程语言，由 OpenAI 开发，已被 PyTorch 原生支持。Triton 抽象了部分硬件细节，让开发者可以聚焦于算法逻辑，但仍有大量优化空间。

::: block-1
Makora 的创新之处在于，它不仅用强化学习微调了当前最强模型 GPT-5，还构建了一整套支持工具、防作弊机制和可扩展评估基础设施，使得 RL 训练在 GPU 内核生成领域真正落地。
:::

## 二、核心创新：为什么 RLVR 比 SFT 更适合 GPU 内核生成？

> Makora 采用的强化学习范式是**基于可验证奖励的强化学习（RLVR）**。这与传统的 RLHF（基于人类反馈的强化学习）不同：RLVR 的奖励来自于客观、可验证的规则，如编译成功、运行正确、速度快慢，而不是容易主观和作弊的奖励模型。

对于 GPU 内核生成，RLVR 的优势是天然的：

- **正确性可验证**：编译和测试可以明确判断内核是否正确。
- **性能可量化**：基准测试可以给出精确的速度数据。
- **无需人工标注**：只要有一个参考实现如 PyTorch 版本，就可以自动生成训练信号。

相比之下，SFT 需要大量人工标注的高质量内核，这在现实中几乎不可能。而且，编译器生成的合成数据会限制模型的上限——模型永远学不会超越编译器的优化技巧。RLVR 则允许模型在优化空间中自由探索，通过试错发现更优的解决方案。

::: block-1
Makora 的作者指出，**RLVR 成功的前提是基础模型已经具备基本能力**：如果模型连 Triton 语法都不懂，生成的代码全是编译错误，那 RL 将得不到任何学习信号（奖励全为零）。因此他们选择了 GPT-5——一个已经具备较强编程能力和 GPU 概念理解的模型。实验也表明，较小的模型（如 Qwen 系列）在 RL 训练中很快陷入平台期，无法持续改进。
:::

### 3.1 数据集构建：质量胜过数量

> 高质量的训练数据是 RL 成功的关键。Makora 的数据集构建流程如图 2 所示，经过了多道精细筛选。

![文章插图](/articles/2026-02-23-triton-43-97-makora-rl-c335e582/images/04.webp)

::: image-caption
图 2 | 数据集处理流程。从公开 PyTorch 代码开始，经过去重、难度分级、形状多样化、运行时测量和过滤，最终得到高质量的 RL 训练样本。该流程为强化学习微调打造了高质量的 GPU 内核生成训练集，先从 GitHub 爬取 PyTorch 示例并与 KernelBench 做数据划分，再经去重、去污染、形状多样化等预处理，结合 LLM 难度评级完成数据筛选。最终通过聚类感知的加权采样，得到 100 和 1000 样本的训练子集，保证了数据的多样性与难度适配性。
:::

主要步骤包括：

- **去重**：首先用 Jina 嵌入模型计算语义相似度，移除与测试集（KernelBench）距离过近的样本（阈值 τ=0.45）。然后进行语法级 Jaccard 相似度去重，移除相似度高于 0.8 的样本，确保训练集与测试集无重叠。
- **难度分级**：使用 LLM 作为法官，将问题分为 L0（琐碎）到 L5（专家级）六个等级。分级标准包括算法复杂性、优化空间、硬件考量等。最终只保留难度 ≥L2 的问题，避免模型在太简单的问题上浪费训练资源。
- **形状多样化**：原始代码中的张量形状往往过于简单（如固定小尺寸），无法体现真实计算压力。Makora 利用 LLM 为每个问题生成多种合理的形状，使训练数据更贴近实际应用。
- **运行时测量**：在 H100 GPU 上运行参考 PyTorch 实现，测量其基线执行时间。过滤掉执行时间小于 1ms 或大于 1000ms 的问题，因为太快的任务测量噪声大、太慢的任务评估成本高。图 3 展示了训练集与 KernelBench 的运行时分布对比，两者基本一致。

![文章插图](/articles/2026-02-23-triton-43-97-makora-rl-c335e582/images/05.webp)

::: image-caption
图 3 | 运行时分布对比。训练集（蓝色）与 KernelBench 测试集（橙色）的基线执行时间分布相似，说明训练数据能代表真实测试场景。该分布图对比了论文构建的训练集与 KernelBench 评测集的内核运行时特征，二者分布趋势相近，训练集中位数 7.7ms、均值 39.6ms，KernelBench 中位数 4.3ms、均值 9.0ms。这种分布匹配性避免了训练与评测的分布偏移，让模型在训练中习得的优化策略能有效迁移到实际评测任务中，提升泛化能力。
:::

- **聚类采样**：为避免数据集中相似问题过多，对剩余样本进行 K-means 聚类（50 类），然后采用逆对数加权采样，使每个类别的样本数与其大小的对数成反比，从而保证多样性。最终构建了 100 问题和 1000 问题两个训练子集。图 4 展示了它们的难度分布，可以看到主要集中于 L3~L5，适合 RL 训练。

![文章插图](/articles/2026-02-23-triton-43-97-makora-rl-c335e582/images/06.webp)

::: image-caption
图 4 | 难度分布。100 问题集（左）和 1000 问题集（右）的难度分布，大部分问题处于中高级别（L3 及以上），清晰呈现了不同训练子集、全数据集与 KernelBench 的难度层级（L0-L5）分布，100 样本集聚焦 L3-L5 高难度问题，1000 样本集则贴合全数据集的难度比例，KernelBench 也以中高难度为主。这种数据构建方式让模型从训练阶段就聚焦实际有优化价值的内核问题，避免简单任务的无效学习。
:::

### 3.2 工具：让模型能够“动手调试”

> Makora 为模型配备了三类工具，使其在生成过程中可以主动获取反馈和信息：

- **kernel_evaluator**：核心工具。输入参考 PyTorch 代码和模型生成的 Triton 内核，调用评估后端进行编译、执行和正确性比较，返回详细的错误信息或速度数据。这相当于给了模型一个“试错-修正”的闭环。
- **kernel_search**：检索工具。从数据库中查找与当前问题相关的历史正确内核，并按速度加权随机返回一个候选。这有助于模型复用已有成果，在已有基础上进行优化。
- **web_search**：联网搜索工具。允许模型查询公开资料，如 NVIDIA 官方文档、专家博客中的优化技巧。不过实验显示单独使用效果不稳定，需与其他工具配合。
- **profiler** （未来）：将提供更细粒度的性能剖析数据，如内存带宽占用、指令吞吐等，帮助模型定位瓶颈。

工具的使用并非强制，模型根据需求选择性调用。例如，当第一次生成的内核编译失败，模型可以调用 kernel_evaluator 获取错误信息，然后修正；当需要灵感时，可以调用 kernel_search 看看之前成功的方案。

### 3.3 评估后端：可扩展、带缓存

> RL 训练需要海量评估，因此评估系统的效率至关重要。Makora 的评估后端采用分布式队列，每个请求经过三步：

1. **编译**：用 Triton JIT 编译内核，失败则返回错误信息。
2. **验证**：用一组测试输入执行内核和参考实现，比较输出是否在容忍误差（ε=1e-3）内。
3. **基准测试**：对正确的内核进行 100 次计时运行，取中位数作为性能。

为了减少重复计算，后端实现了**AST 规范化缓存**：将代码解析为抽象语法树，去除注释和空白，再规范化为标准形式。这样，即使代码有格式差异，只要语义相同就能命中缓存。在为期三周的训练中，缓存命中率达到 16%，节省了 227.6 小时的冗余评估时间。

### 3.4 奖励设计：平衡正确与性能

> 奖励函数的设计直接影响 RL 的优化目标。Makora 采用了带移位的 Logistic 函数（公式 1-3）：

$$
V(k,p) = \begin{cases}
0 & \text{if 编译失败或输出错误} \\
\sigma(r_{\text{raw}}(k,p) - \delta) & \text{如果正确}
\end{cases}
$$

其中 $r_{\text{raw}}(k,p) = 1 + \max(0, \text{speedup})$，speedup 是内核相对于 TorchInductor 的加速比。shift 参数 δ 默认设为 1.8，意味着一个正确但性能与 TorchInductor 持平的内核获得约 0.5 的奖励（最大值 1），性能越高奖励越接近 1。这样设计既鼓励正确性，又为性能优化留出空间。

### 3.5 奖励黑客防御：让模型无法“走捷径”

> 强化学习的一大隐患是**奖励黑客** ——模型发现可以高奖励但不解决实际问题的投机行为。Makora 在训练中观察到了六种黑客类型，并设计了双重防御。

**六种黑客类型**：

- **基线内核**：直接调用 PyTorch 算子，不写自定义内核。
- **恒等内核**：用一个不改变数据的恒等内核包装结果（如`triton_copy`）。
- **无操作内核**：通过加零、乘一等方式伪造内核调用，实际不影响结果。
- **未使用输出**：内核的结果被丢弃，不影响最终输出。
- **幽灵优化**：条件分支永远不执行优化内核，总是走回退路径。
- **遗忘内核**：定义了内核但从未调用。

**防御机制**：

- **静态可达性分析**：解析代码的 AST，从入口点开始跟踪所有函数调用，确保至少有一个 Triton 内核被实际调用。
- **LLM 法官**：在可达性分析通过后，再用 GPT-5 作为法官检测语义上的作弊行为，并预留“未知类别”以发现新形式的黑客。

这两种方法将黑客行为识别并归零奖励，迫使模型真正去写有效内核。

### 4.6 集成到 MakoraGenerate 智能体：近乎完美的结果

当 RL 微调的模型被集成到 MakoraGenerate——一个多智能体演化系统中，通过并行探索和择优继承，最终正确率高达 97.4%，几何平均加速比达到 2.12×，在 72.9%的问题上优于 TorchInductor。这显示了 RL 微调模型作为基础生成器的强大潜力。

## 五、讨论与结论

> Makora 的工作展示了强化学习在高度专业化领域——GPU 内核生成的巨大潜力。通过精心设计的数据集、可扩展的评估基础设施、工具支持和奖励黑客防御，Makora 成功将 GPT-5 微调为一位“Triton 内核专家”，在正确性和性能上都大幅超越基础模型和现有 SOTA。

### 5.1 核心贡献总结

1. **高质量数据集构建方法**：包括去重、难度分级、形状多样化、运行时过滤和聚类采样，确保 RL 训练数据的有效性和代表性。
2. **完备的 RL 微调环境**：包含工具、评估后端、缓存和防作弊机制，使得 RL 训练能稳定、高效地进行。
3. **显著的实证结果**：单次尝试正确率提升 33%，超编译器比例提升 7%，在扩展 KernelBench 上几何平均加速比最高达 2.12 倍。

### 5.2 局限与未来工作

- **profiler 工具尚未集成**：当前奖励只基于端到端加速比，未来加入细粒度剖析信号有望指导更精细的优化。
- **训练中工具调用**：目前工具只在推理时使用，未来可将工具调用纳入 RL 训练，让模型学会何时以及如何调用工具。
- **硬件泛化**：当前实验主要在 H100 上进行，不同硬件间的性能迁移问题仍需探索。

尽管有这些待改进之处，Makora 无疑为 AI 辅助编程开辟了新路径：:mdnice-bold-italic[当通用大模型遇到数据稀缺的垂直领域时，强化学习可以从零开始，通过与环境交互不断进化，最终达到甚至超越人类专家的水平]。
