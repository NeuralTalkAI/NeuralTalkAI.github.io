## 一、引言

> GPU 并行计算生态目前由英伟达单一闭源软件栈垄断。英伟达 CUDA 平台（包含 PTX 虚拟指令集、NVCC 专用编译器、cuDNN/cuBLAS 数值计算库生态）已经成为机器学习、科学计算、高性能数据处理领域的事实行业标准。这份垄断并非单纯源于硬件性能优势，核心原因是**软件绑定锁死**：专为 CUDA 编写的代码，想要在 AMD、英特尔、苹果 GPU 上运行，需要大规模重写改造。

目前行业已存在多款跨平台 GPU 编程接口：OpenCL[19]、Vulkan 计算管线、SYCL 均提供跨厂商应用程序接口；SPIR-V[20]是可跨硬件部署的中间二进制表示（IR，编译器生成的中间代码格式）。:mdnice-bold-italic[但这类工具均仅停留在 API、中间代码层级，刻意屏蔽了底层硬件执行模型。它们只规定了“软件如何与 GPU 交互”，却没有定义“GPU 底层硬件的统一运行逻辑”。]

**直接后果是：性能敏感的核心代码仍需要针对不同厂商硬件单独调优，跨平台接口运行效率通常仅能达到厂商原生代码的 50%~80%[23]。**

::: block-1
我们观察到一条全新可行的技术路线：:mdnice-bold-italic[ARM 指令集的成功并非依靠一套兼容异构 CPU 的上层 API，而是定义了一套精准统一的硬件执行模型，不同芯片厂商可基于这套规范设计完全不同的微架构，同时保证编译后的二进制程序通用兼容]。GPU 领域目前没有同类标准化指令集。
:::

> 本文核心研究问题：能否打造一套通用 GPU 指令集？细分两个子问题：

1. **所有 GPU 硬件共享、不受厂商设计影响的底层基础计算原语有哪些？**
2. **这些通用原语能否形式化定义，构建一套无厂商绑定的统一指令集架构？**

本文研究假设：各大厂商 GPU 架构出现趋同并非巧合，而是并行计算硬件的物理硬性约束所导致。**若假设成立，我们可通过实测归纳通用原语、精准标准化，设计一套任何硬件厂商都能落地、且不损失性能的中立指令集。**

### 1.1 本文创新点

1. 业内首套覆盖英伟达、AMD、英特尔、苹果四大厂商，跨越 15 年、16 代微架构的完整 GPU 指令集跨厂商系统性分析；
2. 归纳十类全硬件通用基础原语，并从芯片物理约束角度论证其存在的必要性；
3. 建立分类体系：区分六类参数化硬件差异、六类不可调和的底层架构分歧；
4. 遵循**薄抽象原则** （仅规定硬件必须实现的功能，不限制底层硬件实现细节）设计抽象 GPU 执行模型；
5. 在英伟达、苹果异构硬件上完成抽象模型的初步性能基准验证。

### 1.2 研究范围与局限性

本文分析对象**仅面向通用计算 GPU**，不包含神经网络专用处理器（NPU）、数字信号处理器（DSP）、现场可编程门阵列（FPGA）。:mdnice-bold-italic[苹果 GPU 所有架构参数均来自逆向工程，相关数据会标注可信度等级]；图形渲染流水线（3D 游戏图形管线）不在本次研究范围内。

## 二、背景与相关工作

### 3.1 GPU 整体架构概况

> 现代 GPU 顶层组织结构具备共性：由大量计算单元阵列构成，每个计算单元内置单指令多线程（SIMD，一条指令同时驱动多条线程并行运算）流水线、片上寄存器堆、程序员可控本地暂存内存；整套单元通过多级缓存层级，连接高带宽片外显存。

但各厂商指令集抽象逻辑差异巨大：

- 英伟达 PTX[1]采用单线程标量虚拟指令语义；
- AMD 对外公开原生硬件指令编码参考手册[6][8]；
- 英特尔提供基于 SIMD 寄存器、搭配消息传递接口的指令体系；
- 苹果从未公开任何官方指令集文档，仅依靠社区逆向工程实现局部解析[14][15]。

### 3.2 现有跨平台兼容技术路线

| 层级 | 兼容方案与说明 |
| --- | --- |
| **API 层级** | OpenCL[19]提供通用执行模型，但未定义硬件底层行为；SPIR-V[20]为跨平台二进制中间码，可被各厂商驱动读取；Vulkan 计算与 SYCL 提供额外抽象层；所有方案均依赖厂商后端编译器，未定义统一硬件执行模型。 |
| **编译器层级** | Halide[21]分离算法与调度，支持跨平台性能调优；MLIR[22]提供多层级渐进式中间表示；TVM[23]可自动搜索适配不同硬件的最优调度；三者最终均需映射至厂商专属后端，缺乏统一硬件抽象模型。 |
| **架构研究层级** | 现有 GPU 架构综述文献仅聚焦单一厂商（如[3][9]）；尚无研究以“提取硬件通用原语”为目标，开展覆盖 NVIDIA、AMD、Intel、Apple 四大厂商的系统性指令集层级对比。 |

### 2.3 ARM 指令集类比

**1985 年诞生的 ARM 指令集是本文最核心的参照范例**。:mdnice-bold-italic[ARM 定义一套标准指令规范，不同芯片厂商可基于该规范设计底层完全不同的微架构，同时保持二进制程序兼容]。这套指令约束边界精准、抽象层轻薄，在限制硬件行为的同时保留厂商微架构创新空间。**我们论证：当下 GPU 架构的趋同程度，已经足够支撑一套同类型通用指令集落地。**

#### 1）物理底层逻辑推导

- :mdnice-bold-italic[锁步并行分组（Wave）存在的核心原因：先进工艺下，单次指令读取的能耗是单条算术运算的 10~100 倍，将一条指令分摊给 $W$ 条线程并行执行，是【硬件节能】的【唯一】可行方案。]
- 掩码分支（mask-based divergence）是【唯一】能兼容锁步执行、且无需分支预测单元即可保证程序正确性的控制流机制。
- 寄存器-硬件占用率的权衡关系由固定面积的片上静态存储（SRAM）约束，对应公式：

$$
O=\left\lfloor\frac{F}{R × W × w}\right\rfloor
$$

- 程序员托管暂存内存长期存在的原因：并行计算访存模式无固定规律，硬件缓存无法预判数据位置，必须由开发者手动放置高频数据。
- 零开销上下文切换：内存访问延迟为 100~800 个时钟周期，是硬件运行瓶颈；将全部线程状态存储在片上 SRAM，面积开销低于复杂分支预测单元，线程切换无需读写低速片外存储，开销趋近于零。
- 工作组同步屏障仅支持工作组域、不支持全局同步：全局屏障要求所有并行工作组同时驻留计算单元，硬件资源无法支撑。

| 类别 | 规范说明 |
| --- | --- |

## 七、实验验证

我们选取本次研究中硬件架构差异最大的两款设备完成验证：英伟达 T4（图灵独立显卡，独立 GDDR6 显存，谷歌 Colab 云环境）、苹果 M1（片上统一内存架构，LPDDR4X，本地测试环境），设计三类典型负载完成基准测试。

### 7.1 实验方法

> 针对每一类负载，我们实现三套对比代码：

1. **厂商原生代码**：:mdnice-bold-italic[手写 CUDA（英伟达）/Metal（苹果），完整使用厂商专属硬件特性]。英伟达包含无存储体冲突的共享内存填充、warp 置换指令、循环展开、单 Warp 私有直方图；苹果使用 simd_shuffle 置换、融合乘加(FMA)内置函数。
2. **抽象模型代码**：:mdnice-bold-italic[完全仅使用通用 ISA 强制原语，不调用任何厂商私有内置函数、无 Wave 置换、无共享内存冲突填充、无编译器专属优化提示]，仅使用平铺式暂存读写、工作组屏障、基础算术、原子操作。
3. **厂商库参考** （仅矩阵乘法 GEMM 负载）：英伟达 cuBLAS 高度优化库，作为硬件性能理论上限参照。

测试参数：矩阵乘法 $N=4096$（FP32 单精度）；规约运算输入规模 $2^{24}$；直方图输入 $2^{24}$、分 256 个统计桶。 每组测试执行 10 次硬件预热迭代消除冷启动延迟，取后续 100 轮运行中位数作为最终性能指标。

::: block-1
重要范围说明：原生代码与抽象代码算法、分块逻辑完全等价，仅使用的底层原语不同。**本次实验仅衡量“移除厂商专属硬件特性带来的性能损耗”，并不代表抽象代码性能对标生产级高度优化库；cuBLAS 仅用于展示我们手写分块内核与硬件峰值性能的差距。**
:::

### 7.3 结果分析

#### 矩阵乘法(GEMM)

> 英伟达 T4 平台中，原生代码、抽象代码性能分别为 0.72 TFLOPS、0.91 TFLOPS，二者均远低于 cuBLAS 约 8 TFLOPS 的硬件峰值。该现象属于正常偏差：:mdnice-bold-italic[本文内核仅实现单层 32×32 分块，未使用生产库的寄存器分块、双缓冲、多层嵌套分块等复杂优化。]

核心对比维度为移除厂商特性后的相对性能变化：**抽象代码性能高出原生 26%，原因是英伟达原生代码为规避存储体冲突采用“Tile+1”填充，浪费大量共享内存**；抽象代码平铺索引逻辑更贴合 NVCC 编译器优化路径。

苹果 M1 平台原生、抽象代码性能均为 1.22 TFLOPS，抽象性能 101.2%，**证明 Metal 编译器对两套代码优化能力持平。**

#### 并行规约(Reduction)

> 本实验是全文关键结论来源：英伟达平台抽象代码仅达原生 62.5%。原生代码使用`__shfl_down_sync`波内置换完成最后 32 线程聚合，省去 5 次同步屏障+共享内存往返；苹果硬件调度器可并行运行 8 倍 SIMD 分组，足以屏蔽额外屏障延迟，仅损失 2.2%性能。

两组硬件性能差异证明：**波内置换无法作为可选扩展，必须纳入通用 ISA 强制原语，才能保证跨平台性能一致性。**

#### 直方图统计(Histogram)

两款硬件上抽象与原生代码性能基本持平（英伟达 100.4%、苹果 102.1%）。英伟达原生方案采用单 Warp 私有直方图降低共享内存原子竞争，但本次测试输入规模下原子冲突程度极低，私有优化无收益，单层全局直方图抽象方案性能无衰减。

#### 结果总结

六组软硬件配对中五组性能超过 80%可用阈值，四组抽象性能优于原生；:mdnice-bold-italic[唯一性能短板仅因缺失波内置换原语，并非抽象模型底层设计缺陷。将置换指令加入强制原语后，我们预判所有测试场景抽象性能均可达到原生 95%以上。]

### 7.4 实验有效性风险

1. 基线代码强度限制：本文原生代码为手写单层分块内核，并非生产级高度优化库。英伟达 GEMM 原生代码仅达到 cuBLAS 峰值性能的 9%。若采用寄存器分块、双缓冲等高优化基线，抽象层性能损耗会更严苛。我们刻意使用等价分块代码，目的是单独隔离厂商专属原语带来的性能影响，该测试结果代表抽象损耗的下限。
2. 厂商硬件覆盖不足：本次基准仅覆盖英伟达、苹果（研究中架构差异最大的两款设备），AMD、英特尔云平台测试正在推进，将纳入论文扩展版本。
3. 负载覆盖有限：三类负载分别覆盖计算密集型、带宽密集型、原子操作密集型场景；不规则稀疏计算、Transformer 注意力等复合 AI 算子、访存发散负载均留作后续研究。
4. 苹果硬件数据可信度：苹果所有架构参数来自社区逆向工程，性能数据为实测真值，但硬件性能差异背后的底层逻辑推导依赖社区逆向文档佐证。

## 八、讨论

### 8.1 当下开展本研究的时代契机

> 当下推进这项研究存在三重关键时代驱动因素。

- 第一，人工智能算力需求激增，英伟达软件栈形成行业垄断，让全球计算基础设施存在单点故障隐患；
- 第二，针对高端半导体的地缘出口管控落地，具备自主可控能力的人工智能算力成为多国战略优先方向，市场迫切需求无厂商绑定的通用软件方案；
- 第三，本文梳理了跨越 15 年、四大厂商迭代的 GPU 架构演进路径，证实各家硬件设计已充分趋同，我们能够稳定提取具备通用性的底层硬件原语。

### 8.2 薄抽象核心设计原则

> 本文整套抽象模型的核心准则为薄抽象：仅定义硬件**必须实现的能力**，而不去硬性规定硬件**内部实现手段**。

- 我们不会固定锁步分组宽度 $W$ 的数值，而是提供运行时查询接口；
- **不会向上层暴露分支发散的底层硬件逻辑**，统一封装为标准化结构化控制流；
- 不强制规定缓存层级数量，仅定义波、工作组、设备、系统四级内存同步作用域；
- 不统一矩阵运算硬件分块尺寸，提供运行时可查询接口。

::: block-1
每一项设计取舍，都是用编译期固定约束换取运行时硬件适配灵活性，让同一套指令集能够覆盖移动端低功耗 GPU、数据中心高性能计算加速卡全品类硬件。
:::

本文基准测试结果为薄抽象原则提供实证支撑：英伟达通用矩阵乘法、苹果直方图两个测试场景中，抽象模型性能反超厂商原生手写代码。**该现象说明厂商专属优化逻辑往往绑定特定硬件参数，更换硬件平台后反而产生性能损耗；轻量化抽象不会固化硬件预设条件，交由编译器与硬件协同寻找最优执行路径，跨设备适配能力更强。**

### 8.3 波内置换原语的关键研究结论

> 并行规约基准测试得出核心结论：波内置换（同一锁步分组内线程高速数据交换指令）在底层原语体系中拥有特殊定位。工作组屏障、原子操作在各家硬件上性能衰减幅度基本一致，但置换操作的运行效率高度依赖硬件对共享内存访问延迟的容忍能力。

- 英伟达 Warp 调度器会激进地流水线化锁步分组运算，若使用共享内存+同步屏障替代置换指令，性能直接下降 37.5%；
- 苹果硬件配备 8 倍冗余 SIMD 分组，足以抵消额外屏障带来的延迟开销，性能仅损耗 2.2%。

**这种跨平台性能不对称性促使我们修正原语集合**：在原本十类全硬件通用原语基础上，将波内置换增设为第十一项强制基础原语。四大厂商现有硬件均已原生内置置换相关硬件指令：英伟达`__shfl`、AMD DPP/ds_permute、英特尔子组置换、苹果`simd_shuffle`，新增该项强制原语不会为芯片厂商增加额外硬件设计成本。

### 8.4 与现有行业标准的关联

> 本文提出的通用 GPU 指令集与现存行业标准化体系属于互补关系，不存在互相替代的冲突。

- SPIR-V 可作为面向本通用 ISA 程序的分发中间载体；
- OpenCL、Vulkan 计算管线能够承担 CPU 主机侧调用 API 的角色。

二者核心区别在于：**OpenCL、SPIR-V 等现有标准仅规定“软件如何和 GPU 交互”的调用协议；本文模型直接定义“GPU 硬件底层统一基础构成”，从根源解决跨平台程序性能大幅衰减的痛点**。

### 8.5 研究局限与后续工作计划

除第七章“实验有效性风险”提及的短板外，仍有多项研究工作待落地。

- 第一，通用 ISA 完整正式规范（包含指令编码规则、二进制文件存储格式）正在配套技术报告中撰写；
- 第二，依托云 GPU 实例完成 AMD RDNA/CDNA、英特尔 Xe 架构的基准测试；
- 第三，扩充测试负载，新增不规则稀疏计算、Transformer 注意力、层归一化等人工智能复合算子、访存发散类任务的基准套件；
- 第四，开发通用 ISA 转换各厂商原生后端的原型编译器，实现全自动代码翻译，无需人工改写，完整验证这套抽象模型的工程落地可行性。

## 结论

> 本文完成业内首次覆盖英伟达、AMD、英特尔、苹果四大主流 GPU 厂商，横跨 16 代微架构的系统性 GPU 指令集跨厂商对比分析。**研究证实，十类底层计算原语由并行芯片物理约束所决定，是所有 GPU 硬件与生俱来的核心基础组件。遵循薄抽象原则搭建的统一抽象执行模型，能够无损耗映射至各家硬件原生运算单元。**

各大厂商 GPU 架构走向趋同**并非行业设计巧** 合，锁步并行分组、掩码分支、寄存器硬件占用权衡、程序员可控片上暂存内存、零开销线程上下文切换、分层存储体系、原子读写修改、工作组同步屏障，**全部是并行计算硬件的固有底层特征，与芯片制造厂商无关。**

我们选取研究中架构差异最大的英伟达 T4、苹果 M1 两款硬件开展基准验证，:mdnice-bold-italic[六组软硬件配对场景里，有五组仅使用通用原语编写的程序性能持平、甚至优于厂商原生优化代码]；唯一性能不达标的场景，仅暴露出波内置换原语的缺失，并非抽象框架存在底层设计缺陷，仅需扩充强制原语清单即可完善。

本研究打通了通用 GPU 指令集的落地路径，有望打造 GPU 领域对标 ARM 架构、可跨厂商兼容的统一硬件指令规范。
