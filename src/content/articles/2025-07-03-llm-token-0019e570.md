## 四、各硬件平台推理表现比较

### 4.1 设置

> 在本节中，我们比较了 CPU、GPU、FPGA、ASIC 和 PIM/NDP 等硬件加速器上最先进的优化方法在生成式 LLM 方面的性能。在传统的硬件性能比较中，通常关注峰值计算性能和功耗。

然而，在生成式大模型的背景下，重点转移到了推理速度（每秒 token 数，tokens/s）和硬件功耗（瓦特，W）。下图中 Y 轴表示推理速度、X 轴为硬件功耗，**曲线的斜率表示硬件效率，单位为每焦耳 token 数（tokens/J）。**

![文章插图](/articles/2025-07-03-llm-token-0019e570/images/04.webp)

因此，**我们收集了每个硬件平台以及所有优化方法的数据，突出显示了它们在运行批量大小为 1 和 8 的生成式大模型（约 70 亿参数）时的推理速度（明确提及或估算）和实际功耗**，如图 13 和图 14 所示。

![文章插图](/articles/2025-07-03-llm-token-0019e570/images/05.webp)

> 在收集数据时，**【绝对推理速度】** 的来源**分为五类**：

::: block-1
- 对于**大多数 CPU 和 GPU 硬件** 平台，**文献中通常会报告绝对推理速度** 以及所运行的特定模型。
- 对于具**有开源和可复现代码的 GPU 平台**，我们通过**实际执行直接测量** 绝对推理速度。
- **FPGA 硬件** 平台的相关**工作有限**。一些论文通过物理测试提供了经过验证的绝对推理数据，而另一些则提供了未经硬件验证的估计值。因此，我们也包括了这些情况下的估计绝对推理速度。
- 对于**大多数 ASIC 平台**，我们首先将具有绝对推理速度的硅后工作[150]定义为基线，并通过峰值计算性能（TOPS 或 GOPS）对结果进行缩放。我们使用 BitMoD[153]的开源基于周期的精确硬件模拟器来模拟 OliVe[148]等基线的性能。
- 一些工作提供了**相对于 GPU 或其他硬件平台的加速比**。在这些情况下，我们根据报告的加速比对现有数据进行缩放，以估计绝对推理速度。
:::

> **【功耗】** 的来源分为三类：

- 对于**大多数 CPU 以及一些 GPU 和 FPGA 硬件平台**，论文中通常会指定所使用的硬件型号和数量。我们使用这些规格来**确定实际功耗**。
- 对于具有**开源和可复现代码的 GPU 平台**，我们通过**实际执行直接测量** 实际功耗。
- 对于**大多数 ASIC 和 PIM/NDP 平台**，我们考虑片上和片外内存访问功耗。

### 4.3 优化方法比较

#### 4.3.1 小批量（bs=1）下各优化方法比较

然后，我们比较了同一平台上的不同优化方法。在图 13 中：

![文章插图](/articles/2025-07-03-llm-token-0019e570/images/04.webp)

> 【CPU 平台】上使用的方法包括量化、稀疏化和异构合作。

::: block-1
- 吞吐：量化可以实现更高的绝对推理速度，达到约 50 tokens/s，而稀疏化和异构合作分别实现了 16.3 tokens/s 和 22.73 tokens/s 的速度。
- 能效：**与稀疏化** （0.16 tokens/J）**相比**，**量化和异构合作可以实现更高的能效**，达到 2.38 tokens/J。
:::

> 在 【GPU 平台】上，使用的方法包括量化、稀疏化、快速解码和算子优化。

- 吞吐：**量化、快速解码** 可以实现**更高的绝对推理速度**，分别达到约 343.4 tokens/s 和 274.4 tokens/s。而算子优化和稀疏化**仅** 达到约 181 tokens/s 和 76.69 tokens/s。
- 能效：与稀疏化（0.434 tokens/J）相比，这三种方法的性能差异相对较小，效率分别为 0.859 tokens/J、0.686 tokens/J 和 0.522 tokens/J。

> 在 【FPGA 平台】上，使用的方法包括量化、稀疏化和异构合作，这些方法通常结合使用。

- 板载部署的最高速度达到 290 tokens/s，能效高达 6.304 tokens/J
- 一些工作通过异构 GPU 和 FPGA 实现了 450 tokens/s 的性能，能效为 0.87 tokens/J。

> 在 【ASIC 平台】上，使用的方法包括量化和算子优化。

- 吞吐：算子优化可以实现最高的绝对推理速度，达到约 2700 tokens/s。相比之下，量化实现了 161.1 tokens/s 的速度。
- 能效：量化和算子优化提供了相似且较高的能效，分别为 8.49 tokens/J 和 12.34 tokens/J。

> 在 【PIM/NDP 平台】上，使用的主要方法是量化、快速解码和异构合作。

- 吞吐：量化可以实现更高的吞吐量，达到 1998 tokens/s，而快速解码和异构合作分别仅实现 174.018 tokens/s 和 400 tokens/s
- 能效：量化也实现了更高的能效，达到 46.66 tokens/J，而快速解码和异构合作分别仅达到 9.94 tokens/J 和 4.34 tokens/s。

## 五、未来 AI 硬件趋势讨论

边缘智能的发展已获得显著动力，这是由 LLM 能力的不断提升以及边缘应用需求的日益增长所推动的。

> 展望未来，有**三大趋势** 逐渐显现：**多模态、推理时计算，以及更高的推理能效**，这些趋势有望重新定义边缘 AI 系统的能力，如图 15 所示。

![文章插图](/articles/2025-07-03-llm-token-0019e570/images/06.webp)

- **多模态** 侧重于整合多种数据类型，如视觉、听觉、文本和传感输入，以增强配备 LLM 的系统理解和适应复杂场景的能力，支持从 PC、智能手机到 AR 眼镜和智能手表等广泛的边缘设备。
- **推理时计算** 强调在 LLM 推理过程中利用诸如思维链（CoT）推理等迭代过程进行深度思考，通过执行后训练过程来持续提升模型能力。
- **更高的能效** 则凸显了在高实时性场景中，将能效从 1 tokens/J 提升至大于 10 tokens/J 的需求，例如以机器人控制和自动驾驶为代表的具身智能场景。

### 5.1 多模态

如图 16 左侧所示，我们总结了过去五年中典型 LLM 的发布日期和训练文本 token 数量。

![文章插图](/articles/2025-07-03-llm-token-0019e570/images/07.webp)

> 训练 token 的数量正以每年 2.5 倍的速度增长。

- GPT-3 仅使用 **0.4 万亿** 文本 token 进行训练
- 而 Qwen2.5 和 Llama3.1 则分别使用了 **18 万亿** 和 **15 万亿** token

根据 Epoch AI 的结果，人类生成的公开文本 token 总数约为 **300 万亿** [305]。按照这个增长速度，**预计到 2027 年**，我们将面临用于训练 LLM 的可用公开文本 **token 短缺的问题**。

::: block-1
除了文本 token，互联网上还有大量其他模态的 token，如图像和视频 token（总数约 1650 万亿[305]）。因此：

- 从 token 可用性的角度来看，通过**利用多种模态的 token 来训练 LLM**，我们可以**延续 LLM 的缩放定律** [60]。
- 从人类交互的角度来看，**人类依赖各种感官** 作为**与物理世界交互** 的通道，这本质上是**多模态的**。
:::

最近的研究还证明，**由于对潜在空间表示的估计更准确，多模态学习的表现无疑优于单模态** [306]。这些因素表明，未来的 LLM 应该具备多模态交互能力，以感知、处理和生成跨多种模态的信息。

![文章插图](/articles/2025-07-03-llm-token-0019e570/images/07.webp)

> **目前**，超过 **80%的多模态 LLM 专注于视觉和语言任务** [307]。如图 16 所示，它们的发展大致可以分为三个阶段。

- 首先，从 2023 年 5 月到 9 月，模型**规模较小，准确率在 20%到 40%之间**。
- 然后，从 2023 年 12 月到 2024 年 4 月，随着 **GPT4v 的发布，模型准确率显著提高，达到近 60%。**
- 2024 年 5 月之后，随着 **GPT4o 的发布，更多的多模态模型被发布，准确率几乎达到 80%。**

::: block-1
需要注意的是：

1. **多模态 LLM（MLLM）的发展在很大程度上依赖于多模态数据集的构建**。
2. MLLM 的另一个重要趋势是**原生多模态的概念**。通过**在训练阶段对齐不同模态**，原生 MLLM 实现了端到端的输入和输出。
:::

### 5.2 推理时计算

在 LLM 时代，数据是基石，但预训练的时代将会结束，因为**数据不再增长** [309]。以 OpenAI 的 **o1 范式[310]为代表的推理时计算，现在被视为下一个 LLM 时代提升模型能力的关键途径**。o1 的原理可以通过它与 GPT4 的区别来阐述，**如图 17(a)所示。**

![文章插图](/articles/2025-07-03-llm-token-0019e570/images/08.webp)

> 在训练阶段，GPT4 遵循传统的工作流程：预训练基础模型，然后通过人类反馈强化学习（RLHF）进行微调。相比之下，o1 在训练后阶段引入了几项创新。除了整合强化学习（RL）之外，o1 还特别强调安全优化，以确保 o1 在部署期间能够胜任更细致的任务和安全决策。

**GPT4 和 o1 在推理阶段的区别更加明显**。GPT4 直接生成答案，不涉及显式的迭代推理。相比之下，**o1 在生成答案之前引入了“思考与总结”阶段**。这一步骤利用高级技术，如思维链（CoT）推理和树搜索，来执行更复杂的逻辑推理和逐步问题解决。与 GPT4o 相比，o1 范式在 AI 数学评估（AIME）测试数据集等复杂逻辑推理任务上的准确率提高了 50%。然而，推理成本增加了 10-100 倍[311]。

> 推理时计算可以提升模型能力，但也会大幅增加推理时间，尤其是对于复杂的推理任务。

![文章插图](/articles/2025-07-03-llm-token-0019e570/images/08.webp)如图 17(b)所示，在 GSM8K 基准测试中，我们使用 Llama2-7B 作为主干 LLM，结合开源的 LLM-Reasoners[312]。与直接使用 Llama2-7B 相比，推理时间增加了 678 倍。这种**巨大的时间开销主要源于推理时计算中固有的迭代多步骤过程，这是满足更复杂推理任务要求所必需的**。因此，**选择合适的场景和条件来应用推理时计算** 仍然是一个值得进一步研究的课题。

::: block-1
此外，**推理时计算还改变了 LLM 推理的运行时开销分布**。如图 17(c)所示：

- 预填充阶段的比例从 1.5%显著增加到 23.5%，而解码阶段则从 98.5%下降到 54.8%。
- 预填充阶段的增加部分是由于需要将人类输入 token 与模板输入 token 合并为整个 LLM 输入，这有效地延长了输入序列长度。

此外，在迭代过程中，**中间输出 token 被累积反馈作为输入，导致预填充的序列长度逐渐增加**。同时，过程奖励模型（PRM）占时间的 21.7%。
:::

> 运行时开销分布的这种变化表明，**未来推理时计算的优化方法应该同时考虑预填充阶段、解码阶段和 PRM。**

**推理时计算有望成为下一代 AI 系统的基础 LLM 推理范式**。对于自动驾驶和机器人等边缘应用，先进的模型能力至关重要，而推理成本的指数级增长对硬件和软件都提出了重大挑战。实时响应能力、更高的吞吐量和高效的资源利用正成为支持这些边缘应用的基本属性。

### 5.3 更高的推理能效

> 在未来的边缘应用中，特别是在以机器人控制和自动驾驶为代表的高实时性场景中，系统的控制频率需要达到 100-1000 Hz[313,314,315,316]。

这意味着**使用 LLM 作为动作或指令决策中心的系统应该至少实现 100-1000 tokens/s 的推理速度**。由于边缘设备需要考虑能源供应，**边缘芯片的功率应小于 20W** （人类大脑的功耗[317,318]），因此**推理效率应超过 10 tokens/J。**

![文章插图](/articles/2025-07-03-llm-token-0019e570/images/09.webp)

然而，如图 18 所示，当前的商用边缘芯片，如特斯拉 RPU[319]和 NVIDIA Jetson Orin[320]，即使采用软件优化方法，实际推理速度也仅为 10-30 tokens/s，效率低于 1 tokens/J。这在绝对推理速度和效率方面与未来的边缘应用需求存在 1-2 个数量级的差距。

> 为了实现这一目标，我们应该继续采用算法-硬件协同设计的方法。

- 在算法方面，可以采用**更激进的模型压缩方法**，并使用**高质量数据集** 进行再训练，以最大限度地减少准确率损失。
- 在硬件方面，除了设计**支持算法优化的特定硬件单元** 外，还需要设计**更具创新性的芯片架构**，如 3D DRAM 堆叠集成架构[321]，它可以显著减少数据传输延迟和能耗；**数据流架构**，优化数据传输路径以提高计算效率；以及**晶圆级架构**，通过超大规模集成提供更高的计算和存储能力。

---

这些协同设计方法可以有效**弥合当前边缘侧芯片在推理速度和能源效率方面的差距**，满足未来应用的需求。

## 六、结论

> 由于**生成式 LLM** （如 GPT 系列和 Llama 系列）具有高算法性能，它们**目前是主要关注点**。

生成式 LLM 的进步**与硬件能力** 的发展**紧密交织**。

::: block-1
本文对不同硬件平台上高效的生成式 LLM 推理进行了全面综述。我们概述了主流生成式 LLM 的算法架构，并总结了针对 CPU、GPU、FPGA、ASIC 和 PIM/NDP 等不同平台的优化方法。

此外，我们通过考虑硬件功耗、绝对推理速度（tokens/s）和能效（tokens/J），对批量大小为 1 和 8 的不同硬件平台上的推理性能进行了定性和定量比较。
:::

我们指出，边缘智能的发展已获得显著动力，**三大趋势（多模态、推理时计算和更高的推理能效）有望重新定义边缘 AI 系统的能力**。

基于软硬件优化，**未来的边缘芯片** 有望实现**高吞吐量和低能耗**，消除边缘 AI 推理中**1-2 个数量级** 的差距。
