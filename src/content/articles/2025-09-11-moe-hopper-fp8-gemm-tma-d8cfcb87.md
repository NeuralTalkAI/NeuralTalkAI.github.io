## TMA-Adaptive FP8 Grouped GEMM

> 当前 FP8 分组通用矩阵乘法（Grouped GEMM）实现方案中，由于硬件存在两大核心约束，必须将每个分组填充（padding，指为满足硬件对齐要求，在数据末尾补充无效数据的操作）至固定对齐长度（例如 128）：

- 一是 NVIDIA Hopper GPU 的张量内存加速器（TMA，Tensor Memory Accelerator）在主机初始化时:mdnice-bold-italic[需静态配置描述符，无法动态适配不同分组的可变行维度]；
- 二是 :mdnice-bold-italic[TMA 对多维批量张量异步拷贝有严格对齐要求] ——全局内存需 16 字节对齐、共享内存需 128 字节对齐。

**这种填充操作会额外引入内存冗余和无效计算开销**，尤其在混合专家（MoE）架构等依赖动态分组（如 top-k 路由生成的可变序列长度）的场景中，开销问题更突出。

本文提出 **TMA 自适应 FP8 分组 GEMM（TMA-Adaptive FP8 Grouped GEMM）**，通过**动态适配可变分组维度**，从根源上消除填充操作，核心实现依赖两大创新设计，且严格满足 TMA 硬件对齐约束：

1. 构建一个 TMA 描述符池，包含 $\log_2(block_M)$ 个预配置描述符，通过运行时动态选择与双阶段加载 - 存储操作处理所有剩余行情况，以极低开销实现全面覆盖；
2. 设计 TMA 对齐感知内存管理机制，满足 16 字节全局内存对齐与 128 字节共享内存对齐要求。

实验结果表明，:mdnice-bold-italic[与 “填充操作 + 当前最先进的 FP8 分组 GEMM” 方案相比]，该方法**实现了 1.7% 至 20.4% 的性能提升，内存占用减少最高达 23.8%，** 同时对有效数据保持完全的数值等价性。源代码已在公开匿名仓库发布，地址为：https://github.com/sukoncon/TMA-Adaptive-FP8-Grouped-GEMM。

## 关键问题

### 问题 1. 本文将 blockN 约束为 64 的倍数以保证 128 字节共享内存对齐，而实际大语言模型（LLM）的输出维度 N 可能存在非 64 倍数的场景，这种 $block_N$ 的固定约束是否会限制 TMA-Adaptive FP8 Grouped GEMM 在多样化 N 维度配置下的适用性，且该约束是否可能引入新的性能损耗（如非最优分块导致的计算效率下降）？

作者明确指出，将 $block_N$ 约束为 64 的倍数（如 64、128、192）是为了确保 128 字节共享内存对齐，而该**约束并不会显著限制其在多样化 N 维度配置下的适用性——因为这些 64 倍数的 blockN 值在实际大语言模型的 N 维度配置中本身就是“最优或近最优选择”**，与 LLM 常用的 N 维度参数（如 3072、4096 等，均为 64 的倍数）天然适配，无需额外调整即可覆盖主流场景。

同时，实验结果已验证该约束下方案仍能实现 1.7%~20.4%的性能提升，未出现因非最优分块导致的计算效率下降问题，反而**通过消除 Padding 开销抵消了潜在的分块约束影响，最终实现了计算吞吐量的提升。**

### 问题 2. 作者提出的双阶段加载存储机制通过重叠内存区域的少量重复数据写入实现边界合规，当组维度 $M_g$ 远小于 $block_N$（如极端动态路由导致部分组序列长度极短）时，这种重叠写入策略是否会显著增加无效内存操作的比例，进而抵消消除 Padding 带来的性能收益，甚至引发数据一致性风险？

针对 $M_g$ 远小于 $block_N$ 的极端场景，本文提出的双阶段加载存储机制通过“安全重叠写入策略”（仅对重叠内存区域写入少量相同数据），可避免无效内存操作比例显著增加的问题：

- 一方面，该机制仅需 2 次 TMA 操作即可处理任意大小的剩余块，与 $M_g$ 和 $block_N$ 的比例无关，不会因 $M_g$ 过小导致操作次数激增；
- 另一方面，实验验证显示，即使在 $M_g=8192（较小序列长度）且分组数=32$ 的场景下，方案仍能实现 23.8%的内存节省和显著性能提升，未出现“抵消消除 Padding 收益”的情况。

此外，该机制通过**严格的边界合规设计和最终写回时对有效数据区域的精准保留，已通过“逐位相同”的数值验证，完全规避了数据一致性风险。**

### 问题 3. 本文实验基于 NVIDIA H800 GPU（Hopper 架构）、PyTorch 2.6.0 及 CUDA 12.6 实现，该方案对 Hopper 架构的 TMA 特性依赖度极高，那么其在非 Hopper 架构 GPU（如 Ampere、Ada Lovelace）或其他支持低精度计算的硬件平台上的迁移性如何？且能否扩展至 FP8 以外的低精度格式（如 INT8）的 Grouped GEMM 场景？

关于迁移性与低精度格式扩展，本文:mdnice-bold-italic[方案存在明确的硬件和精度依赖，但也给出了清晰的适用边界：]

1. **非 Hopper 架构迁移性**：方案核心依赖 Hopper 架构特有的 FP8 张量核心支持及 TMA 对齐规则（16 字节全局内存、128 字节共享内存），而 Ampere、Ada Lovelace 等非 Hopper 架构要么不支持 FP8 张量核心，要么 TMA 对齐要求不同（如 Ampere 无 FP8 TMA 优化），因此直接迁移不可行，需针对目标架构的 TMA 特性和低精度支持能力重新调整描述符池设计与对齐管理策略；
2. **其他低精度格式扩展**：本文方案的设计核心围绕 FP8 的存储特性（如 2 字节半精度数据格式用于计算 Cg 的共享内存行偏移），若扩展至 INT8（1 字节），需重新推导内存对齐公式（如共享内存行偏移、预取行数计算）和描述符池参数，当前方案未覆盖 INT8 场景，需额外开发适配逻辑。

## 一、引言与相关工作

> 为提升计算速度并减少内存消耗，低精度计算（low-precision computation，指使用 FP8、INT8 等低位宽数据格式替代传统 32 位浮点数进行计算的技术，可显著降低内存占用和计算延迟）的研究已成为热点。

- 2018 年，Micikevicius 等人[Micikevicius et al., 2018]率先采用半精度浮点数训练深度神经网络。
- 随着后续硬件的发展，低精度技术持续演进，例如 Mitchell 等人[Mitchell et al., 2023]提出了 SwitchBack——一种用于训练的 INT8 量化线性层；
- 而 DeepSeek-AI[DeepSeek-AI, 2025]最终验证了 8 位精度（FP8 或 INT8）在大型模型训练与推理中的稳定性和计算效率。

> 现代 GPU 架构（如 Hopper 架构及后续架构）支持 FP8 张量核心（tensor core，GPU 中专门用于加速矩阵乘加等 AI 核心运算的硬件单元）。

- 为充分发挥 GPU 性能，研究人员开发了多种优化技术[Zhao et al., 2025; Shah et al., 2024]，包括线程束专用化（warp specialization，指为 GPU 线程束——由 32 个并行线程组成的基本执行单元——分配特定任务以提升并行效率的策略）、张量内存加速器（TMA）[NVIDIA, 2022-03-22]以及线程束组矩阵乘加（warp group matrix multiply-accumulate，指将多个线程束组成小组协同执行矩阵乘加操作，以提高计算密集型任务的效率）等。

这些技术共同作用，最大化了基础模型负载的内存带宽利用率和计算强度（arithmetic intensity，指计算操作数与数据传输量的比值，是衡量硬件计算效率的关键指标）。

> 这些低精度技术在专用架构中具有尤为重要的应用。:mdnice-bold-italic[分组通用矩阵乘法（Grouped GEMM）操作在混合专家（MoE，Mixture-of-Experts）架构中扮演核心角色] ——在 MoE 架构中，通过 **top-k 路由** （top-k routing，指根据输入特征选择激活前 k 个“专家”子网络进行计算的机制）**会产生可变的分组大小**。

**在分组 GEMM 计算中，由于硬件约束** （处理可变维度时，例如 MoE 架构中动态路由的序列长度），**填充操作是必不可少的**。这种必要性:mdnice-bold-italic[源于两个根本性的架构限制]：

::: block-1
- 第一，:mdnice-bold-italic[主机初始化阶段对 TMA 描述符的静态配置]，导致其无法动态适配不同分组的可变行维度；
- 第二，:mdnice-bold-italic[Hopper 架构的 TMA 对多维批量张量异步复制] （multi-dimensional bulk tensor asynchronous copies，指 GPU 中非阻塞式批量传输多维张量数据的操作，可提升数据传输与计算的并行性）:mdnice-bold-italic[施加了严格的对齐要求] ——全局内存需满足 16 字节对齐，共享内存需满足 128 字节对齐[NVIDIA Corporation, 2025]。
:::

> 本文提出 TMA 自适应 FP8 分组 GEMM（TMA-Adaptive FP8 Grouped GEMM）——一种符合硬件要求的 FP8 矩阵乘法优化框架，该框架在严格满足 TMA 对齐约束的同时，消除了填充开销。我们的**方案包含两个关键创新点**：

**第一，构建 TMA 描述符池** （TMA descriptor pool）：预定义所有可能剩余行（分组行数量除以块大小 $block_M$ 后余下的行）对应的描述符，随后通过运行时动态选择描述符和双阶段加载-存储操作，仅需 $\log _{2}( block _{M})$ 个预配置描述符即可覆盖所有可能的剩余行场景。

**第二，提出 TMA 对齐感知内存访问方案** （TMA-alignment-aware memory access scheme）：通过两种机制保证对齐合规性：

::: block-1
- 一是通过过度抓取（over-fetching，指为满足对齐要求，额外读取少量超出当前计算需求的数据，后续仅使用有效部分）维持 16 字节全局内存对齐；
- 二是将 $block_N$（分组 GEMM 中列维度的块大小）约束为 64 的倍数，以确保 128 字节共享内存对齐边界。
:::

### 2.1 分组通用矩阵乘法（Grouped GEMM）的符号与预备知识

表 1 总结了分组通用矩阵乘法（Grouped GEMM）在特定量化方案下使用的关键符号。

![文章插图](/articles/2025-09-11-moe-hopper-fp8-gemm-tma-d8cfcb87/images/05.webp)

参考[DeepSeek-AI, 2025]的研究：

- 我们对矩阵 A 采用 1×128 分块缩放（tiled scaling，将矩阵按 1 行 ×128 列的固定块大小拆分后逐块缩放）
- 对矩阵 B 采用 128×128 分块缩放（按 128 行 ×128 列的固定块大小拆分后逐块缩放）

在大语言模型的混合专家（Mixture-of-Experts, MoE，一种通过“专家网络”分工处理不同输入的架构）架构场景中，维度 $M_g$ 表示分配给专家分组 g 的、经动态路由后的序列长度（即输入文本经 token 化后的序列长度，随输入内容动态变化）。而静态参数 K（隐藏维度）和 N（输出维度）在所有分组中保持不变。

CUDA 内核配置参数 $block_M$、$block_N$ 和 $block_K$ 表示为优化计算性能而设定的固定分块大小（即将大矩阵拆分为小块后并行计算的块尺寸）。

> 在分组通用矩阵乘法（Grouped GEMM）涉及的所有操作数中，:mdnice-bold-italic[从全局内存加载 $S_A^g$ 以及从共享内存加载 $C_g$ 时，需特别关注内存对齐问题] （内存地址需是指定字节数的整数倍，以提升 GPU 访问效率）。

下面讲一下内存对齐分析。

#### 分组通用矩阵乘法（Grouped GEMM）操作数的内存对齐分析

##### 分析1：$A^g$ 的对齐分析

张量 $A^g$ 参与张量内存访问（TMA，Tensor Memory Access）操作，包括全局内存加载与共享内存存储。

- 在**全局内存** 中，$A^g$ 的每行偏移量为 $K$ 字节（其中 $K$ 表示混合专家模型（MoE）架构中的隐藏维度大小）。:mdnice-bold-italic[在现代大语言模型配置（如 Deepseek、Mixtral、Llama）中，通常会设置 $K \bmod 16=0$（即 $K$ 为 16 的倍数），这一做法天然满足 16 字节全局内存对齐要求。]
- 对于**共享内存** 访问，我们在内核初始化阶段通过**从 128 字节对齐地址开始分配内存，确保 128 字节对齐**。该设计使得对齐条件与剩余行数大小（residual row size）或 blockK 参数（矩阵分块中 K 维度的分块大小）均无关。

##### 分析2：$B^g$ 的对齐分析

$B^g$ 的对齐特性与 $A^g$ 遵循相似原理（为简洁起见，省略详细分析）。

##### 分析3：$S_A^g$ 的对齐分析

缩放张量 $S_A^g$ 参与 TMA 操作，包括全局内存加载与共享内存存储。在全局内存中，其每行偏移量为 $4\lfloor K / 128 \rfloor$ 字节（系数 4 源于浮点数据类型的存储占用，即每个 float 类型数据占 4 字节），**这可能违反对齐要求。**

:mdnice-bold-italic[为解决这一问题，我们引入了 2.3 节所述的过度抓取技术（over-fetching technique，指抓取超出当前计算所需的数据以满足内存对齐要求）]。为确保共享内存中的正确对齐，我们在内核配置阶段预先定义了 128 字节对齐的起始地址。

##### 分析4：$S_B^g$ 的对齐分析

张量 $S_B^g$ 无需参与 TMA 加载操作，因为每个线程束组（warp group，warp 是 GPU 中的基本执行单元，通常包含 32 个线程）的矩阵乘法操作通常仅需 1 至 2 个元素用于缩放。

##### 分析5：$C^g$ 的对齐分析

输出张量 $C^g$ 参与 TMA 操作，包括共享内存加载与全局内存存储。在共享内存中，每行偏移量为 $2 \cdot block_N$ 字节（系数 2 源于半精度数据格式，如 FP16，每个数据占 2 字节）。:mdnice-bold-italic[如 2.2 节所示，TMA 的第二阶段从行 $res^g - 2^{\lfloor \log_2(res^g) \rfloor}$ 开始，这可能导致不对齐问题。]

:mdnice-bold-italic[为解决该问题，我们将 blockN（矩阵分块中 N 维度的分块大小）约束为 64 的倍数，确保无论起始行位置如何，均能满足 128 字节对齐]。对于全局内存访问，每行偏移量为 $2N$ 字节。在现代大语言模型架构（如 Deepseek、Mixtral、Llama）中，**通常会设置 $2N \bmod 16=0$（即 $2N$ 为 16 的倍数），这一做法天然满足 16 字节对齐要求。**

### 2.2 带两阶段加载-存储的动态描述符选择

> 我们的核心技术贡献是一种**“硬件感知的 TMA 描述符设计”** ——该设计既满足静态配置要求，又能实现运行时动态适配，同时为输出矩阵的剩余块（residual block，指矩阵分块后未填满一个完整块的部分）设计了新颖的两阶段加载-存储机制。

该方法包含三个阶段：

#### 阶段1：描述符池预定义

![文章插图](/articles/2025-09-11-moe-hopper-fp8-gemm-tma-d8cfcb87/images/02.webp)

在内核初始化阶段，我们基于块维度 $block_M$ 构建一个描述符池（见图 1 的静态配置部分），其定义如下：

$$
\mathcal{D}_{pool }=\left\{\left[2^{i}, block _{N}\right] \mid i \in \mathbb{N}, 0 \leq i \leq\left\lfloor\log _{2}\left( block _{M}\right)\right\rfloor\right\}\tag{1}
$$

其中，$\mathbb{N}$ 表示自然数集，$\lfloor\log_2(block_M)\rfloor$ 表示对 $\log_2(block_M)$ 的结果向下取整；$\left[2^i, block_N\right]$ 表示描述符的维度配置（行维度为 $2^i$，列维度为 $block_N$）。

#### 阶段2：运行时选择

在运行时，对于每个分组 g，先计算其剩余行数 $res^g = M^g \mod block_M$（即 $M^g$ 除以 $block_M$ 后的余数，代表未填满一个完整 $block_M$ 块的行数），再确定最优描述符：

$$
\mathcal{D}_{opt }^{g}=\left[2^{\left\lfloor\log _{2}\left(res^{g}\right)\right\rfloor}, block _{N}\right]\tag{2}
$$

#### 阶段3：两阶段加载-存储

该机制通过两个协同的 TMA 操作实现：

- 将共享内存行 $\left[0, 2^{\left\lfloor\log_2(res^g)\right\rfloor} - 1\right]$ 传输到全局内存行 $\left[M^g - res^g, M^g - res^g + 2^{\left\lfloor\log_2(res^g)\right\rfloor} - 1\right]$；
- 将共享内存行 $\left[res^g - 2^{\left\lfloor\log_2(res^g)\right\rfloor}, res^g - 1\right]$ 传输到全局内存行 $\left[M^g - 2^{\left\lfloor\log_2(res^g)\right\rfloor}, M^g - 1\right]$。

该设计通过“安全重叠写入策略”确保：

::: block-1
1. 所有有效结果得以保留；
2. 严格遵守内存边界（不越界访问）；
3. 描述符的对数级可扩展性（针对 $block_M$ 的剩余行数，仅需 $\left\lfloor\log_2(block_M)\right\rfloor$ 个 TMA 描述符即可覆盖所有情况）；
4. 无论剩余块大小如何，每个剩余块仅需 2 次 TMA 操作。
:::

#### TMA 运行时选择与双阶段加载-存储示例

> 下面我们用一个例子说明。

![文章插图](/articles/2025-09-11-moe-hopper-fp8-gemm-tma-d8cfcb87/images/06.webp)

::: image-caption
图 3. TMA 运行时选择与双阶段加载-存储操作示意图。为便于演示，该配置采用 $M^g=381$、$N=128$。
:::

图 3 以输出矩阵维度为 $[M^g, N] = [253, 128]$ 的 g 组为例。

当 $block_M=128$ 时（$block_M$ 为分组 GEMM 中用于计算优化的固定行分块大小），:mdnice-bold-italic[前 128 行（白色区域）采用描述符为[128, 128]的标准 TMA 操作，而剩余（residual，指分组行数 $M^g$ 除以 $block_M$ 后余下的行数）$res^g=125$ 行（黄色区域）则需要采用我们的双阶段方法]。

根据 2.2 节的方法，我们为剩余部分选择最优描述符 $D_{opt}^g = [64, 128]$。**双阶段操作流程如下：**

::: block-1
1. **第一阶段加载-存储**：将共享内存中的第 0-63 行传输到全局内存的第 128-191 行（红色块）。
2. **第二阶段加载-存储**：将共享内存中的第 61-124 行加载到全局内存的第 189-252 行（蓝色块）。这 3 行的重叠区域可确保覆盖所有剩余行，同时避免越界写入。
:::

该策略可确保：

::: block-1
- 所有 125 行剩余行均被正确存储
- 相邻内存区域不会出现数据损坏
- 满足硬件对静态描述符的要求
:::

### 2.3 TMA 对齐感知内存管理

2.2 节提到，第二次 TMA 加载操作从行 $res^g - 2^{\left\lfloor\log_2(res^g)\right\rfloor}$ 开始，这可能导致内存对齐问题。为确保无论起始行位置如何，均满足 128 字节共享内存对齐要求，我们强制 $block_N$ 为 64 的倍数（因 FP8 数据占 1 字节，64 个 FP8 元素恰好为 64 字节，2 次传输即可满足 128 字节对齐）。

在全局内存中，$S_A^g$ 的每行偏移量为 $4\lceil K/128 \rceil$ 字节（系数 4 源于浮点数 float 的存储字节数），:mdnice-bold-italic[这可能引发对齐问题。我们通过“边界对齐预取”（boundary-aligned prefetching）解决该问题]：**调整起始地址以满足 16 字节全局内存对齐要求**。从之前数据中预取的行数 $row_{prev}^g$ 由以下公式确定：

$$
\min\left\{ \left. row_{prev}^g \right| \left( Addr_{SA}^g - 4 \cdot row_{prev}^g \cdot \left\lceil \frac{K}{128} \right\rceil \right) \mod 16 = 0 \right\}\tag{3}
$$

其中，$Addr_{SA}^g$ 表示向量分组 $S_A^g$ 的基地址（即 $S_A^g$ 在内存中的起始地址），系数 4 对应 float 数据类型的存储字节数。

后续行数 $row_{next}^g = 16 + block_M - row_{prev}^g$ 构成完整的预取窗口，且 TMA 描述符配置为 $\left[16 + block_M, \lceil K/128 \rceil\right]$ 的维度。仅中间的 $block_M$ 行（图 1 中的“有效绿色区块”）参与计算（预取的额外行仅用于对齐，不参与实际运算）。

## 三、实验

实验评估在 NVIDIA H800 GPU 加速计算平台上进行，使用 PyTorch 2.6.0 和 CUDA 12.6。我们的基线实现将显式输入填充（explicit input padding，为满足硬件对齐要求而添加无效数据的操作）与 DeepGEMM（当前主流的高性能 FP8 GEMM 实现，参考[Zhao et al., 2025]）相结合。

> 我们的优化方法与**该基线在三个关键指标上进行对比**：计算加速比、数值等价性和内存效率。

### 3.1 实验设置

实验参数空间的设计参考了现代大语言模型（LLM）的实际配置，具体如下：

- 张量维度 N、K 的取值集合：{3072, 4096, 5120, 6144, 7168, 8192}（覆盖主流 LLM 的隐藏维度与输出维度范围）；
- 分组数（对应 MoE 架构中的专家分组数量）：{4, 8, 16, 32}；
- 经 top-k 路由（MoE 架构中选择对输入贡献最大的 k 个专家的策略）后的序列长度 M：{8192, 16384, 32768, 65536}（覆盖长文本输入的序列长度范围）；
- 每个分组的维度 $M_g$ 通过随机生成得到（方法下面会详细讲解）。

我们使用 Triton（一种用于编写高性能 GPU 内核的编程语言框架）实现了矩阵 A 和 $S_A$ 的填充操作内核。:mdnice-bold-italic[该内核的 DRAM（动态随机存取内存，即 GPU 的主内存）带宽可达约 2000 GB/s（最大 2173 GB/s），确保了我们与基线对比结果的有效性] （排除了填充操作本身性能瓶颈对实验的干扰）。

#### 每个分组的维度 $M_g$ 通过随机生成方法

为生成分组维度 $M^g$（即分配给专家组 g 的动态路由序列长度），我们采用一种随机算法，生成元素和为 M（总序列长度）的 G 个分组的列表。生成过程包含以下步骤：

::: block-1
1. 初始化一个长度为 G 的零向量 V
2. 为 V 中的每个元素 $v_i$ 分配一个均匀分布在 0 到 $2\lfloor M/G \rfloor - 1$ 之间的随机整数（$\lfloor \cdot \rfloor$ 表示向下取整，即对 M/G 的结果取不大于该值的最大整数）
3. 计算缩放因子 $\alpha = M / \sum_{i=1}^G v_i$，并将其应用于每个元素：$v_i \leftarrow \lfloor \alpha v_i \rfloor$
4. 调整最后一个元素 $v_G$ 以补偿任何剩余差值：$v_G \leftarrow v_G + (M - \sum_{i=1}^G v_i)$
:::

该方法可确保生成的分组维度在满足总长度为 M 的前提下，在分组间分布中引入可控的随机性。缩放操作保留了初始随机分配的相对比例，而最终调整则保证了总长度的精确性。

**下面的两个表格是相关系数矩阵，核心作用是量化分析分组 GEMM 的关键参数** （M、N、K、groups）:mdnice-bold-italic[与两个核心优化指标（加速比、内存节省率）之间的线性关联强度]。相关系数的取值范围为 [-1, 1]：

::: block-1
- 绝对值越接近 1，相关性越强；越接近 0，相关性越弱；
- 正号表示 “正相关”（一个变量增大时另一个也增大），负号表示 “负相关”（一个变量增大时另一个减小）；
- 对角线上的 “1.00” 是变量与自身的相关系数（必然为 1），矩阵满足对称性（如 M 与加速比的相关系数 = 加速比与 M 的相关系数）。
:::

> 这两个表格的价值在于，它们**通过量化的相关系数，明确了优化方案的 “收益敏感参数”** （后文会对这两个表格进行详解）：

::: block-1
- 若需最大化加速比：应优先控制 N（输出维度）的大小，避免 N 过大；
- 若需最大化内存节省：应优先增加 groups（分组数），同时避免 M（总序列长度）过大；
- N 和 K 对两个指标均无显著影响，无需为优化这两个指标调整 N 和 K。
:::

这为实际部署（如 MoE-LLM 的训练 / 推理）提供了明确的参数调优方向。

### 3.2 性能分析

![文章插图](/articles/2025-09-11-moe-hopper-fp8-gemm-tma-d8cfcb87/images/09.webp)

> 图 2 展示了不同配置下的计算加速比和内存节省率。

#### 分析点1：计算加速比

**计算加速比（图 2a）的范围为 1.7%~20.4%：**

- 其与序列长度 M 的相关系数 r=0.09（弱正相关，即 M 增大时加速比略有上升）
- 与分组数的相关系数 r=0.096（弱正相关）
- 而与参数 N 的相关系数 r=-0.899（强负相关，即 N 增大时加速比显著下降）

观察到的:mdnice-bold-italic[加速效果源于“消除了填充操作带来的内存事务开销”] （填充的无效数据无需传输和处理）；而:mdnice-bold-italic[加速比与 N 的强负相关，则反映了“剩余数据写回开销的线性增长”] （N 越大，每次写回剩余数据时需处理的列数越多，开销越大）。

#### 分析点2：内存节省率

内存节省率（图 2b）：

- 与序列长度 M 呈强负相关（M 越小，节省率越高）
- 与分组数呈近线性正相关（分组数越多，节省率越高）。在 M=8192 且分组数为 32 的配置下，观察到的最大内存节省率达 23.8%。

:mdnice-bold-italic[这种关系源于“分组张量操作中的几何填充特性”]：当 M 较小时，每个分组的 $M_g$ 更可能小于 $block_M$，需填充的无效数据量占比更高；而分组数越多，此类“需填充的分组”数量越多，因此优化后节省的内存也越多。

#### 分析点3：数值等价性

通过“移除基线输出中的零填充元素后对比结果”，验证了数值等价性：我们的方法与基线实现的结果逐位相同（bitwise identical，即二进制层面完全一致）。:mdnice-bold-italic[这种“零误差保证”源于我们的两阶段加载-存储机制——最终的写回操作仅保留有效数据区域，不会因重叠写入破坏有效结果。]

## 四、结论

> 本文提出了 TMA-Adaptive FP8 Grouped GEMM（TMA 自适应 FP8 分组通用矩阵乘法），这是一种:mdnice-bold-italic[与硬件适配的解决方案，可消除低精度 Grouped GEMM（分组通用矩阵乘法）中需将分组填充至固定对齐倍数（例如 128 个元素）的要求。]

通过解决变长场景下关键的硬件对齐冲突——具体为**静态 TMA 描述符限制与内存边界不对齐问题** ——我们的方法:mdnice-bold-italic[在不降低数值精度的前提下，同时提升了内存效率与计算吞吐量]。

尽管我们的方法将 $block_N$（矩阵分块中 N 维度的分块大小）约束为 64 的倍数（例如 64、128、192），但这些数值在实际应用中是 N 维度的最优或近优配置。实验验证表明，该方法实现了显著改进：**与最先进的填充实现相比，内存分配开销最多降低 23.8%，端到端速度提升 1.7%–20.4%；同时数值验证确认了位级等价性，确保精度不受损失。**

通过从根本上消除填充操作，我们的解决方案为 Grouped GEMM 建立了一种创新范式，在减少内存占用的同时实现了更优的计算效率，并且**无需对分组通用矩阵乘法之外的内核进行修改，即可与动态路由实现无缝即插即用。**

> 至关重要的是，**本研究直接助力混合专家模型** （MoE，Mixture of Experts）大语言模型（LLM）：:mdnice-bold-italic[通过在动态专家路由过程中最小化延迟与内存开销，加速了推理与训练过程]，从而为高性能 MoE LLM 的可扩展部署提供了支持。
