> 大 batch 和长上下文的 LLM 解码受限于从高带宽内存加载键值（KV）缓存，这会增加每个 Token 的延迟，而解码的顺序性又限制了并行性。

我们**分析了算术强度、并行化和模型质量之间的相互作用**，并:mdnice-bold-italic[质疑当前架构] 是否充分利用了现代硬件。

::: block-1
:mdnice-bold-italic[这项工作重新设计了注意力机制]，以在从内存加载的**每字节数据上执行更多计算**，从而在不牺牲并行可扩展性的情况下**最大化硬件效率**。

- 我们首先提出:mdnice-bold-italic[分组绑定注意力] （GTA，Grouped Latent Attention），这是一种简单的变体，它结合并重用键和值状态，在**不影响模型质量的情况下减少内存传输**。
- 然后我们引入:mdnice-bold-italic[分组潜在注意力] （GLA），这是一种**支持并行** 的潜在注意力，配合底层优化实现快速解码，同时保持高模型质量。
:::

实验表明：

1. **GTA** 在质量上与分组查询注意力（GQA）相当，但使用的:mdnice-bold-italic[KV 缓存约为其一半]；
2. **GLA** 在质量上与多头潜在注意力（MLA）相当，且**更易于分片**。例如，在查询长度超过 1 的推测性解码场景中，我们优化的 GLA 内核**比 FlashMLA 快达 2 倍**。此外，通过在每个设备上获取更小的 KV 缓存，GLA 在在线服务基准测试中使**端到端延迟降低、吞吐量提高达 2 倍**。

## 一、引言

> 鉴于测试时计算（OpenAI，2024）的重要性，推理效率现在成为 AI 发展的驱动力，这要求我们更加**重视支持推理的架构**。**逐个 Token 解码的顺序性限制了并行化的机会**。

在解码过程中，多头注意力（MHA）（Vaswani 等人，2017）会缓存所有先前 Token 的键值（KV）状态。这些缓存状态随批次大小和序列长度呈线性增长，并迅速耗尽高带宽内存（HBM）。

此外，从:mdnice-bold-italic[片外内存获取这个大型 KV 缓存占据了执行时间的主要部分]，远远超过每个解码步骤中矩阵向量工作负载所执行的相对较少的计算量。随着 KV 缓存的增长，**内存获取会增加延迟，导致 GPU 利用率低下的周期延长** （He 和 Zhai，2024）。

::: block-1
这一瓶颈阻碍了广泛的应用场景：

1. 对延迟敏感的交互式应用；
2. 用于多步推理的大批次 LLM 代理（Yu 等人，2024b）；
3. 测试时计算扩展（OpenAI，2024；Snell 等人，2024）；
4. 高吞吐量批次推理；
5. 长上下文视频建模（Wu 等人，2024）。
:::

> 总体而言，这些问题凸显了对注意力机制进行硬件高效重新设计的迫切需求。理想的注意力机制应具备以下特点：

1. 实现高模型质量；
2. 在多个设备上高效扩展；
3. 在推理时有效利用现代硬件。

---

支持推理的注意力变体可加速解码，例如：

- 多查询注意力（MQA）（Shazeer，2019）仅缓存单个 KV 头，显著减少内存使用。
- 分组查询注意力（GQA）（Ainslie 等人，2023）通过在较小的查询头组之间共享 KV 头提供了一种折衷方案，以获得更好的质量。
- DeepSeek 最近引入的多头潜在注意力（MLA）（DeepSeek-AI，2024，2025）通过低秩因子分解投影将隐藏状态压缩为联合潜在向量，并缓存大维度的单个潜在头，然后在计算注意力之前对其进行上投影。

如前所述，**这些变体减少了 KV 缓存，从而通过降低数据移动量缓解了解码过程中 MHA 的内存受限性能** （Ivanov 等人，2021；Ootomo 和 Yokota，2023；Gholami 等人，2024）。遗憾的是，现代加速器的计算能力已经超过了内存带宽的增长（Ghose 等人，2018）。

> 算术强度（Williams 等人，2009），即算术运算与内存访问字节数的比率（每字节 FLOPs 数），通常用于分析工作负载是受内存限制还是受计算限制。

- :mdnice-bold-italic[MQA] 通过在所有查询头之间重用单个 KV 头来提高算术强度，减少 KV 缓存内存的占用，从而缩短从高带宽内存重新加载的时间，同时保持 FLOPs 不变，但会牺牲质量和并行性（Pope 等人，2022）。
- :mdnice-bold-italic[GQA] 略微增加了算术强度（与组大小成比例），并在推理期间高效扩展。然而，在中等张量并行度下，每个 GPU 仍然存储相当大的 KV 缓存，并且对于大组大小，模型质量会下降。
- 另外，:mdnice-bold-italic[DeepSeek] 在解码期间吸收其低秩 MLA 投影矩阵，并直接使用单个潜在头计算注意力，相对于 MQA 有效地将算术强度提高了一倍。然而，MLA 本质上在所有设备上复制潜在向量，限制了并行推理能力。

> 在这项工作中，我们:mdnice-bold-italic[从算术强度的角度重新设计了硬件高效的注意力变体]，**重点关注解码阶段的扩展性**，同时保留模型质量。

我们将组大小 $g_q$ 定义为每个不同 KV 头对应的查询头数量；该组大小在很大程度上决定了算术强度。:mdnice-bold-italic[提高 $g_q$ 会提高算术强度，并按比例缩小 KV 缓存]。然而，**超过某个阈值后，$g_q$ 的进一步增加会在每字节内存访问的更高操作数（有效 GPU 利用率）与并行化之间进行权衡**，这会迫使投影权重和 KV 缓存在设备间复制，从而降低并行可扩展性。

在这些设计原则的指导下，我们提出了两种注意力变体，它们将高算术强度与跨设备的高效扩展相结合，并辅以底层优化。为**了将这些设计选择转化为实践，我们的内核通过异步软件流水线和 warp 专业化将计算与内存重叠，采用分页 KV 的协作偏移计算器**，从而使张量核心保持满负荷运行，推动内核从内存受限转向计算受限。

- 我们首先探索了:mdnice-bold-italic[分组绑定注意力] （GTA），它将键和值表示绑定到一个共享状态中，供小的查询头组使用。GTA 可以减少 KV 缓存大小，并在相同组大小下相对于其 GQA 对应变体将算术强度提高多达 2 倍，同时保留质量和并行性。
- 我们提出了:mdnice-bold-italic[分组潜在注意力] （GLA），这是一种支持并行的潜在注意力扩展，受益于底层优化。GLA 实现了与 MLA 相似的质量，并且速度可快达 2 倍；例如，在推测性解码中，当查询序列长度为 2 或更长时。在在线服务基准测试中，GLA 将端到端延迟降低并将 Token 吞吐量提高达 2 倍。

**我们在 FineWeb-Edu 数据集上训练的中等规模语言建模实验中展示了这些变体的有效性**。在 XL 模型（147 亿参数）中，GTA 的困惑度为 10.12（GQA 为 10.20），GLA 的平均下游准确率为 60.0%，困惑度为 10.21（MLA 为 59.1%和 10.25）。在大型模型（8.76 亿参数）中，GTA 实现了 11.2 的困惑度和 57.6%的平均下游准确率（优于 GQA 的 11.3 和 56.9%）。对于中型模型（4.33 亿参数），GLA 的平均下游准确率为 55.4%，略高于 MLA 的 54.9%。

:mdnice-bold-italic[我们将算法设计与一系列底层优化相结合，使注意力解码内核比 FlashMLA 1（Li，2025）快 1.22 倍]。

## 二、预备知识

### 2.1 支持推理的注意力

- :mdnice-bold-italic[多查询注意力（MQA）] （Shazeer, 2019）减少了多头注意力（MHA）中的 KV 缓存大小，从而加速了解码。它**缓存一个由所有查询头共享的 KV 头**。然而，这种激进的共享会牺牲模型质量，并且在头部级别进行工作划分的分布式推理中，每个设备必须复制单个 KV 头以保持其可访问性，从而抵消了内存节省（Pope 等人, 2022）。
- :mdnice-bold-italic[分组查询注意力（GQA）] （Ainslie 等人, 2023）通过**对查询头进行分组以共享不同的 KV 头来解决这些问题**。这种方法在**分布式推理中无需额外内存开销即可消除 GPU 之间的大部分复制**。因此，相对于标准 MHA，它减少了 KV 缓存大小，同时提高了模型质量。为了保持质量，它需要中等数量的组；因此，当仅使用少数设备时（如张量并行度为 2），长序列或大批次的每设备 KV 缓存可能会迅速超过 HBM 容量。只有使用许多设备（如八路拆分）时，每设备 KV 缓存才会显著缩小。
- :mdnice-bold-italic[多头潜在注意力（MLA）] 最初在 DeepSeek V2（DeepSeek-AI, 2024）中引入，并通过其在 DeepSeek R1（DeepSeek-AI 等人, 2025）和 FlashMLA（Li, 2025）中的应用重新受到关注。它**将每个 Token 的隐藏状态压缩为低秩潜在向量 $c^{KV}$，仅缓存该向量，然后将其投影回全头的键和值以保留不同的头特征**。为了进一步减少内存，其设计仅为键和值缓存单个头的低秩联合表示，而不是分开的表示。**在解码期间，键的上投影 $W^{UK}$ 被吸收到查询矩阵 $W^Q$ 中，值的上投影 $W^{UV}$ 被吸收到输出矩阵 $W^O$ 中**。因此，显式的键或值从未具体化；相反，每个查询直接关注潜在向量 $c^{KV}$。
- :mdnice-bold-italic[MLA] 通过**将小的解耦旋转位置编码（RoPE）（Su 等人, 2023）与潜在向量连接**，在压缩路径之外保留位置信息，从而允许权重吸收技巧。得到的预填充计算为 $\sigma(QK^T + Q_{\text{rope}}K_{\text{rope}}^T) \cdot V$。

### 2.2 分布式推理

顺序解码将注意力组件的并行化机会限制为仅头部轴。**张量并行（TP）通过激活的频繁同步（如全收集）在设备间划分注意力层**。这种开销通过快速 GPU 互连（如 NVLink）（NVIDIA Corporation, 2024）得到缓解。

与数据并行（DP）（Li 等人, 2020）不同，TP 避免了每个 GPU 复制整个模型，这对于大型模型来说是不现实的。它还避免了逐 Token 解码期间 GPU 闲置的问题，这是流水线并行（PP）（Narayanan 等人, 2021）的一个限制，该方法将模型拆分为顺序阶段。

> 张量并行在解码期间更受青睐，因为它在 GPU 间分配权重，减少了处理单个 Token 时加载 KV 缓存的瓶颈（Su 等人, 2025）。

### 2.3 硬件特性

- :mdnice-bold-italic[GPU 架构概述]：现代 GPU 由大量计算单元（如浮点单元）组成，排列成流式多处理器（SM），并具有内存层次结构。除了常规浮点单元外，NVIDIA GPU 包含专门用于低精度矩阵乘法的张量核心。内存层次结构由高带宽内存（HBM）和片上 SRAM（通常称为共享内存）组成。例如，NVIDIA H100 GPU 具有 80 GB HBM3，带宽为 3.35 TB/s，每个 SM 上有 256 KB SRAM，整个芯片共有 132 个 SM，芯片 SRAM 总带宽约为 33 TB/s（NVIDIA, 2022）。
- :mdnice-bold-italic[执行模型]：GPU 运行内核，每个内核由许多线程组成，分组为线程块，并在 SM 上调度。在每个块内，线程被组织成 32 线程的 warp，它们可以通过快速混洗指令或片上共享内存共享数据。每个内核将数据从 HBM 加载到寄存器和片上 SRAM（即共享内存），执行必要的计算，并将结果写回 HBM。
- :mdnice-bold-italic[性能特性]：根据计算和内存访问之间的平衡，操作可分为计算受限或内存受限，通过算术强度（Williams 等人, 2009）衡量，定义为每访问字节的算术运算次数。当执行时间主要由算术运算主导，内存访问时间相对较小时，操作是计算受限的。相反，如果内存访问主要主导执行时间，则工作负载是内存受限的。

## 三、方法论

> 我们通过关注算术强度来描述设计硬件高效注意力变体的观点。然后，我们演示如何通过绑定键值状态和分片缓存的潜在表示，在高效跨设备并行化的同时最大化算术强度。

#### 3.1 解码中的算术强度：硬件高效视角

**在顺序解码期间，训练或预填充期间使用的大型通用矩阵乘法（GEMM）工作负载转变为较小的批量通用矩阵向量乘法（GEMV）**。缓存的键矩阵的每个加载的 BF16（2 字节）元素与寄存器中已有的单个 Token 查询元素执行一次乘加（MAC）（2 FLOPs），产生 1:1 的 FLOP 与字节比率。这种算术强度远低于 NVIDIA Hopper H100 SXM GPU 的密集 BF16 理论上限（NVIDIA, 2022），约为 295 FLOPs/字节（$\frac{989 \text{ TFLOPS}}{3.35 \text{ TB/s}}$），导致张量核心严重未充分利用。:mdnice-bold-italic[本质上，分布式推理中的总体延迟受以下最慢者限制]：GPU 以峰值计算完成所有 FLOPs 的时间、以峰值内存带宽传输必要数据的时间，或可用互连带宽下的设备间通信延迟（Pope 等人, 2022；Austin 等人, 2025）。实际上，在中等 TP 度（如八路分片）下，重复加载大型 KV 缓存主导了解码延迟（Recasens 等人, 2025）。

**标准 MHA 的 GPU 利用率在解码期间可低至 7%（Recasens 等人, 2025），其算术强度如表 1 所示约为 1**。:mdnice-bold-italic[理论上，它可以在不增加延迟的情况下容纳大约两个半数量级的更多 FLOPs]。然而，由于内核开销、有限的重叠和其他效率问题，实际加速自然较小。这种低利用率反映了最新 GPU 代际的计算吞吐量与内存带宽之间的日益扩大的差距。:mdnice-bold-italic[现代 GPU 将更多的硅面积用于计算而非内存带宽，这一趋势在 2017 年加剧] （见附录 B.7，如下图 15（右））。

> 硬件 FLOPs 每两年扩展约 3 倍，而 HBM 内存带宽同期增加约 1.6 倍（Gholami 等人, 2024）。

**为了缓解带宽限制并增加解码期间的算术强度，从业者可以融合内核并平铺数据以最大化片上重用**，:mdnice-bold-italic[选择性地重新计算小中间结果而不是存储它们]，或采用:mdnice-bold-italic[专门的注意力重新排序以减少片外传输] （Dao 等人, 2022），而不改变注意力的设计。

### 3.2 最大化算术强度的设计策略

GQA 是一种通用的注意力公式，可在每个查询头组之间重用一个加载的 KV 头。由于共享 KV 头不会减少操作次数（每个查询头仍计算其注意力分数），但会减少内存读取，因此算术强度与组大小 $g_q$ 或每个不同 KV 头对应的查询数成比例增加（见表 1）。例如，在 MQA 中，单个 KV 头在所有查询头之间重用，算术强度约为查询头数 $h_q$。

![文章插图](/articles/2025-07-11-70-53-flashmla-2-ttft-882f73d7/images/06.webp)

DeepSeek 引入的 MLA 采用以推理为中心的设计，吸收低秩矩阵以避免具体化 KV 状态，从而:mdnice-bold-italic[通过三个因素实现高算术强度]：**缓存单个头潜在向量**、**为键和值重用潜在向量**，以及**采用大量查询头**。

最初，**MLA** 加载单个潜在头并在所有查询头之间重用它，类似于 MQA。加载到片上内存的精确潜在表示现在在计算注意力时同时用作键和值状态，**相对于最激进的 MQA 设计，有效地将算术强度提高了一倍** （见图 1 左，MLA 内存加载示意图）。尽管 DeepSeek 的论文（DeepSeek-AI, 2024）没有明确讨论这一点，但使用低秩投影（减少参数数量）来缩小潜在缓存也开辟了增加上投影矩阵列维度以恢复丢失参数的可能性。:mdnice-bold-italic[换句话说，模型可以重新分配释放的参数预算以添加更多查询头，潜在地保留模型容量并通过在更多查询头之间共享单个潜在头来增加解码期间的算术强度]。如表 1 所示，算术强度取决于查询头的数量。通常，增加 $g_q$ 会减少 KV 缓存大小并增加算术强度，有效最大化 GPU 利用率。设 $m_{kv} \in {1, 2}$ 表示 KV 的重复数，其中 $m_{kv}=1$ 当 $K=V$（共享状态），$m_{kv}=2$ 当 $K \neq V$（不同状态）。与增加组大小 $g_q$ 相反，将 $m_{kv}$ 从 1 增加到 2 会增加 KV 缓存并降低算术强度。

![文章插图](/articles/2025-07-11-70-53-flashmla-2-ttft-882f73d7/images/07.webp)

图 2 对分组绑定注意力（GTA）概述。单个投影生成一个同时用作键和值的 KV 状态。完整的绑定 KV 维度用作值。对于键，键维度的一半来自绑定 KV 向量（未应用位置编码），另一半来自隐藏状态的单独单头投影（应用了 RoPE）；这一单独的一半被广播到组中的所有头，并与绑定 KV 的一半连接。相对于具有相同组数的 GQA，GTA 大致将算术强度提高一倍，并将 KV 缓存大小减半。

$$
m_{kv} =
\begin{cases}
1 & \text{如果 } K=V \text{（绑定状态）} \\
2 & \text{如果 } K \neq V \text{（分离状态）}
\end{cases}
$$

$$
\text{KV字节数} = m_{kv} \cdot B \cdot L \cdot \frac{h_q}{g_q} \cdot d_h \times \text{数据类型大小}
$$

$$
\text{算术强度} \approx \frac{2 \cdot L \cdot h_q}{2 \cdot h_q + \frac{m_{kv} \cdot h_q}{g_q} L} \approx \frac{2 \cdot g_q}{m_{kv}} \quad (L \gg h_q)
$$

这里，$B$ 是批次大小，$d_h$ 是每头维度。此外，通过更大的 $g_q$ 增加算术强度需要在并行化能力上进行权衡。这种约束可以通过 $g_q$ 的边界来量化。尽管增加 $g_q$ 会增加算术强度，但如果 $g_q$ 相对于设备数量增长过大，它会复制参数并减少并行化收益。一旦复制因子 $D$ 等于 $N$（其中 $N$ 是 TP 分片数），每个机器都有一个完整的参数和 KV 缓存副本；此时，模型并行性不再受益。对于零冗余并行，KV 头数 $h_{kv} = h_q / g_q$ 应至少为 $N$ 且最多为 $h_q$，即 $g_q \leq h_q / N$。实际上，复制因子（即每组 KV 头在 $N$ 个分片中存在的副本数）为：

$$
D = \left\lceil \frac{N \cdot g_q}{h_q} \right\rceil, \quad 1 \leq D \leq N
$$

$$
\text{零冗余边界：} D=1 \Leftrightarrow g_q \leq \left\lfloor \frac{h_q}{N} \right\rfloor
$$

### 3.3 硬件高效且可并行的注意力

#### 3.3.1 分组绑定注意力（GTA）

奇异值图显示键缓存的方差急剧衰减，几乎所有方差都由几个主方向捕获，因此键位于低秩子空间中，具有高度冗余（Saxena 等人, 2024）。在应用 RoPE 之前，这种效应更为显著，此时键会坍缩到甚至更小的子空间（Yu 等人, 2024a；Sun 等人, 2024）。同时，**多项研究表明，对头部维度的一部分应用 RoPE 可保留准确性，因此旋转整个宽度几乎不会带来额外质量** （Black 等人, 2022；Barbero 等人, 2025）。

如果键本质上是低秩的，并且每个头仅需要一部分维度进行旋转以进行位置编码，那么旋转每个通道并缓存全秩键张量会浪费内存。相反，我们可以仅旋转位置信息所需的头部维度的一部分；剩余的未旋转通道（往往位于低秩子空间且冗余）可以与值状态共享或绑定。GQA 已经通过让多个查询头共享一个不同的 KV 头来减少 KV 缓存和内存传输，并且在多个设备上高效扩展。

> 基于 GQA 的分组设计，结合上述低秩和部分 RoPE 的见解，我们提出分组绑定注意力（GTA），它统一了分组、将 KV 绑定到单个状态，并部分应用 RoPE，所有这些都是为了在保留质量的同时减少 KV 缓存大小。

![文章插图](/articles/2025-07-11-70-53-flashmla-2-ttft-882f73d7/images/07.webp)

在 GTA 中，与 GQA 类似，每个查询头组共享一个不同的 KV 头。GTA 更进一步，将键和值投影参数绑定到单个状态，称为绑定 KV，其形状与单个键或值向量匹配（见图 2，GTA 和 GQA 架构差异示意图）。值路径消耗绑定 KV 状态的全维度，而键路径仅重用其前一半作为未旋转的部分。键的剩余 RoPE 组件来自隐藏状态的单独单头投影，广播到所有组，并与未旋转的一半连接以形成完整的键向量。**实证消融表明，即使在值路径重用前对旋转进行反转，对共享部分应用 RoPE 也会降低质量，因此绑定部分从不旋转**。经过这些步骤后，查询、键和值状态定义如下：

$$
Q \in \mathbb{R}^{B \times L \times h_q \times d_h}, \quad KV, K, V \in \mathbb{R}^{B \times L \times h_{kv} \times d_h}, \quad K_{\text{RoPE}} \in \mathbb{R}^{B \times L \times 1 \times \frac{d_h}{2}}, \quad K_{\text{NoPE}} \in \mathbb{R}^{B \times L \times h_{kv} \times \frac{d_h}{2}}
$$

$$
K_{\text{NoPE}} = KV\left[:,:,:,: \frac{d_h}{2}\right], \quad V = KV[:,:,:,:], \quad K = \text{concat}\left(K_{\text{NoPE}}, \text{broadcast}\left(K_{\text{RoPE}}, h_{kv}\right)\right)
$$

**通过绑定 KV 状态，我们将单个状态加载到片上内存，为键和值重用它，并在一小组查询头之间共享它。这种重用减少了内存传输，大致将算术强度提高一倍**，并将 KV 缓存占用量相对于具有相同组数的 GQA 对应变体减半。GQA-4 表示四个不同的键和值头，而 GTA-4 表示四个绑定 KV 头。实验表明，困惑度（见 5.1.1）和下游任务性能（见 5.1.2）与 GQA 对应变体相当。

#### 3.3.2 分组潜在注意力（GLA）

MLA 的低秩 KV 联合压缩为每个 Token 缓存一个维度为 $d_c = 4d_h$ 的单潜在头。由于张量并行以列并行方式在 ranks 间划分键和值上投影 $W^{UK}, W^{UV} \in \mathbb{R}^{(4d_h \times h d_h)}$，每个设备必须保留整个潜在向量以重建其头部的键和值。因此，潜在 KV 缓存在每个张量并行 rank 中复制，使总 KV 缓存占用量随 rank 数成比例增长。相比之下，当 $d_c < 2h_{kv}d_h$ 且 $h_{kv} > 2$ 时，GQA 每个 Token 存储 $2h_{kv}d_h$ 个元素，其 KV 缓存比 MLA 更大。然而，对于四路张量并行配置，MLA 和 GQA-8 的每设备 KV 缓存大小大致相同，尽管 GQA-8 从基础模型分配的 KV 缓存字节数约为 MLA 的 4 倍。**MLA 设计实现了高算术强度，但通过所有头共享潜在向量来增加算术强度的方式会阻碍分片划分** （详见 3.2 节），因此，预期的头部级并行带来的每设备内存减少效果减弱，限制了分布式推理中的并行效率。

**我们提出分组潜在注意力（GLA），将 Token 压缩为 $h_c$ 个潜在头，每个头维度为 $d_c = 2d_h$（MLA 的 $4d_h$ 的一半）**。训练期间，每个潜在头及其上投影矩阵为其组内的查询头重建不同的键和值特征。因此，一个潜在头的上投影矩阵的列维度为 $g_q d_h$，而非 MLA 的 $h_q d_h$，其中 $g_q = h_q / h_c$ 是组大小或每个不同潜在头对应的查询数。**解码期间权重吸收后，每个潜在头仅关注其组内的查询头**。

- 当 $h_c = TP$ 时，跨张量并行 rank 对潜在头进行分片可实现头部级并行且不复制潜在 KV 缓存；
- 否则，当 $h_c \leq TP$ 时，可减少缓存复制，从而实现高效的分布式扩展。

为具体说明，我们以 $h_c = 2$ 个潜在头的 GLA 为例，其保留与 MLA 相同的 KV 缓存大小（$4d_h$），但当 $TP \geq 2$ 时，每设备 KV 缓存减半。设置 $TP = 2$，GLA 将潜在向量拆分为两个头 $c_0^{KV}$ 和 $c_1^{KV}$，并将查询头分为两组。解码期间，每个 TP rank 使用分配的潜在头和查询组计算局部注意力，应用其输出投影切片，然后参与全归约以将部分输出求和为最终结果。形式化表示为：

$$
c_0^{KV}, c_1^{KV} \in \mathbb{R}^{B \times L \times 2d_h}, \quad Q_0, Q_1 \in \mathbb{R}^{B \times 1 \times \frac{h_q}{2} \times (2d_h)}, \quad W_0^{vo}, W_1^{vo} \in \mathbb{R}^{\left(\frac{h_q}{2} \cdot 2d_h\right) \times D},
$$

$$
O_0 = \text{softmax}\left(Q_0\left(c_0^{KV}\right)^{\top}\right) c_0^{KV}, \quad O_1 = \text{softmax}\left(Q_1\left(c_1^{KV}\right)^{\top}\right) c_1^{KV},
$$

$$
\tilde{O}_0 = O_0 W_0^{vo}, \quad \tilde{O}_1 = O_1 W_1^{vo},
$$

$$
O = \text{AllReduce}\left(\tilde{O}_0 + \tilde{O}_1\right).
$$

当 MLA 在 TP+DP 混合设置中运行以减少 KV 缓存复制时，序列长度不均会导致负载不平衡，因为处理短序列的 GPU 会闲置，直到长序列处理完成，这对延迟敏感的工作负载不利。较小的批次（低于 DP rank 数）也会使许多计算单元闲置。MLA 的较大潜在头维度 $4d_h$ 可能导致长序列或大批次时每设备 KV 缓存耗尽，从而相对于 GLA 限制批次大小或上下文长度。

例如，GLA-4 将潜在向量分片为 4 个头，每个头维度 $2d_h$；在相同配置（$TP=4$，$DP=2$）下，其每设备缓存减半，每步获取更小的缓存，但 KV 缓存大小是 MLA 的两倍。在我们的实验中，我们为 GLA 设置 $h_c = 2$，与 MLA（$d_c = 4d_h$）的 KV 缓存大小相同，此时 GLA 在 147 亿参数模型中质量与 MLA 相当（见 5.1 节实证结果），同时当 $TP \geq 2$ 时每设备缓存占用减半。每设备更小的缓存还允许 GLA 降低 DP rank 数，同时增加 TP 度，提高对工作负载不平衡的容忍度。

![文章插图](/articles/2025-07-11-70-53-flashmla-2-ttft-882f73d7/images/06.webp)

## 四、系统优化：异步与分布式偏移计算

> 我们描述了在 H100 GPU 等现代硬件上为 MLA、GTA 和 GLA 实现峰值性能的系统优化。

得益于 Tensor Core 等极快的专用矩阵乘法单元（第 2.3 节），我们:mdnice-bold-italic[需要通过内存加载和 Tensor Core 指令的精心软件流水线设计，始终保持张量核心忙碌]。这通过 warp 专业化技术实现，以利用现代硬件的异步特性。

### 4.1 软件流水线与 warp 专业化的异步性

我们使用两种技术来重叠计算和内存加载：

1. **软件流水线**：我们在计算当前 KV 块时加载下一个 KV 块。这种经典技术（Lam, 1988）避免了张量核心等待内存加载。
2. **warp 专业化**：我们让不同的 warp 分别执行使用 TMA（张量内存加速器）或异步复制（cp.async 指令）的内存加载，以及矩阵乘加（MMA）计算。前者作为生产者 warp，后者作为消费者 warp（Bauer 等人, 2014）。这常用于矩阵乘法（Thakkar 等人, 2023）和注意力（Shah 等人, 2024a）。这种解耦简化了软件流水线，允许 warp 调度器重叠内存加载和计算。

### 4.2 分页 KV 的分布式偏移计算

> 随着 MLA、GTA 和 GLA 等新注意力变体对计算和内存子系统的压力增大，必须尽可能快速地执行内存加载。

分页 KV（Kwon 等人, 2023）已成为存储 KV 缓存的标准方式。然而，:mdnice-bold-italic[分页 KV 难以使用 TMA] （一种执行地址计算和边界检查以加载连续内存块的专用硬件单元）。相反，我们使用异步复制指令（cp.async），其中每个线程单独发出加载指令。挑战在于地址计算成本惊人，因为它需要 64 位整数索引，这转化为每个整数乘法的多条指令。**因此，我们让同一 warp 中的多个线程协作计算地址**。

::: block-1
例如，对于头维度 128，要从全局内存向共享内存加载 128×128 大小的块，我们使用 128 个线程，每组 16 个线程加载一行：

1. 将 128 个线程分为 8 组，每组 16 个连续线程。每个组 $g$（$g=0,1,...,7$）负责加载行 $g, g+8, ..., g+120$。
2. 对于每个线程 $t$（属于组 $g=\lfloor t/16 \rfloor$），从行 $g + (t \bmod 16) \times 8$ 的页表中读取页索引。使用页索引计算对应行的分页 KV 的全局内存地址，并存储在寄存器中。
3. 对于行 $r \in \{g, g+8, ..., g+120\}$，同一组中的所有 16 个线程通过 warp 混洗从线程索引 $g \times 16 + (r-g)/8$ 获取全局内存地址。使用该地址加载对应行的 KV 缓存元素。
:::

我们发现**每个线程只需存储 1 行的地址偏移** （而非 16 行），因为分配给每组的 16 行的地址偏移分布在 16 个线程中。这使得任意页大小（如页大小 1）的效率很高，尽管地址计算量更大，但页大小 1 与页大小 64 的速度相同。**这解锁了前缀缓存** （Kwon 等人, 2023）**与 RadixAttention** （Zheng 等人, 2024b）**等需要页大小 1 的用例**。我们在附录 B.5 中:mdnice-bold-italic[对 GLA 的分页 KV 速度进行了基准测试，显示速度提升 1.2-1.5 倍。]

![文章插图](/articles/2025-07-11-70-53-flashmla-2-ttft-882f73d7/images/10.webp)

## 五、实验与结果

> 我们通过实验验证，我们的简单方法 GTA 和 GLA 有如下特点：

1. 实现了与 GQA 和 MLA 相当的质量
2. 易于并行化
3. 在 H100 GPU 等现代硬件上高效运行

例如，GLA 实现了与 MLA 相似的上下游质量，但更易于分片，且我们的 GLA 内核在推测性解码设置中比 DeepSeek 的 FlashMLA 快达 2 倍。$GLA_q$ 表示查询潜在向量被分片的配置，消除了设备间下投影的复制，减少了每设备参数数量；我们主要将此变体作为消融实验包含，因为查询潜在向量不缓存。

### 5.2 并行化

**GLA 通过对潜在头进行分片在 GPU 间扩展，减少内存流量以实现更快解码**。带张量并行（TP）的 MLA 反而在每个 GPU 上复制其更大维度的单潜在头；为抑制此成本，早期系统回退到混合张量和数据并行（DP）的 MLA，将不同批次序列分配给不同 GPU，这在大批次或高并发请求时有效。我们在 DeepSeek Coder V2 Base（2360 亿参数，量化为 FP8）上验证 GLA 的可扩展性，使用 SGLang 框架（Zheng 等人, 2024b）和 FlashAttention 3 内核进行基准测试。

实验比较了八块 H100 GPU 上的纯 TP 与混合 TP+二路或四路 DP。在混合设置中，仅注意力子模块在 DP 组间复制；其输出在 MoE 前馈层前全收集，然后重新分配以缓解 MLA 的 KV 缓存复制。GLA 的零冗余分片配置（潜在头均匀分布在 TP ranks 间）在等效并行配置下优于 MLA，因为每设备获取的潜在 KV 缓存更小。

![文章插图](/articles/2025-07-11-70-53-flashmla-2-ttft-882f73d7/images/08.webp)

图 4（右）显示，在 64 个并发请求下，八块 GPU 上的 GLA-8（$h_c=8$，$d_c=256$）吞吐量是单头潜在 MLA（$d_c=512$）的 2 倍，因为每设备加载的 KV 缓存更小。该优势在混合并行下得到延续：GLA-8（TP=8）优于 MLA（TP=2，DP=4），即使在 TP 和 DP 混合的等效设置中，潜在头无复制分片的 GLA 仍领先。同时，纯 TP=8 的 GLA-8 仍可超越混合 TP+DP 的 MLA。GLA 的并行友好设计可提升峰值吞吐量，并对不利的服务负载保持弹性。实际工作负载常存在序列长度不平衡或小批次，导致延迟效应和 GPU 闲置。

### 5.3 速度

我们对 MLA（1 个潜在头，维度 512，RoPE 维度 64）和 GLA（2 个潜在头，各维度 256，RoPE 维度 64）的解码内核进行基准测试，使用分页 KV（页大小 64）。

我们将 GLA 实现与可找到的最优化 MLA 实现（DeepSeek 的 FlashMLA（Li, 2025））进行比较。我们的 GLA 内核在标准解码设置（查询长度 1）中**比 FlashMLA 快约 20%，在推测性解码设置** （查询长度 2）中**快超 2 倍**。

我们的 GLA 内核在 H100 GPU 上**达到最高 93%的内存带宽利用率和 70%的 TFLOPS 利用率**，最大化了内存和计算子系统的使用。

## 六、讨论

我们讨论相关工作、局限性和一些未来方向。

### 相关工作

相关工作方面，**有不少预训练期间减少 KV 缓存的注意力机制**，我们调查了更广泛的**硬件高效设计**，并将相关工作扩展到涵盖更快 LLM 解码的事后策略、应用部分 RoPE 的研究以及低秩投影，**这些见解塑造了我们的方法**。

### 局限性

> GTA 相对于具有相同 KV 头数的 GQA，将未分片的 KV 缓存大小减少了约一半，主要通过每个头缓存一个绑定状态。

- 当 TP=8 且有八个 KV 头时，GTA-8 每个 Token 存储 $1.5d_h$，其中 $\frac{d_h}{2}$ 来自单独的 RoPE，而 GQA-8 存储 $2d_h$，最小节省 25%。
- 然而，对于八个 KV 头和 TP=4，差距扩大，因为 GTA-8 每个 Token 分配 $2.5d_h$，而 GQA-8 使用 $4d_h$，因此**中等 TP 度提供更大的内存缓解**。
- 我们的 GLA 实验利用两个潜在头来匹配 MLA 的未分片 KV 缓存大小，其中当 TP≥2 时，GLA 每设备 KV 缓存减半，而 MLA 在设备间复制 KV 缓存。在 147 亿参数规模下，模型质量仍相当。

### 未来工作

> **下一步，值得评估具有更多潜在头的更大规模模型**，同时将头维度固定为 $2d_h$，以进一步验证 GLA 的性能。

例如，Llama 4 系列模型（参数达 4000 亿）采用 GQA-8（$h_q=40$，$h_{kv}=8$），在 TP=8 度下，每设备每个 Token 的 KV 缓存大小为 $2d_h$，超过此度会复制缓存。匹配的 GLA-8（八个潜在头）每个设备每个 Token 将缓存略多的 $2.5d_h$（其中 $\frac{d_h}{2}$ 来自解耦 RoPE）；**GLA-8 在缓存预算相近的情况下是否比 GQA-8 质量更好仍是一个开放问题**。根据我们 147 亿参数规模的实验，GLA-2 在 FineWeb-Edu 上的验证困惑度为 10.218，而 GQA-4 为 10.202。此外，如 Cohere（Yang 等人, 2025）和 Llama 4（Meta AI, 2025）所示，通过仅在部分层应用 RoPE，可以减轻每 Token$\frac{d_h}{2}$ 的 KV 缓存开销。我们将这些扩展研究留待未来工作。

第 3.2 节表明，:mdnice-bold-italic[算术强度随查询头数扩展]。附录 B.3 提出消融实验，:mdnice-bold-italic[用低秩版本替换完整的查询和输出投影以减少参数]。减少的容量通过扩大列维度来补偿，为 GQA 和 GTA 的每组添加额外查询头。消融实验旨在提高质量（或在进一步减少 KV 缓存时保持质量），同时提高算术强度，有效改善 GPU 利用率。在少数 ranks 和查询头的消融中，验证困惑度比基线略差 0.1 到 0.2，这种权衡的详细研究留待未来工作。

最后，可能进一步**利用现代硬件，探索并行化和算术强度在其他架构** （如 Mamba（Gu 和 Dao, 2024；Dao 和 Gu, 2024）**和线性注意力** （Yang 等人, 2024））中的**相互作用**。

## 七、结论

> 我们证明，关注高算术强度和有效并行化可在解码时产生硬件高效的注意力机制。

我们引入**分组绑定注意力（GTA），其绑定键值（KV）状态**，相对于具有相同组数的 GQA，**KV 缓存需求约减半，算术强度翻倍**。GTA 的困惑度低于 GQA 基线，平均下游准确率更高。

::: block-1
然后我们提出分组潜在注意力（GLA），这是一种**支持并行的、面向推理的注意力变体，实现了高算术强度**，并展示了**解码速度比基线 DeepSeek FlashMLA（Li, 2025）快达 2 倍**。
:::

在所有评估的模型规模和基准测试中，**GLA 始终匹配或超过 MLA 的准确率**。此外，通过在设备间分片潜在头（每设备头维度小于 MLA），:mdnice-bold-italic[GLA 在解码期间获取更小的 KV 缓存，在在线服务基准测试中使端到端延迟降低、吞吐量提高达 2 倍]。因此，GTA 有效替代 GQA（仅需一半 KV 缓存内存），而 :mdnice-bold-italic[GLA 因其跨 GPU 的可扩展分区和更快的解码速度，成为 MLA 的实用替代方案]。
