## 一、引言

### 1.1 大型语言模型的分类与特点

大型语言模型（LLMs）已成为现代人工智能的基石，在从自然语言理解到文本生成的一系列领域中展现出卓越能力 [1,2,3,4,5]。

> LLMs 可分为两种主要类型：生成式 LLMs 和非生成式 LLMs。

- **非生成式** LLMs，如 BERT [6]、RoBERTa [7]、ELECTRA [8] 和 DeBERTa [9]，**旨在基于输入文本进行分类和预测**。这些模型的参数规模通常在数百万到数十亿之间，使其能够在需要辨别和细致理解的任务中表现出色。例如，2018 年推出的 BERT 仅有 3.4 亿参数，2019 年的 RoBERTa 略微增加至 3.55 亿参数，而 2021 年发布的 DeBERTa 则增至 15 亿参数。
- **生成式** LLMs，如 GPT 系列 [10,11,12,13]、T5 [14]、OPT [15]、BLOOM [16] 和 Llama 系列 [17,18,19]，则**将语言生成提升到了新高度。**

### 1.2 生成式 LLMs 的规模演进与趋势

![文章插图](/articles/2025-06-30-llm-llm-llms-a61c8de3/images/05.webp)

如图 1 所示，过去 6 年生成式 LLMs 的模型规模增长尤为显著。

- 2018 年的 GPT1 仅有 1.1 亿参数
- 2019 年的 GPT2 增长至 15 亿参数
- 2020 年推出的 GPT3 大幅增长至 1750 亿参数，GPT3.5 保持相同规模
- 2022 年后，模型规模维持在数百亿至数千亿参数，如 GPT4、Llama3 和 Grok1 [58]。

**LLMs 的发展以模型参数的指数级增长为特征**，这提升了它们的性能和通用性。与非生成式 LLMs 相比，生成式 LLMs 因其优越的算法性能，成为当前 LLM 领域研发的主要焦点。

> 近年来，生成式 LLMs 的参数规模在 **2022 年达到万亿级后，已停止以指数速度增长**。

这一现象可由两个主要原因解释：

::: block-1
1. 随着计算量的增加，对计算能力的需求也显著上升。**硬件能力的缓慢增长**，尤其是摩尔定律 [59] 的放缓，**限制了单芯片计算能力的提升**。
2. 研究人员发现，**模型性能并非仅依赖参数数量，还与训练数据的数量和质量有关** [60]。通过提供更多**高质量的训练 token**，算法性能可进一步提升 [18,19]。
:::

与此同时，生成式 LLMs 的模型规模已**从 “增长” 转向 “稳定” 甚至 “缩小”**，更多小参数模型被发布，更适合在边缘设备上部署。

### 1.3 生成式 LLMs 与硬件能力的关联

> 生成式 LLMs 的进步与硬件能力的发展紧密交织。

由于摩尔定律的延续，从 2018 年到 2022 年，GPU 制造工艺从 12nm 进步到 3nm，**单颗 GPU 芯片的浮点性能从 130 TFLOPS 提升至 989 TFLOPS**。

- 在模型**训练阶段**，由于 CUDA 编程栈 [61] 的用户友好性和 GPU 芯片的高扩展性（如 NVLink [62]），**GPU 被广泛使用**。
- 在**推理阶段**，**CPU、GPU、FPGA 和 ASIC 等各种硬件选项展现出不同的硬件特性，可帮助提升 LLM 推理性能**。CPU 提供高可编程性，计算能力约为 4 至 70 TOPS，功耗约为 4W 至超过 200W。现代 CPU（包括某些片上系统 SoC）通过集成领域特定架构（DSA）单元来增强 AI 性能，例如 Apple M2 Ultra 中的 Neural Engine [63]、高通骁龙 8 Gen3 中的 NPU [64]，以及 Intel 的 AVX/AMX 指令集扩展 [65]。

#### GPU

GPU 擅长并行计算，计算能力在 **70 TOPS 至超过 1000 TOPS** 之间，并具有高达 **1555 GB/s** 的惊人内存带宽。

- 一方面，GPU **集成了大量 SIMD 核心和** NVIDIA V100/A100/H100 中的 **Tensor Core** [66,67,68]，或 AMD Instinct MI100/MI200/MI300 系列中的 Matrix Core [69,70,71]，以提升计算能力。
- 另一方面，GPU **支持低精度计算**，如 INT8、FP8 和 INT4 [67,68]，这允许在给定芯片面积内容纳更多乘法单元。然而，它们的功耗显著更高，范围从约 20W 到超过 700W。

#### FPGA

FPGA 提供强大的并行性和优化能力，计算性能在 **50 至 100 TOPS** 之间，且**能效更高**，功耗约为 **75 至 100W**。

::: block-1
- AMD 的 Xilinx 提供 Zynq [72]、Virtex [73] 和 Versal [74] FPGA 系列，用于边缘和云端计算。
- Zynq 系列（如 ZCU102）将 ARM 处理器与 FPGA 可编程逻辑结合，功耗为 10W-30W。
- Virtex 系列（如 VU13P）专为高性能计算和数据中心设计，提供高达 6.2 TFLOPS 的计算能力，配备 3840 个 DSP 单元，功耗范围为 30W 至 70W。
- Versal 系列（如 VCK5000）集成 AI 引擎 [75] 和高效并行计算单元，提供超过 50 TOPS 的计算能力和 4000 个 DSP 单元，功耗为 225W。
:::

#### ASIC

ASIC（如 Groq LPU [76] 和 Cerebras WSE-3 [77]）通常采用定**制架构** 设计用于**特定应用**，提供**更高的计算效率和更好的能效**。

## 二、生成式大语言模型架构

### 2.1 概述

最常见的生成式大语言模型（LLM）**基于 Transformer 结构，因其具备捕捉长期依赖关系的能力** [87]。生成式 LLM 的推理过程包含两个阶段：预填充阶段（prefill stage）和解码阶段（decode stage），如图 2 所示。

![文章插图](/articles/2025-06-30-llm-llm-llms-a61c8de3/images/07.webp)

在预填充阶段，输入文本被转换为嵌入向量并一次性输入至 LLM 内。每个 Transformer 层执行运算，中间结果（键值对缓存，KV cache）会被保存，供解码阶段复用。完成最后一层和语言模型头（LM head）的计算后，生成第一个 token（如“我的”）。随后在解码阶段，LLM 以自回归方式逐 token 生成输出，并每次更新 KV 缓存，直至生成终止符（如“。”）。

通过对单块 NVIDIA A100 GPU 上的 Llama2-7B 模型进行分析发现：在输入 token 数为 128-256 且输出 token 数大于 32 的日常场景中，**解码阶段的时间占比超过 80%，如图 2(c)所示。**

> 预填充阶段的注意力计算具有与输入文本长度成二次方的计算复杂度和存储复杂度。

为应对这一问题，研究者设计了多种硬件高效型 LLM 以优化长文本处理。因此，我们**在 2.2 小节中对这些 LLM 进行了总结**。

针对**解码阶段**，**后续小节将分别介绍针对 CPU、GPU、FPGA、ASIC 及 PIM/NDP 等平台的硬件优化方法**，并提供生成式 LLM 的推理结果。

### 2.2 高效生成式大语言模型

#### 2.2.1 基于注意力机制的 LLM

> 在 LLM 中，最常见的注意力类型为自注意力（self-attention），即输入序列中的每个 token 会对所有其他 token 进行注意力计算，以捕捉局部和全局依赖关系。

具体实现为：为每个 token 计算三个向量——查询向量（Q）、键向量（K）和值向量（V）。注意力得分通过 Q 与 K 的缩放点积计算，经 softmax 操作后确定各 token 的权重，再基于权重对 V 向量进行加权求和，生成注意力输出。

$$
O = \text{Softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V \tag{1}
$$

**众多方法致力于简化注意力机制**。

- Transformer-XL[88]采用**段级循环机制和位置编码方案**，实现固定长度之外的依赖关系建模，同时维持时序连贯性。
- 线性 Transformer[89]**将自注意力表示为核特征图的线性点积，借助矩阵乘法的结合律调整计算顺序**，将复杂度从 $O(L^2)$ 降至 $O(L)$（L 为上下文长度），显著加速自回归 Transformer 的计算。

---

- 无注意力 Transformer（AFT, Attention-Free Transformer）[90]则是另一种高效结构。与标准 Transformer 先计算查询-键乘积的方式不同，**AFT 在与查询进行元素级乘法前，先将键和值与一组学习到的位置偏差结合**。这使得 AFT 的内存复杂度对上下文长度和特征维度均呈线性关系，支持更大的输入长度和模型规模。
- 基于 AFT 的 RWKV[39]**融合了 Transformer 的并行训练能力与 RNN 的推理效率**，利用线性注意力机制使模型可表示为 Transformer 或 RNN 形态，在训练阶段支持并行计算，同时在推理阶段保持恒定的计算和内存复杂度。

---

DiJiang[91]提出一种**基于离散余弦变换** （DCT, Discrete Cosine Transform）**的频域核化方法**，指出改进注意力机制往往需大量重新训练，这对拥有海量参数的 LLM 而言代价高昂。该方法**通过加权拟蒙特卡罗采样，将预训练的标准 Transformer 转换为线性复杂度模型**，同时保持较低的训练成本。实验表明，该方法在显著提升推理速度的同时，性能与标准 Transformer 相当。

#### 2.2.2 基于状态空间模型（SSM）的 LLM

状态空间模型（SSM, State Space Model）**通过隐藏状态 $h$ 定义从输入 $x$ 到输出 $y$ 的线性映射**，其中 $A$ 为状态矩阵，$B$ 为输入矩阵，$C$ 为输出矩阵。在生成式 LLM 中，SSM 可将输入文本压缩为隐藏状态，进而基于该状态生成输出文本。

$$
\begin{cases}
h = A \times h + B \times x \\
y = C \times h
\end{cases}
$$

- 结构化状态空间序列模型（S4, Structured State Space Sequence Model）[92]**通过低秩校正对矩阵 $A$ 进行参数化**，使其可稳定对角化，**将 SSM 简化为基于柯西核的计算**，在保持理论优势的同时显著提升计算效率。
- 门控状态空间模型（GSS, Gated State Space Model）[93]**基于门控激活函数设计**，在 TPU 上的训练速度显著快于 S4，且性能可与多种基于 Transformer 的 LLM 竞争。

---

- Hyena[94]指出，现有**基于低秩和稀疏近似的亚二次方方法需与密集注意力层结合才能匹配 Transformer 性能**，因此提出一种基于交错隐式参数化长卷积和数据控制门控的亚二次方注意力替代方案，**相比基于状态空间模型的其他方法，其准确率提升超 50 个百分点**。由于线性注意力、门控卷积、循环模型和 S4 均无法进行基于内容的推理，Mamba[43]将 SSM 参数设计为输入的函数，使模型可基于当前 token 选择性地沿序列长度维度传播或遗忘信息，并针对循环模式设计了硬件感知的并行算法以提升计算效率。
- DenseSSM[95]通过**将浅层隐藏状态选择性集成至深层，对 Mamba 进行改进，在保持密集连接的同时维持训练并行性和推理效率**。Mamba2[44]通过对一类结构化拟可分矩阵的分解，**揭示 Transformer 与 SSM 模型族的紧密关联**，并引入状态空间对偶（SSD, State Space Duality）框架，其核心层为 Mamba 中选择性 SSM 的改进版，推理速度提升 2-8 倍。

#### 2.2.3 混合架构 LLM

> 部分 LLM 融合了基于注意力和 SSM 的架构，结合注意力的完整信息提取能力与 SSM 的信息压缩能力，以提升长文本处理性能。

块状态 Transformer（BST, Block-State Transformer）[96]**将用于长程上下文建模的 SSM 子层与用于短序列表示的块 Transformer 子层集成**，该架构融合 SSM 与块注意力的优势，并探索了三种完全并行的变体。

Griffin[97]**结合门控线性循环与局部注意力**，其 Hawk 层（一种带门控线性循环的 RNN）可**提升模型对长序列的处理效率**。Jamba[98]**将 Transformer 与 Mamba 层交替排列，借助混合架构发挥两类模型的优势**，部分层中还引入专家混合（MoE, Mixture of Experts）机制，在控制激活参数数量的同时提升模型容量。

与 BST 不同，无限 Transformer（Infini-Transformer）[99]在**单个 Transformer 块内结合掩码局部注意力与长程线性注意力，其 Infini-Attention 机制在有限内存和计算资源约束下，将压缩内存集成至原始注意力机制中**。MEGALODON[100]是一种针对无限上下文长度的神经架构，基于 MEGA 架构（带门控注意力的指数移动平均），引入复数指数移动平均（CEMA）、时间步归一化层、归一化注意力机制及带两跳残差的预归一化配置，以增强模型能力和稳定性。

## 三、硬件平台上的优化：量化

![文章插图](/articles/2025-06-30-llm-llm-llms-a61c8de3/images/02.webp)

### 3.1.1 量化概述

> 量化是将模型的权重和激活值从高精度格式（如 32 位浮点数）转换为低精度格式（如 4 位整数）的过程，旨在减少模型的存储需求和计算成本，同时保持准确性。

从**数据格式** 角度，量化包括均匀量化和非均匀量化。

- **均匀量化** 是**将数值范围划分为若干等间隔区间**，每个区间映射到一个离散表示值（通常用更少位数表示，如 8 位），其优点是简单且计算效率高，但可能无法有效捕捉数据分布特征，尤其是当数据分布不均时可能导致显著信息丢失。
- **非均匀量化** 则**根据实际数据分布使用不同大小的区间** （例如在数据分布密集区域使用小区间，稀疏区域使用大区间），能更好地保留数据细节和特征，从而提升模型精度，但通常需要额外计算和存储来管理量化区间，复杂度较高。

---

**量化的粒度** （Granularity）对模型性能和效率至关重要，包括组级（group-wise）、通道级（channel-wise）和张量级（tensor-wise）。

- **组级** 粒度是一种较粗的方法，**多个通道或层使用相同的量化参数**，虽然简单且计算存储开销低，但可能无法有效捕捉各通道或层的个体特征，导致模型性能折中。
- **通道级** 粒度对模型中的**每个通道单独量化，每个通道可拥有独立的量化参数**，能根据各通道的权重分布和激活特征进行更精准的调整，在精度和灵活性间取得平衡，但实现和计算复杂度更高。
- **张量级** 粒度是最细粒度的方法，**每个张量** （如权重张量或激活张量）**单独量化，可针对每个张量的特定特征进行优化**，精度最高，但计算和存储成本也最高，实现最为复杂。

---

**量化方法** 主要分为仅权重量化（weight-only quantization）和权重-激活量化（weight-activation quantization）。

![文章插图](/articles/2025-06-30-llm-llm-llms-a61c8de3/images/08.webp)

- **仅权重量化**：**仅将模型的权重参数** 从高精度格式（如 32 位浮点数）转换为低精度格式（如 8 位整数），通常包括将权重离散化为有限离散值并以更少位数表示（如 8 位），可显著减少存储需求并加速计算。**仅权重量化可采用均匀量化或非均匀量化方法**，例如通过矩阵分解量化（将大矩阵近似为多个小矩阵的乘积）降低计算和存储复杂度，**适用于超大规模模型**。
- **权重-激活量化**：**将仅权重量化的概念扩展到模型推理过程中生成的激活值**，即对每层的权重和激活值均进行低精度量化，可进一步降低内存带宽需求并提升推理速度。其**挑战在于平衡量化误差与模型精度**，通常采用**动态范围量化或特定量化方案** （如逐层量化）来平衡精度与计算效率。

---

**KV 缓存量化** （KV Cache Quantization）：Su 等人[127]发现，**少数异常 token** （outlier tokens）**具有偏离** “键按通道分布、值按 token 分布”**模式的独特特征**，可能显著影响量化精度。因此，他们开发了一种异常 token 追踪方法，在**解码过程中精准识别这些 token 并将其排除在量化之外**，在单块 NVIDIA A100 GPU 上使 Llama2-7B 模型达到约 480 tokens/s 的推理速度。

### 3.1.2 CPU 量化

#### CPU 仅权重量化

> CPU 上的量化优化方法主要集中于仅权重量化。

Shen 等人[101]利用 Intel **神经压缩器自动化 INT4 量化** 过程，精度损失可忽略，**支持 GPTQ[111]、AWQ[112]和 TEQ[288]等多种量化方案，并开发了专为 CPU 设计的张量库，支持 AVX2、AVX512、AVX512_VNNI 和 AMX 等主流指令集**。在第四代 Intel Xeon 可扩展处理器单插槽上，对 Llama2、Llama 和 GPT-NeoX 等主流 LLM 的实验表明，参数规模在 6B 至 20B 的模型，token 生成延迟在 12.5 tokens/s 至 50 tokens/s 之间。

高通骁龙 8 Gen3 SoC[64]利用其专有的 **Hexagon 700 AI 处理器和量化技术**，支持高效 LLM 执行，**4 位量化** 的 Llama2-7B 模型可达约 15 tokens/s。开源仓库 llama.cpp[103]专为包括 CPU、GPU 和 ASIC 在内的多硬件平台高效 LLM 推理设计，在 Apple M2-Ultra 处理器上，4 位量化的 Llama2-7B 模型单核心可达 6 tokens/s，8 核心可达 32 tokens/s；2 位量化时，单核心 4 tokens/s，8 核心 21 tokens/s。

由于权重从整数到浮点数的反量化（dequantization）开销，T-MAC[102]利**用查找表（LUT）在边缘 CPU 上实现低比特 LLM 推理，避免反量化和混合精度矩阵乘法**。在 Apple M2-Ultra 处理器上，4 位量化的 Llama2-7B 模型单核心 10 tokens/s，8 核心 38 tokens/s；树莓派 5（集成 ARM Cortex-A76）上可达 3 tokens/s。2 位量化时，M2-Ultra 单核心 17 tokens/s，8 核心 50 tokens/s；树莓派 5 可达 6 tokens/s。

此外，由于注意力计算中大量昂贵的乘加（MAD）矩阵运算，NoMAD-Attention[104]设计了一种高效注意力算法，**用寄存器内查找替代 MAD 运算**。通过硬件感知的算法设计，尽管 SIMD 寄存器容量有限，仍可通过重复快速访问寄存器计算注意力得分。在 2 颗 Intel Xeon E5-2695 V3 14 核 CPU 上，4 位量化的 CodeLlama-7B 模型在短上下文（如 128）下可达 9 tokens/s，长上下文（如 16k）下可达 4 tokens/s。

Zhou 等人[105]**对不同比特宽度的 LLM 进行压缩**，并部署在 Intel Xeon CPU Max 9468 上，批量大小为 1 时，OPT-13B 和 OPT-30B 分别可达 33 tokens/s 和 15.625 tokens/s。Gope 等人[107]提出**基于分组非均匀码本的量化方法和针对超低精度量化的高度优化内核**，在 Arm Graviton3 CPU（64 核）上，4 位量化的 Llama3-8B 模型批量大小为 1 时可达 45.5 tokens/s，批量大小为 8 时可达 184.8 tokens/s。

Jayanth 等人[106]在 Intel Core Ultra 7 165H 处理器上部署 **INT4** LLM，Llama3-8B 和 TinyLlama-1B 分别可达 3.94 tokens/s 和 15.6 tokens/s。Yu 等人[108]在 Intel Ultra-125H 和 Core i9-12900K 上部署 INT4 LLM 和 llama.cpp，Llama2-7B 分别可达 15.625 tokens/s 和 6.393 tokens/s。**DECA[110]首先开发了带有 3D 可视化表示的分析性能模型，揭示内存资源、向量单元和硬件矩阵引擎如何交互以实现压缩（量化和稀疏）的通用矩阵乘法（GeMM），并设计了一种近核 ML 模型解压缩加速器**，将分块去稀疏化和反量化从 CPU 卸载，为核心内 GeMM 引擎提供即用分块。在模拟的 56 核 Xeon 4 服务器（配备 HBM）上，Llama2-70B 模型使用 MXFP4 和 BF8（稀疏度 5%-20%）时，批量大小为 1 可达 14-25 tokens/s，批量大小为 16 可达 194-281 tokens/s。

### 3.1.3 GPU 量化

#### GPU 仅权重量化

GPTQ[111]是一种**基于近似二阶信息和误差补偿的单次权重量化方法，兼具高精度和高效性**，可在约 4 块 GPU 小时内将 1750 亿参数的 GPT 模型量化至每权重 3 位或 4 位，与未压缩基线相比精度损失可忽略。实验表明，3 位量化的 OPT-175B 模型在单块 A100（80GB）上的平均每 token 时间为 14.1 tokens/s，比 FP16 版本（运行于 5 块 GPU）快 3.25 倍；在更易获取的 NVIDIA A6000（48GB）上，平均每 token 时间为 7.7 tokens/s（运行于 2 块 GPU），比 FP16 版本（运行于 8 块 GPU）快 4.53 倍。

**AWQ[112]基于保护 1%激活值极大的显著权重可大幅降低量化误差的观察**，首先搜索每通道最优缩放因子，再将显著权重与通道缩放因子相乘，同样将权重比特宽度降至 3 或 4 位。INT4 实现的实验表明，Llama-2-7B 模型在 RTX 4090 桌面 GPU 上的推理速度从 52 tokens/s 提升至 194 tokens/s（加速 3.73 倍）；Llama-2-13B 在 RTX 4090 上可达 110 tokens/s，在笔记本 RTX 4070 GPU（8GB）上，13B 模型可达 33 tokens/s，而 FP16 实现甚至无法容纳 7B 模型。

为进一步**减少 1-10B 参数规模较小模型的精度损失**，SpQR[113]通过**识别并隔离导致较大量化误差的异常权重，将其以更高精度** （如半精度 16 位）**存储，其余权重压缩至 3-4 位**，在高准确度的 LLaMA 和 Falcon LLMs 上，困惑度（perplexity）的相对精度损失小于 1%。在 A100 GPU 上，3 位和 16 位量化的 SpQR 分别可达 57 tokens/s、44 tokens/s、22 tokens/s 和 12 tokens/s。

与 SpQR 不同，**SqueezeLLM[114]提出基于敏感度** 的**非均匀量化** 方法，**根据二阶信息搜索最优比特精度分配**，并应用密集-稀疏分解，**以高效稀疏格式存储异常值和敏感权重值**。在 A6000 GPU 上，3 位和 16 位量化的 SqueezeLLM 分别可达 63.5 tokens/s、49.2 tokens/s、29.1 tokens/s 和 14.5 tokens/s。LLM-MQ[115]提出基于敏感度的精度分配，根据一阶信息和量化误差在给定权重内存预算内为每层分配合适的比特宽度，并开发高效 CUDA 核心内核，通过融合反量化和通用矩阵向量乘法（GEMV）加速 LLM。在 NVIDIA T4 GPU 上，INT4 量化的 Llama2-7B 模型比 PyTorch FP16 基线实现端到端加速 1.6 倍。

**APTQ[116]提出针对注意力的 2/4 位混合精度量化，不仅考虑每层权重的二阶信息，还首次考虑注意力输出对整个模型的非线性影响**。Li 等人[117]首次提出 LLM 的权重内混合精度量化，在 **3 位下通过 2/4 位混合精度量化**、内存对齐和独家 2 位稀疏异常值保留（速度下降最小），考虑不同模型的所有比例/零值后，每权重可达 2.91 位，精度损失可忽略。此外，他们设计了**异步反量化，并在推理期间融合反量化和 GEMV 内核**，Llama2-7B 模型在 RTX 3090 GPU 可达 45.2 tokens/s，RTX 2080 GPU 可达 34.0 tokens/s。

LUT-GEMM[118]提出一种高效的**基于查找表的 GPU 内核，用于量化矩阵乘法，不仅消除了资源密集的反量化过程，还相比之前的仅权重量化内核降低计算成本**。通过低比特量化和高效查找表操作实现高压缩比，4 位量化的 Llama-7B 模型在 A100 GPU 可达 163.9 tokens/s，相比 PyTorch FP16 基线，token 生成延迟改善 1.64 倍。

FLUTE[119]是**针对 LUT 量化 LLM 的灵活查找表引擎，通过离线重组量化权重矩阵以最小化解包相关的位操作，并对查找表进行向量化和复制以缓解共享内存带宽限制**。在 NVIDIA A6000 和 A100 GPU 上，4 位量化的 Llama3-8B 模型分别可达 91.3-99.8 tokens/s 和 113.7-121.7 tokens/s；3 位量化时，分别可达 91.9-110.0 tokens/s 和 117.7-135.5 tokens/s。

为有效减小 LLM 规模并保持模型精度，**FP6-LLM[120]利用 TC-FPx 提出 GPU 上的 FP6 量化，这是首个支持各种量化比特宽度浮点权重的全栈 GPU 内核设计方案**，解决了不规则比特宽度模型权重的不友好内存访问和高运行时反量化开销问题。在 NVIDIA A100 GPU 上，FP6 量化的 Llama2-13B 模型可达约 55 tokens/s。

GQSA[126]（组量化与稀疏加速）引入一种**新型压缩技术，通过紧密结合量化和稀疏化，利用 GPU 友好的结构化组稀疏和量化实现高效加速**。在 INT4 和 50%稀疏度设置下，Llama2-7B 和 Llama2-13B 模型在 NVIDIA A100 上分别可达 343.43 tokens/s 和 228.95 tokens/s。Ma 等人[128]引入一种**双极 INT 数据格式，支持并行计算和对称量化**，并**实现任意精度矩阵乘法方案，在比特级分解和恢复矩阵**，同时设计面向数据恢复的内存管理系统以最小化内存访问延迟，在单块 RTX 3090 GPU 上，Llama2-7B 模型可达 51.94 tokens/s。

#### GPU 权重-激活量化

> 除支持 FP16 计算的硬件单元外，NVIDIA GPU 还提供支持 INT4、INT8 和 FP8 计算的硬件单元，**其计算单元数量是 FP16 的 2 至 4 倍。**与仅权重量化相比，权重-激活量化可利用 INT4、INT8 和 FP8 计算，从而**最大化 GPU 的峰值计算性能**。由于 LLM 推理的**预填充阶段为计算密集型，权重-激活量化可显著提升该阶段性能**。

LLM.int8[121]**对大多数特征采用向量量化，每个矩阵乘法的内积使用独立归一化常数，对异常特征维度则隔离至 16 位矩阵乘法**，同时 99.9%以上的值以 8 位相乘。在 3 块 A100 GPU 上，BLOOM-176B 模型在解码阶段批量大小为 1、8 和 32 时，分别可达 4.05 tokens/s、30.3 tokens/s 和 109.77 tokens/s，推理速度**略慢于 16 位推理，但 GPU 消耗更低。**

SmoothQuant[122]实现 LLMs 的 8 位权重和 8 位激活（W8A8）量化，**基于权重易量化而激活难量化的观察，通过数学等价变换将量化难度从激活迁移至权重，实现 LLMs 全矩阵乘法的 INT8 量化，精度损失可忽略，加速比达 1.56 倍，内存减少 2 倍**。QUIK[123]首次实现 LLMs 推理的大部分计算可在权重和激活均为 4 位的情况下进行，**将大多数权重和激活压缩至 4 位，同时将部分异常权重和激活保留为更高精度**，并提供与 QUIK 格式匹配的高效逐层运行时 GPU 内核，相比 FP16 执行，预填充阶段端到端吞吐量提升达 3.4 倍。

流行的量化方案（如 W8A8）无法充分利用**现代 GPU 的 4 位整数运算器**，导致性能未达最优。Atom[124]**通过低比特运算显著提升服务吞吐量，并通过新型混合精度和细粒度量化过程保持高精度**，在单块 NVIDIA RTX 4090 GPU 上，单批量推理可达约 30 tokens/s，相比 FP16 和 INT8 量化，端到端吞吐量分别提升 7.73 倍和 2.53 倍，同时保持相同延迟目标。

**与整数量化相比，浮点（FP）量化更适合处理长尾或钟形分布数据**，已成为许多硬件平台的默认选择。LLM-FP4[125]**将 LLMs 的权重和激活均量化至 4 位浮点值（W4A4），精度损失可忽略**，由于 **GPU 缺乏 PF4 计算单元，其解码速度可能慢于 FP16 基线。**

### 3.1.4 FPGA 量化

#### FPGA 权重-激活量化

FlexRun[129]采用 **8 位量化（W8A8）**，深入进行**设计空间探索** 以找到目标 LLM 模型的**最佳加速器架构**，并根据**探索结果自动重新配置加速器**。在 Intel Stratix 10 GX 和 MX FPGAs 上实现的结果表明，FlexRun 在 GPT2 模型上的性能比当前最先进的基于 FPGA 的加速器高出 1.15×–1.50×，平均性能比 Nvidia V100 GPU 高出 2.69×。

HLSTransform[130]使用**高层次综合（HLS）设计 FPGA 加速器，并结合流水线、内存展开、内存分区和传输优化，同时采用 8 位整数量化（W8A8）**。在参数为 1.1 亿的小型模型上，HLSTransform 在 Xilinx Virtex UltraScale+ VU9P FPGA 上可达 57.11 tokens/s。

SECDA-LLM[131]利**用量化（W3A8）并为 llama.cpp 推理框架设计高效的基于 FPGA 的 LLM 加速器**，在 PYNQ-Z1 开发板上部署 TinyLlama 模型（11 亿参数）时可达 0.588 tokens/s。

Chen 等人[132]研究了 FPGA 上 LLM **推理的特定模型空间加速的可行性和潜力，引入综合分析模型以估计采用 W4A8 量化** 的 FPGA 加速器的 LLM 推理性能，并提供可组合和可重用的高层次综合（HLS）内核库。对于 Llama2-7B 模型，预填充阶段在 Xilinx Alveo U280、VCK5000 和 VHK158 FPGAs 上分别可达约 213 tokens/s、43 tokens/s 和 320 tokens/s；解码阶段分别可达约 200 tokens/s、40 tokens/s 和 333 tokens/s。

On-Device Qwen2.5[135]利**用 AWQ 和 FPGA 加速执行流水线**，在 Xilinx Kria KV260 边缘平台上使 Qwen-0.5B 模型达到 5.1 tokens/s。

TeLLMe[137]是**首个面向低功耗 FPGA（如 AMD KV260）的三值 LLM 加速器，完全支持预填充和自回归解码，采用 1.58 位权重和 8 位激活**。在 7W 功耗预算下，处理 1024 token 上下文时吞吐量可达 9 tokens/s，128 token 提示的预填充延迟为 0.55-1.15 秒。

LightMamba[136]提出一种**适合 FPGA 的 W4A4 和 W8A8 训练后量化算法，采用旋转辅助量化和 2 的幂次 SSM 量化，将大部分计算降为 4 位**，在 Xilinx Alveo U280 FPGA 和 Versal VCK190 FPGA 上，Mamba2-2.7B 模型分别可达 93 tokens/s、7.21 tokens/s 和 3.61 tokens/s。

TerEffic[138]也**针对三值量化 LLM 推理设计**，实验表明，HBM 辅助架构在 AMD Alveo U280 上处理 Llama-7B 和 27 亿参数模型时，吞吐量分别为 290 tokens/s 和 727 tokens/s，功耗仅 46W。

Li 等人[139]在基于 Zynq 的 KV260 上部署 **4 位 LLaMA2-7B 模型**，解码速度为 4.9 token/s，功耗 6.57W。

MEADOW[140]**通过新颖的 token 并行头部顺序（TPHS）数据流和带权重打包的混合精度量化，减少 LLMs 的片外内存访问**，在低功耗 Xilinx ZCU102 FPGA 平台（功耗<10W）上，OPT-1.1B 模型可达 0.25-2 tokens/s。

TTD[141]为 LLMs 开发**张量训练分解（TTD）**，并在 FPGA 硬件上实现**高效的组向量 systolic array（GVSA）架构，该架构具有用于 TTD 推理的 DSP 共享并行向量处理单元（PE）**，以及加速器内优化的数据通信。实验表明，在 AMD Alveo V80 FPGA 上，ChatGLM3-6B 和 Llama2-7B 模型分别可达 69.7 tokens/s 和 65.8 tokens/s。

LlamaF[142]利**用 W8A8 量化技术、异步计算和全流水线加速器提升效率**，在 Xilinx ZCU102 平台上的 TinyLlama-1.1B 模型可达 1.5 tokens/s 吞吐量，能效为 0.291 tokens/J。

LNS-LLM[143]指出 LLM **直接采用对数数制（LNS）格式时存在显著异常值，提出数据格式/架构协同设计以弥合这一差距**：在格式方面，**提出动态非对称 LNS 格式**；在**架构方面，在 systolic array 中实现动态 LNS 格式**。在 Alveo U280 FPGA 原型上的实验表明，LNS-LLM 可有效处理异常值，解决 LNS 与 LLM 的不匹配问题。

### 3.1.5 ASIC 量化

#### ASIC 仅权重量化

> 尽管仅权重量化可减少内存占用，但由于从整数到浮点数的反量化操作，实际计算性能并未真正提升。

FIGNA[146]提出**专为 FP-INT 乘加运算（MAC）设计的专用算术单元，并集成到加速器中**。考虑 28nm 工艺下 100MHz 频率的所有内存访问，FP16-INT4 的 FIGNA 提供 3.2768 TOPS 计算能力，功耗 26.58W。估计结果表明，OPT-6.7B 模型在解码阶段可达 21.332 tokens/s。

与常规量化方法不同，MECLA[147]**提出参数高效的缩放子矩阵划分方法（SSMP），将大权重矩阵分解为多个小尺寸源子矩阵（SS）和派生子矩阵（DS）**：在内存方面，SSMP **避免访问完整权重矩阵**，仅需小尺寸 SS 和 DS 缩放标量；在计算方面，所提出的加速器通过片上矩阵重组、内积乘法重组和外积部分和重用，**充分利用矩阵乘法的中间数据重用，可减少 83.6%的内存访问和 72.2%的计算量**。与 NVIDIA V100 GPU 相比，MECLA 在 91.84W 功耗（32 个处理器）下，Llama2-7B 和 BLOOM-7B 模型的推理速度分别提升 6.74 倍和 5.91 倍（分别约 161 tokens/s 和 141 tokens/s）。

FineQ[152]**将 3 个权重量化为 8 位，采用 2/3 位混合精度，并引入利用时间编码的加速器，有效支持量化算法，同时简化 systolic array 中的乘法器**，可实现高达 1.79 倍的能效提升，并将 systolic array 的面积减少 61.2%。

Anda[157]提出一种**自适应数据格式，采用组共享指数位和动态尾数分配。**

#### ASIC 权重-激活量化

基于**异常值重要** 而**其相邻正常值不重要** 的关键洞察，OliVe[148]**采用异常值-受害者对（OVP）量化，以低硬件开销局部处理异常值，实现内存对齐的 W4A4/W8A8 量化，可高效集成到现有的硬件加速器** （如 systolic array 和 Tensor Core）中。考虑 22nm 工艺下的所有内存访问，OliVe 提供 0.71 TOPS 计算能力，功耗 5.95W。估计结果表明，Llama-7B 模型在解码阶段可达 9.95 tokens/s。

Li 等人[149]**对权重和激活进行均匀分组以确保硬件工作负载平衡，提出通道排序和通道选择两种方法以提升量化性能**，考虑 65nm 工艺下的所有内存访问，提供 1.43 TOPS 计算能力，功耗 2.36W。估计结果表明，Llama-7B 模型在解码阶段可达 20.04 tokens/s。

Tender[150]**按不同大小对权重和激活矩阵进行分组，以平滑异常值的影响，缩放因子格式为 2 的幂次，避免显式反量化，可扩展至商用 Tensor 计算硬件**，考虑 28nm 工艺下 HBM2 内存访问，功耗 7.174W（1.60W+5.574W）。结果表明，OPT-6.7B 模型的速度比 NVIDIA A100 GPU 快 1.33 倍（53.33 tokens/s）。

Cai 等人[151]提出**带组内嵌入标识符的分组自适应双范围量化** （ATRQ），**以编码异常值，并开发低开销 ATRQ 解码器和异常值位拆分处理单元（PE），以减少与高比特宽度异常值相关的硬件开销**。实验表明，其设计在 1.632W 功耗下，OPT-6.7B 模型的速度与 OliVe 相当（9.95 tokens/s）。

OFQ-LLM[154]是**面向 LLM 推理的异常值灵活量化** 加速器，在 1.64W 功耗下，7B 模型的速度与 OliVe 相当。

M-ANT[155]提出高效的**实时量化机制**，实现特定处理单元（PE）以有效支持 MANT，并**集成实时量化单元到 systolic array 中，统一组级权重和 KV 缓存量化**，解决相关挑战。评估表明，其平均速度比 OliVe 加速器快 1.96 倍，能耗降低 1.54 倍（19.502 tokens/s，7.57W）。

与以往位串行设计（虽灵活但因按位时序处理导致性能下降）不同，FlexiBit 的架构**支持任意精度和格式的位并行处理**，无需计算单元空闲[156]。

AirGun[158]对非敏感模块**采用硬件高效的逐张量量化，对敏感模块采用逐输入通道量化**，并提出充分利用 AirGun 优势的加速器（12.935 tokens/s，6.1964W）。

Ecco[159]将组级和非均匀量化与预定义共享 k-means 模式和霍夫曼编码结合，**利用 LLM 缓存数据的固有熵特征，引入基于霍夫曼编码的并行解码过程和多级流水线设计**，将延迟降低两个数量级，吞吐量可与 GPU L2 缓存相当。

OwL-P[160]利用**异常值和共享指数** 来**压缩模型权重和激活**。

FGMP[161]提出**细粒度 FP4/FP8 混合精度量化**，以及用于执行两个 FP4 块、两个 FP8 块或一个 FP4 与一个 FP8 块之间点积的硬件实现。

LightRot[162]提出轻量级旋转方案和专为 **4 位 LLM 推理** 设计的专用硬件加速器。

### 3.1.6 PIM/NDP 量化

基于 ReRAM 的模拟 PIM 架构利用电压、电流和电导在**模拟域执行整数矩阵向量乘法** （MVM），限制了其在更精确的浮点（FP）数据格式中的应用。

::: block-1
Guo 等人[163]提出**基于 ReRAM 和 3D-SRAM 的混合 PIM 架构**，采用非均匀数据格式，实现基于 FP 的算法精度、高设备利用率和高能效：

- 在**软件层面**
- 在**硬件层面，提出混合 PIM 架构**，包括使用移位相加执行基于 PN 的 MVM 的 ReRAM 模拟 PIM，以及高利用率的 3D-SRAM 数字 PIM，用于无乘法的基于 FP 的元素-wise 操作。大量实验表明，所**提出的 PIM 架构相比 GPU 和 PIM 基线，速度提升高达 89 倍和 16 倍，能效提升 2537 倍和 12 倍。**
:::

TransPIM[164]是**基于内存的 Transformer 加速方案，采用软硬件协同设计**：

- 在软件层面，采用**基于 token 的数据流**，避免以往基于层的数据流引入的昂贵层间数据移动；
- 在硬件层面，**对传统 HBM 架构进行轻量级修改**，**支持 PIM-NMC 混合处理和高效数据通信**，以加速基于 Transformer 的模型。

TransPIM 系统使用 8GB HBM，面积开销 2.15 mm²，功耗约 40.01W。实验表明，对于 GPT2 模型，TransPIM 的速度至少比 NVIDIA RTX 2080Ti GPU 快 22.1 倍。

其他 PIM/NDP 加速器（如 TransPIM[164]和 Sharda 的方法[165]）也涉及量化以进一步提升 LLM 推理性能。

MVDRAM[167]通过**动态向量编码和水平矩阵布局**，消除基于 DRAM 的处理（PUD）中列到列数据移动的基本限制引入的开销，在 2-8 位量化下，Llama2-7B 模型可达 2-10 tokens/s 和 7-20 tokens/J。

ROMA[169]是具有**混合存储架构的 QLoRA 加速器**，使用 ROM 存储量化的基础模型，SRAM 存储 LoRA 权重和 KV 缓存，在 33.1W 功耗下，2 位 Llama3-8B 模型可达 11600-24100 tokens/s。

### 3.1.7 定量比较

> 我们首先在图 4 中比较不同硬件平台的功耗、推理速度和能效。

![文章插图](/articles/2025-06-30-llm-llm-llms-a61c8de3/images/10.webp)

WaferLLM[252]（ASIC）实现批量大小 1 时的最高吞吐量（硅前仿真结果），Guo 等人[163]的 PIM 架构实现最高 46.66 tokens/J 能效。

---

- **CPU**：功耗范围 3W 至 385W，推理速度 3 tokens/s 至 50 tokens/s，位于图的底部，能效范围 0.0167 tokens/J 至 2.38 token/J。此外，边缘 CPU（包括 CPU SoC）在 3W 至 9W 功耗下表现出更高能效（1 tokens/J 至 2.38 tokens/J）。
- **GPU**：功耗范围 40W 至 450W，推理速度 18 tokens/s 至 343.4 tokens/s，位于图的右上部分，能效范围 0.067 tokens/J 至 0.859 token/J。与其他硬件相比，GPU 因其高计算能力和高带宽可实现更高绝对推理速度，量化方法缓解了 LLM 推理的内存访问瓶颈，进一步释放计算能力。
- **FPGA**：功耗范围 2.490W 至 225W，推理速度 3.61 tokens/s 至 333 tokens/s，也位于右上部分，能效范围超过 0.154 tokens/J 至 6.30 tokens/J，高于 GPU 和服务器 CPU。
- **ASIC**：功耗范围 1.632W 至 91.84W，推理速度 9.95 tokens/s 至 161.1 tokens/s，位于图的左上部分，能效范围 1.16 tokens/J 至超过 8.49 tokens/J，优于 CPU、GPU 和 FPGA 平台。
- **PIM/NDP**：功耗范围 11.516W 至 70W，推理速度 10 tokens/s 至 1998 tokens/s，位于图的左上部分，能效优于其他硬件平台。

> 总体而言，仅权重量化和权重-激活量化方法均可提升绝对推理速度和能效。

- **仅权重量化** 减少带宽需求，但**引入额外反量化操作，可能增加硬件功耗**，同时提升绝对速度；
- **权重-激活量化** 通过**使用更小宽度的计算单元减少硬件计算单元面积和功耗**，在提升绝对速度的同时降低整体硬件功耗。
