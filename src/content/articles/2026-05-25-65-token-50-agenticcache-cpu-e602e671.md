:::

## 一、具身智能的 LLM 规划瓶颈：从泛化性到效率的两难

> 大语言模型为具身智能带来了前所未有的泛化能力，让智能体能够处理从未见过的任务和环境。但这种能力的代价是每一步推理都需要调用昂贵且延迟较高的 LLM，这成为了具身智能走向大规模部署的最大障碍。

在 LLM 兴起之前，具身智能的研究主要集中在手工设计的感知-规划-执行管道上。**研究人员需要为每个特定任务设计专门的感知模块、规划算法和执行控制器**。:mdnice-bold-italic[这种方法在狭窄的、结构化的环境中能够取得不错的效果，例如工业机器人在装配线上的操作。但一旦环境发生微小的变化，或者任务目标有所调整，整个管道就需要重新设计和调试]，这使得传统具身智能的泛化能力极其有限。

### 1.1 LLM 驱动具身智能的兴起与局限

> LLM 的出现彻底改变了这一局面。**通过将感知信息（如图像、传感器数据）转化为自然语言描述，LLM 能够利用其强大的语言理解和推理能力，生成高层的行动计划，然后将这些计划转化为具体的执行指令**。这种统一的决策框架消除了对任务特定工程的需求，使得同一个智能体能够处理多种不同的任务，甚至能够泛化到从未见过的新环境中。

- 例如，Voyager 智能体使用 GPT-4 作为规划器，能够在 Minecraft 的开放世界中自主探索、学习技能、完成任务，展现出了前所未有的泛化能力。
- MetaGPT 等多智能体框架则通过 LLM 实现了多个智能体之间的协作，能够完成复杂的软件开发、项目管理等任务。

在具身智能领域，CoELA、COMBO、COHERENT 等框架都采用了 LLM 作为核心规划器，在各种模拟环境中取得了优异的表现。

:mdnice-bold-italic[然而，这种基于 LLM 的规划架构也带来了严重的效率问题。LLM 的推理过程需要大量的计算资源，即使是在最先进的 GPU 上，一次推理也需要几百毫秒到几秒的时间。] 在同步规划-执行循环中，智能体必须等待 LLM 返回计划才能采取行动，这导致了大量的等待时间，严重影响了系统的实时性。

### 1.2 现有规划优化方法的核心缺陷

> 为了解决 LLM 规划的延迟问题，研究人员提出了多种优化方法，其中**最具代表性的是并行规划-执行和投机规划**。:mdnice-bold-italic[并行规划-执行的基本思想是在执行当前计划的同时，提前查询下一个计划，从而将 LLM 的推理延迟与动作执行时间重叠。]

**这种方法能够部分隐藏 LLM 的延迟，但存在一个致命的缺陷**：预取的计划可能在执行时已经失效。由于具身环境是动态变化的，在 LLM 生成下一个计划的过程中，环境状态可能已经发生了改变，导致预取的计划不再适用。这时智能体就需要重新规划，这不仅没有节省时间，反而增加了额外的开销。

**投机规划则是使用一个较小的、推理速度更快的 LLM 来提出初步的行动计划，然后在执行这些动作的同时，使用一个更大、更强大的 LLM 来验证这些计划的正确性**。

- 如果大模型验证通过，就继续执行；
- 如果验证不通过，就回滚到之前的状态，重新规划。

这种方法虽然能够进一步降低延迟，但在现实环境中表现不佳。因为纠正错误的动作往往需要花费大量的时间，例如移动回之前的位置、撤销已经完成的操作等。在多智能体环境中，错误的动作还可能导致智能体之间的协调失败，进一步降低任务成功率。

::: image-caption

- 投机规划中，小模型提出的计划 E 被大模型否定，智能体需要回滚到 T2 时刻，重新执行计划 A，同样产生了大量的时间浪费；

**而 AgenticCache 通过缓存计划，智能体可以连续执行多个缓存的计划（A、E、C），同时后台异步调用 LLM 生成后续计划（B）**。当缓存的计划需要纠正时，智能体可以立即切换到新的计划，几乎没有等待时间。

:mdnice-bold-italic[现有方法的另一个共同缺陷是，它们都没有利用具身任务中计划的重复结构]。无论是并行规划-执行还是投机规划，都将每一步的规划视为一个独立的决策过程，即使当前和下一个计划遵循可预测的模式，也仍然需要调用 LLM 来生成计划。这导致了大量的冗余计算和不必要的成本开销。

::: block-1
:mdnice-bold-italic[现有规划优化方法虽然在一定程度上缓解了 LLM 推理的延迟问题，但都无法避免每步 LLM 调用，且在动态环境中容易出现计划失效的问题]。它们没有利用具身任务中普遍存在的计划局部性，这为 AgenticCache 的提出留下了空间。
:::

## 二、核心洞察：具身任务中的计划局部性

> 人类在执行日常任务时，并不需要每一步都进行刻意的推理。例如，当我们拿起一个杯子时，下一步通常是将它移动到目标位置；当我们打开冰箱时，下一步通常是取出需要的食物。**这种基于经验的直觉反应，本质上就是利用了任务中的计划局部性。**

**AgenticCache 的核心洞察在于，具身任务表现出强烈的计划局部性，即下一个计划在很大程度上可以从当前计划预测出来**。:mdnice-bold-italic[这种局部性是由具身任务的物理约束和目标导向性决定的。在物理世界中，动作的执行需要遵循一定的顺序和因果关系]，例如必须先抓住物体才能移动它，必须先打开门才能进入房间。同时，具身任务通常有明确的目标，智能体的所有动作都是为了实现这个目标，这使得计划的转换具有很强的规律性。

### 2.1 什么是计划局部性

计划局部性可以定义为：在长程具身任务中，某些计划转换具有很高的**规律性**，对于给定的当前计划，下一个计划通常是少数几个可能的后继之一。:mdnice-bold-italic[换句话说，计划空间中的转换不是随机的，而是遵循一定的概率分布，大部分概率质量集中在少数几个转换上。]

**这种局部性与计算机体系结构中的时间局部性和空间局部性有相似之处**。

- 时间局部性指的是最近访问过的数据很可能在不久的将来再次被访问；
- 空间局部性指的是与当前访问数据相邻的数据很可能在不久的将来被访问。

而计划局部性指的是，当前执行的计划很可能转换为少数几个特定的下一个计划。

::: block-1
人类的行为模式充分体现了计划局部性。我们通过长期的生活经验，积累了大量的短程计划模式，形成了内部的“缓存”。当遇到熟悉的场景时，我们不需要进行复杂的推理，就可以直接调用这些缓存的计划模式，做出快速的直觉反应。只有当遇到不熟悉的场景或者计划执行失败时，我们才会进行刻意的、缓慢的推理。
:::

**AgenticCache 的设计正是受到了人类这种行为模式的启发**。研究者们提出，具身智能智能体也可以像人类一样，通过缓存频繁的计划转换，避免每步都调用 LLM 进行推理，从而实现快速、高效的决策。

### 2.2 计划局部性的量化证据

> 为了验证具身任务中计划局部性的存在，研究者们对 GPT-5 在四个基准测试中的执行轨迹进行了 2-gram 分析。:mdnice-bold-italic[2-gram 是一种统计语言模型，用于计算一个词跟随另一个词的概率。在这里，研究者们将每个高层计划视为一个“词”，计算一个计划跟随另一个计划的概率。]

### 2.3 纯局部性的局限性

> 虽然计划局部性为缓存重用提供了基础，但单纯依赖缓存的计划局部性是不够的。因为具身环境是动态变化的，缓存的计划可能因为环境状态的改变而失效。例如，一个缓存的“GoGrasp”转换可能因为目标物体已经被其他智能体拿走，或者被移动到了无法到达的位置而失败。

为了验证这一点，研究者们实现了一个基于静态模式的智能体，它只使用从 GPT-5 轨迹中提取的 2-gram 计划转换进行决策，而不进行任何上下文感知的更新。然后将这个静态智能体与动态的 GPT-5 智能体进行了对比。

## 三、AgenticCache 设计详解：缓存与 LLM 的异步协同

> :mdnice-bold-italic[AgenticCache 的核心设计理念是将规划过程分为两个部分：快速的、基于缓存的前向规划，和慢速的、基于 LLM 的异步验证与更新]。这种分离使得智能体能够在大部分时间里以缓存的速度执行计划，同时通过后台的 LLM 更新来保证计划的正确性和适应性。

AgenticCache 的整体架构由两个核心组件组成：运行时缓存和异步缓存更新器。

- 运行时缓存作为轻量级规划器，存储频繁的计划转换及其对应的状态条件，智能体在每一步首先查询缓存来获取下一个计划。
- 异步缓存更新器则在后台运行，定期调用 LLM 来验证缓存的计划，并根据环境的变化更新缓存条目。

### 3.1 整体架构

> 图 1(a)对比了基线智能体和 AgenticCache 智能体的架构。基线智能体的感知-规划-执行循环是同步的：智能体首先感知环境，然后调用 LLM 生成计划，最后执行计划。在 LLM 推理期间，智能体完全处于等待状态。

而 **AgenticCache 智能体的架构中，规划器不再直接调用 LLM，而是首先查询运行时缓存**。:mdnice-bold-italic[如果缓存命中，智能体就可以直接执行缓存的计划，无需等待 LLM]。同时，:mdnice-bold-italic[后台的缓存更新器会异步调用 LLM]，根据当前的环境状态验证缓存的计划，并更新缓存条目。

> 这种架构的优势在于：

1. 缓存命中时，智能体可以连续执行多个缓存的计划，完成多个动作后才需要一次后台 LLM 查询，从而大幅降低延迟和成本。
2. 当 LLM 的响应返回时，更新器要么确认当前的计划，让智能体继续执行；要么立即替换为纠正后的计划，保证智能体的动作始终符合当前的环境状态。
3. 随着缓存不断积累经过 LLM 验证的转换，缓存命中率会逐渐提高，延迟和成本会持续降低。

### 3.2 AgenticCache 作为轻量级规划器

> AgenticCache 的每个智能体都维护自己的缓存，它作为一个轻量级规划器，存储频繁的计划到计划的转换。每个缓存条目被表示为一个 2-gram 模式<Pi → Pj>，其中 Pi 和 Pj 是连续的高层计划，例如“GoGrasp→Transport”。

除了转换的统计信息外，每个缓存条目还记录了一组任务状态元数据字段，这些字段是从离线和在线的 episode 中提取的。元数据的具体内容取决于智能体可用的信息和基准测试环境，通常包括步骤索引、持有物体的数量、完成的子目标数量、访问过的房间数量等。对于每个元数据字段，缓存存储观察到的最小值和最大值，形成一个整数范围，用于捕获该转换历史上发生的状态条件。

例如，在 TDW-MAT 任务中，一个“GoTo→GoGrasp”的缓存条目可能包含以下元数据：步骤范围 $[19, 2645]$，持有物体数量 $[0, 3]$，完成的子目标数量 $[0, 9]$，访问过的房间数量 $[1, 4]$。**这意味着，当智能体处于这些状态范围内时，执行“GoTo”计划之后，下一步很可能是“GoGrasp”计划。**

> 在运行时，智能体的控制循环会使用前一个计划 $P_i$ 和当前的任务状态元数据作为键来查询缓存。然后进入过滤阶段，移除那些元数据范围与当前状态冲突的条目，得到可行候选集 $\mathcal{F}(P_i)$：

$$
\mathcal{F}(P_{i}) = \left\{ P_{j} \,\middle|\, s_{t} \in \left[ s_{ij}^{\min}, s_{ij}^{\max} \right],\, h_{t} \in \left[ h_{ij}^{\min}, h_{ij}^{\max} \right] \right\}
$$

其中，$s_t$ 和 $h_t$ 是当前的状态元数据，$s_{ij}^{min}$、$s_{ij}^{max}$ 和 $h_{ij}^{min}$、$h_{ij}^{max}$ 是缓存条目中对应的元数据范围。

得到可行候选集后，智能体会通过最大化综合得分来选择下一个计划 $P^*$：

$$
P^* = \arg\max_{P_j \in \mathcal{F}(P_i)} S(P_i \to P_j)
$$

其中，得分 $S(P_i \to P_j)$ 的定义为：

$$
S(P_i \to P_j) = C(P_i \to P_j) \cdot I(P_j)
$$

这个得分由两个因子组成：

1. 转换计数 C(Pi→Pj)：表示在执行过程中，计划 Pj 在计划 Pi 之后立即被观察到的次数。C 值越高，说明这个转换越频繁。
2. 重要性因子 I(Pj)：表示计划 Pj 被后台 LLM 确认的次数与它作为可行候选出现的次数之比：$I\left(P_{j}\right)=\frac{N^{conf }\left(P_{j}\right)}{N^{cand }\left(P_{j}\right)}$其中，$N^{cand}(P_j)$ 是 Pj 在缓存查询中作为可行候选出现的次数，$N^{conf}(P_j)$ 是后台 LLM 随后确认 Pj 为正确计划的次数。I 值越高，说明这个计划越可靠。

这两个因子捕捉了互补的信号：

- $C$ 是局部信号，特定于 $P_i \to P_j$ 这个转换；
- 而 $I$ 是全局信号，聚合了 $P_j$ 作为候选出现的所有上下文的信息。

:mdnice-bold-italic[它们的乘积奖励那些既频繁又可靠的转换，避免了单一信号的偏差。 这种设计类似于 CPU 中的混合分支预测器，结合局部和全局历史来提高预测准确率。]

### 3.3 异步缓存更新器

> 异步缓存更新器是 AgenticCache 的另一个核心组件，它是一个后台运行的 LLM 进程，负责在不阻塞智能体执行的情况下维护缓存的质量。它通过异步调用 LLM 来验证、纠正和优化缓存条目。

更新器的工作机制如下：当发出一个 LLM 查询时，更新器会记录当前的上下文 $c_t$ 和活动计划 $p_t$。经过 $k$ 步的异步延迟后，更新器收到 LLM 的响应 $p_{t+k}'$，然后将该预测与智能体实际执行的计划轨迹 $\{p_{t+1}, \dots, p_{t+k}\}$ 进行比较，并依据比较结果执行不同操作：

1. **确认**：若 $p_{t+k}'$ 已出现在执行轨迹中，表明缓存正确预测了 LLM 的选择。此时更新器增加对应转移的计数 $C(p_t \to p_{t+k}')$ 和确认计数 $N_{\text{conf}}(p_{t+k}')$，以强化该转移在缓存中的权重。
2. **纠正**：若 $p_{t+k}'$ 未出现在最近的执行轨迹中，表明缓存错误预测了 LLM 的首选计划。此时更新器执行三项操作：

**这种即时替换机制保证了智能体在缓存计划失效时能够快速纠正，避免执行错误的动作**。与并行规划-执行和投机规划不同，AgenticCache 不需要回滚已经执行的动作，而是直接切换到新的计划，这大大减少了时间浪费。

> 为了避免冗余的 LLM 查询，更新器采用了两种查询抑制机制：

1. 确认抑制：当 LLM 的响应确认了当前正在执行的计划时，在该计划完成之前，更新器不会再发出新的查询。因为此时缓存和 LLM 对当前的动作达成了一致，在这个窗口内的查询不会产生新的信息，只会消耗不必要的 token。
2. 纠正抑制：当一个纠正替换了正在执行的计划后，在替换的计划完成之前，更新器也不会发出新的查询。这是为了防止冲突的纠正导致智能体的执行不稳定。

当缓存未命中时，即没有可行的计划可以从缓存中检索到（可能是因为遇到了从未见过的情况，或者所有候选都被元数据范围过滤掉了），高层规划会暂时暂停。这时更新器会向 LLM 请求一个新的计划，新的计划会作为一个新的缓存条目插入到缓存中，然后智能体恢复执行。

**缓存和更新器形成了一个共生系统**：缓存作为快速的、基于模式的规划器，利用历史的规律性来实现高效执行；而更新器则提供基于 LLM 推理的上下文感知纠正，保证智能体在动态环境中的适应性。这种异步合作使得 AgenticCache 能够实现连续的、低延迟的决策，同时保持高任务成功率。

### 3.4 离线模式预填充与热启动

> 与计算机体系结构中的缓存一样，**AgenticCache 在 episode 开始时会遇到冷启动问题。当缓存为空时，智能体无法从缓存中获取任何计划，必须等待 LLM 生成前几个更新**，这会重新引入缓存旨在避免的延迟。

**为了缓解这个问题，AgenticCache 提供了一个可选的离线模式预填充过程**。在执行之前，研究者们:mdnice-bold-italic[使用来自分布外任务的成功 GPT-5 轨迹，提取其中的计划到计划的转换。每个转换会被插入到缓存中，并附带其估计的条件概率和元数据范围，从而生成一个热启动缓存。]

预填充的作用是让智能体从 episode 的一开始就能够立即行动，避免冷启动的延迟。同时，缓存会在执行过程中继续在线演化，不断更新和优化条目。但需要注意的是，预填充并不是 AgenticCache 运行的必要条件。更新器完全可以在线引导一个空的缓存，**冷启动评估表明，即使没有预填充，AgenticCache 仍然能够保留大部分的延迟和成本节省。**

实际上，预填充主要改善的是 episode 的前几个决策。一旦缓存在线填充了足够的转换，异步缓存引导规划的核心优势就会显现出来。对于那些无法获取离线演示轨迹的场景，AgenticCache 仍然可以通过在线学习来构建缓存，实现高效的规划。

> 整个运行过程可以分为以下几个步骤：

1. episode 开始时，智能体执行初始的 Explore 计划（T0-24）。同时，缓存更新器发出第一个周期性的 LLM 查询，记录当前的上下文和活动计划。
2. Explore 计划完成后，智能体查询缓存。由于缓存已经通过预填充或之前的执行积累了一些条目，过滤后返回 GoTo A 作为最高得分的候选。智能体开始执行 GoTo A 计划（T25-40）。
3. GoTo A 计划在步骤 40 完成后，智能体再次查询缓存。这时，一些条目（如 GoTo→Explore）会因为步骤范围不匹配而被过滤掉，剩下的候选中 GoGrasp B 的得分最高。智能体开始执行 GoGrasp B 计划（T41-98）。
4. 在执行 GoGrasp B 计划期间，步骤 1 中发出的 LLM 查询返回了结果，确认 GoGrasp B 是正确的下一个计划。系统会增加 GoTo→GoGrasp 这个转换的计数和重要性，并应用确认抑制，在 GoGrasp B 计划完成之前不再发出新的查询。
5. GoGrasp B 计划完成后，智能体再次查询缓存，使用更新后的元数据。这次，GoGrasp→GoTo 等转换被过滤掉，而 GoGrasp→Transport 的得分最高。智能体开始执行 Transport 计划（T99-155）。
6. 由于新的计划已经开始，且没有任何抑制机制生效，缓存更新器发出第二个周期性的 LLM 查询。
7. 在执行 Transport 计划期间，步骤 6 中发出的 LLM 查询返回了结果，提出 GoTo C 作为下一个计划。由于 GoTo C 没有出现在最近的执行轨迹中，说明缓存的预测是错误的。系统会立即将正在执行的 Transport 计划替换为 GoTo C 计划（T156-），同时减少 GoGrasp→Transport 这个转换的计数和重要性，增加 GoGrasp→GoTo C 这个新转换的计数和重要性，并更新其元数据的步骤范围。然后应用纠正抑制，在 GoTo C 计划完成之前不再发出新的查询。

**从这个示例可以看到，AgenticCache 通过缓存重用和异步更新，实现了连续的、低延迟的执行**。即使缓存的预测出现错误，智能体也能够通过即时替换机制快速纠正，保证任务的顺利进行。

::: block-1
AgenticCache 通过运行时缓存和异步更新器的协同工作，实现了高效且鲁棒的规划。缓存提供快速的基于模式的决策，更新器提供上下文感知的验证和纠正，两者结合使得智能体能够在动态环境中以低延迟、低成本完成任务。
:::

4. BEHAVIOR-1K：家庭日常活动基准测试，使用 COHERENT 智能体框架，5 个异构机器人（机械臂、机器狗、四旋翼），集中式协调，使用 LLM 作为规划器。任务目标是异构机器人协作完成家庭运输任务。

> 研究者们将 AgenticCache 与三种主流的规划方法进行了对比：

1. 同步基线：采用 CoELA、COMBO 和 COHERENT 作为同步 LLM 基智能体，这是当前具身智能领域的标准方法。
2. 并行规划-执行：在执行当前计划的同时提前查询下一个计划，部分隐藏 LLM 延迟。
3. 投机规划：使用较小的 LLM（GPT-5-nano）提出初步动作，然后使用较大的 LLM（GPT-5 或 GPT-5-mini）进行验证。

**首先看任务成功率。AgenticCache 在所有配置中都取得了非常高的成功率**。使用 GPT-5 和 GPT-5-mini 时，AgenticCache 在各个环境中的成功率达到了 84-100%；即使使用最小的 GPT-5-nano，成功率也达到了 68-100%。

**AgenticCache 之所以能够取得如此高的成功率，主要得益于其异步更新和即时替换机制**。缓存更新器会定期验证缓存的计划，当发现缓存计划失效时，会立即替换为正确的计划，避免智能体执行错误的动作。同时，这种机制也避免了并行规划和投机规划中常见的回滚操作，保证了智能体之间的协调动作不会被打断。

:mdnice-bold-italic[再看延迟和成本效率。AgenticCache 在所有 12 种配置中平均降低了 65%的模拟延迟，减少了 50%的 token 使用。这是一个非常显著的提升，意味着具身智能系统的运行速度可以提高近 3 倍，成本可以降低一半。]

具体来看：

- 在 TDW-COOK 基准测试中使用 GPT-5 时，基线方法的延迟为 12.86 小时，成本为 21.0 美元；而 AgenticCache 的延迟仅为 1.75 小时（降低了 86%），成本仅为 4.4 美元（降低了 79%）。
- 在 TDW-GAME 基准测试中使用 GPT-5 时，基线方法的延迟为 7.88 小时，成本为 14.3 美元；而 AgenticCache 的延迟仅为 1.11 小时（降低了 86%），成本仅为 4.8 美元（降低了 66%）。
- 在 BEHAVIOR-1K 基准测试中使用 GPT-5 时，基线方法的延迟为 3.36 小时，成本为 9.3 美元；而 AgenticCache 的延迟仅为 1.55 小时（降低了 54%），成本仅为 6.6 美元（降低了 29%）。

::: block-1
这些巨大的**收益主要来自于两个方面：**

- 一是缓存命中时，智能体可以连续执行多个计划，无需等待 LLM 推理，从而消除了大部分等待时间；
- 二是查询抑制机制避免了冗余的 LLM 调用，减少了 token 的消耗。随着缓存命中率的提高，这些收益会进一步增加。
:::

### 4.6 消融研究：各组件的贡献

> 为了验证 AgenticCache 中各个组件的贡献，研究者们进行了消融研究，评估了四个不同的变体：

1. 静态缓存：没有异步更新和计划替换机制，只使用初始的 2-gram 模式进行决策。
2. 仅缓存更新：启用异步缓存更新机制，但不启用计划替换。
3. 仅计划替换：启用计划替换机制，但不启用异步缓存更新。

## 五、相关工作对比：AgenticCache 的独特性与优势

> AgenticCache 并不是第一个尝试通过缓存来优化 LLM 系统的工作，也不是第一个提出并行规划策略的工作。但它是第一个将缓存驱动的规划与异步更新机制结合起来，专门针对具身智能任务的计划局部性进行优化的框架。

为了更清晰地理解 AgenticCache 的贡献，我们将它与相关领域的现有工作进行对比，分析它们的核心思路和局限性，以及 AgenticCache 相对于这些工作的优势。

### 5.1 LLM 系统中的缓存机制

> 缓存是 LLM 系统中常用的优化技术，用于减少冗余计算。现有的 LLM 缓存机制主要可以分为以下几类：

1. KV 缓存：这是目前 LLM 推理中最常用的缓存技术。它存储之前解码步骤的键值状态，当生成后续 token 时，模型可以重用这些键值状态，而无需重新计算整个前缀。KV 缓存能够显著提高自回归生成的速度，但它只能在同一个推理请求内部重用计算，无法跨不同的请求或不同的规划步骤重用。
2. 上下文缓存：上下文缓存存储提示-响应对或相似的上下文。当一个新的请求与缓存中的条目匹配时，系统可以直接重用缓存的响应，而不需要调用模型。例如，GPTCache 和 Semantic Cache 都属于这类缓存。上下文缓存能够跨不同的请求重用计算，但它主要适用于查询内容高度相似的场景，对于具身智能中动态变化的上下文，匹配率较低。
3. 模板缓存：模板缓存存储与重复任务模式相关联的计划模板或结构化输出。当遇到相似的任务时，系统可以重用缓存的模板，只需要填充少量的变量即可生成计划。例如，Agentic Plan Caching 就采用了这种思路。模板缓存比上下文缓存具有更高的灵活性，但它仍然是静态的，无法适应环境的动态变化。

:mdnice-bold-italic[现有缓存机制的共同局限性是，它们主要是为 LLM 推理本身设计的，而不是为具身智能智能体的规划过程设计的。它们减少的是模型内部的冗余计算，而没有减少执行期间的重复 LLM 调用。] 即使使用了 KV 缓存和上下文缓存，智能体在每一步仍然需要调用 LLM 来生成计划，只是每次调用的速度更快了。

而 AgenticCache 独特地利用了具身任务中顺序决策之间的时间依赖性，即计划局部性。它缓存的不是单个的 LLM 响应，而是计划之间的转换模式。这使得智能体能够在多个步骤中避免调用 LLM，从根本上减少了 LLM 调用的次数，从而实现了更大幅度的延迟和成本降低。同时，AgenticCache 的异步更新机制使得缓存能够动态适应环境的变化，保持了鲁棒性。

### 5.2 具身智能中的并行规划策略

> 如前所述，现有的具身智能规划优化方法主要包括并行规划-执行和投机规划。

- 并行规划-执行的核心思想是将规划和执行重叠，在执行当前计划的同时提前查询下一个计划。这种方法能够部分隐藏 LLM 的延迟，但它存在两个主要问题：一是预取的计划可能在执行时已经失效，需要重新规划；二是它仍然需要每步调用 LLM，成本随轨迹长度线性增长。
- 投机规划则是使用一个小模型来提出初步的行动计划，然后用大模型来验证。这种方法能够进一步降低延迟，但在动态环境中表现不佳，因为错误动作的回滚需要花费大量的时间。同时，投机规划需要同时运行两个模型，增加了系统的复杂度和资源消耗。

**AgenticCache 与这两种方法的本质区别在于，它不是试图隐藏或掩盖 LLM 的延迟，而是通过缓存重用计划，从根本上减少 LLM 调用的次数**。在缓存命中的情况下，智能体完全不需要调用 LLM，因此不会产生任何 LLM 推理延迟。同时，AgenticCache 的即时替换机制避免了回滚操作，当缓存计划失效时，智能体可以直接切换到新的计划，不会浪费时间。

此外，AgenticCache 与现有的并行规划策略是互补的。可以将 AgenticCache 与并行规划-执行或投机规划结合起来，进一步提高系统的性能。例如，在缓存未命中需要调用 LLM 时，可以使用并行规划-执行来重叠 LLM 推理和动作执行；或者使用投机规划来加速 LLM 的推理过程。

### 5.3 从演示中学习与轨迹重放

> 模仿学习和轨迹重放是另一种提高具身智能效率的方法。这类方法通过从专家演示中学习策略，或者重放成功的轨迹，来避免在线规划的开销。

例如，学徒学习和 DAgger 等模仿学习方法通过大量的专家演示来训练一个策略网络，智能体在执行时直接从策略网络中获取动作，不需要调用 LLM。轨迹优化技术如 STOMP 则通过优化专家演示的轨迹来生成更平滑、更高效的动作序列。ALFRED 和 TEACh 等基准则收集了大量的人类演示数据，用于训练具身指令跟随智能体。

**这类方法的主要局限性是，它们需要大量的训练数据**，通常需要数千个专家演示 episode，才能训练出一个泛化性较好的策略。而且，训练好的策略在分布外的任务上泛化性较差，当环境或任务发生变化时，需要重新收集数据进行训练。

> **而 AgenticCache 以完全不同的方式利用演示数据。它不需要训练任何模型，只需要从少量的成功演示中提取频繁的计划转换模式，用于缓存的预填充**。在评估中，每个基准只需要 1-4 个训练 episode，远少于模仿学习所需的数量。同时，AgenticCache 的缓存会在执行过程中不断在线更新和优化，能够适应环境的动态变化，具有更好的泛化性。

此外，AgenticCache 与模仿学习也是互补的。

- 可以使用模仿学习来预训练一个基础策略，然后使用 AgenticCache 来缓存策略的输出，进一步提高执行效率。
- 或者，当缓存未命中时，调用模仿学习的策略来生成计划，而不是调用 LLM，从而降低成本。

::: block-1
AgenticCache 在现有工作的基础上，提出了一种全新的缓存驱动异步规划范式。它针对具身任务的计划局部性进行优化，从根本上减少了 LLM 调用的次数，同时通过异步更新机制保持了鲁棒性。它与现有的缓存机制、并行规划策略和模仿学习方法都是互补的，可以结合使用以实现更优的性能。
:::

## 六、结论与展望

### 6.1 结论总结

> 本文提出了 AgenticCache，一种缓存驱动的异步规划框架，:mdnice-bold-italic[旨在解决 LLM 驱动具身智能的延迟和成本瓶颈。该框架的核心洞察是，具身任务表现出强烈的计划局部性，即下一个计划在很大程度上可以从当前计划预测出来。] 基于这一洞察，AgenticCache 通过运行时缓存频繁的计划转换，结合后台异步的 LLM 更新器来验证和优化缓存条目，实现了高效且鲁棒的规划。

AgenticCache 的设计由两个核心组件组成：运行时缓存和异步缓存更新器。

- 运行时缓存作为轻量级规划器，存储计划到计划的转换及其对应的状态条件，通过综合考虑转换的频率和可靠性来选择下一个计划。
- 异步缓存更新器则在后台运行，定期调用 LLM 来验证缓存的计划，当发现缓存计划失效时，立即替换为正确的计划，并更新缓存条目。

> 在四个多智能体具身基准测试和三个不同规模的 LLM 模型上的全面评估表明，AgenticCache 取得了显著的性能提升：

- 平均提高任务成功率 22%，在多智能体协调任务中表现尤为突出。
- 平均降低模拟延迟 65%，在某些任务上甚至达到了 86%的延迟降低。
- 平均减少 token 使用 50%，大幅降低了 LLM 调用的成本。

此外，AgenticCache 还具有极小的内存开销（每个智能体仅 0.1-1.0 KB）和良好的冷启动性能，即使没有离线预填充，仍然能够保留大部分的效率收益。**消融研究证实，缓存更新和计划替换两个组件协同作用，是实现高性能的关键。**

::: block-1
这些结果表明，**基于缓存的计划重用是实现低延迟、低成本具身智能的实用杠杆**。它为具身智能的大规模部署提供了一条可行的路径，同时也为 AI 系统的跨层优化提供了新的思路。
:::

### 6.2 进阶分析：方法的边界与局限

> 尽管 AgenticCache 取得了令人印象深刻的结果，但我们必须清醒地认识到，它**并不是一个万能的解决方案，而是在特定假设下的阶段性成果**。本节我们将抛开论文作者的倾向性，:mdnice-bold-italic[客观分析该方法的边界条件、局限性和隐性成本。]

*首先，AgenticCache 的有效性高度依赖于具身任务中的计划局部性。*

:mdnice-bold-italic[论文中评估的四个基准测试都是结构化的、目标导向的任务，如运输、烹饪、拼图组装等，这些任务的计划转换确实具有很强的规律性。 但在更开放、更具创造性的场景中，如自由形式的探索、艺术创作、即兴交互等，计划局部性可能会非常弱]。在这些场景中，缓存命中率会大幅降低，AgenticCache 的效率收益也会随之消失。论文中并没有评估 AgenticCache 在这类非结构化环境中的表现，这是一个重要的局限性。

其次，方法论和实验设计中存在一些未被充分讨论的:mdnice-bold-italic[隐性成本]：

1. 缓存预填充需要少量的成功演示轨迹。虽然数量远少于模仿学习，但**仍然需要一定的前期数据收集和标注工作**。对于那些无法获取演示数据的全新任务，冷启动阶段仍然会有一定的延迟开销。
2. 异步更新机制引入了一定的系统复杂度。需要处理计划替换、查询抑制、缓存一致性等问题，增加了工程实现的难度。特别是在多智能体系统中，需要保证各个智能体的缓存更新不会相互干扰，这进一步增加了系统的复杂性。
3. 论文中的成本计算只考虑了 LLM 调用的 token 成本，而没有考虑缓存维护和更新的计算成本。虽然缓存的计算开销非常小，但在大规模部署的情况下，这些开销也需要被纳入考虑。

*第三，结合实验数据，AgenticCache 在以下场景中表现欠佳：*

1. 计划多样性高的环境。例如在 TDW-COOK 基准测试中，由于烹饪任务需要按照严格的食谱顺序执行不同的操作，计划的转换更加多样化，缓存命中率仅为 39-46%，大部分访问仍然需要回退到 LLM 查询。在这种场景下，AgenticCache 的效率收益会受到限制。
2. 长程任务中的多智能体协调场景。在长程任务中，GPT-5 的成功率略有下降，原因是过时的转换在局部仍然合理，但在延迟的环境变化后变得次优，以及独立重用的转换可能导致智能体之间的协调冲突。虽然更新器可以纠正这些问题，但纠正可能在几步之后才到达，导致短暂的性能下降。
3. 动态变化剧烈的环境。如果环境的变化速度超过了缓存更新器的更新频率，缓存的计划会快速失效，导致频繁的纠正和回退，反而可能降低系统的性能。论文中的实验环境虽然是动态的，但变化速度相对较慢，没有评估在高速动态环境中的表现。

最后，:mdnice-bold-italic[AgenticCache 并没有从根本上解决 LLM 驱动具身智能的所有问题]。

它只是**缓解了规划阶段的延迟和成本瓶颈，而感知和执行阶段的瓶颈仍然存在**。例如，视觉感知的延迟、机器人执行的误差等问题，都需要其他技术来解决。

### 6.3 未来工作

> 论文作者在文中明确提出了以下几个未来的研究方向：

1. 扩展缓存到更高阶的转换表示。目前 AgenticCache 使用的是 2-gram 计划转换，只能捕捉相邻两个计划之间的依赖关系。**未来可以扩展到 3-gram 或更高阶的 n-gram 索引，或者使用分层的子程序片段表示，以更好地捕获二元语法局部性遗漏的长程依赖关系。**
2. 设计基于优先级的多智能体协调协议。在多智能体环境中，缓存重用可能导致协调问题，如会合不匹配或资源争用。**未来可以引入资源预留机制和轻量级的冲突解决规则，将本地的缓存效率与全局的多智能体一致性对齐。**
3. 实现自适应的缓存机制。目前缓存的评分函数和查询策略都是固定的。**未来可以让缓存根据执行反馈自动学习评分函数，或者动态决定何时应该 defer 到 LLM，何时应该使用缓存的计划**，从而进一步提高系统的性能和适应性。
4. 评估在结构较少的环境中的有效性。未来需要将 AgenticCache 应用到更开放、更具创造性的任务中，探索在计划局部性较弱的场景下，缓存设计的可能性和局限性。
